# 沒有圖譜的專案答不完表態題

## 現象

一個還沒接知識圖譜的專案(目錄下沒有 `docs/`),只要改動踩到任何一題棧別效能檢核,推送前就會被擋,理由是「表態不完整」。但你照著它給的指令去答題,答案寫不進去——表態指令會直接拒絕,說這個專案沒有 `docs/`,表態進不了治理帳。

**兩邊都走不通:不答被擋,答了寫不進去。** 目前唯一出路是 `--no-verify`,而那等於整道閘都不跑。

## 為什麼會這樣

表態跟審查留痕一樣,都要寫進治理帳才算數(CI 那邊只讀得到治理帳,本機那份記錄是每台機器各自的、不進版控)。治理帳放在 `docs/` 底下,所以沒有 `docs/` 就沒地方寫。

擋人的那一關卻沒有對應的判斷——它只看「有幾題適用、答了幾題」,不管這個專案答不答得了。

**同一支檢查裡的另一關反而處理對了**:合約測試那一關遇到沒有圖譜的專案,會把狀態標成「沒有圖譜」然後放行,不擋。兩關做法不一致。

## 怎麼發現的

2026-09-12,Python 棧支援上線之後。代碼審守衛那組測試用一個假 repo:裡面放一行 `requests.post` 把風險等級拉到高。這行字本來只被當成「資源類風險」,Python 棧上線後它同時觸發了兩題 Python 效能檢核,於是假 repo 第一次需要表態——而它沒有 `docs/`,寫不進去,六條斷言全紅。

一開始看起來像測試寫壞了,查到底才發現測試沒錯,是這個死結。

## 目前處置

測試那邊先讓假 repo 建一個 `docs/` 再開工,讓它走得到原本要驗的那一關。死結本身沒修。

要修得先回答一個設計問題:**沒有接圖譜的專案,該不該被這道閘管?** 兩個方向都說得通——「不該管,照合約測試那關的做法標成沒有圖譜就放行」,或是「該管,那就得讓表態有地方可寫」。這不是改個判斷式的事,要走設計流程。
