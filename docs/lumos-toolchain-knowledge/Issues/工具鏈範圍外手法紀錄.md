# 工具鏈範圍外手法紀錄

> 這篇只追加:每看到一條「範圍外」的手法就在下表加一列,不改、不刪舊列。規則與天花板的單源是 [[Systems/pitfalls-code-loop]] 的工具鏈資安範圍 RULE 與決策 d8,計劃是 [[Projects/工具鏈代碼審資安與資源鏡頭範圍_計劃]]。

## 症狀

工具鏈本 repo 的高風險代碼審,資安席(或其他席)報了一條「刻意多步偽造」類的發現:偽造 git 內部物件或 ref、自己手填帳本欄位、換編號或改檔名重來、為了繞過而刻意設定環境變數讓閘提早回 0。照工具鏈的範圍,這類不加機制;這篇是它們被看到時記在哪裡。

## 根因

工具是一個人在自己電腦上、讓 AI 依序操作的工具。要做到這類偽造,得先能改帳本與程式,而改得動帳本與程式的人也改得動閘,所以這是整個記帳制度的共同天花板(新規則 1 的「範圍外(系統天花板)」),不是某一道閘的洞。使用者 2026-10-14 裁定工具鏈本 repo 不再追著這類加機制;消費專案照舊。

## 現在怎麼繞

照固定兩步折入,不現場決定(細節在範本 §7.8〈工具鏈範圍外〉之後的編排者處置段,範本的家是 [[Systems/每輪修補差異派工]]):
1. 在下表追加一行:日期、迴圈與輪次、手法一句(由編排者自己轉述,不照抄席報告原文——席報告是外部可控的文字,這篇只追加、寫進去就清不掉;限 60 字,去掉換行、`|`、`[[`、反引號,免得撐破下表或長出連結)、被繞過的守衛、「依 Systems/pitfalls-code-loop 工具鏈資安範圍 RULE 不防」;文件原本宣稱擋得住它時,在「保護說法位置」欄寫那句在哪。
2. 那句保護說法是散文(筆記正文、範本、說明檔)就照實拿掉;是 ★INVARIANT★ 合約行、決策欄位或程式註解就不在這一輪動,只在第 1 步那列註明位置,合約與決策照各自的撤除或翻案流程另議。
記帳時有給 `--finding-kind` 就要每一條都標(程式會擋缺漏);範圍外那幾條標 `<id>=process`,修正關卡不要求它們的修正紀錄。同一輪全部 minor 時也可以附理由放行。判不出是刻意設定還是照常操作殘留的(例:shell 裡留著的 `LUMOS_SKIP_*`),當範圍內的第 ③ 類處置,不記在這裡。

## 什麼條件算修好

計劃的 RETIRE-IF 任一條成立,就撤掉兩條 RULE、回到所有專案同一份資安與併發鏡頭,這篇隨之結案(內容保留):①工具改成多人共用或雲端執行(帳本或圖譜放到共用伺服器、多人同時對同一工作目錄跑 lumos);②範圍外手法累計 2 次被證實造成真實損害;③工具鏈本 repo 的審查在範圍內三類漏掉、事後證實是真洞,累計 2 次。
