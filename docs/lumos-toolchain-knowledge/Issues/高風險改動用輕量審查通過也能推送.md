# 高風險改動用輕量審查通過也能推送

## 症狀

pitfalls 把一次推送判成 tier=high(命中風險型樣、殘留索引,或之後的高風險路徑清單),推送閘要求這一版有代碼審留痕;但開一個輕量迴圈(`loop next --tier light`,不分輪次)記一筆乾淨審查、`code-loop pass --loop` 留痕之後,推送照樣放行。高風險該派的多席與資安席沒有被要求。

## 根因

- `code-loop check` 的審查那一道只讀留痕的狀態與版本,不讀那筆留痕對應的審查迴圈定錨成什麼分級。
- `code-loop pass` 寫入前驗凍結判定:`_codeloop_pass_shape` 對不分輪次、定錨 light 的帳回「輕量放行」,不看當下 pitfalls 的分級。
- 手冊寫「`loop next --tier` 要照 `pitfalls --diff` 算出的分級給」,這條只靠編排者照做。

## 現在怎麼繞

編排者照 `pitfalls --diff` 印的 tier 開迴圈;高風險的照開 `--tier high`。推送閘本身不會擋錯配。

## 什麼條件算修好

pitfalls 判 high 的範圍,拿定錨 light 或 standard 的迴圈通過紀錄推送會被擋,並印出要開 high 迴圈的指令;有一支測試從輕量迴圈留痕加高風險範圍跑到擋下。
