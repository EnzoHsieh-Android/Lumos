# 派工鏡頭附的表態取自會談目錄的分支

## 症狀

在一個工作樹開會談、審另一個工作樹的分支時,派工掛鉤(LUMOS-IMPACT 標記)附給席位的「表態記錄」寫的是會談所在分支、那一版的表態。2026-10-24 記憶體與穩定性驗收的代碼審第一輪,整合席看到的表態在講 `scripts/scenario_probe.py`(另一個分支的改動),報成一條「表態不是這次改動的」;實際上被審分支自己的表態是對的。

## 根因

`lumos dispatch-lens` 在 `_dispatch_lens_graph` 裡用 `_codeloop_read_dispositions(root, _codeloop_git_branch(root), marker_only=True)` 取表態(只讀本機 marker):`root` 是執行指令的 repo 根,`_codeloop_git_branch` 回那裡目前 checkout 的分支。審查範圍的終點提交跟這個分支沒有關係,所以範圍在別的工作樹時就拿錯。派工掛鉤在會談目錄跑,一定走到這條。

## 現在怎麼繞

派工詞不放 `LUMOS-IMPACT:` 標記;改到被審分支的工作樹跑 `lumos dispatch-lens <base>..<head>`,把輸出貼進派工詞(這輪 r2 就是這樣做)。

## 什麼條件算修好

鏡頭依範圍終點找表態(終點提交屬於哪個分支、或表態記錄裡記的版本是不是終點的祖先),在 A 分支的目錄派工審 B 分支時印 B 分支的表態;有一支測試在兩個工作樹之間重現上面的 repro 並斷言印的是 B。
