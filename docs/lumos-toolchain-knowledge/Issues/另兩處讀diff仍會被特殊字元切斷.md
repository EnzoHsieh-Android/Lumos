# 另兩處讀diff仍會被特殊字元切斷

## 症狀

本專案還有兩處自己解析 git diff 文字:不可逆提示掃描(提交前提醒疑似不可逆的新增行)與凍結 patch 的檔名指紋(處置閘核對資安席看過的檔)。兩處都用 splitlines 切行、只認 `+++ b/` 開頭的檔頭。內容帶 U+2028、U+0085、單獨 CR 時一行會被切斷;檔名含 tab、雙引號、反斜線時 git 把檔頭包上引號,這兩處認不得,那支檔的行被算到上一支檔頭上(2026-10-09 實測不可逆提示掃描:檔名含 tab 的那一行,提示裡的檔名是空白)。

## 根因

推送前分級在 2026-10-09 目標架構代碼審 r3、r4 被抓到同一族問題,改成以位元組讀、只照換行切行、檔頭認得 C 式引號,並抽成兩支共用函式(推送前分級與派工鏡頭共用,見 [[Systems/pitfalls-code-loop]])。這兩處屬於別的功能,當時不在那次改動範圍,沒有跟著換。

## 現在怎麼繞

不可逆提示只提醒不擋,漏看的後果是少一句提醒;凍結 patch 的檔名指紋影響資安席覆蓋判定,檔名帶這類字元的改動,編排者要自己確認資安席看過那支檔。

## 什麼條件算修好

兩處改用推送前分級那兩支共用的切行與檔頭函式,並各有一條測試:檔名含 tab 與雙引號、內容帶 U+2028 與單獨 CR 時,結果與一般檔名相同。
