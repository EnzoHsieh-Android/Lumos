# 舊句檢查超長行判準偏寬與留痕殘行

白話:舊句檢查(推送時比對「這次消失的程式名稱」跟筆記)在代碼審驗收輪還有兩個小毛病,這批不改程式、附理由放行,記在這裡等兩週回頭那天處理。

## 症狀

1. **超長行判「有關」偏寬(2026-10-09 已修)**:一行超過 2 萬字的筆記行不掃,只看「行裡有沒有出現這次消失的名稱」決定要不要算判不了。原本用純子字串比,名稱只是別的識別字的一段也算有關——block 模式下會擋,結論行還說「行裡有這次消失的名稱」;現在改成整字先篩(`_drift_m1_line_names`),見〈什麼算修好〉第 1 條。
2. **留痕檔的半行會吃掉下一筆**:治理帳寫不進去時另在家目錄留一行痕跡,給兩週回頭數「帳沒記到」。寫到一半(磁碟滿)時只回 False,沒人看;半行留在檔裡,下一筆接上去,兩筆都讀不出來。

## 為什麼放行

- (第一條已在 2026-10-09 修掉,見〈什麼算修好〉;以下是當時的放行理由。)第一條只會多擋、不會漏掉真舊句,而且要同時滿足「圖譜有超過 2 萬字的行」「消失的名稱剛好是那行某個較長識別字的一段」「舊句檢查是 block」才會發生。這個條件原本要專案自己設(當時預設只提醒);2026-10-09 起 `old_sentence` 沒寫照總開關、預設就是 block,不用專案設也會發生([[Projects/舊句兩道轉擋_計劃]])。
- 第二條只在治理帳本身寫不進去、而且留痕檔也寫到一半時才會發生(同一顆磁碟滿),機率低;代價是兩週回頭時可能少數一次「帳沒記到」。

## 附註

- 同一席也提到:m1 兜底最後一道保底印出(判定出錯之後、印出與記帳又出錯時那一句)印例外訊息時仍用舊的跳脫函式(只換控制字元、不換方向控制與零寬),跟第三輪改成新跳脫函式的那一句同一種問題、這一處漏掉。只有連續兩次出錯才會走到,找不到自然觸發的場景;修第二條時順手改。

## 什麼算修好

1. 超長行判「有關」改用跟整字規則一致的判法(例如 `_drift_m1_line_names`),補一支「消失名稱只是較長識別字一段的超長行不擋」的測試。
   - 2026-10-09 已修:舊句兩道轉擋把 `old_sentence` 沒寫改成照總開關、預設 block 之後,這條不用專案設定也會誤擋,所以併進那次代碼審第一輪修補一起改(測試 `t_drift_m1_long_line_whole_word`)。第二、三條照原 REVISIT 處理。
2. 留痕檔短寫時不留半行(截回或先補換行),呼叫端在 stderr 講一句;補一支「短寫之後再寫一筆,兩筆都讀得出來(或短寫那筆被收回)」的測試。
3. 保底印出改用新的跳脫函式。
