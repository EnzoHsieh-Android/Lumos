# 帳本讀取沒接遞迴過深

## 現象

帳本(`.canary-log.jsonl`、`.escape-log.jsonl`、`.governance-log.jsonl` 等)裡如果有一行 `[[[[…]]]]` 這種合法但深到二十萬層的 JSON,Python 解析時丟 `RecursionError`,不是 `ValueError`。只寫 `except ValueError` 的讀帳點接不住,指令會帶著原始錯誤堆疊結束。

更糟的一種:共用的「寫完讀回自驗」如果碰到別筆是這種行,會在**已經寫進去之後**報「沒記成功」。這一處已在逃逸帳那次一起修了。

## 範圍

- 已修(2026-09-26):逃逸帳的讀取、清單、手動記、自動記、逃逸統計讀審查帳與治理帳、判門、共用寫完讀回自驗。
- 沒修:2026-09-26 機械數,主程式裡「`.loads(` 後五行內第一個 except 沒接 RecursionError、也不是接全部」的有 55 處(口徑:只看呼叫 `.loads(` 的行往下五行內第一個 except;不含沒包 try 的呼叫點)。重算:

```
python3 - <<'X'
import re
L=open("scripts/lumos",encoding="utf-8").read().split("\n")
print(sum(1 for i,l in enumerate(L) if ".loads(" in l for j in range(i+1,min(i+6,len(L))) if L[j].lstrip().startswith("except") and "RecursionError" not in L[j] and not re.search(r"except Exception|except:$",L[j]) and not any(L[k].lstrip().startswith("except") for k in range(i+1,j))))
X
```

## 為什麼沒一起修

要觸發得有人往帳本塞一行幾十萬字元的怪資料;後果多半是唯讀指令崩掉,不會寫錯帳(寫完讀回那處例外,已修)。五十幾處逐一改是同族掃描,但更好的形狀是收進一支共用的讀 jsonl 函式,那是另一件事。
