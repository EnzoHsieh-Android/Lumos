# 記帳後改留痕格式讓回放永久紅


## 現場

2026-09-16 跑改制回測週跑，121 包裡 1 包紅：同一份凍結輸入，當時判過、現在判不過，卡在「留痕」那一關——收貨留痕檔的指紋與帳面不符。

追提交史，那份檔在 2026-09-09 被改過兩次：第一次是記帳當下，第二次是同日稍後的實作提交。第二次改的內容是：

- 原本：宣告行後面直接接著說明文字（同一行）。
- 改後：宣告行單獨一行，說明另起一行，並加註「宣告行必須整行只有那幾個字才算數——刻意設計，防照抄模板偽造」。

**所以這不是造假，是有人把格式修對了。** 但帳已經記了，改檔就讓指紋永遠對不上。

## 為什麼在意

- 那一包**每次週跑都會紅一次**，而紅的原因跟品質無關。紅久了人就學會忽略回放的紅燈——**那是這個機制唯一的產出訊號**。
- 而且它掩蓋真正的漂移：下次真的有邏輯漂移時，紅燈清單裡多一包假的，判讀成本上升。

## 這是已知教訓的又一次發作

圖譜裡已經記過「記帳中途別動被審文件」（三犯）。這次是它的變形：**記帳之後、為了過格式檢查而動**——動機正當，後果一樣。

## 修法方向（還沒做，三條各有代價）

1. **帳本允許補一筆「格式訂正」事件**，記明新舊指紋與理由，回放看到就接受。代價：開了一個「可以事後改」的口子，要設計成只能改格式不能改內容——而「只改格式」很難機械證明。
2. **重記那一輪**（換編號重跑記帳）。代價：帳不能撤銷，會多一筆看起來像重審的帳。
3. **接受它，把這包標成已知假紅**，週跑報告裡排除。代價：要維護一份排除清單，而清單本身會腐爛。

**目前沒有裁定，先記著。** 本輪不處理是因為三條都要動機制，而且要有人裁。
