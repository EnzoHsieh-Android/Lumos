# 鏡頭範圍代碼審第二輪放行的小缺口

代碼審 code-工具鏈代碼審資安與資源鏡頭範圍 第二輪七席都只有 minor 或 clean(19 條),依「同輪沒有 major 時 minor 可附理由放行」全數放行、不再開第三輪;逐條原文在 governance/review-reports/code-工具鏈代碼審資安與資源鏡頭範圍/r2-*-sonnet.md,處置在 r2-intake.md。

## 症狀

**A. 文件字面沒跟上(只改文件的分支修):**
- 已修(lens-scope-docs 分支,2026-10-15):計劃做法 10 還引用舊字串「鏡頭範圍: 工具鏈本 repo」(正確性 1、合約 2),改成指「『鏡頭範圍』那一行」;〈版本錯位〉那段還說「照它貼就是少審」(合約 2),改成條件語氣後的現況。
- 已修(lens-scope-docs 分支,2026-10-15):計劃 S9、做法 6、做法 9、現況表寫刪檔紀律是 §5、§6 兩份,測試已驗 10 份(6 份 LUMOS-SEAT 加 §5、§6、§3.1、§9),改成照實;做法 6 與〈回退〉寫「8 支新測試」,改成 11 支並列出後加的 3 支,回退一併拿掉;S10 補上 manifest 那條須知(合約 1、合約 3、合約 7、通才 5)。
- 已修(lens-scope-docs 分支,2026-10-15):Systems/pitfalls-code-loop 與 Systems/每輪修補差異派工 正文寫了「代碼審 r1」這類過程紀錄(合約 4),改成不帶輪次的說法。
- 已修(lens-scope-docs 分支,2026-10-15):Systems/pitfalls-code-loop 第一條 RULE 被擴寫了「判別只看根目錄」「放一支空檔算範圍外」兩段(合約 5),兩段搬出 RULE、改寫成鏡頭範圍那一節的正文說明並註明不是使用者裁的;RULE 只留裁定原文,`[confirmed:]` 不動。

**B. 程式與測試(條件成立再修):**
- `loop next --json` 的 `lens_scope` 值沒有「帳本所在 repo」的但書(資安 1、通才 3)。目前沒有程式讀這個欄位。
- 那一行開頭寫「帳本所在 repo」,帶 `--repo` 時判的是 `--repo` 那個目錄(邊界 2)。
- 被審分支自己新增 `skills/lumos-project-notes/SKILL.md` 一支空檔,消費專案就被判成工具鏈(資安 2;已明文列為刻意手法、範圍外)。
- `t_templates_toolchain_lens_scope` 的逐句斷言只看整個 `### 工具鏈三類` 小節,要貼給子代理的句子被搬到圍欄外仍照綠(邊界 1)。
- `t_loop_next_lens_scope_loose_code_ids`、`t_loop_next_lens_scope_marker_odd_kinds`、`t_toolchain_lens_scope_note_pointers` 沒綁任何驗收條款(邊界 3、合約 3)。
- 以下幾條原屬 A 類,但要動 `skills/lumos-design-loop/templates.md`(幾句被測試逐字釘住,改了就不再是只改文件的分支),移到這裡:
  - 範本 §3 須知 manifest 那條寫「同計劃新規則 2」,應是新規則 3(合約 2、合約 7)。
  - 範本〈工具鏈範圍外〉、Issues/工具鏈範圍外手法紀錄與計劃〈實作紀錄〉寫「整輪每一條都要標 --finding-kind(程式會擋缺漏)」,程式只在有給時才要求全標(合約 6;範本那句被 `t_templates_toolchain_lens_scope` 釘住,兩處一起改)。
  - 範本 §7.8 說明段「看被審 repo 的根」與「沒有那一行就貼六類」兩句對反方向的跨 repo(會談在消費專案、審工具鏈分支)優先序沒寫(通才 1)。
  - §3 須知「manifest 併發題照範圍外標誤報」在帳上沒有可執行的落法:記進範圍外 Issue 歸錯類、記成 refuted 湊不出重現表(通才 2)。
  - 〈工具鏈範圍外〉貼給資安席的那段叫它「看到就標 minor」,判不出刻意與否時席位先自己降級,編排者走不到「拿不準當 ③」(通才 4)。
  - 範圍外紀錄的「手法一句」沒有長度與去掉換行、`|`、連結的規則(資安 3)。

## 根因

第一輪修補把那一行改成條件語氣、範本與測試跟著改,但計劃與 Systems 筆記裡同一句話散在好幾處,沒有逐處跟上;JSON 欄位與逐句斷言的位置在第一輪修補範圍外。沒有一條會讓消費專案的派工少審(那一行的文字已帶但書;JSON 欄位目前沒有人讀)。

## 現在怎麼繞

- 照範本與 `loop next` 的人讀輸出,不要照 JSON 欄位判斷範圍。
- 跨 repo 派工時,看被審 repo 的根有沒有那支檔;判不出刻意與否的資安發現當 ③(範圍內)處置。

## 什麼條件算修好

- A 類:2026-10-15 已在 lens-scope-docs 分支全數修掉(見上面標「已修」的各條)。
- B 類中要動範本的幾條:下一次改到 templates.md §3 或 §7.8 時一併修(連同釘住那幾句的測試)。
- B 類其餘:任一條成立就修——有程式或自動迴圈開始讀 `lens_scope`;下一次改到 `t_templates_toolchain_lens_scope` 或 `loop next` 那一行;資安席在真實派工裡用空檔手法降級成功一次。
