# 處置表把派工問題寫成席位發現


## 發生什麼

代碼審第一輪八席報了 32 條。我寫逐條處置表時，外家否決那一席的五條，**有三條的敘述是我編的**——那些話在它的報告裡完全不存在。

追下去原因很單純：**我照著自己的派工詞寫**。派工詞裡我列了六個問題叫它看（污染規則對不對、三個來源湊得合理嗎、吃兩種格式會不會養出混亂、測試守的是不是對的東西、會不會更容易被誤用、哪裡最像作者說服自己）。寫處置表的時候，我把那六個問題當成它的發現，逐條配上「折到哪」。

而它**真正**報的兩條——候選池的新來源沒有兌現「讓更好的系統找到的節點進池」、以及工具對候選來源的自我說明與實作漂移——**一條都沒被折**。

## 為什麼在意

跟已經記錄過的 [[Issues/編排者改寫席位引句]] 是**同一族**：動到證據本身。差別只在那次是改引句，這次是編摘要。

後果一樣、而且更隱蔽：**帳面看起來完全正常**。處置表列數對得上（32 條）、每一條都有去向、閘也過了。因為機器只數條數與比對指紋，**不會去核對每一列的敘述是不是真的出自那份報告**。

更糟的是它讓真發現消失：那兩條沒被折，而帳上寫著「折 32、放行 0」。

## 怎麼被抓到的

下一輪派了一席專門查帳，它把處置表每一列的敘述拿去原始報告與逐字稿裡 grep，四列查無出處。**不是機器抓到的，是另一個人（另一席）去對的。**

## 規矩（往後照這個做）

- **寫處置表時，每一條的敘述一律從席報告複製，不准自己重述。** 要改寫也只能壓縮，不能換意思。
- **寫完自己先查一次**：把表裡每一列的關鍵詞拿去該席報告 grep，查無出處的就是編的。這件事機器做得到，只是目前沒人叫它做。
- **不要從派工詞回推發現**。派工詞是「我要它看什麼」，報告是「它看到什麼」，兩者不是同一件事——這次就是把前者當成後者。
- **這條目前沒有機械守衛**。REVISIT:2026-10-16 評估要不要加一道檢查：處置表每一列的敘述必須能在對應席報告裡找到錨點，找不到就擋。
