# 預設起點與名冊人數收尾小問題

## 症狀

代碼審 `code-預設起點與名冊人數` 第三輪(一般分級上限輪)兩席都只報 minor,全部放行;卷證在 `governance/review-reports/code-預設起點與名冊人數/r3-*.md`。六條:

1. `_codeloop_default_base` 用 `git symbolic-ref -q --short HEAD` 取分支名,分支和標籤同名時回 `heads/<名>`,讀不到登記的遠端,退到 origin(不崩、不少擋,但用錯遠端)。
2. `t_codeloop_default_base_prefers_newest_mainline` 的「上游是本機分支」案例,上游名稱不含斜線,舊錯法(`@{upstream}` 切斜線)在這個夾具下也會過,釘不住那次修補;也沒覆蓋 detached HEAD、分支與標籤同名。
3. `cmd_loop_next` 的新舊迴圈判斷(`old_panel`)與後面代問閘的 `disposal` 是同一個條件一正一反各寫一次,日後只改一邊會分岔。
4. `cmd_loop_next` 那段註解有舊版殘留,「2026-10-13 踩到」那句出現兩次。
5. 讀 `branch.<名>.remote` 是 repo 裡取上游遠端的另一種寫法(其他地方用 `@{upstream}`);只有這一處,不抽共用,但要在說明裡寫明為什麼不用 `@{upstream}`。
6. `Systems/pitfalls-code-loop` 那行 WHY 只寫到「沒有就用 origin」,漏了「上游是本機分支不算」與「只有一個遠端就用它」。

2026-10-14 起 `_codeloop_default_base` 的本體搬成推送起點那一區的共用函式 `_lens_default_base`,`_codeloop_default_base` 留成薄包裝([[Projects/回頭重讀指紋不因主線前進失效_計劃]]〈做法〉3)。第 1 條只在 `tip=None` 那條路(代碼審預設起點)還在:回頭重讀傳頂端時改用 `for-each-ref --points-at <頂端> --format=%(refname)` 取完整參照,沒有 `--short` 的問題。修第 1 條時改的是 `_lens_default_base`,兩邊一起跑 `-k codeloop_default_base` 與 `-k reread_fp`。同一支函式的範圍收斂另見 [[Issues/推送前其他閘的範圍在合過主線時會多算]]。

## 根因

修補輪的改動沒有再過一次全新席(一般分級上限三輪,第三輪就是最後一輪);這六條都是第二輪修補時順手帶進或沒補齊的。

## 現在怎麼繞

第 1 條:分支別跟標籤同名;或手動 `code-loop check` 時直接給範圍。其餘不影響行為。

## 什麼條件算修好

- 第 1 條改用 `git symbolic-ref -q HEAD` 取完整參照再去掉 `refs/heads/`,測試補「分支與標籤同名」與 detached HEAD 兩案,且還原成 `--short` 時翻紅。
- 第 2 條把夾具上游改成帶斜線的本機分支(例如 `refs/heads/feature/base`)並放一個 `refs/remotes/feature/main` 假候選,還原成切斜線寫法時翻紅。
- 第 3、4 條:先算一個布林值兩處共用,刪掉重複註解。
- 第 5、6 條:說明與筆記補齊。
- 以上走一個小修 PR,照常過代碼審。
