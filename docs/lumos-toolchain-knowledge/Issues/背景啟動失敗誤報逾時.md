# 背景啟動失敗誤報逾時

## 症狀

隔離重現中，背景程序啟動的 `Popen` 拋出 `OSError`，等待端清鎖後仍回 rc 5、`timed_out=true`、`lock_uncertain=true`，甚至指向已不存在的鎖。hook 因此可能把明確的啟動失敗記成逾時。這是 [[Projects/過期鎖安全接手_計劃]] 第三輪正確性席 F2；原報告與凍結快照在 `governance/review-reports/code-過期鎖安全接手/`。

## 根因

`_lens_spawn_warmer` 捕捉 `OSError` 後只刪鎖，沒有把啟動結果回傳給 `_lens_wait_or_warm`；等待端無法分辨「工作根本沒開始」和「工作已開始但超時」。

## 現在怎麼繞

本分支不得標記代碼審通過或推送供共用鎖環境使用。若隔離環境出現這類訊息，先查程序是否確實啟動及鎖是否仍在，不以 `lock_uncertain` 單獨判定殘留鎖。

## 什麼算修好

先用沒有替代持有者、沒有快取的 `Popen` 故障注入驗舊碼誤回逾時；修後立即傳出可辨識的啟動錯誤與鎖路徑，hook 提示啟動失敗並把事件記成 error。保留等待已啟動背景工作的 timeout 行為，再以新審查循環核可。
