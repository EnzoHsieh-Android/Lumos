# 尺切換恆等斷言反覆不過（2026-09-14 立案）

> 白話：評測有一把新尺寫好快三週了，但它一次都沒上線過。程式設計成「等某個條件滿足就自動換尺」，而那個條件反覆滿足、換尺卻反覆失敗，程式自己印著「這不該發生」，沒人去看。

發現於 [[Projects/評測尺修復_計劃]] 的設計審 r1。

## 怎麼重現（一道會翻紅的指令）

    python3 governance/eval/retrieval_eval.py --goldset governance/eval/retrieval-goldset.json

看輸出裡那行「⚠ 未標=0 但恆等斷言不過」。2026-09-15 實跑得到：未標真的是 0/296，五組全不等
（search ranked nDCG 舊 0.8183 vs 新 0.7983；search legacy 舊 0.5042 vs 新 0.4326；
edit 綜合 P 舊 0.7636 vs 新 0.7442；只比文字 P 舊 0.7373 vs 新 0.7241；只比圖 P 舊 0.7175 vs 新 0.7085）。

## 消融怎麼做的（可重複）

複製一份評測器當探針，把題級門檻那一行改成「只要窗內有一筆已判就算有效」，跑同一道指令，
比對哪幾組差異消失。★探針是副本，正式檔沒動，跑完即刪★。

結果：五組剩兩組不等，而剩下的正好是檢查沒涵蓋的那兩條排法。

## 機械證據

- 歷史考卷 100 筆，**未標歸零 19 次，帶切換標記 0 筆**。
- 2026-09-07 排程紀錄原文：

```
⚠ 未標=0 但恆等斷言不過,切換中止(這不該發生——查 condensed 實作):
search ranked nDCG: 舊 0.8695 vs 新 0.8458; search legacy nDCG: 舊 0.478 vs 新 0.3654;
edit fusion P: 舊 0.7967 vs 新 0.7875; edit bm25 P: 舊 0.7717 vs 新 0.7771; edit graph P: 舊 0.7592 vs 新 0.7496
```

- 同一份歷史檔裡另有一組數字直接反駁「切換零重錨、門檻不用動」：某輪新尺預覽的提升幅度 131.5%，同輪舊尺只有 81.9%，**差超過 50 個百分點**。

## 為什麼這件事重要

新尺存在的理由，是解決「沒標過的候選一律計 0，於是改善檢索反而被罰分」這個已經誤導過一次真實決策的問題。**它沒上線，代表那個問題到今天還在。**
