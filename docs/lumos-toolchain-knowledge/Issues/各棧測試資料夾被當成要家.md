# 各棧測試資料夾被當成要家

> ✅ 已修正(2026-09-12):每支檔有家另認各棧的測試資料夾,修正、測試與這篇在同一個提交。下面是症狀與根因紀錄。

## 怎麼發現的

- Enzo 問「Android 的依賴注入類別、XML 這種該怎麼算家」。實跑每支檔有家的判定函式驗各種 Android 檔時,發現 `src/androidTest/` 底下的 Kotlin 測試被判成需要家的程式檔。
- 回頭對平板 POS:之前留著沒家的截圖輔助檔,就在 Xcode 的測試資料夾裡——同一型。

## 為什麼測試地圖那份不改

- 測試地圖的測試檔判定是設計審逐字定過的規格(路徑段、檔名前後綴、多段檔名三條取聯集),而且單數 Test 結尾只對 Java 認,是明文取捨:別的語言裡 `LoadTest` 這種名字常是業務名詞。
- 測試地圖要的是「哪些檔是測試、拿來配對程式檔」;每支檔有家要的是「哪些檔可以不必有家」。後者放寬到整個測試資料夾(連輔助檔一起)是對的,前者放寬會改動測試地圖的配對邊,另有影響。所以只在每支檔有家這層加。

## 修正

- 對照表之後多一個測試資料夾,這裡跟著認:測試裡有一段漂移守衛,拿對照表的每個資料夾樣式造路徑,確認都被認成測試。
- 錨定比對照表的偵測嚴:名稱結尾只看頂層資料夾、要旁邊的程式目標有同一種副檔名的檔;Gradle 的測試資料夾要緊接在 `src` 下一層。反例都釘在測試裡(`tools/androidTest/`、`ios/PosTerminalTests/`、`src/features/abTests/`、`src/scripts/`、`ABTests/`、`PaymentGatewayTests/` 裡的 .py、`LoadTests/`、`CheckoutIntegrationTests/` 裡的 .go、`scriptsTests/` 裡的 .cs、`src/androidTest/` 裡的 .py、`src/internal/androidTest/` 裡的 .go 照舊要家;`UITests/`、`IntegrationTests/` 照認;Java 的 androidTest 輔助檔與 Xcode 測試資料夾裡的 .h 照舊要家)。
- 代碼審第一輪(六席 Claude,外家撞額度缺席)三席各自抓到「頂層只看名稱結尾」會把業務資料夾放掉,加兩道錨後重跑;突變檢查八種全殺(拿掉同名資料夾錨、拿掉副檔名錨、呼叫端沒傳頂層資料夾、.NET 的點號沒剝…)。
- 代碼審第二輪(六席 Claude,外家延到第三輪):架構對齊席抓到取副檔名、算頂層資料夾各自另寫一份(改用測試地圖那支取副檔名、頂層資料夾抽成共用函式,點開頭的不算);邊界、牽連、資安三席抓到 Gradle 那條不看副檔名與深度;資安席抓到同名資料夾只看名字存在;接手的人席抓到裸名 UITests/ 被新錨擋掉。全部折入,突變檢查十種全殺。
- 平板 POS 實跑:測試資料夾 PosTerminalTests/ 旁邊有 PosTerminal/(裡面是 .swift),九支檔(含截圖輔助檔)都認成測試。
- 代碼審第三輪(六席 Claude;外家兩次都撞 Codex 帳號用量上限——第三輪那次整個帳號要到 2026-09-16 才恢復):四席各自抓到 Gradle 那條沒限定那一棧的副檔名(src/main 混了建置腳本,androidTest 裡同副檔名的檔就免家),折入;牽連席反方向指出 Xcode 測試資料夾裡的 .h 仍被擋——四席要收緊、一席要放寬,照「寧可過嚴」取收緊,.h 與 Java 的 androidTest 輔助檔寫進「沒涵蓋」並用測試釘住這個取捨;突變檢查十一種殺十種,活下來的一種是等價突變(「緊接在 src 下一層」被 src/main 的路徑前綴順帶保證)。★第三輪的修正是高風險分級的最後一輪,沒有下一輪獨立審查;三輪都沒有外家(不同模型家族)的眼光。★
