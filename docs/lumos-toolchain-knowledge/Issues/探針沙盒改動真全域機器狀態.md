# 探針沙盒改動真全域機器狀態

> 白話:情境探針會把整個 repo 複製到一個臨時資料夾、在裡面跑一個真的 Claude 來答題。問題是那個 Claude 的家目錄還是你真的家目錄。2026-09-02 跑修法 A 實驗時,`~/.claude/skills` 底下八個 skill 全被重新連到某個臨時沙盒,沙盒清掉後全部變成斷掉的連結,skill 一個都叫不出來。真 repo 跑一次 `lumos install --force` 就修回來了。

## 怎麼發現的

修法 A 實驗跑完,要調 `lumos-code-loop` skill 走推送前代碼審,叫不出來。一查 `~/.claude/skills/*` 全是懸空 symlink,指向 `/var/folders/.../lumos-probe-omhmxazc/repo/skills/`——一個已經被清掉的探針沙盒。連 `csharp-idioms`/`kotlin-idioms`/`vue-idioms` 這些非 lumos 的 skill 也一起被重連,證明是 `lumos install`(它一次裝全部 skills)帶著沙盒路徑跑過。

## 為什麼會這樣(機制)

- 探針 `make_sandbox` 把 repo rsync 到臨時目錄,`claude -p` 的 cwd=沙盒,但 **env 沒有動 HOME**,所以被測 session 的 `~/` 是真的家目錄。
- `cmd_install` 的安裝來源 `src = Path(__file__).resolve()`——在沙盒裡跑就是沙盒的 `scripts/lumos`,於是它把真的 `~/.claude/skills/*` 重連到沙盒的 `skills/`。
- 沙盒跑完被 `rmtree` 清掉 → 連結全懸空。
- **這是 [[Issues/探針沙盒能推到真遠端]](2026-08-23)的同一家族**:沙盒擋了 git push(拔 remote、pre-push 寫死 exit 1),但沒擋「對 `~/` 的寫入」。上次補的是 git 逃逸,這次是 `~/.claude` 逃逸。

## 沒查出來的部分(誠實)

★確切是哪個動作跑了安裝,沒查出來。★ 41 場的工具呼叫記錄裡沒有任何 `install`/`update`/`bootstrap` 執行;第一輪只存前 12 個呼叫,兇手可能被截斷;沙盒已刪,無法回放。懸空連結指向 s15 那題的沙盒名,但 s15 的記錄呼叫也沒有安裝。所以只能確定「安裝家族指令帶著沙盒路徑跑過」,不能確定是被測 AI 主動跑、某個子程序、還是並行 runner 的競態。**防線因此做成「不靠知道兇手」**:一道擋已知指令、一道事後抓未知路徑。

## 防線(2026-09-02 已交付)

驗證見 [[Verification/2026-09-02_探針沙盒全域防護]](兩道防線與退出碼實測)。

1. **探針設 `LUMOS_PROBE=1`**(`scripts/scenario_probe.py` run_one env);`cmd_install`/`cmd_uninstall`/`cmd_update`/`cmd_bootstrap` 開頭 `_refuse_if_probe()` 看到就 exit 2 拒絕。三個入口(install / update / install.sh)實測都退 2。
2. **事後健康檢查**(`global_skills_health()`):探針每批跑完掃 `~/.claude/skills`,懸空或指向 `lumos-probe-` 的連結 → stderr 紅字列出、喊人 `lumos install --force`。

## 殘餘風險與待議

- `LUMOS_PROBE` 只擋 lumos 那四個指令。被測 AI 若**直接** `os.symlink` / `ln -s` 改 `~/.claude`,第一道擋不到,只有第二道事後抓、且要下次跑探針才抓到。
- 乾淨解=給 `claude -p` 拋棄式 `HOME` / `CLAUDE_CONFIG_DIR`,但那樣被測 session 就吃不到真的 skills+hooks——**那正是探針要量的對象**,隔離=改變被測環境。兩難未解,列此待有人撞到真的手動改 `~/.claude` 案例再重議。
- REVISIT:2026-10-02 若這一個月探針又出現一次健康檢查報紅,就正式評估 HOME 隔離(接受「量的是隔離環境」的代價)。
