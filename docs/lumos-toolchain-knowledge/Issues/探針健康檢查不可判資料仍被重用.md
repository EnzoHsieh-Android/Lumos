# 探針健康檢查不可判資料仍被重用

第三輪凍結差異 `governance/review-reports/probe-boundary-remediation/r3-snapshot.patch` 有兩條未處置重大發現，完整席報告 `r3-correctness.md`、`r3-boundary.md`，編排者重現結果 `r3-reproduction.json`，機械判定 `r3-gate.txt`。本 Issue 同時記這兩條相連的資料有效性缺口；`code-probe-boundary-remediation` 第三輪 FAIL，不得用前兩輪 PASS 或251項綠測試替代。

1. 模型 runner 若在執行後、解析時拋例外，流程跳過這一場的 `global_skills_health()`；臨時 repo 的 a 題拋錯且健康檢查回報壞連結時，b runner 仍先被呼叫。當場健康檢查必須在下一題前完成，無論 runner 是否正常回傳；損壞或無法檢查即停批、fatal/inconclusive、退出3。
2. 最終健康檢查拋例外時，探針雖回3並標整批 fatal/inconclusive，逐場仍是 `reason=ok`、有效分母2；消融讀取器 `is_valid` 接受兩列、`needed(a)=0`、`collect_skills_health=[]`，會把不可判資料合併且不補跑。修法要讓結果檔本身足以讓所有既有消費端排除或拒收整批，不能只靠呼叫端看退出碼。驗收需用真 `load_results`、`needed`、`merge` 與 `collect_skills_health` 跑紅綠，不只看探針 JSON 的 `fatal` 欄。

處置上限：本案代碼審已跑三輪（r1九條折入、r2兩條折入、r3兩條 major 未處置）；不能自行開 r4 或留 `code-loop pass`。重驗入口是使用者裁決額外審查範圍後的下一次修補，並保留原 r3 FAIL 卷證。若沒有授權，現狀維持 open，圖譜 Verification 為 fail。
