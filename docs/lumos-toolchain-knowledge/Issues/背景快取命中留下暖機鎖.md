# 背景快取命中留下暖機鎖

## 症狀

派工端先取得 `.warming` 鎖並啟動背景程序；另一個直接呼叫同範圍的程序先寫出快取後，背景程序一進場讀到快取便回成功，但鎖還在。快取 TTL 過後，新請求只見殘留鎖，無法重新暖機。這是 [[Projects/過期鎖安全接手_計劃]] 第三輪正確性席 F1，不代表已在生產發生。原報告與凍結快照在 `governance/review-reports/code-過期鎖安全接手/`。

## 根因

等待端不再按舊持有狀態刪鎖是前輪必要修補；背景端雖在完成新計算後核對鎖內啟動者並清鎖，卻在快取早期命中分支直接返回，沒有經過這段清理。

## 現在怎麼繞

本分支不得標記代碼審通過或推送供共用鎖環境使用。若隔離環境出現這種殘留，依計劃的人工復原程序先確認背景工作都已停，再移除鎖；不能只憑鎖內派工者 PID。

## 什麼算修好

先用屏障測試固定「背景尚未讀快取→另一程序先寫快取→背景進場命中」並驗舊碼留鎖；修後背景端在早期快取出口及正常完成出口都只清自己持有的鎖，等待端仍不得清別人的鎖。另驗快取 TTL 後可重新暖機，再以新審查循環核可。
