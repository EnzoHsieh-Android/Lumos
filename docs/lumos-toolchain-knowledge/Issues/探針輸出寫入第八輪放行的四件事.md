# 探針輸出寫入第八輪放行的四件事

代碼審 code-probe-postreview-dispatch-ledger 第八輪附理由放行的四件小問題，集中在這裡追蹤；細節與原始報告見 `governance/review-reports/code-probe-postreview-dispatch-ledger/r8-intake.md`。

## 症狀

1. 歷史檔追加不看檔案擁有者：別人在共用目錄預先放好的普通檔（只有一個名字、可寫），探針會把紀錄追加進去（r8 SEC8-01，同使用者實驗）。
2. 測試裡有三種逾時寫法：測試執行器的整支逾時、幾處就地借鬧鐘、第七輪新增的借鬧鐘工具（r8 ARCH8-02）。
3. 在 root 身分、而且 `/dev/tty` 節點不存在的極簡沙盒裡，字元裝置那支測試會假紅（r8 PLT8-01）。
4. 「終端讀得慢時大量輸出照樣寫完」那條沒有前置斷言證明現場會擋住寫入；本機 macOS 改壞版本會翻紅，Linux 沒驗（r8 PLT8-02）。

## 根因

1. 歷史檔的規則只擋「會寫到別處或卡住」的型別與多名字，沒把「別人擁有」算進去；修前就是這樣。
2. 第七輪需要「借完鬧鐘還回外層」的行為，既有兩種寫法都沒有，於是另寫一個。
3. 測試以「沒有控制終端時開 /dev/tty 會失敗」當現場，但節點不存在時開跑前檢查走的是「新建檔」分支。
4. 能不能翻紅取決於 pty 緩衝大小與讀寫速度，這是環境假設，沒寫成斷言。

## 現在怎麼繞

1. 不要把 `--history` 指到別人可寫的共用目錄；紀錄只有通過數與耗時，不含密鑰；Linux 的 protected_regular 會擋 sticky 目錄裡的他人檔。
2. 新測試要借鬧鐘時用 `_guard_hang`；其他寫法暫不動。
3. 在一般 Docker、podman 與 CI 環境都有 `/dev/tty`，不受影響。
4. 推送後看 CI 那條斷言在 Linux 上的行為。

## 什麼條件算修好

1. 決定歷史檔要不要加「擁有者是自己」的條件；要的話開跑前檢查與 `_open_history` 一起加，並各補翻紅測試。
2. 全 repo 的測試逾時工具收成一套，或在測試指引寫明三者各自的用途。
3. 字元裝置測試先斷言 `/dev/tty` 節點存在，不存在就明講沒驗到而不是紅。
4. 在 Linux 上確認拿掉改回阻塞會翻紅；不會的話補前置斷言（先用不阻塞的寫法證明這個 pty 確實會擋住大量寫入）。

REVISIT:2026-11-09 看推送後 CI 上 pty 大量寫入那條在拿掉改回阻塞時是否翻紅,並決定歷史檔擁有者檢查與測試逾時工具整併要不要做
