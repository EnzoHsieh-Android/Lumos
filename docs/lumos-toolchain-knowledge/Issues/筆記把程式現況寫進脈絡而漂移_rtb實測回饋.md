# 筆記把程式現況寫進脈絡而漂移_rtb實測回饋

白話:rtb 專案做完 Phase 14(AI 退出加額決策)之後,稽核發現圖譜裡有四成的「現況句」已經跟程式碼對不上,而且大多躲在標成「為什麼」的摘要行和已完成計劃的「現況」段裡——這兩處是 agent 打開筆記時最先讀到的地方(★2026-09-27 工具組更正★:原稿寫「hook 與派工鏡頭最常推到眼前」,對照程式碼不成立——兩者都不帶摘要行與正文,見〈工具組評估〉②)。機械健檢看不到這種漂移,因為句子裡的名字都還在,只是意思變了。這跟 [[Projects/Lumos定位_程式碼為主脈絡為輔_計劃]] 的判斷一致:圖譜重述程式現況時,錯的那份會先被讀到。

## 證據

- 稽核全文(含 55 句逐句對照表,每句附筆記原句與程式 file:line):`governance/audits/2026-09-27-rtb-notes/notes-audit.md`。
- 稽核對象:rtb main 4783e08 的 87 篇筆記;稽核員唯讀,沒改 repo。
- rtb 端處理:22 句全部重新對照程式碼後改寫,另開 `Issues/Phase14後筆記漂移清理`(rtb repo)記根因。清理過程本身又被審查抓到 5 句改寫仍不對、3 處紀錄寫錯——**寫筆記的人即使專門在修漂移,也會寫出新的漂移句**,所以規範要靠工具提醒,不能只靠自律。

## 漂移集中在哪三種寫法

| 寫法 | 抽樣 | 已漂移 | 為什麼會漂 |
|---|---|---|---|
| 「目前沒有 X / 還沒 / 尚未 / 只有 N 種 / 共 N 支」 | 20 句 | 15 句(75%) | 下一個階段把 X 做出來,沒人回頭改這句 |
| 已完成計劃的「## 現況」段 | 7 句 | 6 句 | 開檔時的快照,讀起來卻是現在式;只有明標「以程式碼為準」的那篇沒被誤讀 |
| 掛 WHY/RULE/PITFALL 標籤、內容其實是現況的摘要行 | 隨機 30 條約一半 | 其中 3 條已漂移 | 標籤讓讀者當成決策脈絡,不會去程式碼核對 |

寫死的數值常數(例如某個上限 60 秒)抽樣 0 漂移——它們改動時通常連測試一起改,會被抓到。

## 候選修法(給工具組評估,排序依影響)

1. **【寫法規範+提醒】禁用會過期的現況句型。**「目前沒有/還沒/尚未/只有 N 種/共 N 支」在 WHY/RULE/正文裡出現、同一行沒有「以程式碼為準」+查詢指令時,由 `prose-lint` 或 `lint` 提醒;規範改成二選一:寫成 `FACT:` 並附查詢,或寫成綁事件的 `REVISIT:`(例:「分析端有啟動程式時回改本句」)。
2. **【工具】計劃轉 done 時,「現況」段自動降級。** `lumos set <計劃> status done` 時,在「## 現況」標題旁自動加「(開檔時的快照,已過時;以程式碼為準)」;impact hook 與派工鏡頭推 done 計劃時不帶現況段。rtb 這次手動在 5 份已完成計劃(Phase 6、9、10、11B、14)補了同樣的標語;rtb 共 13 份已完成計劃,其餘沒補。
3. **【寫法規範+lint】摘要行只放程式推不出的東西。** 摘要行設長度上限(rtb 有 122 條超過 300 字);函式名、參數值、錯誤字串、測試名清單不進摘要,測試綁定只留 `[test:]`。另一個觀察:WHY/RULE 標籤被拿來裝現況,可以考慮 lint 對「WHY 行裡沒有出處、只有函式名與數值」的情形提醒。
4. **【工具】doctor 的 S 段提醒別每次提交都重寫進治理帳。** rtb 治理帳 52% 是同一批「22 篇 Systems 沒被重新確認」「索引漏列」提醒反覆寫入,6 天沒人處理,已變成背景雜訊;建議只記變化或去重,並給一條「派無脈絡 agent 跑 `lumos self-audit`」的出口。
5. **【量測,新增寫帳部分須 Enzo 裁】「是不是以程式碼為主」目前在治理帳上答不出來。** impact/search/context/decisions 在 rtb 帳上 0 筆,hook 推送也刻意不記篇數。
   - 先做不用裁的:用既有唯讀儀器 `governance/eval/lens-utilization/recount.py` 與 [[Projects/推播miss量測_計劃]] 的做法,從逐字稿量 rtb 的「推了什麼、之後讀了什麼」。稽核員這次沒用到它,改翻逐字稿得到旁證:讀程式碼約 4,400 次、lumos 查詢 28 次,80 次改程式前都先讀過程式碼;筆記主要經派工鏡頭附進子代理提示(170 次派工 127 次)。
   - 要不要讓 impact/search 寫帳、hook 事件加「附了幾篇」欄位:撞 [[Projects/全repo審視_計劃]] F08 的否決與 [[Projects/派工鏡頭注入_計劃]]「不擋不驗不記不量」,**只能由 Enzo 裁**,不代筆。

## 意涵

- 最危險的路徑是:工作本身以程式碼為主(旁證支持),但子代理沒有主對話的脈絡去懷疑它讀到的筆記。(★2026-09-27 工具組更正★:原稿寫「派工鏡頭裡夾著過時的摘要行」——鏡頭只貼合約行,過時內容是子代理照鏡頭列的路徑自己打開筆記讀到的。)修法 ②③ 縮小的是「打開後讀到什麼」。
- 語意漂移只有「重新對照程式碼」抓得到;修法 ① 是在寫的當下擋掉最常漂的句型,比事後巡檢便宜。

## 工具組評估(2026-09-27,評估當下的快照;程式現況以程式碼為準)

Enzo 裁的目標(d1):**筆記不留存程式碼推得出來的東西**。所以修法方向是「寫的當下就別寫進去」,不是 rtb 原稿提的「標成 FACT+查詢」或「掛 REVISIT 等人回改」——那兩條是把現況留著再想辦法維護,正好是目標要避免的。

- **前置缺口(①③ 都卡在這)**:筆記健檢的提醒在提交時不會出現。單篇健檢只提醒時回 0,提交前的檢查只有非 0 才印輸出,所以 2026-09-21 上線的四條脈絡標記提醒,除非有人手動跑健檢,寫的人看不到。重查:`grep -n "return 1 if errs else 0" scripts/lumos` 與 `grep -n 'lumos" lint' scripts/hooks/pre-commit`。先補「提交時印出這次動到的筆記的提醒,照樣不擋」,①③ 才有意義。
- **① 會過期的句型**:可做且便宜——掛在既有的摘要行標記檢查旁邊,逐篇跑,只唸正在改的那篇,不會一次跳出舊帳。本 repo 評估時掃到這類句子 195 處(摘要行 44、正文 151),已標以程式碼為準的 1 處。提醒語改成「這是程式碼推得出的現況:刪掉;若是因為某個理由才重要,改寫成帶出處的 WHY」。
- **② done 計劃的現況段**:前提一半不成立(見上方更正)——兩個推送機制都不帶正文,「推送時不帶現況段」不用做。剩下有用的是讓已完成計劃的現況段不再以現在式留著;形狀待裁(見下方待裁)。
- **③ 摘要行太長、塞函式名與參數**:跟目標一致。不能設硬上限——本 repo 評估時摘要行 2427 條、超過 300 字的 412 條,一開就是幾百條提醒。改成跟①同路:只唸正在改的那篇,判準是「反引號識別字、數值、測試名佔大半」。
- **④ 體檢提醒重複寫帳**:問題為真且本 repo 更嚴重(評估時 86,594 筆裡約 94% 與上一次體檢逐字相同;rtb 52%),寫入端刻意不去重(`grep -n "dedup 留給讀時" scripts/lumos`)。但「14 天沒人處理就推播」的提醒鏈與「這輪沒點名=已修好」的判定都靠逐次重寫,改成只記變化要連讀端一起改——風險高,另開計劃走 design-loop。跟 d1 目標無關,獨立排程。
- **⑤ 量測**:對 d1 目標不是必要條件。既有量測腳本可唯讀指向 rtb、不用改碼,但 rtb 的改檔前推送真正帶清單的只有 3 次、而且它不記讀了哪些程式檔;要量派工鏡頭得新寫解析,等於翻 [[Projects/派工鏡頭注入_計劃]] d1「不量成效」——評估時未裁,暫不做。
- **順手發現**:派工鏡頭掃合約行的函式說明寫「不掃正文」,實際逐行掃整份檔(`grep -n "不掃正文" scripts/lumos`);[[Projects/Lumos定位_程式碼為主脈絡為輔_計劃]] 自己寫的「反向規則目前沒有」在 2026-09-21 第三階段交付後已部分過時——正是本篇講的句型。

**已裁(2026-09-27)**:d2 舊筆記不回頭清;d3 現況出口收窄成只准寫程式碼答不了的;d4 done 計劃現況段收成一句當時的問題;d5 要機械擋、不只提醒。d5 的理由有前例:[[Verification/2026-08-21_L4交叉審計30節點清帳]] 已寫下「6 月首跑就知道計數型主張最會漂,這次證明知道了仍照寫」,當時的處置(補日期)同樣是靠自律。

**擋什麼的初步實測(2026-09-27,單人目測,樣本小)**:把近一個月 473 個提交裡新增的 25,282 行筆記,各跑三種候選偵測,每種抽 12 條看:
- 「目前沒有/尚未/只有 N/共 N」句型:命中 138 行,抽樣裡真是「程式碼推得出、會過期的現況」約 3–4 條,其餘是帶日期的歷史量測、流程狀態、數學事實——**準度撐不起硬擋**。
- 摘要行識別字密度高:命中 161 行,大量是合約行、測試綁定、已附查詢的 FACT——**撐不起硬擋**。
- 程式行號引用(`檔名:行號`):命中 68 行,抽樣 12/12 都是會隨改碼漂掉的行號——**可以硬擋**。
重跑:近一個月筆記新增行 `git log --since=2026-08-28 --no-merges -p --unified=0 -- 'docs/lumos-toolchain-knowledge/*.md'`,偵測正則見本段三條描述。
