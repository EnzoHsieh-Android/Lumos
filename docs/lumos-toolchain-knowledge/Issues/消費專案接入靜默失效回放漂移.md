# 消費專案接入靜默失效回放漂移

## 症狀

`lumos loop replay 消費專案接入靜默失效 --golden governance/replay/消費專案接入靜默失效/verdict.json --repo .` 回 rc1:凍結時 rc=0 fails=[],現在 rc=1 fails=['留痕'],原因是「r1 intake sha256 與帳面不符(事後被改)」。改前與改後的程式結果相同,主線既有。

## 根因

`governance/review-reports/消費專案接入靜默失效/r1-intake.md` 記帳後,功能提交 69d5fddf 又改了它;帳上記的是改前的指紋。卷證記帳後不准改(記憶「記過帳的 intake 別改」)。

## 現在怎麼繞

週跑回放會持續報這一筆紅燈;知道原因即可,不影響其他迴圈。

## 什麼條件算修好

用 git 歷史找回記帳當時的 intake 內容還原那份檔(指紋對上就回到一致);還原不了就照回放的重凍程序帶 `--note` 寫明原因重凍。修好後跑一次回放確認一致。
