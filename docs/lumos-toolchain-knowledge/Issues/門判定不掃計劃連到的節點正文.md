# 門判定不掃計劃連到的節點正文

> 白話:規格閘判計劃「風險高還是低」時,只在計劃自己的文字裡找金流、對外送出這類詞。計劃寫「做法見」加一個雙中括號連結、把真正要做的事放在那個節點的正文裡,門看不到,照樣判風險低、不派審。

## 症狀

代碼審 code-規格閘不做節 r5 資安席實測:計劃只寫「做法見」加一個連到 Systems/外部做法 的雙中括號連結,「實作退款流程並寄送通知信」寫在那個沒有風險標籤的 Systems 節點正文裡,`lumos spec-gate` 判風險低、PASS,不做清單也沒有被略過的詞,推送前不要求任何輕量審。

## 根因

門判定(`_door_judge`)的訊號 ② 只看連到的節點有沒有 ★IRREVERSIBLE★/★CHECKPOINT★ 合約行或 risk/ 標籤,不掃它們正文的關鍵字;關鍵字表(訊號 ①)只掃計劃本身。這是門判定原本的設計邊界,不是不做節那次改動造成的。同族的行內程式碼(反引號裡的字原本也不掃,刻意留給範例用)已在 2026-10-14 門規則版本 5 起照掃(代碼審 code-規格閘不做節 r6 資安席:落單反引號會把後面整段藏起來),見 [[Systems/規格閘]];這篇剩下的只有連到的節點正文。

## 現在怎麼繞

計劃自己的文字本來就要寫清楚這一版要做什麼(〈做法〉與條款);只用一句連結把要做的事外包給別的節點,本身就是寫錯計劃,代碼審與設計審照規矩看得到。連到的節點若碰金流、對外送出、不可逆或守衛面,給它加 risk/ 標籤,門的訊號 ② 就會判風險高。

## 什麼條件算修好

二選一:①門判定把計劃 lands_in、related 與正文連結指到的節點正文也掃一次關鍵字(要先量全 vault 會讓多少份計劃翻成風險高——連到大節點的計劃很多,訊號 ② 實測已有過半 doing 計劃因連結判高),並升 `_DOOR_RULE_VERSION`;②確認逃逸帳裡沒有任何一筆是這個盲區造成的,在這篇寫明「以撤除條件與逃逸帳兜底」並關掉。

REVISIT:2026-12-15 查逃逸帳每一筆帶 plan 的,看那份計劃是不是只靠連結把要做的事放在別的節點、最後一筆規格閘留痕是風險低;有一筆就照〈什麼條件算修好〉① 開計劃,一筆都沒有就照 ② 關掉這篇
