# 撤除條件檢查末輪遺留四項

接手:[[Projects/筆記格子寫法與過期檢查_計劃]] 第 3 步。四項都不會誤放行或誤擋正常操作(第三輪兩席都判 minor、blocking 0)。

1. **對續行行號下表態不會報錯**:`drift ack <節點> <續行行號> --kind retire` 會記下那一個實體行,但判定給的原文是整條,這筆表態永遠對不上;指令照樣回成功。擋下時印的行號是條目第一行,照提示打不會踩到,要手打錯才會。改法:retire 種類的行號不是摘要條目第一行就擋下並提示。
2. **印出訊息途中出錯會記兩筆帳**:撤除條件那支先記帳再印清單,印的時候若拋例外,兜底會再記一筆 warned,同時回 0 把該擋的放行。目前找不到會讓印出拋例外的輸入(控制字元已清)。改法:記帳挪到印完之後,或兜底只在還沒記過帳時寫。
3. **兜底那筆帳的條數記 0**:沒跑完時記 `handle: 0`、`listed: 0`,讀帳的人會當成判完沒事;舊句檢查判不了時記 null。改法:兜底記 null。
4. **記帳的測試沒釘全**:只判不了時記 warned、成立時 hard 與 nodes、起點不是字串、例外兜底那一筆,拿掉都不會紅。改法:補「預算用完只判不了」與「判定丟例外」兩個情境的帳斷言。

另:寫不進帳時沒有像舊句檢查那樣在使用者快取留痕(第三輪架構對齊席)。這支一次推送最多一筆、不帶逐條清單、節點上限 20,不需要舊句檢查那個為兩週量測做的補記檔;通用寫入器寫不進去時已在 stderr 講一句。照留,不在這篇的待辦裡。

修法(2026-10-02,跟第 3 步一起):續行行號擋下;rc 判完就定,印出與記帳各自兜、出錯只講一句、不改判定、不重記帳(第 2 項原本提的「記帳挪到印完之後」照做:先印後記,同一道閘的 m1 與 c1 到 c5 也是這個順序;第 3 步代碼審 r1 曾改成先記後印、r2 架構對齊席指出跟鄰居相反,改回);兜底條數記 null;記帳的斷言補齊,測試 t_slots_retire_issue_followups。第 3 步代碼審通過、推上主線後結案(第 3 步代碼審 r1 合約圖譜席:審查前就結案,折回時沒人回頭)。
