# 多平台設定下測試指令被默默略過

> ★已結案(2026-09-11)★:工具鏈那一側已修——合約測試閘逐平台處理、訊息點名平台並講明最上層指令不生效,見 [[Verification/2026-09-11_多平台缺指令逐平台處理]];消費專案 pos-ios 設定側也已修好。還掛著的只有 mOrangePos 要不要更新工具(人裁,REVISIT 2026-10-11)。

## 發生什麼

- 2026-09-11,另一個會談在 pos-ios 推送,推送檢查印出「這個專案沒設測試指令(.lumos/config.json 的 test.run_cmd),受波及合約的測試沒有跑——合約測試閘等於沒開」。
- 但那份設定**有**寫測試指令,寫在最上層 `test.run_cmd`。同一份設定也宣告了 `platforms`(iOS 與 maestro 兩個平台,2026-09-10 截圖基準驗收那批工作加的)。
- 工具讀設定的規則是:一宣告 `platforms`,就只讀各平台自己的 `platforms.<平台>.run_cmd`,最上層那條不生效。所以兩個平台都「沒有指令」,閘整批放棄。

## 為什麼會這樣(兩個坑)

1. **訊息沒跟上既有規則**:[[Projects/guard殺傷力驗證_計劃]] 2026-07-10 r3 定了並存優先序——「config 有 platforms 鍵即整組走多平台、test.run_cmd 不生效**並印告警**」。告警只做進 guard kill 那條路;2026-08-22 才加的合約測試閘讀的是同一份設定,卻沒有照印,反而印一句會讓人以為根本沒設的話。這是「規則散在兩處,只做到一處」。
2. **一個平台沒指令,整批放棄**:合約測試閘逐支跑時,碰到第一支所屬平台沒寫指令的測試就回 `no-config`,整批一支都不跑——連其他平台有指令的也一起放棄。本機另一個專案(mOrangePos)的設定也是兩個平台都沒寫指令,而且綁了一條 `maestro:` 前綴的測試,碰到就會觸發這個坑。

## 已做(消費專案那一側)

- pos-ios:`run_cmd` 搬進 `platforms.ios`,拿掉被略過的最上層 `test`,在設定檔的說明欄補一句為什麼;maestro 平台刻意不給指令(目前沒綁合約測試,要綁之前先決定推送時跑不跑需要模擬器的畫面流程)。
- 驗證:`lumos bound-tests --diff 232a6bc~1..232a6bc`,修之前 `no-config`、一支都沒跑;修之後 34 支真跑全綠(145 秒)。iOS 那道閘會檢查每支的輸出有沒有「Executed N tests」(N ≥ 1),所以「真的跑了」有機器證據。
- 這份設定屬於 2026-09-10 截圖基準驗收那批**還沒提交**的工作,提交時機等人裁。

## 修了什麼(工具鏈那一側,2026-09-11 已落地)

- 合約測試閘:有指令的平台照跑;沒指令的平台那幾支列成「平台 X 沒設指令,沒跑」;全部都沒指令才維持 `no-config`。
- 訊息:點名缺指令的平台;設定裡同時有 `platforms` 與最上層 `test.run_cmd` 時,照 2026-07-10 規則明講「多平台模式下 test.run_cmd 不生效,搬進 platforms.<平台>.run_cmd」。
- 優先順序本身不改——不做「多平台沒寫就退回最上層」:那會讓同一份設定在兩條路上各有一種意思。

## 沒解決、要人裁的

- mOrangePos 專案裡的 lumos 是很舊的版本,**還沒有合約測試閘這道檢查**,連 `--version` 都沒有。它的測試不跑,主因是工具太舊。更新會一次帶進這幾週的所有新閘,推送流程會明顯變嚴,要人決定。
