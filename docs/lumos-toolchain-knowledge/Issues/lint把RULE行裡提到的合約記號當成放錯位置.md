# lint把RULE行裡提到的合約記號當成放錯位置

## 怎麼發生的

2026-09-22,另一個專案(rtb-production-agent-demo)接上預告合約機制時回報:他們寫了一條 `RULE:` 行,內容是在說明「這條原本標成硬合約、後來降成規則」,句子裡逐字寫出了那個硬合約記號。`lumos lint` 把它判成「合約標記放錯位置」。

## 為什麼是誤判

合約抽取那一支(`extract_contracts`)刻意只認 KEY 行開頭的標記,註解寫得很明白:錨定行首就是為了排除「散文中提到標記」的誤報,例如方法論文件在講解標記怎麼用。lint 這一條檢查沒有照同一個判準,所以比抽取那支寬,才會把敘述句撈進來。

## 現況與影響

不擋人:回報者改個說法就過了。但它會讓「寫筆記解釋某條規則的來歷」這件事被工具唸,長期會訓練人避開正確的寫法。

## 修的時候要注意

這個 repo 有過「同一種錯連冒四處」的紀錄。動手前先問一次:還有哪幾支檢查在做「找 summary 裡的合約標記」,判準是不是都跟抽取那支一致。
