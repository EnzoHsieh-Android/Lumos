# detekt逗號佔位符代碼審放行的小問題

## 症狀

代碼審 code-detekt逗號佔位符 第 1 輪報的小問題裡,有四條附理由放行,記在這裡下一批一起判(卷證 `governance/review-reports/code-detekt逗號佔位符/r1-intake.md`):

1. 改動檔的路徑文字裡剛好含 `{LINT_FILES}` 或 `{LINT_FILES_CSV}` 字樣時,替換本身只換一次,但執行入口對換好的成品命令再查一次「有沒有佔位符」,判成沒換掉、不跑;新增告警閘把這條記成環境問題自動放行(正確性甲席實跑重現)。改動前的舊佔位符就是這樣,不是這次引入。
2. 開程序遇到「參數太長」時,失敗原因用一個傳入的字典帶回;同一條呼叫鏈其他失敗都用回傳值表達(架構對齊席)。
3. 路徑含逗號或分號的檔借用「檔太大沒檢查」那份清單與同形指紋,但指紋公式在兩支函式各寫一份,擋下訊息的放行提示寫法也跟大檔不同;清單裡的條目靠各消費處判種類(架構對齊席)。
4. CI 裝 detekt 是第一個不走 pip 的工具下載(下載加比對雜湊),跟既有不驗雜湊的下載腳本不同一套(架構對齊席標「判不準」交編排者;detekt 不在 PyPI,pip 這條路走不通)。

## 根因

1. 執行入口「佔位符沒換掉就不跑」的保險,看的是換好的成品命令,分不出「沒換」和「換進去的路徑剛好長得像佔位符」。
2. 抽出開程序那一步時,為了不改既有回傳形狀(兩個呼叫點與多處測試用二元組),把新的失敗種類放進選填參數。
3. 分隔字元路徑想沿用大檔的放行機制,但只抽了清單、沒抽指紋與訊息。
4. CI 需要一支非 Python 工具,專案原本沒有這類下載的共用做法。

## 現在怎麼繞

1. 路徑含佔位符字樣的檔極少見;遇到時改檔名。這個 repo 的威脅模型只防單人、AI 依序操作的誤用,不防刻意取名繞閘。
2.–4. 行為正確,不用繞;只是寫法不一致。

## 什麼條件算修好

1. 執行入口在替換前判「宣告命令有沒有佔位符、檔清單是不是空的」,不再對成品命令做字面判斷,並補一條路徑含佔位符字樣照常跑的測試。
2. 開程序的失敗種類跟其他失敗一樣走回傳值,或判定不值得改並在這裡寫明。
3. 大檔與分隔字元路徑的指紋共用一支函式、擋下訊息的放行提示寫法一致。
4. 第二個非 pip 工具要進 CI 時,把下載加比對雜湊抽成共用步驟,或判定兩支各寫一份可以接受。
