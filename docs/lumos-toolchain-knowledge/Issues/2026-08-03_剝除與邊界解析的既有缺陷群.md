# 2026-08-03 剝除與邊界解析的既有缺陷群

## 怎麼被發現的

修「多詞搜尋回退」時，code-loop r2 順帶挖出兩條既有 major（`load_vault` 幽靈邊、`guard trace` 假佐證），
根因是 `FENCE_RE` 看不見未閉合圍欄。**那說明這個區域的既有缺陷密度比預期高**，
於是 r4 專設一席**潛伏缺陷獵人**（不審 diff，只拿那副鏡頭掃既有碼）。

結果：**7 條，5 條 major，全部附重現。**

## 五條 major

### ① `FENCE_RE` 還活在 refcheck 家族三處 ★最嚴重★ —— ✅ 2026-08-03 已修

`scripts/lumos:1079`（doctor Check P）、`:8024`（`_refcheck_scan`）、`:10447`。

```python
FENCE_RE = re.compile(r"^```.*?^```", re.S | re.M)   # ★錨在第 0 欄★
```

收尾圍欄**縮排一格**就會跟下一個區塊的開頭錯配，把中間的真散文整段當程式碼吞掉。主對話自驗：

```
FENCE_RE 剝完後可見:      ['`scripts/pay.py`', '``']
逐行 toggle 後可見:       ['`scripts/pay.py`', '`scripts/real.py:999`']
```

**消費端是治理機制本身**：`cmd_refcheck`、`loop status --gate` 的 **G1 硬閘**、
`_impact_reverse_lookup`（**Edit/Write 前自動注入「必看合約」的 hook**）。

> 一個縮排的 ``` 就能把某節點的鐵則警告**靜默關掉**，或讓 G1 對一份真的有壞引用的 spec 放行。

★**修法約束**★：**不能**直接換 `_strip_code_text`——它連 inline code 一起剝，
而 refcheck 要的正是 inline code 裡的路徑宣稱。需要「只剝圍欄、留 inline」的新原語。

### ② `cmd_archive:6713` 活守衛護欄用 raw 全文

同一個語意（「這篇 Verification 有沒有提到這個守衛測試」），`guard trace` 剝 code、`archive` 不剝
→ **兩份對同一篇檔給出相反答案**。只在 ```csharp 區塊裡「示範」過方法名的 Verification，
會被 archive **永久**排除在歸檔外，並對外宣稱它「背書存活守衛」。

### ③ `spec-trace:2321/2343` 用 raw 抽 `[SN]`

**`spec-trace` 自己的輸出格式就長 `✓ [S1] ← …`** ——把指令輸出貼進 Verification 當紀錄（極自然的動作）
就等於**認領了全部條款**，rc 從 1（有未認領）翻成 0。另有重複列同一篇的去重 bug（`:2345`）。

### ④ 未閉合 frontmatter → 合約蒸發 ＋ 幽靈邊 —— ✅ 2026-08-03 已修

`split_frontmatter:95-104` 假設 frontmatter 成對；少一個收尾 `---` 就整份檔當 body 索引。主對話自驗：

```
$ lumos contracts            → broken.md 的 ★INVARIANT★ 完全不見
$ lumos backlinks good       → broken.md 產生了一條假邊
$ lumos doctor | grep broken → 0
```

**寫入端 `load_raw_for_edit:5948` 明確 `raise ValueError("frontmatter 未閉合")`，讀取端默默照收。**

### ⑤ BOM 讓 `lint` 的 decisions 守衛靜默關掉

`scripts/lumos:2216` 是全檔 40 幾處讀 vault `.md` 裡**唯一**用 `utf-8` 而非 `utf-8-sig` 的。
BOM 檔 → `startswith("---")` 為 False → 整個 decisions 結構守衛跳過。

> 那個守衛的存在理由正是 2026-07-29 外審的「**綠燈 ≠ schema 有效**」——結果它自己被一個 BOM 關掉。

## 兩條 minor

- **`cmd_lint:2230`** 用 `^\s*-\s` 數**所有**破折號行，把巢狀子清單當獨立決策 → 對合法節點誤報，
  且訊息叫人「用 `decision-add` 重寫」，照做會**毀掉合法的巢狀清單**。
- **JSONL 讀迴圈四份以上**只 catch `ValueError`，一行合法但非物件的 JSON → `gov`／`loop status` 拋 `AttributeError`。
  （拋例外相對安全，但那是治理帳唯一的讀取入口。）

## ★為什麼不與多詞回退同批修（2026-08-03 決定）★

1. **與該功能無關**——是根因分析的副產品，不是它引入的。
2. **5 條 major 動的是治理閘本身**（G1、impact hook、archive、spec-trace、contracts 登記簿），
   混進同一個 commit 會讓因果不可審。
3. ①的修法需要**新原語**（只剝圍欄、留 inline），那本身該有自己的設計與審查。

**待人裁定修復範圍與順序。**

## 誠實邊界

- 7 條裡**主對話只自驗了 ①④ 兩條**（最嚴重的兩條）；其餘 5 條採信獵人席附的重現，**未獨立複驗**。
- 獵人席另列了 3 條「給不出重現、依紀律不標」的疑慮（`discover_test_methods` 的跨行註解正則、
  `make_resolver` 的 basename fallback、`cmd_archive:6743` 的連結正規化用 raw 掃）——**那不是 clean，是未達門檻**。

## ✅ ①④ 已修（2026-08-03，人裁「照建議」＝先做自驗過的最嚴重兩條）

### ① 的修法：抽出唯一的 fence 判定，並分出兩檔

```
_visible_lines(lines, keep_fenced=False)   ← ★全檔唯一★的 fence toggle 判定
   ├─ _strip_code_text(text)       剝圍欄 ＋ 剝 inline code（search／load_vault／guard trace）
   └─ _strip_fences_text(text)     只剝圍欄、★保留 inline code★（refcheck 家族）
```

三處 `FENCE_RE` 全部收編（`doctor Check P`／`_refcheck_scan`／token 抽取），
★`FENCE_RE` 常數本身已刪除並留墓碑註解★——留著一個危險原語就是邀請別人再用一次。

**驗證**：縮排收尾的圍欄之後那條真宣稱（`scripts/ghost.py`）現在抽得到並正確判 missing；
翻紅釘（改回成對正則）翻紅 2 條。

### ④ 的修法：不動解析語意，把讀取端的沉默補成響亮

改解析語意會牽動一堆讀取端。改為 **doctor 新增一道檢查**，且放**硬 issue**——
`doctor --ci` 是 pre-push 的閘，而「靜默少一條合約」正是本工具最不能接受的事。

```
[1.5/4] 未閉合 frontmatter (整份檔被當 body 索引 → 合約靜默蒸發)
  ⚠ 發現 1 篇 frontmatter 開了沒收(以 --- 起頭但找不到收尾 ---):
      • Systems/broken.md
```

**驗證**：測試先斷言三個症狀**真的都發生**（合約蒸發、幽靈邊）才驗 doctor 抓不抓得到；
翻紅釘（移除該段）翻紅 3 條。
