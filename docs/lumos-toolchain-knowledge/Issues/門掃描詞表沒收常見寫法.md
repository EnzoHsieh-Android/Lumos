# 門掃描詞表沒收常見寫法

## 症狀

規格閘判計劃風險時,門的關鍵字掃描(`_door_keyword_hits`,詞表 PITFALL_CLASSES)比不到下面這些一般寫法,計劃作者照日常中英文寫,門就判風險低、跳過設計審。2026-10-15 補審資安席(規格閘第十一輪修補)實測,`_door_keyword_hits` 對這些輸入都回空清單:

- 對外送出:`sends`、`sending`(英文詞界只收 `send` 原形)、`email` 當動詞(`emails customers`、`系統會 email 客戶`)、`寄信`、`發送通知`、`傳送訂單`、`發信`;`LINE 推播`、`LINE Bot 推送`、`LINE 訊息推送`(只收 `LINE推送` 與 `LINE 推送`)。
- 資料不可逆:`上線到正式環境`、`deploy to live servers`、`TRUNCATE TABLE`、`ALTER TABLE … DROP COLUMN`、`rm -rf`、`刪除整張資料表`、`migrate`(只收 `migration`)。
- 金流:`payout`、`收費`、`付款`。
- 簡體字:`迁移`、`发送简讯`、`对外` 都比不到(詞表只有繁體)。

## 根因

詞表每類只列幾個固定寫法,沒有屈折形、同義詞與簡體字;第十一輪把英文詞界收緊成「前後不是英文字母或數字」,`sending`、`emails` 這類本來就比不到(新詞界是舊 `\b` 的超集,不是這次修補讓它變差)。改詞表就是改門判定規則,會讓既有計劃的留痕重數、也會讓 `lumos pitfalls --check` 一起多命中(同一張詞表,見 [[Systems/規格閘]]),要先量多判高的代價。

## 現在怎麼繞

- 計劃碰到對外送出、正式環境、刪資料、金流時,作者自己在開頭欄位寫 `plan_risk: high`,或照實在正文寫出詞表收的寫法(送出、寄送、prod、DROP TABLE、DELETE FROM、payment)。
- 審計劃的人看到門判風險低、但計劃講的是寄信、推播、正式環境、TRUNCATE 這類事時,不要只信門,照風險高處理。

## 什麼條件算修好

另開一份計劃改門的詞表(走設計審、改門判定規則):列出要收的寫法與詞界規則,對本 repo 與至少一個消費專案的全部計劃量多判高的份數,升 `_DOOR_RULE_VERSION`;上面〈症狀〉列的寫法都命中、量到的多判高份數寫進那份計劃,就關掉這篇。
