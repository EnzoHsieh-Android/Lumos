# code-loop-pass不能指定分支

> 白話：在「沒有掛在分支上」的工作目錄做完代碼審，記下的「審過了」會掛在一個叫 HEAD 的名字底下；推到 main 時，推送前檢查按 main 找，找不到。

## 經過

2026-09-11 推「每支檔有家」：本機 main 上有別的會談還沒推的提交，所以在另一個工作目錄（detached）做。
`lumos code-loop pass` 記成「分支 HEAD，版本 dcd5c9dd」；推 HEAD:main 時推送前檢查印「tier=high 且留痕 sha 過時（留痕=c769b746…）」——它找到的是別的會談上一次在 main 記的那筆。
另開私有 clone、讓它的 main 指向功能提交重記一次，推上去（3a59166c），CI 綠。

## 為什麼沒當場修

碰的是 code-loop 守衛的讀寫兩側，屬高風險，要先過設計審；而且讀側曾刻意拿掉分支別名（別的分支的留痕不能拿來用），加旗標要先想清楚不重開那個洞。

REVISIT:2026-10-11 數這一個月治理帳裡分支記成 HEAD 的 pass 有幾筆；有就代表又有人踩到，排進修

## ★同一個病的第二半:表態那邊會來回互推★(2026-09-18)

本篇原本只記「留痕」那一半。**表態那一半症狀不同、而且更難看出來**:留痕是「找不到」,表態是**兩邊互相說對方過期,你修哪邊另一邊就紅**。

### 怎麼發生的

在具名分支的工作目錄上推 `HEAD:main`,於是同一批改動有兩個分支名:

| 誰在看 | 看哪個名字 |
|---|---|
| `code-loop check`(本機檢查) | **當前分支**(`fix/…`) |
| 推送前那道閘 | **推送目標**(`main`) |

表態指令有 `--branch` 可以指定,但**一次只能綁一個**:

- 只綁推送目標 → 本機檢查說過期,一直擋。
- 只綁當前分支 → 推送閘說過期,推不上去。
- **兩邊來回改,每次都只讓另一邊紅。**

### 目前的繞法

**同一份表態送兩次,各綁一個名字**:

```
lumos code-loop dispositions <表態檔>
lumos code-loop dispositions <表態檔> --branch main
```

兩份記錄同時存在,兩道檢查各自找得到自己要的那份。**留痕仍然只能綁當前分支**(`pass` 沒有分支參數),所以留痕那一半的繞法照本篇上面原本寫的走。

### 為什麼會拖這麼久才發現

★因為每一輪都只露出一個症狀★:改了程式碼 → 表態過期 → 重表態 → 提交帳本 → 版本又變 → 再過期。中間夾雜真正的問題(新增告警、合併衝突),**看起來像是「改動太頻繁所以一直要重跑」,而不是「兩個分支名各自為政」**。

分辨的判準:**如果重表態之後另一道檢查立刻說過期,而中間你沒有動過任何程式碼**,那就是分支名不一致,不是版本推進。
