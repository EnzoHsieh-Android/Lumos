# 把自己的推論寫成repo明文寫過

> 白話:我在一份設計計劃裡寫了「這個 repo 明文寫過『0 筆不是沒記,但也不能假裝有記』」。
> **那句話全 repo 查不到,是我自己造的。** 兩個獨立的審查席各自 grep 之後同時抓到。

## 可數的事實

- 全 repo(圖譜 + CLAUDE.md + 程式碼)搜「假裝有記」,只命中那篇計劃自己與它的審查快照副本。
- 真正存在、可查的規矩有兩處,而且都不是那句話:
  - CLAUDE.md 寫的是「0 筆不是沒記——看『逐詞覆蓋』裡標 ★ 的那個詞是 0,換同義詞再查」。
    它講的是**多詞查詢的逐詞覆蓋機制**,不是泛用的 0 筆語意。
  - 工具實際印出來的是「不代表圖譜沒記這件事;先換個說法再查一次」。
- 我用的是「」這對括號,而這個 repo 的慣例是「」代表**逐字引用**。

## 為什麼這件事比「寫錯一句話」嚴重

- **它會製造假錨點**:下一個 session 讀到「這個 repo 明文寫過 X」,會去搜 X。搜不到之後有兩條路:
  一是以為自己搜錯詞、繼續找;二是以為圖譜掉了東西。兩條都是浪費,而且第二條會讓人不信圖譜。
- **這個 repo 有專門的引句錨定治理**([[Issues/引句錨定只驗前綴_後半可編造]]),
  就是因為編造或誤植引句造成過真實傷害。我在一份要進審查的文件裡犯了同一類。
- **審查機制抓得到別人的編造,抓不到我的**:席報告的引句要對回凍結快照(`quote-check`),
  但**編排者自己寫的計劃內文沒有這道檢查**——我引「這個 repo 說過」時,沒有任何機械檢查。

## 這是連續第三次同型

同一批工作裡:

1. 代碼審 r1:我在註解寫「repo 沒有第二種近名判準」——前一天才是我自己加的第二支。
2. 代碼審 r1:我在註解寫「借精簡版那支、不另造第二套」——程式碼其實另打了一份。
3. 這一次:把自己的推論寫成「repo 明文寫過」,還加上引號。

三次的共同形狀是:**我需要一個權威來支撐當下的論點,就順手寫了一個,而且用了肯定的語氣。**
前兩次是「宣稱程式碼是怎樣」,這次是「宣稱文件寫過什麼」——後者更難查,因為它不在被審的 diff 裡。

## 處置

- 那篇計劃已改成引 CLAUDE.md 的真實原文,並註明它講的範圍是多詞逐詞覆蓋、不是泛用的 0 筆語意。
- **規矩**:寫「這個 repo 說過 / 明文寫過 / 既有裁定是」這類句子時,
  ★要嘛附上節點名或檔案路徑,要嘛就不要用引號、改寫成「我的理解是」★。
  沒有出處的權威宣稱,跟沒有出處的數字一樣不可信。
- **機械面的缺口誠實記**:計劃內文的引句沒有任何自動檢查。
  做一道等同 `quote-check` 的檢查在計劃上,成本是要先能辨識「哪些引號是在引 repo 自己」——
  現在做不到。**所以這條目前只有紀律,沒有守衛,這件事本身要寫著。**
  REVISIT:2026-11-07 若再出現第四次同型,就是紀律不夠,要想機械解(例如:
  計劃裡凡是「」引號內超過十個字的句子,一律拿去全 repo grep,找不到就出聲)。

## 第四次,而且是在寫完這一篇之後不到一小時(2026-09-07)

我在另一篇事故筆記([[Issues/同工作區多session並行改動]])裡寫了
「**它是唯一能處理瞬時壞檔那一型的做法**」。另一個 session 更正我,我去查證之後確認**我錯了**:
- 這個 repo 本來就有一條慣例「寫入一律 tmp→自驗→atomic」,圖譜裡至少六篇計劃寫過。
- `scripts/lumos` 裡就有一支現成的函式在做「寫暫存 → 重新 parse 自驗 → 原子改名」。
- 而且那條解**更好**:壞檔窗口是零,而且只要寫的那一邊做,不必兩邊配合。

★時間點是重點★:我寫那句「唯一」的時候,距離我寫完**這一篇**不到一小時,
而這一篇的內容就是「我把沒查過的東西寫成肯定句」。

## 所以這個病的範圍比我原本寫的大

原本我把它框成「編造引言」。實際上共同形狀是:
**需要一個結論來收尾,就順手寫一個絕對的說法,而且沒查。**

它有三種面孔,今天各出現過:
1. **編一句引言**,還加上引號(引號在這裡的慣例是逐字引用)。
2. **宣稱程式碼是怎樣**(「repo 沒有第二種近名判準」「借那支、不另造第二套」)。
3. **宣稱這是唯一解 / 沒有別的辦法**。

★第三種最危險★,因為它讀起來像是「我查過所有可能了」,而實際上我一個都沒查。

## 規矩擴充

除了原本那條(寫「這個 repo 說過」要附出處),再加一條:

**「唯一 / 一定 / 不可能 / 從來沒有 / 沒有別的辦法」這幾個詞,跟引號一樣,寫下去之前要先查。**
查不動就改寫成「我沒有找到別的做法」——那是誠實的,而且下一個人知道那是我的搜尋範圍,不是事實。

## 第五次(同一小時內):我讀了說明字串,就以為我查過了

我寫「`scripts/lumos` 裡**就有一支現成的函式**在做寫暫存→自驗→原子改名」。
另一個 session 開檔看了,說這句要精修,不然下一個 session 會直接去呼叫然後爆掉。

**我實跑驗過,它是對的**:拿一支只有 `x = 1` 的 `.py` 餵給那支函式,當場拋
「這篇筆記開頭沒有欄位區塊(---),沒辦法改欄位」。
★那支函式的射程是「筆記的開頭欄位」★——它會去切開頭欄位、確認要寫的欄位值真的寫進去了、
再比對有沒有多出會讀錯的寫法。可借的是**形狀**,不是函式本身。

### 為什麼這次特別值得記

- **我有查**。我讀了那支函式的說明字串,上面寫著
  「寫 tmp → re-parse 自驗 + lint 無新指紋 → atomic rename」。
- **那句說明字串沒有錯**。錯的是我沒看它 parse 的是什麼。
- ★一句正確的說明字串,配上沒看內文,就足以生出一個錯的結論。★
  這比「說明字串過期」更難防,因為**沒有任何東西是壞的**。

### 所以處方要改

原本這篇寫的是「寫下去之前要先查」。**這次我查了。** 所以要加一句:

★驗一支函式能不能用,要看它**吃什麼、吐什麼、對輸入有什麼假設**,不是看它的說明字串講它在做什麼。★
說明字串回答的是「它做什麼」,你要問的是「它能不能吃我手上這個東西」。

### 還有一層,關於這個病的性質

我是在**寫一篇講「不要順手寫沒查過的絕對說法」的筆記時**犯的這一次(第四次也是)。
而同一小時內,另一個 session 也犯了一次同型(它宣稱那條慣例可以直接用)。

★所以真正的教訓不是「要小心」——寫下那個教訓的動作,不會保護你在那一句裡不犯它。★
兩個 session、一小時、三次、三種面孔,而且每次都是在很有把握的時候。
**這個病跟「不小心」無關,它跟「需要一個結論來收尾」有關。**

## 第六次:我把審查席的一句附帶提醒,當成查過的事實抄進計劃

第一輪某一席在報告最後附帶提了一句「被抄的那把鎖的鎖目錄其實沒有被忽略清單涵蓋,
只是平常不落地才沒炸」。**我沒查證就抄進計劃**,還加了一句「★已審過不等於來源本身無瑕★」
把它當成一個有教訓價值的發現在講。

第二輪另一席去查了:**那是錯的**。實際建立那個目錄再查,它命中忽略清單的規則;
而且追 git 歷史,那條規則跟鎖機制是**同一次進 repo** 的——從頭就有涵蓋。

### 這一次的面孔:借來的權威

前五次是我自己造的說法。這一次**是別人說的**,而我把「審查席說的」當成「查證過的」。

★審查席的報告本身也是待驗的材料★——這件事流程上早就知道
(所以才有引句要對回凍結快照、發現要機械重現這些收貨檢查)。
但那些檢查驗的是**它列成 finding 的東西**;
**它在報告最後隨口附帶的一句話,不在任何檢查的射程內**,而我照抄了。

### 規矩再擴充

**要把某句話寫進計劃、而那句話會影響判斷的,不管來源是誰,都要自己查一次。**
「審查席說的」不是出處,「我開檔看過」才是。
如果只是想保留那個線索而還沒查,就寫成「某席提過,我還沒查證」——那是誠實的。

## 第七次(2026-09-07 下午,代碼審 r1 邊界席當場打臉)

我在健檢那段的註解裡寫:「★兩條讀同一份健康檔★,**所以不會各說各話**。」

邊界與輸入席餵一份「五步全 0、只有 total 欄位壞掉」的健康檔,兩邊當場講出完全相反的結論
——健檢說「五步都是 0,沒事」,看門狗說「有步驟失敗,見 steps 欄」(而那個 steps 欄全是 0)。

**錯在哪**:讀同一份檔案 ≠ 看同一個欄位。健檢讀 `steps`,看門狗讀 `total`。
我寫那句話的時候腦子裡想的是「同一個資料來源」,但實際成立的條件是「同一個判準」,
而我沒有去比對兩邊的碼各自讀了什麼。

**這一型的新特徵**:前六次是「宣稱某個東西存在/不存在」,這次是**宣稱兩段程式之間的一條不變式**。
不變式比存在性更容易寫錯,因為它牽涉兩處,而人只會回想自己剛寫完的那一處。

**收束**:寫「所以不會 X」「兩邊一定一致」這類跨模組不變式之前,把**兩邊各自的判準行**並排看一次。
寫不出「這兩行讀的是同一個欄位」就不要寫那句話,改成「兩邊都以 <欄位> 為準」並真的讓它成立。
這次的修法就是這樣:兩邊都改成讀 `steps`,`total` 降級成交叉檢查,對不上就單獨喊一種狀態。
