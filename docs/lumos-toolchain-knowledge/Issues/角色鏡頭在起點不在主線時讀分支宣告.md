# 角色鏡頭在起點不在主線時讀分支宣告

> 已結案(2026-10-09):角色鏡頭的 review_roles 改讀起點與主線的分叉點(跟目標架構共用同一支),卡片照附、只是宣告不再由被審分支決定;守它的測試 t_review_role_declaration_from_fork_point。以下是當時的排查紀錄,不是現況。

## 症狀

派工鏡頭的角色段讀「範圍起點那一版」的 `.lumos/config.json` 裡的 review_roles,用意是被審分支不能自己改宣告決定自己拿哪張卡。但修補輪常用「上一輪終點..這一輪終點」當範圍,那個起點是被審分支自己的提交:分支在上一輪提交裡把 review_roles 改掉,這一輪的角色卡就照分支寫的宣告附。

## 根因

角色段只檢查範圍格式與提交存在,沒檢查起點在主線歷史上;圖譜段有這道檢查。角色鏡頭計劃的驗收條款明文決定「base 不在主線時角色卡照附」(為了圖譜段失敗時卡片不跟著丟),當時沒考慮到起點本身就是分支提交時宣告不可信。

## 現在怎麼繞

修補輪派正確性席時,LUMOS-IMPACT 的起點寫主線上的提交(例:主線與分支的共同祖先),不用上一輪的終點。目標架構段已改成起點不在主線就不附規則(見 [[Systems/arch-alignment-lens]])。

## 什麼條件算修好

角色段在起點不在主線時改讀主線版的 review_roles(或不附卡並附一行說明),並有一條測試:分支提交改 review_roles 後,用分支提交當起點跑派工鏡頭,角色判定仍照主線版宣告。改之前要先跟角色鏡頭計劃的那條驗收條款對齊(那條要改寫或標作廢)。
