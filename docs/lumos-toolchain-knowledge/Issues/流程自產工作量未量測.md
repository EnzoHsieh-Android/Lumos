# 流程自產工作量未量測

> 白話:這套審查流程確實抓到真缺陷。但它抓到的缺陷裡,有一部分**是因為流程要求你先寫一份規格,才會存在的缺陷**。這個比例從來沒有人算過。

## 具體案例(2026-08-20,[[Projects/閘觸發帳統計_計劃]])

交付物:`lumos gov --stats`,**82 行、唯讀、只印字**。

投入:三輪對抗審計 / 9 個審查席 / 5 次追問補件 / 44 條 findings / 3 次人工裁決 / 最終未收斂由人放行。

**抓到的真缺陷(流程的價值,不否認)**:三層數字混用、漂移測試涵蓋不到一半 gate、除以零、節點欄語意不同質、基線數字量錯方法。

**但同時**,findings 中有相當一部分屬於這型:「表頭第三行沒定義」「桶名沒跟著改」「白話摘要與範圍刀矛盾」「測試枚舉不完整」——★這些缺陷存在的前提是那份規格文件存在★。

## 為什麼這是問題

不是「規格沒用」。是**這個比例從未被量測**,而量測它並不困難(逐條標記 findings 屬於「產品缺陷」還是「文件自身缺陷」)。

★不對稱★:對「檢索排序改了有沒有比較好」會做 goldset 對照實驗、算 nDCG、甚至做消融把功能殺掉;對「這套流程的成本效益」用的是信仰。

## 可能的反駁(先寫下來,免得討論繞圈)

- 「文件缺陷也是真缺陷,照這份實作會做錯」——部分成立,但**若沒有這份文件,實作者會直接看 code 與測試**,那些缺陷不會以這種形態存在。要比的是兩條路的總成本與總漏網,不是單看一條路抓到幾個。
- 「這案是加嚴後的第一次,不具代表性」——成立。所以本單主張的是**開始記**,不是現在下結論。
