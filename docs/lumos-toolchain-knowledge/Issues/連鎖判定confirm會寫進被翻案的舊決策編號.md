# 連鎖判定confirm會寫進被翻案的舊決策編號


## 怎麼發生的

決策翻案會開一張待辦單，要人逐篇判「引用它的筆記還成不成立」。判「還成立」時工具會把依賴關係寫進那篇節點的依賴欄——**寫的是那張單的起點，也就是被翻案的那條舊決策**。

2026-09-16 實際踩到：判完一篇之後，體檢立刻多出一條「這篇引用了被翻案的決策」。而那篇節點的內容**其實是對的**——它正文明寫「新決策取代舊決策」，只是依賴欄被填了舊的編號。

## 為什麼在意

**清帳的動作自己製造新帳。** 判得越勤，體檢喊得越多，而喊的內容是假的（節點沒有建立在舊決策上）。這會訓練人忽略那條提醒——跟這個機制要防的「提醒麻痺」同一個方向。

而且它讓兩個檢查互相打架：一個要你判、判了另一個就喊。

## 當下處置

手動把那篇的依賴欄從舊編號改成翻案後的新編號，體檢那一條就清掉了。

## 修法方向（還沒做）

判「還成立」的時候，寫進去的應該是**這條鏈目前有效的那一條決策**，不是起點那條。工具手上有整條鏈（翻案時就記了指向），取最終有效那一條即可。

或者退一步：依賴欄記「這條鏈」而不是「某一條決策」，體檢就不會誤判。

**這條沒有機械守衛**，而且會在每次清連鎖帳時重現。REVISIT:2026-10-16 下次有人清連鎖帳時如果又撞到，就該修掉而不是再手動改一次。
