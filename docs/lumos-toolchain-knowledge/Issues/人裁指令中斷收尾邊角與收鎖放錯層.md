# 人裁指令中斷收尾邊角與收鎖放錯層

背景:[[Projects/情境題答案要引規格出處與回寫循環_計劃]] 的人裁指令,代碼審 code-情境題引規格出處 跑到第 4 輪(已破例)仍有下列問題;使用者 2026-11-13 問清「正常使用下會有什麼影響嗎? 還是極端操作?」後裁「接受風險直接收」。卷證:`governance/review-reports/code-情境題引規格出處/r4-intake.md` 與 r4 各席報告。

## 症狀

1. **關終端連送兩個掛斷訊號被當成強制結束**(r4 通才 t1、正確性 c2):人裁正跑殺傷力或正在寫回時關掉終端,約隔 50 毫秒的兩個 SIGHUP 讓兩段式把第二個當成「再按一次」,收尾被打斷、隔離工作樹留成殘骸;剛好落在計劃已寫、帳沒記那一刻時要手動刪那條條款再重跑。
2. **建鎖微秒空窗留下空鎖檔**(r4 合約 g1、資源 z2、正確性 c1):等寫入鎖時中斷剛好落在 `_excl_lock_try` 建好鎖檔、寫入程序編號之前,留下空鎖檔;收鎖只認「第一行是自己的程序編號」,認不得,之後寫筆記卡 60 秒報錯,要手動刪鎖檔。
3. **收鎖判斷放在指令層**(r4 架構對齊 a1):`_situation_rule_drop_lock` 在人裁指令裡自己比對程序編號、直接動寫入鎖模組的內部登記表,是專案第三份收鎖邏輯;執行時沒影響,改鎖模組時容易漏改。
4. **收尾的 git 子程序成孤兒**(r4 資源 z1):外部只對 lumos 的 pid 送兩次 SIGTERM 時,強制結束只收測試程序群組,收尾裡卡住的 `git worktree remove` 沒人收。用 Ctrl-C 時整個前景群組一起收到訊號,不受影響。
5. **副檔名大寫的錯誤訊息是死路**(r4 邊界 b1):`Projects/Plan.MD` 這種計劃,錯誤訊息叫人照實際檔名重打,重打又因 `.md` 去尾只認小寫而找不到。
6. **計劃文件缺口**(r4 合約 g2、g3):〈依據來源〉沒有中斷兩段式的業界來源那一列;〈實務隱患〉一行與範圍 4 的提示字面跟現況對不上。

## 根因

1、4 是兩段式只數訊號次數、強制結束只收登記過的測試程序群組;2、3 是收鎖寫在指令層、補不到鎖模組內部建檔與寫編號之間的空窗;5、6 是邊角輸入與文件同步沒掃到。

## 現在怎麼繞

- 跑人裁時放背景、別關終端;萬一被打斷,隔離工作樹一天後下次跑人裁時清掉。
- 寫筆記卡 60 秒報錯鎖時,確認沒有 lumos 在跑後刪掉圖譜寫入鎖檔。
- 計劃檔名用小寫 `.md`。

## 什麼條件算修好

- 第二個訊號要距第一個超過一小段寬限(業界有用時間窗判第二次 Ctrl+C 的做法)才強制結束,有兩個 SIGHUP 隔 50 毫秒仍完成收尾的測試。
- 收殘鎖搬進寫入鎖模組(正常收尾與強制結束共用),建鎖檔到寫入程序編號之間的空窗補上,有中斷落在空窗的測試。
- 強制結束也收收尾裡的 git 子程序。
- 副檔名大寫的錯誤訊息給得出可行的寫法。
- 計劃〈依據來源〉補兩段式來源列,〈實務隱患〉與範圍 4 字面跟上現況。
