# 派工鏡頭對單篇計劃筆記算三分鐘

白話:派工鏡頭是派審查員時,自動把「這次改動牽連到的筆記」附在派工詞尾端的那個機制。2026-10-06 量到:一個只改了一篇計劃筆記的提交,鏡頭要算 3 分 14 秒;而派工時的掛鉤只等 45 秒,所以這種改動派審查席時,鏡頭會附不上。

怎麼發現的:兩支認領測試拿「主線到目前版本」當範圍跑鏡頭,合併請求 #14 的範圍正好是這個提交,測試卡過 180 秒而紅。測試那邊已改成挑主線上最小的提交([[Projects/鏡頭測試範圍固定_計劃]]),不再受影響;鏡頭本身慢還沒查。

根因:我沒查。印出的「外部碼表補選因時間上限中止」表示有一段補選撞到時間上限;推測跟那篇筆記提到很多函式名、檔名(含主程式那支大檔)有關。

下一步:照 repro 指令加上剖析(例:`python3.14 -m cProfile -s cumtime scripts/lumos dispatch-lens …`)看時間花在哪一段,再決定是加快取、限制補選範圍,還是讓計劃筆記的改動走輕量路徑。
