# 筆記格子第3步末輪遺留

接手:下一個碰到 doctor S16 到 S19 或推送時撤除條件那支的改動;沒有的話照下面的回頭日期單獨修。都不會誤擋或誤放行正常操作(第三輪七席 blocking 0)。

1. **stderr 壞掉時推送那支會整支冒出去**(四席同報):撤除條件那支「清單印到一半出錯」與判定兜底的那一句 print 本身沒包,stderr 管線關掉時例外冒出 `cmd_drift_check`,那一筆帳沒寫、指令以 traceback 結束。第二輪為了跟 m1 與 c1 到 c5 一致拿掉了另寫的吞錯小工具,這個洞跟著回來;鄰居同樣不防。改法:只在那兩個 except 裡多包一層 try(不另寫小工具),或整道閘一起收斂。在那之前,系統筆記「印出與記帳各自兜、出錯只講一句」要加「stderr 本身壞掉除外」。
2. **S18 fail-open 那行印例外全文、沒清控制字元**(四席同報):改成印型別名或過 `_esc_clean`。目前例外訊息的內容外人控制不到。
3. **函式名與說明過期**:帳增速段的註解還寫 `_drift_jsonl_parse`(系統筆記 lumos-cli-read 那句 2026-10-02 回頭重讀時已改),實際用 `_drift_jsonl_iter`;逐筆版只省掉 dict 清單,整份解碼字串與切行清單仍在(16MB 帳尖峰 124MB 降到 58MB),說明寫「不留整份清單」偏滿;改法可先 `raw.split(b"\n")` 再逐行解碼。
4. **`_esc_clean` 不擋雙向文字控制字元與 U+2028/U+2029**(共用函式,實測原樣通過):補進去,一次涵蓋全部呼叫點。
5. **摘要讀法的邊角**:同一篇兩個 `summary:` 鍵時行號取第一個、值取最後一個;引號跨行的 summary 與「單行值後面接續行」兩種寫法仍漏判(改前也漏);drift scan 與推送時的 `_retire_lines` 不補單行 summary(doctor 那側補了)。改法:`_note_summary_entries` 的說明寫明不支援的寫法,或兩側共用同一支。
6. **路徑超長時原因被截掉**:`_DOCTOR_LINE_MAX` 截尾端,路徑超過 300 字時看不到原因;改成截中段或先截路徑。
7. **S16 清控制字元沒有測試釘住**:補一條 S16 輸入帶控制字元的斷言。
