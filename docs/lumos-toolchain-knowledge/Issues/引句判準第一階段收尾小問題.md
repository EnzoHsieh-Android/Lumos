# 引句判準第一階段收尾小問題

## 症狀

代碼審 `code-引句錨定整段比對` 第 5 輪(人裁破例輪)八席都只報 minor、0 條 blocking,只改文件的部分已折入,要動程式的部分在最後一輪之後不再改(改了就沒有全新席看過),統一放行並列在這裡。卷證在 `governance/review-reports/code-引句錨定整段比對/r5-*.md` 與 `r5-intake.md`。

1. 手動 `quote-check` 文字輸出的引句沒跳脫(見 PITFALL)。舊版就有;full-span-v1 的引句可以跨行,讓換行變成可達。
2. 擋下事件 note 裡 `report=`、`loop=`、`auditor=` 原樣寫入:路徑能偽造第一個 `id=`;報告檔名不是 UTF-8 時 note 帶孤立代理字元,治理帳寫入丟例外被吞,這筆擋下事件沒進帳;路徑沒有長度上限。
3. 程式裡兩段註解是舊做法的殘骸:`_quote_block_note` 片段前一段還寫「`_esc_clean` 換空格」;處置閘診斷行註解還寫「整行再過 `_esc_clean`」。行為正確,註解誤導。
4. `quote-check` 的參數宣告還是為比較模式留的形狀:報告 `nargs="?"`、`--spec` 說明寫「一般模式必填」;測試標題「一般模式缺 --spec」同。應改回 argparse 必填。
5. 新判準對不足 10 字的引句仍整份掃快照(`_quote_anchor_row` 先搜再判長度);大快照下每條約 28 ms,白花。改成先判 `too_short` 不影響任何輸出欄位。
6. 引句條數乘快照大小的線性成本沒有條數上限(兩版共通的舊成本)。
7. 兩條修補沒有翻紅釘:事件報告指紋改用寫側驗過的那份(沒有「驗證後換檔」的測試)、診斷路徑超過 1000 字改印說明(只測了控制字元那支)。
8. 標籤正規式有兩份(`_QUOTE_LABEL_RE` 與舊判準內嵌那條),沒有測試釘兩份相等。
9. 章值不認得的訊息 `{v!r}` 沒有長度上限(同段其他例外訊息截 120 字)。
10. `_drift_sh` 白名單含 `=`,`=` 開頭的相對路徑照貼到 zsh 會被展開(共用函式既有行為,處置閘只有找不到 repo 根時才印相對路徑)。

## 根因

最後一輪之後的修正不再進同一個迴圈(沒有全新席看過的改動不推);這些都是 minor,行為上不影響判定。

## 現在怎麼繞

第 1 條:別在終端直接看不可信報告的 `quote-check` 人讀輸出,改用 `--json`。其餘不影響使用。

## 什麼條件算修好

- 第 1、2 條:人讀輸出的引句過 `_kill_esc`;note 的路徑、編號、席名過同一套跳脫並設長度上限,非 UTF-8 檔名不再讓事件寫不進帳;各補一支改回原樣會翻紅的測試。
- 第 3、4 條:註解改成現況;參數改回 argparse 必填,測試標題同步。
- 第 5 條:先判長度;補一支大快照加大量短引句的限時測試。
- 第 7 條:補「驗證後換檔」與「超長路徑」兩支測試,變異拿掉會翻紅。
- 第 8、9 條:補兩份標籤規則相等的測試;訊息截 120 字。
- 第 6、10 條:評估後決定修或寫明接受理由。
- 以上走一個小修 PR,照常過代碼審。
