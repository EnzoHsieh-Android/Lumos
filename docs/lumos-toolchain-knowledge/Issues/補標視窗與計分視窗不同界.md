# 補標視窗與計分視窗不同界

> 白話:評測「算分要看前幾名」這個數字可以用指令參數調,但「產生待標清單」那支工具寫死了前 8 名。兩邊對不齊的時候,有些會被算進分數的候選,人根本沒機會標到。

## 現況

- 算分的視窗:跑評測時 `-k` 指定,預設 8。
- 未標檢查的視窗:2026-09-15 起已跟著 `-k` 走(這一半修好了)。
- **產待標清單的視窗:寫死 8**,那支腳本沒有 `-k` 參數。

## 為什麼不算緊急

失效方向是保守的:補不完 → 未標數不為零 → 不可逆的尺切換被擋下。**擋住比誤放行安全。**

代價是使用者體驗:用非預設 `-k` 跑的人會遇到「怎麼補都補不完」,而且沒有任何訊息告訴他原因出在工具視窗不同界。

## 要做什麼(還沒做)

三選一,都要人裁:①補標腳本加 `-k`,跟評測共用同一個預設 ②兩邊的視窗抽成單一來源常數 ③明寫「補標池子固定 8」是刻意契約,並在未標檢查發現 k>8 時印一句提醒。

REVISIT:2026-11-15 有人真的用非預設 -k 跑評測時處理;在那之前如果都沒人用,就改判成刻意契約(選項③)並關掉這篇。
