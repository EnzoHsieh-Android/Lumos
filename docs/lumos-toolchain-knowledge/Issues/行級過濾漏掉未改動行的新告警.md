# 行級過濾漏掉未改動行的新告警

> 白話：檢查工具找到問題之後，我們只留下「問題正好落在你這次寫的那幾行」的，其餘丟掉。聽起來合理，但檢查工具常常把問題標在一個你沒動過的位置上——例如你把某個例外處理改壞了，工具卻指著上面那行 `try:` 說「這整段有問題」。那一行你沒碰，所以被丟掉了，而且**沒有任何訊息告訴你丟了東西**。

## 怎麼重現

在一個乾淨的 git repo 裡放一支 Python 檔：

```python
def risky():
    try:
        do_work()
    except ValueError:
        pass
```

提交，然後**只把第 4 行**改成 `except:`，再提交。這時候：

- 這次改動實際碰到的行：第 4 行。
- 檢查工具報告問題的位置：**第 2 行**（`try:` 那一行）。
- 行級過濾的判斷：第 2 行不在新增行集合裡 → 丟掉。

## 為什麼會這樣

檢查工具比對的是一個**結構**（整個 try/except 區塊），報告位置用的是這個結構的開頭。你改的是結構的某一部分，但問題屬於整個結構。這不是特例——任何跨多行的規則都有這個性質。

## 打算怎麼修

併進新增告警閘那個計劃，改成**對改動檔跑兩次比差集**：用現在這份規則掃基準版一次、掃現在版一次，兩邊都有的不算新增，只有現在版才有的才算。這樣問題報在哪一行都無所謂，因為比的是「有沒有」而不是「在第幾行」。
