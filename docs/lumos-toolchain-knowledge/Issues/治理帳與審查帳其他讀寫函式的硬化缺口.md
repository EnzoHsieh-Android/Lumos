# 治理帳與審查帳其他讀寫函式的硬化缺口

白話:治理帳(記每道閘擋了誰、放了誰)和審查帳(記每輪審查)各有好幾支讀它、寫它的程式。跑滿回顧那一族在這次代碼審裡被磨得很硬——行尾怎麼切、檔案是捷徑或無限大怎麼辦、寫一半的帳尾怎麼補、壞字元怎麼處理都講好了;其他讀者和寫者還是舊做法。結果是同一本帳,有的程式讀得到、有的讀不到;有的寫得乾淨、有的會黏行。

出處:「審查跑滿回顧」代碼審第四輪(2026-10-06)七席報告與收貨紀錄,都在 `governance/review-reports/code-審查跑滿回顧/`。這四項都是本分支之前就存在、本分支沒改的函式,所以那一輪放行、開這篇。

## ① `_drift_jsonl_iter` 這一系的讀者只在 \n 切行

- 出處:r4-架構對齊-r4-sonnet.md F1、r4-通才-r4-sonnet.md F3、r4-邊界-r4-sonnet.md F2、r4-合約圖譜-r4-sonnet.md F1。
- 現況:跑滿回顧一族與 r3 換掉的約 20 處讀者走 `_ledger_lines`(認 \r\n、\n、\r);`lumos gov` 的載入器(走 `_drift_jsonl_parse`)、`_gov_ledger_rows_by_time`、doctor 治理帳增速與度量段、`_fix_check_events`(自己 `raw.split(b"\n")`)仍只認 \n。整本 \r 行尾的帳,閘看得到人裁紀錄,`lumos gov` 與 doctor 一筆都讀不到。
- 重現:`raw=b'{"gate":"a","kind":"x"}\r{"gate":"loop-retro","kind":"cap-decision"}\r'`;`[x for x in m._ledger_lines(raw) if x]` 得 2 列,`list(m._drift_jsonl_iter(raw))` 得 0 列。
- 守衛缺口:`t_cap_retro_r3_ledger_lines_everywhere` 只掃 `.read_text(...).splitlines()` 樣式,掃不到這一系。

## ② 約 20 處讀帳不判一般檔、不限大小

- 出處:r4-資安-r4-sonnet.md F2。
- 現況:r3 換成 `_ledger_lines(path.read_text(...))` 的讀者只先判 `exists()`/`is_file()`,跟隨捷徑、不判一般檔、不限大小(跑滿回顧一族自己用 `_retro_gov_path_err` 加 `_retro_read_bytes` 擋住了)。審查帳的 `_canary_ledger_scan` 用 `read_bytes` 同理。
- 重現:臨時 repo 把 `docs/.governance-log.jsonl` 換成指向 `/dev/zero` 的符號連結,跑 `lumos --vault <vault> loop list --all`,6 秒內常駐記憶體約 2GB 還在長(例如 `_loop_close_stamps`)。版控能存符號連結,拉下惡意分支就中。

## ③ 三支追加寫入器沒補帳尾換行、沒接編碼例外

- 出處:r4-併發資源-r4-sonnet.md F1、F2。
- 現況:`_gate_event`、`_append_governance_log`、`_drift_ledger_append` 追加前會呼叫 `_ledger_tail_needs_newline` 補換行,也接 `UnicodeEncodeError`;代碼審的 `_codeloop_gov_log`、`_codeloop_dispositions_gov_log`(治理帳)與 `_jsonl_append_verified`(審查帳)直接 `open(path, "a")`,前兩支只接 `OSError`。
- 重現:治理帳檔尾寫成半行 `{"gate": "ci", "kind": "ha`,再呼叫 `_codeloop_gov_log(root, "feat", "passed", "ok", "a"*40, ts)`:新事件黏在半行後面,`_codeloop_read_from_ledger(root, "feat")` 回 None,`code-loop pass` 卻印「已留痕」(CI 只讀治理帳會擋)。`_codeloop_dispositions_gov_log` 帶 `"x\udcff"` 的表態直接丟 UnicodeEncodeError。審查帳檔尾留半行後 `canary record` 第一次回 2、第二次成功,但黏出來的壞行永久留著,`loop status --disposal` 回 2「有 1 行讀不懂」。

## ④ fix-check 紀錄樣板原樣輸出帳上的 C1 控制字元

- 出處:r4-架構對齊-r4-sonnet.md F4。
- 現況:跑滿回顧的骨架用 `_json_text_escaped`(跳脫 C0、C1、雙向、零寬等字元),同型的 `fix-check --record-template`(`_fix_check_template`)仍用 `json.dumps(..., ensure_ascii=False, indent=2)` 原樣印,帳上的發現 id 帶 C1(例如 U+009B)會送進終端。
- 重現:`canary record … --findings-set $'F1\x9b2J'`(發現 id 沒有字元集檢查)折入後跑 `lumos loop fix-check <編號> <輪> --record-template`,`groups[].findings` 原樣含 U+009B;單看 `json.dumps(["F1\x9b2J"], ensure_ascii=False)` 就會原樣輸出。

## 怎麼收

一支讀帳函式(開檔判一般檔、設上限、`_ledger_lines` 切行)加一支追加函式(補帳尾換行、只略過不能編碼的那筆、寫不進去回 False),兩本帳的讀者與寫者都改走它們;骨架輸出統一走 `_json_text_escaped`。這幾支函式的家是 [[Systems/reversibility-governance-ledger]],修好後說明寫回那一篇,本篇結案。相關的另一件:[[Issues/治理帳多個寫入者都沒上鎖]](同一批寫入器沒有鎖)。
