# 推送前其他閘的範圍在合過主線時會多算

## 現象

推送前掛鉤的漂移檢查在代碼審第一輪被抓到:功能分支合過主線再推、或重定基底後強推時,「遠端舊值..本地新值」會把主線上別人的改動算進這次推送。第一輪折入時掛鉤自己算起點;第二輪代碼審查出掛鉤、CI、工具三份各有洞,改成起點只在 lumos 裡的 `_push_range_start` 算一處:掛鉤把「遠端舊值..本地頂端」連同遠端名(`--push-remote`)與遠端 ref 名(`--pushed-ref`)原樣交給 `lumos drift check`。規則(第三輪代碼審後):主線候選是遠端 HEAD、`main@{upstream}`、`master@{upstream}`、遠端 main、遠端 master,跳過指到「推送遠端/被推分支」的那個,其餘一起算分岔點、取離頂端最近的;每一個分岔點都是遠端舊值的祖先才用舊值;git 查詢本身失敗算判不了。`_lens_push_base` 與 `_push_range_start` 的程式說明互相指到這篇,收斂時兩邊一起改。測試 `t_prepush_drift_range_ref_shapes`、`t_prepush_drift_start_mainline_shapes`、`t_ci_drift_start_shapes`、`t_ci_drift_default_branch_shapes`、`t_drift_check_push_start_edges` 釘著各種推送形狀。

同一支掛鉤裡的每支檔有家(home check)與筆記形狀擋(note-shape)用的是另一套範圍算法,正確性席指出同一個「合過主線」的形狀可能也會多算;那次代碼審的範圍只限漂移檢查,沒動這兩道。

## 要做的

- 先重現:在臨時 repo 造「功能分支合過主線、主線上有別人新增一支沒家的程式檔或一句新的程式行號引用」,推功能分支,看這兩道會不會擋到別人的改動。
- 會的話,這兩道改用 `_push_range_start`(`home check`、`note-shape` 比照 `drift check` 加 `--push-remote`/`--pushed-ref`,掛鉤原樣交範圍),別在掛鉤裡另寫一份,並補同一組推送形狀的測試。
- 不會的話(它們的算法其實已經排除了遠端上已有的提交),在這篇寫明為什麼、結案。

另一處不一致(第二輪代碼審架構對齊席 F3)**已修**:原本掛鉤裡只有漂移檢查那道把「回傳碼 128 以上」(被 Ctrl-C 或訊號殺掉)當成整支停下,每支檔有家與筆記形狀擋被中斷時會放行往下跑。提交「fix: 推送前其他閘被中斷時也停下,不再當成放行(代碼審折入)」把每支檔有家、筆記形狀擋、spec-gate、code-loop check 與漂移那道一起改走同一支 pp_stop_if_signaled,測試 `t_prepush_gates_stop_on_signal`。這篇剩下的只有範圍多算那件事。
