# 寫下風險當成處理風險

> ## ✅ 已結案(2026-08-22)— 承認句必附重驗條件
>
> 立成 CLAUDE.md 第 4 條鐵則:寫「沒守衛/只提醒/單次量測」旁邊要有什麼時候回頭看。**實證**:本輪三處承認句都對到了週抽/空轉週報/留痕。
>
> ⚠ 鐵則本身靠自律,沒有機械檢查承認句有沒有附條件。
>
> ★以下「症狀 / 根因」是當時的排查紀錄,不是現況。★

> 白話:這套系統教人「把沒守住的地方標出來」。標久了會長出一批**標得很漂亮、但一樣沒守住**的地方——而且因為標得漂亮,看起來像已經處理過了。

## 現象

以下句式在圖譜與 skills 中反覆出現,已成慣用語:

- 「★這是觀測不是強制★」「恆 rc0,不擋」
- 「無機械守衛,靠自律」「純靠 honor-system」
- 「這個數字是拍的,無根據」
- 「本工具不碰 GitHub 設定,要擋得自己去設分支保護」

## 2026-08-20 當日新增的三處(★同一天,同一個人,同一種句式★)

1. 鏡像分家:「移除 remote 只擋誤推,不擋有人手動加回來再推——無機械守衛,靠本決策留痕」
2. slim 凍結:「凍結沒有機器在守,靠 FROZEN.md 與節點橫幅」
3. `gov --stats`:限制聲明寫死進輸出(★這一處有測試釘住,是三處裡唯一真的被守的★)

## 為什麼這是問題

★**誠實有兩種**★:一種是「我知道這裡沒守住,所以我要嘛去守、要嘛明確接受風險並定期回看」;另一種是「我知道這裡沒守住,寫下來,然後心安理得地繼續」。

**第二種在感覺上與第一種難以區分**——都產生一句誠實的句子。差別只在後續有沒有動作。目前的紀錄無法分辨這批承認裡哪些屬於哪一種,因為**沒有任何機制在追蹤「已承認風險」的後續**。

## 這不是要把所有承認都變成待辦

那會製造一張永遠做不完的清單,反而讓真正該處理的沉底。**要的是判準。**

## 判準(2026-08-21 裁,Enzo「繼續」放行編排者提案)

把全庫 38 處「靠自律／honor-system」讀完,它們是**三種不同的東西混用同一個句式**。判準就是把它們分開,★每種只有一個合法的後續★:

| 型 | 怎麼認 | 合法後續 | 不合法 |
|---|---|---|---|
| **A 天花板型** | 結構上不可機械化——事情發生在模型腦內(派工有沒有餵 manifest)、自報值(severity/處置帳)、判斷本身(辯方裁決) | 承認即處置。措辭標「天花板」而非「靠自律」,讓讀者知道這不是待辦 | 假裝未來會補機制 |
| **B 可機械但未做型** | 存在便宜的檢查點——常數比對、欄位存在性、清單成員、計次 | **二擇一且必須當場選**:①開 Issue 進待辦帳 ②**把散文降級**(「須」→「建議」,或刪)使文件不再承諾工具沒做的事 | 只寫「靠自律」然後繼續 |
| **C 已接受型** | 評估過、決定不做 | 一句理由 + 一個回看觸發條件 | 只寫「無守衛」不寫為什麼可以 |

**B 型的「降級」選項是關鍵**:多數 B 型的正解不是補機制(那會餵 [[Issues/只退場不痛的機制]]),是讓文件**停止宣稱**工具會做它不做的事。
