# 寫下風險當成處理風險

> 白話:這套系統教人「把沒守住的地方標出來」。標久了會長出一批**標得很漂亮、但一樣沒守住**的地方——而且因為標得漂亮,看起來像已經處理過了。

## 現象

以下句式在圖譜與 skills 中反覆出現,已成慣用語:

- 「★這是觀測不是強制★」「恆 rc0,不擋」
- 「無機械守衛,靠自律」「純靠 honor-system」
- 「這個數字是拍的,無根據」
- 「本工具不碰 GitHub 設定,要擋得自己去設分支保護」

## 2026-08-20 當日新增的三處(★同一天,同一個人,同一種句式★)

1. 鏡像分家:「移除 remote 只擋誤推,不擋有人手動加回來再推——無機械守衛,靠本決策留痕」
2. slim 凍結:「凍結沒有機器在守,靠 FROZEN.md 與節點橫幅」
3. `gov --stats`:限制聲明寫死進輸出(★這一處有測試釘住,是三處裡唯一真的被守的★)

## 為什麼這是問題

★**誠實有兩種**★:一種是「我知道這裡沒守住,所以我要嘛去守、要嘛明確接受風險並定期回看」;另一種是「我知道這裡沒守住,寫下來,然後心安理得地繼續」。

**第二種在感覺上與第一種難以區分**——都產生一句誠實的句子。差別只在後續有沒有動作。目前的紀錄無法分辨這批承認裡哪些屬於哪一種,因為**沒有任何機制在追蹤「已承認風險」的後續**。

## 這不是要把所有承認都變成待辦

那會製造一張永遠做不完的清單,反而讓真正該處理的沉底。**要的是判準。**

## 待裁

- [ ] 「已承認但未處理的風險」要不要可查?(最小解:一個標記,doctor 能列出來,不擋)
- [ ] 什麼樣的風險只准承認就好?什麼樣的必須有處理計畫或明確的接受留痕?
- [ ] 定期回看的觸發條件是什麼?
