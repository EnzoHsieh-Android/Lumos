# 範本空清單被判成純量

> 白話:新筆記範本裡寫 `aliases: []`(空清單),但工具判型別的規則只認「冒號後面是空的」,
> `[]` 不是空的 → 被當成純量 → 從範本建出來的筆記,第一次加別名就被擋。**已修。**

## 怎麼發現的

2026-08-23 design-loop `about-code-field` r3 席一審「範本要加 `about_code:` 空欄」這條時,
順手查既有 `aliases: []` 怎麼被處理——直接跑 `edit_fm_append` 重現失敗。
**不是本案的 bug,是既有的,但本案要照抄同款寫法,會把它複製進新欄位。**

## 影響範圍

全庫 `aliases: []` 的節點:工具鏈 13 篇、Landmark 2 篇。
這些節點 `lumos append aliases` 一律 rc2「aliases 是scalar型欄位」。
★aliases 宣告制 lint 只管 system/issue,所以範本只在那兩種放這行——影響面由此限定。★

## 修法(判定層,不改範本)

`fm_structure` 加一個分支:冒號後恰好是 `[]` → 判 list(start==end,區塊一行)。
`edit_fm_append` 遇到 `key: []` 那一行 → 先改寫成 `key:`,再照常插第一項。

**為什麼修判定層不改範本**:YAML 標準 `[]` 就是合法空清單;改範本要動 15 篇既有節點,
修判定層一處解決、既有節點不用動。

★範圍刀★:只認空的 `[]`。非空 inline list(`[a, b]`)仍判 scalar——要真的解析逗號與引號,
不在本次;而且 append 遇到它會被擋(不會壞),可接受。測試明確釘住這個邊界。

測試 `t_empty_list_bracket_is_list` 6 條:判 list / append 成功變多行 / 純量不受影響 /
非空 inline 仍 scalar(邊界釘) / ★e2e 從範本建節點 append rc0★ / 檔案格式正確。
另用真檔副本(known-pitfall-refresh-token)驗過。

## 誠實缺口

- `fm_structure` 有 8 個呼叫點,本次只驗了 append 路徑與全套回歸;
  其他路徑(set/remove/decision-add)對 `[]` 的行為沒逐一看。
- 非空 inline list 的支援沒做,重啟條件:有人真的在 frontmatter 手寫 `[a, b]` 然後 append 被擋。
