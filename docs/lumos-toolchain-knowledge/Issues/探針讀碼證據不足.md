# 探針讀碼證據不足

FLAG: TECHNICAL

PITFALL: 2026-10-03 試行第1案，收窄讀碼正則仍會把搜尋路徑字串當讀碼，且讓合法相對路徑由綠變紅；出處 [[Verification/2026-10-03_修復穩定性試行第1案]]，重現為載入情境探針 grade，對 v04 傳入下述命令和「這是帳本檔案白名單」。

## 症狀

對 v04 輸入 `grep 'scripts/lumos' README.md` 或 `find . -type f | grep scripts/lumos`，修前和候選修後都判通過，實際只搜尋文字或列檔。候選又把 `cd scripts && cat lumos` 從通過改判失敗。

## 根因

判分使用扁平工具呼叫摘要。命令提到某路徑不等於讀取其內容；要求固定路徑拼字也不能處理工作目錄變化。R2C1 是原有漏看，R2C2 才是本次 C1 修復引入，已用同一輸入查兩版，不混計。

## 現在怎麼繞

已撤回 C1 候選正則與其新增測試，保留原始快照/紅綠輸出；回退只消除新誤判，沒有修好原有假通過。因此本案不准宣告收斂或寫 code-loop pass；此題通過結果不能作為已讀碼的充分證據。其他兩項執行器/摘要修復保留為本機待審修補，未推送。

## 什麼條件算修好

先重估證據要落在哪一層，評估保留原生工具路徑與關聯工具結果；這是候選方向，尚未設計或實作。新方案需同時拒絕 README/列檔/搜尋路徑文字、接受直接與切目錄後的真讀碼、保留歷史 grep/sed 案例，並把缺失/失敗結果的處理寫成可验收條件。不得以把合法案例改判失敗來讓測試綠。
