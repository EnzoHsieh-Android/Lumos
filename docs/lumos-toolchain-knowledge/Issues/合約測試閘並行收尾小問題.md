# 合約測試閘並行收尾小問題

> 白話:合約測試閘可以同時跑多支測試之後,最後一輪審查還點出幾個小問題,都不會讓判紅綠出錯,所以先放行、在這裡接著修。修的時候當成一個小改動,自己走一次審查。

## 要修的(程式)

- **出錯或中斷時收程序,最多只等兩秒**:同批有一支測試剛開出程序、還沒登記時,使用者又按一次 Ctrl-C,或開程序卡超過兩秒,那一支會在程式結束後留成孤兒。修法方向:等待迴圈外層用 try/finally,保證收程序在 finally 裡再跑一次;或讓開程序和登記在同一把鎖內完成。審查席加人為延遲才重現得出來,不加延遲連跑 20 次沒撞到。
- **收程序用 `getpgid` 查程序群組,有極窄的 pid 重用窄縫**:每支測試本來就開在自己的新程序群組裡,群組編號等於程序編號,直接用程序編號砍整個群組就好,不用再查一次。
- **收程序的寫法在程式裡變成三份,而且跟既有兩份不完全一樣**:修上一條時順手收成一份共用的。
- **登記程序的類別直接繼承 list,專案裡沒有先例**:改成一般類別包一個清單,跟其他地方的寫法一致。
- **執行函式裡有一段舊註解,還在說「同批已開跑的子程序會跟循序時按 Ctrl-C 一樣成為孤兒」**:現在已經會收掉,要改成現況。

## 要修的(測試)

- **中斷時收程序這條路沒有會翻紅的測試**:現有的中斷測試只查「不再派新的」,不查有沒有留下孤兒。要補一支,拿掉收程序那段就會紅。
- **出錯就停的那支測試,缺一個前置斷言**:要先確認「有抓到已開跑的程序編號」,才去查它們有沒有被收掉;不然清單是空的時候也會綠。

## 要修的(計劃文字)

- **〈回退〉說只改設定檔時風險分級是 light,這不對**:通過代碼審之後再提交一個改設定檔的提交,代碼審的通過紀錄會失效,推送閘看整段改動,會判成高風險。實際停用要嘛重跑審查,要嘛用「跳過並附理由」。
- **回頭條件的取數指令跟撤除條件口徑不一**:撤除條件說「綠的支數 50 以上」,取數指令篩的是紀錄開頭的項目數(會把被幾篇筆記重複綁的算多次)。兩邊要對成同一個數。

## 什麼條件算修好

- 上面每一條都有對應的改動;程式與測試的改動各附一支拿掉修補就會紅的測試。
- 計劃〈回退〉與回頭條件改成跟實際一致。
