# 刪除守衛在消費專案把工具更新刪掉的名稱當成專案的

## 現象

消費專案(裝了 lumos 的專案)跑 `lumos update` 之後提交,工具自己的程式檔(例如 `scripts/lumos`)被新版換掉,舊版裡有、新版裡刪掉的函式名會被刪除守衛抽出來,拿去搜專案的圖譜。圖譜碰巧提到同名的東西時,守衛提醒「刪掉的東西筆記還在講」——但刪掉的是工具的東西,不是專案的。rtb 2026-09-30 回報這是誤報。

## 試過、又撤掉的做法

[[Projects/漂移修法補強_計劃]] 第 5 節試著讓刪除守衛在消費專案跳過工具自裝檔,經過三輪代碼審,每輪都在判斷「這支檔算不算工具原樣」上錯一種位置(摘要四條 PITFALL):

1. 只比檔名(設計審版本)。
2. 比安裝清單的指紋,但讀工作目錄(第一輪折入後)。
3. 改讀 git,只看改之後那一版(被第二輪抓到)。
4. 改之前、改之後兩態都讀,但刪除行和新增行的跳過不對稱(被第三輪抓到)。

同一類第三次,照設計審定下的規矩整類拿掉:刪除守衛回到不跳過任何檔,消費專案更新工具時的誤報照舊存在。

## 要重做時先過的檢查

- 先寫出一條會對症狀翻紅的測試:舊版安裝的專案升級、專案改過工具檔再升級、只改參數的函式、暫存與工作目錄不一致這四種形狀都要在同一支測試裡跑。
- 判法要逐個名稱判(那個名稱在改之後的工具檔裡還在不在),不要整支檔判。
- 讀 git 的次數與時間要有上限、吃守衛剩下的 deadline。
