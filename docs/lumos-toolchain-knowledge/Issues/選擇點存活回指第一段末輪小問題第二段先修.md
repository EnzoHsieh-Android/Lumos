# 選擇點存活回指第一段末輪小問題第二段先修

## 症狀

選擇點存活回指第一段代碼審跑滿三輪,第三輪七席只報小問題、資安判乾淨;這些小問題在上限內不再改程式(改了就沒人審),放到第二段開工先修,第二段本身也走完整代碼審。

1. **逾時斷路太早**(r3 正確性 #1、資源 #1、邊界 #1、通才 #2):掛覆蓋跑滿單支上限,在不掛重跑之前就斷路。測試本身不掛也逾時時,誤把整個平台組的覆蓋關掉。只變慢、不判錯。
2. **跨套件續跑會刪掉有效快取**(r3 正確性 #2):快取鍵不含這次的專案套件,但「Robolectric 專案類別 0」用這次的套件算;同一個提交先跑 A 檔、再 `--only` 跑 B 檔時,對 A 有效的快取被當成設定沒生效刪掉重量。只變慢。
3. **說明文字過時**(r3 通才 #1、架構對齊 #1):`red_rerun` 的說明還寫回傳 5 項,實際固定 6 項。
4. **計劃與圖譜沒寫三個新行為**(r3 合約 #1):逾時當場斷路、Robolectric 0 不進快取、分析輸出三鍵都要在。
5. **Groovy 測試在沒有 Groovy 的機器只剩靜態檢查**(r3 邊界 #2):CI 沒有 Gradle 快取時只擋一種字面寫法。
6. **測試樣板繞過建構子**(r3 架構對齊 #2):`_ckc_cb_stub` 用 `object.__new__` 手設欄位,建構子多欄位時不會紅;鄰居用真建構子加替身。
7. **測試讀真家目錄的 Gradle 快取**(r3 架構對齊 #3):繞過測試的 HOME 隔離(唯讀);測試檔其他地方沒有這種寫法。

## 根因

第二輪修補為了少等、少寫,把斷路提前、把快取判斷綁在這次的套件上,並用最省事的方式造測試樣板。

## 現在怎麼繞

都不影響判定結果。第 1、2 條遇到時會比預期慢:`--no-cov` 可整段關覆蓋。
