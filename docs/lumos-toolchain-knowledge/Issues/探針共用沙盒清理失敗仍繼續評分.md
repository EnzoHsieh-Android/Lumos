# 探針共用沙盒清理失敗仍繼續評分

## 症狀

第四輪R4-B3在臨時兩題批次重現：第一題破壞專用副本的Git資料並留下poison.txt，逐題還原命令失敗，第二題仍看到poison與缺失Git資料；兩題mock runner都回通過時整批仍回rc0。637989b1與8922c3c9同樣成立，屬原有漏看，並非第四輪修補首次引入。實驗只在臨時repo；真模型未跑。

## 根因

共用沙盒的逐題`git checkout`與`git clean`只啟動程序，沒有檢查退出碼，也沒有清理失敗時停止或標記儀器例外。第四輪替命令補了Git環境清洗，沒有處理清理結果。與source_probe每場專用副本的fatal清理路徑不同，不能拿後者的綠測試替前者背書。

## 現在怎麼繞

此分支第四輪FAIL、未放行；不執行正式模型探針，也不使用這批次輸出當可靠成績。觸發排查入口是共用副本逐題清理失敗、下一題狀態異常，或更改main的逐題清理流程。

## 什麼條件算修好

在同一兩題臨時fixture下讓清理失敗立即停止下一題，整批報儀器例外/不確定且非零退出；正常兩題、限額重試與每場專用副本既有路徑仍保持。先配對修前後同例，再走授權範圍的代碼審；不得沿用已用盡的第4輪作放行帳。
