# 輕量設計審紀錄只在本機帳乾淨clone推送誤擋

白話:規格閘說「不做清單略過了危險詞,推送前要一筆輕量設計審」;審完的紀錄只存在做審查那台機器的本機帳裡。換一台機器、或重新 clone 一份再推,推送閘看不到那筆紀錄,當成沒審而擋下。方向是往嚴的錯(多擋,不會漏放),所以排在後面處理。

## 症狀

在 `lumos init` 建的專案裡,規格閘判風險低但略過了危險詞、照指示做完輕量設計審並提交;之後在另一份乾淨 clone 推送,`lumos spec-gate --push-check` 判這份計劃沒有輕量審、擋下推送。原本那份工作目錄推送則會過。這條是 2026-10-15 對 [[Projects/筆記指令健檢與規格閘小修_計劃]] B3(規格閘留痕在乾淨 clone 不見)做實測時,讀推送閘查表的程式推得的;輕量審這一半還沒實跑重現。

## 根因

- 輕量設計審的紀錄跟其他審查席的帳一起寫進 `docs/.canary-log.jsonl`;`init` 產的 `docs/.gitignore` 把這本當本機流水帳忽略,不進版控。
- 推送閘查輕量審時讀的是同一本本機帳(`_nogo_ctx` → `_spec_gate_ledger_index`),沒有讀進版控的治理帳;代碼審通過的留痕則是寫在治理帳,所以那一條在乾淨 clone 看得到,這一條看不到。
- 工具鏈自己的 repo 審查帳有進版控,所以本 repo 不會中;只有 `init` 建的消費專案會中。

## 現在怎麼繞

在當初做輕量審的那份工作目錄推送;或在新的 clone 裡照規格閘印的指令再做一筆輕量審。不要為了推過去把本機帳檔從別台機器複製過來——那份帳沒有版控歷史,事後查不到來源。

## 什麼條件算修好

推送閘查輕量審時也讀得到進版控的治理帳(做法比照 [[Projects/筆記指令健檢與規格閘小修_計劃]] 對規格閘留痕的處理:寫審查帳時同時寫一筆治理帳事件、推送閘本機帳找不到時改讀治理帳),而且有一支測試在「沒有本機審查帳的乾淨 clone」裡,對做過輕量審的計劃推送放行、對沒做過的照擋。
