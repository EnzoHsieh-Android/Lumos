# 診斷迴圈先行

## 這條規則補的洞

lumos 原有的是 CLAUDE.md 的一句：

> 已知行為測試先行、**未知行為實驗先行**：探索性工作先做最小實驗、結論定案後補回歸測試。

**「實驗先行」沒有完成判準。** 沒有判準的紀律，等於在你最急的時候不存在——而最急的時候正是它該生效的時候。

外部對照：`superpowers:systematic-debugging` 有「穩定重現」這個**條目**，也要求修法前先寫失敗測試，但同樣**沒有完成判準**、沒有「在那道指令存在之前不准建立理論」的停止規則；而且它 Phase 3 是「形成**單一**假說」。

## 完成判準（這是本節點的全部重點）

**在你能講出這樣一道指令之前，不准開始建立理論：**

一道**你已經跑過至少一次**的指令（貼出呼叫與輸出），而且：

- **red-capable** — 它驅動真正壞掉的那條路徑，並斷言**使用者描述的那個症狀**。不是「跑起來沒炸」，是**它能對這個 bug 翻紅、修好之後轉綠**。
- **確定性** — 每次跑結論一樣。
- **快** — 秒級，不是分鐘級。
- **agent 可自行跑** — 不需要人在旁邊點。

**如果你發現自己在這道指令存在之前就在讀程式碼找原因——停。** 直接跳到假說正是這條規則要防的那個失敗。

### 怎麼建（依序試）

1. **失敗測試**，在任何搆得到 bug 的接縫上。
2. **CLI 呼叫 ＋ 固定輸入**，把 stdout 跟已知良好的快照 diff。
3. **重放捕獲的產物** — 把真實的 log／輸出／設定檔存下來，隔離餵進那條路徑。★2026-08-01 教訓：那份產物往往早就在那裡了★（`/tmp/lumos-prepush-tests.log` 從第一分鐘就存在，我到第二次診斷才去讀）。
4. **拋棄式 harness** — 最小子集，一次函式呼叫就打到 bug。
5. **差異迴圈** — 同一份輸入跑「舊版 vs 新版」或「兩種設定」，diff 輸出。
6. **bisect harness** — 症狀出現在兩個已知狀態之間時，把「切到狀態 X → 檢查 → 重複」自動化。
7. **屬性／模糊迴圈** — 「有時候答案是錯的」這種，跑 1000 組隨機輸入找失效模式。

### 把迴圈當產品來磨

有了**一個**迴圈之後還要**收緊**它：更快（跳過無關初始化）、訊號更利（斷言具體症狀而非「沒崩」）、更確定（釘時間、固定亂數種子、隔離檔案系統）。

**30 秒的 flaky 迴圈只比沒有好一點；2 秒的確定性迴圈是除錯的超能力。**

### 非確定性的 bug

目標**不是**乾淨重現，是**提高重現率**。跑 100 次、加壓、縮時間窗、插 sleep。50% 可以除錯，1% 不行——把重現率拉到可除錯為止。

### 真的建不出來

**停下來明講。** 列出你試過什麼，然後要：能重現的環境、捕獲的產物（log／trace／錄影帶時間戳）、或加臨時觀測的許可。**不要在沒有迴圈的情況下往下猜。**

## ★兩條本專案自己流血換來的規則★

### ① 更嚴重的症狀 ≠ 同一個原因

**收斂條件是「這個假說解釋得了觀察到的那幾條」，不是「這個假說造得出一堆紅」。**

2026-08-01：pre-push 測試閘紅三條，我押 `GIT_DIR` 環境洩漏；實測把 `GIT_DIR` 指向本 repo，紅的條數暴增到 **65**，機制完全講得通，於是當成找到真因、修完就推——**還是紅三條**。真因其實是交付薄殼呼叫外部 `dirname`，而測試把 PATH 縮到最小、綠或紅取決於那台機器的 `git` 裝在哪。

**65 ≠ 3 這個數字對不上，就是訊號。** 當時被「機制講得通」蓋過去了。

### ② 不得在真環境製造你要驗的傷害

**要驗「X 會造成傷害」，就在拋棄式環境造 X**（假 `HOME`／臨時 clone／worktree），沒有例外。

同一天兩犯：

- 為了驗 `GIT_DIR` 污染，直接在真 repo 上跑 → 127 筆測試 fixture commit 寫進 main（834 → 1029），得 reset 到乾淨基底重貼內容。見 [[Issues/prepush測試閘假紅-git環境洩漏]]。
- 為了驗 `teardown` 該擋 Windows 自刪，測試沒隔離 `HOME`、又用了一個**我以為存在其實不存在的環境變數** → `teardown -y` **真的執行**，刪光真機的 `~/.claude/hooks` 四支與全域 `lumos`。見 [[Issues/測試未隔離HOME刪掉真機Claude-hooks]]。

★附帶教訓★：**假設接縫存在而它其實不存在時，測試不是「紅」，是「真的去執行」**——紅燈會叫你，真執行不會。

## 假說階段

**先列 3-5 條、排序過的假說，再測第一條。** 單一假說會錨定在第一個看起來合理的想法上。

每條必須**可證偽**——講得出預測：

> 「若 X 是原因，則改 Y 會讓症狀消失／改 Z 會更嚴重。」

講不出預測的是感覺，丟掉或磨利。

**把排序過的清單先給人看**（人常常一眼就重排：「我們昨天剛動過第 3 條」）。人不在就照自己的排序往下，不要卡住。

## 修法與收尾

- 每個探針對應假說裡的一個具體預測，**一次只動一個變數**。
- 除錯用的 log 加**唯一前綴**（如 `[DEBUG-a4f2]`），收尾一次 grep 清乾淨。沒加前綴的會活下來。
- 回歸測試寫在**正確的接縫**上。**找不到正確接縫時，那件事本身就是 finding**——是架構在阻止這個 bug 被鎖住，記下來；不要退而求其次寫一條驗不到真實呼叫現場的弱測試，那會直接掉進 [[Systems/測試假綠形態]] 的第③④型。
- 收尾問一句：**什麼本來能防住這個 bug？** 答案若指向架構，那是另一個題目。

## 誠實天花板

- **這是紀律層，沒有機械閘。** 沒有任何東西會在你跳過完成判準時擋下來——它靠你記得、靠你誠實，跟 lumos 其他紀律層規則同一個等級。
- **它的效力只能事後量。** 唯一可查的指標是：之後的事故節點裡，還有沒有「跳過迴圈直接猜」這個形狀。
- 完成判準四條（red-capable／確定性／快／可自行跑）**本身就是「我枚舉了 N 條」**，同 [[Systems/測試假綠形態]] 的天花板——★假設有第五條★。
