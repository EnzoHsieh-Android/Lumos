# 每支檔有家

> 白話：每支程式檔都要有一篇「管它的」節點；節點只准寫自己管的檔；程式改了，說明寫進改到那支檔的那一篇。新加的違規在提交前、推送前當場擋，舊帳交給健檢提醒。

## 為什麼有這一道

2026-09-11 對三個 POS 消費專案健檢，客人網頁那個專案又長成一篇包全部——距離後端第一次長歪不到兩天，而且整套工具全綠。
查下來不是哪道檢查壞了，是**沒有檢查在量這個形狀**：節點用反引號寫了別人的檔，改那些檔時工具就推它、寫回就落它；
提交前只看「有沒有動任何一篇」；合約條數提醒只數合約。詳細的來龍去脈、兩次設計審的發現與處置在 [[Projects/每支檔有家_計劃]]。

## 三個進入點共用同一套判定

| 進入點 | 讀哪個版本 | 判什麼 |
|---|---|---|
| 提交前 `lumos home check --staged` | 提交索引 | 這次提交跟 HEAD 比多出來的違規 |
| 推送前 `lumos home check --diff` | 範圍兩端的提交 | 這次推送整段多出來的違規 |
| 健檢 S8–S10 | 提交索引 | 舊帳(只提醒);三段都分「上線後才出現」(有人繞過或開關被關)與「上線前就在」兩群 |

實作都在 `scripts/lumos` 的「每支檔有家」那一段;掛鉤只呼叫、不重寫判定。
