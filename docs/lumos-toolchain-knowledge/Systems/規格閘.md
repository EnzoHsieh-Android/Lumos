# 規格閘

## 為什麼獨立成一支

設計審的散文收斂在本 repo 從沒收斂過(五輪 118 條、每輪都有 blocker;見 [[Projects/規格落成可驗收條件_計劃]])。這道閘把力氣搬到「條款能不能被機器認出來、有沒有接到真的測試、跑起來是紅是綠」。半套所有計劃照舊派審——它不減少審查,只讓「條款有沒有接到測試」變成可見的數字。

## 邊界

管計劃裡 `[SN]` 那幾行、它們綁的測試、以及「這份計劃風險高還是低」的判定。2026-09-17 起也判門、放行風險低、寫審查帳留痕、在推送前讀留痕跑測試(設計在 [[Projects/雙向門放行_計劃]]);逃逸帳的寫入語意在 [[Projects/逃逸自動記_計劃]]。門是機械判、預設單向:作者只能把門往嚴調(plan_risk: high),寫 two-way 沒有意義。

**問題只有一個**:還原這次提交之後,外面的世界要不要人手動收拾?要=風險高,不用=風險低。程式碼本身永遠改得回來,所以判準看的是提交以外的副作用:
