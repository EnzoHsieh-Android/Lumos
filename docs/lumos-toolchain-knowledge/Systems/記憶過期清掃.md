## 為什麼需要它（不是理論，是實際踩到）

2026-09-14 量：76 篇記憶裡 **19 篇含「當下狀態」的宣稱**，其中 **3 篇當場被證明是假的**——兩篇寫「沒推」而那些提交早就在遠端、一篇寫「工具沒裝」而那台機器早就裝了。**這三篇的圖譜筆記都是對的，錯的只有記憶那份影子。**

**為什麼特別危險**：記憶是開場自動塞進視野的，圖譜要主動去查。**所以錯的那份先被讀到，而且會塑形之後的每一步。**

## ★時間當判準沒有用★

借的是 memanto 的形狀（過期是跑清掃執行的政策、蓋章留痕可審計、可復原），**但觸發條件必須換掉**：memanto 按類型給保留天數，而這裡量過——記憶檔「最後修改」的中位數只有 **6 天**（它們常被改）。**會爛的不是舊的，是講狀態的。**

所以改成：每一條這種宣稱自己帶一行可以跑的檢查。

## 程式在哪

`scripts/hooks/claude/memory-sweep.py`。它掛在開場事件上（註冊表與天花板住在兩家設定合併器那邊，見 [[Systems/codex-harness]]），安裝時複製到各機器的 hook 目錄。**它自己從當下目錄推算出這個專案的記憶目錄**，所以每個專案都適用；沒有記憶目錄的專案完全靜默。★原始碼裡沒有任何寫檔呼叫,有測試直接掃原始碼釘住這件事★。

## 怎麼用

```
verify:
  - claim: 這篇宣稱的那句話（寫給人看的）
    pushed: fd7cdc1          # 或 not-pushed / installed / not-installed
                             #    / before: 2026-12-14
```

**★不執行任何外來字串★（2026-09-14 改，這是這支東西最重要的設計決定）**：第一版是 `cmd:` 一行 shell。它的問題不是難用，是**這支 hook 每次開場自動跑、而執行內容來自記憶檔**——等於任何能往記憶目錄寫檔的東西，都拿到「你一開這個專案就執行一次」的能力。改成只認幾種宣告式型別(現在五種)，工具自己用參數陣列去查，**沒有 shell，記憶檔裡的字串不可能被當成指令**。

代價是新型態要改程式才能加。**現在只剩五型**（`pushed`／`not-pushed`／`installed`／`not-installed`／`before`）。原本有七型，另外兩型 `file-exists`／`no-file` 在代碼審第八輪後整類拿掉（見文首現況區塊）；實際用過的檢查除了那一條都落在這五型裡，所以代價目前是理論上的。舊的 `file-exists` 寫法同樣會被報成「驗不了」並講為什麼拿掉。舊的 `cmd:` 寫法會被**明確報成「驗不了」並說明原因**，不是靜靜跳過——靜靜跳過等於看起來有守衛其實沒有。

判過不是影子副本的，寫一行 `shadow_ok: <理由>` 下架——**理由留在檔案裡供人反駁，不是靜靜消失**。會這樣設計是因為**一份永遠歸不了零的清單注定被當背景噪音**（本 repo 的空轉週報喊了 70 天沒人理就是這樣）。

## 依據哪一套做法（2026-09-14 網搜，Enzo 要求照業界標準）

PRIOR-ART: 三個來源，都指向同一個結構，**不自創**：

- **CoALA 的記憶分類**（2023，這個領域現在通用的詞彙）：工作／情節／語意／程序四種。**本專案的切法＝語意記憶全部歸圖譜，記憶只留程序（怎麼做事）與情節（哪天發生什麼，且標明是當時快照）。**
- **兩層模式**：真相層與衍生層要分開，衍生的必須能指回原始那一筆。原話是「不把真相跟檢索分開，你的系統就會對你說謊」。另一句更關鍵：**檢索是用來找到那一筆，被讀取被引用的是那筆紀錄本身**——所以記憶可以說「去哪裡查」，不可以自己講內容。
- **權限分層**：專案共有真相 ＞ 角色經驗 ＞ 事件證據；**頭號病因是「單一事件沒經過任何閘就升格成政策」**。另外兩條可抄：政策要有「誰能撤銷」，以及**衝突要浮上來、不要靜靜挑一個**。

## 這支實際做的四種檢查

| 檢查 | 機械程度 |
|---|---|
| 每條宣稱自帶的 `verify:` 宣告式檢查 | **全機械**。對不上就報出來(唯讀,不改檔) |
| 影子副本（引用了圖譜節點、自己又在講狀態） | **啟發式**。靠關鍵字，會有誤判，所以配 `shadow_ok` 豁免 |
| 壞指標（`[[…]]` 指到不存在的節點） | **全機械**（判定邏輯有測試釘，實際目錄上的表現沒有） |
| 狀態打架（記憶說還沒做、節點已 done，或反過來） | **全機械**。★兩邊都喊出來，不替任何一邊決定誰對★；狀態詞要出現在提到該節點的那一行才算（原本拿整篇去套，一篇裡兩個狀態相反的節點會兩個都報——2026-09-14 外家席抓到） |

## 推送前的效能追問逼出一個真問題（2026-09-14）

原本每查一個節點的 status 就重走一次整個圖譜目錄——**76 篇記憶各自點名幾個節點，就是上百次整樹走訪，每次 500 多個檔**。這是「迴圈裡逐筆查」那一型，只是查的是檔案系統不是資料庫。改成走一次建成對照表再查，而且讀節點只讀開頭一千兩百個字元、不整檔進記憶體。

**值得記的是它怎麼被發現的**：不是我自己想到，是推送前那道效能追問問「迴圈裡有沒有逐筆查」，我照實回答的時候才看到。

## 自己的閘擋下自己（2026-09-14）

這支寫完之後被推送前的新增告警閘擋了 19 條，全是它自己的問題：**主函式複雜度 27，門檻 10**——正是本 repo 前一天才立的那條判準。拆成四支（數東西的、跑檢查的、蓋章的、跟圖譜對帳的）之後過關，行為沒變、發現數一樣。

其餘修掉的：沒用到的匯入、每次都重建清單的寫法、含糊的單字母變數、以及**日期用了會受時區影響的取法**（換時區跑出來的蓋章日期會不一樣）。

## ★誤判修了四輪，這是這次最大的教訓★

偵測器上線後連續四次吐出假清單，每一次都會讓人不再相信它：

1. **分隔符沒列全**——分號、引號、左括號被當成節點名的一部分，吐出「…實作;09-15」這種查無。
2. **散文裡順口提到的當成承諾**——改成只認寫成 `[[…]]` 的。
3. **記憶之間也用 `[[…]]` 互連**——每一條「相關：某篇記憶」都被報成壞指標。
4. **`rstrip(".md")` 是按字元刪不是按結尾刪**——把 `…hazard` 削成 `…hazar`。[test:t_memory_sweep_core]

**共同形態：偵測器的假陽性不會報錯，只會讓清單變成沒人看的噪音。** 這跟本 repo 那份喊了 70 天沒人理的空轉週報是同一個死法。

**★而且我第一版宣稱「三個坑都造了會翻紅的檔驗過」是假的★**（2026-09-14 代碼審 r1 合約一致席 blocker）：那條斷言的測試字串只有一行內文，而程式有個後備分支會把欄位插在同一個位置，所以斷言實際上只在檢查「字串有沒有出現」，不檢查「插對地方沒有」——**把兩個坑還原回去，它照樣是綠的**。現在的四個翻紅釘（`_stem`、`is_stamped`、撤章的完成條件、壞檔隔離）是逐條拆掉接線跑過、確認整組真的翻紅才留下的。

## 代碼審 r1 折入了什麼（2026-09-14，八席、44 條）

**六條 blocker 全部同一個形態：一支壞檔炸掉整輪。** 開頭欄位沒收尾、非 UTF-8、剛好叫 `x.md` 的目錄、檔案唯讀——任一種原本都讓整支 Python 崩潰，**而且排在它後面的記憶完全不會被檢查、跟圖譜對帳那整段也不會跑**。現在逐檔隔離，壞檔被報出來、整輪照跑完。

**最有價值的一條是外家席抓的**：時間預算用完時，跳過的檢查讓「對不上」清單變空，於是走進撤章分支——**超時會讓守衛自己把警告擦掉**。折成一條不變量：**撤章的唯一條件是「這篇每一條檢查都真的跑完而且都通過」**，跳過的、驗不了的一律維持現狀。[test:t_memory_sweep_core]

**其餘折入**（每條都是多席或單席實測重現的）：

- **崩潰沒人知道** → 接上五支 hook 共用的事件記帳，並把它加進 `lumos enforcement` 那份**寫死列舉**的判準清單。原本它不在裡面，等於靜靜失效也沒有訊號。
- **逾時互相矛盾** → git 呼叫原本寫死 20／25 秒，而外層天花板是 12；改成一律取「外層還剩多少」與單條上限的小者。注入框與逾時預算兩段改成**逐字抄正典**，讓「副本不准漂」那支測試認得它。
- **連不上遠端時拿舊快照硬答** → `fetch` 失敗一律回「驗不了」，不判死也不撤章。
- **畸形寫法靜靜蒸發** → 型別打錯字、claim 沒配到型別鍵，一律收下並報出原因。
- **狀態打架是假陽性產生器** → 狀態詞要出現在提到該節點的那一行才算。實際目錄上從 6 條假警報降到 3 條真衝突。
- **算專案目錄只換斜線** → 改成非英數一律換掉，跟同倉庫已驗證的規則一致。
- **`--restore` 路徑穿越** → 只收檔名。資安席**實測成功**寫到記憶目錄以外。
- **對 Codex 那一家沒有意義** → 直接安靜退出（記憶是 Claude Code 自己的機制）。

**折的過程自己又炸一次，值得記**：把正典的逾時函式抄過來時漏抄它的伴生常數，跑起來是 `NameError`——**而 fail-open 的包裝把它整個吞掉、安靜回 0**。看起來一切正常，其實整支沒跑。這正是「fail-open 會讓守衛靜靜消失」的現場，也正是為什麼**接上事件記帳**那一條非做不可。

## 邊界（老實講它守不到什麼）

- **「要不要寫檢查」沒有機械判準。** 這支只知道「有沒有寫」，不知道「該不該寫」。關鍵字撈得到「沒推／沒裝」，撈不到「那份自帶的工具是 9/11 版」這種沒有否定詞的腐爛宣稱。
- **檢查本身可能是假的。** 綁錯版本代號、或寫一條恆真的命令，這支分不出來。程式那邊有翻紅驗證，**記憶這邊沒有**。
- **驗不了不算過期**，會另外列出來——但那條等於沒有守衛。
- **擋不了任何事。** 寫記憶不經過提交也不經過推送，沒有攔截點。它只能在開場喊。

## 實作時踩到的三個靜默坑（都造了會翻紅的檔驗過才算修好）

- **章只蓋一半**：原本錨在 `modified:` 那一行，手寫的記憶檔沒有那欄 → 錨不到就整段不插，但正文警告照樣加；而撤章看的是開頭欄位，於是永遠撤不掉。改成錨在 `metadata:` 區塊尾。
- **子字串誤判**：用 `"status: stale" in text` 判斷有沒有蓋過章，結果「說明這個機制」的那篇記憶正文寫到那幾個字就被誤判。改成只認行首欄位。
- **比對式開了 DOTALL**：`.` 吃掉換行，欄位被插到檔案最後面——又是半套。只能開 MULTILINE。
