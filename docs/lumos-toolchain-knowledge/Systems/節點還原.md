# 節點還原

> 白話:接手一個跑了很久、圖譜是空的專案,怎麼把「這塊 code 為什麼長這樣、誰共用它、動了會壞什麼」還原成節點——七步流程,任何技術棧。本節點只記機制脈絡與指針;**操作全文的單一權威在 skill 的 reference〈節點還原(brownfield 冷啟動)〉**,設計理由與六輪 30 席 153 條的審計史在 [[Projects/節點還原SOP_計劃]]。

## 這塊拼圖補什麼

[[Systems/外部對照-code衍生wiki]] 早就承認:冷啟動整個陌生 repo 是 lumos 的弱項(對手 openwiki 的強項)。但 openwiki 式的全倉攤平=無查核的合成敘事。本 SOP 的賭注:**惰性還原**——跟著任務走、每句 why 標出處、出口過雙 agent 交叉查核,寧可慢也不編。守衛端([[Systems/check-j-regen-guard]])早已存在,本案補的是產出端(建哪些、從哪開始、多深算夠)加上索引路由(此前 commands/ 索引查「重建」零命中)。
