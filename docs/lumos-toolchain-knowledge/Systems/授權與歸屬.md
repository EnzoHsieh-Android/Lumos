# 授權與歸屬

> 白話:這個工具會把自己的程式複製進別人的專案,所以「授權放哪」比「選哪個授權」更關鍵。2026-09-06 定 MIT,而且★授權全文放在主程式檔頭★,不是只放根目錄——因為根目錄那個檔不會跟著複製過去。

## 為什麼這件事跟一般專案不一樣

散布單位是「一支裸檔飄進別人的 repo」,不是整包 repo:`lumos init` / `update` / `bootstrap` 三個入口全走同一條複製路徑,把主程式、四支輔助腳本、整個 hooks 目錄複製進消費專案,而且**不會被 gitignore**,會跟著那個專案一起被 commit。實測本機有 11 份副本,10 份在公司/客戶的 GitHub 組織裡,版本從 3628 行到 16288 行不等。

所以:根目錄放一個 LICENSE 對已經飄出去的副本毫無作用。合規完全靠檔頭。

## 決定

- **MIT**,著作權人 Enzo Hsieh(2026-09-06 本人確認歸屬)。
- **主程式檔頭帶 MIT 全文**(約 1KB、20 行,MIT 是唯一塞得進檔頭的候選)。其餘被複製的檔帶兩行 SPDX 加一行指路。
- **★LICENSE 不得加進 `_VENDORED_TOOLKIT` 白名單★**:`lumos deinit` 對白名單每一項無條件 unlink,加進去會刪掉使用者專案自己根目錄的 LICENSE。MIT 靠檔頭全文就不需要複製任何授權檔。[test:t_license_headers_travel_with_vendored_files]
- **紀律區塊模板不加授權標頭**:它會被合併進消費端自己的設定檔,標頭會落進每個人的檔案裡。改成在兩份 README 各寫一句。
- **明講「工具寫進你專案的東西是你的」**:設定檔裡的紀律區塊、使用者寫的圖譜筆記,Lumos 不主張任何權利。這句在 LICENSE、兩份 README、上手指南都有。

## 為什麼不是別的(2026-09-06 五個候選各派一個反方挑戰後裁)

- **不授權(維持現狀)**:法律預設是別人沒有複製/修改/散布的權利,而這三件正是核心用法;GitHub 服務條款只授「平台上 fork」,蓋不到 clone 下來複製進私有 repo。它唯一的優點是保留反悔權,但代價是現有 11 份副本全部沒有書面授權。
- **Apache-2.0**(次選):§4(a) 要求再散布時給接收者授權全文——11KB 塞不進檔頭、白名單又不複製授權檔;§4(b) 要求被改的檔帶修改聲明——而覆蓋式 update 會把那行刪掉。★它該贏的唯一情況★:手上有白紙黑字的外部要求(客戶合約或公司開源政策明文要專利授權條款)、或開始收外部 PR 且貢獻者受僱於有專利佈局的公司。真要改,要複製的授權檔必須另取名(不能叫 LICENSE,理由同上)。
- **MPL-2.0**:它的 Larger Work 安全港只保護「獨立的檔案」,而本工具會把紀律區塊**合併進消費端自己的設定檔**,正好落在保護範圍外——它唯一貼合的優點在最特別的那條路徑上失效。加上企業掃描會把 copyleft 標紅,曝險面是 10 個公司/客戶 repo。
- **BSD-3-Clause**:兩軸都被支配(要摩擦小 MIT 更好,要法務好過 Apache 更好),換到的只有背書禁令,而那條保護的是著作權人姓名不是專案名。

## 第三方元件(LICENSE 尾段登記)

- `scripts/vendor/marked.min.js`(marked 12.0.2,MIT,Christopher Jeffrey):★檔頭本來就有完整聲明★,內嵌時原樣跟著走,已合規。
- `scripts/vendor/3d-force-graph.min.js`(1.80.0,MIT,Vasco Asturiano):★上游 minified build 沒帶 banner,整檔找不到版權字樣★——而 `export --standalone` 會把它整段內嵌進交出去的 HTML,那是一次沒帶聲明的再散布。修法:不編輯 minified 內容,改在 LICENSE 尾段與產出 HTML 的註解裡補聲明。它打包的下一層(three r183、d3-force-3d 等,MIT/ISC)一併列出。
  - ★這份內層清單是從套件相依關係推出來的,沒有逐段讀那 1.29MB 壓縮碼確認★。REVISIT:2026-12-06 若升級 3d-force-graph 版本,用會產授權清單的工具重跑一次核對,或改用帶 banner 的官方 dist。
- CI 的 actions、可選 import 的 certifi:不隨散布物走,無義務。

## 消費端那 11 份副本:Enzo 2026-09-06 裁「不追」

Enzo 裁定:那些 repo 是**前公司**的專案,拿到的是這套治理工具的半成品;主要開發權與話語權在 Enzo 這邊。因此下列三件★明文不做★,不是還沒查:

- **不去翻那些交付合約**有沒有「第三方開源須事前核准 / 須提供開源清單」條款。
- **不主動去那幾個 repo 跑 `lumos update`** 讓舊副本換成帶授權的版本。它們要不要跟上是那邊的事;真跟上了,覆蓋式更新自然會帶到新檔頭。
- **不做補揭露**。

這條決定同時答掉了「職務著作歸屬」那個前提:著作權人是 Enzo 本人。

★這一段的意義是「以後不要再有人把它當未辦事項提出來」★——它是裁決,不是遺漏。要翻案得有新事實(例如那邊主動來問授權)。

## 其餘沒解決 / 仍要人確認的

- **一行 SPDX 是否滿足 MIT 的「permission notice shall be included」實務界有爭議**——所以主程式貼全文而不是只貼 SPDX;其餘檔案只貼 SPDX 是取捨,不是保證。
- **3d-force-graph 內層清單是從相依關係推的**,沒有逐段讀那 1.29MB 壓縮碼。REVISIT:2026-12-06 若升級版本,用會產授權清單的工具重跑核對,或改用帶 banner 的官方 dist。

## 這條合約被獨立審計判過一次 fail(2026-09-06)

派了一個沒有脈絡的審計員,要求它**實際構造破壞**而不是推論。它判 fail,列出三條實測成立的假綠管道,全部折入:

- **只驗白名單內容,擋不住繞過白名單的人**。審計員完全不碰白名單,直接在移除函式開頭加一行刪 LICENSE,原本那支測試 6/6 全綠什麼都沒發現。→ 加一支端到端測試:在假的消費專案放 LICENSE/COPYING/NOTICE,真的跑完移除流程,再確認三個檔都在、內容未變。
- **檔案清單是手寫的,跟真正會被複製的集合對不齊**。在 `scripts/hooks/` 頂層(不是 claude 子夾)新增一支沒標示的檔,它會被真的複製出去,而手寫清單掃不到。→ 改成跟生產邏輯同一套算法算(白名單 + 兩個目錄整夾遞迴),紀律模板明文豁免。
- **「MIT 全文」其實只比兩句片語**。把中段整個掏空、只留那兩句,照樣綠。→ 改成跟根目錄 LICENSE 的 MIT 正文逐行比對。
- 附帶抓到一個數字錯:摘要寫「其餘 12 支」,實際是 13 支(少算了一支 hook)。改成不寫死數字,由算法決定。

**四種假綠管道現在全部翻紅,原檔全綠**——含三席代碼審各自構造的那三種。這支測試前後被打臉四次才長成現在的樣子,每一次的壞例子都寫進 docstring,免得以後有人「簡化」它時把守衛範圍縮回去。
