# 多詞評測


## 它在量什麼

**兩臂**：一臂把整串查詢當成一個片語查（字要連在一起出現），一臂把查詢拆成各個詞分別查再取聯集。後者只在前者**全庫零命中**時才啟動。這支工具就是量「拆詞這一招到底有沒有用」。

十題全是中文多詞查詢。題目、候選池、兩位評審的分數、裁決結果、最終標註，全部存在版控裡，可以自己覆核。

## 怎麼跑

量測（要有標註）：

```
python3 governance/eval/retrieval_eval_multiword.py --labels <標註檔> --pool <題庫> --vault <語料>
```

重組候選池（不量測、不碰標註）：

```
python3 governance/eval/retrieval_eval_multiword.py --pool <舊題庫> --vault <語料> --rebuild-pool <出檔>
```

標註檔兩種格式都吃：扁平的（節點對分數）與含各評審意見的（節點對一包分數，取其中的最終分）。**還沒裁決的不算標註**，不會被當成 0 分——0 分的意思是「判過，不相干」，跟沒判過是兩回事。

## 候選池怎麼組（三個來源聯集）

- **拆詞那一臂的前十名**——現行系統自己撈到的。
- **每個詞各自出現次數最多的前三篇**——只數字面出現次數，不經排序器。
- **三個詞全都出現在同一篇、依「最少的那個詞出現幾次」取前十**——2026-09-15 新增，同樣不經排序器。

後兩個來源存在的理由是**防止只標得到現行系統找得到的東西**。池若只從現行系統的輸出來，新系統找到的好節點會因為不在池裡而沒標、被當成 0 分，量出來反而變差。

池的順序**打散**（固定亂數種子，同一份輸入每次一樣）：標註的人不該看到名次，否則標出來的答案就不再獨立於被它驗證的那套排序。

## 兩個已知會咬人的地方

- **題目寫進圖譜就毀掉那一題**——圖譜就是這套評測的語料，詳見 [[Issues/評測題目寫進圖譜就毀掉那一題]]。重組候選池時碰到被污染的題會直接擋下並指出是哪一篇筆記，不會照組。
- **標註比語料舊的時候，數字會像排序爛掉**——沒標過的一律當 0 分。輸出裡「前幾名一個相關的都沒有」那段會同時提醒這個可能。

## 誠實邊界

候選池有一半來自現行系統自己的輸出，所以分數是**池內相對值**，不是絕對召回品質；「更好的系統會找到、但現行系統沒找到」的節點，只有靠另外兩個不經排序器的來源去撈，仍然不完全乾淨。題數只有十題。
