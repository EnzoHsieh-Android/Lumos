# 多詞評測


## 它在量什麼

**兩臂**：一臂把整串查詢當成一個片語查（字要連在一起出現），一臂把查詢拆成各個詞分別查再取聯集。後者只在前者**全庫零命中**時才啟動。這支工具就是量「拆詞這一招到底有沒有用」。

十題全是中文多詞查詢。題目、候選池、兩位評審的分數、裁決結果、最終標註，全部存在版控裡，可以自己覆核。

## 怎麼跑

量測（要有標註）：

```
python3 governance/eval/retrieval_eval_multiword.py --labels <標註檔> --pool <題庫> --vault <語料>
```

重組候選池（不量測、不碰標註）：

```
python3 governance/eval/retrieval_eval_multiword.py --pool <舊題庫> --vault <語料> --rebuild-pool <出檔>
```

標註檔兩種格式都吃：扁平的（節點對分數）與含各評審意見的（節點對一包分數，取其中的最終分）。**還沒裁決的不算標註**，不會被當成 0 分——0 分的意思是「判過，不相干」，跟沒判過是兩回事。

## 候選池怎麼組（三個來源聯集）

- **拆詞那一臂的前十名**——現行系統自己撈到的。
- **每個詞各自出現次數最多的前三篇**——只數字面出現次數，不經排序器。
- **三個詞全都出現在同一篇、依「最少的那個詞出現幾次」取前十**——2026-09-15 新增，同樣不經排序器。

後兩個來源存在的理由是**減輕「只標到現行排序器排前面那批」**。

**★不要把它說得太滿★**（2026-09-15 代碼審 r2 外家否決席訂正）：**三個來源都以同一組查詢字面為入口**，所以它**不能**宣稱「更好的系統找得到的都會進池」。靠同義詞、別名或圖關係才找得到、但不含這些字面的節點，永遠不會進池、也永遠不會被標。**這把尺目前只比得了現在這兩臂**；要跟另一個系統比，必須先把那個系統的輸出併進池、把新增的標完，否則它找到的好東西會被當成 0 分。

池的順序**打散**（固定亂數種子，同一份輸入每次一樣）：標註的人不該看到名次，否則標出來的答案就不再獨立於被它驗證的那套排序。

## 標註怎麼產生（沿用既有工具，沒有第二套）

合併兩席與寫回，**都用既有的那支標註工具**，這支不自己再寫一份：

```
python3 governance/eval/refresh_labels.py merge --a <甲席> --b <乙席> --out <合併檔>
python3 governance/eval/refresh_labels.py apply --merge <合併檔> --goldset <標註檔> --adjudication <人裁檔>
```

沿用的理由是那支帶著三樣東西：寫入鎖、原子寫入，以及「還有人裁沒填就不准寫」那道閘。自己重寫一份等於把這三樣一起重寫，而這個 repo 已經為「同一個問題長出第二份獨立實作」付過學費。

代價是**標註檔要長成題庫的形狀**：有 labels、search、edit 三個鍵，其中後兩個在這裡是空的（題目存在候選池檔裡）。量測那支讀得懂這種外殼。

★寫回那支把兩席的欄位名寫死了★，記下來的來源會是錯的，見 [[Issues/標註寫回把評審名字寫死]]——實際是誰標的要看當次卷證。

## 什麼算「命中」一律問搜尋，不自己算（2026-09-15 代碼審 r1 折入）

污染檢查與候選池那兩個不經排序器的來源，**都改成問搜尋**，不再自己掃原始 Markdown。原本自己算的版本跟搜尋有三處語意不一致，每一處都會讓結果錯：

- **搜尋不分大小寫**，自己算的版本分——大小寫不同的污染會漏擋。
- **搜尋預設排除程式碼區塊、行內程式碼與作廢節點**，自己算的版本全都算進去——只出現在範例指令裡的查詢會被誤判成污染，而這篇自己的文件慣例正好就是用程式碼區塊寫查詢範例。
- **中文重疊命中**：程式語言內建的計數對「哈哈哈」數「哈哈」只回 1，實際有兩處。

附帶好處是不必把整個語料讀進記憶體。代價是每題多跑幾次搜尋，重組一次約 30 秒。

**★已交付的那份候選池是用舊方法組的★**：用新方法重組會差 17 筆（多 17、少 21）。已實測那 17 筆**一筆都不會進計分視窗**，所以 2026-09-15 那組基線不受影響、仍然可用。下次重組會得到不一樣的池，屆時新增的要補標。

## 進場前先驗輸入

語料目錄存不存在、裡面有沒有筆記、題庫檔讀不讀得進來、形狀對不對——這幾道在動任何東西之前先跑，過不了就講清楚哪裡不對、退出碼 2。**最危險的是語料路徑打錯那一種**：原本不報錯，會印「重組好了」而且退出碼 0，產出一份每題 0 筆候選的空池。

這幾道抽成獨立一支而不是塞在進入點裡，是因為推送前的新增告警閘判進入點太複雜（2026-09-15 擋下）。

## 污染兩條路都擋

量測那條路碰到污染也會擋下並退出碼 2，不是只印警告就照算——原本只擋重組那條，而量測正是產出治理數字的那條路，把錯誤輸出丟掉就完全看不出來。真的要拿被污染的題跑（例如重現舊結果）要明著加旗標，**而且那句「不得當成證據」會印在報告本體裡、逐題列出受影響的是哪幾題**——不是只印在錯誤輸出（r2 資安席：原本乾淨結果跟加了旗標的結果一字不差，事後從報告完全看不出來）。

**★重組候選池一律不吃那個旗標★**（r2 折入驗收席實測）：加了它連重組都會照組，而且**把造成污染的那篇筆記收進池裡**——等於把壞掉的題目烤進資料，後面每一次量測都繼承。量測留逃生口是為了重現舊結果，重組沒有這種需要。

## 兩個已知會咬人的地方

- **題目寫進圖譜就毀掉那一題**——圖譜就是這套評測的語料，詳見 [[Issues/評測題目寫進圖譜就毀掉那一題]]。重組候選池時碰到被污染的題會直接擋下並指出是哪一篇筆記，不會照組。
- **標註比語料舊的時候，數字會像排序爛掉**——沒標過的一律當 0 分。輸出裡「前幾名一個相關的都沒有」那段會同時提醒這個可能。

## 標註進行中不得動語料

候選池裡有四分之一的圖譜篇數。**評審在判分的時候去改任何一篇候選，等於改正在批改的考卷**——2026-09-15 那輪，三篇原本要順手更新的節點正好都在池裡。這條目前沒有機械守衛，只能記得：派了評審就不要動圖譜，等全部收回來再說。

## 誠實邊界

候選池有一半來自現行系統自己的輸出，所以分數是**池內相對值**，不是絕對召回品質；「更好的系統會找到、但現行系統沒找到」的節點，只有靠另外兩個不經排序器的來源去撈，仍然不完全乾淨。題數只有十題。

另外兩條已知的題目品質問題（一題的查詢在這個庫有三種意思、一題的查詢鑑別度太低）2026-09-15 Enzo 裁先不處理，回頭條件寫在那篇驗證裡。
