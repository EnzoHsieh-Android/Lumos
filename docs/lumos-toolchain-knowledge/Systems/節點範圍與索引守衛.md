# 節點範圍與索引守衛

> 白話：三道提醒，防止「圖譜悄悄長歪但工具全綠」。

## 這三道各自在補什麼洞

| 檢查 | 抓什麼 | 事故 |
|---|---|---|
| S5 | 計劃條款寫了測試名，但那支測試不存在 | 一份計劃寫了七個測試名，其中五支從來沒寫出來，掛了一整天 |
| S6 | 節點沒被總索引連到 | 兩個消費專案的索引是空殼，於是「這條合約該放哪」只有一個答案 |
| S7 | 一篇的合約多到一次讀不完 | 同一個作者兩天內讓圖譜長歪兩次，形狀還不一樣 |

## 為什麼是「提醒」不是「擋」

三道量的都是**還讀不讀得完 / 找不找得到**，不是對錯。擋下去只會讓人學會跳過檢查。
但★提醒型檢查一旦噪音大就等於不存在★——所以三道的門檻都拿真圖譜校準過，
而且都照既有軟提醒的截斷規則印。

實作在 `scripts/lumos` 的 doctor 那三段；測試用**合成筆記**當 fixture
（不拿會持續變動的活圖譜，否則之後新增節點就可能讓測試為無關理由翻紅）。
