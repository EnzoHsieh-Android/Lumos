# 回合結束寫法檢查

> 白話:像收工前有人看一眼你這回合寫的程式。AI 每回合要收工時,對「這一回合改過、還沒提交」的檔跑規則包,有新增告警就擋下叫它先修;同一批只擋一次,修不好就照放行指令寫理由。

## 怎麼運作

- `stop-lint-hook.py` 同一支檔註冊兩個事件,依 payload 的 `hook_event_name` 分流:
  - 送出提示:每次都把 `{prompt_id, 時刻}` 原子寫到 `~/.cache/lumos/stop-turn/<會談>`,不看專案有沒有宣告、不輸出。`prompt_id` 這個鍵存的是回合編號(Claude Code 的提示編號,沒有時是 Codex 的回合編號);同一個回合編號再送一次(Codex 回合中途插話)時,時刻保留第一次的,換回合、紀錄讀不到或壞掉才寫這次的時刻。
  - 收工:先只用標準庫預篩(repo 根 `.lumos/lint.json` 有 `ast-grep` 字樣),沒過就結束、連共用模組都不匯入;過了才比對起點、呼叫可信 lumos 的 `lint-new --worktree --since <起點> --json --pgid-file … --budget …`。
- 只在「退出碼 1、最後一行是 JSON、status 是 blocked 而且有新增告警」三件事都成立時擋;rc3 印一行、rc2 印「重跑安裝」、沒正常結束(traceback、被訊號殺掉)印一行、status off(含 `LUMOS_SKIP_LINT_NEW`)印一行,其餘不出聲。吞掉的逾時記 `timeout`、rc2 與沒正常結束記 `error`(`_hookevent.mark`);rc3 照 lint-new JSON 的 `unchecked_kind` 記——`deliberate` 記 ok、`timeout` 記 timeout、`failed` 與欄位缺或不認得記 error。
- 擋下原因逐條累加(最多 10 條、整段不超過 1500 字),結尾「另 N 條」一定留得下;放行指令照 lint-new 給的原樣印、不截斷不改字元,看起來不是那樣產生的(有反引號、換行、控制字元)整行不印。
- 擋下名額記在 `stop-block/<會談>.lint-<回合>-<批次>`(O_EXCL);佔到名額立刻輸出,寫不出去就退名額;輸出寫出去之後才呼叫 `lint-new --record-stop-block` 記一筆 `stop-lint` 治理帳。
- 逾時:lint-new 在自己的程序群組;到內層時限先 SIGTERM、1 秒寬限,過了才 SIGKILL 它與登記檔裡的工具群組。鉤子自己被 SIGTERM、SIGINT 或 SIGHUP 時同順序、等 0.5 秒;開 lint-new 到登記之間收到的先記下、登記完補跑;其他例外漏出去時 lint-new 還在跑也一樣收掉。沒有 `os.killpg` 的平台只收 lint-new 本身。
- 檢查本體(工作樹模式、白名單、改名鏈、宣告檔乾淨判法)在主程式的 `lint-new`,見 [[Systems/pitfalls-code-loop]] 的新增告警閘;這篇不管判定本體。

## 共用模組

`_hookshared.py` 放兩支收工鉤子共用、漏帶只會功能退化的那幾段:家目錄底下的標記目錄(逐層建逐層檢查)、標記目錄信任檢查、標記檔名消毒 `_mark_name` 與 O_EXCL 佔名額 `_claim_mark`(兩支的標記在同一個 `stop-block/`,規則一分家檔名就對不上)、檔名消毒、git 防護清單與環境注入。收工點名照名字匯入回來(見 [[Systems/graph-sync-coverage]])。只用標準庫、沒有模組層 I/O;匯入約 3.5 毫秒(實驗 E12)。

**可信來源解析與逾時預算不在這裡**:那兩段跟安全邊界綁在一起,照 [[Systems/hook信任邊界]] 是每支鉤子自己的逐字複本,守衛逐字比對(代碼審 r1 曾發現它們被搬進共用模組、守衛跟著放寬到擋不住「換成從 PATH 找」,已搬回)。
