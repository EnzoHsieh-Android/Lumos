# 安全證據閘

白話:盤點(security list)把資安護欄列成一張表;這道閘把表上每一條 active 的資安護欄拿去對「真的跑過、對得上現在版本、抓得到錯」的工具結果,拿不出來推送時就擋。設計與條款在 [[Projects/安全主張驗收閘_計劃]];盤點本身的讀法在 [[Systems/lumos-cli-read]],威脅類別表在 [[Systems/資安威脅類別表]],code-loop check 其他幾道在 [[Systems/pitfalls-code-loop]]。

## 現在有什麼

- `lumos security evidence [--commit <sha>] [--json]`:唯讀判定;`code-loop check` 的安全證據那一道呼叫同一支 `_secev_evaluate`,同一個提交、同一個主線 tip、同一個 UTC 日期是同一個答案。只讀提交樹、不讀工作目錄,不執行任何掃描或壓測;security_verdict 固定 not_assessed。
- `lumos security approvals payload|verify`:核可鏈 `.lumos/security-approvals.jsonl` 的「印出要簽的那一筆」與「從頭驗整條」。寫入型在 code-loop 族:`code-loop security-approval-add`(驗過整條鏈加這一筆才追加)、`code-loop security-backing`(guard kill 背書寫進受版控的 `docs/.security-backing.jsonl`)。
- `code-loop check --security-only [--at-sha]`:只跑這一道,tag 與非分支 ref 用;任何非 0 都是擋下。
- 判定:每條護欄先看護欄層(必要種類或威脅類別空、表版號不認得、核可過的表算出的最低種類不夠、來源決策作廢、引用的待決問題沒結 → unsound,例外蓋不掉),再逐種類看證據(同種類多筆取最差,好的蓋不掉壞的),最後看例外。原因代碼的單一來源是程式裡的 `_SECEV_CODES`。
- 三版凍結:必驗集合是推送版、merge-base 版、主線 tip 版 active 資安條目的聯集;推送版刪掉、降級或變弱而核可鏈上沒有 revision 核可的,照嚴的那版判;主線 tip 版有、推送版刪掉的證據項照算。
- 判不清就擋(evaluation_error、evaluation_timeout、mainline_unknown…),不走同族的 `_gate_failopen`;誤擋的出路是使用者簽例外或 gate_setting 降成只提醒。

- 給消費專案的使用說明:lumos-project-notes skill 的 commands/10-資安護欄(什麼時候登記、圍欄範例、證據欄位、哪些判斷要使用者簽);守則範本查詢表與 skill 首頁各有一行指過去,範例由測試對真盤點解析守著,設計見 [[Projects/資安護欄登記手冊_計劃]]。
- 接線:pre-push 對分支 ref 照舊叫 `code-loop check`(安全證據那一道在裡面),對 tag 等非分支 ref 叫 `--security-only`;CI 的分支推送在 code-loop gate 那步一起判,tag 推送由 security_tag 工作判;doctor 對有登記但 CI 缺這兩樣的消費專案印可貼的範本(只提醒)。掛鉤原因對照表的第五句正本在 [[Projects/推送前一次列出全部擋下原因_計劃]]。
