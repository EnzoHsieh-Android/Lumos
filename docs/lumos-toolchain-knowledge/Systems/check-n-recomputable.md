# Check N — 可重算數字宣稱（存查詢不存答案）

## 語法

在節點正文，把標記緊跟在數字後面：

```markdown
- **修法**：**7 處** <!--lumos:count=7 re=某正則 in=**/PointsMall*.cs--> 全部放寬為…
```

`doctor` 會用 `re=` 的正則掃 `in=` glob 命中的檔案，算出實際數，跟 `count=` 比對。

## 為什麼需要它

F 類（寫死易漂的值）在 2026-08-12 那輪全 24 篇交叉審計中**每一批都復發**：

| 節點 | 寫的 | 實際 |
|---|---|---|
| 點數商城 | 「共 5 處」「5 處全部放寬」 | **7 處** |
| QA驗收清單 | 「46 場景」 | **40**（§9.4 被砍） |
| 會員專區 | 「8 個元件」 | **9**（漏列 `AddressEditModal`） |
| 票券帳務字典 | `TicketRepository.cs:173/392` | **189/415** |
| 滿額贈 | 「11 情境通過」 | 早已不只 |

★**最刺眼的是**★：2026-06-10 的首輪交叉審計**就把這條寫成教訓**了——「計數/清單型主張最會漂，這類數字要附截止日或乾脆不寫死」。
**但沒有配任何機制**，於是兩個月後照樣復發五次。

> 這是「**知道了但沒有機制逼你做**」的標準案例。Check N 就是那個缺掉的機制。

## PRIOR-ART

`PRIOR-ART: borrow-design。借 doctest(Python 2001 起)的單一真相源哲學——同一份東西既是文件也是可執行檢查,不維護第二份。差別:doctest 執行程式碼比對輸出;這裡不執行任何東西,只重算「數量」這種可靜態計數的宣稱。`

## 安全邊界（節點內容＝使用者輸入，不可信）

- **不執行 shell、不 `eval`**——只用 python `re` + `fnmatch`
- 掃描量上限：4000 檔 / 40MB，超過就落成提示要你收窄 glob
- ★**壞正則吞成單條提示，不炸 doctor**★

## 為什麼是軟提醒

數字漂了是「**提示你更新**」不是「你錯了」——code 本來就會長。
真正該硬擋的是合約（Check T：★INVARIANT★ 沒綁測試就擋），不是計數。

## 已知限制

- **只處理「數得出來」的宣稱**——「行號」目前不支援（行號要的是位置不是數量，正解是**改寫成方法名/符號名**而非重算）
- glob 寫太寬會掃很久（有上限保護，但會變成提示而非答案）
- 標記本身要有人寫；**存量節點不會自動獲得保護**
