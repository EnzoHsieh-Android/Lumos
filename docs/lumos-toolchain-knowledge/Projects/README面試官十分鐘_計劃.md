# README面試官十分鐘_計劃

> 白話:把 README 改成面試官花 10 分鐘就能讀懂「這是什麼、解決什麼問題、怎麼運作、做到什麼程度」的版本;順手把跟現在程式對不上的措辭改掉。和 Codex 分工:它逐句對程式碼查核、之後審稿,我合稿改寫。

PRIOR-ART: 沿用 [[Projects/對外說明親和化改寫]] 的四站骨架、圖與兩道既有文件守衛(文件裡教的指令要存在、安裝網址不得指開發線);不新增圖、不新增機制。
RETIRE-IF: README 不再作為求職展示入口,或讀者再次換成「潛在使用者」時,改回以安裝轉換為主的版本。

## 範圍

- 動:README.md、README.en.md 的正文措辭、段落長度、段落順序微調。
- 不動:圖(assets/)、深入文件(docs/)、工具行為。深入文件的措辭漂移若查到,只記下不修,另開。
- 使用者既有裁定照舊:「節點」「圖譜」兩個詞可以留;〈成本與界線〉不回 README;循環是主軸。

## 分工

1. Codex:逐句查核 README 主張對不對得上程式碼,輸出「主張/判定/依據(檔+函式)」表。唯讀。
2. 乾淨讀者(Claude 子代理,不給脈絡):扮面試官讀 10 分鐘,回報看不懂、覺得是空話、想追問的地方。
3. 我:合兩份,改寫中文版,再同步英文版。
4. Codex:審改寫稿(事實有沒有被改錯、白話有沒有犧牲準確度)。

## 驗收

- 中文正文(去標籤)字數降到約 4,000 字以內,估讀 10 分鐘(含看圖)。
- 查核表裡判「對不上」的每一條,在稿中都有處置(改寫/刪除/保留並說明理由)。
- 兩版錨點與圖片路徑 0 斷;文件子集測試綠。
