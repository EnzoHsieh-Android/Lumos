## 要回答的問題(設計審 r1 的發現就是假設,實驗逐條量)

1. **「消失」怎麼判**:逐檔比(搬到別的檔會被當消失,r1 在 b2fc512 量到 38 個名稱、127 行)vs 全 repo 比(同名定義會遮掉真消失)vs 起點終點做改名配對。r1 出處:正確性 F4、外家 F11、邊界 F1。
2. **同一次推送裡寫下又失效的句子**(A1:b2fc512 裡寫下、同一提交裡失效,名稱在起點也不存在):要不要改成「新寫的行提到終點不存在的符號就列」,那樣的誤報多少。r1 出處:正確性 F1(b2fc512 有 91 行因「新寫的跳過」被放過)。
3. **撤除過的節怎麼認**:rtb 主力家筆記用括號行 `(… 撤除 …,見文末〈…〉)`,不是引用區塊;字樣比對又會把「尚未撤除」當撤除(delguard 已否決過字樣判法)。r1 出處:正確性 F2、外家 F6、delguard 計劃 r2 改判。
4. **「家」怎麼算**:消失名稱原本所在那支檔的家(起點的樹)vs 範圍裡任一改到檔的家;改名後終點 about_code 已換成新路徑的情形。r1 出處:正確性 F3、外家 F9。
5. **跟 delguard、Check Y、drift-history 的關係**:共用骨架、收窄輸出,還是另開一支。r1 出處:架構對齊 F1、F2、接手 F2。
6. **歷史過濾與成本**:「曾經定義過」會挑中講「已移除」的正確歷史句(r1 在 rtb 粗算 149 筆、115 筆在含撤除字眼的行);`git log -G` 單次約 14 秒,不能放進每次推送都跑的 doctor。r1 出處:正確性 F10、併發 F1、邊界 F5、外家 F12。
7. **非 Python 專案**:識別字比對的誤報沒量過,不能跟 Python 同一個預設擋。r1 出處:外家 F8、接手 F3。
8. **筆記點名的測試已不存在**(`[test:]` 懸空):rtb 有 72 處;從沒存在過的(寫錯名字)算不算要列。r1 出處:正確性 F9。
9. **Python 抽取的細節**:某一版 ast 解不開(語法錯誤、合併衝突殘留)時整檔怎麼算(不能當「全部消失」);模組層常數的值是運算式(`int(os.environ…)`)時比不比;條件式定義(`if …: def f`)與動態產生的名稱(`globals()[…]`)抓不到要不要揭露。r1 出處:邊界 F2、F7、F8。
10. **只有一棵樹時怎麼跑**:推送閘有起點與終點可比「消失」,健檢只有現況一棵樹——健檢要跑這一道的哪一部分(只跑「新增程式檔喚醒否定句」?完全不跑?)。r1 出處:正確性 F16。

## 實驗怎麼做

- 寫一支只算分數、不擋任何東西的實驗程式(放在 `governance/eval/drift-exam/` 旁,不進 `scripts/lumos`,也不接任何掛鉤),對考卷機制①那 9 題(A1–A3、C1–C3、D1–D3)的失效提交與 13 題非漂移,跑每種判法,記:擋到、點到、漏、誤報、每個提交的「要處理」筆數。
- 另外對工具鏈自己最近 50 個提交跑同一批判法,量日常推送的噪音。
- 結果寫進本篇〈實驗結果〉,再照數字開設計(或依 RETIRE-IF 只留提醒)。
