## 最小改法

影響分析種子入口沿用原簿記目錄、原程式副檔名／首行辨識與 Git 凍結模式／物件；只排除已知普通非程式附件。程式副檔名、無副檔名腳本與可執行檔保留；無副檔名普通卷證按凍結首行排除，未知或超過既有上限時保守保留；已刪檔用刪除前模式，staged 用索引模式。共享審查角色檔案消費者使用同一入口，不另抄一套程式清單。附件仍由 Git 追蹤。零新依賴，不改評分、鏡頭快取、合約條款、審查輪數與處置語意。

- [S1] 當差異只含既有簿記目錄下的審查附件時，系統應排除歷史片段；當差異同時包含正式程式、已刪檔或相鄰目錄程式時，系統應保留其種子、家與事故，而卷證檔仍被 Git 追蹤。[test:t_impact_diff_review_artifacts]
- [S2] 當真正程式的檔名含換行或 tab 時，系統應以精確路徑保留種子、家與事故，並排除相鄰普通附件。[test:t_impact_diff_special_paths]
- [S3] 當首行候選物件的累計宣告大小超過既有首行上限時，系統應停止超額內容讀取並保守保留未讀項目，而未指定整批上限的舊消費者應維持原語意。[test:t_impact_diff_head_batch_total_cap]
- [S4] 當角色鏡頭剩餘正預算於新增簿記查詢階段耗盡時，系統應將剩餘時間傳給 raw 查詢、停止後續首行讀取並明示超時。[test:t_review_role_bookkeeping_remaining_budget]
- [S5] 當真正程式改名進簿記目錄且終點成為普通附件時，系統應保留舊側程式刪除的種子、家、事故及角色輸入；一般程式改名的角色清單仍只取新路徑。[test:t_impact_diff_bookkeeping_boundary_rename]



已知普通附件：在既有簿記目錄中，模式已知且不是100755、原程式副檔名判準未命中；需要首行判斷的類別另須從對應凍結物件確認不是 shebang。未知：模式資料缺席；或需要首行判斷但物件名稱為零、首行批次讀取失敗、單一物件缺失／超限、路徑特殊字元使首行不可安全批次讀取；這些狀態不當作排除證據，保守保留。raw diff 整體讀取失敗仍走入口既有錯誤回傳。固定帳檔、圖譜與 golden 的先行排除維持原範圍；不把全域舊排除規則改寫成所有目錄皆保留程式。
