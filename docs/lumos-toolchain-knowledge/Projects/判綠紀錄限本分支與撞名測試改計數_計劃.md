# 判綠紀錄限本分支與撞名測試改計數_計劃

> 白話:紅燈版實跑三缺口(PR #154)合併後回 mOrangePos 考場做平板實機驗收,又抓到一個問題:治理帳被 git 忽略時,別條分支留下的「判綠」紀錄會漏到新分支,新分支一個紅燈版都存不到、不出聲。順手收掉兩件小事:主線 CI 時好時壞的那支效能測試、代碼審 r5 放行時寫進回頭條件的三引號常值斷言與兩處註解。

## 名詞

- 紅燈版:規格閘判出紅的那一刻,把那支 Kotlin/Java 測試檔整份存下;推送前比對拿它當新測試的改動前版本,抓「把預期值改成實作輸出」這類作弊。
- 判綠紀錄:規格閘判出綠的測試記一筆(spec-gate-green 事件),之後同一支測試再判紅也不存紅燈版(判綠過的不算實作前的版本)。
- 治理帳:docs/.governance-log.jsonl,規格閘留痕與判綠紀錄都寫在這裡;設計上要進版控,mOrangePos 從 2026-06 起把它設成 git 忽略。
- 祖先:git 歷史上,從目前 HEAD 往回走得到的提交。
- 分岔點:這條分支跟主線分開的那一版提交;治理帳被 git 忽略時,那一版的提交裡根本沒有治理帳。
- head_sha:寫治理帳事件時 `_gate_event` 自己跑 `git rev-parse HEAD` 記下的當下 HEAD;git 叫不起來時不寫這欄,還沒有任何提交的 repo 會寫成字面的 HEAD(兩種都不像提交編號)。
- 事件的分支名(ref 欄位):`_gate_event` 已有的選填欄位,端到端驗收的事件已經拿它記分支名;本計劃讓規格閘留痕與判綠紀錄也記。
- 考場:mOrangePos 的演練工作樹與只留本機的分支,拿來實機驗 lumos,不推、不併。
- 撞名:`-t`/`-g` 這類用名字篩測試的參數,會連帶選中別支名字相近的測試。標題索引(`_TitleIndex`)是把整個平台的測試標題建成可查的索引,每個平台建一次,之後每個綁定名(條款 `[test:]` 寫的測試名)只在它上面查;索引裡另把標題按種類串成一長串(`_join`),每種串一次。
- 比對工具:`lumos test-guard`,拿改動前版本對照新測試抓作弊;它列的 tq/assert-weakened 是「斷言變少、相等比對變少,或實際值被換成常值」。

## 問題與最小解

立案(2026-11-03,Enzo 原話):看完實機驗收結果後「處理掉」。

1. **判綠紀錄跨分支漏過來**:`_redbase_branch_rows` 拿工作目錄的治理帳減掉分岔點那一版,算出「這條分支自己寫的」紀錄。治理帳被忽略時分岔點那一版根本沒有,工作目錄裡所有分支、所有計劃留下的紀錄都被當成這條分支的。考場實測:上一條分支實作完成後補跑留下的判綠紀錄(head_sha 9101c0b,不是新分支的祖先)漏到從設計重來的新分支,五支測試全被判成「曾判綠,不算實作前的版本」,一個紅燈版都沒存(卷證在考場本機分支 drill/service-charge-e2e2 的 drill-evidence/redbase-realrun2/)。同一份計劃在任何分支判綠過一次,之後所有分支都失去比對作弊的起點。
2. **效能測試在 CI 上時好時壞**:`t_name_collision_scales` 要證「撞名判定每個平台只建一次標題索引」,卻每次直接傳原始標題清單給 `_name_filter_collisions`,等於每個名字都重建一次 22000 筆的索引;本機 5.8 秒,CI 兩次 16.2、18.5 秒超過 15 秒門檻(PR #153 的 CI 與它合併後的主線 CI)。
3. **代碼審 r5 放行時寫的回頭條件**(見 [[Projects/紅燈版實跑三缺口_計劃]] 做法 1):`_TG_CONST_PAT` 不認三引號字串;`_tg_ident` 的說明寫錯傳進去的函式;`_TG_LIT_PAT` 的註解沒寫明跟 `_C_STRIP_PAT` 的差別。

最小解:①規格閘留痕與判綠紀錄多記分支名(治理帳多一個既有欄位);只在治理帳被 git 忽略時,讀紀錄改成「同一份計劃、同一個分支名、head_sha 是目前 HEAD 祖先」才算這條分支的;判不了的照舊算(跟現在一樣)。代價:治理帳被忽略的專案,壓過或 rebase 過的分支上舊的判綠紀錄不再算數(見天花板一);②效能測試改成走正式的快取路徑 `_name_collision_reason`,數標題索引與串接各建了幾次,牆上時間只留寬鬆的安全網;③`_TG_CONST_PAT` 補三引號、兩處註解改對,比對工具的測試補一個三引號常值的案例。

不放進本計劃:考場更新 lumos。`lumos update` 除了換考場分支裡的工具檔,還會拉工具鏈來源 repo、設 repo 共用的 hooksPath、覆寫整台機器的全域掛鉤與設定(`_vendor_toolchain` 與 `_sync_global_from_project`),不是分支內可還原的改動。本批合併後當成一次部署另外做,做之前確認沒有別的會談正在用那些掛鉤。

PRIOR-ART: 判斷一筆紀錄屬不屬於目前分支,git 的標準問法是 `git merge-base --is-ancestor <提交> HEAD`(rc 0 是祖先、1 不是、其他是錯誤;https://www.kernel.org/pub/scm/git/git-manpages.git/tree/man1/git-merge-base.1);用它過濾時,被壓掉或 rebase 掉的提交的紀錄也會被濾掉,而且別條分支合併進主線後它的提交也成了祖先,所以單靠祖先不夠,再加比分支名(本 repo 端到端驗收事件已經用 ref 欄位記分支名)。本 repo 既有的判祖先寫法在 `_note_reread_own_fps`:rc 0/1 直接用,其他回傳碼再用 `cat-file -e` 問提交在不在,本計劃照它寫。效能測試改數次數:要證的是「不重做」這個行為,數建構次數是確定性的檢查,不受機器快慢影響;牆上時鐘門檻只能證「這台機器夠快」(本 repo 測試品質標準的抓錯證據原則)。
既有否決的對照:[[Systems/規格閘]] 判綠那條 WHY 的不選理由否決過「記寫入當下的版本編號」,因為壓提交後原提交不在。那條原文是「記寫入當下的版本編號跟測試首次提交比」;本計劃仍用 head_sha,是因為只在治理帳被忽略時才用(那種專案分岔點相減根本做不了,沒有別的訊號),而且拿分支名補上;治理帳進版控的專案照舊只靠分岔點相減,不受壓提交影響。
RETIRE-IF: 治理帳在所有消費專案都進版控時,第 1 項的過濾不會再被走到,可以拿掉 [retire:人裁] [until:2027-05-03]

## 做法

1. **治理帳被忽略時,判綠紀錄只認本分支的**:
   - 取分支名抽成一支小函式,借回頭重讀的 `_note_reread_branch`(`symbolic-ref -q HEAD`、同一道控制字元清洗)再去掉 refs/heads/(不用 `--short`,有同名 tag 時它回 heads/<名>。分離 HEAD 或 git 失敗回空字串),寫入端兩處與讀取端共用;`_redbase_branch_rows` 現在在 `if head:` 裡面才取,要搬到外面,HEAD 還沒有提交時也取得到分支名。
   - 寫入:規格閘留痕(spec-gate-record)與判綠紀錄(spec-gate-green)兩處 `_gate_event` 呼叫多傳 `ref=<目前分支名>`(取不到就不傳)。留痕那筆的 extra 由留痕內容組成,組之前確認裡面沒有同名的 ref 鍵。
   - 部分複製的認法(`_git_partial_clone`,回頭條件那支也用):`git config -z --get-regexp` 讀三個設定(以 NUL 分隔,遠端名含空白也切得對),`promisor` 的值照 git 自己的布林規則(`_git_bool`:裸鍵與非 0 整數算真,false/no/off/0/空字串算假);判不了回 None,回頭條件那支把 None 當判不了(代碼審 r3 三席與架構對齊席)。
   - 讀取:`_redbase_branch_rows(rr, loop=None, ignored=None, budget=10)` 多收這份計劃的迴圈編號、治理帳被不被忽略與過濾那段的秒數(預設值讓既有只傳一個參數的呼叫,例如 `t_spec_gate_redbase_written_on_red`,行為不變)。先問 `_git_partial_clone`:是部分複製(或判不了是不是)時不讀分岔點那一版(讀舊版本會自動連遠端、逾時殺不到抓取的子程序,代碼審 r1 r3 資源席)——帳被忽略就直接讀整本工作目錄的帳,帳不是被忽略就印一句這次沒有判綠觀測與去重、回空清單;不是部分複製時照舊減分岔點那一版(帳被忽略也減:帳曾進版控、後來才改成忽略時,主線上的舊判綠要減掉,代碼審 r4 通才席),沒有分岔點時減空樹,空樹照這個 repo 的格式算(`_drift_empty_tree`,SHA-256 的 repo 跟 SHA-1 不同,代碼審 r3 r4 邊界席)。收齊紀錄後 loop 有給就只留 loop 是這份計劃的。`_redbase_attach` 先叫一次 `_gov_ledger_ignored`,結果傳給它,寫完紅燈版後的提醒也用同一個結果,不重複問 git;截止時間在過濾前一刻用 budget 起算。帳不是「被忽略」(進版控或判不了)時不做分支名與祖先過濾。
   - 被忽略時逐筆判,判斷依序是:
     a. 紀錄有字串的 ref、目前分支名也取得到、兩者不同 → 丟。
     b. head_sha 不是字串或不像提交編號(既有的 `_LENS_SHA_RE`),或目前 HEAD 解不出來 → 留。
     c. 同一個 head_sha 只問一次 `git merge-base --is-ancestor <head_sha> HEAD`:rc 0 留;rc 1 → 不是淺複製就丟、淺複製留(淺複製的歷史被截掉,rc 1 不可信);其他回傳碼 → 再問 `cat-file -e <head_sha>^{commit}`(回傳碼的處理借 `_note_reread_own_fps` 那一段;它存的是「不是祖先」、比的是分岔點、沒有淺複製判斷,只借回傳碼處理):提交不存在而且不是淺複製就丟,其他留。
     d. repo 種類跟回頭條件那支 `_drift_born_env_err` 共用判法,第一次需要時問一次:部分複製用新的共用函式 `_git_partial_clone`(git 設計文件寫明三個設定各自認定承諾遠端:`extensions.partialClone`、`remote.<名>.promisor=true`、`remote.<名>.partialCloneFilter`;只看第一個會漏掉 git 2.39 `clone --filter` 只寫後兩個的複製,代碼審 r2 邊界席),是部分複製就整批不問 git、照留(部分複製問本機沒有的提交會自動連遠端抓,逾時殺不到抓取的子程序,代碼審 r1 資源席);淺複製用既有的 `_git_is_shallow`,逾時當判不了(留)。只有判成完整 repo 時,rc 1 與提交不存在才丟。
     e. 所有 git 呼叫走 `_lens_git_dl`,共用一個截止時間(具名常數 `_REDBASE_ANC_BUDGET_SEC`,10 秒);a 丟掉之後還要問 git 的不同 head_sha 超過具名常數 `_REDBASE_ANC_CAP`(200 個)時,從最新的問起,較舊的不問(較舊的照留,比最新的別分支判綠漏過來代價小)。截止時間在問祖先前一刻才起算,讀帳與算分岔點不吃這份預算。b 以外因為判不了而留下的(淺複製、部分複製、git 叫不起來、過了截止時間、超過上限)合計 N 筆,N 大於 0 就印一句「N 筆紀錄判不了是不是這條分支的,照舊算進來」。
   - 方向:判不了一律留,是因為留下就是現在的行為(不會比現在更鬆);鄰居 `_note_reread_own_fps` 判不了當「不是」,是因為那裡「不是」才是安全的一邊,兩邊各取自己安全的方向。
   - `_redbase_branch_state` 拿同一批列判「判綠過沒」與找「上一份紅燈版」,過濾後兩者都只看本分支的紀錄;別條分支的上一份紅燈版不再拿來去重,這是預期效果。
2. **效能測試改數次數**:`t_name_collision_scales` 改成走 `_name_collision_reason`:
   - 暫時把 `_raw_test_titles` 換成回傳那 22000 筆標題;把 `_TitleIndex` 換成會計數的子類,數建構次數,並記下同一種串接每次拿回的結果是不是同一份(重算一次就多一份;只數「快取沒命中」看不到快取守衛被拿掉,代碼審 r1 邊界、整合席)。換成函式不行:`_name_filter_collisions` 用 isinstance 判是不是索引。兩者都在 finally 換回(載入的模組是全測試共用的單例);
   - pentry 照既有測試的形狀給 `{"profile": {..., "name_filter": "regex_tail"}, "root": ..., "profile_name": ...}`(給 `ident` 會直接回 None、不建索引,測試空轉);
   - 同一個 cache 底下 1000 個名字:`_TitleIndex` 恰好建 1 次、每種 (種類, 大小寫) 組合只算一次(之後每次拿回同一份);牆上時間 60 秒內只當安全網(本機實測 0.29 秒)。
   - 「`containing` 退化成逐筆線性掃描」這類只慢不重做的退步,次數與 60 秒安全網都不會紅(原本 15 秒門檻在 CI 上時好時壞,也不能拿來守它)。
   REVISIT:2027-05-03 本機量一次 1000 個名字的撞名判定耗時(本機 0.3 秒),超過 2 秒就查 `containing` 有沒有退化成逐筆掃描,並想一道不靠牆上時鐘的檢查
   - 同步改 [[Projects/測試名收自由字串_計劃]] 綁這支測試的那條「15 秒內做完」條款,與 [[Systems/test-profile-multiplatform]] 講這支測試的那句,改成「索引只建一次、串接只算一次」。
3. **三引號常值斷言與註解**:
   - `_TG_CONST_PAT` 的字串那段照 `_TG_LIT_PAT` 開頭那段三引號樣式抄一份,註解寫「三引號寫法同 `_TG_LIT_PAT`」(本 repo 樣式常數都是獨立字面字串、互相抄並註明出處,不拼接,定義順序也不用動)。`_TG_CONST_PAT` 有三處 fullmatch:`assertThat` 單參數的那個參數、`assertTrue`/`assertFalse` 的條件、實際值參數全是常值;三處都會一起認得三引號,不只 S4。
   - `t_tq_guard_string_comma_args` 補一個案例:`assertEquals(1, f())` 換成 `assertEquals("""a""", """a""")` 要列 tq/assert-weakened(現行程式不列,先紅);測試說明補上本計劃的條款。
   - `_tg_ident` 說明改成「只換字串外壓法的呼叫端傳 fold(例如 `_tg_ws_keep_strings` 傳 `_tg_ws_collapse`)」。
   - `_TG_LIT_PAT` 註解寫明跟 `_C_STRIP_PAT` 的主要差別:它要求字串收尾、只認 `"""`、單行雙引號與單字元 `'x'`;`_C_STRIP_PAT` 還收沒收尾的字串、三個單引號、C# 的 `@"…"`、反引號,而且連註解一起吞。
4. **寫回既有筆記**(這幾句會因本計劃變假):
   - [[Systems/規格閘]] 判綠那條 WHY:改成「同一條分支(治理帳被忽略時認分支名與祖先)之後再跑出紅,那支不存紅燈版」,並寫明不選理由那條為什麼這次仍用 head_sha(見上面〈既有否決的對照〉)。
   - [[Projects/規格閘紅燈測試快照_計劃]] 講「判綠觀測只看這條分支自己寫的那幾筆(跟分岔點那一版做行差)」「只有在 main/master 才看整本帳」「判綠過的不存」那幾段:補治理帳被忽略時的認法。
   - 比對工具的已知限制清單 `_TG_LIMITS` 與測試品質標準裡同一份「抓不到」清單,「判綠過的不存」補一句「治理帳被忽略的專案,壓過或 rebase 過的分支上舊的判綠紀錄不算」;這份清單由 `t_tq_guard_cli_contract` 逐字比對釘住,兩處一起改,補的句子不含句號。
   - [[Systems/test-guard]] 講字串常值樣式那條 WHY:補「判常值斷言的樣式也認三引號」。
   - [[Projects/紅燈版實跑三缺口_計劃]] 做法 1 的「已知漏判」那段改寫成歷史說法(「r5 放行時不認,已由本計劃補上」),它的 REVISIT 行加 `[closed:日期 本計劃補上]`;同計劃講三引號「幾處一起生效」那句一起核對。

## 驗收條款

- [S1] 當治理帳被 git 忽略、裡面有同一份計劃在別條分支(分支名不同)留下的判綠紀錄時,規格閘應照樣存那支測試的紅燈版 [test:t_spec_gate_redbase_green_other_branch]
- [S2] 當治理帳被 git 忽略、判綠紀錄的分支名相同(或紀錄沒有分支名),而且 head_sha 是目前 HEAD 的祖先或紀錄沒有 head_sha 時,規格閘應照舊不存那支測試的紅燈版 [test:t_spec_gate_redbase_green_other_branch]
