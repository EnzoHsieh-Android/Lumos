# 中文無空白查詢回退_計劃

> 白話:用一串沒有空白的中文查圖譜,**結構上永遠查不到**——除非那一整串剛好逐字出現在某篇筆記裡。
> 現在的做法是印一句「請加空白再查」。而 CLAUDE.md 的第一條紀律就是在教這件事;
> **一條紀律存在,就代表這個坑一直有人踩,而踩的人是每個新 session 的 AI。**

## ★第一輪把這份計劃打掉了大半,先誠實記★

五席合起來否掉了第一版的四個前提。**其中一條是我自己的品質問題,不是設計問題**:

- ★我編了一句引言★:第一版寫「這個 repo 明文寫過『0 筆不是沒記,但也不能假裝有記』」——
  **那句話全 repo 查不到**,兩席各自 grep 後同時抓到。真正可查的是 CLAUDE.md 的
  「0 筆不是沒記——看『逐詞覆蓋』裡標 ★ 的那個詞是 0,換同義詞再查」,
  而且它講的是**多詞查詢的逐詞覆蓋**,不是泛用的 0 筆語意。
  獨立事故筆記見 [[Issues/把自己的推論寫成repo明文寫過]]。
- **「切詞器已經在做召回」是假的**:它只服務排序(重排既有候選)。
  真正做召回的是另一份帶三道濾網的邏輯,而且那三道濾網是實測逼出來的
  (某個純數字命中 381/385 等於全庫召回;單字漢字也是全庫召回)。
- **「先補評測題再翻預設」跟前例的教訓相反**:那篇有一節標題就叫「★上一版想錯了★」,
  寫著「原本打算先補評測集再動 code。**做不到**——候選池撈不出東西就沒得標」。
- **「退回之後幾乎不可能回 0」是錯的模型**:實測不是「訊號必然消失」,是**兩態分化**——
  稀有字對仍誠實回 0(五個假話題有三個全字對零覆蓋);
  但只要一個常見字對命中就爆量(我自己舉的例子回 150/434 篇,全庫 35%)。

## 先講幾個詞

- **字對**:把中文連續段切成相鄰兩字一組(「檢索優化」→「檢索、索優、優化」)。程式裡叫 bigram。
- **召回 vs 排序**:召回是「決定哪些筆記進入候選」,排序是「把已經在候選裡的重新排名次」。
  **這兩件事在這支程式裡是兩份不同的碼**,第一版把它們當成同一支。

## 設計

### [S1] 順序:先實作(藏在旗標後)→ 組池 → 標註 → 量測 → 才決定要不要變預設

★這是照前例訂正過的順序,不是我原本想的那個★。理由就是前例寫的:
評測的組池工具靠現有搜尋撈候選給人標註,而現在這些查詢回 0 候選,**沒東西可標**。
所以必須先讓新回退能跑(藏在旗標後、預設不開),候選池才撈得出東西。

### [S2] 評測要另開一套,不進既有題庫

★不准塞進既有的搜尋評測★:那支評測的兩臂**都固定關掉回退**(為了防回退污染排序的尺),
所以新題塞進去兩臂都是 0 候選,**量不到任何改善,還會讓既有閘的分母出現 0 而失義**。
多詞那案就是為了這個才另開一支腳本與題庫,理由寫在那支腳本自己的說明裡。

本案照做:**另開一支「無空白回退」的評測腳本與題庫**,顯式比較「關掉回退」與「開啟回退」兩臂。
題目要涵蓋實測出來的三類:①全字對零覆蓋 ②只有一個常見字對命中 ③多個連續字對命中。
題目由另一個家族出,既有的兩套題庫完全不動。

### [S3] 召回層:要新建一支有明確合約的候選收集原語

**不能說「同一支直接用」**。★r2 兩席都建議走 (乙),我裁定就走 (乙)★:

- **(乙,採用) 只在搜尋函式現有的預檢與主迴圈裡擴充那份詞清單。**
  現有主迴圈已經把路徑篩選、可見文字判定、命中行標記、排除已作廢節點、隱藏筆數、
  三種輸出次序全部綁在一起;(乙) 只更換「回退時用哪一組詞」,這些行為自然保留。
- **(甲,不採用) 抽一支獨立的候選收集原語。** 它要重構一整段**有歷史事故的控制流**:
  這支檔案裡就記著兩次真事故,都是因為「同一個問題出現第二份獨立實作」
  (預檢自己剝一份而跟主迴圈分岔,造成幽靈連結邊、以及逐詞覆蓋虛報非零)。
  ★如果將來真的要走 (甲),它的合約必須明寫「一定要呼叫既有那兩支判定,不准重新實作」★
  ——只列「要處理哪些情況」是不夠的,照著清單重寫一份 regex 一樣能滿足每一條、
  然後把那兩個已經付過學費的 bug 再生一次。

★不管哪一條,候選收集端都要比照鄰居那三道濾網★(丟純數字、丟單字、丟可拆分的詞),
否則會重演「不先濾就全庫召回」。
★而且「產生字對」這件事要抽成一支小的純函式★,給預檢、主迴圈、提示、測試共用——
不要讓那三道濾網被複製四份(這正是 (甲) 想避開的病,(乙) 也躲不掉,只是規模小)。

### [S4] 「查無」訊號的還法:不猜詞界、不設分數門檻

前一版給的兩個候選**實測都不可行**:
- (甲 已刪除) 要判斷「不跨詞邊界」,而切詞器根本不產生詞界資訊;另加斷詞器違反零依賴家規。
- (乙 已刪除) 要一個分數門檻,而打分是以**每次的候選集**當語料算的,
  絕對分數不可跨查詢比較(21 個候選的 2.02 跟 1 個候選的 0.31 用的不是同一個語料)。
  **鄰居那案已經因為同一個理由刪掉過分數門檻**,現在明定「分數只管排序,不管資格」。

★採第三條(外家席提的,我判它對)★——保留兩層訊號,不猜詞界也不設門檻:
1. **永遠明示原整串命中數是 0**:「整串沒找到,以下是弱回退的結果」。
2. **每個字對輸出覆蓋數**,沿用既有的逐詞覆蓋與零命中標記(不新造)。
3. **每筆結果顯示「命中幾個字對 / 總共幾個字對」**——這是**查詢內可比**的比率,
   不像分數要跨查詢比。可以拿來排序或分級。
4. **機讀輸出同時回三個欄位**:原整串命中數、有沒有用到回退、每個字對的覆蓋。
   機器端不必去解析提示文字。

★誠實記兩個已知的彆扭★:
1. 零命中標記會落在跨詞邊界的無意義字對上(「銀行貸款利率」切出來的「行貸」「款利」
   本來就不該有命中),所以那些星號看起來像「這個概念圖譜沒有」,其實只是切割產生的雜訊。
2. ★比率本身也分不乾淨★(r2 通才席實測,前一版漏掉):
   查一個圖譜真的沒有的詞「房屋貸款利率」,回 1 筆、比率 0.60(五個字對命中三個)——
   **命中的原因是這份設計文件自己在討論一個不相干的例子「銀行貸款利率」**。
   看到「3/5 命中」的人會合理地以為這個概念存在。
   這跟第 1 點是不同的失敗:第 1 點是無意義的碎片,這一點是**一份語意完整但不相干的文件
   產生了中高的比率**。
   ★所以訊息在「候選很少、比率中等」這個區間不准把比率講得可信★——
   要另外講「只有一兩筆命中,而且是靠字面重疊,不一定相關」。

### [S5] 旗標:不共用既有那支

★不准讓新回退共用 `--no-any`★:那支旗標的語意有硬合約明文釘住只管「多詞查詢」,
共用等於在沒走合約更新流程的情況下改寫合約範圍。而且使用者可能想「單獨關字對回退、
保留多詞回退」。**新開一支獨立旗標**,預設**關**(照 [S1] 的順序,量測完才裁預設)。

### [S6] 字元域要對齊,順手修一個既有的洞

現在那句提示把漢字、假名、諺文都算 CJK;而切詞器只接受漢字基本區與擴展 A。
直接共用觸發條件的話,日文或韓文查詢會進回退,切詞器卻可能切出空的。

★但「統一成一支漢字判定」會靜默拿掉日韓查詢現在有的那句提示★
(r2 通才席與外家席都判 blocking,而且實測純平假名查詢今天確實會收到提示)。
**要把兩件事分開裁,不能一起收掉**:
- **(a) 要不要跑新的字對回退** → **只有漢字**。假名與諺文在切詞器裡根本產不出字對。
- **(b) 要不要印「加空白」那句建議** → **保留給日韓**。那是跟文字系統無關的操作建議,
  對日韓查詢一樣有用;現在拿掉等於行為退步。★只是訊息裡不要再說「一串沒有空白的中文」★,
  改成不指定語種的說法。
- **(c) 日文漢字假名混寫** → 只有「連續漢字段能產生足夠多個有效字對」才啟動回退,
  否則只印 (b) 的建議。門檻多少要在 [S2] 的對照組裡定,不要拍腦袋。
正反例都要有測試(純假名、純諺文、日文混寫、純漢字)。

★順手修的既有洞★:現在那句提示判「有沒有空白」只認半形空白,不認全形。
實測用全形空白分詞的查詢會同時收到兩行互相矛盾的訊息——先說「已經照規矩分詞查過」,
再說「你查的是一串沒有空白的中文,請加空白」。這個洞不是本案造成的,但既然要動同一個判準,順手修掉。

### [S7] 訊息照三段式,不用行話

既有定案的格式是「發生什麼 → 為什麼該在意 → 指令獨立一行」,同一批也明訂「代號砍」。
「字對召回」對使用者是沒解釋過的行話,不要用。
新訊息要講:整串沒找到(發生什麼)、以下是放寬條件找到的、可能不準(為什麼在意)、
怎麼關掉 / 怎麼查得更準(指令獨立一行)。

### [S8] 翻案只翻該翻的那一部分

★我把那條決定的①認錯了★(r2 通才席抓到,查證屬實)。它真正的三個部分是:
①**注入範本的對照表加一列** ②搜尋在「≥4 個中日韓字、沒空白、0 命中」時提示改寫 ③索引子檔與說明書頭版同步。
我原本把①寫成「加空白的紀律」——那是這條決定的**主旨**,不是它的第①項。

**所以①不是「不用動」,它要跟著改**:那一列的原文寫著
「整串當片語比對,黏成一串幾乎必定 0 筆」——★②一旦演進成有弱回退,這句話就變成錯的★
(不再是「幾乎必定 0 筆」,而是會拿到打過分的部分結果)。
而**那份範本會透過更新機制散到每一個下游專案的 CLAUDE.md**,
放著不動等於把一句自相矛盾的指引推給所有專案。

**裁定**:①要改那一列的措辭(從「幾乎必定 0 筆」改成「整串比對找不到就退成弱召回,
但加空白仍然比較準」),②從「只提示」演進成「保留加空白建議 + 明示整串 0 命中 + 提供弱回退」,
③照舊同步。★用指令對到那個決策編號新增一條補充決定,不整條標翻案★。
改範本這件事要算進本案的工量,不是「順手」。

## 實作紀錄(2026-09-07,S1 的第一步:藏在旗標後)

**做了什麼**:`--cjk-loose`,預設關。開起來時,一串沒有空白的中文查不到,就把
**連續漢字段**切成相鄰兩字一組去召回。

- **照 [S3](乙) 做**:不新開候選收集器,只換掉「回退時用哪一組詞」——
  既有預檢與主迴圈的路徑篩選、可見文字判定、命中行標記、排除作廢節點、隱藏筆數、
  三種輸出次序因此全部自動保留。
- **切字對抽成一支純函式**(`_cjk_bigrams`),預檢、主迴圈、提示、測試共用。
- **[S4] 三層訊號都在**:明示整串是 0、每一組各自命中幾篇(沿用既有的 ★ 零命中標記)、
  每筆結果「幾組裡命中幾組」;機讀輸出直接給三個欄位,機器端不必解析提示文字。
- **[S5] 獨立旗標**,`--no-any` 關不掉它(有測試釘)。
- **[S6] 兩件事分開裁**:跑不跑回退只認漢字;印不印「加空白」建議照舊涵蓋日韓,
  只是訊息不再說「中文」。順手修掉全形空白那個洞。
- **[S7] 訊息三段式、不用行話**:對使用者講「相鄰兩字一組」「幾組裡命中幾組」,
  不講「字對」「bigram」「召回」。

**觸發下限用一個暫用值**:只有長度 ≥4 的連續漢字段才拿來切(4 個字 = 3 組,
跟既有那句提示的觸發條件同一個數,不是另外拍的)。**這個數還沒有實測依據**——
[S2] 明寫門檻要在對照組裡定,而對照組要等這支能跑才組得出候選池。預設關,所以拍錯不影響任何人。
這一條同時當「短漢字段不觸發」的濾網用,不另立第二個判準(兩個判準各寫一份,
就是這支檔案付過兩次學費的那個形狀)。

### ★訂正:「預設關 = 行為一行不變」是我寫太大的宣稱★

代碼審 r1 外家否決席判 major,查證屬實。同一批**還改了那句「加空白」提示**,而它在預設路徑上:

- 措辭改了(不再說「中文」,因為對日韓查詢是錯的)
- 全形空白分詞且 0 命中時**不再印**(那是刻意修掉的矛盾訊息)

所以「沒有任何呼叫端的行為改變」是假的。用固定語料實測(三篇假筆記、五種查詢),
**輸出唯一的差異就是提示措辭那兩行,結果行一字不差**。精確版本是:

> ★候選集與結果不變,變的只有那句提示——而且是刻意變的。★

★這是同一個病的第 N 次★:**用一個維度描述範圍,另一個維度就不在視野裡**
(見 [[Issues/把自己的推論寫成repo明文寫過]])。這支檔案的註解裡已經記著同型三次,

### 通才席另外三條(它自己跑了實驗,不是讀碼推論)

- **長查詢沒有上限,會慢到像掛住**(major)。成本是 O(字對數 × 篇數 × 篇幅)。
  它量到 3000 字要 47.9 秒;我自己在本庫 441 篇上量:10 字 0.55s / 50 字 1.18s /

  ——純粹是演算法複雜度。修法:超過 50 組就不跑,並且講清楚「是太長不是查不到」。
  **不做無聲截斷**——那會讓人以為查完了。50 這個數是照那條曲線挑的(約 1.2 秒)。
- **夾一個看不見的零寬字元,兩條路同時無聲失效**(minor)。`split()` 不把 U+200B 當空白

- **同一個建議印兩次**(minor)。字對回退觸發但每組覆蓋都 0 時結果是 0 筆,
