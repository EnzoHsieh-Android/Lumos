## 範圍

- **做**:`[count:路徑::名稱=N]` 的解析與求值;`drift scan`(文字與 `--json`、工作目錄與 `--at`)列出對不上的(新種類 `count`)與判不了的;`doctor` 存量漂移段(Z)列標籤總數與寫錯的;`drift ack --kind count` 照留;`drift fix --kind count` 改成現值。
- **不做**:推送擋(依賴欄位那份的〈待解問題〉大多是推送擋才有的,留給那邊);`[value:]`、`[lives:]`;非 Python 檔;寫新句子時提醒加標籤(C2,另案)。

## 做法

1. **寫法與位置**:`[count:路徑::名稱=N]`,N 是非負整數。路徑必帶(不帶就列成「寫錯了」);`路徑::名稱` 從最後一個 `::` 切(同 `_drift_cond_split` 的 symbol 切法),`=` 從最後一個切。只認筆記的可見行(正文與摘要;圍欄、行內程式碼不算,同 `_probe_lines` 的判定),表格行照算(數量句常寫在表格裡,而且這個寫法沒有 `|`)。已標 `[status:superseded]` 的摘要行不算。
2. **求值**(只認 Python:`.py`,或沒副檔名、首行是 python 的 `#!`,同 `_drift_probe_is_py`):用 `ast` 讀那支檔的**模組最上層**:
   - 名稱是模組最上層恰好一次的指派(`X = …` 或 `X: T = …`),值是:元組/清單 → 元素數;集合 → 元素都是字面常數時去重後的數;字典 → 鍵都是字面常數時去重後的數;`frozenset(…)`/`set(…)`/`tuple(…)`/`list(…)` 包一個上面那種字面值 → 同上(集合類去重)。
   - 名稱是模組最上層的類別,基底是 `Enum`/`IntEnum`/`StrEnum`/`Flag`/`IntFlag`(名稱或 `x.Enum` 這種屬性):成員=類別本體裡單一名稱的指派、名稱不是底線開頭;值都是字面常數或 `auto()`;字面常數有重複(別名)→ 判不了。
   - 其他一律判不了,講原因:不是 Python、檔不在、名稱找不到、指派不只一次、值不是字面值集合、含展開(`*x`、`**x`)、集合或字典有非常數成員、列舉有別名或非常數值、檔案解不開;代碼審 r1 補:列舉有底線開頭的名稱或 `_ignore_`(是不是成員看 Python 特例,不模擬)、Flag 的值不是單一位元(組合值是別名)、整支檔裡有增量指派、會改內容的方法呼叫或下標賦值改過那個名稱(數的是定義當下)、標籤數字超過九位;r2 補:列舉本體有看不懂的語句(多重指派、拆包、區塊裡的成員)、auto() 與明寫的值混用,名稱在模組這一層被重新綁定(指派、拆包、刪除、for/with/海象)、被 global 或 import 蓋掉、呼叫只讀以外的方法——原則是「看不懂就判不了,不略過、不模擬」。r3 補:名稱重新綁定改成反過來列「哪些出現方式不算綁定」(讀取、屬性名、關鍵字參數名、字串常數、import 的模組路徑),其餘每次出現都算綁定,超過定義那一次就判不了。
   - 「找不到名稱」也算判不了而不是對不上:名稱改了該由人看(訊息講「找不到,名稱可能改了」)。
3. **drift scan**:新種類 `count`(名稱「數量對不上」),排在撤除條件之後、同一棵樹、同一個總預算;讀檔用 `_DriftProbeTree` 既有的批次讀(先收齊全部路徑一次讀)。對不上 → 發現 `{"kind":"count", …, "why":"寫 N、現在是 M", "count": {"claimed": N, "actual": M}}`;判不了 → 問題清單一行(同回頭條件的「判不了」那一路)。已表態的照 scan 慣例列在已表態。
4. **doctor**:存量漂移段(Z)照回頭條件的先例,**不評估、只讀筆記**:多列一句「數量標記 N 處(由 lumos drift scan 評估);寫錯的 M 處」。不在 doctor 數:Z 段的既有規矩是不評估條件、不讀程式檔(回頭條件也是交給 scan),多一條評估路徑就是第二種做法;rtb 原提案要 doctor 也報數字對不上,這裡只做到「提醒去跑 scan」(見〈天花板〉5)。
5. **drift ack --kind count**:沿用既有表態(同一路徑、一字不差的原文、同一種類);數字改了原文就變,舊表態自然失效。
6. **drift fix --kind count**:重算那一行;還對不上才改。改兩處:標籤整個重寫成 `[count:路徑::名稱=M]`(原本寫 `= N`、`=0N` 也改得到);句子裡(方括號欄位與行內程式碼以外)**恰好一個**前後不是英數字或底線的阿拉伯數字 N 也改成 M(`F3` 這種識別碼裡的數字、`2026-10-04` 這種日期與 `1/2`、`10:30` 裡的數字不算;行內程式碼的判定跟抽標籤同一支 `_inline_mask`,雙反引號與未閉合反引號之後都看不見;標籤裡夾行內程式碼就擋下);行內程式碼裡的範例標籤不動;寫之前先重抽改好的那一行,標籤真的是 M 才寫。句子裡找不到 N、或不只一個 → 擋下,請人自己改(中文數字、「十來個」這類不猜)。判不了 → 擋下講原因。其餘照 `drift fix` 既有流程:預覽、乾淨檢查、寫入、重驗、記修復帳。

## 實務隱患

- **效能**:每個標籤指到的檔讀一次、解析一次(同一支檔多個標籤共用);受 scan 總預算管。doctor 只讀筆記,不讀程式檔。
- **記憶體**:只留被指到的 Python 檔與它的語法樹;rtb 規模(20 多處標籤、十來支檔)可忽略。
- **相容**:`--json` 多一種發現;`drift ack`/`drift fix` 的 `--kind` 多一個值;既有種類不變。
- **跨環境**:語法樹用執行 lumos 的 Python 解析;被數的檔用了更新版本的語法就判不了(訊息講解不開),不猜。
- **回滾**:還原本案提交;表態檔與修復帳裡 kind=count 的列會被讀側略過(讀側只收認得的種類)。

## 驗收條款

- [S1] 當 `[count:a.py::X=N]` 指到的是元組、清單、集合、字典、`frozenset(…)` 字面值或列舉類別,`drift scan --json` 應 在數字對不上時列一筆 kind=count、帶 claimed 與 actual,數字吻合時 應 不列;工作目錄與 `--at` 應 都判得出 [test:t_count_tag_scan]
- [S2] 當名稱找不到、指派不只一次、值不是字面值集合、含展開、非常數成員、列舉別名、不是 Python、檔不在、檔案解不開、沒帶路徑,`drift scan` 應 列成判不了並講原因、應 不列成對不上 [test:t_count_tag_unknown]
- [S3] `drift scan` 應 不評估圍欄與行內程式碼裡的標籤、應 照評估表格行裡的標籤、應 不評估已標 `[status:superseded]` 的摘要行 [test:t_count_tag_places]
- [S4] doctor 的存量漂移段 應 列出數量標記總數與寫錯的處數,應 不評估數字、不影響 doctor 的結束碼 [test:t_count_tag_doctor]
- [S5] `drift fix --kind count` 應 把標籤與句子裡恰好一個的舊數字一起改成現值並記修復帳;句子裡的舊數字找不到或不只一個 應 擋下不寫;已吻合 應 回報不用改;`drift ack --kind count` 應 讓那一筆列在已表態 [test:t_count_tag_fix]

## 天花板

1. 只數 Python 模組最上層的字面值集合與列舉;程式組出來的集合(集合相減、迴圈組出來的)判不了——rtb 試標時最常過期的正是這類,要靠 doctor N 的正規式數量。
2. 列舉成員互換而總數不變抓不到。
3. 句子裡的數字用中文寫(「四種」)時 fix 不改,要人改。
4. 不擋推送:對不上只在有人跑 scan 時看見。
5. doctor 只提醒有幾處標籤、不數數字(Z 段不評估的既有規矩);要看哪幾處對不上得跑 `lumos drift scan`。
