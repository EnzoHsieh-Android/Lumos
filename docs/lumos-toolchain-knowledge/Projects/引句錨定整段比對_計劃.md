# 引句錨定整段比對_計劃

> 白話:審查席每條發現要附一段原文引句,工具檢查那段字真的在被審材料裡——這是收貨時唯一擋「編造證據」的一道。現在的抽取只取到第一個閉引號,後面寫什麼都不看:前半照抄、後半接一個閉引號再編,照樣判「全數錨定」(Issue 2026-09-06 實測)。這篇改成照括號配對切出整段引句,引號裡面那段整段都要對得上(引號外的文字不算引句,工具不驗);引號沒閉合、或引句結束後到下一條引句之前還有落單的收尾引號,判格式不合。哪一版判準由記帳當下蓋在帳上的章決定,處置閘與回放照章重算;寫側用哪一版由程式常數決定。分兩階段上線:先讓所有讀帳的地方認得章(寫側仍用舊判準),再用一個提交把寫側切到新判準、同時改文件。來源是世界解總覽〈跨類優先順序〉第 6 名(總覽寫「行區間+整段」,本篇只做整段,理由見〈量測〉),也是立案清單第 18 項。

PRIOR-ART: 括號配對(深度計數)是解析巢狀分隔符的標準做法,不另發明判準。「判準版本蓋在資料列上、讀的時候照那一列的版本選判準」在本 repo 是新機制:既有的版本欄位(回放凍結閉包的 `engine_rev`)語意是「版本對不上就視為過期、跳過重算」,不是在兩套活著的判準之間分派;本篇不沿用它,理由見〈判準版本蓋在帳上〉最後一點。外部對照是資料庫的「先擴後縮」遷移(expand/contract:先上線認得新格式的讀者,再上線寫新格式的寫者)與序列化格式的 schema version 欄位。兩個時間切換先例(`_SEV_WRITESIDE_CUTOFF` 純日期字串比對、`_SECURITY_SEAT_SINCE` 帶時區走 `_loop_ts_key`)不採用:它們留下「合入當天舊碼寫帳」與時區兩個坑,蓋章做法兩個坑都沒有。「版本蓋在帳列」本身有先例:`_DOOR_RULE_VERSION` 蓋在 spec-gate 帳列的 `door_rule`、`small_change_rule` 欄,但只記錄、不分派判準;本篇差在讀的時候照章選判準。寫側判準不放設定檔,用程式常數 `_QUOTE_WRITE_RULE`(同 `_REPLAY_ENGINE_REV` 由提交改):設定檔任何一處寫壞都會讓寫側悄悄退版、而且帳只進不出(r4 正確性、邊界、簡化三席),常數要改就得過推送閘與代碼審、git 有痕。
RETIRE-IF: 第二階段合入後 8 週內,寫側記下的引句擋下事件裡 `kind=new-only`(只有新判準擋、舊判準會放)的那些,人工逐條看後誤傷(原文引句正當卻判不合)多於抓到的真截斷或夾帶,就還原第二階段的提交(寫側常數回 `legacy`,文件一起退)並重新設計;或之後改成結構化引句(席位交回 JSON、引句欄位單獨一格),文字抽取不再需要,這套規則整個拿掉。

## 範圍

- 只改「從報告抽出引句並判格式」這一步;比對前的正規化 `_quote_norm`、10 字下限、比對方式(子字串、空白全剝再比一次)都不變。
- `_quote_rows` 是唯一抽取實作(函式說明寫明單一實作),新舊兩版判準都留在它裡面,用必填的 `rule` 參數選(`"legacy"` 或 `"full-span-v1"`),不給預設值——四個呼叫點(記帳寫側、處置閘、手動 `quote-check`、席位核對 `seat-check`)各自明確傳。`legacy` 分支照現行程式原樣保留,一字不改。
- 不改席位交回報告的形狀(仍是文字);結構化引句另案。

## 做法

### 抽取規則(新判準 `full-span-v1`)

「標籤」在本節一律指:「引句」加可選的全形括號註記、可選的粗體星號、全形或半形冒號、任意空白(含換行),後面緊接開引號 `「` 或 `『`——與現行標籤規則相同。後面不是開引號的「引句:」不是標籤,照舊不理,也不當任何邊界。

依序做(每一步都整份報告只掃一次,總成本與報告長度成正比):
1. 預先配對(只用來找每個開引號的閉引號):從頭到尾掃一次,兩型引號各自用一個堆疊,遇開引號推入位置、遇同型閉引號且堆疊不空就配對彈出,堆疊空時的閉引號不配對。得到每個開引號對應的閉引號(或沒有)。
2. 找出所有標籤位置。依位置由前往後處理:標籤的開引號有配對 → 開引號到配對閉引號之間是整段引句(可巢狀、可跨行);範圍內的其他標籤當成引句內容,不另成一條結果。沒有配對 → 這條判格式不合,`kind="unclosed"`,`quote` 欄取開引號之後到那一行結尾、最多 200 字(先限長度再切,不複製到報告結尾),接著處理下一個標籤。
3. 一條忘了閉合的引句被後面多出來的同型閉引號補閉合時,照第 1 步的配對,整段變成一條很長的引句——它幾乎必定錨不到,判 `ok=False`(錨不到),仍擋下;被包進去的標籤不另成一條。
4. 尾段落單(**每條引句自己數,不看第 1 步的全域堆疊**):尾段是引句結束後到下一條獨立引句的標籤開頭(或報告結尾)為止的文字。在尾段裡從頭掃,兩型各一個計數器,遇開引號加一、遇同型閉引號時計數器大於零就減一、等於零就是落單收尾引號;尾段有任何落單收尾引號,這條判格式不合,`kind="stray"`。各條的尾段互不重疊,總成本仍與報告長度成正比。不用全域堆疊的理由:報告前文只要有一個沒閉合的開引號(散文或型態錯配),全域堆疊會把後面編造段落的收尾引號配走,落單偵測整份失效(r4 正確性、邊界兩席實測;帳上 3034 份有引句的報告有 22 份留有到結尾都沒配對的開引號)。前綴照抄後接閉引號再編造、換行後再補收尾引號、用另一型收尾引號、中間插一個後面不是開引號的「引句:」字樣、前文有沒閉合的開引號,五種都會中。
5. 照舊:正規化後整段要是凍結快照正規化後的子字串;正規化後未滿 10 字判錨不到。
6. 每條結果帶 `ok` 與 `quote`;格式不合的另帶 `malformed: True` 與 `kind`(沿用現行 `malformed` 鍵,`seat-check` 照舊跳過這種列),而且只有格式不合的列 `quote` 欄截到 200 字並加「…(截斷)」——錨定與錨不到的列保留全文,`seat-check` 拿全文比材料範圍。

工具保證的範圍(寫進範本與 Issue,不宣稱更多):引號「裡面」那段是真的。引句結束後、沒有落單收尾引號的文字(例如引句後接註記或散文,或 `引句:「真前綴」「編造後半」` 這種第二對沒有標籤的引號)不算引句內容,工具不驗也不擋——這跟正當的「引句後接註記」在文字上分不開,只能靠讀的人看清楚引號在哪裡結束。舊判準對這類一樣放行,不是新退步。

### 判準版本蓋在帳上

- 寫側判準:程式常數 `_QUOTE_WRITE_RULE`(與 `_quote_rows` 放同一區),第一階段值 `"legacy"`,第二階段改成 `"full-span-v1"`。不放設定檔(理由見 PRIOR-ART)。
- `_quote_rows(text, snap, *, rule)`:`rule` 是只收關鍵字的必填參數,值 `"legacy"` 或 `"full-span-v1"`,其他值丟 `ValueError`。四個呼叫點(記帳寫側、處置閘、手動 `quote-check`、席位核對 `seat-check`)各自明確傳。
- 寫側(`cmd_canary` 驗載體引句那段):用 `_QUOTE_WRITE_RULE` 檢查,通過時寫入的那一列帶 `quote_rule=<_QUOTE_WRITE_RULE>`,章跟帳在同一行一次寫入;被擋時不寫帳。主檢查本身丟例外時照現行政策處理(原例外往外傳、rc1,`t_canary_carrier_invalid_snapshot_encoding` 釘住),不吞。
- 讀章(處置閘專用一支小函式,與 `_quote_rows` 同區;回放經由處置閘,不另設呼叫點):該列有 `quote_rule` 鍵、值是 `legacy` 或 `full-span-v1` → 用那一版;沒有這個鍵 → `legacy`;有這個鍵但值是別的 → 判失敗、不 traceback,訊息一律「引句判準欄不認得:<repr(值)>,可能是新版程式寫的或帳被手改」。
- 處置閘引句那一步:第一行印「引句判準:<版本>」(沒章時印「引句判準:legacy(帳上無章)」)。呼叫 `_quote_rows` 時除了現有的 `OSError`、`UnicodeDecodeError`,其他例外也接住:這一步判失敗,印「引句判準 <版本> 丟例外:<型別>:<訊息前 120 字>」,不 traceback——回放對同一迴圈因此算出「判失敗」,跟凍結時的「過」不同,週跑報邏輯漂移(紅燈),不會落進一般錯誤。判失敗時(錨不到、零引句、讀檔失敗、判準丟例外)另印一行新增的診斷指令 `lumos quote-check <報告> --spec <快照> --rule <版本>`(現行沒有這一行;路徑照處置閘的 `--repo` 解成實際路徑(r3 回滾席:不然要在 repo 根才照抄得動),每個參數交給同檔的 `_drift_sh(node=True)`(要引號才加、開頭是 `-` 補 `./`;r3 架構對齊席:不另寫一套);路徑含 `_PATH_SPECIAL_CATS` 那幾類字元或超過 1000 字時改印一句說明、不印可照貼的指令(消毒或截斷會讓照抄的指令指到別的檔,同 `_drift_fix_hint` 的做法;r4 正確性、邊界席);章不認得的列不印)。這一行與「引句判準:」那行都帶處置閘各行共用的 `[disposal] ` 前綴(r3 規格符合席)。錨不到那行另標「(其中 N 條格式不合)」。記憶體不足(`MemoryError`)不當成判準丟例外,照常往外丟(代碼審 r1 資源席:否則暫時性資源不足會被凍成判失敗);寫側求 `kind` 那一次同一規則(r2 架構對齊席),代價是 `loop next` 代問處置閘時遇到記憶體不足會整支 traceback、結束碼非 0,不會誤放行(r2 資源席)。
- **判準一經蓋章就不改它的判定**:之後要調整新判準的判定結果(放寬、收緊、修誤判),一律新增一個版本值(例如 `full-span-v2`)與對應分支,舊版本分支照原樣留著;只修「丟例外、不改任何判定」的錯不算改判定。機械守法:`t_quote_full_span_v1_pinned` 用一組固定輸入釘住 `full-span-v1` 每條結果的 `ok`、`malformed`、`kind`,測試說明寫明「這支紅了代表改了已蓋章判準的判定,該開新版本值,不是改測試」。這是回放能重現已凍結判定的前提,也是不推進回放引擎版本的代價。
- 手動 `lumos quote-check <報告> --spec <快照> [--rule legacy|full-span-v1]`(`--rule` 用 argparse 的 choices,值不認得走 argparse 的 rc2):預設用 `_QUOTE_WRITE_RULE`;人讀輸出第一行印「引句判準:<版本>」,格式不合的列標「(格式不合:<kind>)」;`--json` 物件多一個 `rule` 欄。
- `seat-check` 用 `_QUOTE_WRITE_RULE`;現有注入測試把 `cmd_seat_check` 放進只有少數全域名的環境跑,同步把那個測試的替身改成收 `rule=` 關鍵字,並把 `_QUOTE_WRITE_RULE` 放進那個環境。
- 回放:凍結閉包裡的帳是整行原樣(含 `quote_rule`),重算照章判;已凍結的 305 個迴圈都沒有這一欄,照 `legacy` 重算,跟凍結當時相同。不推進 `_REPLAY_ENGINE_REV`——推了會讓全部黃金抽查變成「制度已演進、跳過重算」,丟掉回放保護。

### 量測與留痕

- 兩版判準的交叉比較不做成指令(使用者 2026-10-13 裁):原本的 `quote-check --compare-rules` 只為第一條 REVISIT 的一次性決定服務,代碼審 r1–r4 四輪的 major 多半落在它(讀帳上不可信路徑、印到終端、大小上限、記憶體),設計審 r4 簡化席當初就建議不做成永久指令;第一條 REVISIT 改用一次性腳本(放會談暫存區、不進 repo:讀 `docs/.canary-log.jsonl`,每組(報告, 快照)用 `_quote_rows(..., rule="legacy")` 與 `rule="full-span-v1"` 各跑一次;報告超過 256 KB 先略過,舊判準對大量未閉合標籤是二次方成本),輸出照〈量測〉的五格加略過計數,結果寫回〈量測〉。手動 `quote-check` 回到只有單一報告模式,缺報告或缺 `--spec` 手動擋下 rc2。
- 寫側擋下載體時(不論哪一版判準擋的,含零引句),用 `_gate_event_or_warn(..., "canary", "blocked", note, hard=True)` 記一筆,note 形狀照同檔既有擋下事件:`quote-rule:<_QUOTE_WRITE_RULE> kind=<new-only|both|legacy-only|unknown> cats=<unclosed,stray,miss,short,none 的集合;舊判準的格式不合列沒有 kind,記成 unclosed> report=<報告路徑> report_sha=<前 12 碼> loop=<編號> auditor=<席> id=<隨機碼> quote=<第一條不過的引句取前 60 字、空格與 Tab 壓成一格、再過同檔既有的無損跳脫 `_kill_esc`(共用 `_PATH_SPECIAL_CATS`:控制、格式含標籤字元與方向標記與零寬、行段分隔、孤立代理字元換成看得見的 `\uXXXX`),空白記 `-`>`。片段是審查席可控的文字,所以重用既有的跳脫(r4 架構對齊席:不另寫第三套過濾;改成看得見的跳脫,不刪也不換空格,資訊不丟、也沒有看不見的字元進帳)、而且排在最後;私用區(Co)、未指派碼位(Cn)與外觀空白的字母(例如韓文填充字 U+3164)不在共用類別裡,原樣留著——它們不會操控終端、也不會切斷欄位,片段排在最後,在單人威脅模型下接受(r4 資安、邊界席):讀者照「第一個 `report=`」取值時不會被片段裡偽造的欄位騙到(代碼審 r1 資安席)。`kind` 由寫側另用另一版判準算一次得出(擋下那一刻是唯一確定讀得到報告原文的時候,事後報告常被退回重寫覆蓋,r4 接手的人席),這一次計算整段包例外保護,出錯就記 `kind=unknown cats=err`,擋下照舊。`quote=` 片段讓 REVISIT 在報告已不在時仍能判真抓或誤傷。
- `lumos gov --stats` 的「記帳被寫側擋下」改成四格互斥:先判 note 是否以 `quote-rule:` 開頭 → 引句判準;其餘照現行的包含判斷分 `report-not-normalized` → 報告沒正規化、`findings-over-reported` → findings 多於 reported、其餘 → 缺 refuted-set(這一格現行就混有跑滿回顧沒寫的擋下事件(`scripts/lumos` 記 cap-retro 那段),本篇不改它的語意);輸出逐字 `記帳被寫側擋下 N 次(報告沒正規化 a / 缺 refuted-set b / findings 多於 reported c / 引句判準 d)`,四格相加等於 N。
