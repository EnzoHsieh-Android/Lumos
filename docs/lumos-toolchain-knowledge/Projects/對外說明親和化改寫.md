# 對外說明親和化改寫

> 白話:把 README 從「一份文件講完所有事」改成「一份入口文 + 三份深度文」,並且第一次給它真的畫面。原因是它本來對沒脈絡的人不成立——不是寫得不好,是結構在同時服務五種讀者,而且從頭到尾沒有一張圖告訴你「這東西長什麼樣」。

## 動筆前診斷出的九條(照傷害排序)

1. **從頭到尾沒有「東西長什麼樣」的畫面**——唯一的圖是 logo;所有程式碼區塊都是「你要打什麼」,沒有一塊是「你會看到什麼」。抽象名詞沒有實體對照,就是讀得懂字、建不起概念。
2. **開場先要人同意一個立場才給場景**——第一句是命題(「AI 寫大部分 code 的時代,最貴的是還有沒有人懂」),不同意的人就走了。
3. **一份文件同時服務五種讀者**——說服路人 / 教安裝 / 講心智模型 / 當指令手冊 / 揭露成本,一條線走到底。這是 370 行讀不完的直接原因。
4. **裝完之後沒有「第一次成功」**——安裝那節結束在驗證裝好,直接跳心智模型,中間缺「現在做這三件事,你會看到 X」。
5. **術語一次上五個且多半自創**——圖譜、節點、合約鏈、可逆性鏈、誠實天花板、席、派工單、留痕、處置閘。
6. **中段那張 mermaid 大圖對新手是勸退的**——它是給懂的人看的地圖,不是入口。
7. **〈成本與界線〉的位置在自我拆台**——內容本身是最強的差異點,但讀者在「還沒決定要不要用」的狀態下讀到「每天燒 210–330 美元、收斂 0」,結論會是不要用。
8. **沒有一句話說「這適不適合你」**——讀者無法自我篩選。
9. **語氣偏密**——破折號、括號、巢狀補充多,長句多;開場的咒語比喻佔黃金位置卻沒傳遞資訊。

## 第二輪:頭圖推翻重做(2026-09-07)

第一版頭圖用 GIF 錄真實圖譜視圖。Enzo 三則更正把它整個換掉:

1. **「字也看不清」「關聯的線好像不太明顯」** — 根因同一個:GIF 是點陣圖,深色底佔 95%,縮到 820 寬之後標籤糊掉、關聯線被調色盤吃掉。而「彼此怎麼連」正是這張圖唯一該講的事。→ 改 SVG。
2. **「每個功能模組,都應該先長出計劃」** — 力導向散圖讓功能模組憑空出現,把最該表達的紀律藏掉了。→ 改成三層帶:①先寫計劃 ②才長出功能 ③留下紀錄。
3. **「綠色出現了,藍色才畫金圈＋星號」** — 合約不是宣稱就算,是綁到證據才算。→ 金環的出現時間綁在驗證節點之後(結帳流程 1.8s 出現、驗證 5.4s、金環 6.4s)。

順帶自己修的:事故的回饋線原本是直線,會穿過中間那層、看起來像連到功能模組 → 改成往左彎的弧線;第三層帶原名「做完留驗證」但事故也在那層(事故不是驗證)→ 改成「留下紀錄」。

**那張圖的產生器自己帶三條 assert**(`make_graph_svg.py`,留在 scratchpad,★範圍只到這一張圖★):
畫上去的合約節點要有驗證連過去、畫上去的功能模組要有計劃長出它、金環時間要晚於驗證時間。
★餵壞的進去實測會翻紅★——拿掉「結帳流程→結帳端對端」那條驗證線,產生器直接擋下並指名 `co`。

**這三條不是 repo 層的規則,也沒有進測試套件**;產生器不在 repo 裡,所以嚴格講現在沒人在守。這件事列進下面的回頭條件。

## 踩到的三個坑(給下一個做同類事的人)

**① `<img>` 載入的 SVG,CSS animation 不會跑,SMIL 會。**
第一版用 CSS `@keyframes`,直接開 SVG 檔看動得很好,包進 `<img>` 就凍住——三次截圖間隔 8 秒完全同一格。換成 SVG 自己的 `<animate>` 標籤後正常。**因為 README 的圖一律走 `<img>`,這條是硬約束。**
連帶的紀律:每個元素的靜態屬性要設成「動畫沒跑也是一張讀得懂的圖」——凍在第一格時四格不能全暗、說明句不能全部隱藏。

**② 深色底的 GIF 不能用預設調色盤。**
畫面 95% 是深色背景,`MEDIANCUT` 會把 256 個名額幾乎全給暗色階,節點的藍綠橘紫被壓成白點或全紫。手動排調色盤(背景只留 48 階、其餘分給節點色的明度階)+ Floyd–Steinberg 才救回來。**不 dither 檔案小很多但顏色會塌**,這是取捨不是 bug。

**③ 用本 repo 自己的圖譜當示範,陌生人看不懂。**
節點名全是治理機制的內部代號。**形狀對了、意義沒對上。** 所以另外造了一份虛構線上商店的示範圖譜(登入/購物車/結帳/付款/庫存/推播 + 驗證 + 事故 + 計劃,共 14 篇),`doctor` 0 issue,截圖用它。示範圖譜的產生器與卷證留在本次 session 的 scratchpad,不進 repo。
