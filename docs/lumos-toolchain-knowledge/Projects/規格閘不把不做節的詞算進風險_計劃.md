# 規格閘不把不做節的詞算進風險_計劃

> 白話:規格閘判「風險高還是低」時,會在計劃全文找金流、對外送出這類詞。計劃裡專門寫「這一版不做什麼」的那一節,寫的正是不碰的東西(例:「不做退款」),卻因為出現「退款」兩個字而被判成碰到金流。改成:只有標題就叫「不做」的那一節,裡面的字不算進關鍵字比對;其他判法一律不動。

## 緣起

- 2026-10-13 後端示範:計劃 `Projects/訂單下單_計劃`(示範 repo,只在本機)的「## 不做」節寫「不做退款(d2)」,規格閘的關鍵字表把「退款」算成金流訊號。那份計劃本來就因為其他訊號是風險高,結論沒錯,但這一筆訊號是錯的;同樣的寫法放在一份真正風險低的計劃裡,就會把它推去走完整設計審。出處:使用者 2026-10-14 問「這次示範有什麼 lumos 可以改進」時列的第 7 條。
- 使用者裁(2026-10-14):只排除「不做」那一節,精準、不放寬。
- [[Systems/規格閘]] 已承認「四類關鍵字表粗,常用詞會把計劃判成風險高,這是預設單向的代價」;本計劃只拿掉其中一種有結構可認的誤報,不改那條取捨。

PRIOR-ART: 規格閘自己已經用同一支 `_h2_section_lines` 認「## 回退」與「## 實務隱患」兩節(那支的說明寫明「找節邏輯不准長出第三套」);舊否決清單也已有「計劃裡的不做小節不收,多半是這一版的範圍刀」的先例。借這兩樣,不另寫找節邏輯。
RETIRE-IF: 有任何一次逃逸(放行之後在實作或之後抓到金流、對外送出、不可逆、守衛面的問題),逃逸帳的 `plan` 指到的計劃,最後一筆規格閘留痕是風險低且 `nogo_skipped_n` 大於 0——撤回,不做節照掃。
REVISIT:2026-12-15 對逃逸帳每一筆帶 `plan` 的,查那份計劃最後一筆規格閘留痕的 `door` 與 `nogo_skipped_n`,照 RETIRE-IF 判;同時數靠不做節放過(留痕風險低且 `nogo_skipped_n` 大於 0)的計劃有幾份,0 份代表這條規則沒省下任何設計審,一併考慮撤。
PRIOR-ART(外層看門,代碼審 r3):擋法借既有的 light 謂詞(`loop status --light`,抽成共用的 `_light_gate_fails`)與 `loop next --tier light` 的派工,不另寫一套判「審過沒」的邏輯;「同一類兩輪就換形狀、整類拿掉或外層看門」是本 repo 審查迴圈的既有做法。
RETIRE-IF:被要求輕量審的計劃累積 20 份,沒有一份審出夾帶(major 以上),而且這段期間沒有任何不做節相關的逃逸——把推送前的輕量審要求改成只提醒。
WHY:輕量審抓到 major 之後,推送前只認系統既有的兩條路——這個編號的 light 閘(`loop status --light` 的 ratchet)加綁定快照的被略過行相同,或原編號加 -std 的完整設計審過處置閘 [不選:內容比對 ratchet(看 major 看過的被略過行雜湊、跨編號建索引)] [因:r4–r7 連續被自填欄位繞過,ratchet 不該比整套審查系統更強] [出處:governance/review-reports/code-規格閘不做節/r7-intake.md] [代價:改檔名、換編號、自填輪次欄位這類手法這道檢查分不出來,跟處置閘與代碼審留痕同一個天花板(〈實務隱患〉)] [test:t_prepush_nogo_light_major_points_to_std] [test:t_prepush_nogo_std_review_exit]

## 做法

1. **新增一個標題規則**:`_NOGO_H2_RE`,寫法照 `_HAZARD_H2_RE`(允許標題前的編號、尾端括號註記),核心字只認「不做」兩個字。認得:`## 不做`、`## 一、不做`、`## 1. 不做`、`## 不做(這一版)`、`## 不做 (退款)`、尾端或中間有全形空白。不認得(照舊全文掃):`##不做`、`## **不做**`、`### 不做`、`## 不做的事`、`## 範圍外`、`## Non-goals`、`## Not doing`、`## 不做:`、`## 不做 ##`、括號沒收尾、`## 本版不做`——照使用者裁定,精準不放寬;要用就把標題改成 `## 不做`。標題行本身照掃(標題括號裡寫了危險詞,照樣算)。
2. **只跳過緊接在標題下面的那一段清單**:`_door_judge` 掃關鍵字時,除了現在跳過的合格已排除行,另外跳過「## 不做」標題下面**緊接著的那一段連續清單**,其餘一律照掃。不做節本來就是一張「不做什麼」的清單;散文、引用塊、表格、子標題之後的內容照掃。
   - **怎麼認那一段**:用一支新函式 `_nogo_skip_lines(text)`,在 `_visible_lines` 的可見行上(圍欄裡的行本來就不算),找到符合 `_NOGO_H2_RE` 的標題行(跟 `_h2_section_lines` 認標題同一個條件:行首是 `#`、去掉頭尾空白後符合正規式),從下一行開始往下看,每一行只有三種可以繼續:
     - 空行;
     - 清單項目:符合 `_NOGO_ITEM_RE` = `^ {0,3}(?:[-*+]|\d{1,9}[.)])[ \t]+\S`(標記後一定要有空白,所以 `**粗體**`、`-退款`、`3.14 版`、`2026.10` 都不是項目),而且不是分隔線(`---`、`***`、`___` 那種);
     - 續行:縮排至少到上一個項目的內容起點(標記之後第一個非空白字元的欄位),而且上一個非空行是項目或續行。
     遇到第一個不是這三種的行就停,之後全部照掃。所以任何標題(三級子標題、tab 標題、縮排標題、空的 `##`)、Setext 標題的文字行、散文段落、表格、引用塊,都會讓它停——不用另外認標題,也就不另寫一套標題邏輯。
   - **逐句判、每一句都要以否定片語開頭**(代碼審 r2 改形狀,取代 r1 的「整行含否定字樣」):清單裡每一行(項目、子項目、續行**各自判、不繼承**父項目)先剝掉行內標記與清單標記,再照標點(`,,;;。::`)與轉折詞(但、但是、而是、只、只有、另外、同時、並且、改成、改為、還要、也要、and、but、instead、also)切成子句;每個非空子句都要以否定片語(`_NOGO_NEG_PREFIX_RE`:不做、不支援、不提供、不處理、不含、不包含、不實作、不開發、暫不、本期不、本版不、這一版不、不在本期、排除、也不做、亦不、out of scope、not doing、won't、will not;片語只定義一次,句首與標頭兩支正則由它組出)開頭,這一行才跳過;任何一句不是,整行照掃,清單照舊往下判。代碼審 r3 起:判之前先剝粗體記號、把只有決策或條款編號的括號(`(d2)`)整段拿掉;括號不再切子句(「不做退款(含部分退款)」是補充說明),括號裡的轉折詞照切。例外只剩一個:一行以「否定片語+冒號」開頭(`out of scope: refunds`)時,冒號後第一句算在否定裡。**這一層只是降噪,不是防線**:它判錯的代價由第 6 點的輕量設計審兜住。代價:「本期不做」寫在句尾(「多商品購物車需求原文沒提,本期不做」)會照掃。否定片語、標頭、切點、編號四支正則都進門判定規則指紋。r1 的「整行出現不/無/not 就算」作廢:「不可逆」本身含「不」會替自己作保。
   - **空行後下一個非空行要是項目**(代碼審 r1):空行之後接的若不是清單項目(例如縮排夠深的散文),就停,不當續行。
   - **候選行由 `_h2_section_lines` 取、行號斷開就停**(代碼審 r1):`_nogo_skip_lines` 不自己逐行找節,改在 `_h2_section_lines(text, _NOGO_H2_RE)` 的結果上,只從緊接在標題下面的那一行開始取連續清單;被它略過的 `###` 標題、圍欄、第二個 `## 不做` 標題都會讓行號斷開,斷開就停。
   - **註解**:不數 `<!--`、`-->`(`_visible_lines` 刻意不處理註解,有兩條 blocker 紀錄,這裡不另寫一份)。改成:那一段裡任何一行含 `<!--` 或 `-->` 就停。標題落在註解裡、後面緊接著也在註解裡的清單被跳過,那段本來就是被註解掉的文字;註解在清單中間收尾、後面接真正的內容的形狀,會在含 `-->` 那一行停下。
   - **核取方塊**:`- [ ] 實作扣款` 也是清單項目,照規則會被跳過。在不做清單裡寫一條要做的事等於寫錯計劃,跟下面〈實務隱患〉那一型一樣處理,不另外排除。
   - **跟既有函式的關係**:`_h2_section_lines` 會把行首是 `#` 的行全部略過、只在 `## `/`# ` 結束節(r2 兩席實測),所以不拿它來取不做節,它的簽名與行為都不改;新函式只做「標題下面那一段連續清單」這一件事,不是第三套「找節」邏輯。
   - `_NOGO_ITEM_RE` 寫成具名常數,與 `_NOGO_H2_RE` 一起進門判定規則指紋;判斷邏輯本身改用版本號進指紋(代碼審 r1 架2:執行時取原始碼是專案第一次這樣做,退回位元組碼又會隨 Python 版本變):常數 `_NOGO_SKIP_LOGIC_VERSION` 進門判定規則指紋,執行時不取原始碼;`t_nogo_skip_logic_version_pin` 釘住 `_nogo_skip_lines` 與它依賴的全部函式(`_nogo_line_says_nogo`、`_ns_indent`、`_h2_section_lines`、`_visible_lines`、`_strip_inline_markup`、`_inline_hidden`)的原始碼、加上不做清單幾支正則的 pattern 的雜湊和版本號(代碼審 r2 正3),改了判斷邏輯卻沒升版號,那支測試會紅。
   - **程式碼圍欄裡的行也掃**(代碼審 r5 資3,門判定原本的盲區):危險內容放進 ``` 圍欄就判風險低、連輕量審都不用。關鍵字掃描(`_door_keyword_hits`)改用 `_visible_lines` 的 `keep_fenced`,其餘(條款、連結、已排除行、不做清單)照舊只認圍欄外的行;開關 `_DOOR_SCAN_FENCED` 進門判定規則指紋,版本升 4。寧可多判高:範例請改用「」引號或寫成已排除(2026-10-14 量 vault 裡 26 份判低的計劃,沒有一份因此翻高)。推送前重判照舊不讀版本號;舊版留痕在新規則下判高時,擋下訊息多一句「留痕用的是較舊的門判定規則」。連到的節點正文不掃,留在 [[Issues/門判定不掃計劃連到的節點正文]]。
   - **關鍵字掃描看每一行原文**(代碼審 r6 資2、邊1):成對反引號裡的字、行首或行中一個落單反引號之後的字(`_strip_inline_markup` 把未閉合反引號之後整段當看不見)、圍欄開頭那一行本身(`_visible_lines` 跳過標記行),之前都看不到,危險詞放進去就判風險低。`_door_keyword_hits` 改成逐行看原文、不經 `_strip_inline_markup`、不經 `_visible_lines`;原本的開關 `_DOOR_SCAN_FENCED` 拿掉,版本升 5。其餘(條款、連結、已排除行、不做清單逐句判)照舊用剝過的文字。實測見〈實務隱患〉。

     - **(b) 這個編號加 `-std`(或原編號自己帶輪次)的完整設計審過了處置閘**(`_nogo_full_review_gate`):設計審手冊的 light 升級規則(「light 輪只要冒出存活 ≥major → 開原編號加 -std 走完整迴圈」)。處置閘判定走唯一的 `_disposal_judge`(跟 `loop status <編號>-std --disposal --spec <這份計劃>` 同一支,不另寫判法):處置集合、留痕、引句、條款綁定、落點、跑滿回顧全照它;另看帳上每一筆帶審材路徑的紀錄,審的都是這份計劃(內容一模一樣的別的檔過得了 hash 鏈)。r8 起判法跟 (a) 對齊,見下面「(b) 出口跟 (a) 同一套判法」。
     - 兩條都不成立就擋,訊息講兩條出口;(a) 因為曾抓到 major 或帶輪次而失效的,直接指 (b),給 `lumos loop next <編號>-std --tier standard --orchestrator claude --spec <計劃>` 與處置閘的指令。做完全綠、沒有風險低留痕的計劃(r6 正1)的出口就是 (b),是既有的正規路徑。審查帳讀不到照擋(代碼審 r6 G2)。

   - **綁到這份計劃與被略過的那幾行**(代碼審 r4 改:r3 版傳那筆審查自己的 result 雜湊給 light 謂詞,比對變成自己比自己,審一個無關檔、借別份計劃的審都放行;審到一半計劃被改、重跑規格閘,舊版的審記在新留痕之後也放行):推送前只看最近一筆規格閘留痕**之後**的紀錄(窗口;沒有規格閘留痕就是整本帳;窗口只要求「最後一筆輕量審記在這筆留痕之後」與找架構對齊以外的一席,major 照上一點由 light 謂詞看這個編號全部的紀錄判),最後一筆要過 light 謂詞,而且帳上的審材路徑(`spec_path`)是這份計劃、凍結快照(`snapshot_path`,派工當下計劃的副本)讀得到且雜湊等於記帳時存的、`reviewed_sha256` 就是快照的雜湊、快照用同一支 `_nogo_skipped_rows`(以 `_nogo_skip_lines` 判)算出的被略過那幾行跟現在的一模一樣;窗口裡還要至少一席不是架構對齊、有席名、綁好又沒出事的審查席(只有架構對齊席等於沒人逐行看那幾行;代碼審 r5 起席名去掉所有空白、連字號、底線並轉小寫後含「架構對齊」或 arch 就算架構席——之前只看開頭,`claude-架構對齊`、`ARCH-alignment` 都被當成通才席;r6 起先做 NFKC,全形 `ａｒｃｈ` 也算;寬判多擋,席名自報仍是天花板)。審材路徑先問檔案系統是不是同一個檔(`os.path.samefile`,macOS 大小寫不同、硬連結都認得,讀不到退回 NFC 字串比);帳上的路徑解析不了(手改帳含 NUL)當成沒綁到並講原因、不崩;帳上相對路徑接 repo 根走共用的 `_under_root`(處置閘的 `_prov_path` 同一支,代碼審 r6 架2);快照重驗走共用的 `_prov_read`(`_prov_check` 的本體,讀一次同時驗指紋與取行,代碼審 r6 併2)。推送前檢查開頭把審查帳讀一次、每份計劃查表,同一份快照只算一次;讀帳走 `_spec_gate_ledger_index`(保留規格閘留痕、編號 NFC、壞位元組換替代字元、只留判定用的欄位;帶輪次的列照留,給 (a) 判「判不了」),逐行核心 `_canary_ledger_rows` 跟審查輪那一族的 `_canary_ledger_scan` 共用、篩法各在呼叫端,開檔逐行讀、不整本讀進記憶體(代碼審 r7 架1、併1:r6 讓一支函式帶兩種模式,「逐行解碼」仍先整本讀進來再切),**帳讀不到就擋並講原因**(代碼審 r6 G2)。任一不成立就擋並講原因。
   - **逃不出這道檢查**(代碼審 r4 資2):推送範圍改到的每份 Projects 筆記(檔名清單,含改名後的新路徑),不論狀態、不論有沒有規格閘留痕,都重判一次門;判風險低又略過了危險詞的,一律走上面同一套檢查;沒有風險低留痕(改過檔名、從沒跑過、上次判高)也不強迫先跑規格閘(代碼審 r5 合約席:做完、全綠的計劃跑規格閘過不了也不留痕,叫人跑等於沒有出口),一筆綁好的輕量審就放行,擋下訊息給 `lumos loop next … --tier light`。判風險高的照舊不在這道檢查裡(要走設計審)。範圍比使用者指定的 `Projects/*_計劃.md` 寬一點:改名成 `X.md` 迴圈編號不變,不寬就能躲。
