# 工具分類（2026-09-08）

> 白話：這個工具鏈長到六十多個指令、六十多個機制，之前的整理方式都是「按動詞」（讀／寫／巡檢）或「按你正在做什麼」（進場／動手前／寫回…）。Enzo 要的是第三種軸——**按研究方向**分，好讓之後「檢索怎麼更準」「迴圈什麼時候該停」「agent 怎麼組」這些題目各自開調研、各自量、各自收。分類本身不改任何行為，只是給每篇筆記掛一個「它屬於哪個研究方向」的標籤。

## 邊界規則（最容易混的三對）

- **迴圈工程 vs Agent DAG**：迴圈管「一輪過不過」（判準、證據、處置）；DAG 管「怎麼組人」（拓撲、順序、脈絡、權限）。派工鏡頭「附什麼給審查員」歸 DAG，「附的有沒有被讀」歸評測。
- **合約守衛 vs 節點內容**：合約的「寫法」與內容新鮮度檢查歸節點內容；合約「怎麼被執行」（綁測試、殺傷力、pre-push）歸守衛閘門。
- **評測 vs 迴圈**：canary 統計、黃金回放、成本帳這種「量迴圈本身」的歸評測；迴圈只留「當下這輪過不過」的判準。

跨類的體檢（全 repo 審視、外審吸收、地基盤點）一律掛第 9 類，因為它們的產出是「整體哪裡要修」而不是某一類的機制。

## 守衛

- `.lumos/config.json` 加 `scope` 區塊宣告九值與 `required: true`；lint 對非 MOC 節點：沒掛 → warning、掛超過兩個 → warning、值不在表內 → warning。**只提醒不擋**，rc 不變。
- 沒宣告 scope 區塊的專案（所有消費端）完全不受影響，行為與今天一樣。
- 不走 created cutoff：本圖已全量回填，之後任何新節點漏掛都該被唸。

## 刻意不做

- **不進檢索排序、不進 hook 注入**（見 summary 第三條）。理由是 2026-08-05 的 A3 消融：高連結、高分類的節點是導覽樞紐不是答案，拿分類加權會把樞紐推上來擠掉真答案。
- **不拆 Verification 成獨立判斷**：驗證紀錄跟著計劃走，計劃換類它就換類。
- **不改架構文件的指令家族圖、不改 INDEX 的九個情境子檔**：不同軸，各管各的。
