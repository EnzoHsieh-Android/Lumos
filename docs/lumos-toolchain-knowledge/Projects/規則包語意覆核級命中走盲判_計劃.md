# 規則包語意覆核級命中走盲判_計劃

> 白話:Kotlin 規則包有一類規則,形狀抓得到可疑寫法、卻分不出它是不是真的錯(要知道型別或語意,例:`.setValue` 是 LiveData 還是 Firebase、`.value.add` 是狀態容器還是 Map.Entry)。這類規則放在第三級「語意覆核級」(`rules-review/`,ast-grep 的 info 等級),不擋、也不降成容易被忽略的提示級;這份計劃讓它們的每個新增命中由沒看過作者說法的代理逐筆判「真問題 / 誤報」,判定留痕、可複查、統計準確率。使用者原話(2026-11-05):「如果形狀都改不好,是不是可以參語意判斷?會不會比 hint 靠譜一點,因為 hint 感覺是會被忽略的東西,或你上網查看看大家是怎麼做的」。從 [[Projects/Android寫法語意情境表態與盲判_計劃]] 範圍 8 拆出(那份設計審 r2 對範圍 8 報 blocker,累計折入已過熔斷門檻)。

PRIOR-ART: Semgrep 在固定規則上疊模型判誤報:只在有把握時判;判成誤報的不自動關,而是藏起來集中給人批次複查;準確率底線九成(https://semgrep.dev/blog/2025/announcing-ai-noise-filtering-and-triage-memories )。學術上 ZeroFalse(https://arxiv.org/html/2510.02534v1 )、Wagner 等(https://arxiv.org/abs/2506.16899v1 )讓模型裁判靜態分析結果。採用「規則抓寬、模型逐筆判、判成誤報的進複查清單不直接消失」;不採「模型判完自動放行且沒人看」。r2 通才席指出原範圍 8 引用了這個做法卻讓誤報判定直接放行,跟引用的做法相反。
RETIRE-IF: 上線八週後:某條語意覆核級規則經人複查的判定準確率低於九成 → 那條規則的命中改回人判;整級八週內新增命中少於 5 筆 → 撤掉這一級,規則降提示級。

## 狀態

初稿,還沒開設計審。下面〈開審前必須先解〉是從母計劃設計審 r2 帶過來的問題,開審前要先逐條解進範圍。

## 開審前必須先解

來源:governance/review-reports/android寫法語意情境表態與盲判/ 的 r2 席報告(通=通才、正=正確性、邊=邊界、架=架構對齊)。

1. **分流機制**(通1 blocker、架2):新增告警閘對 `.lumos/lint.json` 每條命令一視同仁,info 級命中會直接進「新增告警就擋」。要在 `_lint_new_run_cmds` 分流:照既有 `report_only` 同形加一個欄位(例 `review_tier`),判別方式要定(命令的 `--config` 指向 `sgconfig-review.yml`,或 lint.json 加標記;後者牽動 `_lintcheck_validate`)。
2. **核對放在哪**(通2 blocker、邊F4):表態那一道在沒有適用題時提早返回、而且吃的資料刻意不跑 lint;應該放在新增告警閘那一道,跟它的開關(`lint_new.gate`)與預算走。
3. **身分與放行用同一把鑰匙**(架1、正6):覆核段身分直接用新增告警閘的 `_lint_new_key`(加同指紋第幾次出現),放行沿用 `lint-waive`,不另起一套;複製貼上時「新增」那一筆是排在後面的那一處,材料要取對位置;`lint-waive` 的指紋是片段雜湊,放行一處等於放行同檔同片段的每一處,要決定接受或加出現序號;`.lumos/lint.json` 缺、閘逾時或環境不可用時覆核命中算不出來,要跟「覆核過且沒命中」分開。
4. **判成誤報不直接消失**(通10、正7、邊F10):照 Semgrep 的做法,判誤報的放進複查清單(doctor 與推送前小結列出,直到人 `--ack`),不是只計數;是否要第二個代理覆核判誤報的那一票,要量成本後裁。
5. **記錄格式**(通5、架5):覆核段的結果 `{seg, verdict, reason}` 跟情境段不同形,事件要帶 `type` 欄或另用事件種類,寫入驗證分流。
6. **沒宣告、環境不可用要講出來**(邊F5):沒有宣告覆核命令、ast-grep 沒裝時,要跟「覆核過且沒命中」分開,doctor 提醒一行。
7. **統計門檻**(通11):升降級建議兩邊都要樣本下限;依據要是人複查過的準確率,不是單一盲判自己的比例。
