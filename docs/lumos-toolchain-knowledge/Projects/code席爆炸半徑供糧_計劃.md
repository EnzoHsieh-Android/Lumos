# code席爆炸半徑供糧_計劃

PRIOR-ART: **借用既有計算與掛點,不建新指令**——爆炸半徑的計算已存在(`impact --diff` 波及清單、`pitfalls --diff` 的必看節點);席位派工的內容慣例已裁([[Systems/design-loop]] d8:貼內容不貼路徑,[[Projects/impact鏡頭機械化_計劃]] 停案正途明文「改派工模板,不改工具」);機械掛點已存在(`loop next` 首輪 advisory=入口栓 A,code 迴圈必經)。本案的全部工作=把「已算出的爆炸半徑」接上「派工詞」這最後一里。**已排除**:派工端機械強制/證明材料進了 prompt(兩前案裁死,結構上無強制點)、任何閘。

> 迴圈編號=`爆炸半徑供糧`(慣例應為檔名去尾,但「code」開頭會被 kind 偵測誤判成 code-loop 帳——實測 roster 判不出;去前綴取尾段,此行即映射紀錄)。

## 問題(機械證據,2026-08-30 盤點)

- **審查席判不了爆炸半徑**:code 席只拿 patch+原始碼;圖譜記的「這段碼綁哪條合約、出過什麼事故、連到哪些功能」沒進派工詞。內容級盤點([[Verification/2026-08-30_席報告圖譜使用一次性盤點]]):**code 迴圈 10 份報告,嚴格 0 份真使用圖譜知識**(design 側 25-33%)。
- **派工單稽核:0/28**(機械數兩法同值:目錄法與 loop 欄法皆 28;數法=materials 欄含 -knowledge/ 路徑;前掃 agent 數 27 係其 find 誤差,已對帳):歷史 28 份 code 派工單,0 份帶爆炸半徑節點;僅 2 份帶任何圖譜材料且都是「被審 spec 自己」。
- **★關鍵時間線(前掃修正後的誠實版)★**:「每席都附圖譜鏡頭、貼內容不給路徑、固定席必答」這條規則 **2026-08-29(d8)才進 code-loop skill**(skill:19,格式指 templates §3 鏡頭 3)——歷史 0/28 是背景不是罪證;**罪證是規則上線後唯一的 code 迴圈(code-entry-latch,3 輪派工)0 執行,而編排者=規則作者本人、同一天**。紀律路線在作者身上上線當天就失守=546 形態最純標本,這是 B(機械助攻)的立案理由。
- 對照:爆炸半徑的機械強點今天全掛在編排者/推送閘(hook 推合約、落成核對、綁定測試真跑、pass 前 sync-check 四條全在跑)——唯獨「席位的眼睛」這環斷糧。

## 裁定(r1 五席+外家全票後;原提案 A/B/C 節縮案重寫)

**B 廢**(blocker×多席):①停案判決 d2 **明文列舉並否決過**「pitfalls→loop next 改工具落點」——B 就是那個選項本人,無新論證(P-1);②top-N 截斷=停案 :52 判死的「把被消滅的步驟裝回來」,我引判決當出處卻沒讀出它在講自己(P-6);③「loop next 必經所以有效」被自己的證據反駁——skill:19 同樣緊鄰必經、同樣被同一人跳過,同類機制(C-5/外家1);④「其餘印名列表」=d8 前一天才實測封殺的「給路徑不給內容」換皮,且 free_total 少報陷阱原句重演(C-2/M-6);⑤證物污染守衛比既有 skip-list 窄,routine 同 commit 的 docs 筆記就是污染源(M-4/C-1);⑥固定席層無上限(實測 20+11=31 篇),「top 3」在底層原語上不成立(M-3);⑦--json 合約/redirect/去重全缺(M-2/C-3/C-4)。

**C 廢**(P-4):與剛判死的常設指標同構念同母體同方法,卻繞過母案([[Projects/loop數據收集_計劃]] d2)當天寫下的三個重開條件。成效量測**改掛既有條款**:[[Verification/2026-08-30_席報告圖譜使用一次性盤點]] revalidate ②(code 鏡頭改版→重跑基線)——本案的文字修正落地即觸發該條款,不另立承諾、不繞閘。

**存活交付=一句話**(外家「更簡單的路」+8/2 A案的血統延續):`pitfalls --diff` 既有的 impact 提示句(scripts/lumos:13638 一帶,本身就是 2026-08-02 裁的 A 案產物)措辭升級——跑完 impact 後「把固定席貼進每席派工詞(貼內容不貼路徑;見 code-loop skill 步驟 2)」。改文字不改工具,落在編排者必經且已在讀的位置。誠實定位:仍是紀律輔助,不宣稱根治;成效由上述既有條款量,若重跑基線仍為 0 → 承認「提醒類全數無效」,屆時唯一沒試過的正途=把「貼」變成派工詞模板的必填結構欄(另案,須人裁)。

**★本案最值錢的副產物(機械席 M-3,留待人裁)★**:d8 規則「固定席必答」對 code 迴圈照字面**執行不動**——固定席層在底層原語無上限,真實 code diff 實測 31 篇,每席貼 31 篇內容+逐條必答=派工詞爆炸。這可能才是規則上線後 0 執行的結構性原因(不純是紀律)。d8 規則要不要為 code 迴圈加量詞(如「以落成核對的 capped 呈現為準」)=改 d8 語意,須走設計迴圈+人裁,本案不動,立此存照。

**P-3 修辭訂正**:「上線當天」→「上線次日」(d8=08-29 15:40,派工=08-30);0 執行的機械事實不變。
