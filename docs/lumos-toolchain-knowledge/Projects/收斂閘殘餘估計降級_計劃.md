# 收斂閘殘餘估計降級_計劃

## 問題（r1 審計修正版）

panel 模式收斂合取有一條「capture-recapture 殘餘估計 < 1.0」，帶 fail-closed（無重疊數據＝直接不收斂）。r1 統計效度審計後的精確描述：

- **鑑別力趨近零**：殘餘 < 1.0 的輪下一輪仍出 major+ 的比率 67%（14/21），殘餘 ≥ 1.0 的對照組 79%（49/62）——差 12 個百分點、Wilson 95% CI 大幅重疊、二比例檢定 p≈0.25。下一輪挖到 major 的底噪本來就約四分之三，這個估計器的讀數幾乎不改變它。
- **公式退化**：Chao1 修正式在 f1≤1 時分子恆為 0——「估 0 → 下輪 23 條」那筆（capture_counts=[3,1,3]）是公式退化不是「低估」，且該輪自身有 blocker、本就被存活合取擋下，從未構成真實假安心事件。
- **前提失效有自家證據**：席獨立與等捕獲率前提，被自家帳的重疊分布（相異缺陷 64–71% 僅單席抓到）直接否定；文獻（Wohlin 1995 起十年線）對前提違反下估計不可靠的一般性結論適用。
- **攔截側的誠實帳**：這條合取歷史上 78.5% 的時間在擋（非「三分之二時間放水」——原措辭誇大，已撤）；被擋的輪 87.8% 同時有 major+ 存活（其他合取本就會擋，冗餘），**獨佔攔截僅 17 輪（9.6%）**。降級會放過這一類——但在鑑別力≈0 的前提下，這些攔截與隨機摩擦統計上不可區分，留著買不到偵測、只買到輪數。

結論：留它當硬合取＝讓收斂被一個不帶訊息的數字隨機延長，且 PASS 時還宣稱「有統計背書」。降 advisory、收斂重量全押 K=2 枯竭連勝＋存活合取＋處置帳。

## 改動（四條 S，r1 折入版）

### S1 capture 兩條合取降 advisory＋PASS 橫幅措辭同步（核心）

- `_panel_round_conjuncts`（scripts/lumos:3520 與 3530 的兩個 `fails.append`，邏輯段 3516-3530）移除，改純觀測輸出。合取縮為：輪有效 ∧ 存活 max≤minor（＋既有 K=2／G3／min-seats 旗標啟用項）。
- **★r1 折入★同函式呼叫端的兩處 PASS 橫幅（scripts/lumos:3642、3645）必須同步改**——現文寫死「∧ capture-recapture 枯竭」，降級後不再被驗證、變字面不實；改法對齊 cluster 路徑既有正確寫法（3739/3743 不提 capture）：`K=2 ∧ 輪有效 ∧ 存活≤minor` / `輪有效 ∧ 存活≤minor`。
- **一刀切、不設 cutoff**：fails 集合是純累加、無 short-circuit，移除兩條後新集合是舊集合子集 → 舊 PASS 必仍 PASS（r1 正確性席逐行核對成立）；放鬆方向無誤紅，已終結 loop 無重問場景。**對稱側已量化**：獨佔攔截 17 輪會轉 PASS——接受理由見〈問題〉末段（零鑑別力下＝隨機摩擦）。

### S2 觀測行語意升級（含 quiet 路徑）

- 判定輪（quiet=False）：有 counts 印 `[panel] capture-recapture 殘餘(advisory,不進合取): 估計 X.XX`；估計 <1.0 加「⚠ 低殘餘讀數無鑑別力(自帳對照 67% vs 79%,2026-08-14)」。無 counts 印 advisory 缺席提示，不 fail。
- **★r1 折入★K=2 前一輪（quiet=True）路徑**：不整段重印，但呼叫端的前一輪摘要行**行內附殘餘觀測值**（如 `K=2 前一輪(rX): ✓ (殘餘 obs 2.50)`／無 counts 附 `(殘餘 obs 缺席)`）——否則 K=2 已是 2026-08-06 起新 loop 預設，前一輪觀測在多數真實場景整段消音。

### S3 canary-stats 席位重疊分布段（r1 折入三補）

`loop canary-stats [<id>]` 新增重疊分布輸出，明定：

- **資料涵蓋**：讀取全部 kind（caught/missed/**none**）記錄的 `capture_counts`——現行掃描迴圈對 kind=none 是 `continue`（scripts/lumos:3920-3922）、per-auditor 迴圈也排除 none（3923-3924），**必須連動改**，否則報表對停用制主流資料空轉。
- **none-only 提前返回路徑（3934-3940）**：重疊段必須在該路徑也輸出（提示行＋重疊統計並列），不得被 early return 吃掉——這正是未來所有 panel loop 的形態。
- **跨輪聚合語意（明定）**：各輪 capture_counts 是獨立母體，**彙總＝跨輪 counts 分布合併統計**（f1 佔比＝所有輪所有缺陷中 count==1 的比例），輸出行明印「跨輪分布合併,非同一母體去重」。
- **型別防禦（r1 邊界席實跑實證）**：`capture_counts` 非 list（如字串 "3,2,1"）時 `_estimate_remaining_defects` 會靜默回 0.0（最強假收斂訊號）——重疊段讀取端必須 `isinstance(list)` 檢查，非 list 計入壞行計數並明示跳過，不得靜默算。
- 誠實界線印在輸出裡：席名＝auditor 欄原文（寫法不統一）、鏡頭層不在帳內。空 list／無 counts loop 該段印「無重疊數據」不炸。

### S4 席名慣例（r1 折入：四處同步）

`--auditor` 席名建議 `<鏡頭>-<模型>`（如 `correctness-sonnet`），純慣例無機械檢查（明寫）。同步四處：design-loop SKILL.md panel 節、**templates.md 記錄模板行（`<slotN>` 範例改）、code-loop SKILL.md 端到端範例（slot1 改）、code-loop reference.md 兩處**——只放一處會被各檔自己的舊範例稀釋。

## 測試策略（TDD：先紅後綠；r1 折入修正）

1. **既有期望反轉**：`t_loop_panel_gate` 兩條改期望 rc0。斷言**必含觀測行存在性**：超門檻 fixture（counts=1,1,1,1→殘餘 6.0）斷「advisory」＋估計值字串，**不得斷 ⚠ 低殘餘句**（r1 邊界席：該句只在 <1.0 印，斷了必紅）；無 counts fixture 斷缺席提示。
2. **新 t_capture_advisory**：①超門檻→rc0＋advisory 行 ②無 counts→rc0＋缺席提示 ③存活 major 照樣 rc1 ④**低殘餘 fixture（獨立造 counts 使殘餘 <1.0）印無鑑別力警語** ⑤**★r1 折入★PASS 橫幅不再含「capture-recapture 枯竭」字樣**（斷 stdout 不含）⑥K=2 場景前一輪摘要行含 `殘餘 obs`。
3. **新 t_canary_stats_overlap**：①kind=none 記錄帶 counts→重疊段印出且 f1 佔比正確 ②none-only loop 帶 --loop 查詢→提前返回路徑仍印重疊段 ③counts 為字串型→計入壞行提示、不靜默算 ④無 counts→「無重疊數據」不炸。
4. 全套迴歸（cluster 帳、light/settle/循序不變）。

## 實務隱患（r1 折入版）

- **鬆閘補償**：合取剩「輪有效∧存活≤minor∧K=2」。K=2 是外部多判準停損建議中的穩定窗項（**非唯一主判準**——外部建議為三取二，含「實質/表面改動區分」尚未落地＝候選②另案；此處如實不誇大）。收斂措辭講小：本輪起 PASS 語意＝「此陣容未再發現」，且本案審計因 Codex 缺席為**單家族視角**。
- **反向誘因**：降級後「無 counts 不再 fail」可能讓人懶得記重疊數據，餵不飽 S3 報表——緩解＝loop next 記帳模板照帶 --capture-counts、缺席時 advisory 行點名。
- **測試假綠**：反轉後斷言必含觀測行存在性（同 F5 教訓）；橫幅斷言用「不含」方向（⑤）。
- **散落同步清單（r1 整合席補全版）**：design-loop SKILL.md＋code-loop SKILL.md＋templates.md＋**design-loop reference.md §D1＋code-loop reference.md**＋Systems 節點 **design-loop／loop-convergence-recording／convergence-evidence-gate／heterogeneous-finder-ensemble**（pitfalls-code-loop 僅涉 cluster 帳不動）＋調研節點統計修正。折入時跑散落 grep（`殘餘<門檻`／`fail-closed`／`capture`）。
