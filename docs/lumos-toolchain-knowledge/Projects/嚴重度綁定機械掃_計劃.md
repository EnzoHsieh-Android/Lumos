# 嚴重度綁定機械掃_計劃

> 白話:整套新收斂制信一件事——記帳的人把審查員講的最嚴重等級照實抄。這件事現在靠自律。r1 外家把原案(只做事後掃描)否決掉了:掃描器抓到的時候閘已經放行,而且「報告乾脆不寫等級」就掃不到。反轉後的做法:**入帳那一刻就擋**——新帳列的報告裡沒有機器讀得懂的等級宣告、或帳面跟報告對不上,直接拒絕記帳;掃描器降級為歷史帳的補掃跟縱深保險。

PRIOR-ART: borrow——同 repo 的 quote-check/refcheck/seat-check 收貨三道就是「報告↔帳」機械對帳的現成模式,本案第一層是寫側前置驗證(比照 record 既有 --severity choices 白名單的「入口擋」哲學,往內容層延伸一步),第二層才是收貨型掃描(severity 維度的第四道);報告檔已凍結入帳(path+sha256),parse 基礎全在。

## 現況事實

- 帳列有 severity(寫側白名單擋值域)、report{path,sha256}。席報告格式★不★一致:2026-08-26 普查 59 份,41 份用「severity: <值>」獨立行,但外家席(codex)報告慣用「### id / 等級 / 標題」表頭、全篇零獨立行——恰好是掛否決權重、最需要機械驗的席(r1 兩席獨立實測證偽了「全部報告皆此格式」的原始前提)。表頭型的正規化★不是既有 code 步驟★(全庫 grep 零命中,r2 delta 抓的)——是本案新立的收貨 SOP:存席報告時把表頭型嚴重度轉為「severity: <值>」獨立行(與引句正規化同一手工步驟,寫進 design/code loop 收貨規矩);漏做的機械後果=record 時 rc2 擋下(守衛本體),不是靜默放過。
- 綁定驗證現況=編排者自律;人工核僅一次(0/18);disposal 閘不驗此維度——低報 severity 可讓 major 變 minor 逃過「code-* major 必折」鐵則。

## 條款

- **[S1] record 寫側強制(第一層,硬擋)**:`canary record` 凡帶 --loop+--auditor 的★審查席帳列★(結局帳 --outcome 豁免;★code-batch3 折入:原「三者齊備」觸發=漏打 --round 即整層蒸發,外家+內席各自實測繞到 converged——觸發不再看 round★)一律必附 --report(不帶=rc2「審查記帳必附報告」——原案以「帶 --report」當觸發條件,不帶就整層蒸發,r2 delta 抓的繞過門;非審查類帳列如自主迴圈結局帳不受影響)。★這是行為改變★(r3 delta 抓的:實帳 681 筆審查席帳列有 286 筆無報告,08-22 的迴圈還在用這個形狀)——生效後該形狀被拒,不設過渡豁免,理由:不附報告的審查帳事後無從重驗(disposal ③ 留痕重驗也會 FAIL),正是本案要堵的縫;合規路徑=loop next 記帳範本本就帶 --report,補記/救回輪也要先落報告檔才記。入帳前驗:讀報告檔(此時本來就要算 sha),parse 全部嚴格整行——逐行 `fullmatch`、空白只認 `[ \t]*`(`\s` 會吞換行讓標籤與值跨行黏上,r2 外家抓的;大小寫、全形冒號、行首多餘字元一律不認,fixture 釘變體+「標籤與值分兩行不得匹配」),取最高,且至少 parse 到一行(乾淨輪也要一行 severity: clean——這行不是樣板,是機械可驗的宣告本體;豁免 clean=重開「低報成 clean」的無聲逃逸門,r1 ext-f1 同型;多寫一行是刻意選的成本,收貨 SOP 同步補)。方向非對稱(r2 delta 抓的:原「不等就擋」會逼保守記帳者回頭改已凍結報告配平,恰是 ext-f2 點名要避免的形狀):★低報(帳面<報告最高)=拒絕入帳 rc2★,訊息指路「先把報告 severity 行補齊/對正再記」;高報(帳面>報告最高)=放行+advisory 提醒(記高是保守方向,下游三閘全是「越高越嚴」,r1-s1 乾淨面分析成立);parse 不到=拒帳 rc2。嚴格整行錨定天生排掉兩型逃逸(r1 兩席各抓一型):引句行(以「引句」標籤起頭,整行不可能匹配)與 blockquote(以 > 起頭,同理)——不需要任何「排除引句行」啟發式;fixture 各釘一個逃逸樣本。值序抽模組常數 `_SEV_ORDER`(既有三處字面複製回填,不開第四份)。
- **[S2] severity-check 掃描器(第二層,advisory)**:`lumos severity-check --loop <id> --round <rN> --auditor <席>`——吃帳列座標不吃檔案路徑(對帳對象是帳列;resolver 複用 loop status 既有 loop/round 篩選,單一實作——這是四道收貨裡第一個吃座標的介面,理由在此交代)。生效日前的歷史帳=純 advisory(格式掃不出=提醒,相容);生效日後的新帳=縱深重驗,抓到低報=**寫側有 bug**(第一層本應拒帳),紅字轉述+開 Issue 攤人;converged 不自動撤(撤=改閘語意,另案過審)。standalone 模式自驗報告 sha 與帳面一致;被 disposal 尾端呼叫時信合取③已驗過(旗標跳過,不對同一檔重算兩遍雜湊)。
- **[S3] 併入 --disposal 尾端(異常才發聲)**:問閘收尾對判定輪逐席跑 [S2],比照 roster 尾端(try/except 降級、__seqN 合成鍵跳過、advisory 恆不動 rc);轉述行必帶「(觀測,不進合取)」免責字樣(canary 觀測段已有先例,roster 尾端漏了——本案順手補上同款,一行);留痕★不開新檔★——寫進既有 `roster-alerts.log` 同一寫入路徑,kind=`severity_underreport`(第二個沒人讀的孤兒檔比一個更容易被忘;檔名沿用,定位升為「問閘尾端異常留痕簿」,Systems 筆記記一句)。
- **[S4] 歷史首驗**:對★全部帶 report_path 的審查席帳列★跑 [S2] 歷史掃——不設日期起點(r3 delta 抓的:原「08-25 起」會把 d5 世代 08-14~08-24 的 218 筆漏在外,64%;掃描器守的「severity 忠實轉錄」不限制度世代,有報告檔就能掃)。結果分段呈現:08-25 起處置閘世代/08-14~08-24 過渡世代/更早舊制;無 report_path 的審查席列(現帳 286 筆)統計為「不可驗」明列,不摻進「全量」;「n/全量」的全量=帶報告的審查席列總數。結果入本案驗證紀錄。
- 邊界:寫側新增「入帳前置驗證」(★推翻原「不動記帳寫側」邊界——r1 外家否決層次倒置成立★),但不動 severity 值域白名單、不動閘判定布林;生效日邊界★歸讀側 [S2]★(歷史掃用 ts 分新舊;寫側每筆 ts 天生=now,「舊帳豁免」對寫側是死條件——r2 delta 抓的,別在寫側刻 ts 分支,更嚴禁為了讓豁免生效而新增 --ts/backdate 覆寫參數=時戳造假後門);報告格式正規化發生在收貨轉錄(既有步驟),不是掃描器去適配百家格式。

## 行為斷言

fixture:【寫側】新帳列報告 blocker+帳 minor(低報)→拒帳 rc2 指名差異;報告無 severity 行→拒帳 rc2;報告 minor+帳 major(高報)→放行+advisory 提醒;審查席帳列不帶 --report→拒帳 rc2;標籤與值分兩行→不匹配;引句行/blockquote 內含 severity 字樣→不計入 parse(逃逸樣本各一);全形冒號/大小寫變體→不認。【掃描器】歷史帳低報→紅字轉述+rc 不變;新帳低報→轉述行標「寫側 bug」;sha 不符→拒掃指路 quote-check;尾端轉述行帶「(觀測,不進合取)」且 rc 不變(打樁);歷史掃跑完出統計行;留痕落 roster-alerts.log 且 kind=severity_underreport。

- 守衛面:第一層(寫側)天生是硬擋(拒帳 rc2),不存在「等掃描器抓到才升級」的循環空窗(r1 外家 ext-f4 指的循環盲點因此不成立於新案);第二層 advisory 恆不動 rc。已排除:金流/對外/不可逆。

- 回頭條件(機械):2026-11-26(=[[Projects/roster對帳併入問閘_計劃]]立的兩季覆核日,兩案共用同一天免多一個沒人記得的日期)數 `roster-alerts.log` 的 `severity_underreport` 條目——任一條=寫側有 bug,當場開 Issue 攤人;零條=第二層掃描器+尾端一併重審是否退場(寫側 fixture 常駐測試網,不在重審範圍)。
