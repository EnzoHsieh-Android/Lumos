# 標籤系統精簡（排隊中，等檢索核心落地）

> 白話：同一件事在同一篇檔案裡寫兩遍（一次欄位、一次標籤），只有一半有守衛。本來要把第二遍改成「需要時當場算出來」。**兩輪設計審之後結論是：這件事本身沒錯，但順序錯了**——它要對抗的那些脆弱性，全部來自「撈候選」那一關，而那一關正要被重建。等它重建完，本案會從一個工程縮成幾個小步驟。

上游盤點在 [[Projects/標籤系統盤點_調研]]。前置是 [[Projects/檢索核心重建_計劃]]。

## 為什麼排隊（這是本篇現在最重要的內容）

兩輪設計審，五席＋三席，共 50 條發現、34 條標 blocking。把它們歸類之後：

| 歸因 | 條數 | 索引落地後還在不在 |
|---|---|---|
| 撈候選那一關是字面掃檔（承諾罩不到、行為靜默改變、排序統計量會抖） | 過半 | **消失**——索引建在合成後的標籤上，字面殘留自動不被看見；語料變全庫，分數不再隨候選集抖動 |
| 清理器的併發、中斷、回滾 | 6 | 還在，要照下面條款做 |
| 合成的邊界值規則寫錯 | 3 | 還在 |
| 教學面同步、舊節點認領、過期註解 | 5 | 還在，但都是小事 |

**所以現在做，是在對抗一個即將被換掉的東西。** 等索引落地，這份計劃的核心條款（讀時合成、字面路徑的行為改變）大半會變成索引的設計決定，剩下的是清理器與文件同步。

## 執行時的條款（已折入 r1 + r2 全部發現）

- **[S1] 鏡像標籤改成讀時合成，範圍限欄位型判斷。** 四個欄位型消費點走同一個 helper：結構化查詢篩選、排序的標籤欄組裝、進場頭部顯示、單篇快檢的研究方向檢查。後兩者目前各自直接疊代標籤欄位、沒走既有清單正規化，一併收攏。 [test:t_query_tag_synthesized_from_field] [test:t_query_ignores_stale_mirror_tag] [test:t_tag_helper_is_sole_field_path]

- **[S2] 合成的空值規則（r2 兩席修正）。** 判準不是「缺席或空字串」，而是**「去空白後為空、或型別不是字串」就不合成該家族的標籤**。理由：既有解析器對純空白的欄位會產出空清單而非空字串、對三個空白字元只去引號不去空白、未加引號的 null 會存成字面字串——原本的字面判準三種都擋不住，會合成出垃圾標籤。**測試必須經真解析器進 helper**，不得直接餵造好的字典。 [test:t_synth_skips_blank_and_nonstring_field] [test:t_synth_goes_through_real_parser]

- **[S3]（作廢）** 原本寫「鏡像清理對排序位元不變」。r2 外家席實驗證偽：排序統計量取自候選集，清掉鏡像會改變候選集，連帶改變留下節點的分數。**正確的驗收只能在索引落地、語料變成全庫之後跑金標對照。** 移交 [[Projects/檢索核心重建_計劃]]。 [manual:索引落地後跑金標前後對照，把三個指標差異寫回本節點]

- **[S4] 同步器與兩道漂移閘退場，舊測試同批處理。** 既有兩支測試斷言的正是要拿掉的行為，必須同批刪除或改寫。 [test:t_set_status_no_longer_syncs_tag] [test:t_lint_no_mirror_drift_error]

- **[S5] 四種節點範本不再產鏡像標籤。** [test:t_new_templates_have_no_mirror_tags]

- **[S6] 存量清理做成 lumos 子命令。** [test:t_tags_prune_is_idempotent] [test:t_tags_prune_resumes_after_interrupt] [test:t_tags_prune_per_file_lock] [test:t_tags_prune_inline_list_fails_loud] [test:t_tags_prune_saves_undo_payload] 照既有前例註冊在子指令表、dry-run 預設、`--apply` 才動手。r2 折入的五個要點：
  - **鎖逐檔取得釋放，不整批持有**。那把鎖是整座筆記庫粒度、閒置 30 秒就判定持有者已死並原子接手，門檻依據是「單篇寫入不到一秒」；批次跑數分鐘必撞破，另一程序會搶走鎖，變成兩個程序同時相信自己持有。**每一檔在鎖內重讀再寫**。
  - **回滾要存得回內容，不是存檔名**。取消乾淨檢查後，同一支檔可能同時含使用者原有未提交正文與本次刪除，按檔名還原會把兩者一起丟掉；原子寫入不留舊版。**清理前內容（或可逆差異）要落地持久化**，中斷時的寫入順序也要進驗收。
  - **一篇一次寫入**。既有清單移除原語一次只吃一個值，多標籤會變多次寫入、中斷會停在「部分清理」這個未定義中間態。轉換函式一次算出該篇的最終標籤集，一次寫完。
  - **inline list 的例外要逐檔明確接住**，結果是中止該篇、繼續下一篇，不是整批中止。
  - **數字當場機算**，完成度判準不是本篇寫死的快照數字。

- **[S7] 存量清理範圍。** 刪完標籤會變空的節點整個拿掉 tags 欄位（以執行當下掃描為準）。 [test:t_tags_prune_drops_empty_tags_key]

- **[S8]（改裁，移交）** 原本是「語意警示與優先級兩個家族凍結退場」。2026-09-14 Enzo 改裁：**新目標是優化機制不是精簡，退場等於拿掉東西**——改成「給它們一份工作」（優先級接待辦排序、風險類接動手前的注入），設計併入 [[Projects/檢索核心重建_計劃]]。本案不動這兩個家族。附帶更正：原文說它們「沒有家族專屬程式碼」是假宣稱，優先級有值域硬擋。 [manual:確認檢索核心案已接手這兩個家族的用途設計]

- **[S9] 殘留清掉。** 格式不合的裸標籤（其中 3 篇沒有對應摘要行，要先補上）、1 篇停用滿 40 天的舊領域標。 [test:t_lint_warns_on_bare_family_tag]

- **[S10] 摘要符號詞彙表：先修正則、合併兩份表、再收 `PRIOR-ART:` 與 `REVISIT:` 兩個值。** [test:t_symbolish_regex_reaches_hyphenated_prefix] [test:t_symbol_vocab_single_source] [test:t_symbol_typo_variant_still_flagged] 抓打錯字的正則只認連續大寫字母，含連字號的前綴從一開始就不會被比對到，所以直接加白名單是無效動作。程式裡有兩份獨立寫死的九值列舉（一份給單篇快檢抓錯字、一份給搜尋標記命中行的符號區域），只改一份會讓「已收編」只有一半是真的。**測試不得空過：要同時斷言打錯字的變體仍會被唸**，證明正則真的伸到那裡。與下方「不動既有九個值」不矛盾——那句講的是不刪不改既有九個，這裡講的是新增兩個。

- **[S11]（移交）** 原本是「字面搜尋的行為改變要出聲」。r2 外家席指出字面路徑不只搜尋一條：動手前的入口召回自己掃檔案原文、連搜尋都不走，加在搜尋上的提示罩不到它。**三條路共用同一份索引之後這個問題消失**，移交 [[Projects/檢索核心重建_計劃]]。 [manual:確認索引落地後三條字面路徑都吃同一份索引]

- **[S12] 教學面同步。** 規範文件的家族對照表、示範 frontmatter、以及一段寫死在文件裡的建檔指令字串（跟程式範本是兩條不同路徑，[S5] 碰不到）。 [manual:改完逐處 grep 鏡像標籤，確認規範文件零殘留]

- **[S13] 舊節點認領，不留說謊節點。** [manual:跑重驗候選掃描把命中的兩篇都處理掉並在本節點列出處置] [manual:對舊計劃節點新增一條翻案決策，內容含對它當初兩條理由的回應] 那篇驗證紀錄的重驗欄位當初就寫著「若做砍標籤徹底去重遷移 → 這兩道都該退場」；舊計劃節點寫著「不做」，理由是①檢索對開頭標籤的依賴未驗證 ②動 140 篇成本不成比例。理由①今天被證實為真（兩輪審查都指向它），本案是收窄承諾而不是無視它。

- **[S14] 修掉過期三週的註解。** 風險標籤那段仍寫「保送固定席」，實際已降入參考道。 [manual:讀 impact 那兩段註解確認說法一致]

- **[S15]（移交）** 研究方向進排序的消融量測。索引會重建排序的語料基礎，在舊基礎上量的數字沒有意義。移交 [[Projects/檢索核心重建_計劃]]。 [manual:確認檢索核心案已排入這項消融]

## 邊界與不做

- **不動摘要符號的既有九個值**（KEY／FLOW／DEP／TEST／AUTH／FLAG／DECISION／VERIFY／CORE）——意思是不刪不改既有九個，不是總數封頂九個（[S10] 要新增兩個）。
- **不要求消費專案遷移**，但已遷移的圖譜要求讀它的工具也是新版；消費專案的順序是先更新工具再遷移。
- **總索引那篇會第一次出現在標籤查詢結果裡**（它沒有 tags 欄位但兩個純量欄位照常填著）。一致性變好不是變壞。
- **預覽數字與實際執行之間不綁版本**：轉換是對當下狀態做冪等判斷、不重放預覽快照，所以數字對不上只會看起來不一致，不會寫錯。這是既有兩段式指令的共通設計。

## 實務隱患

- **不可逆與回滾** — 見 [S6]：要存得回內容，不是存檔名。
- **★Obsidian 標籤面板會空掉一半（本 repo 自己就會）★** — 圖譜以 Obsidian vault 慣例維運，它的標籤索引讀實體開頭欄位、不會呼叫合成 helper。Enzo 2026-09-14 已知此代價並選擇砍掉。
- **遷移順序** — 清理器與合成 helper 同在一支檔，版本一致是天然保證。
- **併發** — 逐檔取得釋放那把鎖，鎖內重讀再寫。
- **效能** — 合成 helper 進熱路徑，驗收用針對它本身的微基準（固定跑 N 次查詢與搜尋量開銷），不用全套測試時間當替代指標。
- **資源** — 逐檔原子寫入，用既有慣例。
- **狀態同步** — 兩份真相改成一份，承諾範圍限欄位型判斷。
- **快取** — 測試有快取分片檔，清理大量節點後要重跑受影響子集，不能只信快取。
- **認證、限流、個資、金流、對外寄送** — 無。不出本機、不碰網路、不碰個資。

## 風險與回頭條件
