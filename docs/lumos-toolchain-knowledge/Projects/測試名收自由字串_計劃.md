# 測試名收自由字串_計劃

> 白話:前端的測試習慣用一句話當名字(`it('下單後按鈕會停用')`),lumos 目前只認得 `pay_guard` 這種「識別字」名,句子名一律掃不到,條款綁上去全部懸空,規格閘卻還印「✓」。這份計劃讓測試綁定收整串句子(含中文與空白),懸空時規格閘改印明顯的警示,跑測試時把句子安全地交給測試工具的名稱篩選。來源:Web 示範前端(order-web)15 條條款全懸空,比對表見 [[Projects/Web示範前端缺口_調研]] 的 W1。

PRIOR-ART: 不新建機制、不加新語法。①名稱照原樣整串比對,沿用 Kotlin 反引號測試名早已收空白名的做法(KOTLIN_TEST_RE 收 `` `名` ``、`_kill_norm_method` 拆殼);②測試工具那邊:Jest 的 `-t`、Vitest 的 `-t`、Playwright 的 `-g` 都是拿正規式比對「完整名稱」的子字串,flutter 的 `--plain-name` 是純文字子字串——所以跳脫只對前三者做,跳脫字元集照 MDN 的 escapeRegExp(`.*+?^${}()|[]\`);③平台逃生口沿用單平台已有的 `test.method_regex` 與 `_safe_user_regex`,只是讓多平台也讀得到。曾被否決的 `[test:名稱(理由)]` 新語法(Projects/測試綁定一行一支提醒_計劃)本計劃不碰:舊寫法一字不改照讀,只放寬「名字裡可以有什麼字」。
RETIRE-IF: 上線 8 週內,自由字串綁定造成的假綠(綁定判成綁好、測試工具卻跑了別支或零支而閘報綠)出現 2 次以上,而同期它幫忙抓到的懸空與紅燈少於這個數——照〈回退〉的範圍收回(掃描與寫入路徑一起收),規格閘的懸空警示保留。

## 舊決策與為何翻案

舊設計在 [[Projects/多平台合約測試綁定_計劃]] 的 D4 與 [[Systems/test-profile-multiplatform]] 的摘要:「識別字名才可綁,含空白的 title NO MATCH,是刻意設計」。當時三個理由:

1. 不改 `IDENT_RE`,免得牽動 C#/Kotlin 既有守衛;
2. 擷取群組 `([A-Za-z_]\w*)` 後面要緊接閉合引號,多字 title 整個不匹配,不會「抓到前半個字」製造假證據;
3. 當時沒有任何網頁 repo,Playwright profile「先內建、不接線」。

為何翻案(使用者 2026-10-15 裁):

- 理由 3 不在了:這次示範就是真的網頁專案,15 條條款全懸空,前端的慣例就是句子名——要求改成識別字等於要求整個前端生態改寫法。
- 理由 2 照樣守得住:新的掃描擷取「整個字串字面」,而且字面後面要緊接逗號或右括號才收(做法 2),只拿得到一部分的寫法一律不收;部分擷取的假證據不會出現。
- 理由 1 改成分開處理:`IDENT_RE` 只留給會「產生程式碼與檔名」的 `guard scaffold`,綁定名稱另用一條名稱規則(做法 1),C#/Kotlin/Python 的識別字名照樣合法、判法不變。
- 舊設計還有一個沒寫出來的代價:掃不到的句子名在規格閘只算「懸空、只提醒」,而那一行仍印「✓」,作者以為綁好了。

舊計劃的決策 d1(設定改成多根多 profile)跟這件事無關、照樣成立,不作廢;被推翻的是 D4 那段正文設計與 Systems 節點的兩行摘要,實作時在那兩處標明被這篇取代(做法 7)。

## 做法

### 1. 一條名稱規則、一套切法

- **名稱合法性只有一支函式** `_test_name_ok(name)`:去頭尾空白後不是空的、至多 200 字、不以 `-` 開頭、不含 `[` `]` `,`(半形逗號),也不含 `_PATH_SPECIAL_CATS` 那幾類字元(控制字元、格式字元、行分隔與段分隔;用既有的 `_path_special_chars` 判,不另寫第三份控制字元定義)。中文、空白(中間的空白原樣保留、不壓縮)、括號、冒號、引號、全形標點都可以。Windows 上另外不收 `& | < > ^ % " !`(cmd.exe 不認單引號,shell 引號包不住;代碼審 r1 資安席)。擋下訊息的白話收成一句 `_TEST_NAME_RULE_ZH`。
- 取代目前分散的三種判法:`_KILL_METHOD_OK_RE`(`^[\w .]+$`,不收括號、冒號、引號)、綁定路徑上的 `IDENT_RE`、`_NsTrJudge._plat` 自己寫的「含方括號就壞名」。
- **反引號拆殼只有一條規則**:整串剛好被一對反引號包住(Kotlin 的 `` `名` ``)才拆,其他位置的反引號是名稱的一部分。`discover_test_methods` 現在的 `.strip("`")`、`_kill_norm_method`、`_test_names_of` 都改用這條,不然 `` `useFoo` 回傳 x `` 這種標題兩邊拆的深度不一樣,比對不上。
- **「一格 `[test:]` 的值 → (平台, 名稱)」只有一支函式** `_split_test_ref(seg, platforms, default)`,`resolve_test_refs`、`_test_names_of`、`_kill_method_name`、`_dispositions_split_test` 都改呼叫它。這四支現在各切各的:`_kill_method_name` 多平台時見冒號就丟掉前面;`_dispositions_split_test` 單平台見冒號就拒收;`_test_names_of` 不管平台都剝前綴、還把冒號後的空白吃掉(`API: 逾時` 變成 `API:逾時`)。統一規則:
  - 單平台(沒有 `platforms`):整串就是名稱,不切冒號。處置帳那邊原本「單平台帶前綴就明講沒開多平台」的提示改成:名稱找不到、而且冒號前面那段長得像平台名時,找不到的訊息加一句「這個專案沒開多平台」。
  - 多平台:第一個冒號(半形或全形)前面那段如果是已定義的平台,就是前綴,名稱是冒號後面那段、只去頭尾空白。不是已定義平台時:半形冒號而且前面那段只有英數、底線、連字號(長得像平台名),照舊判壞名,不猜(擋 `wbe:x` 這種打錯字);其他情況整串都是名稱。所以名字本身有冒號(`API: 逾時顯示重試`)時要寫平台前綴(`[test:web:API: 逾時顯示重試]`),壞名訊息補一句這個寫法。
  - 多支用半形逗號分開;**全形逗號是名稱的一部分**(中文句子常有「，」)。`_test_names_of` 原本兩種逗號都切,改成跟 `resolve_test_refs` 一樣只切半形。全形冒號照舊當前綴,但只限前面是已定義平台:note-shape 那組刻意收的全形冒號容錯(既有測試 `[test:py：test_alive]`)保留,而且條款綁定、合約閘這兩條路也跟著收。
- 標記的邊界:`TEST_REF_RE` 用「到第一個 `]`」,`slot_parse` 數方括號層數,兩者對含方括號的值切法不同。名稱規則不收方括號之後,合法名稱兩邊切出來一樣,含方括號的兩邊都判壞名。這兩支本身不改。
- 名字比對一律整串相等(去頭尾空白後),不做大小寫或空白正規化。既有的「`類別.方法` 寫法拿最後一段比」(`_classify_test_refs`、`_NsTrJudge._judge`)只在點號兩邊都是識別字時才用,句子名裡的點號照整串比。

### 2. 掃描收整個字串字面

- **剝註解的做法**(r1 五席同報的根因;下面第一段是 r1 前的說法,現行做法以緊接的子項為準——不另開模式,`c-style` 本身換掉):`_strip_test_comments` 的 c-style 用 `//[^\n]*` 與 `/\*.*?\*/` 直接刪,不認字串。句子名裡的網址(`http://…`)會被從 `//` 截斷,`/*`(`GET /api/*`)會一路吃到檔內下一個 `*/`,中間的真測試整支消失;沒有結尾 `*/` 的 `/*` 每一個都掃到檔尾,是二次方時間(資源併發席實測 8000 行 11 秒)。改法:新增 `comment_strip: "c-style-strings-kept"`,一趟由左往右的交替比對,依序認字串字面(單引號、雙引號、反引號,含跳脫)、`//` 註解、`/* */` 註解;字串原樣留下,只刪註解。沒有結尾的 `/*` 一路刪到檔尾,所以每個位置只走一次,是線性時間。node-jest(含 node-vitest)、playwright、dart 改用它;java 的 `c-style+strings`、其餘 profile 不動。正規式寫的 JS 正規表示式字面(`/'/`)可能被當成字串開頭,這是已知限制,寫進 Systems 節點。
  - (代碼審 r2 後改)多行字串也要認得:三個雙引號(Kotlin、Swift、C# 11、Dart)、三個單引號(Dart)、C# 的 @ 加雙引號,不然字串裡單獨一個 `/*` 會被當成沒收尾的註解、刪掉後面全部測試。
  - (代碼審 r1 後改,編排者裁)不另開新模式:直接把 `c-style` 換成這種認得字串的剝法,所有用 c-style 的語言(Kotlin、Swift、C#、Maestro 也是)一起改——字串裡的 // 或 /* 在每種語言都會截斷或吞掉測試;java 的 `c-style+strings`(刻意清空字串)保留,剝法從三種變兩種。正規式用展開式寫法,32MB 字串不再要 4GB 記憶體。
- `JEST_TEST_RE`、`PLAYWRIGHT_TEST_RE`、`DART_TEST_RE` 改成收第一個引數的完整字串字面:單引號、雙引號、不含 `${` 的反引號樣板三種。字面主體限 200 字(名稱上限本來就是 200),每個起點最多走 200 字,所以一行塞很多個 `it('` 的壓縮檔也是線性。收之前還要滿足:
  - 字面後面緊接(可夾空白)`,` 或 `)`:`it('下單' + suffix, …)`、`it('a'.repeat(3))` 這種只拿得到一部分的不收。這就是舊設計理由 2 要防的部分擷取。
  - 呼叫前面不能是 `.`、英數、底線或 `$`:`/\d/.test('hello world')`、`foo.it('x')` 這種別的物件的方法不收。
  - 字面裡只認 `\'`、`\"`、`\\`、反引號、`$` 五種跳脫並還原(反引號與 `$` 是樣板字串與 Dart 會用到的);出現其他跳脫(`\n`、`\u4e2d`、`\x41`)就不收,免得收到的跟測試工具看到的標題不一樣。Dart 字面裡有沒跳脫的 `$`(插值)也不收;`.each` 與帶 `${` 的樣板照舊不收(名字跑的時候才算得出來)。Playwright 的宣告字面後面要接逗號(本體那個引數一定有;測試本體裡的 `test.skip('原因')` 不算宣告,代碼審 r1 邊界席)。
- **含半形逗號或方括號的標題不收進測試集合**(編排者 2026-10-15 定:這兩種名字不收,見〈不做〉)。掃描照樣比對到,但還原出來的名稱過不了 `_test_name_ok` 就丟掉,不進 `discover_test_methods` 的結果,所以不管怎麼綁都是懸空,不會因為被逗號切成兩半而各自配到別支。**這條只套在字串標題型的 profile**(JS 三家與 Dart,即做法 4 的 `name_filter` 是 `regex` 或 `plain` 的那幾家):Kotlin 反引號名 `` `when offline, shows banner` `` 現在就收得到,照舊收、判法不變。條款綁定列懸空時,如果那一格 `[test:]` 的值裡有半形逗號、切出來的幾段又都不是真測試,那一行多印一句提示:含逗號或方括號的測試名綁不了,請改測試名或寫 [manual:]。
- 修飾:Jest/Vitest 收 `.only/.skip/.concurrent/.todo/.fails`;Playwright 收 `test(`、`test.only/skip/fixme/fail(`、`test.describe(`(含 `.serial/.parallel/.only/.skip`);`test.step(` 不是測試,不收。
- Playwright profile 補檔名錨 `file_name_match: ["*.spec.*", "*.test.*"]`(Playwright 預設也只收這兩種檔名):現在它掃整個 repo 的 `.ts/.tsx/.js/.jsx`,連建置產物和一般程式碼裡的 `test(` 都會被看到。
- 一個正規式裡三種引號是三個分支,擷取群組不只一個:新增 `_test_name_of_match(m)`(回第一個有值的群組並還原跳脫),`discover_test_methods`、`_residual_test_files`、派工鏡頭備援段的受影響測試都改用它;使用者自訂的 `method_regex` 也走它,只有一個群組的舊寫法結果不變。
- Maestro(`name:` 欄位)不在這次範圍,見〈不做〉。

### 3. 懸空要明顯標出

- `_clause_check`(規格閘與處置閘第五步共用)目前懸空時仍印 `條款綁定: ✓ — N 條全標(…懸空 k 只提醒不擋…)`。改成:有懸空就印 `條款綁定: ⚠ — N 條全標(綁了…/靠人…),懸空 k 只提醒不擋(綁的測試找不到,逐條見下…)`,「懸空 k 只提醒不擋」照舊保留,讀的人知道這行不擋;下面逐條一行列出編號、名稱與懸空種類,最多 15 行、其餘講總數;沒懸空才印 `✓`。懸空種類的意思:
  - 寫錯:程式碼裡完全找不到這個名字;
  - 設定認不到:檔裡有這個名字的宣告,掃描設定不收;
  - 只被提到:名字在程式碼文字裡出現過,但不是掃描認得的測試宣告,例如寫在註解或一般字串裡;
  - 壞名:平台前綴未定義,或名稱不合法。
- 擋不擋不變:風險高照舊只提醒,回傳狀態照舊是 ok,rc 不變——印 ⚠ 但狀態 ok 是刻意的,⚠ 的意思就是「提醒、不擋」。呼叫端(處置閘第五步、規格閘)判過不過看回傳狀態,不比對 `✓` 字樣(2026-10-15 grep 主程式沒有比對這個字樣的地方,只有測試會比)。風險低本來就要求測試存在(`_clause_check_twoway`),照舊擋。要不要讓懸空在風險高也擋,記成待決問題 Q1,不在這次改。
- `_spec_gate_runnable` 在條款全都懸空時目前印「沒有綁 [test:] 的條款,沒東西可跑」,會讓人以為根本沒綁;改成「k 條綁了測試但全懸空,沒東西可跑」。
- 新增或改寫的訊息(含冒號的壞名、含逗號的提示、`guard scaffold` 擋下)照既有三段式寫:發生什麼、為何在意、下一步的指令獨立一行。

### 4. 跑測試時名字怎麼交給測試工具

- profile 加一個鍵 `name_filter`:`regex`(node-jest、node-vitest、playwright)、`plain`(dart)、`ident`(其餘;名字本來就是識別字,行為不變)。多平台每個平台跟著它的 profile 走。
  - (代碼審 r1 後改)playwright 改成 `regex_tail`:2026-10-15 再實跑 1.64.1,`-g` 比的是「專案名 檔名 describe 標題」整串(`-g login` 連 login.spec.ts 整檔、`-g chromium` 整個專案都選中),所以名字跳脫後錨在結尾,實跑確認只選中標題結尾是這個名字的測試;撞名也只數這種標題。代價:Playwright 綁 describe 標題會選到零支,測試工具印 No tests found 並回 1,判紅(擋推送)。
  - (代碼審 r2 後改)錨定式改成 `\s<跳脫後>(?:\s@\S+)*$`:Playwright 把 tag(含 describe 繼承來的)接在標題後面比,`(?:^|\s)…$` 會讓帶 tag 的測試必紅;前面用 `\s` 不用 `(?:^|\s)`——-g 比的字串以檔名開頭,標題前面總有空白,而且不用 `|`、`^`(Windows 的 cmd.exe 會當管線與跳脫)。撞名比之前拿掉標題尾巴的 @tag(r3 起改成用實際篩選式比,見下面 r3 那條);自己那支只由「種類是測試、文字相同」的第一個佔用(describe 同名不搶);describe 結尾加測試標題拼起來等於這個名字的也算撞名(只看一層)。標題頭尾有空白的不收(Playwright 不修剪標題,收成修剪過的名字會對不到)。以上 2026-10-15 在 order-web 副本實跑 1.64.1 確認。

  - 過濾探針 `_FILTER_PROBE_NAME` 是識別字,跳不跳脫一樣,照傳。
- **撞名靠事前的靜態檢查,不靠讀輸出**(r1 三席同報的根因):前一版說既有的「篩到幾支」判法會把選到兩支以上判成弱證據,這不成立——`_RAN_EVIDENCE` 只有 python 讀得出支數,node-jest 只讀得出有沒有跑過,node-vitest、playwright、dart 連這個都沒有;推送前合約測試閘也根本不呼叫那兩支。改成一條跟輸出格式無關的規則 `_name_filter_collisions(name, methods, name_filter)`:`regex` 與 `plain` 的平台,數這個平台的宣告名稱(測試標題與 describe 標題都算)裡有幾個「含有這個名稱」,`regex` 不分大小寫數(Jest 的 `-t` 與 Playwright 的 `-g` 不分大小寫,多數一點只會比較嚴),兩個以上就是撞名。撞名的那支:
  - (代碼審 r1 後改,三席同報)數的是「篩選選得到的全部標題」(`_raw_test_titles`:it.skip、帶 ${ 的樣板、.each、含逗號或方括號、沒還原的跳脫、超過 200 字的都算),不是只數可綁定的;判定收成一支 `_name_collision_reason`,推送前閘、規格閘、guard kill 共用。
  - (代碼審 r3 後改)撞名一律拿實際會用的篩選式比每個標題(regex_tail 用錨定式 search,不先剝 tag);describe 加測試的拼名只在同一支檔裡配對;標題索引每個平台建一次。頭尾空白不收只用在 Playwright。Windows 上 {method} 改用 list2cmdline。
  - 規格閘、相依回歸、修正關卡第 4 項(都走 `_spec_gate_judge_items`)判弱證據,原因寫「篩選會同時選中 N 支:…,換一個不會被別的標題包含的名字」;
  - 推送前合約測試閘(`_run_bound_tests` 之後)判成「證不出」(既有的 unproven,不是綠)。
  - 綁的是 describe 標題時(Jest、Vitest),底下的測試標題通常不含它,數出來是 1,照常跑整組;那是作者要的語意。Playwright 例外:錨在結尾後選到零支、判紅(見上一條)。
  - 跨標題的比對(Jest 拿「describe 標題 + 空白 + 測試標題」整串比,綁的名稱剛好橫跨兩段)數不到,寫進 Systems 節點當已知天花板。
- 零支:跳脫寫錯或名稱對不上時會選中零支。python、node-jest 由既有的「跑過的證據」判沒證明;node-vitest、playwright、dart 沒有證據樣式,靠測試工具自己找不到就回非零,或靠過濾探針(指令對不存在的名字也回 0 時,整個平台的指令被判成不可信)。實作時在示範專案(Vitest 與 Playwright)各實跑一次「跑 1 支」與「跑 0 支」,把輸出樣式補進 `_RAN_EVIDENCE`,能讀出支數就補 `count_re`;Dart 本機沒有環境,不補。

## 不做

- 名字含半形逗號或方括號的測試不收:那要新語法(引號包名),先前同類的新語法被否決過(要改解析、索引、doctor 好幾處,舊筆記也讀不懂)。這種測試改名,或條款寫 `[manual:]`。
- REVISIT:2026-12-15 數消費專案的筆記與測試檔:有沒有因為名稱含逗號或方括號而綁不上的,有 3 筆以上就另開計劃談引號包名。
- Maestro 的 `name:` 多字名不收:Maestro 跑測試是指定檔案、不靠名稱篩選,而 `\s*$` 行尾錨是為了擋部分擷取的假證據才加的,這次沒有它的真專案可驗。
- `guard scaffold` 不收句子名(它拿名字產程式碼和檔名)。
- 「只換測試綁定不算寫說明」的豁免不放寬到句子名:句子名剛好等於一句說明,就能把說明藏進綁定繞過寫回落點([[Projects/只換測試綁定不算寫說明_計劃]] 的撤除條件講的就是這個)。它的判法(`_NODEHOME_TAG_NAME_RE`)只收單一識別字,所以不只中文,英文句子名(`shows error (500)`)也不豁免:換一個句子名會被當成寫了說明,要寫進那支檔的家,方向是多擋,安全。
- 派工鏡頭備援段只列識別字名(餵給審查席的文字,句子名不轉印),句子名只算數字。
- Kotlin 反引號名經 Gradle `--tests` 跑的跳脫不在這次範圍(那是 Gradle 的萬用字元,不是正規式)。
- 不在 `CODE_SKIP_DIRS` 補 `.next`、`coverage`、`out`:那張表全程式共用,Playwright 補了檔名錨之後已經不掃建置產物。

## 回退

- 一個功能一個提交,還原那個提交即可,程式回到舊行為。**還原後的殘局**:新版寫下的句子名,在舊版下會判懸空或壞名,而且不只提醒,有三條路會擋:
  1. ★INVARIANT★ 合約行綁的句子名(`guard bind`、`guard settle` 或手寫):舊版推送前合約測試閘判紅,碰到那些節點的推送被擋;修正關卡第 3 項也不過。
  2. 代碼審處置帳裡 `test:<句子名>` 的證據:舊版判不在測試集合裡,擋推送。
