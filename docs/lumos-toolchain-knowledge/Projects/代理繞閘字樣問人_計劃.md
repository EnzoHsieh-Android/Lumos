# 代理繞閘字樣問人

> 白話:代理在推送被擋、使用者又在催的時候,會順手在指令上加 `--no-verify` 或用環境變數把檢查關掉,而 Lumos 目前在執行前完全不攔、不問人。這篇在 Claude Code 的「Bash 執行前」掛一道檢查:指令真的在對一個非拋棄式的 repo 做繞過(推送或提交帶 `--no-verify`、提交帶 `-n`、用 `-c core.hooksPath=` 或 `git config core.hooksPath` 改掉或拆掉掛鉤、在 git 或 lumos 前設 `LUMOS_SKIP_*`),就回「問人」,讓使用者按允許才執行。只是在引號裡或 heredoc 內容裡提到這些字樣(搜尋、說明文字),或在拋棄式實驗 repo 裡做實驗,一律放行不問;沒加引號的字面(例如 `echo git push --no-verify`)會被當成指令而問一次,這是刻意接受的誤問方向。來源是世界解總覽〈跨類優先順序〉第 7 名。

PRIOR-ART: 世界解 W09 spec-gates(代理邊界的 Bash 指令遇到 `--no-verify`、`git commit -n`、`core.hooksPath`、`HUSKY=0` 就問人)與 TDD Guard 同形;Claude Code 官方的 PreToolUse 掛鉤 `permissionDecision: "ask"`。本 repo 既有的工具前掛鉤(`scripts/hooks/claude/impact-hook.py`、`dispatch-lens-hook.py`)由 `scripts/merge-claude-settings.py` 註冊、讀 stdin 事件、印 JSON、用 `_hookevent.guard` 記「活著沒」;這支照同一套註冊、讀寫與記事件方式。**有意偏離「掛鉤是薄殼、邏輯進 lumos」**(`Projects/派工鏡頭注入_計劃` r3 裁定;`impact-hook.py` 的檔案過濾與 `memory-sweep.py` 是既有的厚掛鉤先例):這支每條 Bash 都會被叫,叫一次 lumos 主程式的啟動成本遠大於判斷本身,所以分類邏輯放在掛鉤內,以 `lumos decision-add` 記進本篇 decisions。與總覽第 7 名原句的差異:只做 Claude Code(Codex 另見 REVISIT);不新增任何寫帳入口,存活事件照既有界線只記「活著沒」、不記問了幾次(`_hookevent.py` 檔頭與 `Projects/enforcement可觀測性_計劃` 明定不記成效),事後量測拿 Claude 事件帳重跑同一支分類函式;不列 `LUMOS_STOP_BLOCK_OFF` 與 `HUSKY=0`(理由見〈範圍〉)。自寫一套切段器、不重用收工圖譜同步檢查那支掛鉤裡的 `_segment_command` 加 `shlex.split`:那套不追蹤引號、heredoc、`cd` 與子殼層(作者自註「Quote-aware 不嚴格」),而且兩支掛鉤檔名帶連字號、各自獨立安裝,不能互相 import(代碼審 r2 架構對齊席要求寫明)。審查席的推送已由 `mods/claude/lumos-guard` 擋下,那支外掛依 `Projects/審查席唯讀隔離_計劃` d4 不跑外部指令、只對審查席生效,所以不放進它。對照該計劃 d3、d4(d4 取代 d3 的事後查部分,保留審查席 Bash 粗擋、不逐詞解析 git 指令、寧可誤擋):那條管審查席、動作是擋,誤擋只讓審查席少做一個實驗;這條管主會談、動作是問人,誤問的代價是把使用者訓練成反射按允許(〈量測〉照字面比對一週問一百多次),所以這裡選逐段解析、寧可漏問——兩條不衝突。這個取捨同樣以 `lumos decision-add` 記進本篇 decisions。

## 範圍

- 只做 Claude Code 的 Bash 工具前事件;Codex 適配另見 REVISIT,安裝 Codex 時這條註冊要跳過(見〈做法〉)。
- 只看指令文字;以下攔不到,這篇防「代理順手繞」、不防有心改寫(spec-gates 與 TDD Guard 都同樣自承):變數拼接(`F=--no-verify; git push $F`)、shell 別名與函式、自寫腳本裡藏繞過、`bash -c "…"`/`sh -c`/`env -S` 包起來的字串、`eval`、餵給 shell 執行的 heredoc(`bash <<EOF`、`sh <<EOF`、`ssh 主機 <<EOF` 的內文照字面看、不當指令)、xargs 組出來的指令。另外這些也攔不到、在這裡承認(代碼審 r1 通才席):直接改 `.git/config` 檔(`sed -i`、`>>` 寫入)、`git config --edit`;用 Edit、Write 等不是 Bash 的工具改 `.git/config`、`scripts/hooks/` 的閘或 `~/.claude/settings.json`(這支只掛 Bash;`scripts/hooks/` 的閘在錨點名單裡,事後 `anchor verify` 抓得到);不經 `git push` 的送出(`git send-pack`、`git commit-tree` 加 `git update-ref`、`git fast-import`);git 自己的別名(`alias.p='push --no-verify'`);用 Bash 直接改、刪 `scripts/hooks/` 的閘檔或拿掉執行權限(同樣在錨點名單裡,事後 `anchor verify` 抓得到);`set -a` 之後的一般賦值變成匯出(代碼審 r4 通才席);`GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM` 指到別的設定檔(repo 層的 `core.hooksPath` 會蓋過,r4 資安席實測閘照跑)。
- 同一條指令裡改寫判斷當下已存在的路徑——把實驗目錄刪掉或搬走再換成指回真 repo 的連結、在已存在的暫存目錄裡寫 `.git` 檔或連結指回真 repo——攔不到:掛鉤只能看到判斷當下的檔案系統,這種寫法要刻意構造路徑,屬「有心改寫」(代碼審 r3 資安席、通才席;決策 d4 修正 d3 對「封閉」的說法)。
- 刻意不攔:`merge`、`rebase`、`am`、`cherry-pick`、`pull` 帶 `--no-verify` 或 `-c core.hooksPath=` 只影響 pre-merge-commit、commit-msg、pre-rebase 這類本 repo 沒裝的掛鉤,不影響 Lumos 的提交前閘與推送前閘(`scripts/hooks/` 只有提交前、推送前、提交後三支);`LUMOS_SKIP_*` 只有推送前閘與 lumos 指令在讀,接在 merge、cherry-pick 等前面不關任何閘。安裝時這支也會被複製到 Codex 的掛鉤目錄(兩邊共用同一份複製名單),但 Codex 不註冊它、不會被執行。
- `LUMOS_STOP_BLOCK_OFF` 不列:它關的是 Claude Code 自己的收工掛鉤,在 Bash 指令裡 export 只影響那條指令的子程序,關不到掛鉤。
- `HUSKY=0` 不列:它是 W09 針對 husky 的通用字樣,Lumos 的推送前閘與提交前閘走 `core.hooksPath` 指向的 `scripts/hooks/`,`HUSKY=0` 關不到;本 repo 不用 husky,列了只會在消費專案對無關的閘問人。
- 無人值守的執行(`claude -p`、每天的自主迭代迴圈)遇到命中時沒有人能按允許,指令不會執行、代理收到理由——這正是要的效果(無人看顧時不該繞閘),不另開例外。

## 做法

- 新增 `scripts/hooks/claude/bypass-ask-hook.py`。
- **讀輸入與預篩(在 `_hookevent.guard` 之外)**:
  - 從 stdin 讀一次原始文字(位元組以 UTF-8 解碼、錯字元替換),之後傳給 `main`,不再讀第二次;進入點是 `entry(stdin 位元組)`,進場就開始算逾時預算。
  - 預篩看解碼後的指令本身(先解析 JSON 取 `tool_input.command`;解析不了才看原始文字,讓壞事件照樣進記失敗的路):換行與 Tab 在原始 JSON 裡是 `\n`、`\t`,直接看原文會把頂在續行開頭的 `-n` 擋掉(代碼審 r1)。先拿掉引號與反斜線(`--no-ver''ify`、`-"n"` 這種拆字也認得),再不分大小寫找 `--no-veri`、`hookspath`、`lumos_skip_` 任一個;或同時有 `git`、`commit` 與一個以單一 `-` 開頭、含 `n` 的短旗標。都沒有就直接結束:不輸出、**不記任何事件、不跑任何子程序**。絕大多數 Bash 呼叫走這條。
  - 預篩自己包一層 try/except,任何例外都直接結束、不輸出(放行;這一層不記事件,因為記事件要先跑 git 子程序)。這個入口形狀跟鄰居掛鉤不同(鄰居在 `main` 裡讀 stdin),原因就是預篩要在 `guard` 之外,程式註解寫明。
  - 理由:`guard` 每次都會跑一次 `git rev-parse` 並寫一筆存活事件,存活事件檔滿 512KB 會修剪成最後 2000 行、而且總大小在上限一半以內;每條 Bash 都記會一天灌數千筆,把其他掛鉤的存活紀錄擠出去,讓 `lumos enforcement` 對它們判過期。
- **過了預篩**才進 `guard("pretooluse-bypass-ask-hook", __file__, main, swallow=True)`:
  - 事件名跟 `enforcement_status` 的列名同字串,鄰居都這樣(`_hook_recent_ok` 拿列名比對事件的 hook 欄)。
  - `swallow=True` 讓任何例外都放行(這道是問人層,不是安全邊界),例外由 `guard` 記成 error。`main` 內部若自己吞了例外,要 `mark("error", …)`,不能記成 ok。
  - 存活事件不加任何「問了」的備註(只記活著沒,見 PRIOR-ART)。
- **逾時預算**:照抄鄰居掛鉤從 `_BUDGET_RATIO` 到 `return max(_BUDGET_FLOOR,…)` 的逐字複本(有測試要求各份一模一樣),吃安裝時附的 `--budget 5`;下面查遠端、查工作樹的 git 子程序用 `_inner_budget()` 當逾時,逾時或失敗當「判不出」處理。一次判斷最多跑 4 個 git 子程序(`MAX_GIT_CALLS`),同樣的查詢只跑一次;跑滿之後一律當「查不到」(=不豁免、照問)。任何一次逾時或起不來、或共用預算已經用到下限(例如找 repo 根就花掉大半,代碼審 r4 併發資源席),這次判斷就不再跑 git(git 卡住時連續等滿會把整支推過 5 秒,代碼審 r2 實測 6.5 秒);預算從進場就開始算。只用共用的 `_inner_budget`,不另寫一套預算算法(代碼審 r3 架構對齊席)。沒有上限時,幾百段都要查 git 的指令會超過 5 秒外層預算、被砍掉而放行(代碼審 r1 實測 262 段約 7 秒)。
- **長度上限**:指令超過 2 萬字就不做結構分類,直接走下面的「字面判」。2 萬字內各種最壞形狀(深層 `$(`、大量引號、未閉合 heredoc、ANSI 引號、反斜線、大量 cd 與 mkdir)實測都在 0.11 秒、1MB 內(2026-10-14)。
- **一趟前處理**(在切段之前,自己逐字掃、追蹤引號狀態;`$(` 裡重開一層引號狀態——訊息用 `"$(cat <<'EOF' … don't … EOF)"` 寫時,內文的撇號不能算進外層,代碼審 r1):

  - 引號遮罩:引號裡的 `();|&<>`、換行、`#`、反引號先換成私用區字元,切完詞再還原——引號裡的括號、分號不會被當成分段;切詞當下就標好哪些詞是分隔符。(更正 2026-10-15:反引號只在單引號裡該遮;雙引號裡的反引號 bash 照樣執行,改成跟 `$(` 一樣開一層反引號層、照引號外規則解析,收層後抽出來另外判,見家筆記的事故行)
  - ANSI 引號 `$'…'` 解出內容(`\n`、`\'`、`\xHH`、`\uHHHH`、`\UHHHHHHHH`、八進位 `\NNN`、`\cX`)後當成引號裡的字(`git commit -$'n'` 就是 `-n`);`$"…"`(語系翻譯字串)照雙引號看;被反斜線跳脫的字元一律當普通字遮罩(跳脫的反引號、分號都不是結構)。
  - 續行:引號外與雙引號裡的「反斜線加換行」照 bash 直接拿掉、前後接起來(`--no-\⏎verify` 就是 `--no-verify`),在這一趟裡做——另開一趟只追引號的話,註解或 heredoc 裡的撇號會讓它判錯(代碼審 r2)。
  - ANSI 解碼原地比對、不切片(線性時間);`\c` 後面緊接結尾單引號時照字面留下,不吃掉那個引號(代碼審 r4 邊界輸入席:吃掉會讓引號一路開到指令尾、後面全被當成字串)。
  - 單引號裡與被跳脫的 `$` 是字面,不展開變數(`cd '$D'` 進的是名叫 `$D` 的目錄,代碼審 r4 正確性席);雙引號裡的 `"$D"` 照常展開。
  - 導向前的檔案代號(`2>` 的 2、`{fd}>` 的 {fd})在前處理就標記,切詞後連同導向剔除——不靠「是不是數字」猜(`git commit -m 1 >x -n` 的 1 是 `-m` 的值,代碼審 r3 正確性席);`)>`、`;>` 這種黏在一起的標點拆成分隔與導向。
  - 預篩與「切不動時的字面判」共用同一個字樣比對;預篩比對原文加上前處理後的文字,超過 2 萬字只看原文(代碼審 r4 併發資源席:超長指令的前處理撐破預算);字樣另認拆掉或改名 `core` 區段與引入設定檔(代碼審 r4 正確性席:分類器會問的 `--remove-section core` 原本過不了預篩)。
  - 預篩用同一套前處理(接續行、解 ANSI 引號)後的文字再比字樣,分類器認得的寫法不會在入口就被放行(代碼審 r3 邊界輸入席、規格符合席)。
  - 分隔符與導向在切詞當下看原始字元認定(`_Sep`、`_Redir`),所以指令本身就含私用區字元也只會還原成普通字,不會變成結構。
  - heredoc:
  - 只認不在引號裡的 `<<WORD`、`<<-WORD`、`<<'WORD'`、`<<"WORD"`;`<<<`(here-string)、`$((…<<…))` 算式與指令位置的 `(( 1<<EOF ))` 算術命令不算(後者被當 heredoc 會把下一行的真指令當內文剝掉,代碼審 r4 資安席)。
  - 同一行有多個 heredoc,依出現順序在下一個換行之後逐一配對內文。
  - 結束字必須獨佔一行;`<<-` 允許前置 Tab。
  - 找不到結束字就不剝(內文留著當指令看,寧可多問),而且之後不再找(避免每個換行都重掃到尾、變成平方時間)。
  - 剝掉的是內文與結束字那一行,heredoc 運算子本身留著。
- **切詞與切段**:
  - 續行已在前處理接好。
  - 指令替換 `$(…)`、反引號、程序替換 `<(…)`、`>(…)` 換成判不出的佔位詞,裡面的指令抽出來另外判(一趟掃完、巢狀也一次拆開;逐層重掃在三千層巢狀下要好幾秒),目錄當「判不出」、不給拋棄式豁免;`$((…))` 算式只換掉。括號配對一次掃完(線性時間;代碼審 r2 量到逐個找配對在大量沒配對的 `$(` 下要 3 秒),找不到配對的保留原樣,相鄰的替換併成一個佔位詞。(代碼審 r4 資安席、邊界輸入席:程序替換原本被當成導向,吃掉後面的 `git`;指令替換原本承認攔不到,改成抽出來判。)
  - 空字串參數(`''`、`""`)是一般的詞,不是標點(代碼審 r4 合約圖譜席、通才席:原本讓切詞丟例外、整條退回字面判)。
  - 用 `shlex`(posix、`punctuation_chars`、`whitespace_split=True`、關掉註解),並把換行從空白字元裡拿掉、改當標點,讓換行成為分隔(引號裡的換行已遮罩,留在詞裡)。
  - 由標點字元組成的詞(`;`、`&&`、`||`、`|`、`&`、`);`、`(`、`)` 等)一律當分段界線;括號另用來追蹤子殼層範圍。
- **找 git 指令**:不看「段首程式名」,而是段裡任何一個詞的檔名部分等於 `git`(引號裡的整串不會是單獨的 `git` 詞),就從那裡開始解析一條 git 指令到段尾;直接叫子指令執行檔(`git-commit`、`git-push`、`git-config`、`git-remote`)也算,沒有全域選項(代碼審 r4 資安席)。所以 `env`、`timeout 60`、`time`、`nohup`、`command`、`then`、`do`、`!`、`{` 這類前綴不必列舉。
  - 全域選項:子指令之前所有以 `-` 開頭的詞都跳過;`-c`、`-C`、`--git-dir`、`--work-tree`、`--namespace`、`--super-prefix`、`--config-env`、`--attr-source` 分開寫時再多吃一個詞;黏著的 `--git-dir=X` 不多吃。記下 `-C` 的目錄(可多次,後者相對前者)、`-c` 與 `--config-env` 的鍵,以及有沒有 `--git-dir`、`--work-tree`。
  - 判長選項 `--no-verify`:詞以 `--no-veri` 開頭、而且是 `--no-verify` 的前綴(git 接受長選項的唯一縮寫)。只看選項位置上的詞:吃值選項的值(`-m --no-verify` 的 --no-verify 是訊息)、`--` 之後的詞都不算(代碼審 r4 合約圖譜席)。吃值的長選項也認縮寫:`--push-o` 就是 `--push-option`、`--rep` 就是 `--repo`(代碼審 r4 資安席:縮寫的值曾被當成推送目的地)。
- **命中規則**(都在「非拋棄式」時才算,拋棄式見下一條):
  - 子指令是 commit 或 push,後面有 `--no-verify`(含縮寫)→ 理由代號 `no-verify`。Lumos 的閘只有提交前與推送前兩道;`merge`、`rebase`、`am`、`cherry-pick`、`pull` 跳過的是本 repo 沒裝的掛鉤,不問(代碼審 r2 合約圖譜席指出〈範圍〉與命中規則對 merge 互相矛盾,收成這一句)。
  - 子指令是 commit,短旗標組逐字看,遇到吃值的旗標(`-m -F -C -c -t`,值可黏著也可在下一個詞;`-S -u` 的值只會黏著)就停,停之前出現 `n` → `commit-n`。`-n`、`-qn`、`-m x -n` 命中;`-mnote`、`-m -n`(`-n` 是訊息)、`-F -n` 不命中。
  - 會換掉掛鉤目錄的設定鍵是 `core.hooksPath`,以及引入別的設定檔的 `include.path`、`includeIf.*.path`(代碼審 r4 資安席:引入的檔可以帶 `hooksPath`,指令字面不含這個字)。全域 `-c core.hooksPath=…` 或 `--config-env core.hooksPath=…`(鍵不分大小寫,引入設定檔的鍵同樣),或同段在 git 之前設了 `GIT_CONFIG_KEY_<n>=core.hooksPath`、`GIT_CONFIG_PARAMETERS` 帶 `core.hooksPath`(含先前 export 的),而且子指令是 commit 或 push → `c-hookspath`(這幾種是 git 原生的同義寫法,代碼審 r1)。
  - 子指令是 `config`,鍵是上面那幾個(不分大小寫),而且是寫入:帶值(含空字串值)、或帶 `--unset`/`--unset-all`/`--replace-all`/`--add` → `config-hookspath`。新語法 `git config set core.hooksPath …`、`git config unset core.hooksPath`,以及 `--remove-section core`、`--rename-section core …`(整段 core 拆掉或改名,hooksPath 跟著沒了)同樣命中。導向(`>`、`2>&1`、`&>`、`<` 連同目標檔與前面的檔案代號數字)在解析參數前先剔除——切詞當下就認定哪些詞是導向,引號裡的 `>` 不算(代碼審 r2:推送的導向目標曾被當成遠端、讀值加 `2>/dev/null` 曾被當成寫入)。`--get`、`--get-all`、`--list`、只給鍵不給值(讀)不命中。commit 的長選項 `--message`、`--file` 等會吃下一個詞當值,`--` 之後不再看旗標。
  - `LUMOS_SKIP_*=`(含 `+=`)以「指令前綴」身分出現——段首的賦值,或 `env` 後面的賦值(跳過 `env` 的選項,以及 `-u 名稱`、`-C 目錄`、`-S 字串` 這類選項的值,代碼審 r4 正確性席)——而且這一段的 git commit/push 或 lumos 指令在它後面 → `lumos-skip`。當成一般參數出現的不算(`grep -n "LUMOS_SKIP_X=1" scripts/lumos` 是搜尋,代碼審 r2 通才席)。lumos 指令跟 git 一樣在段裡任何位置都認(`timeout`、`sudo`、`env -i …` 等前綴不必列舉):段裡有檔名為 `lumos` 的詞(lumos 本身,或 `python3 scripts/lumos`、`bash scripts/lumos` 的腳本參數都是這個詞;`cat scripts/lumos` 也會算進來,刻意寧可多問,不列舉包裝程式——代碼審 r4 規格符合席指出這跟 [S2] 的字面衝突,已把 [S2] 改成同一個說法)。`LUMOS_SKIP_*` 有幾個是 lumos 自己的閘在讀(修正關卡、筆記內容審、新增告警等),直接跑 lumos 指令時設它一樣會關掉閘。
  - `export LUMOS_SKIP_*=`、先賦值再 `export 名稱`、`declare -x`/`typeset -x` 之後,同一條指令後面有上一條所說的 git 或 lumos 指令 → `lumos-skip`;`export -n`(取消匯出)不算。
- **拋棄式判定**(只決定命中算不算,不決定命中與否;★只認判斷當下就存在、而且用 git 確認過的事實★,同一條指令裡的推論一概不認——代碼審 r1、r2 兩輪都在「同指令建的目錄」「mktemp」「同指令加的遠端」這類推論上找到繞法(`mktemp -p 真repo`、在建好的目錄底下 `ln -s` 回真 repo、`remote set-url --add` 追加真遠端),換形狀見 d3):
  - 先定每段的「生效目錄」:有 `git -C` 就以它為準(多個依序相對解析);否則用目前追蹤到的 `cd` 目錄;一個都沒有就用事件的 `cwd`。
  - 設過 `GIT_DIR`、`GIT_WORK_TREE`、`GIT_COMMON_DIR`(段首賦值、`env`、`export`、`declare -x`、先賦值再 `export 名稱` 都算;只認指令前綴位置與 `env` 後面的 `名稱=` 賦值,`grep GIT_DIR`、`echo GIT_DIR=x`、`-m "GIT_DIR=x"` 都不算,代碼審 r4 邊界輸入席),或任何 git 帶 `--git-dir`、`--work-tree`,在那之後的命中一律不給豁免——commit、config、push 都一樣(動的不一定是生效目錄那個 repo)。
  - 路徑不做純文字化簡:`連結/..` 在 `git -C` 與作業系統是先進連結再往上一層,文字化簡會走到別處(代碼審 r3 資安席);存在與否、在不在暫存根底下,一律對實際路徑(`realpath`)判。
  - 換行跟 `;` 一樣是結束 `&&` 鏈的分隔;但 `&&`、`||` 後面接換行仍是同一條鏈(`false &&⏎cd X⏎git commit -n` 的 cd 是條件式,代碼審 r4 正確性席)。`cd` 追蹤:依序處理,後一個覆蓋前一個;相對路徑接在目前的追蹤目錄之後;括號子殼層裡的 `cd` 在右括號後恢復原值;管線(`|`、`|&`)兩側與背景 `&` 的段落在子殼層跑,裡面的 `cd` 不影響後面;接在 `&&` 或 `||` 後面的條件式 `cd`,只有後面緊接 `&&` 時在那條 `&&` 鏈裡算數,鏈一斷就變「判不出」;`cd` 不帶參數、`cd ~…`、`cd -`、`pushd`/`popd`、目標含指令替換、反引號或展開不了的變數 → 目前目錄變成「判不出」。
  - 變數展開只認同一條指令裡先出現的 `VAR=值`,展開後超過 4096 字就判不出(`A=$A$A` 連續翻倍會指數膨脹,代碼審 r3 實測 250 字的指令吃掉 14GB);指令替換(含 `$(mktemp …)`)一律判不出。
  - 條件式與子殼層的 `cd` 一律保守:`||` 左右兩側的 `cd`、`if`/`while`/`until`/`!` 條件裡的 `cd` 都變成判不出;大括號群組放在管線或背景裡時(`{ cd X; } | cat`),群組裡的 `cd` 不影響後面;`if`/`for`/`while`/`until`/`case`/`select` 的本體或分支裡、大括號群組(可能是沒被呼叫的函式本體)裡改過目錄的,結構結束後目錄變成判不出——結構裡面照常追蹤(代碼審 r4 正確性席、邊界輸入席)。
  - 生效目錄判不出,或事件的 `cwd` 缺欄、不是字串 → 非拋棄式。
  - 暫存根由 `_temp_roots()` 給出:`/tmp`、`/private/tmp`、`/var/tmp`、`/private/var/tmp`、`/var/folders`、`/private/var/folders`(與 `mods/claude/lumos-guard` 的暫存根取聯集),加上 `tempfile.gettempdir()`(一律加,與 `scripts/lumos` 判暫存目錄的做法一致);比對前兩邊都 `os.path.realpath`(會解開 `..` 與符號連結,所以指回真 repo 的連結不算)。
  - commit、只寫 repo 本身的 `config`:生效目錄要在判斷當下**已存在**、在暫存根底下,跑 `git -C 目錄 rev-parse --git-common-dir` 得到的共用 git 目錄也在暫存根底下(暫存目錄可能是真 repo 的工作樹),而且沒有任何網路遠端(`remote.*.url`、`remote.*.pushurl` 都是明確的本機路徑;暫存目錄裡的真工作副本不算實驗 repo,代碼審 r3 通才席)才算拋棄式;git 失敗時只有錯誤訊息明說「不是 git repository」才算(不在任何 repo 裡,之後建的只會是新的),其他失敗(擁有者不同被拒、逾時、git 跑不起來)都不算。
  - `config` 帶 `--global`、`--system`、`--file`/`-f`、`--blob` 時寫的不是生效目錄那個 repo(使用者層設定會關掉所有 repo 的閘)→ 不給豁免。
  - push:推送目標是明確的本機路徑(`/`、`./`、`../`、`file://` 開頭)而且判斷當下存在、落在暫存根底下 → 拋棄式;是遠端名稱時,生效目錄要已存在且在暫存根底下,跑 `git -C 目錄 remote get-url --push 名稱` 查到的**推送**位址是明確的本機路徑而且存在、落在暫存根底下才算(`host:path` 這種沒有斜線開頭的一律當網路位址)。同一條指令前面動過遠端設定(`git remote` 會改位址的子指令 `add`/`rename`/`remove`/`rm`/`set-url`——`prune`、`update`、`-vv` 不算,代碼審 r4 規格符合席——、`git config` 寫入 `remote.*`、`url.*` 的鍵——讀值不算),或這次推送本身用 `-c remote.*`/`-c url.*`、`GIT_CONFIG_KEY_n=remote.*`/`url.*`(含先前 export 的)改了位址時不給豁免——判斷當下查到的是改之前的位址。推送帶 `--repo` 時目的地是 `--repo` 的值,位置參數只是 refspec。沒寫遠端、查不到都不算。
  - 其他命中類型(`lumos-skip` 接 lumos 指令)不給拋棄式豁免,一律照問:lumos 指令讀的是 lumos 自己的閘,不看所在目錄。
  - 代價(2026-10-14 事件帳重放):一週約 6 次「同一條指令裡建實驗 repo 再加 `--no-verify` 提交或改掛鉤設定」從放行變成問人(審查席做實驗時),一天不到 1 次;換來的是這一整類推論繞法消失。
- **字面判**(切不動、或超過長度上限):`shlex` 失敗(引號不成對等)或指令超過 2 萬字時,含 `git` 或 `lumos`,而且有 `--no-veri`、`hookspath`、`lumos_skip_` 任一個、或有 `commit` 加含 `n` 的短旗標,就算命中(理由代號 `literal`),其他放行。
- **命中**:印 `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "ask", "permissionDecisionReason": "<三段式>"}}`。三段式:發生什麼(這條指令會跳過 Lumos 的閘:<命中理由的固定說明>)、為什麼在意(閘被跳過就沒人檢查這次推送或提交,代理順手繞過是已知模式)、怎麼做(確定要跳過就按允許;不確定就拒絕,讓代理改成修好被擋的原因)。理由只用理由代號對應的固定文字,不嵌入指令內容。
- 決策邏輯放在 `decide(event) -> dict | None`(回要印的 JSON 物件或 None),分類放在 `bypass_reasons(command, cwd) -> list`;`main` 只負責解析已讀的文字、叫 `decide`、印出——測試直接呼叫這兩支。
- `scripts/merge-claude-settings.py`:

- `scripts/lumos`:

- 新 Systems 節點 `Systems/代理繞閘問人` 管這支掛鉤檔(每支檔有家,與 `Systems/改檔前推播`、`Systems/記憶過期清掃` 一支掛鉤一篇的慣例同);`scripts/lumos` 與 `merge-claude-settings.py` 的改動寫進 [[Systems/lumos-cli-lifecycle]]。

## 回退

- 要整支撤掉:同時做三件事(另把 `_VENDORED_TREE_FILES`、`ANCHOR_FILES` 的那一行與 `t_bypass_ask_*` 測試一併拿掉、`lumos anchor approve` 重簽)——拿掉 `merge-claude-settings.py` 那條 Bash matcher、把檔名從 `scripts/lumos` 的 `_GLOBAL_CLAUDE_HOOKS` 移到 `_RETIRED_STUB_CLAUDE_HOOKS`(相容期換成空殼,下一版再移到 `_RETIRED_CLAUDE_HOOKS` 真刪)、從 `enforcement_status` 列舉拿掉那一列,再重跑安裝。只拿掉 matcher 不夠:合併器只新增、不移除已寫進 settings.json 的條目,檔案還在就不算懸空、不會被剪,每次命中仍會問(代碼審 r1 合約圖譜席實測)。中間狀態(代碼審 r2 合約圖譜席隔離 HOME 實測):移到空殼名單那一版重跑安裝後,掛鉤檔換成直接放行的空殼、不再問,但 settings.json 裡的註冊還在;要到下一版移到真刪名單,檔案刪掉、註冊變懸空,才被 `_prune_dangling` 剪掉。
- 誤問太多:先調分類函式(加拋棄式目錄、收窄命中形狀),不必整條拿掉。
- 不可逆的部分:無。掛鉤只回「問人」、不改指令、不寫治理帳(只在過了預篩時寫 `_hookevent` 的存活事件)。

## 實務隱患

- 每條 Bash 指令都多一次 Python 啟動(約幾十毫秒):過去「每次 Bash 都觸發」的掛鉤被撤,是因為每次付高成本且核心邏輯跑不到;這支預篩在掛鉤內、`guard` 之外完成,不叫主程式、不跑 git 子程序,命中預篩才做結構分類與記事件。
- 存活事件檔共用:只有過了預篩才寫,量到一週約 375 到 408 次(各輪實跑),修剪後保留最多 2000 行、總大小在上限一半以內,不會擠掉其他掛鉤的紀錄。
- 逾時與壞掉都放行:Claude Code 對逾時的掛鉤照常放行工具呼叫,逾時時 Python 被砍、`guard` 寫不出事件,所以逾時不留痕;預篩階段的例外放行且不記事件(記事件要先跑 git);過了預篩之後丟例外會記 error,在 `lumos gov --stats` 的掛鉤段看得到(`lumos enforcement` 那張表只認成功事件)。不採用官方的「失敗即擋」選項:掛鉤自己壞掉會讓每條 Bash 都卡住,跟「問人層不是安全邊界」相反。長度上限與三種最壞形狀的計時測試讓逾時不容易發生。
- 誤問:暫存目錄的豁免只給「確定不是真 repo」的情形,其餘照問;推送與真工作樹的設定改動照問。新的寫法可能誤問或漏問,RETIRE-IF 與第一條 REVISIT 盯著。
- 子程序:只有在命中而且生效目錄落在暫存根底下時才跑 git(查共用目錄或遠端位址),用內部預算當逾時,失敗當「非拋棄式」。
- 問人只擋「順手繞」:有心改寫攔不到(見〈範圍〉)。
- 已排除:正式環境不可逆:掛鉤只回「問人」、不改指令也不寫治理帳,拿掉註冊即完全還原(見〈回退〉)
- 已排除:金流:不碰任何金流或扣款相關程式
- 已排除:對外送出:只讀本機 Bash 事件,不送任何東西到外部服務
- 自我治理:這是守衛本身;掛鉤壞掉時放行(問人層不是安全邊界),過了預篩之後丟例外會記 error 事件。
