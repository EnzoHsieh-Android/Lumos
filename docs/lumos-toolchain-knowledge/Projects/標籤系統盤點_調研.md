# 標籤系統盤點（2026-09-14）

> 白話：把「一篇節點身上掛了哪些標」整個攤開數一遍，然後一個一個問「這個標到底有誰在讀」。答案是：真的被程式吃進去、會改變行為的只有三個；其餘不是欄位的影子，就是印給 AI 看的裝飾。

本篇是**盤點與對照**，不是改動計劃。要動哪一項由 Enzo 裁，裁完再開實作計劃。

## 二、七個發現

### F1 三分之二的標籤行是欄位的影子，而且只有一半有守衛

`type/` 與 `status/` 加起來 983 行，佔全部標籤行的 63%，內容完全等於 frontmatter 的 `type:` / `status:` 純量欄。這是 2026-07-20 就記過的反正規化。

當時補的三樣東西只蓋住 status 那半：改狀態時會順手同步標籤、寫完 lint 會驗、doctor 有一道專門的漂移檢查。type 那半一樣都沒有。

實測（臨時庫，不動正式圖譜）：建一篇 `type: system` 且掛 `type/system`，用 `set` 改成 project 之後，標籤仍停在 `type/system`；lint 回「0 問題」，doctor 也沒唸。本庫現在零漂移，是因為沒人改過 type，不是因為有東西擋著。

### F2 scope 進了搜尋排序，跟白紙黑字的邊界相反

[[Projects/工具分類_計劃]] 明寫：那九個值只當索引軸，不進 search 與 impact 排序。

但排序用的欄位權重表把 tags 欄設在 1.5（標題 4.0、別名 3.5、摘要 2.5、正文 1.0），而 tags 欄的內容就是把整串標籤接起來去斷詞——`scope/evals` 會斷成 evals。

實跑 `search evals`：前十筆有七筆的命中行就是 frontmatter 那一行 `- scope/evals`，正文與標題一個字都沒提到。所以 scope 不但進了排序，還是那些節點浮上來的唯一理由。

這不見得是壞事（同類節點一起浮上來可能有用），但**現在的狀況是文件說沒有、實際上有**，兩邊必須有一邊改。

### F3 `flag/` 家族在程式裡一個消費點都沒有

全 repo 搜過：除了測試檔跟 skill 文件的說明表，沒有任何程式讀 `flag/`。它唯一的效果是進場時 `context` 頭部會把它印出來給 AI 看——這算一種作用，但沒有值域檢查（`priority/` 和 `risk/` 都有），所以打錯字不會有人講。

skill 文件列了四個「已知有效」的值，本庫只用到兩個。5 篇在用。

### F4 `priority/` 只活在 Issues，而且只蓋四分之一

58 篇 Issues 裡只有 15 篇掛 priority，其餘型別零。消費方式跟 flag 一樣：印出來、可以篩，沒有任何閘或排序吃它。

換句話說，「這件事多急」目前不是靠標籤在管的——自主迴圈的待辦帳自己有價值分與衰減，那才是真的在排序。

### F5 摘要符號表跟紀律文件互相不知道對方存在

詞彙表九個符號。本庫實際用七個，AUTH 與 CORE 零次——這兩個是給消費專案用的（授權、核心規則指標），本庫沒有那類內容，不算廢值。

真正的缺口在另一邊：CLAUDE.md 要求設計筆記寫 `PRIOR-ART:`（124 次在用），它不在詞彙表裡，只是因為含連字號，剛好躲過抓錯字的正則，所以沒被唸。而紀律鐵則四要求的 `REVISIT:`（96 次）也不在表裡，**寫進摘要就會被 lint 當成打錯字**（已實測）。

現在沒爆是因為 141 行 REVISIT 全落在正文。但鐵則寫的是「緊鄰原句」，只要原句在摘要，照做的人就會被唸。

### F6 risk 的程式註解過期三週

程式裡寫「risk/ 標節點保送固定席」——那是 2026-08-05 的事實。skill 文件記的才是現在：2026-08-24 起 RISK 值降入「守衛面參考」道、上限三筆，固定席只認 INVARIANT／IRREVERSIBLE 與事故。同一支檔裡另一段註解也寫了降級的理由（樞紐筆記搭便車，是噪音主力）。兩段互相打架，先讀到哪段就信哪段。

### F7 三筆小殘留

- 4 篇掛裸 `prior-art` 標籤（沒有值，不合「家族／值」格式，零消費）。
- 1 篇還掛已停用的 `area/`，停用滿 40 天，lint 只出 warning 不擋。
- status 值域違規 0 筆——2026-08-06 那道「舊帳不回溯」的赦免線，在本庫目前沒赦免到任何東西（消費專案不同，那邊是它存在的理由）。

## 三、業界怎麼做

| 對照對象 | 他們的做法 | 對本圖譜的意義 |
|---|---|---|
| Kubernetes recommended labels | 一小組固定前綴標籤，採用理由明寫是「讓工具互通」；組織自訂的另開前綴，不跟標準集混用 | 家族前綴制我們已經一樣。差別是對方那組每個標籤都有真消費者，我們有兩個沒有 |
| Obsidian（properties vs tags） | 官方立場：properties 查詢、tags 分類；且 frontmatter 裡的 tags 與行內 tag 功能等價 | 等於官方也承認兩邊寫是重複。我們選擇重複寫，代價就是 F1 那個同步器加兩道閘 |
| ADR / MADR | status 與 supersede 是公認必要欄；翻案用新檔加改舊檔 status | 與 `decision-supersede` 同構，這塊我們走在正路上 |
| docs-as-code lint 工具 | 用 JSON Schema 驗 frontmatter，值域宣告在 schema 檔而不是寫死在程式 | 我們只有 scope 走宣告制，其餘 enum 寫死。要不要全面宣告制是可選項 |
| 知識管理界共識 | taxonomy 沒人養 6–12 個月就等於沒有；審 taxonomy 要連使用率一起審 | 本篇就是第一次審使用率。審出來的結果是有兩個家族在空轉 |
| Zettelkasten 社群 | tags 不 scale，真正承重的是連結與 structure note | 與本圖譜的 A3 消融結論（高連結節點是導覽樞紐不是答案）是同一教訓的兩面：分類軸不該進排序 |

## 四、可動的選項（待 Enzo 裁）

按「省下的東西 ÷ 動它的代價」排：

1. **[O1] 補齊 type 的漂移守衛**，跟 status 對稱。小、便宜、補的是實測存在的洞。
2. **[O2] 裁定 scope 到底進不進排序**：要嘛改文件承認它有進（並補一組金標量它是幫忙還是噪音），要嘛把 scope 值排除在 tags 欄之外。現在這樣是文件與程式不一致。
3. **[O3] `flag/` 與 `priority/` 二選一**：給它們值域檢查與一個真消費者，或者退場（照 `area/` 的凍結模式）。
4. **[O4] 把 PRIOR-ART 與 REVISIT 收進符號詞彙表**，或明寫「摘要符號」與「正文標記」是兩套詞彙、各自的邊界在哪。
5. **[O5] 清殘留**：4 篇裸 prior-art、1 篇 area/、1 段過期的 risk 註解。
6. **[O6] 砍掉 type/ 與 status/ 兩個副本家族**（省 983 行、一個同步器、兩道閘）。**代價明寫**：`query --tag` 目前是直接比對標籤清單，砍了就要改成從純量欄合成虛擬標籤；Obsidian 的標籤面板會空掉；`search "status/doing"` 這種字面查法會失效。這是本篇裡唯一需要遷移的選項，建議排最後，而且要先確認消費專案（Landmark、KDS）沒有靠標籤面板在用。
