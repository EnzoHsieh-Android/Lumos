# 新寫句子的數量與位置提醒_計劃

白話:這份做兩個「寫的當下就提醒」的小功能,都只在提交時印提醒、不擋。

- **數量**:筆記寫「`_LUMOS_PLUGINS` 有三支」,三這個數字之後清單一改就過期,沒人知道。已經有一種標記 `[count:路徑::名稱=N]` 能讓工具去數(見 [[Projects/數量標記檢查_計劃]]),但要寫的人記得掛。這份在提交時抓出「點名了程式裡的清單、寫的數字剛好是它的成員數、卻沒掛標記」的新句子,提醒掛上,連要貼的標記都印好。
- **位置**:更正括號寫「(更正:第 3 項其實是…)」,之後那份清單刪掉一項,「第 3 項」就指到別的東西。這份在提交時抓出新寫的更正括號裡用「第 N 個/最後一個/倒數第 N」指位置的寫法,提醒改成引那一項的名字。

依據:
- rtb 第三輪提案 C2 與 A2(`[[Projects/交接2026-10-03_計劃]]`〈rtb 第三輪提案〉第 5 優先)。
- 2026-10-07 對本 repo 現有 759 篇筆記試掃(只是量規則準不準,不是上線後的量):

  - 字眼加上同一段有反引號名稱:121 行,抽 30 句約 3 句。
  - 名稱在 Python 檔模組最上層數得出成員(沿用數量標記的數法):52 行;再要求句子裡有一個數字等於成員數、而且至少 2:約 7 行,其中約 6 行真的在講那個清單的成員數(例:`_LUMOS_PLUGINS` 三支、`IRREVERSIBLE_HINT_PATTERNS` 7 條、`NARROW_ZH` 19 個)。

  - 實作後用上線版規則對全部現有筆記重掃(cut=0、不設名稱上限):數量 12 處,約 8 處真的在講那個清單的成員數,其餘是數字剛好撞上(例:「`_VENDORED_TOOLKIT` 常數 + 五個 helper」)。

## 範圍

- **做**:提交前(`note-shape --staged`)多一組「新寫句子寫法提醒」,兩條規則(數量、位置);開關 `note_shape.wording`(warn 預設/off);doctor 在 off 或寫了看不懂的值時講一句;hinted 帳一筆;手冊 `skills/lumos-project-notes/commands/03-寫回圖譜.md` 那一列補一句。
- **不做**:擋(字眼規則撐不起擋,見 `[[Systems/筆記內容閘]]` 摘要裡「只有 N 種」句型準度那一行);推送時與 CI 不跑(提醒只對寫的人有用);舊句子不回頭掃;非 Python 的清單;數量不吻合的句子(那是寫錯或不是在數那個清單,判不出是哪個,交給數量標記檢查與人)。

## 做法

1. **共用容器**:照前綴提醒的 `_ns_tag_hints_prepare/collected/emit` 形狀開一組 `_ns_wording_*`,讀開關用既有的 `_note_shape_mode_parse(cfg, "wording", "新寫句子寫法提醒")`;只在 `--staged` 時給容器;逐篇在 `_note_shape_eval` 裡呼叫 `_ns_wording_collect(box, p, text, rows, pairs, files, reader)`,跟另外兩組並排。丟例外就清空、記類別名、這次不再算;印「新寫句子寫法提醒這次沒跑完(類別名),不影響這道檢查的判定」。★不進違規清單、不改回傳碼★。
2. **要看哪些行**:`rows` 裡 body 與 summary 區塊、圍欄外看得見的行;REVISIT 行不看。舊行原封不動、只在句尾補括號(`_NotelinesPairs` 配到、可見文字以舊行的可見文字開頭)時,只看補上的那段。
3. **數量規則**:
   - 那一行看得見的文字裡(行內程式碼以外)已經有 `[count:` 或 `lumos:count` 就不看。
   - 成對引號(「」『』“”"")裡的字兩條規則都不看:只是在提這種寫法(同否定現況句提醒);這也是誤報的出口。
   - 一行照「。;；!?！？,,」與破折號切成段;一段裡要同時有:反引號包著的名稱(`名稱` 或 `路徑::名稱`,名稱是 Python 識別字),以及行內程式碼與方括號欄位以外的一個數量——阿拉伯數字或中文數字(一到九十九,含「兩」),後面可隔空白接「種、類、項、款、樣、個、支、條、值、成員、鍵、欄、組」之一,前面不是「第」;阿拉伯數字前面緊貼英數字或 `_ . / : -` 的不算(`v3`、`r1-3`、`a/3`;跟 `drift fix` 認的獨立數字共用同一組字 `_COUNT_NUM_EDGE`),緊貼中文字照算(「有3種」)。
   - 名稱怎麼找:被檢查版本裡所有 Python 檔(`_drift_probe_is_py` 的判法)一次建索引:每支檔行首像 `名稱 =`、`名稱: … =`、`class 名稱` 的位置。帶路徑就只看那支檔。每一處先只解析定義那一段數成員(便宜);有一處數得出句子寫的數,才用 `_drift_py_names`(ast,drift 那邊判「是不是模組最上層定義」的唯一判法)確認哪幾處是真的——字串裡頂格的假定義(測試夾具常把程式寫在三引號字串或 t-string 裡)不算。真的恰好一處、而且就是數得出那個數的那處才提醒。這一步整支解析,只在要提醒時才付(本 repo 3 MB 的檔約 2.2 秒、330 MB);大於 4 MB 的檔照舊句檢查的上限 `_DRIFT_M1_PARSE_MAX_BYTES` 不解析、不提醒。代碼審 r2 架構對齊席抓到修補中途另用 tokenize 判是第二種做法,改成這樣。
   - 怎麼數:★只解析定義那一段★(從定義行到下一個頂格的語句,最多 2000 行),整段交給數量標記的 `_count_eval` 判哪種語句算定義、怎麼數(只有一份判法;代碼審 r1 架構對齊席);解析時關掉 Python 警告(無效跳脫的 SyntaxWarning 會直接印到終端,代碼審 r1 正確性席)。不解析整支檔,所以不查定義之後在檔裡別處有沒有被改過。理由:本 repo 的常數大多在一支 3 MB 的檔裡,整支解析一次約 1.8 秒、350 MB,實作時量到的最壞情況是一次提交 24 秒、728 MB;只是提醒,掛上標記後 drift scan 照完整判法再判。
   - 上限:Python 檔讀進來的總量超過 64 MB,或這次要數的名稱(找得到定義的)超過 50 個,就停、這次之後的行不再看數量,印一句沒跑完(位置規則照跑)。同一次提交同一個名稱只數一次。
   - 段裡有數量等於成員數 M、而且 M 至少 2,就提醒一次(同一行只提醒第一處),印出要貼的標記 `[count:路徑::名稱=M]`。
4. **位置規則**:看得見的文字(行內程式碼與引號裡遮掉)裡每一層的括號群(半形與全形混用、可巢狀,跟 `_ns_paren_groups_only` 同一種括號;每個右括號配最近一個沒配到的左括號,沒收尾的左括號不吃掉後面的群;更正括號常包在別的括號裡,所以任何一層都看,代碼審 r1 正確性席);最外層括號群是更正括號——左括號後(可隔一個 12 字以內、不含空白與括號的短前綴加空白,例「r1 」「2026-10-07 」)緊接「更正、修正、訂正、勘誤」之一再接半形或全形冒號——而且裡面有「第 N 個/項/條/點/行/列/筆/段/格/欄/處/支/句/步/節」「最後一個/項/條/點/行/列/筆/段/支/句/步/節」「倒數第 N」之一,就提醒一次(同一行只提醒第一處)。N 是阿拉伯數字或中文數字,中間可以有空白。
5. **印出與記帳**:有提醒才印。開頭「提醒:這次提交新寫的句子有 N 處之後容易過期或指錯(note_shape.wording=warn,不擋):」,每處一行「路徑:行號 [數量|位置] 片段」;數量那行後面接要貼的標記,位置那行接「改成引那一項的名稱或開頭幾個字」。結尾講:不是在數那個清單就不用理、這次提交之後這幾行不會再提醒、關掉的設定。記一筆 hinted 帳:`check=wording`、`rules`(count/position)、`lines`、`notes`。
6. **doctor**:開頭筆記形狀擋那幾行,`note_shape.wording` 是 off 或看不懂的值才講一句(照前綴提醒)。

## 實務隱患

- **效能**:沒有候選段就不讀任何程式檔;有候選才讀 Python 檔,每支只讀一次、建一次索引,只解析定義那一段。實作時量過(暫存專案、一篇 3000 行新筆記、41 支 Python 檔含一支 5 MB):沒候選 1.1 秒、每行都有候選 1.4 秒,子程序峰值 221 MB、254 MB(代碼審 r2 修正後重量;那支 5 MB 的檔超過 4 MB 上限、不整支解析;機器同時有別的會談在跑測試,秒數會飄);真的要出提醒、名稱定義在 3 MB 的檔時,那次提交多約 2.2 秒、330 MB(關掉這組提醒的對照 1.1 秒、222 MB)。
- **記憶體**:讀進來的 Python 檔文字在這次提交內留著,總量上限 64 MB;不留整支檔的語法樹。
- **相容**:新開關預設 warn,消費專案更新後提交時會開始看到這組提醒;不改回傳碼、不改任何既有提醒的字樣。

## 驗收條款

- [S1] 當提交新寫的正文或摘要行在同一段裡點名 `名稱`、寫了等於它成員數(至少 2)的數量、而且沒有數量標記,`note-shape --staged` 應 印出數量提醒與要貼的 `[count:路徑::名稱=M]`,回傳碼 應 跟沒有這行時一樣 [test:t_note_wording_count_hint]
- [S2] 當數字不等於成員數、成員數小於 2、那一行已有數量標記、名稱在 Python 檔裡零處或兩處以上有定義、數字在行內程式碼或方括號欄位或引號裡、前面是「第」、阿拉伯數字緊貼英數字、名稱與數字不在同一段、行在圍欄裡、行是 REVISIT 行,數量提醒 應 不出 [test:t_note_wording_count_quiet]
- [S3] 當新寫的更正括號(左括號後緊接更正類字眼加冒號,可隔一個短前綴)裡用「第 N 項/最後一個/倒數第 N」指位置,`note-shape --staged` 應 印出位置提醒;括號不是更正括號(沒有標記、只是提到「修正」)、位置寫法在括號外、「第 2 輪」這類時間序、整個括號在引號裡,應 不出 [test:t_note_wording_position_hint]
- [S4] 當舊行原封不動、只在句尾補括號,兩種提醒 應 只看補上的那段 [test:t_note_wording_tail_append]
- [S5] `note_shape.wording=off` 應 不出這組提醒、doctor 應 講一句;看不懂的值 應 照 warn 並講一句;推送時(`--diff`)應 不出這組提醒 [test:t_note_wording_switch]
- [S6] 這組提醒的任一步丟例外 應 只印一句沒跑完,回傳碼與否定現況句提醒、筆記前綴提醒 應 照常;有提醒時 應 記一筆 check=wording 的 hinted 帳 [test:t_note_wording_isolated]

## 天花板

1. 數量只抓「點名 Python 模組最上層的字面值集合或列舉、數字剛好等於成員數」的句子;程式組出來的集合、其他語言、沒點名的句子(「外掛有三支」)都抓不到。
2. 寫的數字已經跟成員數不一樣的句子不提醒(分不出是寫錯還是在數別的);反過來,數字剛好撞上成員數、其實在數別的東西也會提醒(試掃約三分之一)。
3. 只解析定義那一段,定義之後被改過的集合照樣會提醒;貼上標記後 drift scan 會判成「數不準」,那時再拿掉標記。
4. 位置只看更正括號;一般句子裡「見上面第 3 點」這種指涉不提醒(全文命中大多是「第 2 輪」這類時間序,誤報太多)。
5. 只提醒不擋,作者可以照樣提交。
6. 「是不是真的模組最上層定義」只問名稱在那支檔的語法樹裡有沒有(`_drift_py_names` 回的模組層指派與任何層的類別),不問行首那一處是不是就是它(代碼審 r3 正確性席,編排者重現):同一支檔裡行首那處在字串裡、真的那個是巢狀類別或連鎖指派的另一個目標時,會印出指向字串裡那處的標記(貼上後 drift scan 判數不準);同一支檔裡真定義與字串裡的假定義並存時不提醒。兩種都要同一支檔裡同名出現兩次。
7. 關掉 Python 警告(`warnings.catch_warnings`)只在這組提醒的兩處呼叫做,drift 那邊呼叫 `_drift_py_names` 時照舊會把無效跳脫的 SyntaxWarning 印到終端;太大或解析不了的檔一律不提醒,不像舊句檢查退回文字抽定義(代碼審 r3 架構對齊席)。
