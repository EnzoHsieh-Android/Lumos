原文(已推翻):這是**結構性**的,不是實作沒做好:

- **派工發生在編排者的 agent 呼叫裡,沒有任何 hook 攔得到。** 治理帳裡根本沒有 `pitfalls` 這個閘;唯一機械保證會跑的地方在 `scripts/hooks/pre-push`,而那已經**晚於派工**。
- 因此任何方案——不管把東西掛在 `pitfalls`、`loop next` 還是新指令——**都只是「另一個你可能不跑的指令」**。換落點解決不了。
- 2026-08-02 拒絕加閘的理由(擋 high 抓不到 standard、擋 standard 逼人 `--no-verify`),經本次兩輪十席獨立重驗,**仍然成立**。

## 兩輪各自撞死在哪(給下一個想開這題的人)

**v1(manifest 進派工必附材料,靠 seat-check 對帳)—— r1 五席,3 blocker + 17 major**
- 收貨檢查只比對**檔名字串**:實跑證明「派工單列一個不存在的 manifest + 報告寫一句我讀了它」→ **全綠 rc0**。任何建在它上面的閘都是裝飾。
- 它只讀**頂層** materials;實帳逐席派工單 100 份 / 單一 75 份,逐席那批直接判 vacuous。本案自己那份派工單就是逐席形態。
- `materials` 的「被審檔」語意是先前一輪**刻意折入**的三集合語意,v1 一句「不新增 schema」就推翻;而多一份材料會讓 `out_of_scope` **反向放寬**。
- `loop next` 沒有 diff 範圍,且 design/code 共用。

**v2(改在 `pitfalls --diff` 人可讀分支直接印釘住節點)—— r2 五席,7 blocker**
- **vault-free 破約**:`pitfalls` 在 docstring、CLI help、圖譜節點三處明文宣告不需要圖譜(vendored 到無圖譜專案要能用),掛 impact 即破約;被當「現成護欄」的那支測試,現場正好沒有 vault。
- **截斷把被消滅的步驟裝回來**:固定席實測 20~26 篇、**無一低於 8**,截斷後要拿完整清單仍須跑那道指令——正是 v2 宣稱已消滅的那道。
- **因果論證有反例**:觸發本案的那一輪,編排者**確實跑了** `pitfalls`(tier 由此而來)。故失敗模式若非「看到提醒卻忽略」(推翻「不是人不聽提醒」),就是「他走的是 `--json`」(v2 對該輪零效力)。兩叉都打穿。
- **範圍口徑自打架**:`pitfalls` 明文排除 `governance/review-reports/`(歸檔的審查快照裡**故意埋著 bug**)與測試檔,`impact` 沒排。實測某範圍排名第一、滿分、必掛★的節點,**唯一來源就是一份審計證物 patch**。
- 同步落點 6 檔 9 處(含要改的那個函式自己的反向註解);`scripts/hooks/pre-push` 是錨點檔,改它要重新蓋章。

## 我方犯的錯(誠實記,這才是最該留的)

1. **沒查圖譜就開案。** 2026-08-02 已有幾乎同名的節點,三個方案攤過、已裁 A 案。專案第一條規矩就是先查圖譜,我用一個數字說服自己跳過。
2. **數字錯兩次。** 立案寫「74 份只有 8 份」——分母混了 design 與 code 兩種迴圈;v2 訂正時又寫「code 迴圈 2/25」,而同篇上一段自己算出的是 **27**,分子實際是 3。
3. **把別人做的事說成自己挖到的洞。** v2 宣稱「發現 2026-08-02 排除理由的洞(熱路徑)」——實際上那個理由在 **2026-08-22** 落成核對上線時就已作廢(`pre-push` 每次推送本來就無條件跑一次 impact)。
4. **共同形態=先有結論再找證據**,三次都是。這比方案失敗本身更值得記。

## ★副產物:兩個真缺陷(本案不修,留待另案)★

1. **impact 會把審計證物當程式碼來源**:`governance/review-reports/**` 底下的凍結快照 `.patch` 裡故意埋著 bug,`pitfalls` 明文排除、`impact` 沒排,於是那些檔會把「事故」類節點頂到滿分。**這是 impact 的既有缺陷,與本案無關但由本案審出。**
2. **`impact` 人可讀輸出的兩個誤導**:①非固定席在上游已被截成 8,再報「還有 N 篇」會少報(真數在 `meta.free_total`,實測 8 vs 20)②讀不到的筆記靜默消失、rc 仍 0——「我沒去看」與「看過沒有」印成同一句。

## ★留下的正途(另案,不在本案)★

**改派工模板,不改工具。** 架構對齊席的模板早就有一格內插 impact 的固定席(`skills/lumos-design-loop/templates.md` §7.6),**那是今天唯一真的在消費圖譜節點的派工路徑**。把那一格擴到其他審查席即可——紀律點落在「我正在寫的那份派工詞」上,比「多跑一道指令」難跳過得多。仍是紀律不是機械,但**這是本題目前可得的最好形態**。

## 順帶澄清:code-loop 並沒有忽略圖譜

本案講的是一個**很窄的缺口**,別讀成「代碼審不看圖譜」。今天圖譜進 code-loop 有四條路,三條是機械的:
1. **改檔前 hook 推合約/事故**(PreToolUse,每次都跑)
2. **推送前落成核對**(`pre-push` 的 sync nudge,每次都跑,印出這批動到哪些筆記)
3. **綁定測試自動真跑**(diff 碰到帶硬合約的節點,`code-loop check` 會把那些測試真跑一遍,紅了擋推送;2026-08-22 起機械化)
4. 架構對齊席派工模板的固定席那一格(派工時,唯一的人工路徑)

**缺的只有第 4 條沒擴到其他席。**
