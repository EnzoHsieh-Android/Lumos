# 提交時自動更新筆記日期_計劃

(檔名沿用第一版「提交時自動更新」;設計審 r1 後方向改成健檢列出加一鍵修,見摘要。)

白話:每篇筆記開頭有一欄 `updated`(最後更新日期),靠人改完內容記得改它,常常忘。這次讓 doctor(健檢)把「`updated` 比 git 上那一篇最後一次改動還舊」的筆記列出來,再給一條指令 `lumos updated-sync`,一次把列出來的改成今天。不在提交時偷偷改檔,所以不碰提交流程、不影響設計審的指紋。

依據:Enzo 2026-10-06 兩次裁定——先選「提交時自動改」,設計審 r1 指出它會讓已通過的設計審失效等代價後,改選「健檢列出加一鍵修」。

PRIOR-ART: `git_last_change_dates(repo_root, vault)` 已經一次 `git log` 拿到圖譜底下每篇的最後改動日期(2026-08-23 為工具清單 #5 做的,目前沒有呼叫者);doctor 的提醒段(warn_soft)與其他「列出加指令」的形狀照既有寫法;寫檔照 `lumos set` 的寫入原語(`_vault_write_lock`、`load_raw_for_edit`、`atomic_write_verify`)。
RETIRE-IF: 2027-01-06 起連續兩次 doctor 在本工具鏈與 rtb 都列出 0 篇落後(大家已經習慣改或用指令),就把 doctor 那一行降成只在 --verbose 印。

## 範圍

- 做:doctor 多一行提醒(只提醒不擋):圖譜裡有 `updated:` 欄、而且它比 git 上那一篇最後一次提交日期早超過一天的筆記(早一天以內不算:今天改、隔天才提交是正常的),印筆數與前 3 篇,附一條指令 `lumos updated-sync --stale`。git 不可用(不是 repo、git 失敗)或淺複製(只有最近幾個提交,每篇的 git 日期會變成同一天)就不印。
- 做:新指令 `lumos updated-sync <節點>… | --stale [--dry-run]`:把指定的筆記(或 doctor 那一行列的全部)開頭 `updated:` 改成今天(本機日期,專案慣例 `datetime.now(timezone.utc).astimezone().date()`);沒有 `updated:` 欄的不加;已是今天的跳過;印改了哪幾篇。寫入照 `lumos set` 的寫入原語,一篇一篇寫,任一篇失敗印原因、其他照寫,最後 rc 非 0。
- 做:指令說明字典、skill 總目錄與速查(`commands/03-寫回圖譜.md`、`04-自檢與健康.md`)、指令總數同步。
- 不做:提交時自動改、推送前或 CI 擋。
- 不做:判斷「正文改過」還是「只改了開頭其他欄位」(git 最後改動日期不分);只改了狀態而沒改日期的也會被列,改成今天即可。

## 做法

1. doctor:`git_last_change_dates(repo_root, vault)` 拿表;對 env.notes 裡每篇有 `updated` 的,`updated`(只認 YYYY-MM-DD)早於表裡那篇的日期 → 落後;印一行 `updated 落後 git 最後改動的筆記 N 篇(例:…)——lumos updated-sync --stale 一次改成今天`;0 篇不印。
2. `cmd_updated_sync(env, nodes, stale, dry_run)`:`--stale` 用同一支判落後的函式取清單;節點名用 `env.find`(找不到走 `_node_not_found`)。每篇走 `_cmd_set_locked(env, rel, "updated", 今天)`(set 已有的寫入路徑,含鎖、自驗、原子寫入)。
3. 判落後抽成一支 `_updated_stale_notes(env, repo_root)`,doctor 與指令共用。

## 實務隱患

- **提交日期與本機日期**:git 的日期是提交當下的提交者日期(%cs),本機改成今天;跨午夜或時區不同時可能差一天,只影響列不列,不擋任何東西。
- **改完要提交**:`updated-sync` 改的是工作目錄,要跟其他改動一起提交;它會改到計劃筆記的整檔指紋,跟手改日期一樣——正在設計審中的計劃,審完再跑。
- **大量落後**:第一次跑可能列出很多篇(存量);`--dry-run` 先看。
- 已排除:金流:只改筆記的日期欄,不碰任何金流
- 已排除:對外送出:不連網、不送任何東西出去
- 已排除:不可逆:改的是版控裡的筆記,提交前可 git 還原
- 已排除:守衛面:doctor 只多一行提醒、不擋;新指令只在人手動跑時寫檔,不改任何閘

- [S2] 當跑 `lumos updated-sync --stale` 時,應 把 doctor 列的每一篇 updated 改成今天、其他欄位與正文不動;沒有 updated 欄的不加、已是今天的跳過 [test:t_updated_sync_stale]
- [S3] 當指定節點名跑 `lumos updated-sync <節點>` 時,應 只改那一篇;找不到的節點 應 走近名候選訊息並讓 rc 非 0、其他照改;`--dry-run` 應 只印不寫 [test:t_updated_sync_nodes]
