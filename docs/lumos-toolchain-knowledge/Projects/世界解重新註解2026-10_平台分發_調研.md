# 世界解重新註解2026-10_平台分發_調研

> 白話:這一類問的是「Lumos 這套工具怎麼裝上去、怎麼更新、怎麼拆乾淨,怎麼同時接 Claude Code 與 Codex,以及別人能不能藉這條管線塞壞東西進來」。世界大勢:技能(SKILL.md 資料夾)已經是各家通用的單位,掛鉤(hooks,harness 在特定時點自動執行的命令)沒有標準,但各家都向 Claude Code 的格式靠攏,而且都改用「外掛包」來裝掛鉤、讓 harness 自己負責移除。對 Lumos 最重要的兩個結論:第一,「Codex 掛鉤有沒有被信任,本機讀不到」這個前提在 2026-10 已經不成立,狀態就寫在 Codex 設定檔裡;第二,Lumos 的 git 閘指向工作樹裡的資料夾、分發走可移動的 git 分支且不驗簽,這兩處是本類最大的安全暴露面,世界上有現成且成熟的對照做法。

本篇是 [[Projects/世界解重新註解2026-10_總覽_調研]] 的第 8 類分篇。守門類機制的世界解另見 [[Projects/世界解重新註解2026-10_守衛閘門_調研]]。

## 這一類在問什麼、Lumos 現在怎麼做

本類問三件事:工具本身的分發與生命週期(裝、更新、拆、版本)、跨 harness 接線(同一批掛鉤接 Claude Code 與 Codex)、供應鏈安全(分發與掛鉤會不會變成別人執行程式碼的入口)。

機器與專案兩層的安裝生命週期:
- [[Systems/lumos-cli-lifecycle]]:安裝、更新、一鍵 bootstrap 的總家;分「機器層」(全域指令、技能連結、全域掛鉤)與「專案層」(複製工具組進專案、注入紀律區塊、設 git 閘路徑)。
- [[Systems/lumos-deinit]]:拆除,是安裝的鏡像,永遠保留圖譜。
- [[Systems/授權與歸屬]]:被複製出去的每支檔都帶授權標記,授權檔永不進複製清單。

跨 harness 接線與掛鉤執行:
- [[Systems/codex-harness]]:同一批掛鉤腳本加一個旗標接上 Codex;記錄 Codex 的天生限制(要人按信任、信任狀態讀不到等)。
- [[Systems/hook信任邊界]]:掛鉤只執行系統裝的那份 lumos,絕不執行被打開資料夾裡的那份。
- [[Systems/hook逾時預算]]:內層逾時從外層天花板扣掉已耗時間算出來,逾時走自己的放行。
- [[Systems/lumos事件帳]]、[[Systems/lumos-guard]]、[[Systems/lumos-context]]:三支以 Claude Code 外掛(mods,行程內的 JS/TS 事件處理器)形式安裝的模組:結構化事件帳、審查席工具限制、壓縮前交棒。

跨平台:
- [[Systems/native-windows-support]]:原生 Windows 支援;安裝邏輯收進 Python 單一來源,掛鉤命令按 Git Bash 設計。
- [[Systems/python直譯器選擇]]:各入口腳本怎麼找到 Python 3.14 並把版本判斷交給主程式。
- [[Systems/雲端工作階段開場設定]]:Claude Code 雲端會談開場補工具。

公開精簡版(2026-08-20 起在本 repo 內凍結,交付庫獨立演進):
- [[Systems/slim-gen-生成器]]、[[Systems/slim-scan-掃描器]]、[[Systems/slim-skill-修剪]]:從完整版生成精簡包、掃私有內容、修剪技能。
- [[Systems/slim-get-一行安裝]]、[[Systems/slim-install-安裝器]]、[[Systems/slim-uninstall-一行卸載]]、[[Systems/slim-readme]]:精簡版的一行安裝、安裝器(複製而非連結、記雜湊供卸載比對)、一行卸載、說明文件。

相關計劃與議題(沒有獨立 Systems 家):
- 生效檢查 `lumos enforcement`:約 24 列三態儀表板,見 [[Projects/enforcement儀表板_計劃]];目前沒有 Systems 家(有一篇 open Issue 記這件事)。
- 發版流程:開發線 main、對外線 release 只由維護者快轉,見 [[Projects/版本發布流程_計劃]]。
- CI 回流:`lumos ci-wait` / `ci-status` 等 CI、結果進治理帳、在場會談最多修兩次、明文不採雲端自動修,見 [[Projects/CI回流閉環_計劃]]。
- 每日 wrapper 看門狗:健康狀態原子寫入、另一支排程每小時讀,見 [[Projects/每日治理wrapper活著沒_計劃]]。
- git 閘路徑指向工作樹內的風險:[[Issues/git-hooks路徑指向樹內_checkout即執行分支碼]](open,`REVISIT:2026-12-01`)。

- 關係:可借鏡(本類第一個結構性改法)。Lumos 的三支 mods 已用資料夾型市集安裝,但六支核心命令型掛鉤仍由合併器寫進使用者層 Claude 設定檔(核對答案 Q08-01:部分有)。

## 世界證據對 Lumos 做法的挑戰

1. **「Codex 信任狀態本機讀不到」**。世界證據:openai/codex main 把信任存成設定檔的 `hooks.state` 表,app-server 回傳信任狀態;本機 0.160.0 有 15 個表。挑戰的前提:生效檢查 Codex 五列「永不 active」、Codex完全支援計劃的誠實邊界。怎麼驗證:拋棄式 Codex 家目錄裝一支掛鉤,按信任前後比對設定檔是否出現對應 key(候選 1 的最小實驗)。
2. **全域指令與技能連結指向活的來源 clone(決策 d2)**。世界證據:Claude 安裝器、uv、Homebrew 都用版本化目錄;Plugin4Shell 說明「從 git 自動跟新、不驗來源」是零點擊攻擊面。挑戰的前提:「git pull 即更新」的便利值得「來源被劫持或切分支即全機生效」的代價。怎麼驗證:在來源 clone 切到別的分支,看全域 `lumos --version` 與掛鉤行為是否立刻改變(依程式推論會)。
3. **git 閘路徑指向工作樹內**。世界證據:pre-commit 對這個設定的態度是拒絕安裝;2026 年蠕蟲已把 repo 內的代理設定當持久化點。挑戰的前提:「單人 repo 可接受」。怎麼驗證:重放 Issue 的暫存 repo 實驗,加一個「依賴寫入樹內掛鉤」的情境。
4. **以「改使用者設定檔」承載掛鉤**。世界證據:Claude、Codex、Antigravity、Copilot、Qwen 都以外掛包承載掛鉤、由 harness 負責移除。挑戰的前提:合併器自癒足以維持生命週期對稱。怎麼驗證:候選 3 的最小版本跑一輪裝、更新、拆,比殘留與版本數。
5. **版本戳只提醒**。世界證據:pre-commit、mise、Claude 都提供可硬擋的最低版本。挑戰的前提:不是「版本號不當新舊判準」本身(那條仍成立),而是「完全沒有相容下限」。怎麼驗證:統計 Codex 0.160.0 後收工檢查靜默略過的次數(事件帳已記這次失效)。
6. **Windows 按 Git Bash 設計**。世界證據:Claude Code 讓 Git for Windows 變選配,沒有時改 PowerShell;Python 傳統安裝器 3.16 起不提供。挑戰的前提:「Windows 機器一定有 Git Bash、Python 裝在傳統路徑」。怎麼驗證:Windows 真機兩種環境各跑一次(見候選 5)。
7. **provenance 不等於安全**(支持現狀)。TanStack 案的有效 SLSA L3 provenance 說明簽章必要不充分;若 Lumos 將來加簽章,不能拿掉人工發版關卡。
8. **拒絕雲端自動修**(支持現狀)。世界正走向雲端自動修 CI,但嚴謹的實作都有「寫入分離、模糊交人、不碰主線」三道邊界;Clinejection 是現行立場最強的外部支撐。解禁條件(審查席唯讀隔離落地並過終審)2026-10-11 仍未成立。

## 筆記與程式或來源對不上的地方

1. **Codex完全支援計劃,Codex 對照表的掛鉤列**:同一格先寫「信任綁 hook 定義的內容 hash——lumos 每次更新 hook 檔都要再審一次」,後面又寫「信任綁命令列,只換檔內容不用重審」;並說信任存放處沒查出來。實際:讀 openai/codex main,雜湊算的是正規化後的掛鉤定義(含命令列),不含腳本內容,存放處是 Codex 設定檔的 `hooks.state`;本機 0.160.0 有 15 個表。建議:改句刪掉「每次更新都要再審」,存放處那句改成帶日期與版本的觀察;同時立 Issue 讓生效檢查重看(候選 1)。狀態:已讀碼確認(Codex main),0.160.0 二進位行為需要實機確認。
2. **enforcement 儀表板計劃與 codex-harness 的「信任狀態本機讀不到」**:同上,這句在 0.160.0 不再成立。建議:立 Issue,處理後改句。需要實機確認(拋棄式家目錄跑一次)。
3. **Codex工作流整合調研的「plugin_hooks 已移除(掛鉤不能靠外掛帶)」**:本機 0.160.0 的功能清單確實仍印 removed;但 Codex main 原始碼註解說它是「已移除的相容旗標」,掛鉤登記處直接收外掛掛鉤來源。原句把「開關被拿掉」讀成「功能被拿掉」的機率高。建議:在該篇補一行帶日期的更正,並以拋棄式家目錄實測一個帶掛鉤的外掛。狀態:已讀碼確認(main),需要實機確認(0.160.0)。
4. **版本發布流程計劃的落地紀錄**:把 [S5] 算成做了,但 [S5] 條款裡的「`--ref` 釘版本 opt-in」與「detached HEAD 下 `--pull` 必須回非零」沒有實作,一行安裝腳本只認 `--pull`、`--init`,「沒做」清單也沒列。建議:改落地紀錄,把 [S5] 拆成「通道已做 / 釘版本未做」。已讀碼確認。
5. **可信 lumos 判斷的註解**:註解說「不是 symlink 指到別處」,程式沒有這項檢查;用 `stat()` 跟著連結走,檢查的是目標檔與「連結所在」的資料夾。建議:改註解或補檢查,並寫一支先紅的測試。已讀碼確認。
6. **可信 lumos 判斷在 Windows 上全部判不合格**:規則拒絕「同群組或其他人可寫」,而 CPython 在 Windows 回報一般檔 0o666、資料夾 0o777;核對 agent 以模擬確認回傳變成空值,依程式設計改檔前推播、開場防護檢查、派工鏡頭都會靜默跳過,掛鉤本身仍記成功;對應測試在非 POSIX 直接標「沒驗到」。建議:立 Issue。已讀碼確認(邏輯),需要實機確認(影響)。
7. **Codex 收工檢查的版本白名單**:只認 0.144.1、0.153.2 兩版逐字稿,本機 0.160.0 一律略過且只印 stderr(而 stderr 對 Codex 模型零訊號);生效檢查的 codex-cli 列卻照樣標 active。事件帳節點已記這次失效。建議:codex-cli 列對白名單外版本標 degraded(候選 6)。已讀碼確認。
8. **掛鉤事件不分 harness**:掛鉤寫事件時只記掛鉤名、repo、指紋,不記是 Claude 還是 Codex 跑的;依程式推論,同名掛鉤在 Codex 跑過也會被算進 Claude 那一列的「近期成功」。建議:事件加 harness 欄位。需要實機確認。
9. **native-windows-support 的「Windows 用 Git Bash 跑」**:Claude Code 官方文件 2026-10 寫 Git for Windows 是選配,沒有時改用 PowerShell。原句只在「有 Git Bash」時成立。建議:改句加前提,並把 PowerShell 退路列為已知未驗情境。來源對照(外部文件),Lumos 端需要實機確認。
10. **研究筆記本身**:把「卸載殘留註冊」當成搬外掛的痛點之一,但那篇 Issue 已在 2026-07-24 用合併器自癒結案;本篇已改採前例對照的說法。
11. **worktree 下生效檢查把 git 兩列報 inactive**:研究與核對都在本工作樹看到;本機 git 閘路徑設定是主工作目錄的絕對路徑。是比對邏輯的錯,還是主工作目錄那份 pre-push 沒帶新版旗標(程式有一條專抓「舊掛鉤搭新工具」的判斷),本次沒查清。建議:先以 `git config --show-origin` 與兩份 pre-push 的差異查一次,再決定立 Issue。需要實機確認。

## 誠實界線

- **只經一次核對**:預定的第二輪獨立複查(Q08-02、03、04、08、09)在本篇定稿時不存在,這五題的現況判定只經一個乾淨 agent 核對一次。其中 Q08-02 的關鍵事實(15 個狀態表)我另外計數確認過一次。
- **完全沒實測的建議**:16 條候選都沒有在目標環境跑過最小實驗;候選 1、3、7、11 的成立都依賴 harness 實際行為,第一步都寫成實測。
- **Windows 相關全是推論**:沒有 Windows 機器。PowerShell 退路下命令解析失敗、可信 lumos 判斷全數不合格、Install Manager 路徑、Codex 在 Windows 用哪個 shell,全部是讀文件與讀碼推論;使用者 2026-10-05 已裁「先不管 Windows」,做不做要人裁。
- **只讀到摘要或二手的來源**:Shai-Hulud 系列、Miasma、SANDWORM_MODE、技能市集稽核、Plugin4Shell、Claude Code 信任前執行類 CVE、Codex 外掛上市日期、Gemini 逾時放行、Nx 自修 CI、GitLab flow、Claude 桌面 PR 監看、Codex OTel 事件、Cursor 讀使用者層 Claude 設定。
- **未複驗的數字**:Shai-Hulud 2.0 影響 repo 數(25,000 到 30,000 各家不一)、Mini Shai-Hulud 約 170 個套件、Cline 惡意版約 4,000 次下載、ClawHub 惡意技能 341 到 1,184 支、Miasma 擴散 73 個 repo 與 105 秒停用、MCP Registry 近 2,000 個 server。
- **讀碼範圍**:Codex 只讀了掛鉤發現、設定、外掛描述檔、命名空間、功能旗標幾個檔;沒讀雜湊序列化函式本身,所以「Lumos 能否重算出完全相同的雜湊」未驗證;本機設定檔只計數、沒比對 key 與 Lumos 掛鉤的對應。
- **版本敏感**:Claude Code 2.1.277、2.1.287、2.1.295 與 Codex 0.160.0 的行為都是 2026-10-11 快照,兩家每週發版。
- **前例對照只當背景**:「以前怎麼判過」不拿來刪候選;其中「研究員以為缺,其實已有」的三處(卸載殘留、擁有權標記、Windows 固定候選)已照實改寫。
