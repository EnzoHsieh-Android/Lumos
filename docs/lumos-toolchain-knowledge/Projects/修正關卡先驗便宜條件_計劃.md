# 修正關卡先驗便宜條件_計劃

白話：先看報修單填對沒有，再開機器驗修復。讓便宜錯誤早回報，把等待時間留給有效修正。

## 原因與實驗

WHY:先收齊便宜的輸入錯誤再跑測試，縮短修補回饋等待而保留通過標準 [出處:2026-10-06 使用者要求持續改善代碼審收斂性] [因:附件修復的兩次修正紀錄輸入錯誤各等待約四分鐘]

實驗卷證在 governance/review-reports/fix-check-preflight/。四種便宜錯誤均回 1，卻仍啟動一至兩個測試 runner；暫存原型讓它們零啟動且仍失敗，有效綠紀錄照常兩次啟動。有效真紅修正測試與真紅合約仍判紅。草稿反向夾具曾把沒有改過的檔標為 fixed，因此不算有效紀錄；原始結果保留，由 manifest 排除，正確控制另存 countercontrol-valid-red.json。合成控制只證明順序，不證明真實審查輪數下降。

PRIOR-ART: 借用分階段先快後慢的既有做法，最小改動在既有 fix-check 編排，重用紀錄、測試解析與治理事件，無新依賴。Fowler 的 staged build 先快測試後慢測試（https://martinfowler.com/articles/continuousIntegration.html）；pytest 區分名稱表達式與精確收集識別（https://docs.pytest.org/en/stable/how-to/usage.html），所以本次不對任意 runner 自建名稱碰撞規則。
RETIRE-IF: 累積十次有便宜錯誤的 fix-check，提前失敗仍啟動測試 runner，或修正後有效紀錄不再跑合約，撤回這次順序改動；保留失敗事件，以測試及治理帳裁定。
REVISIT:2026-10-20 核對十次便宜錯誤的耗時、失敗項與未執行提示，以及修好紀錄後的合約結果；樣本不足延後量測，不宣稱輪數下降。

## 核心裁定

沿用 [[Systems/代碼審修正關卡]] 的提醒與記帳分工；測試背書依 [[Systems/測試假綠形態]] 的現場成立與防假綠脈絡，不修改該節點合約。

只調整既有 cmd_loop_fix_check 的執行順序，仍在釘住 HEAD 的隔離工作樹解析。先完整收齊 record、repeat、tests-exist，以及 run_cmd 缺少方法占位符的錯誤。任一存在時，修正測試與受波及合約測試均未執行；輸出兩段未執行與修好紀錄後重跑提示，仍回 1、passed=false，沿用一筆 warned 事件，不記 passed 或成功快取。

沿用 [[Systems/reversibility-governance-ledger]] 的既有事件入口，JSON 與治理事件新增可選清單 not_run_items：前置失敗為 tests-green、bound-tests，有效紀錄為空；舊事件缺欄保持未知，不能推成已執行。gov 共用型別檢查與 mapper 保留此欄，錯型別列沿用既有略過規則。不新增事件種類、不改 loop next 的 passed 判法。

前置全過照常跑兩段測試，修正測試紅仍跑合約收齊診斷，不把動態紅混成前置錯誤。原本回 2 的不可讀輸入、建樹失敗與顯式整道跳過路徑不改。仍由原本 context manager 清理，不提早 return 漏掉事件或清理。短名實際選中多支仍由既有跑測試判法處理。

## 驗收條款

- [S1] 當紀錄類別不合法時，應回 1、收齊 record 錯誤、零啟動測試 runner 且記一筆 warned 事件。[test:t_fix_check_preflight_record_stops_runners]
- [S2] 當連續兩輪同類 major 缺少 prior 時，應回 1、列出 repeat 錯誤且零啟動測試 runner。[test:t_fix_check_preflight_repeat_stops_runners]
- [S3] 當紀錄指向不存在的方法時，應回 1、列出 tests-exist 錯誤且零啟動測試 runner。[test:t_fix_check_preflight_missing_stops_runners]
- [S4] 當平台命令沒有方法占位符時，應回 1、保留 tests-green 配置錯誤且零啟動測試 runner。[test:t_fix_check_preflight_command_stops_runners]
- [S5] 當前置條件全過時，應照常跑修正與合約測試，綠才通過，任一真紅應回 1 且不得略過另一段。[test:t_fix_check_preflight_valid_still_runs]

- [S6] 當前置失敗或前置全過時，JSON 與治理事件應保存未執行階段清單，gov 應保留新欄、容忍舊列缺欄為未知並略過壞型別列。[test:t_fix_check_preflight_not_run_is_durable]

## 實務隱患

- 守衛面：提早失敗減少當次動態診斷，必須明示未執行，失敗事件不能當通過；修好紀錄再重跑。
- 版本與並行：沿用隔離樹、HEAD、紀錄指紋、平台根判法與依賴連結策略。
- 資源與例外：沿用清理與事件入口，不新增背景程序，有效紀錄的逾時與中斷策略不改。
- 已排除金流、外部送出、不可逆部署：只重排本機驗證，無業務外部動作。Windows 與外層 pytest 歸屬不在本次範圍。

## 回退

撤回本功能提交即恢復原本前置錯誤仍跑測試的順序。治理帳只追加，不刪事件；新測試隨功能撤回，計劃標 superseded。通過條件、處置閘、正式三輪上限與其他合約驗證不改。
