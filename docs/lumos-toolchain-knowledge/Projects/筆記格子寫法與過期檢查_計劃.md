## 格子規格(統一文法,寫進紀律範本,前綴定義的唯一來源)

**一種文法**:

```
<前綴>:<核心一句> [鍵:值] [鍵:值] …
```

- **欄位**:只有鍵名在白名單(下表加〈鍵的意思〉)裡的 `[鍵:值]` 才是欄位;其他方括號(`a[0:3]`、`[RFC:9110]`)是正文的一部分。欄位可以寫在句子前面或後面(既有 RULE 多半寫在前面)。冒號收半形與全形(`[出處：…]` 也算),冒號後的空白不算進值;英文鍵名不分大小寫。行內程式碼(成對反引號)裡的方括號不是欄位(正文舉例 `` `[confirmed:]` `` 不會被當成空值欄位);反引號不成對時,從那個反引號到行尾都當正文,不會把後面的真欄位丟掉。
- **核心一句**:整行去掉前綴與所有欄位之後剩下的文字(前後空白不算);WHY 放決定、RULE 放限制、PITFALL 放症狀、FACT 放現況。核心一句空的算缺。
- **值**:可以含成對的方括號(`[[連結]]`、`[0-9]`、`app/[id]/page.tsx` 都行,解析器數括號層數);值整段用反引號包起來時,反引號裡面照字面、不數括號(指令裡有單獨方括號就這樣寫,例 ``[repro:`grep -c "\[test:" f`]``);其他方括號不成對算這一格寫錯,印「值裡的方括號要成對,或把值用反引號包起來」。值空的算缺。
- **重複鍵**:`[test:]` `[applies:]` `[不選:]` `[同族:]` 可以寫多次(多支測試、多個範圍);其他鍵寫兩次算寫錯(擋)。`[test:a,b]` 的逗號寫法照舊可用。
- **適用範圍**:只看摘要區塊的前綴行;圍欄、行內程式碼、表格裡的示範行不算;摘要裡縮排更深、不以前綴開頭的續行接回上一行一起判。
- **空前綴**:冒號後面什麼都沒寫的行(骨架留的 `FLOW:` `DEP:` `KEY:` `TEST:` `SEE:`,任何前綴都一樣)不算違規,沿用既有的「空行不查」;「核心一句空的算缺」只在冒號後有東西(例如只寫了欄位)時才判。
- **各前綴的差別只剩「哪些鍵必有」**:一張表,lint 與提交時的擋都讀它。

| 前綴 | 核心一句 | **必有鍵**(新寫的行缺了提交時擋) | 常用選填鍵 |
|---|---|---|---|
| WHY | 決定 | `[出處:]` `[因:]` | `[不選:]` `[代價:]` `[test:]` `[applies:]` |
| RULE | 限制 | `[依據:人\|外部\|審計\|法規\|相容]` `[since:日期]` `[retire:機器式之一]`;`[retire:人裁]` 另必有 `[until:日期]` | `[confirmed:日期]`(要挑戰程式碼就必須半年內)`[test:]` `[applies:]` `[until:日期]` |
| PITFALL | 症狀 | `[出處:]` `[根因:]`,再加 `[test:]`、`[repro:指令]`、`[防回歸:無 理由]` 三選一 | `[觸發:]` `[修法:]` `[影響:]` `[同族:]` |
| FACT/FLOW/DEP | 現況與數值 | `[來源:部署\|資料庫\|生產\|外部\|人工]` `[confirmed:日期]` | `[recheck:週期]` `[查:指令]` `[applies:]` |
| SEE(新) | 不寫句子 | 至少一個 `[[連結]]`,除了連結只准有分隔字(跟既有「只放連結」的判法同一個定義) | — |
| 任一前綴標作廢時 | — | 加上 `[status:superseded]` 就必須有 `[被取代:…]` | — |

- **鍵的意思**:`[出處:]`=這句話從哪來(日期加對話、審查、事故);`[依據:]`=誰或什麼規定了這條限制;`[來源:]`=這個現況值從哪裡觀測(既有鍵);`[confirmed:]`=最後一次確認還成立的日期(既有鍵,RULE 與 FACT 共用——FACT 原本提的觀測日期併進這裡);`[被取代:]`=這行作廢後改看哪裡,值是 `[[節點]]`、全域決策編號 `節點路徑#dN`(圖譜裡既有的寫法帶 `.md`,例 `Projects/X_計劃.md#d6`;不帶 `.md` 也收,解析時補上;單寫 `d3` 算寫錯;第 0 步讓 `decision-add` 除了「編號 d3」也印出這個全域編號,免得人抄到裸編號),或 `無 <理由>`(限制自然消失、沒有接手的);不用 `by`,因為 `by` 在回頭條件裡已經是期限日期;也不用「取代」,讀起來像「我取代誰」,方向相反。
- **作廢的兩個地方**:節點開頭的決策(`decisions:`)被翻案,照舊用 `lumos decision-supersede`(寫 `superseded_by`);摘要裡的前綴行作廢才用 `[status:superseded] [被取代:]`。同一件事若兩邊都有,行上的 `[被取代:]` 指到新決策的 `節點#dN`。
- **日期**一律 `YYYY-MM-DD`(只認這個寫法,不收 `20261001`、週日期);`[since:]` `[confirmed:]` 晚於「今天加一天」算寫錯,而且只在提交時(本機掛鉤)查——推送與 CI 不查未來日期,因為 CI 跑在 UTC,台灣凌晨寫的「今天」在那邊還是明天;`[until:]` 可以是未來。
- **撤除條件的機器式**(D):
  - 事件:`[retire:when-file:路徑]`、`[retire:when-symbol:路徑::名稱]`、`[retire:when-test:路徑::名稱]`、`[retire:when-status:節點=值]`——跟回頭條件同一套條件語法(既有 `_PROBE_KEYS` 四種)與同一個值文法檢查;一行只放一個 `[retire:]`。符號與測試必帶路徑,比回頭條件嚴:RULE 行長命、數量多,不帶路徑的候選每次推送都要讀全庫測試檔(回頭條件數量少,維持原寬度)。
  - 度量:`[retire:度量 <閘>.<種類> <比較> <整數> 近<N>週]`。閘只收既有的已知閘清單(`_KNOWN_GATES`,已有測試釘住它跟程式同步),種類只收 `blocked` `warned` `skipped-env` `hinted` `acked` 五種,白名單寫在程式裡、不從呼叫點靜態整理(有些呼叫點的閘名是變數);比較只收 `<` `<=` `>` `>=` `==`;N 是 1 到 8(治理帳只讀檔尾 24MB,照現在的寫入量約裝得下兩個月,N 再大就讀不到)。提交時就驗這個文法(同撤除條件的事件寫法),寫錯當場擋。數的是整個閘的事件數,不是這條 RULE 自己的(治理帳不認得是哪條 RULE 觸發的)。不判(不提醒)的情況:讀到的檔尾最舊一筆不早於 N 週前(檔尾被截斷或歷史不夠長,一律當暖機)、這條 RULE 的 `[since:]` 不滿 N 週、那道閘在目前設定裡是 off。
  - 人裁:`[retire:人裁]` 加必有的 `[until:日期]`。
- **確認週期**:`[recheck:N天|N週|N月]`,N 是 1 到 999、中間不留空白,一個月算 30 天;寫不成週期的提醒一次,改用來源預設(生產 30 天、資料庫 90 天、外部 90 天、部署 90 天、人工 180 天,本篇新訂)。
- **同族掃描**(F,選填):同一形狀第二次以上出事的 PITFALL 建議寫 `[同族:查了幾處、結果]`。
- **範圍**(G):`[applies:]` 只寫具體路徑或模組。
- **SEE**(C):就是「只放連結的 DEP」換個名字,算計劃連結時跟 DEP 的連結同等對待;骨架留的空前綴(`DEP:`、`SEE:` 什麼都沒寫)照舊不算違規。
- **過程紀錄**:不開前綴、不進摘要(跟 [[Projects/筆記標籤_過時判定與按需載入_計劃]] 一致)。
- **不套格子**:合約行(`KEY:★INVARIANT★` 等)、PRIOR-ART、DECISION、TEST、VERIFY、AUTH、FLAG、CORE、REVISIT、RETIRE-IF;工具自己寫的固定樣板行,列一張豁免清單(`lumos guard plan` 寫的預告句,以及 `lumos guard settle` 轉正後帶「已轉正」尾巴的同一句,同否定現況句提醒的樣板豁免)。重建筆記(regen)寫的行不豁免:第 0 步把 skill 裡 regen 的寫法一起改成新文法——指針級的 FLOW/DEP 改寫成 SEE;從程式碼推出來的流程描述照兩個宗旨不再寫進摘要;KEY 不在格子表裡,照舊不查。
- **代價**(承認):理由、根因原本可以寫成一句通順的話,現在要放進方括號,可讀性差一點;換到的是機器認得出、擋得住。

```
PITFALL:分派入口收到空清單會靜默成功 [出處:2026-09-30 事故] [根因:呼叫端沒判空] [test:t_dispatch_empty_list]
WHY:改用結構化欄位記植入型別 [出處:2026-08-05 Enzo] [因:散文帳不可重算] [不選:維持散文]
RULE:分析行程不准有送提案以外的寫入呼叫 [依據:審計] [since:2026-09-23] [retire:when-file:sandbox/policy.yaml] [test:t_analyzer_no_write]
FACT:點數商城兌換約十幾 TPS、零競爭 [來源:生產] [confirmed:2026-08-13] [recheck:30天]
WHY:改用逐行判定 [出處:2026-09-01 審查] [因:整篇判太粗] [status:superseded] [被取代:Projects/新判法_計劃#d2]
```

## 擋(提交時,只看新寫的行)

- **掛在筆記形狀檢查**:同一條路——新增行、違規清單、`LUMOS_SKIP_NOTE_SHAPE=1` 單次跳過留帳、CI 照擋(淺複製的 CI 除外,見天花板 5)。
- **開不開由掛鉤的旗標決定**:格子規則只在掛鉤呼叫 `note-shape --staged --slots` 時才跑;舊掛鉤只有 `note-shape --staged`,格子規則不跑。消費專案的程式與掛鉤是同一輪 `lumos update` 一起複製進去的(兩者都在工具自裝檔清單裡),所以「程式上線」跟「開擋」要靠旗標分開——第 1 步的程式認得旗標,但掛鉤範本先不帶:
  - 提交時:沒帶 `--slots` 就整段跳過格子規則。
  - 推送、CI、doctor 事後掃描:用 `note-shape --staged --slots` 這串當格子自己的上線點記號(掛鉤裡呼叫那一行的參數順序就固定成這樣;掛鉤的註解與說明文字不准出現這串——上線點是對整支掛鉤找字串第一次出現,寫在註解裡會把上線點提前;測試釘住「整支掛鉤恰好出現一次、在呼叫行」);**找不到這個記號 = 格子規則整段不跑**(明寫的例外——既有上線點找不到時是「不過濾、全查」,格子不能照抄,否則程式一上線就把整段歷史當新違規)。找得到就只查記號出現之後的提交。
  - 推送與 doctor 只抽取一趟新增行,逐提交記下那個提交的掛鉤有哪幾個記號,再把格子規則只套在有格子記號的提交上(抽取的回傳形狀會多一欄,筆記內容審共用同一支抽取,要一起改)。舊行判定另外要一次範圍淨差異(拿刪除行)與一批起點版本讀取;doctor 事後掃描照既有上限只看最近 200 個提交,上限之外不查。
  - 筆記形狀檢查原本的規則照舊用原本的記號 `note-shape --staged`(新記號包含舊記號,舊規則照常認得)。
- **改到舊行不算新寫**:新增行若在「上一版」裡有同前綴、同核心一句的行(只差在欄位),算改了欄位的舊行,不套必有鍵——補 `[confirmed:]` 重新確認舊 RULE、補連結都不會被擋。細節:
  - 「上一版」:提交時是 HEAD 那一版;推送時是推送範圍的起點那一版,再加上範圍裡「格子還沒上線的提交」寫的行(沿用既有抽取另收的那一份,開擋前切出的分支寫的行,開擋後只補欄位不被當新寫)——不是逐提交的上一個提交,所以第一個提交用單次跳過放進的違規行,第二個提交只改欄位,推送時照樣查得到;改名照既有改名偵測帶回舊路徑。
  - 跨篇搬移:同一次提交(推送時為同一範圍)裡別篇被刪掉的行若有同前綴、同核心一句,也算舊行(拆節點、併節點不被迫改寫)。
  - 比對核心一句時,`[[連結]]` 與分隔字也去掉再比,所以在舊行補一個連結不算新寫;只放連結的舊 DEP/FLOW 行改了連結,上一版同前綴也是只放連結的行,也算舊行(不被逼著改 SEE)。
  - 除了上一條,核心一句是空的永遠不算舊行(空的跟空的不算同一句)。
  - **例外**:這次才加上 `[status:superseded]` 的行(上一版沒有),一律要有 `[被取代:]`——作廢幾乎都是改舊行做的,不能被舊行豁免吃掉。
- **撤除條件提交時就驗寫法**:新寫(含改了 `[retire:]` 值)的 RULE 行,`[retire:when-*]` 的值先改寫成回頭條件的 `[when-…]` 標記,再交給既有的條件解析(同一支正規化與值文法檢查,REVISIT 與 RULE 對同一條件得到同一個值),寫錯當場擋;度量的文法也在這裡驗。不留到推送時才被濾掉、變成永遠不觸發的死條件。
- **子開關(新增)**:`note_shape.slots`(`block` 預設 / `warn` / `off`;用自己的設定讀取函式,同否定現況句,不擴既有那支兩值解包的讀取)。跟總開關的關係:總開關 `note_shape.gate` 是 off 時整道不跑;總開關是 warn 時格子違規也只提醒;總開關是 block 時照 slots 的值。壞值照 block 並講一句;slots 不是 block 時 doctor 講一句(同既有開關的先例);掛鉤沒帶 `--slots` 時 doctor 也講一句「格子規則沒在跑」(開擋前這是最常見的狀態,要看得見)。
- **擋下訊息**:每條印缺哪幾格、該前綴的一行範本、把這行的核心一句填進範本(核心一句超過 120 字截斷,控制字元清掉);一次最多印 20 條,其餘印總數。標題寫「筆記格子缺漏」,不沿用「程式碼推得出來的形狀」那句。
- **治理帳**:用結構欄位記(同否定現況句提醒的 `extra` 寫法),不塞說明字串——筆記路徑走既有的 `nodes=` 欄位(上限 50),`extra` 只放 `{"slots_lines":條數,"slots_missing":{鍵:次數}}`(不用 `notes`,同一道閘已有事件把 `notes` 當整數);一次提交同時有格子違規與其他違規時,同一筆擋下事件兩種都記,`slots_lines` 大於 0 就算格子擋下。單次跳過:只在提交時、而且掛鉤帶 `--slots`、slots 不是 off 時,才在跳過前算一次格子違規並記進跳過事件;這一步整段包在例外處理裡,算不出來就照舊只記一筆不帶格子欄位的跳過事件、照樣放行(逃生口不能因為多算一步而失效);推送時的跳過不算(避免同一次跳過記兩筆)。RETIRE-IF 用「30 分鐘內、同一批 `nodes`」配對(提交前寫帳時新提交還沒有編號)。被擋下的行文字不進帳,抽查從 git 歷史重建(擋下後同路徑的下一個提交)。
- **範圍**:所有專案的新寫行(Enzo 先前裁定寫法規則不分新舊專案);一個 repo 有多個圖譜時只查第一個(既有限制,見天花板 8)。

## lint 與擋同一張表

- 既有 lint 的脈絡標記規則(WHY 要出處、PITFALL 要防回歸、FACT 要來源)與筆記形狀檢查的前綴規則,改成讀本篇的必有鍵表;表在第 0 步進程式,第 1 步的擋只引用它。RULE 六個鍵的既有解析(含值被 `]` 截斷的提醒)改成呼叫新的欄位解析器,不留兩套——新解析器帶一個舊行模式,舊寫法的行照舊「重複鍵取最後一個、日期照舊寬鬆」,lint 對舊行的結果不變。`[test:]` 在合約行的綁定解析(既有 `TEST_REF_RE`)不換:合約行不套格子,兩邊管的是不同的行。
- lint 對整篇筆記只提醒。**怎麼分新舊**:行裡出現任一個新文法才有的鍵(`[出處:]` `[因:]` `[依據:]` `[根因:]` `[防回歸:]` `[被取代:]` `[recheck:]`),或是 SEE 行,算新文法、用新表;其他都算舊寫法,照舊判準(舊 FLOW/DEP 照舊不唸、舊 FACT 照舊只看來源,沒有 `[confirmed:]` 的舊 FACT 不判過期)。新寫卻一個新鍵都沒有的行,lint 當舊寫法看,但提交時的擋看的是「新增行」,照樣擋。
- 舊判準的表留著,因為舊筆記不轉換;撤掉的條件:工具鏈圖譜裡 lint 數到的舊寫法行歸零。
- 既有的單源守衛測試(偵測 skill 裡有沒有第二份前綴表)用的偵測字串跟著新表的寫法改,不然它永遠偵測不到複本。
- `[防回歸:無 理由]` 算有防回歸;RULE 的 `[status:superseded]` 訊息從「整行刪掉」改成「留著並寫 `[被取代:]`」。
- 測試把「紀律範本的必有鍵表」與「程式裡的必有鍵表」釘在一起,比對的是結構化投影,不是 markdown 原文:每個前綴 → {全必有的鍵、三選一的鍵組、條件式必有(`[retire:人裁]` → `[until:]`)、列舉值(`[依據:]` `[來源:]` 的可選值)};範本表格裡三選一一律寫成「`A`、`B`、`C` 三選一」、條件式一律寫成「`[X:值]` 另必有 `[Y:]`」,投影照這兩種寫法拆;「FACT/FLOW/DEP」一列展開成三個前綴;SEE 列與作廢列另外比對。範本只放前綴表、必有鍵表與一個例子(範本每回合注入,已超過瘦身提醒門檻),鍵的意思、撤除條件寫法等細節放 skill 子檔。

## 格子欄位的過期檢查

| 欄位 | 什麼時候算過期 | 擋或提醒 | 掛在哪 |
|---|---|---|---|
| `[retire:when-*]` | 條件在這次推送從不成立變成立;或這次新寫(改了條件)時條件已經成立 | 擋(推送) | 存量漂移檢查:新寫一段從 RULE 行抽出 `[retire:when-*]`,交給既有的回頭條件判定(同一個轉變判定;起點那一版也用同一支 RULE 抽取,否則既有判定在起點只認 REVISIT 行、找不到「同一條」,每條 RULE 都被當成新寫);**已標 `[status:superseded]` 的行不抽**(標作廢就是處理完了,下一次推送不再擋);放在自己的函式、在既有核心判定之後呼叫(同舊句檢查的先例,不改考試與歷史重放的基準),共用核心判定已載入的起點圖譜與樹;預算用核心判定剩下的、最多 20 秒,不跟回頭條件搶,最壞情況是撤除條件整批判不了、只列出;`drift_check.gate` 是 off 時這段也不跑;判不了的另成一張清單、每筆帶種類、筆記路徑與行號,只列出不擋(既有的回頭條件判不了照舊擋),兩張清單的輸出都最多 20 條加總數、控制字元清掉;子開關 `drift_check.retire`(`block` 預設 / `warn` / `off`,同 `drift_check.old_sentence` 的寫法),誤報成批時只關這一段;新種類登記進種類清單、種類名稱表、`drift scan` 的種類,改法提示另寫一支(像回頭條件那樣:「標作廢並寫 `[被取代:]`,或 `drift ack`」),不進 `drift fix` |
| `[retire:when-*]` | 工作目錄裡條件現在已成立(兜底:轉變那次判不了或被跳過就再也不會被擋) | 提醒 | `lumos drift scan`(既有手動指令,已有 60 秒預算);不放 doctor——既有決定是 doctor 的漂移段不評估條件、只讀筆記(存量漂移防線那篇的 [S14] 釘住)。已標作廢的行與已 `drift ack` 的不列 |
| `[被取代:]` | 指到的節點或決策不存在、或它自己也作廢了(節點 `status: superseded`,或決策 `valid: false`) | 提醒 | 完整 doctor 才跑、`--ci` 不跑(只讀筆記,不跑 git);只看一跳,不沿鏈(叫人改指到最新的那個);`無 <理由>` 不查(不擋,維持「人寫的連結只列出」的既有決定) |
| `[retire:度量 …]` | 近 N 週的事件數符合比較(不判的情況見〈格子規格〉) | 提醒 | 完整 doctor 才跑、`--ci` 不跑;一次只讀一遍治理帳檔尾(上限照既有 24MB),所有度量共用;已標作廢的行不判 |
| `[confirmed:]` `[until:]`(RULE) | RULE 超過半年沒確認;`[until:]` 到期(含人裁) | 提醒 | 不新做:lint 既有的 RULE 生命週期提醒,加上 [[Projects/筆記標籤_過時判定與按需載入_計劃]] 的 doctor 段(`t_doctor_lists_stale_rules`) |
| `[confirmed:]`(FACT) | 超過 `[recheck:]` 或來源預設;沒有 `[confirmed:]` 的舊 FACT 不判 | 提醒 | doctor(不計入問題數;`--ci` 也最多 20 條加總數);已標作廢的行不判 |
| `[test:名]` | 測試不存在 | 擋(推送) | 不在本篇:依賴路線圖 1b「所有筆記的 `[test:]` 驗存在」那案;那案上線前只驗有寫(天花板 3) |
| `SEE:` 連結 | 連到的筆記不存在 | 提醒 | doctor 既有的斷連結檢查 |
| 數量、值、錨點 | 見 [[Projects/依賴欄位_過時判定_計劃]] 的〈待解問題〉 | — | 本篇第 4 步另開設計審 |

時間到期一律只提醒;只有「條件因為這次推送剛成立」這種跟改動有關的才擋。

## 分期(每一步各自實作、各自過代碼審;回退由後往前)

0. **規範、前綴與 lint**(跟 [[Projects/筆記標籤_過時判定與按需載入_計劃]] 第 0 步併成同一次推送,但拆兩個提交:**0a** SEE 註冊進前綴表、算計劃連結的程式也讀 SEE——這個提交回退時不還原;**0b** 其餘全部):SEE 進摘要前綴表;紀律範本的前綴表改成格子規格(單一來源),skill 裡第二份前綴表(reference.md 的符號表與範例、03-寫回圖譜子檔、INDEX 的擋下種類、regen 的寫法)改成指回範本;`lumos new` 骨架提示改用新範本與 SEE;算「計劃連到哪些節點」的程式改成也讀 SEE;lint 訊息裡叫人補 `DEP:` 的那句改 SEE;必有鍵表、新的欄位解析器、lint 改讀同一張表、`[防回歸:無 理由]` 被認得、`decision-add` 印全域編號、RULE superseded 訊息改寫——都在這一步,範本換了 lint 就跟著換,不留一段「範本教新寫法、lint 唸它錯」的空窗。範本一次改完,消費專案只需一輪 `lumos update`。skill 子檔目前沒有 Systems 節點管,動手前先 `lumos impact --file` 找家,沒有就開一篇(每支檔有家)。
   - 進度(2026-10-01):0a 與 0b 已實作(SEE 前綴、範本格子表、欄位解析器、lint 新舊分流、決策印全域編號),連同分類計劃第 0 步(提交時 RULE 提醒、`note_shape.tag_hints`、doctor S16)代碼審三輪通過(governance/review-reports/code-筆記格子第0步/,折 15 條、放行 1 條 minor);新寫的函式照新增告警閘拆到複雜度 10 以內。
1. **擋的程式**:引用第 0 步的必有鍵表;`--slots` 旗標與格子上線點、舊行判定、提交時驗撤除條件寫法、`note_shape.slots`、擋下訊息、治理帳結構欄位、工具樣板豁免清單、推送與 doctor 的單趟抽取雙記號。上線後沒有任何掛鉤帶 `--slots`,所以不擋任何人。
   - **開擋步**:把 `--slots` 加進掛鉤範本(掛鉤在錨點清單裡,改它要 `lumos anchor approve --note …`)。第 0 步推上主線滿 14 天之後才做(先讓範本到位),開擋那天由 Enzo 決定;各專案 `lumos update` 換到新掛鉤那一刻才開始擋。不溯及既往有一個缺口:開擋前寫好、開擋後才 rebase 的提交會被當成上線後的提交(見天花板 10)。
2. **推送時的撤除條件**:`[retire:when-*]` 抽取(略過已作廢的行)、排在回頭條件之後的預算、判不了另成清單、`drift_check.retire`、種類登記。
3. **doctor 與 drift scan 的提醒**:`drift scan` 列出撤除條件現在已成立;doctor 的 `[被取代:]` 一跳、度量、FACT 確認週期。RULE 的確認與到期不在這步:分類計劃的 doctor 段上線前,既有 lint 的 RULE 生命週期提醒已經在唸 `[until:]` 到期與半年沒確認,人裁的到期不會沒人管。
4. **數量、值、錨點**:照依賴欄位那份的待解問題重新設計,另開設計審。

## 天花板

1. **擋得住「格子空著」,擋不住「格子亂填」**:有寫、內容空洞的機器分不出,靠分類判定者與 RETIRE-IF 抽查。
2. **理由、根因、代價只能驗有沒有寫,驗不了對不對**。
3. **`[test:]` 在路線圖 1b 上線前只驗有寫**:寫一個不存在的測試名也能過防回歸那格。
4. **閘的開關讀被推送版本裡的設定**:同一個提交可以把 `note_shape.slots` 改成 off,只防疏忽。
5. **淺複製的 CI 不跑**:筆記形狀檢查與存量漂移檢查在淺複製下都會跳過(既有行為),靠本機掛鉤與 doctor 的 CI 提醒補。
6. **時間類的過期只提醒**。
7. **改到舊行的判定靠「同前綴、同核心一句」**:核心一句改一個錯字就算新寫,要補齊必有鍵。
8. **一個 repo 有多個圖譜時只查第一個**:沿用筆記形狀檢查既有的範圍(既有限制,本篇不改)。
9. **度量數的是整個閘,不是單條 RULE**:治理帳不記是哪條 RULE 觸發的;歷史上那道閘關過的期間也算進去(只看得到目前設定)。
10. **rebase 會讓開擋前寫的提交被當成上線後的**:是否上線看的是每個提交自己樹裡的掛鉤,rebase 到開擋後的主線,重建的提交樹就帶了新掛鉤;緩解:開擋前把手上的分支推掉,或推送時單次跳過(留帳)。
11. **撤除條件的兜底靠人跑 `drift scan`**:doctor 不評估條件(既有決定),轉變那次判不了或被跳過,要到有人跑 `drift scan` 才看得到。

## 不做

- 不轉換、不檢查舊筆記;不改 `lumos init`。
- 不開 LOG 前綴;過程紀錄不進摘要。
- 不在推送時擋 `[被取代:]`;不沿鏈追。
- 不擋時間到期;不在推送時跑 `[repro:]` 的指令。
- 不做 `[expect:]`(漂移路線圖機制 3 提過的「條件帶預期防觸發錯位」)與「撤除條件提交時當場求值」:撤除條件在提交時只驗寫法,成立與否交給推送時的轉變判定與 `drift scan` 兜底;錯位問題等真的出現再開案。依賴欄位那份的〈不收〉曾否決行內 `[retire-when-*]`,本篇翻案的理由:Enzo 裁「一個固定標籤加某個符號」,所有前綴的格子統一寫在行內,撤除條件不再另起一行。
- 數量、值、錨點的機械判定在第 4 步另外設計。

## 實務隱患

- **併發**:新增寫入只有治理帳(沿用既有);兩個推送各自對遠端舊值算範圍。
- **效能**:必有鍵是新增行的字串比對;舊行判定多一次範圍淨差異與一批起點版本讀取;撤除條件只看這次推送改到的路徑、符號與測試必帶路徑,共用核心判定已載入的起點,預算用剩下的、最多 20 秒;doctor 不評估撤除條件,度量一次只讀一遍治理帳檔尾、`--ci` 不跑;推送與 doctor 的格子檢查共用既有的一趟抽取。
- **資源**:不開長駐程序;紀律範本每回合注入、已超過瘦身提醒門檻,所以範本只放表與一個例子,細節放 skill 子檔。
