# 只換測試綁定不算寫說明_計劃

白話:「每支檔有家」有一條規則是:同一個提交裡改了程式,又改了某篇系統筆記的內容,那篇就得是那些程式檔的家——不然等於把說明寫錯地方。問題是它把「換一個測試名」也當成「寫了說明」。rtb 改了一支測試的名字,另一篇筆記裡綁著舊名,換成新名就被擋;測試檔本身不需要家、也當不了家,沒有合法出口。這次讓「只換、加、刪測試綁定標記」的改動不算寫說明。

依據:[[Projects/交接2026-10-03_計劃]]〈rtb 第三輪提案〉第 4 優先的 D2;那篇有一條 2026-10-15 到期的回頭條件。

PRIOR-ART: Git 的 `diff --ignore-matching-lines`(`-I<正則>`)與 GitHub CODEOWNERS 之外常見的「只有格式或簿記的改動不需要審」做法,都是先把不算數的部分正規化掉再比;本案同一招,只拿掉綁定標記。同專案:行內標記的辨認已有 `slot_parse` 一套(`_SLOT_KEY_RE` 認鍵、`_SLOT_CANON` 正規化大小寫、`_slot_value_end` 數方括號層數找收尾、行內程式碼不算欄位),本案沿用它的零件、不另寫掃描器;判斷「內容有沒有變」本來就只比摘要、決策、正文三欄,`updated`、驗證連結這類開頭欄位早就不算(`_nodehome_parse_note` 的 sig,推送前逐提交那條也共用);筆記形狀擋認「舊行尾補括號不算新寫」(`_ns_is_tail_append`)是另一條規則,本案不沿用它的括號豁免,理由見摘要。
RETIRE-IF: 有人回報有人把說明藏進測試綁定裡繞過寫回落點(新名稱已限定成指得到真測試的單一識別字,剩下的是「說明剛好寫成一個真測試名」),就把豁免收窄到只認「上一版的名稱在這次被刪掉的測試裡、新名稱在這次新增的測試裡」(改名配對);或連續一季兩個專案都沒有任何提交因為這條放行(推送前帳本看不出時人工抽查),表示需求消失,可以撤掉。

## 範圍

- 做:提交前與推送前兩條路判斷「這篇內容有沒有變」時,兩版只差測試綁定、而且這次★新出現★的綁定都站得住,就不算寫說明:新的 `[test:]` 名稱要是單一識別字(可帶平台前綴;帶點號、::、#、空白的不豁免,代碼審 r3)而且指得到真測試;新的 `[test-gone:]` 名稱要跟上一版的某個 `[test:]` 整串一致(不去平台前綴,前綴不核對就能夾帶說明,代碼審 r3fix;用意是「測試刪了、改標成已刪」,但程式只核對上一版綁過這個名稱,不核對那支測試真的刪了),`@` 後面只認 7 到 40 碼小寫十六進位的提交編號(一般綁定的值也套);拿掉綁定不核對(刪資訊不是寫說明)。★自己核對、不靠「筆記測試綁定要存在」補洞★(代碼審 r2:那道對 test-gone、合約行不核對名字,單次跳過、降級時也不核對,一句英文說明會兩道都過)。
- 做:辨認標記照行內標記解析 `slot_parse` 的既有判法,★逐行★處理:鍵、冒號、值從哪裡收尾、行內程式碼(同一行裡成對的反引號)裡的不算、不成對的反引號到行尾都當正文、方括號沒收尾的整段照留、寫在別的欄位值裡面的(例:`[不選:… [test:x] …]`)算那個欄位的一部分不拿掉。程式碼圍欄裡的行整行照留。
- 做:只拿掉值「像測試名」的:值去頭尾空白後不是空的、至多 200 個字,字元只有英數、底線、點、冒號、斜線、井號、@、逗號、連字號、空白、半形圓括號、方括號、單引號、`>`;另可整段包在一對反引號裡,反引號裡面套同一組字元。值裡有中文或其他字的不拿掉,照舊算內容。拿掉之後還要過上一條的真測試核對。
- 做:空白規則:標記前面有正文、後面不是緊接著字(空白、標點、行尾),就連前面的空白(半形、tab、全形)一起拿掉,後面緊接著英數或中文就留著前面的空白(不把原本沒有的空白當成沒變,代碼審 r3;標點那半是 r3fix),前面只有縮排或什麼都沒有就改拿後面緊接的空白;其他空白照比(只改縮排、圍欄裡的空行照樣算內容有變,代碼審 r2 邊界席、正確性席)。一行拿掉標記後只剩空白或清單符號(`-`、`*`、`+`、`1.`、`1)`,沿用既有的 `_NOTELINES_BARE_LIST_RE`;核取方塊行不算在內,勾選狀態是內容)的整行不算,它前後都是空行時多出來的那個空行也不算。每行去尾端空白,跟原本的比法一樣。
- 不做:更正括號、現況句改寫、回頭條件改綁的豁免(都是散文,照舊算寫說明;拆兩個提交是既有出口)。
- 不做:讓測試檔可以當家。
- 不做:`[confirmed:日期]` 這類行內日期欄位的豁免(沒有回報被擋,先不放)。
- 不做:筆記形狀擋那邊的放行。換綁定的那一行對筆記形狀擋仍是新寫的行,那一行本身要合格(例:沒帶來源的 FACT/FLOW/DEP 行照擋)——本案只管「每支檔有家」。

## 做法

1. 在 `slot_parse` 旁邊新增兄弟函式 `_slot_strip_keys(line, keys, keep)`:掃描邏輯跟 `slot_parse` 同一套,回「(拿掉指定鍵的欄位後的那一行, 拿掉的欄位 [(鍵, 值)])」;`keep(值)` 回真的那個欄位照留;空白照〈範圍〉第四條。兩支共用掃描:把 `slot_parse` 的迴圈抽成一支逐段吐「正文片段/欄位(鍵、值、起訖位置、錯誤)」的產生器 `_slot_scan`,掃描規則只有一份。
2. 新增 `_nodehome_test_tag_value_ok(v)`(〈範圍〉第三條的值判準)與 `_nodehome_strip_test_tags(text)` → (拿掉綁定後的文字, 拿掉的綁定 {(鍵, 名稱)}):`_visible_lines` 取圍欄外的行號,圍欄裡的行原樣放回,圍欄外的行逐行呼叫 `_slot_strip_keys`;名稱照 `_test_names_of` 的切法(逗號切開、去反引號、test-gone 去 @提交)。
3. `_nodehome_parse_note` 原本的 sig 不動,另加 sig_t(摘要與正文過 `_nodehome_strip_test_tags`;決策欄不動)與 tag_names。新增 `_nodehome_tag_only_change(b, n, judge)` 判〈範圍〉第一條;`_nodehome_tag_judge(repo_root, tip)` 共用筆記測試綁定要存在的 `_NsTrJudge`(提交時只查測試索引,推送時再到終點版本找),推送時 `_ns_tr_guard` 說測試索引對不上被推的版本就回 None(不豁免)。home check 建一個用到才建的判定交給提交前(`_nodehome_evaluate`)與推送前逐提交(`_nodehome_mark_note_content`)。
4. 寫回圖譜:[[Systems/每支檔有家]] 摘要加一行 WHY;同篇兩行現況說明一起改(簿記不算寫回那句、唯一合法寫法那句)。[[Systems/筆記內容閘]](`slot_parse` 的家)加一行 WHY 記共用掃描與兄弟函式。[[Projects/每支檔有家_計劃]] 的「內容有變」定義、[S12]、唯一解法那句補例外。
5. 上線後告訴 rtb:可以重做 2026-10-03 放棄的那次測試改名,並關掉交棒單那條回頭條件;同時講明筆記形狀擋那邊照常(換名那一行本身要合格)。

## 實務隱患

- **藏說明**:新出現的 `[test:]` 名稱要指得到真測試、新的 `[test-gone:]` 要是上一版綁過的,一句英文說明包成綁定(不管在一般行還是合約行)都不算只換綁定([S6] 實測)。剩下的洞:說明剛好寫成一個真的測試名(Jest、Kotlin 的測試名本來就是句子),見〈天花板〉1。
- **判定的測試索引跟被推的版本對不上**:推送時目前簽出的不是終點、或工作目錄有沒提交的測試或設定改動,一律不豁免(照舊擋),不冒「索引說有、被推的版本其實沒有」的險;CI 的工作目錄就是終點,不受影響。
- **誤判沒變**:只有綁定標記被拿掉;同一行其他字、縮排、圍欄裡的空行有改照樣算內容有變;行內程式碼、程式碼圍欄裡的舉例、寫在別的欄位值裡的不拿掉。
- **抽共用產生器改到 `slot_parse`**:`slot_parse` 是筆記格子、測試綁定、回頭條件好幾道檢查的共用解析,抽迴圈要保證輸出逐字不變——既有 slot 系列測試全綠,另有 [S5] 對全 repo 筆記逐行比對。
- **提醒多唸**:只換綁定的那篇如果正好是改動檔的家,「該動哪篇」的提醒(只提醒不擋)會照樣說「它的家這次沒動」——那篇確實沒寫說明,提醒是對的。
- **效能**:sig_t 每篇多一次逐行掃描,跟 `slot_parse` 同為線性;測試名判定要掃測試檔建索引,只在某篇「sig 不同但 sig_t 相同」而且有新出現的單一識別字 `[test:]` 名稱時才建,一次執行最多建一次。
- 已排除:金流:只改判定邏輯與 slot_parse 的內部寫法
- 已排除:對外送出:不連網,也不寄送任何東西給外部
- 已排除:不可逆:不寫任何檔,只改判定邏輯與 slot_parse 的內部寫法(輸出不變,由 [S5] 釘住)
- **守衛面(沒排除,本案就是放寬一道會擋提交的檢查)**:放寬的只是「內容有沒有變」這個判斷;它同時影響寫回落點與「有寫回時改動檔要有家」兩條(後者本來就該跟著放,見 [S3]),新增沒家、家被拿掉、寫進別人檔名、負責範圍那幾種判定不讀這個值,不變。

## 驗收條款

- [S1] 當同一個提交改了 A 的程式、另一篇 B 只把 `[test:舊]` 換成指得到真測試的 `[test:新]`、多加真測試的綁定(逗號清單、鍵大寫、全形冒號照認)、刪掉一個綁定、把上一版綁著的 `[test:x]` 改成 `[test-gone:x@提交]`、或同一個提交把測試改名而 B 換成新名時,提交前的 home check(`--staged`)應 回 0;B 同時改了一個散文字、新加的綁定指不到真測試(英文句子、不存在的名稱、反引號英文句子)、新寫的 `[test-gone:]` 不是上一版綁過的名稱、新名稱不是單一識別字(一句說明.真測試名、不存在的類別.真測試名、類別::方法、類別#方法)、`[test-gone:]` 的名稱跟上一版綁的不是整串一致(多了平台前綴或一串連字號英文前綴)、@ 後面不是小寫十六進位提交編號(一般綁定帶 @ 也算)、綁定標記的值是中文、空的 `[test:]`、或改的是行內程式碼裡舉例的標記時 應 回 1 並點名 B [test:t_nodehome_test_tag_only_edit_is_not_write_back]
- [S2] 當推送範圍裡某個提交改了 A 的程式、同一個提交裡 B 只換測試綁定時,推送前的 home check(`--diff`)應 回 0;同一個提交裡 B 改了散文時 應 回 1 [test:t_nodehome_diff_test_tag_only_edit_is_not_write_back]
- [S3] 當同一個提交改了一支原本就沒家的舊檔、另一篇只換測試綁定時,應 只提醒沒家(回 0),不報「有寫回時每支改動檔都要有家」 [test:t_nodehome_test_tag_only_edit_is_not_write_back]
- [S4] 當 B 的改動是跨三行的假標記(第一行開了綁定標記、第三行才收尾)、前一行有落單反引號而下一行行內程式碼裡的舉例標記被改、程式碼圍欄裡的標記被改、寫在別的欄位值裡的標記被改、方括號沒收尾的假標記、只有空白的值、值超過 200 字、反引號裡寫中文、pytest 參數化名稱(核對不了真測試)換名、只改縮排、圍欄裡少一個空行、標記插在兩個字中間(前有空白後緊接字)、或只剩綁定的核取方塊從未勾改成勾時,提交前的 home check 應 回 1;單獨成一行的綁定(清單符號加標記,含夾在空行之間的)被加或刪、標記在行首或縮排後面或前面是全形空白或 tab、標記後面緊接句號或全形逗號、整篇換成 CRLF 時 應 回 0 [test:t_nodehome_test_tag_strip_edges]
- [S5] 當 `slot_parse` 改成走共用產生器之後,對本 repo 圖譜每一篇筆記的每一行,輸出 應 跟改之前逐字一樣(改之前的輸出用測試裡留的舊版實作算),而且 `_slot_strip_keys` 拿掉全部鍵後去掉空白 應 等於 `slot_parse` 的核心一句去掉空白 [test:t_slot_parse_unchanged_after_scan_refactor]
- [S6] 當推送範圍裡某個提交改了 A 的程式、又在 B 的合約行新寫指不到真測試的 `[test:英文句子]`、或新寫上一版沒綁過的 `[test-gone:英文句子]`(帶不帶 @提交)時,推送前的 home check 應 回 1 並點名 B;新寫的是真測試時 應 回 0;推送時已追蹤的測試檔有沒提交的改動、或推送的不是目前簽出的版本時 應 不豁免、回 1 [test:t_nodehome_tag_only_new_names_must_be_real_tests]

## 回退

還原本案的提交即可:只改判定用的正規化與 `slot_parse` 的內部寫法(輸出不變),不寫任何檔、不改帳本格式。

## 天花板

1. 說明剛好寫成一個真的測試名(例:Jest、Kotlin 用句子當測試名,`[test:a retries three times]` 而且真有這支測試),工具分不出它是綁定還是說明;靠 RETIRE-IF 的回報觸發收窄。
2. 更正括號(行尾補一段「(更正:…)」說明舊句錯在哪)、現況句改寫仍算寫說明;跟程式改動混在同一個提交時要拆提交。
3. 現存筆記裡有些 `[test:]` 的值帶中文說明(例:「綁的是某某那半」)、帶白名單以外的符號(`$`、`=`、`*`、`!` 等)、或是核對不了的寫法(pytest 參數化名稱帶方括號),這種換名照樣算寫說明、照樣擋——要嘛把說明移出標記,要嘛拆提交。
4. 本案只放「每支檔有家」;換綁定那一行在筆記形狀擋照樣算新寫的行,那一行本身要合格。
5. 推送時目前簽出的不是終點(例:`git push origin 別的分支`)、或工作目錄有沒提交的測試或設定改動,一律不豁免;簽出要推的那條、或交給 CI。
6. 把綁定改成 `[test-gone:]` 只接受上一版就綁著同一個名稱的;直接新寫一個 test-gone(沒綁過)算寫說明。
7. 新名稱只收單一識別字:Java 的 `類別#方法`、`類別.方法`、C# 的 `類別::方法`、Kotlin 反引號句子測試名、帶連字號或括號的名稱都不豁免(誤擋方向,照舊拆提交)。專案沒設 test_profile 時測試索引照預設棧掃,掃不到就一律不豁免。
8. 提交前只查工作目錄掃出來的測試索引:測試檔改了名卻沒 git add,提交前會放行;推送前到被推的版本裡再找一次會擋回來(代碼審 r3 判定路徑席實測)。
