# 撤除候選也看manual條款_計劃

白話:健檢 S20 有一類「撤除候選」——計劃的驗收條款下一層寫了「撤除」,條款本身卻沒標作廢,提醒人補標。它原本只看掛 `[test:]` 的條款;掛 `[manual:]`(靠人驗、沒有測試)的條款寫了撤除也不會被列,rtb 一次漏了七條。這次讓它也看 `[manual:]` 的條款。

依據:rtb 2026-10-06 盤點 C5;rtb 2026-10-03 第三輪回傳第 7 點。

PRIOR-ART: 沿用 S20 既有的散文撤除候選判法(`_ns_tr_sub_says_retire` 看下一層、`_ns_tr_retired` 判已作廢、裁定後接改寫保留不算),只放寬「條款要綁了什麼」與入口篩選;「已寫成已撤除的 `[manual:]`」沿用條款綁測試算進度的寫法(`[manual:已撤除,見 …]` 就是撤除後的正式寫法)。
RETIRE-IF: 計劃條款不再用 `[manual:]`(例如改成一律綁測試或另一種人工驗證標記),這條放寬跟著改。

## 範圍

- 做:S20 入口篩選除了整篇有 `[test:]`,整篇有 `[manual:]` 的計劃也看。
- 做:散文撤除候選的條件從「條款綁了測試名」放寬成「綁了測試名,或掛了 `[manual:]` 而且內容不是以『已撤除』開頭」;已標作廢、下一層沒寫撤除的照舊不列。
- 做:列出的那行講清楚是哪一種(`[test:]` 或 `[manual:]` 條款);修法提示講標作廢、`[test:]` 改寫成 `[manual:已撤除,見 …]`。
- 不做:擋下(S20 這類照舊只提醒)、自動標作廢。

## 實務隱患

- 已排除:金流:只改 doctor 的列出,不碰任何金流
- 已排除:對外送出:不連網、不送任何東西出去
- 已排除:不可逆:不寫任何檔,退回提交即恢復
- 已排除:守衛面:S20 只提醒不擋,不改任何閘的判定

## 驗收條款

- [S1] 當計劃條款只掛人工驗證標記、下一層寫了撤除、條款沒標作廢時,doctor S20 應 列進散文撤除候選並講是 `[manual:]` 條款(整篇沒有 `[test:]` 也一樣);`[manual:]` 已寫成已撤除、條款已標作廢、下一層沒寫撤除時 應 不列 [test:t_doctor_s20_prose_retire_manual]

## 回退

退回本案的提交即可:只改 doctor 列出的範圍。

## 天花板

1. 只認「已撤除」開頭的 `[manual:]` 為已處理;寫成別的說法(例:「已移除」)照樣會被列,人看一眼補標作廢即可。
2. 同一個條款編號定義兩次、或合法定義後又出現在認不得的清單行時(條款解析判成重複或被遮),掛 `[manual:]` 的那條不列(掛 `[test:]` 的照舊列第一條):條款解析把它判成重複、spec-trace 與處置閘都標錯要人先修;為了讓這條路一致而把單行丟回解析器重判,是第二套判法(2026-10-07 代碼審跑滿三輪,Enzo 裁)。
