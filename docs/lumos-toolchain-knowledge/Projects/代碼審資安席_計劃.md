# 代碼審資安席_計劃

> 白話:高風險的代碼審,一律多派一席專門從攻擊者角度看這份改動;收斂判定多一個條件——整個審查迴圈裡,至少要有一輪真的派了資安席、而且它的報告記進了帳,不然不給收斂。

## 緣起

- 2026-09-11 治理日報四篇,其中兩篇直接相關:掃 3,171 個 AI 助手設定倉庫有 16% 帶安全缺陷(這套自己就是往別人機器裝 hook 的分發者);以及「機器算得出來的判定,該擋在動手那一刻,不是推到審查員眼前指望它自己想到」。
- Enzo 問「code loop 的分席鏡頭有資安角度嗎」。查的結果:**沒有,而且是刻意的**——[[Systems/pitfalls-code-loop]] d5(2026-08-27)明文排除,理由「單人私有 repo、非對抗威脅」,回頭條件「工具鏈真的吃不可信外部輸入時重拉」。
- 現況(我查一次、另一個乾淨 agent 用原始問題獨立再查一次,2026-09-11,兩邊一致):
  - 代碼審 skill 全文沒有「安全 / security」;編制表沒有資安席;風險掃描的類軸只有併發 / 效能 / 資源。
  - 190 份派工單裡有 8–9 個迴圈臨時加過帶安全味的鏡頭(兩次查的關鍵字口徑不同,差一個),沒有任何規定要求。
  - 本機 9 個消費專案的派工單,沒有一份用過資安鏡頭。
  - 技術棧慣例 skill 只有 node-idioms 有資安條款;linter 目錄列了資安類 linter,但擋推送那條鏈恆 `--no-lint`(2026-08-26 d4)。
- d5 的前提已經對不上:repo 在 GitHub 上是 **PUBLIC**(`gh repo view` 2026-09-11 查;8/27 當時是不是公開沒查),README 教陌生人一行 `curl … | bash` 安裝;2026-09-06 [[Systems/hook信任邊界]] 實地重現「打開陌生 repo 時進場 hook 執行對方的程式」——那就是 d5 自己寫的回頭條件。而那條回頭條件是純散文、節點裡 REVISIT 行 0 筆,所以沒人被叫回來看。

## 人裁(Enzo 2026-09-11,三問三答)

1. 「消費級的專案必須要有資安鏡頭」——範圍 = 所有接了 lumos 的專案(選項:全部 / 只有對外給一般使用者用的產品;後者要人標記、標錯就漏)。
2. 觸發範圍 = **只在代碼審本來就有跑的時候加一席**(選項:另給風險掃描加「資安」類、碰到敏感程式就判高風險 / 只在 high 代碼審加一席)。代價寫在〈承認的限制〉。
3. 「工具鏈也納入吧」——所以規則不分專案:**所有專案的高風險代碼審一律必派資安席**,不需要分辨「是不是工具鏈自己」。

PRIOR-ART: ①最小解層級=既有處置閘加一步(照 `_disposal_clause_step` 的形狀)+既有編制表加一席+既有派工範本加一節;不新增指令、不動 `code-loop pass` 介面 ②世界解過:Anthropic `claude-code-security-review`(五類清單、硬排除清單、信心 <0.7 不報、每條必附 exploit_scenario;2026-09-11 讀 claudecode/prompts.py)(Anthropic 官方公開的代碼資安審查 GitHub Action)、OWASP Top 10(網頁應用最常見的十大風險清單)與 MASVS v2(OWASP 的行動 App 安全驗證標準) ③裁定=借用:資安席「看什麼 / 不報什麼 / 嚴重度錨」照 Anthropic 那份改寫、行動端補 MASVS;閘與編制照本 repo 既有架構加一小段自建;零新依賴

## 條款

- [S1] 編制表:`("code","high")` 加一席 `資安`,派工要求用新值 `required-gated`(必派,而且由處置閘硬擋);設計審各級、代碼審 standard 不加 [test:t_roster_code_high_has_security_seat]
  - 為什麼用新值、不沿用 `required`(r1 架構對齊 D1、整合 C4):表裡「架構對齊」標的 `required`、「外家否決」標的 `required-fail-closed` 一律只提醒不擋——席位對帳只轉述、不裁決。資安席是第一個真的會擋的席,用不同的值把「會擋」寫在表上,而不是讓同一個 `required` 有兩種意思。**只有人裁能把一席標成 `required-gated`**(本案依據 d6)。
  - 席位對帳(`_roster_observe`)的人數對帳照舊只數 `required` / `required-fail-closed`,不數 `required-gated`——否則生效日前已經合規收斂的舊 high 迴圈,重問一次就會被追溯貼上「席數不夠」,污染 2026-11-26 靠 `roster-alerts.log` 做的退場盤點。`required-gated` 席有沒有出席,由處置閘那一步負責。
  - `loop next` 照樣把這一席印出來,派工要求那欄印成人看得懂的「必派(問閘會擋)」。
  - 家族預設同門(相對於編排者),理由是外家額度:high 已經固定要兩席外家(找洞、否決),再多一席外家容易一輪吃光額度、退回「沒有外家席」(`Issues/外家席長期缺席仍照跑loop` 的前科;額度數字見 templates.md §3 ④ 的註記,未實測——這一句是推論,不是量過的)。**閘只看鏡頭、不看家族**,編排者可以改派外家模型坐這一席(r1 通才 A1)。
  - 既有測試 `t_loop_next_roster` 斷言「code/high 不佔 W 的席有 3 席」,加席後變 4,同一次改動一起更新(r1 通才 A2)。
- [S2] 處置閘加「資安席」一步:對「迴圈種類是 code、定錨分級是 high、首筆帳列時間 ≥ 生效日」的迴圈,要求編制表上每個 `required-gated` 席都有出席、留痕對得上,而且它看過的檔涵蓋最後一版 [test:t_disposal_security_seat_required]
  - ★編號 code 開頭卻不是 code-(看不出是設計審還是代碼審)→ 照最嚴的當代碼審★(代碼審 r1 通才 A2:原本整步跳過,換個名字就繞過;條款綁定那一步對同一種編號也是照它自己最嚴的方向判)。
  - 名字與形狀照 2026-09-08 條款綁定那一步(`_disposal_clause_step`):獨立函式 `_disposal_security_step`,回 fail / ok / skip,自己印一行,fail 時把 `資安席` 加進 fails。★不叫「第五條」★——處置閘的第五步已經是條款綁定;加上這一步,處置閘共六步(G3 hash 鏈、處置集合、留痕、quote-check、條款綁定、資安席)。`_loop_status_disposal` 說明文字還寫「四條合取」是過期的,實作時一併改正。
  - **分級看定錨分級**:帳上第一筆帶 tier 的值,跟 `loop next` 同一個判法(抽成共用小函式,兩邊呼叫同一支)。不用「任一筆 tier=high」:寫帳那側不擋中途改 tier,用「任一筆」會對一個從沒被派過 high 編制的迴圈要求資安席,只能整個編號重開(r1 邊界 B3)。
  - **怎麼算「有資安席」**:席名用連字號切開,**任一段完全等於「資安」或「security」(英文不分大小寫)** 就算——`資安-sonnet`、`資安-gpt-5.6-terra`(模型名自己帶連字號)、`s4-資安-sonnet`(前面帶席號)都算;`資安審-sonnet`、`非資安-sonnet` 不算(整段相等,不是子字串)。原本的「取最後一個連字號前那段」會把模型名帶連字號的真實命名判成沒有——帳上 308 個席名有 109 個帶兩個以上連字號(r1 邊界 B1、整合 C1)。
  - **留痕**:那筆的報告檔(`report_path`)要在、sha 要跟 `report_sha256` 一致。現況:處置閘的留痕重驗是寫在閘裡的迴圈,判定輪一段、intake 一段各抄一份,沒有可呼叫的函式;實作時把「單一帳列的報告檔在且 sha 對」抽成一支小函式,原本的留痕重驗與這一步共用,不抄第三份。
  - **看過的檔要涵蓋最後一版**(設計審 r1 外家否決 E1;★代碼審 r1 通才 A1/資安 C1 改成比內容★):代碼審每輪的凍結材料是整條分支的 diff(`git diff <merge-base>..HEAD`),所以可以機械比——判定輪凍結 patch 裡每支檔的「改動指紋」(hunk 裡的增刪行、上下文行、`@@` 後的段落標頭+mode/改名/二進位檔頭;不算行號與 index 那行),要在某一筆資安席帳列的凍結 patch 裡找到同檔名、同指紋;沒看過的檔、或看過但之後內容又改了的檔 → fail,訊息分開點名。原本只比檔名,同一支檔換成含後門的內容照樣 PASS(兩席各自實跑重現)。只差行號(rebase 常見)仍算同一版;上下文變了就算改過——只算增刪行時,同一段 `-check(user)/+allow(user)` 從公開端點搬到管理員端點指紋完全相同(代碼審 r3 外家否決 Codex 實測),代價是 rebase 後這段附近的程式也變了,資安席要對最新版再看一次(誤擋方向)。檔名取 `b/` 那側(改名取新名);git 預設會把中文等非 ASCII 檔名加引號、寫成八進位跳脫(`core.quotePath` 預設開,本 repo 滿是中文檔名)。★源頭照專案慣例關掉★:代碼審 SKILL 的凍結指令改成 `git -c core.quotePath=false diff …`(代碼審 r1 架構對齊 B1,同本 repo 各處 git 呼叫);讀的一側仍容錯還原,因為凍結 patch 是編排者自己產的輸入,舊迴圈或別家編排者會帶引號。只去掉行尾換行、不削空白——檔名尾端空白是檔名的一部分(代碼審 r1 外家否決 E1)。2026-09-11 鏡像核對後實看兩個真實代碼審的凍結 patch(`code-工具自裝檔不算消費專案` r1–r4、`code-差異讀取遇到非UTF-8` r1):都是標準 unified diff,每檔一行 `diff --git a/… b/…`,抓得出檔案清單。這擋住「前輪資安審的是 A、後面換成審不相干的 X」,也擋住「修正時新碰了一支檔、資安角度沒人看過」。同一支檔在資安審之後又改了內容,也算沒看過(比的是改動指紋)。
  - **看整個迴圈,不是每一輪**:判定輪常是只複查修正處、只派一席的 delta 輪,逐輪要求會誤擋。
  - **凍結 / 回放**(r1 外家否決 E2):凍結時把資安席帳列的報告檔與凍結 patch 也收進凍結閉包(`files`),跟判定輪的檔一樣要求進版控;這一步在凍結 / 回放模式下照樣重讀報告檔、比 sha。所以即時問閘判不過的,凍結重算也判不過;回放的完整性檢查也蓋得到那些檔。原本寫的「凍結模式只看帳列、不重讀報告檔」刪除——那樣會把即時判不過的洗成通過。
  - **訊息**(r1 通才 A4、架構對齊 D3):成立印 `[disposal] 資安席: ✓ — <輪> <席名>(看過的檔涵蓋最後一版 N 個)`;不成立第一行照鄰居形狀印 `[disposal] 資安席: ✗ — <缺什麼>`,接著照工具輸出白話三段式,各一行寫為什麼在意、下一步指令獨立一行;跳過印 `[disposal] 資安席: —(原因)`。找不到資安席時,把這個迴圈帳上出現過的席名列出來,命名寫錯的一眼看得出來;補救是用正確席名把同一份報告再記一筆帳(帳本只能追加)。
  - **退出碼**:不成立 → 問閘未過(退出碼 1;退出碼 2 保留給帳面壞或參數錯)。
  - 讀側可重算:只讀帳本、報告檔與凍結 patch,不信寫側。
- [S3] 生效日:常數 `_SECURITY_SEAT_SINCE = "2026-09-12T00:00:00+08:00"`,寫法與比法照 `_CLAUSE_GATE_SINCE`(用 `_loop_ts_key` 比;帳上 ts 讀不動或沒時區 → fail,壞資料不放行) [test:t_disposal_security_seat_cutoff]。迴圈首筆帳列時間早於它的,這一步印一行「生效日前開的迴圈,不要求資安席」並回 skip。理由:同一個工作目錄的其他會談當天已開的代碼審,不該在拉到新版後突然被擋。

## 邊界與不做

- 不改風險掃描的觸發條件(人裁 2);不改代碼審 standard 與設計審的編制;不把 linter 接進擋推送的鏈(d4 維持);不動 `code-loop pass` 指令。
- 「安裝收據 / 重裝預演」是另一案,還在等人裁,不併進來。

## 承認的限制(每條附回頭條件)

- **只有 tier high 才審資安**:只改登入、權限、密鑰這類程式、卻被判成 standard 的改動,沒有人從資安角度看。這是人裁 2 選的取捨。

## 實務隱患

- 併發:資安席這一步只讀帳本、報告檔與凍結 patch,不新增任何寫入;帳本被別人同時追加、讀到半行的情況,即時問閘已經 fail-closed(壞行直接退出碼 2),這一步跑在它之後。凍結入口遇到讀不懂的帳列是跳過——既有行為,不是本案造成,本案不改。無新增併發面。
- 效能:掃的是「這一個迴圈」的帳列(實際一個迴圈幾十筆以內),加上資安席報告算 sha、讀幾份凍結 patch 的檔頭行;問閘是人手動問、推送前一次,不在熱路徑。無。
- 資源:讀檔走 [S2] 抽出來的單列留痕小函式;不開連線、不拿鎖。無(r1 外家否決 E5:原句說「既有函式」,跟 [S2]「現在沒有可呼叫的函式」自相矛盾)。
- 守衛面(這本身就是一道閘):誤擋與漏擋兩邊都要顧(r1 邊界 B2 指出原清單不完整)。誤擋——判定輪只派一席、生效日前開的迴圈、席名沒帶模型尾碼、模型名自己帶連字號、席名前面帶席號、Codex 編排、帳上中途改 tier、舊迴圈被席位對帳追溯貼標籤:在 [S1][S2][S3] 處理。漏擋——席名亂取、`code-loop pass` 不回頭驗問閘:寫在〈承認的限制〉附回頭條件;「同一支檔在資安審之後又被改」原本列在這裡,代碼審 r1 後改成比改動指紋,已擋得到。
- 可逆性:純程式與文件改動,revert 就退;帳本格式不變(不加欄位),舊帳不用遷移。
- 凍結判定與回放:凍結下來的判定(`verdict: {rc, fails}`,fails 是 `G3`、`留痕`、`條款綁定` 這類短標籤)會多一個可能的 `資安席`;凍結閉包多收資安席的報告與凍結 patch。生效日前的迴圈這一步回 skip、不進 fails、也不多收檔,所以已凍結的舊判定回放時結果不變;這點要有測試釘住(驗收最後一條)。
- 金流(pitfalls 命中 payment):不適用——本案不碰任何金流程式;計劃裡「金流」只出現在「敏感檔案形狀」的舉例。
- 對外送出(pitfalls 命中 external-send):不適用——不對外送任何東西;資安席是本機子代理,跟其他審查席同一條路。
- 認證 / 個資 / 快取 / 遷移 / 限流 / 狀態同步:本案不碰這些程式;它們是資安席要審的對象,不是本案的改動面。

## 驗收(測試先行,每條先紅後綠)

- code 迴圈、定錨 high、生效日後、帳裡沒有資安席 → 問閘未過(退出碼 1),訊息含「資安席」、列出帳上出現過的席名、附下一步指令。
- 同上但有一筆 `資安-sonnet` 帳列、報告 sha 對、它的凍結 patch 檔案清單涵蓋判定輪全部檔 → 資安席這一步 ok(其餘各步照舊判)。
- 資安席帳列在,但事後報告被改(sha 不符)→ 問閘未過(退出碼 1)。
- 資安席在 r1、判定輪 r2 的 patch 多一支 r1 沒有的檔 → 未過,訊息點名那支檔;r2 的 patch 檔案清單是 r1 的子集 → ok(迴圈層級,r1 外家否決 E1)。
- 席名 `資安`、`資安-gpt-5.6-terra`、`s4-資安-sonnet`、`Security-codex` 都算;`資安審-sonnet`、`非資安-sonnet` 不算(r1 邊界 B1、整合 C1)。
- 凍結 patch 檔名解析:同一支中文檔名,一份用 git 預設(加引號、八進位跳脫)、一份用 `core.quotePath=false` 產生,判成同一個檔;改名取新名;檔名尾端空白保留(`app/login.py` 與 `app/login.py ` 是兩支) [test:t_patch_parse_keeps_trailing_space]。
- 資安席看過的檔之後內容又改了 → 未過並點名;只是上下文與行號變了 → 仍算涵蓋;編號 code 開頭不是 code- 的高風險迴圈沒派資安席 → 不過 [test:t_disposal_security_seat_content_and_id]。
- 定錨分級 standard(即使後面有一筆 tier=high)→ 不要求(r1 邊界 B3);設計迴圈 → 不要求;生效日前的迴圈 → skip 且印一行說明;帳上有一筆 ts 讀不動 → fail(壞資料不放行)。
- 凍結:資安席報告在凍結前已被改 → 凍結重算同樣判不過;凍結閉包含資安席的報告與凍結 patch(r1 外家否決 E2)。
- 編制表:`loop next code-x --tier high --orchestrator claude` 與 `--orchestrator codex` 都印出資安席、派工要求顯示「必派(問閘會擋)」(r1 外家否決 E6);`t_loop_next_roster` 的不佔 W 席數更新為 4(r1 通才 A2)。
- 席位對帳:生效日前、同門 5 席的舊 high 迴圈(`code-batch2` 那種形狀),加席後重問不冒新的席數不夠異常(r1 整合 C4)。
- 文件同步守衛:[S5] 清單上每個檔都提到資安席;清單上的檔都不再寫「四條合取」;設計審派席說明沒有資安席。
- 既有測試:roster / disposal / loop_next / replay 相關子集全綠。
- 凍結判定回放:生效日前已凍結的代碼審迴圈,回放判定不因資安席這一步改變。
