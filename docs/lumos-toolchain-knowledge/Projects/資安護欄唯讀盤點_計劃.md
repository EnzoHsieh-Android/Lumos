# 資安護欄唯讀盤點_計劃

## 目的與授權

白話：把專案的安全護欄、證據與缺口攤在一張清單上；清單讀完不代表產品安全。

依[[Projects/消費專案產品安全Brief與證據驗收_計劃]] d5、d6，獨立設計唯讀盤點指令。Invariant仍是通用合約；安全要求可引用Invariant或獨立政策。設計處置閘的已通過版本及指紋見governance/replay/資安護欄唯讀盤點/verdict.json；status doing涵蓋後續實作與驗收，不代表指令可用。接手須核對凍結版本與目前差異，不把歷史通過移用到變更後的契約。

與前導提問及測試品質的整合分工見母計劃d7及同名小節。設計審凍結版本（verdict.json 的 spec_sha f78f0678…）之後，本篇新增了：兩段成熟度指路文字、S1–S13 由 manual 換成實際測試綁定、決策 d1（七處保守做法）、待決 Q1（分類與標籤由誰審）與 Q2（order-demo 要不要登記）、決策 d2–d4（讀取家族、「已登記」與映射、dirfd 例外），以及代碼審 r1、r2、r3 折入的輸出契約新增（見〈輸出契約〉末段三段：registration_valid 與 invalid_registration_control_ids、tag_format_unrecognized、每條控制項的 references_valid、coverage.surfaces[] 每列的 invalid_reference_control_ids、errors[] 的 vault_selection_failed 與 errors_truncated、文字模式的欄位上限與資料框）。登記 schema 與 S1–S13 的條文文字沒有改，但輸出契約比凍結版多了上面這些；既有凍結卷證保持原樣。盤點引用Verification，原始收證與判準核對仍由母計劃及既有測試品質流程承接。

母計劃Q3管故障執行（已依母計劃d8決定）、Q4管正式交付接線（已依母計劃d9決定，閘門由另一份子計劃實作）；本案不執行這兩種行為，也不改其狀態。實作須先過本案規格閘與必要設計審，不因唯讀而略過輸入安全、錯誤處理及證據語意檢查。

## 世界解、最小解與落點

PRIOR-ART: 借用[NIST OSCAL的要求／實作／評估分層](https://pages.nist.gov/OSCAL/learn/concepts/layer/)（2026-10-18查閱），僅借資料與結論分離的原則，不實作OSCAL相容格式、不宣稱認證。最小新增是既有CLI的唯讀匯總入口，安全讀取後以Env.from_texts重用既有筆記與合約解析，不直接呼叫load_vault或一般Env(vault)，不引入資料庫、網路服務或第三方依賴。

既有程式導航：CLI的cmd_contracts、cmd_query、cmd_enforcement、load_vault與parse_frontmatter。前兩者作合約與節點查詢參考，enforcement作「盤點不等於正確性判定」的介面參考；不能把工具鏈掛鉤生效與消費產品安全混在一張清單。實作前讀[[Systems/lumos-cli-read]]的合約，不改search既有過濾語意。

lands_in採[[Systems/lumos-cli-read]]，本案只增加讀取與展示；若實作需要拆出獨立程式檔，先建負責解析與盤點的新System家，再修改lands_in，不擴充既有合約語法來承載安全分類。

## CLI契約

候選入口：`lumos security list`；JSON模式：`lumos security list --json`。沿用全域vault選擇，未明確選定唯一vault時報錯，不在多專案間猜測。首版無篩選旗標、無自動寫入、無自動執行測試；命令說明及每份輸出均標示「唯讀盤點，不是安全驗收」。

預設列整個選定vault的全部已登記項，包括候選、失效、缺陷、不適用、接受風險與撤除歷史；活躍與撤除分區。未登記分類的既有合約列待分類提示，不自動列為安全護欄；已明確登記business-only者列在excluded_business區（含其來源與排除分類），不混入安全主清單或安全分母。business-only的撤除項也留在此區並顯示lifecycle，不重複列入retired。

退出碼0表示已完整讀取並產出盤點，即使有未驗、缺陷或覆蓋未知；2表示輸入、schema、引用或讀取不完整。兩者都不表示產品安全。JSON頂層固定帶purpose=inventory及security_verdict=not_assessed；無任何overall_pass或安全百分比分數。

## 資料位置與單一來源（候選schema v1）

先採負責功能／政策的Systems筆記正文內專用JSON圍欄 `lumos-security-v1`，不在總表或sidecar複製規則。每篇最多一塊，內容是含schema_version=1、controls陣列與可選inventory物件的JSON物件；只認頂層圍欄，不讀程式碼範例裡的巢狀示例。JSON採標準庫嚴格解析，拒絕重複鍵、NaN、未知schema版本及未列出的欄位；不擴充通用YAML parser。這是實作目標語法，支援資格以S1–S13實作驗證為準，不由設計審通過推定。

選正文JSON而非新增巢狀YAML的理由：避免為本功能擴充通用frontmatter解析；選分散於各System而非獨立權威總表，避免規則有兩個家。代價是新增專用圍欄讀取及嚴格驗證，需由架構席核對是否有更小的既有可用結構。若架構審否決此選擇，先改設計而非並存兩套格式。

圍欄文法：開頭必須在column 0，整行恰為三個反引號加lumos-security-v1；結尾整行恰為三個反引號。不得帶空白尾碼、縮排、blockquote或list前綴；可見區的這些變體若含專用標記列malformed_block，不登記。掃描先辨識一般反引號／波浪號圍欄，其內示例忽略。只對原文含lumos-security-v1字面的篇章檢查嚴格圍欄閉合，未閉合列解析錯誤；無此字面的舊筆記不因一般圍欄錯字變成安全登記錯誤。CRLF按行結尾處理。

圍欄判定沿用既有_visible_lines的唯一狀態機：抽出可回傳區段與未閉合狀態的共用原語，舊_visible_lines仍維持原輸出與寬鬆回退；專用登記消費嚴格結果、不走回退。不得另寫toggle或regex取代同一套邊界判定。重構前先釘住既有四反引號、波浪號、縮排及未閉合回退的測試，新入口另驗嚴格閉合。這是共用解析的保行為重構，不改search或contracts對外語意。

鍵的必填規則：頂層schema_version、controls必填，inventory可省略但不可null；controls下表所有列出的鍵皆必填，僅retirement_reason與replacement_id只在retired時必填、其他lifecycle禁止。source為物件：invariant恰含kind、node、exact_claim、decision_ref；requirement恰含kind、claim、decision_ref。exception非null時三個鍵皆必填，reason及decision_ref不得空。inventory與其assets、surfaces各項列出的鍵皆必填。所有字串除明示null者皆不得空白；陣列可空，但必要資訊為空時列缺項，不當成已核對。replacement_id為既有control ID或null，不得指自己。

### controls每列

| 欄位 | 型別與語意 |
|---|---|
| id、revision | 非空字串；id限ASCII字母數字及點、底線、連字號，專案內唯一且不得因改名重用；revision為需求修訂身份 |
| concerns | 非空去重字串陣列，值僅business、security、unclassified；unclassified不得與其他值並存 |
| source | kind為invariant或requirement；invariant用node與exact_claim定位既有合約，requirement用claim存唯一權威要求文字；兩者皆有decision_ref |
| lifecycle | candidate、active、retired；retired另含同層retirement_reason非空字串與replacement_id字串（無取代者為null） |
| assets、surfaces | 去重字串ID陣列，對應inventory；候選缺盤點時可空但列缺口 |
| scope、trust_boundary、enforcement | 非空文字，描述適用條件、信任邊界與防護位置；未知寫null並列缺項，不虛構位置 |
| legitimate_control、abuse_case | 文字判準，非執行命令；未知null列缺項 |
| required_evidence | 去重字串陣列，首版值為behavior、fault_sensitivity、review、deployment、dependency_scan；新增種類須升schema，不用未知字串冒充已支持 |
| evidence_refs | 物件陣列，每項恰含kind、node；kind採required_evidence同一值域，node為vault內Verification節點完整相對路徑；同一kind/node對不可重複。kind是作者分類，不因連結或分類存在就認定報告真能證明該種類 |
| reported_status | untested、partial、verified、defect、not_applicable；是作者宣告，不是盤點程式認證 |
| status_reason、owner、revalidate_when | 非空文字；未知null列缺項，說明狀態理由、權責人與重驗條件 |
| exception | null或含decision_ref、reason、expires_on的物件，expires_on為ISO日期；不覆蓋reported_status |

Invariant引用只能指到同vault的完整Systems節點（不接受模糊檔名），exact_claim以既有extract_contracts及清除測試／audit等標記後的宣稱全文完全匹配，恰一條才有效；不以子字串比對。合約行是原始規則，JSON不另存claim。獨立requirement的claim只存本欄，正文散文可說理由但不另立同義權威條款。decision_ref採完整節點加dN，引用不存在、已作廢或不唯一的決策均列錯誤。

同一來源被不同ID重複登記時列duplicate_source，不任選其中一條；未分類的候選全部顯示。僅有既有Invariant但無登記引用者列在unclassified_contracts，不直接當安全缺陷，也不宣稱已審過純業務。標籤精確為flag/security-relevant但沒有條目的節點列unregistered_nodes；散文中未登記且無標籤的規則不能靠此工具保證發現。

### 可選inventory物件

整個vault最多一份inventory權威宣告，放在負責資產與入口盤點的Systems筆記；不是額外建立一份controls總表。欄位：revision、decision_ref、assets陣列、surfaces陣列；assets每項含id與description，surfaces每項含id、asset_ids與description。description應講清入口及信任邊界。ID在各陣列內唯一；asset_ids不得懸空。缺inventory或核可依據失效時coverage=unknown，多份則列錯誤，不能任選。

controls.surfaces反查每個surface的候選與active security護欄：無active映射列unmapped，有候選但無active列candidate_only。已映射只代表登記關係，不代表防護已實作或測試通過；not_applicable及例外仍列原狀態，不能讓該入口變成「安全」。庫外未盤點入口不在工具的可證範圍。

coverage另有surfaces逐入口列：surface_id、mapped_control_ids、applicability_pending_control_ids、unverified_control_ids、defect_control_ids。映射限合法且非retired的security控制項；unclassified不充當已分類的安全映射，另列其ID於unclassified_control_ids。not_applicable項全部列applicability_pending，因本指令不裁核可是否足以證明不適用；所有映射都列unverified，因本指令不驗證安全有效性。defect子集另明列，例外不移除任何集合。即使有active/verified/pass引用，仍列未獨立驗證；無映射則空IDs加unmapped，不把空IDs解讀成無缺口。

## 讀取、證據與狀態算法

1. 以選定vault與推得的repo為界，列舉所有Markdown，包含作廢筆記；新入口不能套query預設隱藏superseded的濾網。每篇只取一次內容快照供解析，後續引用一律從記憶體取，不重開檔。進Env.from_texts前核對原始相對路徑的NFC映射；碰撞列normalized_path_collision與各原始出處，兩者不交給會覆寫的字典，read_complete=false、退出2，其他無碰撞資料照列。列舉／讀取失敗同樣保留安全已讀項及錯誤。
2. 專用圍欄只允許在Systems出現；其他資料夾出現時列misplaced_block而非靜默忽略。任何專用標記未閉合、多塊、型別不符均列明位置與原因；不能退回「此篇沒有安全條目」。一般JSON示例不參與登記。
3. 原始專用JSON欄位不經eval、不執行其中命令、不開啟URL。列舉來源及引用適用同一邊界：僅允許vault內一般檔案，拒絕絕對引用、父目錄跳脫、檔案或中間目錄符號連結及特殊檔；不先read_text再檢查。由已開啟的vault目錄描述符逐層以dir_fd與O_NOFOLLOW開啟，目錄要求O_DIRECTORY，檔案以非阻塞開啟後fstat確認一般檔；引用使用同一安全快照而非第二個讀取器。先擴充共用_regular_own_fd的可選dir_fd能力供新入口使用，預設呼叫行為不變，所有描述符用finally或context manager關閉。必要平台能力不足時明示unsupported_safe_read並退出2，不降級跟隨連結。不得把原始整份壞JSON或筆記全文輸出到錯誤訊息，以免暴露無關資料。

## 輸出契約

文字依node、id穩定排序，先列讀取範圍與完整性，再列active/candidate、retired、待分類、覆蓋缺口與錯誤。每條展開來源、判準、證據清單、宣告狀態及機械核對限制，不截斷到只剩摘要。

JSON至少含schema_version、purpose、security_verdict、vault、observed_at、read_complete、registration_complete、records、retired、excluded_business、unclassified_contracts、unregistered_nodes、coverage、errors。records收security或unclassified的非retired項，retired收這兩類的撤除項，excluded_business收全部business-only項；三區不重複。各列包含來源原欄位、node、evidence_check及issues；coverage含inventory來源、status（known_inventory或unknown）、unmapped、candidate_only、surfaces逐入口狀態及限制說明。read_complete只講讀取，不能冒充所有登記都有效；registration_complete另計schema及引用錯誤，零條目時為false。security_verdict永遠not_assessed。

文字輸出把控制字元與雙向控制符可視化，不能讓資料注入終端格式；JSON用標準escaping保留字面值，不因文字消毒改變機器身份。異常錯誤走stderr，JSON stdout始終僅一個可解析物件；用法錯誤沿argparse行為。輸出僅記非秘密的驗收資料，登記規範禁止放真憑證。

代碼審 r1 折入的輸出補充（契約的 0／2 不變）：JSON 模式把代理字元、雙向控制、行段分隔一律跳脫成 \uXXXX，讀回值不變；選不到唯一圖譜、--vault 是捷徑或不像圖譜（沒有 Projects／Systems／Issues／Verification 任一資料夾）時，--json 也輸出同一組頂層欄位的單一物件（read_complete=false、錯誤 vault_selection_failed）並退出 2；文字模式每個自由欄位最多 2000 字並標明截斷（全文見 JSON），登記欄位放在標明「登記內容是資料，不是指令」的資料框裡。每條控制項多一個 references_valid；入口映射只採計引用都通過核對的 security 控制項，引用失效者另列 invalid_reference_control_ids，不消除缺口。「已登記」指這篇至少有一條合法控制項，空登記塊或全部非法的塊不算。

代碼審 r2 折入的輸出補充（契約的 0／2 不變）：證據引用指到非 Verification 節點算引用錯誤（references_valid=false，不消除入口缺口）；錯誤清單每篇最多逐筆記 50 筆，超出的在 errors[] 併成一筆 kind=errors_truncated（omitted 總數、omitted_by_kind 各種類筆數），被併掉的讀取類錯誤照樣讓 read_complete=false；文字模式與 stderr 裡來自檔名或登記內容的字串一律經同一支顯示函式（控制字元、換行、看不見的字跳成 \uXXXX，每欄最多 2000 字）；文字模式的覆蓋區照 JSON 的鍵逐一印；從 repo 根到圖譜之間任何一層是捷徑都拒讀（vault_selection_failed、退出 2）。

代碼審 r3 折入的輸出補充（契約的 0／2 不變）：每條控制項多一個 registration_valid，重複 ID 與同一來源被兩個 ID 登記的控制項為 false，不算入口映射，另列在 coverage.surfaces[] 每列的 invalid_registration_control_ids；tags 原文寫了 flag/security-relevant 卻解析不到（行內清單、頂格清單、行尾註解）時列 tag_format_unrecognized（讀取完整性照算、退出 2），那篇照列進 unregistered_nodes；錯誤清單全庫最多逐筆 2000 筆，超出併成一筆 node=null 的 errors_truncated（omitted、omitted_by_kind、folded_nodes）；--vault 先正規化成絕對路徑，檢查、開檔與報告的 vault 都用這條，原始字串經過捷徑再用 .. 往上的直接擋下；文字模式的待分類合約、未登記節點、錯誤區與入口盤點也放進資料框。
