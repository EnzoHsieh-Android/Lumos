# 逃逸自動記_計劃

白話:以前「設計審或規格閘放行了、後來在下游炸掉」這種事沒人記,逃逸帳六筆全是人手寫。這份計劃把三個下游(代碼審、CI、推送閘)都掛上自動記:一擋下就自己對回計劃筆記寫一筆。**它是所有「少審一點」的機制的安全網——沒有這本帳,退場就是盲飛。** 從 [[Projects/規格落成可驗收條件_計劃]] 拆出來(Enzo 2026-09-17 裁),因為它已經落地、跟規格閘本體是兩件事、各自要有自己的撤除條件。

PRIOR-ART: ①最小解=在三個既有寫入點各掛一個 fail-open 的鉤子,不新開帳、不新開指令(沿用 `lumos loop escape` 加 `--auto`)②世界解過:Meta RADAR 靠事後量事故率決定哪些改動可以不審——量測先於放權 ③借用不自建:對回沿用 `git diff --name-only`(帶 `-c core.quotePath=false`)、去重與寫入沿用 `_jsonl_append_verified` 與 `_vault_write_lock`
RETIRE-IF: ①三個月內自動記的列裡「對回計劃」的比例低於五成 → 對回啟發式重做,做不好退回人手記 ②治理帳裡 `escape-auto-failed` 一個月超過 3 筆 → 寫側有結構性問題,先修再說 ③連續 90 天零筆、而同期審查帳有代碼審 major 以上或 CI 帳有測試步紅 → 掛勾斷了,當事故處理

## 逃逸的定義與三個來源(r1–r4 四輪定死語意)

**逃逸**=「一個本該在設計審/規格閘被抓到的缺陷,在下游現形」。**流程沒走完**(缺表態、風險高計劃缺審查留痕)**不是逃逸**;但「計劃被判成風險低、跳過審查,結果下游擋下」是逃逸——那是門判錯的訊號(這一路等 [[Projects/雙向門放行_計劃]] 上線前恆為零筆、空轉不炸)。

| 來源 | 記的條件 | 不記 |
|---|---|---|
| 代碼審 | `code-<主題>` 裡**有一條 `finding_kind=code` 的發現、它自己的嚴重度 major 以上**。逐條嚴重度走 `cmd_canary --finding-severity`(**給了就要每條各標一個**——r4 邊界席 blocker:只驗子集會讓人只標不重要那條、把真 major 漏掉還標成高精度;程式已改成跟 `--finding-kind` 同款全集檢查);沒給嚴重度、或給了嚴重度沒給型別 → 退回「輪級 major 且任一條 code」的粗判,帳上標 `precision: round` | spec/process 型的發現 |
| CI | 結論在 `_CI_RED` 且失敗步驟是測試步:帳上 `failed_step` 長「工作名/步驟名」、多步用 `;` 串,**只看每段「/」後的步驟名**(r3 回滾席:本 repo 唯一的工作叫 `test`,看整串每一步都像測試步——帳上真實列 `test/Anchor verify…`);步驟名切詞後有一個詞等於 test/tests/pytest/unittest/testing、或含中文「測試」(r3 邊界席:切詞只認 a-z0-9)。`;` 也可能是步驟名自己的字元(帳上 `test/code-loop gate (push 後盾;體檢`,r4 回滾/邊界席)——切錯段目前只會少判不會多判,接受,寫進誠實界線 | build/lint/timeout/startup_failure |
| 推送閘 | ①「受波及合約的測試沒過」;②只認「tier=high 且…」開頭的缺留痕句(r2 回滾席:測試紅的擋下句尾巴也帶 `tier=high`)、而該計劃有 `kind: spec-gate` 風險低留痕 → 階段 `push-gate-unreviewed` | 缺表態;風險高計劃的缺留痕 |

- **精度欄 `precision`**:只有代碼審來源會寫(`finding`/`round`);CI、推送閘、手動記的列**沒有這個欄位=事件級證據,照數**(r4 正確性/回滾席:寫成「只數 finding」會把最硬的兩個來源排除在門檻之外)。任何拿逃逸帳算門檻的地方(風險低計劃的撤除條件),規則寫死:**只排除 `precision: round` 的列**。
- 對回計劃:代碼審用 `code-<主題>`→`<主題>`;CI 與推送閘用提交範圍碰到的 `Projects/*.md`(`_plans_in_range`,只認計劃檔本身,不讀 `lands_in`——r4 接手席:要讀落點的家是風險低推送閘的需求,記在那份計劃)。路徑存在性兩邊 NFC。對不回不記。歸因守衛放寬成「迴圈在審查帳 **或** 計劃檔存在」,帳上 `attribution: ledger|plan-file`。
- 去重鍵(計劃、階段、sha);寫側整段在 `_vault_write_lock` 裡。
- **fail-open 的失敗要看得見**:失敗寫治理帳 `kind: escape-auto-failed`;治理帳也寫不進去就只剩 stderr——**帳上量不到,接受**;唯一線索是 vault 唯讀/磁碟滿的系統事故,事故筆記要回查逃逸帳斷點。
- 帳是 git 追蹤檔,hook 只 append 不 commit;提交紀律照治理帳。

## 進度(2026-09-17,三來源全部落地、測試綠)

- 初版:`lumos loop escape --auto --stage <站> --severity <級> --desc <句> --range <a..b>`;代碼審記到 major 以上時自動對回;推送閘擋下時在 exit 前自動記(fail-open);CI 掛在 CI 帳寫入處,範圍取「上一個綠 sha..這次紅」。
- 踩到舊坑:git 對中文檔名預設加引號轉義,`git diff --name-only` 一個計劃都對不上;要帶 `-c core.quotePath=false`。
- 四輪設計審同步改進(先紅後綠、翻紅釘):代碼審只收 code 型且逐條 major 以上(`--finding-severity`,全集檢查,沒給/沒型別 → round);CI 判準三版(子字串→切詞→只看步驟名+中文);推送閘 unreviewed 只認「tier=high 且」;階段名 `push-gate-unreviewed`;寫側鎖;NFC;治理帳留痕。測試九支:`t_escape_auto_from_prepush`/`_from_ci`/`_scope_rules`/`_ci_only_test_step`/`_unreviewed_twoway`/`_code_finding_severity`/`_lock`/`_dedup`/`_from_code_loop`,`-k escape_auto` 32 passed。
- **推送前**:`scripts/hooks/pre-push` 與 `scripts/test_lumos.py` 是錨點檔,要 `lumos anchor approve`。

## 實務隱患

- **守衛面**:改的是推送閘 hook 與審查帳寫入處。處置:全部 fail-open(記帳失敗不能變成擋推送的第二個理由)、翻紅釘、錨點核可。
- **已排除:效能**——每次最多掃一個提交範圍的 `diff --name-only`,毫秒級。
- **已排除:多人並行**——寫側上 vault 寫入鎖,去重鍵擋重複。

## 驗收條款(全部有真測試、綠)

- [S1] 當代碼審記下的發現裡有一條型是 code 且它自己 major 以上且該迴圈對得回計劃,逃逸帳應自動多一筆並帶階段與 sha [test:t_escape_auto_from_code_loop]
- [S2] 若代碼審沒給逐條嚴重度或沒給型別,則逃逸帳應退回輪級判準記帳並標 precision 為 round [test:t_escape_auto_code_finding_severity]
- [S3] 若逐條嚴重度只標了部分發現,則記帳應擋下並要求每條各標一個 [test:t_escape_auto_scope_rules]
- [S4] 當推送閘因受波及合約測試沒過擋下且提交範圍碰到計劃筆記,逃逸帳應自動多一筆 [test:t_escape_auto_from_prepush]
- [S5] 若同一計劃、同階段、同 sha 已有逃逸紀錄,則不應重複寫入 [test:t_escape_auto_dedup]
- [S6] 當推送閘因高風險缺審查留痕擋下且該計劃有風險低留痕,逃逸帳應多一筆階段為 push-gate-unreviewed 的紀錄 [test:t_escape_auto_unreviewed_twoway]
- [S7] 當 CI 紅但失敗步驟不是測試,逃逸帳不應多一筆 [test:t_escape_auto_ci_only_test_step]
- [S8] 當兩個行程同時對同一計劃同階段同 sha 自動記逃逸,逃逸帳應只多一筆 [test:t_escape_auto_lock]
- [S9] 當 CI 紅且範圍碰到計劃筆記,逃逸帳應多一筆階段為 CI 的紀錄 [test:t_escape_auto_from_ci]

(S3 的斷言目前在 `t_escape_auto_code_finding_severity` ⑥;搬進 `t_escape_auto_scope_rules` 是落地前的收尾,見進度。)

## 回退

三個掛勾各是一個 `if` 區塊,回退=把三處呼叫拔掉(`cmd_canary` 尾端、`_ci_record` 尾端、pre-push 兩個 grep 分支),`loop escape --auto` 指令與帳保留。已記的列不刪。

## 誠實界線

- 對回是啟發式(範圍碰到計劃檔),誤對回與漏對回都可能;RETIRE-IF ① 量它。
- `push-gate-unreviewed` 這一路在 [[Projects/雙向門放行_計劃]] 上線前恆為零筆。
- CI 步驟名裡自帶 `;` 會被切段,目前只會少判不會多判;帳上 `test/code-loop gate (push 後盾;體檢` 就是實例。
- 雙重失敗(逃逸帳與治理帳都寫不進)帳上量不到。
