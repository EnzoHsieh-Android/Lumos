# 殺傷力配方綁的測試要在合約清單_計劃

白話:合約行(★INVARIANT★)寫了 `[test:…]`,列出守這條合約的測試;推送前會真的跑它們。殺傷力配方則是「故意把程式改壞,看綁定的測試會不會紅」,證明那支測試真的守得住。配方新增時如果帶 `--test` 指定測試,工具不會檢查那支在不在合約清單上——結果可能是:殺傷力證明的是 A 測試,推送前跑的卻是 B 測試,兩者對不上而沒人發現。rtb 就有一條這樣的(rtb 庫的 Systems/執行迴圈,F7 合約)。這次在新增時與 doctor 都提醒,不擋。

依據:Enzo 交棒單的 rtb 待辦;rtb 2026-10-06 盤點與工具鏈回覆的排序(本項排第 3)。

PRIOR-ART: 合約行的測試清單用既有 `resolve_test_refs(合約行, 平台表, 預設平台)` 解析成 (平台, 方法) 對——平台表照既有呼叫點的閘法:多平台傳設定的平台表、單平台傳空表(不切冒號);配方這一側照 guard kill 實際的跑法取 (配方的 platform 欄或預設平台, `_kill_method_name(test, 多平台)`)。兩邊的方法名再過同一支正規化(去前後空白、去 Kotlin 反引號、再去空白),比 (平台, 方法) 對,不比字串;單平台只比方法名。doctor 的提醒併進既有的 P2 段當第三個提醒(warn_soft、`_kill_note_skipped` 跳過規則、共用 P2 掃描已讀好的設定、每篇每條各自例外保護、gov_events 落帳);kill-add 的提醒接在既有的鎖外提醒 `_kill_add_after_lock`/`_kill_add_warn` 之後、`--try` 之前。對回合約行:把 kill-add 鎖內那段「去標記後含片段、恰好一行」抽成一支共用函式,kill-add 與 doctor 都用它,不另寫第二套。
RETIRE-IF: 本工具鏈本機治理帳連續 60 天 `check-p2t` 的 warned 是 0 筆,就把 doctor 那一則拿掉(kill-add 的提醒留著;rtb 那邊看它自己的帳、由 rtb 回報)。

## 範圍

- 做:比對規則抽成一支共用函式(輸入:配方、合約行文字、平台設定;輸出四種):
  - 在清單上 → 不提醒。
  - 方法名在清單上、平台不同 → 「配方會在 A 平台跑、合約綁的是 B 平台」(典型:清單寫 `[test:ios:Foo]`、kill-add 沒帶 `--test` 也沒帶 `--platform`,配方存成 `ios:Foo` 沒有 platform 欄,guard kill 會在預設平台跑 Foo)。修法講「用 `--platform B` 重新 kill-add」,不叫人 bind。
  - 方法名不在清單上 → 「不在清單上」;清單空時講「這條合約還沒綁任何測試」。
  - 比不了 → 交代原因,由呼叫端決定印不印:設定檔讀不了、配方平台不在設定裡、配方測試名不合法(這三種 P2 前兩則與 kill-add 原文提醒已經講過,新提醒不重複)、合約行有未定義的平台前綴(既有提醒沒講,新提醒印一行「沒比對」)、配方欄位型別壞(platform 不是字串、配方不是物件)。
- 做:`guard kill-add` 寫入成功後,比對這次實際寫進去的那條配方(含「只更新 covers」沿用的既有配方——規則看配方實際的測試,不看這次有沒有帶 `--test`;既有配方本來就不在清單上的,每次補 covers 都會再提醒一次,屬實)。合約行文字在鎖內已定位,隨要驗的配方一起交到鎖外,鎖外只比對、不重讀筆記(以寫入當下那份為準)。寫入照常、rc 照常,stderr 至多一行;跟原文失配提醒同時成立時兩行各印、先原文失配後測試未綁,都在 `--try` 試跑之前。比對自己出了沒預料的錯也只印一行「沒比對」、照常 rc(同 `_kill_add_warn`)。
- 做:doctor 的 P2 段第三個提醒(warn_soft,只提醒不擋):共用 P2 掃描已讀好的設定;P2 掃描整段例外或設定檔讀不了就整則跳過、不落帳。逐篇(照 `_kill_note_skipped`)讀配方,每條配方用共用定位函式對回合約行——對不到或對到多行、invariant 空白或不是字串的,這則不管(guard kill 跑到那條會自己擋下「找不到合約行/對到好幾條」)。每篇、每條各自例外保護,一條壞配方不吞掉其他條。列出「不在清單上」與「平台不同」兩種(節點、合約前 30 字、配方的測試、修法),比不了的不列。gov_events 記 `check-p2t`(登進已知閘清單與本機帳分流清單兩處)。不跑 git。
- 做:修法提示由 (平台, 方法) 產生:平台不是預設平台時 bind 指令帶 `--platform`;方法名不是識別字(反引號名、含點)時不給 bind 指令,改講「這種名字 guard bind 綁不了,改把配方的測試換成清單上那支」。bind 會讓這條合約變成多支測試,提醒順帶講「綁上後 kill-add 不帶 --test 會要你指明哪一支」;另一條路是 kill-rm 後用清單上那支重新 kill-add。kill-add 那一行列清單時最多列 3 支加總數。
- 做:說明同步(見〈落地清單〉)。
- 不做:擋下、自動綁上、自動補 platform 欄;改 kill 的跑法;列出「配方對不回合約行」(另一個問題,真要管另開案、要逐條列)。

## 實務隱患

- **多平台 ref**:配方的測試有三種存法(方法名加 platform 欄、帶前綴沒有 platform 欄、只有方法名),清單裡預設平台的測試也可能有前綴或沒有,Kotlin 反引號與前綴後的空白兩邊處理不同;都轉成正規化後的 (平台, 方法) 再比——測試涵蓋這幾種組合加單平台含冒號。
- **大圖譜**:doctor 這一則只讀開頭欄位的 kill_recipes 與合約行,不跑 git、不跑測試、不另讀設定。
- **並行**:kill-add 的比對用鎖內讀到的合約行,放鎖後別的會談改了清單,這次提醒仍以寫入當下為準;下次 doctor 會看到新狀態。
- 已排除:金流:只多兩處提醒,不碰任何金流
- 已排除:對外送出:不連網、不送任何東西出去
- 已排除:不可逆:只多提醒與本機治理帳的例行紀錄,退回提交即恢復(見〈回退〉)
- 已排除:守衛面:只多提醒,不改任何閘的判定

## 驗收條款

- [S1] 當 `guard kill-add` 寫入的那條配方的測試不在那條合約行的測試清單上時,應 照常寫入、rc0,stderr 提醒一行;清單空時 應 改講「還沒綁任何測試」;在清單上時(預設平台有前綴與沒前綴、Kotlin 反引號、前綴後帶空白、單平台含冒號)應 不提醒;清單寫別的平台前綴而沒帶 `--test` 也沒帶 `--platform` 時 應 改講平台不同;合約行有未定義的平台前綴時 應 印一行沒比對、不失敗;與原文失配同時成立時 應 兩行、先失配後未綁;只更新 covers 時 應 比既有那條 [test:t_kill_add_warns_test_not_bound]
- [S2] 當圖譜裡有配方綁的測試不在對應合約行的測試清單上時,doctor 的 P2 段 應 列出那一筆並在本機治理帳記 `check-p2t` 的 warned(不進版控帳);都在清單上時 應 不列;同一篇兩條合約兩條配方 應 各對各;對不回合約行、欄位壞的配方 應 不列也不拖累其他條;設定檔讀不了時 應 整則不出現;非識別字的測試名 應 不給 bind 指令 [test:t_doctor_kill_test_not_bound]

## 回退

退回本案的提交即可:兩處提醒消失,筆記與配方資料不受影響。本機治理帳裡已記的 `check-p2t` 行會留著,舊版讀它不崩潰(統計表多一列沒登記的閘);若有人把撤除條件寫成以 `check-p2t` 為度量的機器式,退回前先改掉那條,不然 lint 會判閘名不認得。
