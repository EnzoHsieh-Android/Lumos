# 模擬器自動開關與裝置分工

> **已撤案(2026-10-31 Enzo 裁)**:端到端驗收各塊一律照現行規則在實機跑(決策 d1、d2),本計劃的主軸「沒裝置就自己開模擬器」因此不成立;改做「實機保持可用」(自動叫醒、解鎖、重連)的提議也一併不做。CI 那一塊要看公司慣例,這次不做決定。以下是撤案前的設計,不是現況,也不是待辦。

白話:現在的 Android 端到端驗收像一位驗收員,要人先把手機插好、解鎖他才肯開工;沒人在旁邊時,代理寫完畫面就卡在「判不出要用哪台裝置」。這份計劃讓驗收腳本在沒有手機時自己開一台模擬器、跑完自己關掉,並把「哪一塊驗收在哪種裝置上跑才算數」寫成規則:畫面與流程(UI flow、截圖比對)用模擬器,毫秒類效能與記憶體穩定性照舊只認真機(記憶體見決策 d1)。2026-10-31 Enzo 問「如果我想全自動開發 Android,我們目前還缺乏什麼機制?」,調研排出五塊缺口,這是第一塊;Enzo 看完白話版回「好」、選「寫計畫」。

翻案範圍:[[Projects/Android端到端驗收_計劃]] 的 PRIOR-ART 把 Gradle Managed Devices 模擬器列為「不選」,理由是「跟本機實機跑的決定衝突,雲端裝置的效能不能當基準」。那條理由只涵蓋效能;本計劃只把 UI 流程與截圖搬到模擬器,效能不動。是否翻案要 Enzo 裁(Q1),裁定前不寫程式。

PRIOR-ART: Android SDK 的 `emulator` 命令列(`-avd <名> -no-window -no-audio -no-boot-anim -no-snapshot-save -read-only -port <偶數埠>`;`-read-only` 讓同一個 AVD 能同時開多份,兩個工作樹不會互搶)、`adb -s <序號> wait-for-device` 加輪詢 `getprop sys.boot_completed`、`adb -s <序號> emu kill` 關機、`getprop ro.kernel.qemu` 判是不是模擬器;Maestro 的 `--device` 指定裝置;既有範本腳本的裝置鎖、程序組收尾與中斷處理([[Systems/android-e2e-acceptance]])。CI 那層的現成輪子(reactivecircus/android-emulator-runner、Gradle Managed Devices 的 ATD 精簡映像)留給第二步(Android CI 範本)。借用:以上全部。自建:範本腳本裡一段「沒裝置就開、自己開的自己關」,和一個 `e2e.emulator` 設定段。不選:Gradle Managed Devices(它只跑 Gradle 的儀器測試,不跑 Maestro flow,裝置生命週期也綁在 Gradle 任務裡,範本腳本拿不到序號);每次自動建 AVD(要下載系統映像、同意授權條款,這步要人,v1 只檢查、印出建立指令)。

RETIRE-IF: 連續四週的驗收總表裡,自己開的模擬器那幾次「開機逾時或開機失敗」超過全部自動開機次數的兩成(誤擋多過省下的看顧),就把自動開機改回只提醒、驗收照舊要人接裝置;或 Android CLI 這類官方工具提供「開一台、跑完收掉」的穩定指令,就改呼叫它、拿掉自建那段。

REVISIT:2026-12-15 Q1 裁了沒;沒裁就判延後或撤案 [closed:2026-10-31 Q1 已裁(d2),計劃撤案]

## 要解的兩個問題

1. **沒裝置就卡住**:範本腳本挑裝置那一步只看 `adb devices` 已經連上的,零台或多台都擋下;本機其實裝了 `emulator` 與 `avdmanager`、也有一個 AVD(`kds_bench`),只是沒接上。
2. **截圖與效能的裝置規則互相打架**:[[Projects/截圖基準驗收流程_計劃]] 寫「只認模擬器」(真機每台字型、解析度不同,基準圖對不上);效能這邊官方建議只用真機(Macrobenchmark 在模擬器上會報 EMULATOR 錯誤,[[Projects/Android診斷證據接入_調研]])。一次驗收只用一台裝置,兩邊沒法同時滿足;KDS 試點用實體平板,截圖乾脆沒開。

## 做法(Q1 裁定後才動手;以下是建議版)

1. **設定**:`.lumos/macrobench.json` 的 `e2e` 段多一個選填的 `emulator` 段:`avd`(AVD 名,必填)、`boot_timeout`(秒,預設 300)。另加選填的 `real_serial`:效能與記憶體要用的那台真機。沒寫 `emulator` 段時行為完全不變。
2. **挑裝置**:
   - 寫了 `adb_serial` 或 `ANDROID_SERIAL`:照舊用那台,不開模擬器。
   - 有 `emulator` 段、而且 `adb devices` 裡沒有序號跟 `real_serial` 不同的已連線裝置:自己開一台(無視窗、不存快照、唯讀、挑一個沒人用的偶數埠),等 `sys.boot_completed` 變 1,再解鎖、讓螢幕常亮、關掉三個動畫比例;等超過 `boot_timeout` 就擋下並印模擬器的輸出尾段。
   - AVD 不存在:擋下,印一行可以照抄的 `avdmanager create avd` 指令(系統映像要人下載、同意授權)。
3. **裝置分工**:UI 流程與截圖在模擬器上跑;效能與記憶體在 `real_serial` 上跑;沒有 `real_serial` 或它沒連上時,這兩塊記成「沒跑:沒有實機」——效能照現行規則只提醒,記憶體照現行規則判不出來就擋(決策 d1),不擋 UI 與截圖照跑。在模擬器上絕不跑效能與記憶體(效能結果不能當基準、Macrobenchmark 也會報錯;記憶體驗收的程序前提是實機)。
4. **記下裝置種類**:steps.json 每一步記 `device_kind`(`emulator`/`physical`,用 `ro.kernel.qemu` 判,不靠序號字樣)與 AVD 名;judge 照它判「這一塊在對的裝置上跑才算數」。
5. **收尾**:只關自己開的那台,寫在既有的收尾流程裡(正常結束、失敗、Ctrl-C、TERM、HUP 都關);`emu kill` 沒在寬限秒數內收掉,就對模擬器的程序組補 KILL。不是自己開的裝置一律不碰。
6. **截圖基準綁 AVD**:基準圖是在哪個 AVD 上錄的,寫進驗收素材(算進指紋);驗收時 AVD 名或它的螢幕寬高、密度、系統映像跟錄的時候不同就擋下,印「基準圖是在 X 上錄的,這次是 Y」。理由:換了 AVD 尺寸,截圖比對會整片紅,紅的原因不是程式。

## 驗收條款

- [S1] 當 e2e 段有 `emulator` 段、`adb devices` 看到 0 台可用時,範本腳本應用設定的 AVD 開一台無視窗模擬器,等開機完成後照常跑完驗收,結束時把它關掉(跑完 `adb devices` 不再有它) [test:t_android_e2e_emulator_boot_and_kill]
- [S2] 當驗收被 Ctrl-C、TERM 或 HUP 中斷,或任一步失敗時,範本腳本應關掉自己開的那台模擬器;不是自己開的裝置不應收到 `emu kill` [test:t_android_e2e_emulator_cleanup_on_interrupt]
- [S3] 當 e2e 段寫了 `adb_serial` 或環境有 `ANDROID_SERIAL` 時,範本腳本不應開任何模擬器,行為跟沒有 `emulator` 段時一致 [test:t_android_e2e_emulator_respects_serial]
- [S4] 當模擬器在 `boot_timeout` 內沒開好時,範本腳本應回 2、印「擋下:」與模擬器輸出尾段,並收掉那台模擬器 [test:t_android_e2e_emulator_boot_timeout]
- [S5] 當設定的 AVD 不存在時,開跑前檢查應回 2,並印一行 `avdmanager create avd` 指令 [test:t_android_e2e_emulator_missing_avd]
- [S6] 當效能那塊要跑、可用裝置只有模擬器時,範本腳本不應在模擬器上跑效能,judge 應把效能記成「沒跑:沒有實機」 [test:t_android_e2e_perf_never_on_emulator]
- [S7] 當截圖基準的 AVD 跟這次驗收裝置的 AVD 名或螢幕規格不同時,judge 應判截圖那塊沒過,並印兩邊的 AVD [test:t_android_e2e_visual_avd_mismatch]
- [S8] 當 steps.json 裡某一步的 `device_kind` 不在允許清單內(例如效能或記憶體記成 `emulator`)時,judge 應把那一塊判成沒跑成,不能判通過 [test:t_android_e2e_device_kind_gate]
- [S9] 當沒有 `emulator` 段時,既有的端到端驗收測試應全部照舊通過,輸出一字不變 [test:t_android_e2e_no_emulator_section_unchanged]
- [S10] 當 e2e 段開了記憶體與穩定性、可用裝置只有模擬器時,範本腳本不應在模擬器上跑記憶體收集,judge 應把記憶體各項判成沒判到、照現行規則擋推送,並印「記憶體要在實機跑:沒有實機」 [test:t_android_e2e_memory_never_on_emulator]
- [S11] 當在本機用 `kds_bench` 或 macrobench-lab 對應的 AVD 實際跑一次整套(沒接真機)時,應自動開機、UI 流程跑完、模擬器被關掉,並記下開機秒數與整套秒數 [manual:本機實跑一次,結果寫進驗證紀錄]
