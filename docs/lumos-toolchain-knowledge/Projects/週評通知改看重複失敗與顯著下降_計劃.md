# 週評通知改看重複失敗與顯著下降_計劃

> 白話:自主迴圈每週抽 8 題情境探針(在凍結副本開會談,看 AI 有沒有照規矩用 lumos),現在只要一題沒過就發 LINE。題目是輪流抽的,同一題要隔幾週才再出現,單次沒過多半是雜訊;歷史 7 週裡 5 週會響,響久了就沒人看。這篇改成只在兩種情況通知:同一題最近兩次出現都沒過(規矩真的守不住),或本週通過率顯著低於同判準的歷史(Wilson 區間不重疊)。同判準的歷史不夠時照舊「有題沒過就通知」並寫明基準不足。來源是世界解總覽〈跨類優先順序〉第 2 名。

PRIOR-ART: 評測界對小樣本比例用 Wilson 區間而不是點估計(本 repo `scripts/lumos` 的 `_wilson_interval` 已用在逃逸帳統計,這裡直接借用,不另寫);「同一題連續失敗才告警」是監控常見的連續 N 次才發(Prometheus 告警規則的 `for:` 期間、SRE 的「別為單點抖動叫人」)。世界解總覽另提的哨兵題 pass^k 本篇不做:題庫沒有指定哨兵題,要先決定哪幾題當哨兵。
RETIRE-IF: 上線後連續 12 週的週抽,新規則沒通知的週裡,事後有人發現規矩其實已經退化(回頭看那週的失敗題確實是真退化)達 2 次以上,就改回「有題沒過就通知」或收緊條件;或同判準歷史始終累積不到 3 週(判準一直在改),新規則永遠走基準不足那條路,等於沒做。

REVISIT:2026-12-31 回頭數上線後各週的通知與否,對照事後確認的真退化,看 RETIRE-IF 的兩條有沒有成立

## 實測(2026-10-13)

- `governance/scenarios/history.jsonl` 有 7 週週抽(2026-W34 到 W40),5 週有題沒過、照現行規則會響(71%)。
- 現有歷史只記沒過的題,不記這週抽了哪些題,所以算不出「這題上次出現時有沒有過」;這 7 週也都沒有判準版本欄位(判準 2026-10-03 才開始記版本),跟現行判準不能比。也就是說新規則上線後會先走「基準不足」那條路,要累積 3 週同判準、帶題號的歷史才真的生效。
- 如果只看沒過的題名,W39 與 W40 都有「上一次沒過的題又沒過」(d01 在 W35、W39;d04 在 W39、W40);沒有題號無法確認中間有沒有出現又過。

## 範圍

- 只改「要不要發 LINE」的判斷,不改探針怎麼抽題、怎麼判分;總結行格式不動(自主迴圈靠它解析)。
- 週抽歷史多記這週有效場次的題號(`ids`),之後才算得出觸發 A。
- 不做哨兵題 pass^k、不做逐題跨週通過率報表(之後有需要另案)。

## 做法

- 探針腳本新增純函式:輸入週抽歷史各列(最後一列是本週),回「要不要通知、原因」。
  - 只看週抽列(seed 是 `YYYY-Www`、預設組別、跑一次);本週這批無法下結論或有儀器事故 → 通知。
  - 同判準(`grader` 欄位相同、帶題號、非無法下結論、非事故、不是本週;同一週重跑只留最後一列)的過去週不到 3 週 → 照舊有題沒過就通知,原因寫明「同判準歷史只有 N 週,基準不足」。
  - 觸發 A:本週沒過的某題,在最近一次「題號清單含它」的同判準過去週裡也沒過 → 通知。
  - 觸發 B:本週通過率 Wilson 區間上緣 < 同判準過去週合計通過率 Wilson 區間下緣 → 通知。
  - 都沒有 → 不通知,原因列出本週單次沒過的題,寫明「下次抽到再看」。
- 探針主程式寫完週抽歷史後印一行 `週評通知:是 — <原因>` 或 `週評通知:否 — <原因>`;剛寫進去的最後一列不是這次的預設週抽、或判斷出意外就不印。
- 要通知時探針主程式另印一行 `MSG:<整句訊息>`(總結行加判定原因,python 組好)。自主迴圈的 `run_probe` 同 `run_replay` 的慣例:有判定行就只認 `MSG:` 行、原樣轉交 LINE 通知,不在 shell 拆字串或組訊息;沒有判定行(舊版探針、或探針中途壞掉)才退回現行「p≠n 就通知」。

## 驗收條款

- [S1] 當同判準的過去週不到 3 週時,有題沒過 應 通知、全過 應 不通知,原因 應 寫明基準不足與週數;剛寫進歷史的最後一列不是這次的預設週抽(跑多次、別的組別)時,判定行 應 不印,讓自主迴圈退回舊規則;判斷出任何意外、或歷史檔讀不到或編碼壞掉時 應 不印;本週無法下結論或有儀器事故時 應 一定通知(不論基準夠不夠) [test:t_weekly_alert_fallback_when_thin_history]
- [S2] 當同判準過去週夠時,本週沒過的題在它上一次出現時也沒過 應 通知並在原因點名那題;上一次出現時有過 應 不通知;過去週題號清單不含它的不算它出現過;同一週重跑的多列 應 只算一週,而且不算本週的「上一次出現」;有儀器事故或無法下結論的過去週 應 不算它出現過 [test:t_weekly_alert_repeated_failure]
- [S3] 當同判準過去週合計 24/24、本週 3/8 時,週評 應 通知(顯著下降);本週 6/8 而且沒有重複失敗時 應 不通知;判準版本不同、或同判準但沒有題號的過去週 應 不算進基準;借不到 Wilson 區間時 應 退回有題沒過就通知並寫明原因 [test:t_weekly_alert_significant_drop]
- [S4] 週抽歷史那一列 應 帶本週有效場次的題號 `ids`,被排除的場次(截斷、用量上限)不在裡面;探針主程式要通知時 應 另印一行 `MSG:` 整句訊息,判定為否時 應 不印 `MSG:` 行 [test:t_probe_history_records_ids]
- [S5] 自主迴圈的探針段:探針輸出判定行而沒有 `MSG:` 行時 應 不送 LINE;有 `MSG:` 行時 應 照它原樣轉交 LINE 通知;沒有判定行而總結行 p≠n 時 應 照舊送 LINE,沒有判定行時雜散的 `MSG:` 行 應 不送;log 記的探針結果 應 是錨在行首的總結行而不是 `MSG:` 行 [test:t_autoloop_probe_alert_follows_verdict]

## 回退

- 單一提交還原即可。週抽歷史多出的 `ids` 欄位舊版程式不讀;還原後自主迴圈回到「有題沒過就通知」。
- 只想暫時回到舊行為不還原:沒有開關——新規則在基準不足時本來就等於舊行為;真要停就還原提交。

## 實務隱患

- 新規則會讓「單次沒過」不再通知:真的退化但只在某題出現一次時,要等它下次被抽到(依題庫大小約數週)才會叫。這是刻意的取捨,用 RETIRE-IF 回頭量。
- 判準版本一改,同判準歷史歸零,又回到基準不足三週:改判準的人要知道週評會暫時變回吵的那一版。
- 載入 Wilson 區間要載入整支 `scripts/lumos`(約一兩秒),每週一次,可接受;載不進就退回「有題沒過就通知」並寫明原因。
- 已排除:金流:不碰任何金流或扣款相關程式
- 已排除:對外送出:LINE 通知本來就會送,這篇只改什麼時候送,送的對象與內容格式不變
- 已排除:不可逆:只改判斷與多記一個欄位,還原提交就回到原狀;既有歷史不改寫
- 已排除:守衛面:不碰任何推送閘或判分;只影響每週一次的提醒
