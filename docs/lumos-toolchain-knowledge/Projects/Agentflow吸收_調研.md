# Agentflow吸收_調研

> 白話:一份外部報告(Enzo 2026-09-07 帶進來)拿 Agentflow 跟 Lumos 對照,建議 Lumos 吸收五件事。
> 逐條查證後的結論:**五件裡有兩件這裡早就有了(其中一件比報告提的更嚴,但對零篇筆記生效)、
> 兩件部分有、只有一件是真的該補**;而且★報告有兩條把不存在的東西記到 Agentflow 頭上★。

PRIOR-ART:①最小解在既有機制層——「知識權威」那件(報告 P0 第二項)**已經蓋好了**:Check J 重生來源軸(`[src:]`/`[git:]`/`推測:`/`佚失:` 四級 + 不對稱接線),見 [[Systems/check-j-regen-guard]];要做的不是造,是**擴大射程**。②世界解過但沒報告說的那麼多——Agentflow 有 route 與 minimality,★沒有 I-NNN 事故規則、沒有明文 closeout stop rule★(逐條查證見下)。③不採用新依賴:Agentflow 是 markdown prompt 包(99★、3 commits),形狀可借、無實作可用。

## 這份報告在主張什麼

外部報告把兩者定位成「Agentflow 管這次工作怎麼可靠做完 / Lumos 管整個系統怎麼長期不失憶」,建議 Lumos 吸收五件事:①Route Selection(分級,別每個改動都跑完整治理)②Knowledge Authority(標 FACT/DECISION/INFERENCE/HYPOTHESIS,防 AI 推論污染圖譜)③Minimality Gate(審查員不得自行擴大範圍)④Incident→Rule Lineage(`lumos why-rule`)⑤Convergence/Stop Contract(什麼算完成、什麼變更會讓它失效)。

★這份報告與 [[Projects/執行DAG_調研]] 是同一個形狀★:外部觀察者提「Lumos 缺一個執行層」,而且同樣**沒有深入 repo 查證**。兩份的處理方式也一樣——先逐條對 repo 查,再談要不要做。

## ★原稿的類比錯了(外家 f1,已改;這條打到本篇的命脈)★

外家的判準(我接受,且開檔複驗過來源計劃的前提):

- **AI 對「原設計者當初為什麼這樣做、這件事該不該升格成合約」不是目擊者**——那要靠讀 code 逆推,正是重建者的位置。
- from-scratch 計劃自己把前提限定在「目擊記錄佚失／從未存在／整篇重寫／接手 legacy repo」。

| 主張型別 | AI 的身分 | 適不適用來源軸 |
|---|---|---|
| 本輪親自執行或直接觀測(跑了什麼、輸出什麼、測試綠不綠) | **目擊者** | **不適用**——課它重建成本沒有道理 |
| 從既有 code 逆推的歷史意圖、why、「這是合約」 | **重建者** | **適用**——這才是 Check J 的病理 |

**原稿從第二類風險直接跳到「日常回寫全面擴射程」,把第一手執行紀錄也一起課稅,不成立。**

★但這個修正反而讓建議更利★:合約行(★INVARIANT★ 那類)幾乎全是第二類主張——「這條規則不能改」本來就是關於意圖與歷史的斷言,不是關於「我剛剛跑了什麼」。**所以只對合約行要求證據,既是最便宜的一刀,也剛好落在唯一適用的那一類。**

## ★真正的缺口可能比「射程」更前面:證據「存在」≠證據「支持」(外家 f6,原稿與外部報告都漏掉)★

`[src:路徑:行號]` 的驗證只呼叫存在性檢查——**路徑在、行號沒越界,就過。**

★所以任何 agent 都可以把一個錯的主張,指到一個真實存在、行號合法、但語意完全無關的位置,而檢查會放行。★系統驗的是**引用格式**,不是**引用支不支持主張**。repo 自己的 Check J 系統筆記已經承認這個天花板,但原稿把「現 code 可驗」寫得像內容已經被驗真。

**這比「射程沒擴到日常」更接近知識權威的核心缺口**——射程再大,如果每個標記都可以指到不相干的行,那只是把幻覺換了一種格式。

低成本的第一步(不必一開始就造全自動語意閘):高風險合約的 `[src:]` **要求逐字摘錄它所支持的那一段**,或對合約行做抽樣的「主張↔來源」語意核對。
