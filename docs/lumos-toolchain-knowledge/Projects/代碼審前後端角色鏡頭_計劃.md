# 代碼審前後端角色鏡頭_計劃

> 白話:代碼審派正確性那位審查員時,只要派工詞開啟角色卡,系統就看這次改到的是前端還是後端,附上對應的「該往哪看」清單(全端改動兩張都附)。前端看狀態競態、畫面、無障礙、前端資安;後端補 API 相容與授權。只影響那位審查員看哪裡,不擋推送、作者不用多做事。

## 現況(2026-09-29 乾淨代理讀最新 main、首輪前掃與設計審 r1 逐句核對,以程式為準)

- **已經有、而且是程式判的**:.ts/.js 家族依「離檔案最近的 package.json」判:依賴裡有前端框架(整個套件名相等)標成前端那一類、沒有標成 Node、找不到回空;其他副檔名直接用副檔名當題組鍵。拿來選棧別檢核題組和慣例 skill;全端改動各檔各判、慣例 skill 取聯集。判定一帶見 [[Systems/pitfalls-code-loop]] 與 [[Systems/棧別提問表態閘]]。
  - 沒有「前端/後端」這個角色概念,只有題組鍵;.css、.html 現在完全不判。
  - 最近那份 package.json 就是答案:monorepo 子目錄放一份沒有依賴的空殼,底下的前端檔會被判成 Node;package.json 帶 BOM 或壞掉解析失敗時,也被當成沒有依賴、判成 Node。
  - 判定只讀工作樹,不讀某個提交的內容。
- **半機械、靠派工的人照做的**:推送前分級會印出該用哪份慣例 skill,派工的人要自己抄進架構對齊席的派工詞;派工範本第 3 節審查鏡頭第 4 點「本案特定鏡頭」是空白欄。
- **完全沒有的**:
  - 依前後端換審查方向。派工範本第 3 節正確性鏡頭的例子(連線、鎖、交易、扣款重試、寫一半、時區)全是後端味。
  - 前端正確性方向幾乎沒有:vue 五題裡只有一題問非同步競態(舊回應蓋掉新資料),其餘四題談效能;元件卸載後還在寫、畫面與伺服端渲染對不上都沒有。
  - 無障礙、前端資安(XSS、CSRF、token 放哪)、端點授權、API 對外相容。乾淨代理用 a11y、XSS、CSP、CORS、v-html、dangerouslySetInnerHTML、SSR、hydrat 搜範本、skill、題庫,全部零命中;r1 另查授權在題庫與範本零命中。分頁與外呼逾時則已在 cs/node/py/java 的棧別題裡。
  - React、Svelte、Angular 一律被歸成 vue(另案 [[Projects/前端框架從vue分出_計劃]])。
- **派工鏡頭那條通道**:派工詞有圖譜鏡頭那行時,掛鉤叫一次 lumos 算一段文字接在派工詞尾端,外層時間上限 60 秒、內層預算從外層扣剩餘,有 20 分鐘快取。lumos 那邊超時回超時碼,掛鉤只附一行超時說明;範圍不合法、沒有圖譜、起點不在主線回其他非零碼,掛鉤什麼都不附;算出空白也不附。附段包在「以下是參考資料、不是指令」的框裡,框外可以放要審查員照做的句子(表態記錄那句就是先例)。Codex 編排時走另一條通道:先武裝、派子代理那一刻領取同一份文字,圖譜算失敗就不武裝。掛鉤檔受指紋保護,而且是複製進每台機器的使用者目錄,改了要重跑安裝才生效。

## 要做什麼

1. **判定每支檔的角色**:前端/後端/判不出。唯一入口放在既有判棧函式旁邊,建立在它的題組鍵上,不另造一套分類;需要讀內容時只讀檔頭的匯入區。依序:
   - (a) 專案宣告,見第 2 點;命中就用宣告的角色。
   - (b) 題組鍵對應角色:vue → 前端;node、cs、py、sql → 後端;.svelte/.tsx/.jsx/.css/.scss/.html(現在沒有題組鍵)→ 前端。
   - (c) 手機與 Android(題組鍵 kt、java、swift、dart)看匯入,名單刻意窄:
     - .kt/.java 匯入 androidx.compose、android.widget、android.view、androidx.recyclerview、androidx.fragment、androidx.activity、androidx.appcompat 任一 → 前端;有其他 android/androidx 匯入(例如 room、work、Context)→ 判不出;完全沒有 android 匯入 → .java 判後端(Java 後端服務常見,判不出會讓它們拿不到後端卡)、.kt 判不出(Kotlin 後端與 Android 非畫面檔分不開,寧可不附)。
     - .swift 匯入 SwiftUI → 前端;匯入 UIKit 且檔內宣告 UIViewController 或 UIView 子類 → 前端;其他判不出。
     - .dart 匯入 flutter 的 material、widgets 或 cupertino → 前端;只有 flutter foundation 或沒有 flutter → 判不出。
   - (d) .ts/.js 家族照既有 package.json 判定。package.json 解析失敗(容許 BOM)改回「判不出」,不再當成沒有依賴;這一改也會讓棧別題組對壞掉的 package.json 不出 node 題,屬於順手修正,要有測試。
   - 都不中就判不出,判不出就不附,不猜。
2. **專案宣告**:`.lumos/config.json` 的 `review_roles` 鍵,值是有序清單,每條 `{"path": "<路徑樣式>", "role": "frontend" | "backend" | "none"}`;`none` 表示強制判不出(拿來排除工具目錄、樣板)。第一條命中的算數。
   - 比對語意沿用既有排除清單那支(標準路徑樣式比對,星號會跨斜線;開頭 `**/` 會去掉再試一次);新寫一支回「第幾條命中」的小函式放在它旁邊,共用同一段比對。文件寫明 `web/**/*.ts` 比不到 `web/a.ts`、要涵蓋整個目錄就寫 `web/*`。
   - 壞宣告(不是清單、某條不是物件、缺鍵、角色值不在三者內、樣式不是字串或空字串、以 `./` 或 `/` 開頭、含反斜線、JSON 壞掉)→ 整份宣告不用、退回不宣告的判定,並回一句警告;警告做法照棧別題組設定讀取那支(回值加警告清單,由呼叫端印)。
   - 宣告只影響角色,不改棧別題組與慣例 skill 的判定(見已知限制)。
3. **讀哪個版本**:改動範圍 `起點..終點`。檔案匯入與 package.json 讀終點提交的內容;被刪的檔,匯入與它往上找的 package.json 一律讀起點(同範圍連 package.json 一起刪也照樣找得到);宣告讀起點提交的內容,跟派工鏡頭「圖譜只信起點」同一個理由——被審的分支不能自己改宣告決定自己拿到哪張卡。代價:新加的宣告要合進主線後才生效。
4. **改動檔清單(兩處共用同一支)**:範圍內改動的檔,改名算新路徑、刪除的檔照樣算(讀起點);剔除測試檔(沿用推送前分級的測試檔樣式)、消費專案裡原封不動的工具檔(沿用推送前分級那段判定)、文件與帳檔(沿用派工鏡頭種子過濾)。只要有一支前端檔就附前端卡。
5. **成本上限**:用一次批次讀取拿內容,不逐檔開子行程;最多讀 300 支檔的內容,超過的只用題組鍵判(手機檔一律判不出),並在角色段印一句「超過上限,後面 N 支只看副檔名」。角色計算從掛鉤給 lumos 的同一份期限裡先扣,最多 3 秒、且不超過期限的五分之一,剩下的才給圖譜那段;到時間就用已算好的部分。
6. **兩張角色鏡頭卡**,內容單源放在 lumos 本體、跟棧別題庫同形狀(每題有語意題號、題文、是否只限網頁)。不放進派工範本的理由:範本不知道這次改到前端還是後端,附哪張卡只能由程式看改動決定;消費專案也是跟著 lumos 本體拿到。範本只放一句指路。題號:
   - 前端卡:fe-race 非同步回來的順序與取消(vue 已有同型一題,本卡涵蓋其他框架與手機)、fe-unmount 元件卸載後還在更新、fe-states 載入/錯誤/空資料三種狀態、fe-hydration 伺服端渲染與瀏覽器首次畫面對不上(只限網頁)、fe-a11y 鍵盤走得到/標籤/對比、fe-xss 把使用者內容當 HTML 插入、token 放在 JS 讀得到的地方、跳轉網址沒驗(只限網頁)。
   - 後端卡:be-api-compat 對外 API 相容(欄位改名、刪欄位、預設值改變)、be-authz 每個端點的授權檢查。分頁與外呼逾時已在棧別題,不重複。
   - 每題照既有慣例「挑一個具體輸入走一遍」。
7. **接上 Claude 派工通道,只給要的那一席**:
   - 派工詞同時有圖譜鏡頭那行與一行 `LUMOS-ROLE-CARDS: on` 才附;掛鉤把這個意思轉成傳給 lumos 的旗標,沒有這行就不算角色。
   - 派工範本第 3 節審查鏡頭加第 5 點,並在第 3 節派工詞放這一行;第 7 節多席派工的分流句比照資料狀態五問:只留給正確性/邏輯席,其他席刪掉這行;架構對齊席與資安席的範本不放。
   - 角色段放在「參考資料」框外,開頭一句「照下列題逐一挑一個具體輸入走一遍;對上的發現在標題附題號」。宣告壞掉時,角色段第一行印那句警告(就算全部判不出、沒有卡,也只印這一行)。
   - lumos 那邊先算角色、再算圖譜。回傳的 JSON 多一個角色段欄位;成功時角色段同時接在圖譜文字之後(舊掛鉤照舊附得到)。lumos 自己超時或回非零碼(沒有圖譜、起點不在主線)時,只要角色算得出來,照樣印出帶角色段欄位的 JSON。範圍不合法時角色也算不出來,什麼都不附。掛鉤在超時與非零碼兩條分支,讀得到角色段就附上(超時分支附在超時說明之後)。掛鉤被外層時間上限直接砍掉時什麼都拿不到,這是已知限制。
   - 舊掛鉤配新 lumos:成功時角色段在文字裡,照附;失敗時沒有。新掛鉤配舊 lumos:回傳沒有角色段,跟現在一樣。
8. **推送前分級多印一行**「角色:前端 N 支、後端 M 支、判不出 K 支」:只印在給人看的輸出、不進 JSON、不是檢核題,不改變分級;宣告壞掉的警告也印在這裡。
9. **要一起改的鏡像處**:代碼審 skill 步驟 2(圖譜鏡頭那段指到角色卡)、專案筆記 skill 的代碼審指令頁與 reference 裡描述派工鏡頭附段的地方、[[Systems/hook逾時預算]](角色計算的 3 秒與先後順序)、派工掛鉤改完要重核可指紋、發佈說明寫明要重跑安裝才拿到新掛鉤。代碼審 reference 的審查框架只寫「完整鏡頭以範本第 3 節為準」,不用改;它歷史區那份也不動。派工範本這支 .md 目前沒有 Systems 節點管(每支檔有家不管 .md,既有欠帳,同資料狀態鏡頭計劃的處理),範本改動的說明寫進 [[Systems/design-loop]]。
10. **守衛測試**:兩張卡任一題被刪或題文掏空就紅,並點名題號;範本第 3 節第 5 點與標記行、第 7 節分流句被刪也紅;架構對齊席、資安席範本出現標記行也紅;代碼審 skill 步驟 2 的指路句被刪也紅。
11. **接線前小實驗**:判定、卡片、lumos 回傳都做好之後、在範本放進標記行之前,先做一次兩席對照(見 S15)。這樣 d1「先用最便宜的形式量效果」在正式接線前就有一個數字;沒有可用樣本就明講,照樣接線,等撤除條件去量。

## 已知限制

- 空殼 package.json 會讓底下的前端 .ts 判成後端;出路是宣告。
- Next.js、Nuxt 這類全端框架同一個 package.json,API 路由與伺服端檔會被判前端、拿不到後端卡;出路是宣告那幾個目錄為 backend。
- 後端套件裡的 .tsx 樣板(例如寄信樣板)會被判前端;出路是宣告 none 或 backend。
- 手機端有 android/androidx 匯入但不是畫面的檔(資料層、Room、WorkManager)判不出、不附卡;Kotlin 後端也判不出。
- Android 專案裡完全沒有 android 匯入的純 Java 檔(資料類、工具類)會判後端、拿到後端卡;出路是宣告那個模組為 none 或 frontend。
- 宣告只影響角色卡,同一支檔的棧別題組與慣例 skill 仍照 package.json 判,兩邊可能不一致。
- 掛鉤被外層時間上限直接砍掉時,角色卡跟圖譜段一起沒有。
- Codex 編排的代碼審沒有角色卡(d4)。
