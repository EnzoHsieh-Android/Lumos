# 逃逸帳對得起來_計劃

PRIOR-ART: 比例的 Wilson 信賴區間(統計標準做法);稽核帳「只追加、撤回也是追加一筆撤回紀錄」(會計沖銷的做法,不改舊列);專案裡決策的翻案寫法(`decision-supersede` 讓舊的標 `valid:false` 並指向新的,舊的仍留在帳上看得到);Meta RADAR(arXiv 2605.30208v1)用結果校準自動化程度的前提——先有可信的分類事故率。機制層沿用:逃逸帳與讀取函式 `_escape_rows_for`、圖譜寫入鎖 `_vault_write_lock`、處置閘過關時寫進治理帳的收斂紀錄、定錨分級 `_loop_anchor_tier`(取帳上第一筆)、`_plan_for_loop` 對計劃的查法;新統計照既有 `loop canary-stats` 的「一本帳一支統計子指令」形狀放成 `loop escape-stats`,不放進 `gov`(`gov` 讀的帳是寫死的一組,舊編號 r1 架構席指出)。
RETIRE-IF: 逃逸帳改成由別的系統(例如事故單)取代、不再追加;或三個月後各類別放行數仍都不到 20、統計從來沒被拿來做決定(量尺沒人用)。

## 一句話

先讓逃逸帳每一列都說得清「歸給哪一種迴圈、佐證是什麼、有沒有被撤回」,再用同一個單位(迴圈)算每一類別放行之後漏了多少。

## 做法

### 一、每一列說清楚是哪一種迴圈

- 新寫的列加 `loop_kind`:`design`(設計審迴圈)、`code`(代碼審迴圈)、`plan`(沒有審查帳的計劃,例如風險低直接實作)。
- ★列上已經記了 `loop_kind` 就以帳上的為準★,不因後來才有審查紀錄就事後改類(代碼審 r1 外家兩席);沒記的舊列才用下面的判法推。
- 判法寫成一支函式,寫的一側與讀舊列都呼叫它,**只看兩個欄位:`loop` 與審查帳的審查紀錄**:`loop` 以 `code-` 開頭 → `code`;否則審查帳裡有這個編號的**審查紀錄**(kind 是 none/caught/missed 的列;規格閘自己的 `kind=spec-gate` 留痕不算——風險低沒審的計劃也會有那種列,外家席抓到)→ `design`;都不是 → `plan`。撤回紀錄不是逃逸事件,不帶 `loop_kind`。(代碼審記到 major 自動記的那種,`loop` 已經是去掉 `code-` 的計劃名,所以自然落在 `design` 或 `plan`,不用另看站名。)
- 這種列的意思是「設計審放過、代碼審接住」——對設計審迴圈而言它是**下一站接住**,不是漏到下游;第四節的站名規則就是這樣分的。設計審迴圈的「漏網」只算過了代碼審之後才被發現的(CI、正式環境、使用者回報…)。

### 二、每一列要有缺陷佐證

- 新寫的列至少要有 `sha` 或 `defect_ref` 其中之一,去掉頭尾空白後不得是空的。手動記帳今天只把 `--defect-ref` 寫進列、`--sha` 沒寫進去(r2 正確性席重現),這次一起補上。兩個都沒有時,要另給 `--missing-defect-ref "<為什麼沒有>"`(理由用獨立旗標;不用 `--no-` 開頭,專案裡 `--no-X` 都是「關掉 X」),理由至少 4 個字而且有實字,否則擋下;理由寫進帳列的 `defect_ref_missing` 欄。
- 手動記帳這次也包進 `_vault_write_lock`(跟自動記、撤回同一把,整個 `loop escape` 指令族一致)。
- 三份操作說明(lumos-design-loop、lumos-code-loop、lumos-project-notes 的逃逸記帳範例)同一次改動裡同步補上。
- 舊列兩個都沒有的,統計時列為「無佐證」,不參與去重。

### 三、能撤回,而且看得到

- **指令**:`lumos loop escape --withdraw <token> --reason "<理由>" --withdrawn-by "<誰>"`。撤回者由呼叫的人明講、不自動去讀 git 設定;旗標叫 `--withdrawn-by` 而不是 `--by`(代碼審 r1 架構席:`--by` 在別的子指令已有兩種意思)。撤回者是自報的、不驗身分。token 在 `--list` 每一列印出來。
- **撤回紀錄長這樣**:`{"kind":"withdraw","target":"<被撤的 token>","reason":"…","by":"…","ts":"…","token":"<新的 ESC- 編號>"}`——有自己的 token,不跟目標共用;沒有 `loop`、`stage`、`severity`、`loop_kind`(它不是逃逸事件)。
- **擋下的情況**:目標 token 不存在、目標已經被撤過、目標本身是撤回紀錄(撤回不能再撤;要反悔就重記一列)、撤回者空白、理由不到 4 個字或沒有實字(跟缺佐證理由同一道門檻);`--withdraw` 跟記帳參數、`--list`、`--auto` 混用(比照 `--auto` 既有的不准混用)。
- **確認目標用原始讀法**:另拆一支「讀原始列」的函式(`_escape_raw_rows`,含撤回紀錄、只跳過壞行與非物件行),`_escape_rows_for` 建在它上面再過濾;撤回確認目標、去重與清單都用原始讀法——`_escape_rows_for` 永遠不吐撤回紀錄,拿它確認會讓「已撤過」判不出來(r3 併發席、回滾席)。
- **上鎖與寫入**:整段「讀帳確認目標→寫入」包在 `_vault_write_lock` 裡(手動記帳今天沒上鎖,這裡要明確加);寫入走既有的 `_jsonl_append_verified`(讀回自驗);★帳本檔是符號連結就擋下的那道檢查不在這支函式裡,在 `cmd_loop_escape` 手動記帳那段★(r3 外家席),撤回要先過同一道檢查——把那段抽成一支函式,手動記帳與撤回共用。拿不到鎖時要印「擋下:…」:今天 `loop escape` 的指令分派外面沒有其他寫入指令那層接例外的包裝,這次要補上(r3 整合席、併發席),不讓例外直接冒出來。
- **讀的一側一律認得撤回紀錄**:`_escape_rows_for` 讀到的列先過兩道:①不是 JSON 物件的列(`null`、陣列、字串)當壞行跳過;②`kind=withdraw` 的撤回紀錄**永遠不當成逃逸列回傳**。另加參數 `include_withdrawn`(預設否):
  - 統計類讀者(問閘尾漏斗、治理帳統計、健檢的撤除條件分子、小改動閘的歷史檢查、escape-stats)用預設,**不算**被撤的列。
  - **自動記的去重用 `include_withdrawn=True`**:撤回過的仍算「已經記過」,同一個 (迴圈, 站名, sha) 再觸發不會悄悄補回來。
- **清單照樣列、標出來**:`loop escape --list` 保留自己讀檔、對壞行寬容的寫法,列出所有逃逸列,被撤的標「已撤回(理由、誰、何時)」;撤回紀錄本身不另列成一行逃逸。`--list --withdrawn` 只列撤回過的那些(是 `--list` 的修飾,單獨給會擋下並提示)。
- **規則缺口統計**:保留自己找檔的讀法(它要支援知識庫就在 repo 根的佈局,也排在找到知識庫之前跑);讀到的列套同一支「是不是撤回紀錄、是不是被撤回」的判斷函式後再數。
- **舊版 lumos 讀到撤回紀錄**:還沒更新的消費專案跑舊版 `--list`,會把撤回紀錄當成欄位不標準的可疑列印出來(不會壞,只是吵);在說明裡寫明要 `lumos update`。

### 四、逃逸率(新指令 `lumos loop escape-stats`,唯讀)

- **單位一律是迴圈**:
  - 分母:放行了的迴圈數。放行 = 治理帳有這個迴圈 `kind=converged` 的紀錄(處置閘過關時寫的;設計審與代碼審過處置閘都寫在 `gate=design-loop` 這個閘名下,`nodes` 帶迴圈編號——代碼審通過留痕 `gate=code-loop, kind=passed` 不帶迴圈編號,不用它),而且審查帳裡有這個編號的審查紀錄(排除測試或別的工具寫出、審查帳沒有對應審查的收斂紀錄)。
  - 同一個迴圈同時有 `converged` 與 `cap-reached`/`rewrite` 時:**只要有任何一筆 `converged` 就算放行**(先跑滿、後來又審過關是真實會發生的)。
  - 分子:分母裡,至少有一列有效逃逸(沒被撤回、不是下一站接住、不是歸因不明)的迴圈數。率一定在 0 到 1 之間;某格放行數是 0 就印「—」不算率。
- **下一站接住**:站名是 `實作`、`code-loop`,或以 `push-gate` 開頭(推送閘擋下,含 `push-gate-unreviewed`)的,另列一欄,不算漏網。其他站名(CI、prod、使用者回報、消費專案真推送…)算漏網;不認得的站名算漏網並另列「站名不認得」幾列。
- **歸因不明**:先剔掉無佐證的列(sha 與 defect_ref 都空,不參與比對);sha 與 defect_ref 各自當一個比對鍵,任一個對到兩個以上迴圈就算(代碼審 r1 外家否決席);再只看屬於分母母體(放行了的設計審或代碼審迴圈)的列;同一個佐證在這些列裡還對到兩個以上迴圈,才算歸因不明、不算進任何分子,另列筆數。對到一個就歸給那一個——自動記會把同一個 sha 記到範圍碰到的每份計劃,那些沒審查帳的計劃不該讓真正受審的迴圈被排除(r3 正確性席、邊界席)。
- **沒放行的迴圈**:沒有任何 `converged` 紀錄的迴圈(以 `cap-reached` 或 `rewrite` 收尾、或還開著的)底下的逃逸列,另列「未放行迴圈的逃逸」筆數,不進任何類別。
- **類別**:分級 × 範圍類。
  - 分級:`_loop_anchor_tier`(帳上第一筆帶 tier 的值;帳上前後不一致時以第一筆為準,跟處置閘同一支);都沒有就是「未定錨」(2026-09-26 數,代碼審 146 個迴圈裡 33 個早於分級制度)。
  - 範圍類:查計劃時先把 `code-` 前綴去掉、兩邊都做 NFC 正規化,再用 `_plan_for_loop`(直接修在它裡面,其他呼叫者一起受惠);計劃的 `scope/<類>` 標籤;沒有就「未分類」;有兩個以上就每個都算一次,輸出註明各列加總會大於全體。
  - `plan` 類(沒有審查帳)沒有分母,只列逃逸列數,不算率。
  - ★`code` 類的率只含手動記的逃逸★:自動記的逃逸全部歸給計劃名(設計審或計劃),從不歸給 `code-` 迴圈,所以代碼審那一格的率天生偏低。輸出在 code 類旁明寫「只含手動記的逃逸,低估」;要改自動記的歸因是另一件事,這一期不做(r3 外家席)。
- **輸出**:只印有放行數的類別組合(不印全交叉表的空格);每類印放行數、有漏網的迴圈數、率、95% Wilson 區間、下一站接住數;放行數少於 20 的標「樣本太少不下結論」,仍印原始數字。末尾印全體的無佐證、歸因不明、站名不認得、未放行迴圈的逃逸各幾列,以及撤回過幾列。

## 之後另開(不在本案)

- **②抽查已放行的改動**:舊編號 r1 抓到的前提要先解——每週上限要在寫入鎖裡判;重現指令要有逾時;誰在什麼時候觸發(接到每日治理排程)要寫明;抽查確認的缺陷走本案的撤回路徑;消費專案預設不抽(私有程式碼不送外部服務);「已推上遠端」要用遠端分支判,不能只看通過留痕。
- **③盲審對照實驗**:舊判準「12 對裡 3 對以上盲審較多」在沒有差別時也約 98% 會觸發(舊編號 r1 正確性席算的),要換成有鑑別力的檢定並先算要幾對;審查帳要有盲審與配對席的欄位;「不給看原審查」光靠派工詞守不住(帳本檔案讀得到),要換成材料隔離的做法。

## 條款

- [S1] 當新寫一列逃逸帳,它應帶 `loop_kind`,且值只由 `loop` 欄與審查帳的審查紀錄依第一節規則決定(規格閘留痕不算);舊列讀出來時應用同一支函式推出同樣的值 [test:t_escape_loop_kind_written_and_inferred]
- [S2] 若手動記逃逸帳時 sha、defect_ref 去掉空白後都是空的,又沒有至少 4 字實字的 `--missing-defect-ref` 理由,則寫入應被擋下;手動帶的 `--sha` 應寫進帳列,理由應寫進 `defect_ref_missing` [test:t_escape_manual_requires_defect_ref]
- [S3] 當一列被撤回,統計類讀者(問閘尾漏斗、治理帳統計、escape-stats、規則缺口統計)都應不再算它;`loop escape --list` 應仍列出它並標已撤回與理由 [test:t_escape_withdraw_hidden_from_stats_shown_in_list]
- [S4] 若撤回的目標不存在、本身是撤回紀錄、撤回者空白,或理由不到 4 字實字,則應擋下且帳本不變;拿不到寫入鎖時應印擋下訊息而不是拋出例外 [test:t_escape_withdraw_validation]
- [S5] 當一列被撤回後同一個 (迴圈, 站名, sha) 再被自動記觸發,不應再寫入新列 [test:t_escape_withdrawn_not_resurrected_by_auto]
- [S6] 當 escape-stats 算率,分子與分母都應以迴圈為單位、分母只算 kind=converged,任何類別的率都不得大於 1,放行數為 0 的格不得算率 [test:t_escape_stats_rate_unit_is_loop]
- [S7] 若一列的站名是實作、code-loop 或以 push-gate 開頭,則它應列在下一站接住而不算進率;不認得的站名應算漏網並另列筆數 [test:t_escape_stats_next_stage_and_unknown_stage]
- [S8] 若同一個佐證出現在兩個以上迴圈,則這些列應列入歸因不明;若迴圈以 cap-reached 或 rewrite 收尾,則它的逃逸應列入未放行迴圈的逃逸;兩者都不算進任何類別的分子 [test:t_escape_stats_unattributed_and_unreleased_buckets]
- [S9] 若迴圈在審查帳沒有分級,則應歸在未定錨;帳上分級前後不一致時應取第一筆;計劃有兩個範圍類標籤時應兩類各算一次並註明加總會重複 [test:t_escape_stats_category_untiered_and_multi_scope]
- [S10] 若迴圈編號以 code- 開頭,則查計劃時應去掉前綴並做 NFC 正規化後找到對應計劃 [test:t_plan_for_loop_strips_code_prefix_nfc]
- [S11] 若某類別放行數少於 20,則輸出應標樣本太少不下結論,且仍印出原始數字 [test:t_escape_stats_small_sample_flag]

## 回退

- 撤回與 `loop_kind`、`defect_ref` 規矩:還原寫入端與撤回指令;★但「讀到 `kind=withdraw` 一律不當逃逸」那道過濾要留著★——不然已寫進帳的撤回紀錄會被各讀者當成新的逃逸列算進去(r3 外家席)。回退後撤回失效、被撤的列重新被算;舊版 `--list` 會把撤回紀錄印成可疑列。回退說明要寫這幾點。
- `_plan_for_loop` 的前綴與 NFC 修正:既有唯一呼叫者自己已經先去掉 `code-`,不受影響(r2 回滾席實跑);真正依賴它的是 escape-stats——單獨回退這一項會讓 escape-stats 把 `code-` 迴圈靜默歸成「未分類」,所以要跟 escape-stats 一起回退。
- escape-stats:純唯讀新指令,移除即可。

## 實務隱患

- 併發:撤回的「確認目標→寫入」與自動記同一把寫入鎖;兩個會談同時撤回同一筆,第二個在鎖裡會看到已撤過而擋下。讀的一側遇到寫一半的最後一行略過。
- 效能:escape-stats 要讀逃逸帳、審查帳(約 1.7MB)、治理帳(約 13MB)與計劃筆記;是手動或週報才跑的唯讀指令,不進任何提交或推送的閘。
- 守衛面(不排除):撤回會讓漏斗與統計少算,是會讓數字變好看的操作——所以撤回一定要理由與撤回者、清單一定標出來、`--withdrawn` 可以單獨列;這一期不限制誰能撤(單人 repo),REVISIT 時看撤回次數。
- 已排除:金流:只讀寫本機帳本,不碰任何付款或計費
- 已排除:對外送出:不呼叫任何外部服務
- 已排除:不可逆:只追加,不改舊列;撤回本身也列得出來

## 誠實界線

- 逃逸帳只記得到「後來浮上來的錯」;沒浮上來的漏網,這份量不到(那是之後抽查那份的事)。
- 「歸因不明」與「未放行迴圈的逃逸」一律不算進率,方向是低估;共用一次 CI 失敗的迴圈越多、重寫收尾的越多,低估越多。
- 站名分類是寫死的對照,新站名出現時算漏網並另列,要人補對照。
- 樣本很小(一個類別要 20 個放行才下結論),這一期只保證「開始量得對」。
