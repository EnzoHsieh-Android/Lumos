# 對話裡不准跑全套測試_計劃

> 白話:在 Claude Code 的對話裡直接打 `python3.14 scripts/test_lumos.py`(沒帶 `-k`、`--suite`、`--list`)會跑滿約 8 分鐘的全套,超過對話工具的時間上限、還會吃掉大量記憶體。規則寫在 CLAUDE.md 與記憶裡已經一再被繞過(2026-11-07 又兩次)。這份計劃讓測試執行器自己認出「在對話裡、又不是推送前閘」而且沒帶任何篩選條件的全套呼叫,當場拒跑並印出該怎麼跑子集。設計審跑滿三輪沒收斂,使用者 2026-11-08 裁「照你建議」:接受風險、縮成最小形狀,判斷只看有沒有帶篩選條件,已知的繞法寫進天花板。使用者原話(2026-11-07):「又在跑全套，要講幾次」「你可以不斷繞過這個規則，代表這個功能根本沒做好吧」「推完戊線就去做擋全套的機制」。

PRIOR-ART: 同一個執行器入口已經有兩個「在唯一進入點清掉外部注入」的先例(清 `GIT_*` 變數、關掉子程序上色),理由是對現有與未來的呼叫一律成立、不靠每個呼叫點自己記得;`scripts/scenario_probe.py` 開巢狀 Claude 子程序前也拿掉 `CLAUDECODE`。Claude Code 會在它開的殼裡設 `CLAUDECODE=1`(本機實測 2026-11-08);推送前閘在跑測試前 export `LUMOS_PUSH_ATTEMPT`(`scripts/hooks/pre-push`)。借用這兩個既有標記判斷,不另造。不選 Claude Code 工具前掛鉤比對指令字樣:只認得到字面寫法,`python3.14 -m`、shell 別名、先 cd 再相對路徑都繞得過。
RETIRE-IF: 計數檔(`~/.cache/lumos/full-suite-guard/events.jsonl`)八週內逃生門放行次數超過擋下次數(擋錯多於擋對)→ 撤掉改回只提醒;擋下一直有、逃生門很少 → 留著當守衛。

設計第四版(2026-11-08,設計審 r3 後人裁接受風險、縮成最小形狀)。

[[Projects/測試總檔預設切片_計劃]] d1(2026-11-05)在「預設切片 / Claude Code 工具前掛鉤擋 / 兩個都做」裡選了預設切片,解的是「全套被單一程序跑、慢到三小時」。本案解的是另一件事:全套根本不該在對話裡跑(就算切片也要約 4 分鐘、超過對話工具的兩分鐘預設上限、還占住使用者機器)。使用者在 2026-11-07(那個決定之後)明確要求做這個擋,所以不算翻案;擋的位置也不是那次不選的「工具前掛鉤」,是執行器本身。

## 範圍

### 做

1. **一進 main 就記下是不是在對話裡**:清 `GIT_*` 那段之前,先讀 `CLAUDECODE`、`LUMOS_PUSH_ATTEMPT`、`LUMOS_FANOUT_CHILD`、`LUMOS_ALLOW_FULL_SUITE` 四個值存進區域變數,接著把 `CLAUDECODE` 從 `os.environ` 拿掉(測試開的沙盒執行器與子程序不繼承);之後的判斷只讀存下來的值(解 r3 正確性 F1、通才 F1:原本「讀當下」與「先拿掉」順序打架)。
2. **只看有沒有帶篩選條件**(取代第三版的估耗時佔比;使用者裁縮成最小形狀):新增 `_chat_full_suite_block(args, snap)`,回擋下訊息或 None。在對話裡(存下的 `CLAUDECODE` 是 `1`)、不是推送前閘、不是切片子程序、逃生門理由不合格時,參數裡沒有關鍵字(`-k` 或直接打名字)、沒有 `--suite`、沒有 `--list` 就擋;只帶 `--shard`、`--serial`、`-x`、`--ff`、`--seed` 這些不縮小範圍的旗標也擋。
3. **接在參數解析之後、`_fanout_wanted` 與 `_isolate_environment()` 之前**:那時還沒開任何子程序、沒建暫存根目錄、`HOME` 還是真的家目錄(解 r3 通才 F2、正確性 F2、架構 F2:隔離之後 `HOME` 已換成拋棄式目錄,計數寫不到真的家目錄)。擋下時印訊息到 stderr、回 2。逃生門合格時照常往下走,全套照樣預設切片(解 r3 通才 F5:放行後被強制單程序)。
4. **擋下訊息**:第一行「擋下:在對話裡不帶篩選條件會跑滿全套(約 8 分鐘),不准跑」;第二行講為什麼(超過對話工具上限、吃記憶體、推送前閘會自己跑);第三行起指令各自獨立一行:`python3.14 scripts/test_lumos.py -k <關鍵字>`、`--suite docs`、全套交給推送前閘(`git push` 放背景)或請使用者在一般終端機跑。**訊息不印逃生門的變數名**,逃生門只寫在 [[Systems/測試執行器]]。
5. **推送前閘的補救提示**(解 r1 正確性 F4、r3 正確性 F3):`scripts/hooks/pre-push` 紅燈那段兩處「下一步」從 `--ff -x` 改成逐支 `-k`:從完整輸出抓 `✗ FAILED <測試名>` 行(執行器對每支紅的測試都印這一行)取出測試名,每支印一行 `<python> scripts/test_lumos.py -k <測試名>`(最多 10 支,超過印「還有 N 支,看完整輸出」);一支都抓不到(紅在測試以外,例如切片子程序沒寫出摘要)時印「打開上面的完整輸出看紅在哪」,不印指令。執行器本身沒有其他地方印 `--ff -x` 叫人跑(說明文字裡的旗標介紹不算指令)。
6. **逃生門要帶理由**:`LUMOS_ALLOW_FULL_SUITE=<理由>`,理由照 `lint-waive --note` 既有判法(去空白後至少 10 字、至少一個文字或數字字元)才算數;不算數照擋並講要寫理由。只在「本來會擋」時印一行「對話裡放行,理由:<理由>」。
7. **計數**:擋下與逃生門放行各追加一行到 `~/.cache/lumos/full-suite-guard/events.jsonl`(時間、種類、理由)。寫法走 `scripts/lumos` 的 `_home_cache_append_line`(從既有 `_drift_m1_ledger_miss` 抽出的單一來源:逐層信任檢查、`O_NOFOLLOW`、`0600`,開了再確認是自己的一般檔),只在真的要記時才載入 `scripts/lumos`,平常啟動不載;載入或寫入失敗都略過、不影響判斷(代碼審 r1 架構對齊席:原本自己開檔追加,少了信任檢查,`~/.cache/lumos` 被換成連結時會寫到別處)。不寫治理帳:治理帳在 repo 裡,執行器寫了會讓「工作目錄乾淨」的測試與提交前檢查看到改動。
8. **手冊**:[[Systems/測試執行器]] 補 WHY、逃生門寫法、`CLAUDECODE` 被拿掉的副作用(之後開的子程序看不到它;現在只有 `scripts/scenario_probe.py` 讀它而且本來就拿掉)。

### 不做

- 不在 CI 擋:CI 沒有 `CLAUDECODE`。
- 不擋人在一般終端機跑全套:沒有 `CLAUDECODE` 就不判。
- 不寫治理帳(理由見做 7)。
- 不管其他 AI 工具(Codex 等沒設 `CLAUDECODE` 的):另案。
- 不擋對話裡 `git push` 觸發的推送前閘全套:那是規定的跑法,推送要放背景跑。
- 不新增 `--lf`(理由見做 5)。
- 不估耗時、不判佔比(第三版的做法;r3 繞過席指出佔比不綁絕對耗時、通才席指出兩成線落在分片邊界,使用者裁縮成只看有沒有篩選條件)。

## 實務隱患

- **人在 Claude Code 的終端分頁裡手跑**:那個殼也有 `CLAUDECODE=1`,會被擋;要帶逃生門加理由。
- **Claude Code 改了變數名**:擋不到但不會擋錯;寫成回頭條件。
- **測試沙盒繼承環境**:做 1 處理;驗收的子程序測試從頭組環境(只給 `PATH`、`HOME`、`CLAUDECODE=1` 與私有 `TMPDIR`),不繼承外層的推送前閘、切片子程序與逃生門標記,免得在推送前閘裡真的開出全套。
- **消費專案**:測試總檔會被安裝進消費專案,那邊在對話裡跑全套也會被擋,跟本 repo 一致。
- **自動迭代迴圈**:headless 的 Claude 也設 `CLAUDECODE`;它跑全套同樣被擋,要改走推送前閘。
- 已排除:金流:不碰付款
- 已排除:對外送出:不連網、不呼叫外部服務
- 已排除:不可逆:只改執行器入口一段判斷與推送前閘紅燈提示,計數檔在工作目錄外;退提交即回原狀
- 守衛面:不排除——這是一道新的擋停(擋 AI 在對話裡跑全套),判風險高

## 天花板

1. 只認 Claude Code 設的 `CLAUDECODE`;別的 AI 工具不受限。
2. 逃生門與兩個豁免標記(`LUMOS_PUSH_ATTEMPT`、`LUMOS_FANOUT_CHILD`)都是環境變數,AI 讀原始碼就知道;逃生門至少留理由與計數,手設豁免標記沒有紀錄(屬刻意偽造,不防)。直接手跑 `scripts/hooks/pre-push` 腳本也會帶出 `LUMOS_PUSH_ATTEMPT`(r2 繞過 F5),同屬這一類。
3. `env -u CLAUDECODE`、`CLAUDECODE=0`、tmux 或 cron 這類不繼承環境的新程序都繞得過(r1 繞過席實測 `env -u` 有效)。
4. 只要帶了任何篩選條件就放行:`-k t_`(每支測試名都含)等於全套,擋不到;`--suite docs` 也照放(r3 繞過席量過它不短)。這是使用者 2026-11-08 裁縮成最小形狀時接受的風險;分片輪流跑(`--shard i/16` 在只帶分片時會擋,但 `-k t_ --shard i/16` 不擋)同屬這一類。
5. 對話裡 `git push` 讓推送前閘跑全套是規定的跑法,不擋;推送要放背景跑。
