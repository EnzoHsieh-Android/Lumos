# 測試綁定一行一支提醒_計劃

白話:筆記裡寫 `[test:t_a,t_b,t_c]` 是在說「這三支測試守著這句話」。可是一句話對三支測試,讀的人分不出哪支守哪一點;搬遷測試時整批套上去,其中一支其實沒在守(核心斷言在走不到的分支),也沒人看得出來。這份在提交時抓出「新寫的一行一次綁兩支以上」,提醒拆成一支一行、每行寫那支守的是什麼。只提醒、不擋。

依據:
- rtb 第三輪提案 A4(`[[Projects/交接2026-10-03_計劃]]`〈rtb 第三輪提案〉第 5 優先):搬遷測試時一句話套一批綁定,其中一支核心斷言在走不到的分支;要求每支綁定各寫一行理由。
- 2026-10-07 本 repo 現有筆記試算:帶 `[test:]` 的行 1648 行,一行綁一支 1183 行、兩支以上約 200 行(兩支 119、三支 47、四支 19、五支以上 15)。上線後只看新寫的行,既有的不回頭提醒。
- 2026-10-07 乾淨代理核對:這件事只在交接筆記的待辦裡,沒有計劃、程式裡也沒有;現有的 guard kill、配方不在合約清單提醒、test_refs、S20 只管「測試存在、殺得掉」,抓不到「一句套一批其中一支沒在守」。

PRIOR-ART: 最小解在既有的提交前寫法提醒這一層([[Projects/新寫句子的數量與位置提醒_計劃]] 剛做好的 note_shape.wording):只看新寫的行、只提醒、引號是誤報出口、舊行尾補括號只看補上的那段,全部沿用;測試名稱怎麼切沿用 note-shape 與 S20 共用的 `_test_names_of`。外界做法:需求追溯工具(Doorstop、OpenFastTrace)也要求一條需求對一個驗證項目各自寫連結,本案用「一支一行」達成同樣效果,不加新語法。
RETIRE-IF: 上線滿 8 週,從 hinted 帳(check=wording、rules 含 binding)抽 20 筆對回提交:一半以上作者沒拆、或拆了也只是把同一句複製幾次(理由沒變具體),就撤掉這條規則。
REVISIT:2026-12-07 數 hinted 帳裡 rules 含 binding 的筆數並抽 20 筆對回提交,照 RETIRE-IF 判
REVISIT:2026-12-07 抽樣的那 20 筆裡看有沒有〈天花板〉4 的情形(值裡夾引號被拆成多支);有一筆就改成先用 `_ns_neg_quote_spans` 找值裡的成對引號、整段剔掉再切名稱

## 範圍

- **做**:新寫句子寫法提醒多一條規則「綁定」;hinted 帳的 rules 多一個值 binding;手冊 `skills/lumos-project-notes/commands/03-寫回圖譜.md` 那一列補半句。
- **不做**:擋;新語法;判斷那支測試到底有沒有在守(那是 guard kill 的事);舊行不回頭提醒;`[test-gone:]` 不看(那是已經不在的測試)。

## 做法

1. **哪些行**:跟數量、位置兩條同一批——body 與 summary 區塊、圍欄外看得見、不是 REVISIT 的新行;舊行原封不動只在句尾補括號時只看補上的那段。
2. **怎麼數**:掃原文、走專案唯一的欄位掃描器 `_slot_scan`(slot_parse 也走它),起點落在成對引號裡的 `[test:]` 欄位不算、值裡整個被引號包住的名稱也不算(同另外兩條規則的引號出口;代碼審 r2:原本先把引號遮成看不見的字,值裡夾的引號被當成一支),再用 `_test_names_of` 切名稱——跟 note-shape 的 test_refs 與 S20 同一套:鍵名不分大小寫、冒號收全形、行內程式碼裡的範例不算、反引號包住的名稱照認(代碼審 r1:原本先找字面 `[test:` 又餵遮掉行內程式碼的文字,這幾種全漏或變亂碼);去重後兩支以上就提醒一次。佔位名稱(`_ns_tr_placeholder` 認的)不算。一行裡寫兩個 `[test:]` 各一支也算一行綁兩支。
3. **同一行**:數量與位置照順序取第一個;綁定另外看,同一行可以兩則都出(代碼審 r1:原本同一行只出一則,數量先命中就把綁定吞掉,修完數量那行變舊行、綁定永遠不再提醒)。帳本的 lines 數不重複的行。
4. **印出**:每處一行「路徑:行號 [綁定] 片段」,下面一行「→ 這行綁了 N 支(名稱…):拆成一支一行,每行寫那支測試守的是哪一點」,名稱最多列 5 支、其餘照檔內既有寫法講「等 N 支」;記帳 rules 多 binding。

- **回滾**:還原本案提交。

## 驗收條款

- [S1] 當提交新寫的正文、摘要行或計劃條款在一行裡綁了兩支以上不同的測試(一個 `[test:]` 寫多支,或多個 `[test:]` 各一支),`note-shape --staged` 應 印出綁定提醒與那幾支的名稱,回傳碼 應 跟沒有這行時一樣 [test:t_note_wording_binding_hint]
- [S2] 當一行只綁一支、同一支寫兩次、只有 `[test-gone:]`、綁定寫在行內程式碼或引號裡、行在圍欄裡、行是 REVISIT 行、舊行原封不動只在句尾補了不含綁定的括號,綁定提醒 應 不出 [test:t_note_wording_binding_quiet]
- [S3] 有綁定提醒時,hinted 帳那一筆的 rules 應 含 binding;`note_shape.wording=off` 時 應 不出 [test:t_note_wording_binding_ledger]

## 回退

還原本案的功能提交。設定與帳本格式沒變(rules 只是多一個值)。

## 天花板

1. 只看一行裡綁了幾支,不判那支測試到底有沒有在守那句話;拆成一支一行之後,理由寫得具不具體只能靠人。
2. 一句話跨好幾行、每行各綁一支的寫法照樣不提醒。
3. 只提醒不擋。
4. `[test:]` 的值裡夾一段引號、而且引號跨過逗號(`[test:t_a,「t_b,t_c」]`)時,名稱先被逗號切開,引號那段會被算成兩支、印出殘缺的引號(代碼審 r3 正確性席,編排者重現);「整個被引號包住的名稱不算」是逐名稱比頭尾,沒有沿用 `_ns_neg_quote_spans` 的成對判定(代碼審 r3 架構對齊席)。
