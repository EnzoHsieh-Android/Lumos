# 改摘要單行的指令_計劃

白話:筆記開頭的「摘要」區塊一行一條(WHY:、RULE:、KEY:…),但 lumos 沒有指令能改其中一行——`lumos set` 只收單值欄位,改摘要只能手改,跟「開頭欄位一律用指令改」的規矩打架。rtb 這輪手改了 10 次,全是「同一行改一小段字」。這次加一個指令:給一段舊字和一段新字,工具在摘要裡找出唯一含那段舊字的那一行,換掉、驗證、寫回。

依據:Enzo 交棒單列的 rtb 第三輪待辦 D1;rtb 會談 2026-10-06 回覆的實測數字(見摘要 WHY 的出處)。

PRIOR-ART: 同工具 `guard bind`(`cmd_guard_bind`)已經用「片段比對、對到多條就擋」定位摘要裡的合約行,寫入走 `load_raw_for_edit` + `atomic_write_verify`(寫暫存、重新解析自驗、lint 不得多出新指紋、原子換檔);寫入上鎖照 `cmd_set` 包 `_vault_write_lock`。本案照這三樣組,不另寫讀寫或驗證。
RETIRE-IF: 2027-04-06 前各消費專案治理帳裡 `summary-line` 一次都沒被呼叫(手改照舊),就撤掉這個指令。

## 範圍

- 做:`lumos summary-line <節點> "<舊片段>" "<新片段>" [--nth N] [--dry-run]`。
- 做:定位——摘要區塊裡含舊片段的實體行;恰一行而且那一行裡只出現一次 → 換;零行 → 擋(rc2,講找不到);兩行以上、或同一行出現兩次以上 → 擋(rc2),列出每個候選的行號與前 40 字,教人給更長的片段或 `--nth N`(N 從 1 起,照摘要裡由上而下的順序數「含舊片段的出現處」)。
- 做:換完那一行只剩空白 → 拿掉那一行;摘要因此一行都不剩 → 擋(摘要不能空)。
- 做:那一行屬於跨多個實體行的條目(後面接著續行、或本身是續行)→ 擋,講不支援續行、請手改。
- 做:寫入照 `atomic_write_verify`(寫暫存、重新解析開頭欄位自驗、開頭欄位的格式檢查不得多出新問題,失敗原檔不動);同一次把 `updated:` 改成今天(本機日期,專案慣例 `datetime.now(timezone.utc).astimezone().date()`);印改前與改後那一行,並提示 `lumos lint <節點>`(筆記層級的檢查,例如 RULE 行欄位齊不齊,不在寫入自驗的範圍)。`--dry-run` 只印不寫。
- 做:指令說明字典、skill 指令速查(`commands/03-寫回圖譜.md`)、指令總數(ARCHITECTURE.md、`skills/lumos-project-notes/reference.md`)、總目錄 `commands/INDEX.md` 同步。
- 不做:插行、改前綴、續行、正文段落(正文用一般編輯)。
- 不做:改完自動跑結案連帶掃描(選配,另案)。

## 做法

1. `cmd_summary_line(env, node, old, new, nth=None, dry_run=False)`:`env.find` 解析節點(找不到走 `_node_not_found` 給近名候選);`_vault_write_lock` 內 `load_raw_for_edit`;摘要區塊的實體行用 `_notelines_regions` 判(`summary: |-`、`|`、`>` 之後縮排更深的連續行)。摘要寫成單行值 `summary: 一句` 的不支援(會報找不到),要改就手改或先改成區塊寫法。
2. 舊片段不得是空字串;舊、新片段都不得含任何換行類字元(`str.splitlines` 認得的全部);舊新相同擋下講「沒有要改的」(rc2)。
3. 收集所有出現處(行號, 在行內的位置);依範圍第 2 條判定;`--nth` 超出範圍 rc2。
4. 續行判斷沿用 `_ns_summary_logical`:目標行若不是某個邏輯條目的唯一一行 → 擋。
5. 新行 = 舊行把那一處換掉;若去掉縮排後是空的 → 刪行。`updated:` 行存在就換成今天,沒有就不加。
6. `atomic_write_verify(path, new_lines, "summary", check)`,check 驗新摘要裡含新的那一行(刪行時驗舊行不在);失敗原檔不動、rc2。
7. 印 `改前:…` / `改後:…`(刪行時印「已刪除」);成功 rc0。
8. 寫回 [[Systems/lumos-cli-write]](寫入指令的家)。

## 實務隱患

- **同一篇兩人同時改**:寫入包 `_vault_write_lock`,跟其他寫入指令排同一把鎖。
- **片段含特殊字元**:用純字串比對(不是正則),特殊字元照字面。
- **改到合約行(★INVARIANT★)**:`atomic_write_verify` 只驗 lint 沒有新指紋,不驗合約語意;合約行改字會讓綁定的測試對照失效——沿用既有規矩,合約行改動由推送前的合約閘把關。
- 已排除:金流:只改筆記的一行文字,不碰任何金流
- 已排除:對外送出:不連網、不送任何東西出去
- 已排除:不可逆:改的是版控裡的筆記,提交前可 git 還原;寫入失敗原檔不動
- 已排除:守衛面:不改任何閘的判定,只多一個寫入指令;寫入照既有的自驗與 lint 不得退步

## 驗收條款

- [S1] 當舊片段在摘要裡恰好出現一次時,summary-line 應 把那段換成新片段、把 updated 改成今天、印改前改後,其他行一字不動 [test:t_summary_line_replace]
- [S2] 當舊片段出現在兩行以上、或同一行兩次以上時,summary-line 應 rc2 不寫,列出每個候選的行號與前 40 字;帶 `--nth 2` 應 改第二個出現處 [test:t_summary_line_ambiguous]
- [S3] 當舊片段找不到、是空字串、含換行,或新片段含換行時,summary-line 應 rc2 不寫 [test:t_summary_line_rejects]
- [S4] 當換完那一行只剩空白時,summary-line 應 拿掉那一行;摘要因此變空時 應 rc2 不寫 [test:t_summary_line_delete]
- [S5] 當目標行屬於跨多個實體行的條目時,summary-line 應 rc2 不寫並講不支援續行 [test:t_summary_line_continuation]
- [S6] 當寫入自驗失敗時,summary-line 應 rc2、原檔不動;`--dry-run` 應 只印不寫;成功後 應 提示 `lumos lint <節點>` [test:t_summary_line_verify]

## 回退

退回本案的提交即可:只新增一個寫入指令與說明,沒有改動既有指令的行為或資料格式。

## 天花板

1. 只認單一實體行的條目;續行條目得手改。
2. 只換字,不判斷改後的句子對不對;寫入只驗開頭欄位格式,筆記層級的檢查(RULE 欄位齊不齊)要跑 `lumos lint`,工具只提示不代跑。
