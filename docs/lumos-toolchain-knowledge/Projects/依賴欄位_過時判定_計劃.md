# 依賴欄位_過時判定_計劃

> 白話:脈絡(為什麼、規則、坑)常常依賴某個程式事實,例如「模型變數的數量要跟記憶體對齊」依賴那個數量。這份計劃讓寫的人在脈絡行上宣告依賴(`[count:路徑::名稱=N]`、`[value:…]`、`[lives:路徑::名稱]`),之後有人改程式讓依賴對不上,推送時就擋下,逼人回頭確認那條脈絡還成立。設計在 [[Projects/筆記標籤_過時判定與按需載入_計劃]] 的第二版審過一輪,問題還很多,先拆出來排隊。

依據:
- rtb 試標(見 [[Projects/漂移防治路線圖_計劃]]〈標籤試標結果〉):數量欄位標上的 21 句全判得出、抓到 6 句過期、誤報 0;但數量句只標得上 18%(加上值約四成)。
- 設計審 r1、r2 的席報告在 `governance/review-reports/筆記標籤-過時判定與按需載入/`(本篇的設計就是那份第二版的〈欄位 v1〉)。

## 第二版設計草案(設計審 r2 審過,未定稿)

| 欄位 | 寫法 | 判過時(推送時,只看這次改到 `路徑` 那支檔的欄位) | 求值 |
|---|---|---|---|
| 數量與值 | `[count:路徑::名稱=N]`、`[value:路徑::名稱=字面值]` | 起點 N(或字面值)吻合、終點不吻合 → 擋;終點那個名稱不見了 → 擋;這次新寫的欄位在終點就不吻合 → 擋(寫錯了) | 新寫的小求值器:Python 用語法樹讀模組層的指派——清單、元組、集合、字典字面值的成員數,Enum 類別的成員數,常數字面值(整數、浮點、字串、布林);其他語言或讀不出來的(例:程式組出來的集合)→ 起點終點都「判不了」就不擋,寫的當下提醒改用正規式數量 |
| 錨點 | `[lives:路徑::名稱]` | 起點有這個名稱、終點沒有 → 擋 | 沿用回頭條件探針的符號判定(同一支 `_DriftProbeTree`;Python 用語法樹、其他語言用文字) |

- **正規式數量**:找不到具名集合時,用既有的 `<!--lumos:count=N re=… in=…-->`(HTML 註解可以裝含方括號的正規式)。本案把 doctor N 段裡內嵌的重算抽成共用函式,存量漂移檢查也呼叫它:這次推送改到符合 `in=` 的檔,才重算那個標記;起點吻合、終點不吻合 → 擋。重算受存量漂移檢查的總時間預算管,不再每個標記各自無上限地掃整個 repo。
- **列舉**併進數量:列舉的成員數用 `[count:路徑::列舉=N]`。成員互換而總數不變抓不到,記在〈天花板〉。
- **撤除條件**用既有的條件式回頭條件行(`REVISIT:[when-file:…][by:…]` 那套),緊鄰寫在 RULE 下一行,不新增欄位。
- **路徑與名稱怎麼切**:`路徑::名稱` 在「路徑」這段以第一個「帶副檔名的路徑之後的 `::`」切開,名稱可以再含 `::`(Rust、C++ 的限定名);名稱後面第一個 `=` 之後全是值,值可以含 `:` `=`,不可以含 `]`(含 `]` 的值改用正規式數量)。
- **寫在哪裡才算**:跟回頭條件同一套——只算可見的正文與摘要行;行內程式碼、表格、圍欄、frontmatter 非摘要欄位裡的欄位不評估(文件範例才不會被當真),寫在那裡的提醒「寫在不評估的地方」。
- **判不了**:照存量漂移檢查既有的處理(git 逾時、淺複製、預算用完時的嚴格判定沿用它的設定),不另訂。

不收(設計審 r1 與 rtb 原提案對照):`[enum:]`(併進 count)、`[retire-when-*]` 與 `[expect:]`(用既有回頭條件行;2026-10-01 翻案一半:撤除條件改寫成行內 `[retire:when-*]`,理由與 `[expect:]` 仍不做的原因見 [[Projects/筆記格子寫法與過期檢查_計劃]]〈不做〉)、`[supersedes:]` `[superseded-by:]` `[id:]`(專案已有決策的取代鏈與 `[status:superseded]` 兩套,再開一套是第三種做法)、`[snapshot:]`(「哪些小節算現況」定義不出來,[[Projects/筆記形狀擋_計劃]] 也記過這形狀不固定;留 v2)、`[retired:]` `[test-gone:]`(歸路線圖 1b/1c)、錨點的「名稱本體變了」(沒有基準可比,逐行回溯 git 成本高且淺複製判不了;同次推送改了程式又改了筆記的情況,既有的回頭重讀已涵蓋)、rtb 提的 from、same-as、deliver、recheck(留 v2)。

## 待解問題(設計審 r2 指出,重開設計審前要逐條改掉;編號是 r2 席報告裡的編號)

- **判不了有兩種意思混在一起**(R2B1、R2C3、R2R1):求值器讀不懂(非 Python、程式組出來的集合)不該擋;git 逾時、預算用完照既有存量漂移檢查「判不了算要處理」。兩個詞要分開,各自寫明擋不擋。
- **轉變判定方向跟既有相反**(R2C1):既有回頭條件判定擋「不成立變成立」,欄位要擋「吻合變不吻合」,判定函式要新寫;「名稱不見了」也要有起點條件(R2C2)。
- **新寫的欄位寫錯算哪一道**(R2A2、R2I2、R2R7):候選篩選只看改到目標檔的欄位,新寫但目標檔沒改的欄位寫錯會漏;要嘛放進提交時的筆記形狀檢查,要嘛照回頭條件「起點沒有同一條一律是候選」。另外「起點」取哪個版本的筆記要定義。
- **`::` 切法與無副檔名路徑**(R2A1、R2B2、R2C4、R2C5、R2I3):既有共用切法從最後一個 `::` 切;工具鏈主程式沒有副檔名。沿用既有切法、允許無副檔名,限定名只取最後一段,寫進天花板。
- **非 Python 的錨點只判「字還在不在」**(R2B3):定義刪了、註解還提到名字,錨點不會擋;Rust 這類限定名在定義檔裡不會出現整串字。
- **求值器邊界**(R2B4、R2C10):負數、運算式、展開、重複成員、條件式內定義、重新指派、Enum 別名、字面值怎麼比對,都要逐條定義;不在定義內的一律算「讀不懂」。
- **舊的 HTML 數量標記不該變成推送閘**(R2B5、R2K1、R2R4):舊筆記裡已有的標記若被新閘評估,打破不溯及既往;正規式在推送閘上沒有中斷點(R2B6、R2R2)、工作目錄與提交樹讀法不同(R2A5、R2C9、R2I4)。建議 v1 不碰 HTML 標記。
- **新發現種類要登記**(R2A4、R2I1、R2K3、R2B16):`drift ack`、種類名稱表、`drift fix` 提示都只認既有七種;新種類要一起登記,ack 的比對鍵要能跨「數字被改」的情況。
- **開關關係與預算**(R2A3、R2K2、R2I7、R2B16):`drift_check.fields` 跟 `drift_check.gate` 的關係、壞值方向、預算掛哪一個、設定讀取函式回傳形狀(既有測試會拆它)都要定;照舊句檢查的先例另開一支、自己的開關與預算最一致。
- **已作廢行上的欄位**(R2C7):帶 `[status:superseded]` 的行不該再評估欄位(已作廢標記本身擴到 WHY、PITFALL 由 [[Projects/筆記標籤_過時判定與按需載入_計劃]] 負責)。
- **舊帳由誰列**(R2K4、R2I12):「起點就不吻合不擋、由 doctor 列出」要有對應的步驟與條款;doctor 只有一棵樹,判不了「變了」。
- **寫法提醒的成本與判準**(R2B8、R2B9、R2I5、R2R3、R2C11、R2B12):「建議宣告依賴」的範本要找路徑與值,等於提交時全庫找符號,要有上限;「程式符號」沒有判準;同一行重複事實的比對在單位數上誤報。
- **範例與不評估區**(R2I10、R2B7):範例別包反引號;不評估區的提醒會在說明文件上大量誤報;否定現況句的欄位遮罩要補新鍵。
- **CI 淺複製與合併時序**(R2R5、R2R6):淺複製下存量漂移檢查靜默跳過、doctor 沒提醒;經由合併按鈕併入時沒有 rebase,第二個併入的推送才事後擋。
- **落點**(R2A6):動到 doctor N 的重算就要寫進它的家 `Systems/check-n-recomputable`。
