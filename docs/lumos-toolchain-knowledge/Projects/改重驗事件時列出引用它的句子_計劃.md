# 改重驗事件時列出引用它的句子_計劃

白話:驗證紀錄有一欄 revalidate_when,寫「什麼事發生時要重驗」,是自由文字。別篇有時會寫「某事發生時,由那篇的 revalidate_when 觸發重驗」,把重驗交給它。之後那篇的事件清單被改了、拿掉了那件事,這句就變成永遠不會觸發的承諾。這次讓改事件清單的那一刻,把指向它的句子都列出來,讓改的人當場看一眼要不要跟著改。

依據:rtb 第三次全圖譜比對回傳第 10 項(README 流程動圖計劃那句「Phase 11B 增量 2 接入分析端或 Phase 12 頁面上主線時由驗證紀錄的 revalidate_when 觸發重驗」,而那篇的事件清單從沒列過 Phase 11B 或 Phase 12)。2026-10-07 量測:rtb 主線 1 句、工具鏈 2 句這種引用,真壞 1 句(就是 rtb 那句,一開始就寫錯,本案抓不到,請 rtb 手動改)。

PRIOR-ART: 沿用結案連帶掃描(`lumos set status` 之後 `_drift_print_backrefs` 列出連到這篇還寫待定的句子)的形狀:狀態一變當場列、只印不擋。句子認法借 [[Projects/指向別篇的回頭條件懸空_計劃]] 的連結比對(連結本身在行內程式碼裡不算、同一句不跨句尾 `_SENT_END_RE`、連結先過 `link_target`)。
RETIRE-IF: 連續 8 週工具鏈與 rtb 都沒有人在改 revalidate_when 時看到這份列表(治理帳沒有對應的改欄位事件,或兩邊這種引用句數維持 0),就拿掉這段列出。

## 範圍

- 做:`lumos set` 改的欄位是 revalidate_when、而且寫入成功時(append、remove 本來就不收這欄,只能 set 整欄換),掃全庫可見文字(程式碼區不算),列出「連到被改那篇、同一句(不跨句尾)24 字內講到 revalidate_when」的句子:來源篇、行號、原句;最後印出那篇改完之後的 revalidate_when。
- 做:沒有這種句子時什麼都不多印。
- 不做:擋下;判斷句子有沒有寫錯(不比對事件內容);doctor 全庫掃(Enzo 裁);valid_under(那欄是快照前提,不是觸發事件)。

## 實務隱患

- 已排除:金流:只在 set/append/remove 之後多印,不碰任何金流
- 已排除:對外送出:不連網、不送任何東西出去
- 已排除:不可逆:只印不寫,退回提交即恢復
- 已排除:守衛面:不擋、不改任何閘的判定

## 驗收條款

- [S1] 當 lumos set 改了某篇的 revalidate_when 而別篇有句子連到它、同一句講到 revalidate_when 時,應 列出那些句子的來源篇、行號與原句,並印出那篇改完之後的 revalidate_when;沒有這種句子時 應 不多印,而且 應 不擋、不改別篇 [test:t_set_revalidate_when_lists_backrefs]
- [S2] 當連結包在行內程式碼裡、整句在程式碼區裡、連到別篇、revalidate_when 跟連結隔著句尾、或改的是別的欄位時,應 不列;同一份圖譜裡沒有這些情形的對照句 應 照列 [test:t_set_revalidate_when_backrefs_excluded]

## 回退

退回本案的提交即可:只在寫入成功之後多印一段。

## 天花板

1. 一開始就寫錯的句子(聲稱的事件從沒出現在對方清單裡)抓不到;rtb 現有那一句請 rtb 手動改。
2. 只認「`[[X]]` … revalidate_when」這種寫法;沒寫欄位名的(「由 X 的重驗條件觸發」)看不到。
3. 庫裡有同名、不同資料夾的筆記時,只寫短名的連結照全工具共用的解析規則可能解析成另一篇,那句就不會被列出(代碼審 r1 正確性席,附理由放行)。
4. 切句時沒有排除行內程式碼:句子中間夾著含句尾符號的行內程式碼(例如 `` `。` ``)時,同一句會被切成兩筆殘片;doctor S21 用同一種切法、同樣有這個毛病(代碼審 r3 正確性席,修補前就有,附理由放行)。
