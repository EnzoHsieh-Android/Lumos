# 殺傷力驗證編譯快取誤判_計劃

白話:`lumos guard kill` 在同一個隔離工作樹裡一條接一條「把程式改壞 → 跑綁定測試 → 還原」。測試工具如果靠「檔案修改時間(到秒)+ 大小」判斷要不要重新編譯(Python 的編譯快取、macOS 內建的 make 就是),兩次寫檔落在同一秒、大小又一樣,後一次就拿到前一次留下的編譯結果——實際跑的不是這一條的壞法。誤判是雙向的:一條根本沒傷害的壞法被判成殺得掉(假的「合約有守住」),一條真的會傷到合約的壞法也可能吃到原檔的快取被判成沒殺掉。修法:每次寫檔(套壞法、還原)之前,如果現在跟上一次寫檔或上一次跑測試結束落在同一秒,就等到下一秒再寫——寫出來的修改時間是真實的、而且每次都不同秒,任何靠修改時間的快取都會重編;不把時間設到未來。

依據:
- [[Issues/guard kill在Python專案會沿用編譯快取誤判殺得掉]](殺傷力配方修補體驗代碼審第 1 輪的審查員回報;rtb=另一個用 lumos 的消費專案)。
- 編排者 2026-10-01 重現(改動前版本、本機):`_mk_kill_env` 的 repo,同一篇兩條配方指 `prod.py`——第一條 `LIMIT = 5` → `LIMIT = 99`(讓測試紅)、第二條 `def check(n):` → `def check(n): `(無害,多一個空白,改完跟第一條一樣多一個字)。第二條單獨跑 5/5 判 survived;排在第一條後面 5/5 判 killed。兩條改完檔案大小相同是必要條件(兩條都改成同長度、跟原檔一樣大時沒重現)。本機的 `python3` 是 macOS 內建 3.9,編譯快取寫在 `~/Library/Caches/com.apple.python/<絕對路徑>`,不在工作樹的 `__pycache__`;手動在兩條之間睡 1.5 秒誤判就消失。

## 範圍

- 做:guard kill 每次寫檔(套壞法、還原)之前,等到現在跟同一組上一次寫檔、上一次跑測試結束都不同秒(最多等 3 秒);寫完讀回修改時間,沒有晚於那兩者就再等、再碰一次(`os.utime(path)` 不帶時間=設成現在),最多重試 3 次;還是不行就把這條結果標成弱證據。
- 不做:不改合約測試閘與其他呼叫 `_kill_run` 的地方;不把任何檔的修改時間設到未來;不改 guard kill 的判法、回傳碼、`--json` 欄位;不清使用者專案的快取資料夾。

## 做法

- **狀態**:`cmd_guard_kill` 每個平台組開工作樹之後建一個 dict `{"w": 0, "r": 0}`——`w`=上一次寫檔後★讀回的修改時間取整秒★,`r`=上一次跑測試結束時的牆鐘取整秒。★每一次 `_kill_run` 跑完都更新 `r`,包括每個不同測試指令各自的 baseline★(baseline 以指令快取、夾在配方之間;只記第一次會讓 make 專案把真的傷到合約的壞法判成沒殺掉,第 2 輪正確性席實測 5/5)。
- **等**:新增 `_kill_wait_new_second(state)`:`while int(time.time()) <= max(state["w"], state["r"])` 就睡 0.05 秒,最多等 3 秒(時鐘往回撥時不空轉;第 2 輪正確性席實測撥回 6 秒卡 6.5 秒、撥回一小時卡一小時)。
- **寫後確認**:新增 `_kill_after_write(path, state)`:讀回修改時間,`int(mtime) > max(state["w"], state["r"])` 就記進 `state["w"]`、回 True;否則等 1 秒、`os.utime(path)`、再讀回,最多 3 次;都不行回 False(比的對象跟「等」一致,第 2 輪兩席:原稿讀回只比上一次寫檔,跟 S2 不一致)。
- **插的位置**:套壞法——原文恰好一次、要寫檔之前「等」,寫完「寫後確認」;跑完測試更新 `r`;還原——`git checkout -- <file>` 之前「等」,成功之後「寫後確認」。配方漂移沒套上、逃逸、還原失敗這些分支在寫檔前就離開或結束,不等。
- ★還原前那次等待是必要的★:測試跑得快時,還原寫回的檔可能跟壞法落在同一秒、大小又一樣;下一條配方改的是另一支檔、測試卻 import 這支時,會吃到壞法的快取(第 2 輪正確性席實測拿掉還原前等待、改 a 再改 b,3/3 誤判)。
- **弱證據**:任一次「寫後確認」回 False,在這條結果記旁路欄 `_mtime_unsure=True`(還原那次沒錯開時,那支檔在被成功重寫之前,同一組後面每一條的測試都可能 import 到它的舊快取,都一起記——以「還原沒錯開、還沒成功重寫的檔」清單判斷;代碼審第 1、2 輪正確性席)、在標準錯誤印一行提醒(照 kill-log 寫入失敗那條的寫法,固定走標準錯誤;同一次 guard kill 只印一次);收尾重算 `weak` 的那段把 `_mtime_unsure` 也算進去(★不能在迴圈裡直接設 weak:收尾那段會無條件重算、蓋掉★,第 2 輪兩席實測),`--json` 輸出前跟 `_logged`、`_rid` 一起濾掉。
