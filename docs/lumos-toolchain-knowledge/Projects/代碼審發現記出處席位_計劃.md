# 代碼審發現記出處席位_計劃

## 白話

審查帳現在記得住每條發現最後是折入、放行還是重現不到,卻記不住它是哪一席報的。所以「哪一席最常報沒用的東西」只能用很小的樣本猜:2026-11-20 離線統計全帳 19,760 條發現,只有「那一輪恰好只有一席報東西」的輪能歸屬,架構對齊席 42 條裡放行 19 條、正確性席 39 條裡放行 17 條,樣本太小,不夠拿來決定要不要調席位。發現編號的字首也不能當依據:同一個字母在不同迴圈對到不同席(例如 s 只有一半是資安席)。

這份計劃在載體記帳時多記一欄「每條發現是哪一席報的」,代碼審新開的迴圈從生效日起必填;`lumos gov --stats` 多印一段逐席沒用率。純記帳,不改任何閘的判定。

WHY:代碼審載體記帳新增 `--finding-seat`,生效日後新開的代碼審迴圈必填,處置閘判定不動 [出處:2026-11-20 使用者回「好」,同意先做「記帳時每條都記是哪一席報的」;2026-11-21 使用者裁舊否決 canary-audit d4 在這裡不適用、照做] [因:Google Tricorder 以逐檢查的有效誤報率決定哪條檢查該降級,我們要做同樣的事就得逐席有數字;全帳整體沒用率 4.6%,人力主要在每輪條數與修補回歸,調席位前要先有逐席證據] [不選:沿用 `--finding-source`(它綁著「major 輪放行 minor」的核對與「載體最後記」擋法,不適用的輪寫側會擋,硬放寬會動到處置閘第⑨步);規定發現編號字首等於席位(字面慣例,歷史帳已證明守不住);只提醒不擋(選填欄位歷史上帶的比例很低:866 筆代碼審載體只有 52 筆帶逐條來源,資料會缺)]
PRIOR-ART: Google Tricorder 對每支分析器量「有效誤報率」(開發者看到後沒採取行動的比例),超過 10% 的分析器要改或關掉(Sadowski 等,Tricorder: Building a Program Analysis Ecosystem, ICSE 2015,https://research.google/pubs/tricorder-building-a-program-analysis-ecosystem/;Lessons from Building Static Analysis Tools at Google, CACM 2018,https://cacm.acm.org/magazines/2018/4/226371-lessons-from-building-static-analysis-tools-at-google/fulltext)。本 repo 既有的 `--finding-kind`(每條發現標在修什麼、全集要對得上、`gov --stats` 算佔比)就是同形狀的純記帳欄位,新旗標照它寫;生效日照 `_SECURITY_SEAT_SINCE` 的寫法(帶時區的完整時間、用 `_loop_ts_key` 比、壞時間不放行),另借 `_CHOICE_SINCE` 的環境變數覆寫讓測試總檔預設停在生效前。
RETIRE-IF: 必填滿 8 週後,逐席沒用率沒有促成任何一次席位調整(降級、改條件席、改派工詞),或抽查發現編排者填錯席的比例超過一成——就把必填改回選填或整欄撤掉。

## 用詞

- **載體**:一輪裡帶 `--findings-set` 的那一筆帳,彙整全輪每條發現的去向;一輪只准一筆。
- **席名**:帳上 `auditor` 欄的字串,照記帳時給的原樣(例 `正確性-sonnet`,含模型尾碼)。
- **重現不到清單**:載體 `--refuted-set` 的 id;寫側已擋它跟發現清單重疊,所以兩份清單的聯集就是這輪全部發現。
- **結局帳**:迴圈收尾的那一筆(帶 `--outcome`),跟規格閘留痕一樣不算進「首筆帳」。
- 「一輪只准一筆載體」是處置閘讀側在驗,寫側不擋;舊帳裡有同輪多筆載體,所以統計另定取法。

## 舊否決比對

- [[Systems/canary-audit]] 決策 d4(2026-08-08)否決過「跨期統計/席位信譽」:理由是模型換代、規格各異、植入假 bug 的難度由人拿捏,跨期累積的分數站在流沙上,而且模型變強後抓漏分數會飽和。2026-11-21 問使用者,裁「這次不同,照做」。差別寫在這裡:這次量的是「席位報的東西人有沒有採用」(Tricorder 的有效誤報率),不是對植入題打分;數字只給人看,不進任何閘、不自動調席位;統計只看最近 8 週,同一席不同模型分開列,模型換代不會跟舊數字混在一起。
- [[Projects/審查帳節點映射_計劃]] 決策 d2 停案時寫:沒有讀者的遙測欄位正是 canary 協議被淘汰的死因,重開要有讀者承諾讀新欄。這次的讀者是 `gov --stats` 那一段與 2026-12-11 的回頭檢查(帶數字給使用者裁席位);同一筆也寫「一輪只准一筆處置集合,逐席映射無處合法落帳」——這次欄位掛在那唯一一筆載體上,不新增第二筆處置帳。

## 範圍

- 做:①`canary record` 新增可重複旗標 `--finding-seat <id>=<席名>`,帳上存 `finding_seats: {id: [席名, …]}`;②代碼審載體在「這條迴圈首筆帳不早於生效日」時必填,而且要涵蓋發現清單與重現不到清單的每個 id;③席名必須是同輪帳上某一席的 `auditor`(含本筆);④`lumos gov --stats` 印逐席沒用率;⑤`loop next` 代碼審的載體記帳範本帶上這個旗標,並改既有照填範本真跑的測試(`t_fix_check` 第 2 輪範本那段);⑥治理帳讀側認得這欄:型別檢查(值要是字串清單,跟 `finding_sources` 同形狀,泛化既有的 `_finding_sources_typed` 共用)與 canary 列的欄位白名單都加上它;⑦手冊與筆記同步,並用 `lumos decision-add` 在 [[Systems/canary-audit]] 記一筆:d4 否決的「跨期統計/席位信譽」不涵蓋這次的逐席沒用率,寫明範圍與差別。
- 不做:不改處置閘、代碼審留痕或任何推送前閘的判定;不改 `--finding-source` 的語意;不回溯舊迴圈(生效前開的迴圈照舊可以不帶);散文設計審不必填(設計審整體沒用率 1.3%,沒有逐席的需要),但帶了照收、一樣驗;不依沒用率自動調席位,調不調仍由人裁。
- 不涵蓋沒帶 `--round` 的載體:帶 `--findings-set` 卻沒帶 `--round` 的處置帳,寫側更早就擋了(處置帳必須綁輪次),這條路走不到。

## 做法

- **旗標**:`--finding-seat <id>=<席名>` 可重複;同一個 id 可以給多次(多席報了同一件事),存成清單、照給的順序、重複的只留一個。id 與席名前後空白先去掉。跟其他逐條旗標一樣要跟 `--findings-set` 一起給,單獨給就擋。
- **涵蓋**:給了就要全集對得上(跟 `--finding-kind` 同規矩),全集是發現清單加重現不到清單;不管是不是必填,給了而缺 id 都擋,缺的逐一點名。鍵也不能在全集外。重現不到的也要記席位,因為它正是「沒用」的一種。
- **值**:去掉前後空白後,必須跟同輪帳上某一筆的 `auditor`,或本筆自己的 `--auditor` 比對相等(兩邊都做 NFC 正規化;不做全半形折疊)。帳上存的是比中的那筆 `auditor` 原字串,不是旗標原值,同一席不會因寫法差一點在統計裡分列。比不中就擋,訊息列出同輪帳上現有的全部 auditor,並提醒「那一席還沒記的話先記它,載體最後記」。手冊規定載體最後記,但工具只在帶 `--finding-source` 時強制,所以要靠這道擋下訊息。讀不到這個迴圈的帳就擋,不猜。
- **必填條件**:迴圈種類照全檔唯一的判法 `_roster_kind`,不是設計審(代碼審,或 `code` 開頭看不出種類的從嚴)、本筆帶 `--findings-set`、這條迴圈的首筆帳時間不早於生效日。首筆=同迴圈已讀進的帳列(寫側讀同迴圈帳那一份,已排除結局帳與規格閘留痕)裡時間最小的一筆;帳上還沒有任何一筆時,拿本筆自己的時間比。
- **生效日**:常數 `_FINDING_SEAT_SINCE`,寫成帶 `+08:00` 的完整時間(合進主線隔天的 00:00),跟 `_SECURITY_SEAT_SINCE` 同寫法,用 `_loop_ts_key` 換成可比的鍵;帳上有一筆時間讀不動或沒帶時區,照那條先例判「壞資料」擋下、不放行。測試要能把生效日推到未來,所以另留環境變數 `LUMOS_FINDING_SEAT_SINCE` 覆寫(值讀不成帶時區的時間就用常數);這是帳上時間比對裡第一個有環境變數覆寫的,理由是既有 87 處造帳測試都用當下時間。測試總檔預設設成 `9999-12-31T00:00:00+08:00`,新測試自己改。
- **擋下留痕**:必填缺漏與席名比不中兩種擋下,照 `--refuted-set` 缺漏的寫法在治理帳留一筆 canary blocked 事件(原因 `finding-seat-missing`、`finding-seat-unknown`),回頭檢查量得到這道擋被撞了幾次。
- **統計**:`lumos gov --stats` 在「發現在修什麼」那段後面加一段「逐席沒用率」:
  - 窗口:從 `gov --stats` 已算好的起算點往後,再跟「現在往前 56 天」取較晚的那個;時間用 `_loop_ts_key` 換算比較,起算點當下那一刻算在內。
  - 單位:每筆載體列各算一次(id 每輪重編,不跨列去重);同一個 (迴圈, 輪) 有兩筆以上帶 `finding_seats` 的載體時只取帳上最後一筆,跟修正關卡取載體的規矩一樣。同一列內同一條被兩席報,兩席各算一次。
  - 去向:id 在折入清單算有用,在放行清單或重現不到清單算沒用。
  - 席名:照帳上原樣,只把夾在角色與模型尾碼之間的輪次記號去掉(`架構對齊r2-sonnet`、`架構對齊-r2-sonnet`、`架構對齊2-sonnet` 都併成 `架構對齊-sonnet`);不同模型不合併。派工詞與手冊另寫明席名不帶輪次。
  - 印法:每席一行,印條數、沒用條數與比例,依條數多到少、同數依席名;條數少於 10 的加「樣本少」。值不是字串清單的列整列略過、不噴例外。窗口內一筆都沒有就整段不印(跟「發現在修什麼」一樣)。段尾固定印一句口徑:放行不一定是雜訊、折入不一定有用,只供人裁。
- **範本**:`loop next` 印的載體記帳範本,迴圈不是設計審時多一段 ` --finding-seat <id=席名>`(每條各一個);設計審的範本不印(設計審不必填,印了反而誤導)。

## 實務隱患

已排除:金流:只改審查帳的記帳欄位,不碰付款
已排除:對外送出:不連網、不寄送
已排除:不可逆:擋下時不寫審查帳(只在治理帳留一筆 blocked 事件,跟既有擋下同寫法),改正後重記同一輪;寫進去的欄位是純記帳,沒有閘讀它
- 併發與交易:審查帳與治理帳都沿用既有的附加寫法,這次不新增寫入函式
- 守衛面:記帳寫側多一道必填檢查,擋錯了會讓載體記不進帳、整輪卡住。防線:擋下時不寫帳、訊息點名缺哪些 id 或哪個席名並列出同輪現有的 auditor、治理帳留 blocked 事件可數;生效前開的迴圈不受影響;席名比對只要求「同輪帳上有這一席」,不要求跟報告內容對得上。
- 天花板:席位是編排者自填的,工具只驗席名存在,不驗那條發現真的出自那一席的報告。填錯會讓逐席數字失真,靠 REVISIT 抽查;要機械驗得從報告逐條對 id,那就是 `--finding-source` 的形狀,這次不做。
- 負擔:每條發現多一個旗標(真帳一輪 1 到 18 條),跟 `--finding-kind` 同量級;編排者在收貨時本來就知道每條是哪一席報的。
- 消費專案:這個工具也被其他專案用;生效日後它們新開的代碼審迴圈一樣要填。擋下訊息直接給寫法,不用查手冊。
- 席名碎片:帳上同一角色有很多寫法(`鏡頭1-正確性-sonnet`、`正確性A-sonnet`、`架構對齊二-sonnet`)。統計只併輪次記號,其他寫法照分列,靠手冊規定席名寫法收斂;12-11 回頭檢查時碎片多到湊不滿 30 條,就照實回報。
- 樣本偏差:「放行」不一定是雜訊(可能是真問題但修的成本太高),「折入」也可能高估有用(major 一律要折)。統計段標明口徑,段裡只印數字與那一句口徑,不印任何調席位的建議。
