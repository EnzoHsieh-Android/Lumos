# 世界解重新註解2026-10_迴圈工程_調研

> 白話:這一類問的是「一輪審查什麼時候算過、那個過可不可信」。世界上做得好的審查迴圈都是「先放寬去找、再用不是當事人的東西去驗」,而一次「過」有多可信,取決於驗證者能不能碰到對話紀錄以外的真實狀態。Lumos 在「每條發現都要有去向、帳本可重算、推送前硬擋」這一層比世界上任何產品都嚴;弱點在閘裡面由模型自己說了算的幾格:辯方的反證沒人機械查、折入對不對沒人獨立量、修補只驗修後綠、席位預設同一家模型。下一步最划算的是先補引句錨定的漏洞,再讓辯方反證過機械查核,接著趁 2026-10-20 的回頭日重裁「修前會紅」。

## 這一類在問什麼、Lumos 現在怎麼做

先講幾個詞:**席**是一個不知脈絡、只拿到凍結材料的審查代理;**編排者**是派席、收報告、記帳的主會談;**外家**指跟編排者不同家的模型(例如 Claude 編排時的 Codex);**折入**是把一條發現修掉,**放行**是附理由不修;**辯方**是專門反駁某條發現、想把它降級的代理。

**進場與分級(審多重)**
- [[Systems/規格閘]]:設計寫完先判門,風險低直接實作、不進設計審。
- [[Systems/pitfalls-code-loop]]:代碼審與推送閘;用改動風險分級決定派幾席,沒留痕擋推送。
- [[Systems/risk-tiered-review]]:自主迴圈對設計文字的關鍵字分級,外層腳本自己重算等級、不信編排者自報。

**派席(誰來看、帶什麼鏡頭)**
- [[Systems/design-loop]]:設計審迴圈;多席乾淨審查、處置閘判過不過、跑滿上限交人。
- [[Systems/派工鏡頭]]:派工時自動附上這次改動碰到的合約與事故筆記。
- [[Systems/每輪修補差異派工]]:修訂輪把上一輪的修補差異一起交給新席看。

**收貨、判讀與收斂**
- [[Systems/lumos-refcheck]]:機械查席報告引的檔案與行存不存在。
- [[Systems/finding-refute]]:辯方;只對低共識、存活且 major 以上的發現派一個,要附檔案行號反證才准降級。
- [[Systems/judge-severity-gate]]:嚴重度由誰說了算(舊制獨立判官,現由寫側「帳面不得低於報告宣告」取代)。
- [[Systems/loop-convergence-recording]]:審查帳與治理帳、處置閘(每條發現都要折入或附理由放行,可從帳本重算)、凍結判定回放、逃逸帳(審過卻漏網的缺陷紀錄)。
- [[Systems/convergence-evidence-gate]]:已退役的「連 K 輪乾淨」舊收斂閘,只供回放。
- [[Systems/heterogeneous-finder-ensemble]]:把多席、linter、測試當不同找錯者,用捕獲再捕獲(從重疊估剩餘數)估殘餘缺陷;2026-08-14 降為只觀測。
- [[Systems/canary-audit]]:植入假缺陷看審查員醒著沒;2026-08-14 停用。

**上限、修補、事後與自主**
- [[Systems/loop-retro]]:跑滿上限後由沒參與的乾淨代理起草回顧。
- [[Systems/代碼審修正關卡]]:修正關卡第 0 步,驗修正紀錄完整、修後綠、受波及合約測試綠;只提醒不擋。
- [[Systems/autonomous-iteration-loop]]:每日自主選題、寫設計、跑設計審、停在人工放行;派工段 2026-09-05 起預設暫停。
- [[Systems/開發工作流總覽]]:整條流程的總圖。

一次「過」實際站在哪(借 Macedo 的五階驗證梯:L1 確定性測試、L2 規則檢查、L3 延遲的真實結果、L4 模型判官、L5 人):代碼審 high 是 L2 收貨檢查包住 L4 多席判斷,碰到合約時有 L1 綁定測試真跑,推送前沒有 L5;設計審是 L2 包 L4;自主迴圈最後有 L5 人工放行。

## 世界解註解

欄位:出處與日期｜怎麼運作｜證據強度(A 受控實驗或方法公開的基準、B 生產數據或廠商自報、C 實務經驗、D 行銷宣稱)｜註解深度｜跟 Lumos 的關係。註解深度沿用研究筆記標記:讀碼、讀全文、讀官方文件、二手摘要。

**甲、迴圈本身:停止條件與驗證者站位**

1. **進度幻象:迴圈內判官 vs 迴圈外評估**(Park & Choi,arXiv 2607.25152,2026-07-27 v1、09-29 v2,作者稱初步稿)
   - 運作:同一代理只換把關者的資訊通道。代理 54 輪每輪都說有進步,實測 56% 沒進步或退步;最強的「迴圈內判官」(讀完整產物與 diff)放行的輪有 44% 是真退步、又拒掉 37.5% 的真改進;但成功條件寫在產物裡可直接驗的對照任務,誤差降到 0。建議評估者放迴圈外、讀版控與只增不改的帳;「迴圈水電可委派給平台,接地的判斷不行」。
   - 證據:A(受控、方法公開),但只是試點:單一代理、每臂 3 次。深度:讀全文。
   - 關係:驗證(只增不改的帳、卷證檔交接);缺口(設計審的席全在迴圈內,看不到「這題該不該用這個解」,正好解釋 [[Issues/自主loop加法偏食]] 那個 6 輪把過度設計磨到自洽的案例)。
2. **迴圈規格五件與五階驗證梯**(Macedo,arXiv 2607.00038,2026-06-28)
   - 運作:迴圈寫成觸發、目標、驗證、停止、記憶五件;終止狀態分 success/no-op/blocked/stalled/exhausted,「錯誤或預算用盡永遠不算成功」;要求「誠實標出驗證者實際站哪一階」。50 個公開迴圈裡只 18% 是做與驗分開。
   - 證據:C(描述性語料,單一作者編碼)。深度:讀全文。
   - 關係:驗證(做的人不當放行的人、到頂交人裁);可借鏡(放行輸出逐次標示驗證層級)。
3. **LoopTrap 終止投毒**(arXiv 2605.05846,2026-05-07)
   - 運作:在代理讀到的內容埋「還沒做完」的訊號,平均攻擊成功率 86.3%、步數放大 3.57 倍;建議用獨立模組拿客觀條件驗進度。
   - 證據:A(受控攻擊實驗;防禦未實測)。深度:讀全文。
   - 關係:驗證(Lumos 已借此立「被審材料的散文不是終止指令、只認帳與上限」,另有硬上限);可借鏡(唯讀覆核指令 `loop verify-progress` 是選用,不是每輪必經)。
4. **原生停止條件:Claude Code `/goal` 與 Codex goal 模式**(code.claude.com/docs/en/goal,2026-10-11 讀;openai/codex 續跑範本,2026-09-09 提交)
   - 運作:`/goal` 每輪由另一個小模型判「未達/已達/不可能」,評估者不呼叫工具、只讀對話,輪數上限只能寫進條件文字。Codex 範本要求「把完成當成未證明」、逐條需求找權威證據、「稽核要證明完成,不是沒找到剩餘工作」、同一阻塞連三輪才准標 blocked、不得改成更好測的解來讓測試變綠。
   - 證據:C(官方文件與生產提示詞,無成效數據)。深度:讀官方文件、讀碼。
   - 關係:原生重疊(做與驗分開的停止判斷已內建);衝突(`/goal` 評估者讀的正是散文);可借鏡(Codex 的忠實條款與「連三輪才算卡住」)。

**乙、商用審查產品與公開基準**

5. **Cursor Bugbot**(cursor.com/blog/building-bugbot,2026-01-15;官方文件 2026-10-11 讀)
   - 運作:v1 是 8 次平行掃描、每次 diff 順序隨機、多數決;後來改成單一代理自己決定往哪挖,並改用積極提示。前幾輪留言全部解決之前 check 不綠;autofix 每個 PR 最多 3 次。指標是合併時 AI 判定的解決率(52%→70% 以上)。
   - 證據:B(廠商自報,解決率由 LLM 判)。深度:讀官方文件。
   - 關係:驗證(放棄多數決,與 Lumos 取聯集同向;「前輪沒清完不綠」≈處置閘);可借鏡(隨機檔案順序是零成本的席間去相關)。
6. **Anthropic Claude Code Review 託管版**(code.claude.com/docs/en/code-review,2026-10-11 讀;claude.com/blog/code-review,2026-03-09)
   - 運作:多代理各管一類問題平行找,再用驗證步驟對照實際程式行為殺誤報;分 Important/Nit/Pre-existing(既有問題)三級;官方建議在審查規則檔寫「行為主張要附檔案行號」與「第一輪之後只報 Important」,避免一行修補被風格拖到第七輪;check 永遠中性、不擋合併。
   - 證據:B(有實質意見的 PR 16%→54%、被標錯 <1%,無召回數據)。深度:讀官方文件。
   - 關係:驗證(行號門檻≈refcheck);可借鏡(既有問題分流、第二輪起控量);衝突(產品刻意不擋,Lumos 沒留痕就擋推送;無人看顧下 Lumos 的理由成立)。
7. **GitHub ReviewBench 與 Copilot 多模型合成 A/B**(github.blog,2026-10-05;批評 JPHutchins/code-review issue 282,2026-10-06)
   - 運作:219 個 PR、187 個 repo,資深工程師重標一致 96.6%;線上 A/B 顯示「多個獨立模型跑完合成一份審查」召回 +13.6%、處理率 +8.0%、留言量 +61%、成本 −8.0%。每 PR 只審一次,量不到多輪收斂。
   - 證據:A(方法、資料、判官公開,主研究員核過原文),A/B 數字屬 B;廠商主辦且自家第一。深度:讀全文。
   - 關係:驗證(多席合成);挑戰(多模型比同家多席好,Lumos 2026-09-30 起預設同家);延伸(世界沒有任何多輪收斂基準)。
8. **CodeRabbit 野外實證**(arXiv 2607.03316,2026-07-03 v1、07-23 v2)
   - 運作:31,073 對審查與回饋、10,191 個 PR:AI 留言被接受 36.4%、討論 7.3%、拒絕 56.3%;被拒主因是誤報、重複、超出範圍;拒絕可被預測到 76% F1。
   - 證據:A(野外大樣本;摘要沒交代標註方式)。深度:二手摘要(主研究員核過摘要)。
   - 關係:挑戰(Lumos 已處置發現 98.8% 是折入,差距大到要懷疑折入不是精確率訊號)。
9. **Qwen Code `/review`**(QwenLM/qwen-code 使用者文件,首版 2026-04-06、2026-10-04 更新)
   - 運作:high 級最多 16 個平行代理;每條發現必寫「失敗情境」,寫不出就丟;分片驗證時「要駁回 Critical 只能引用矛盾的程式碼,不確定就降級不刪除」;反向稽核連續 2 輪沒新發現才停,上限依規模 10/5/3 輪加牆鐘期限;`--fix` 後只派一個看不到原 diff、不報新發現的代理稽核修補,理由是重跑整份「會是對另一份程式的新審查,卻掛著這次的判定」。
   - 證據:C(只有零星量測)。深度:讀官方文件(主研究員核過原文)。
   - 關係:驗證(鏡頭拆分、獨立驗證、修補另審幾乎同構);可借鏡(辯方只准引碼駁回、降級不刪);衝突(停止規則是計數式早停,Lumos 是固定上限)。
10. **Anthropic 開源 code-review 與 security-guidance 外掛**(anthropics/claude-code plugins,2026-10-09 版)
    - 運作:code-review 現行版(2025-12-06 起)4 個代理平行找、每條再派一個驗證子代理,拿掉舊版「打 0–100 分、低於 80 丟」;README 仍寫舊門檻。security-guidance 第三層「調查段只求召回、反駁段每條要附檔案行號證據才能駁回、預設存活」,發現位置在 diff 外必須指出是哪一行改動讓它成立。
    - 證據:C(提示詞與歷史公開,有內部評測沒數字)。深度:讀碼。
    - 關係:驗證(廠商自己也是「召回段+附證據的反駁段、預設存活」,與辯方同形);可借鏡(diff 外發現要錨到啟用它的改動行)。

**丙、企業內部部署**

11. **Uber uReview**(uber.com/blog/ureview,2025-08-12)
    - 運作:三個助手產生評論,第二個提示打分、語意去重、按類別壓掉歷來低價值的類;「已處理」的自動量法是在最終提交上重跑 5 次,都沒再產生相近評論才算。
    - 證據:B(有用率 75%、已處理 65%,人寫評論 51%)。深度:讀官方文件。
    - 關係:可借鏡(不靠處置者就能量「折入有沒有生效」);缺口(Lumos 不按鏡頭量精確率)。
12. **字節 BitsAI-CR**(arXiv 2501.15134,FSE 2025 工業論文)
    - 運作:規則分類體系、微調找錯器、微調二元驗證器;每天人工標註最多約 10% 線上評論,每週看每條規則「被標的行後來被改的比例」,低於門檻的規則淘汰。驗證器「先結論再推理」精確率 77.09%,勝過先推理。
    - 證據:B(線上精確率約 25% 升到 75%;論文內數字有幾處互相矛盾)。深度:讀全文。
    - 關係:可借鏡(人工抽樣量精確率、按鏡頭淘汰);衝突(把召回讓給精確)。
13. **Atlassian RovoDev**(arXiv 2601.01129 v2,ICSE 2026 SEIP)
    - 運作:LLM 產評論後過「事實正確性 LLM 判官」與「可行動性分類器」兩道;消融顯示拿掉分類器跟人類評論位置對齊掉約 15–20 點,拿掉 LLM 判官「影響很小」。
    - 證據:B(一年線上;判官只用 47 則驗證)。深度:讀全文。
    - 關係:挑戰(Lumos 殺誤報主要靠 LLM 辯方,而辯方的效益從沒做過開/關對照)。

**丁、辯論、判官偏誤與錯誤相關**

14. **辯論放大偏誤、增益多來自投票**(Judging with Many Minds arXiv 2505.19477,Findings of EMNLP 2025;Debate or Vote arXiv 2508.17536,NeurIPS 2025;Talk Isn't Always Cheap arXiv 2509.05396)
    - 運作:判官跟唱反調的批評者來回,位置與從眾偏誤第一輪就被放大、之後不回落;元判官偏好有說服力的解釋。七個基準上辯論的增益幾乎都來自多數決,理論上辯論不提升期望正確率;「把信念更新只往可驗證的更正方向偏」才有用。孤立的正確者最容易被說服改錯。
    - 證據:A(受控、多基準,模型偏小)。深度:讀全文。
    - 關係:驗證(Lumos 禁席間互辯);挑戰(辯方只處理低共識發現,正是「孤立正確者」;擋得住的前提是反證真的被機械查核)。
15. **錯誤高度相關**(Goel 等 arXiv 2502.04313,ICML 2025;Kim 等 arXiv 2506.07962,ICML 2025)
    - 運作:模型越強錯得越像;判官偏好功能上相似的模型;350 多個模型裡,兩個都答錯時約 60% 錯成同一個答案,跨供應商的強模型也相關。
    - 證據:A(只做選擇題,自由文字的找缺陷相關性是推論)。深度:讀全文、二手摘要。
    - 關係:挑戰(席與辯方預設同家;Lumos 的捕獲再捕獲鑑別力約 0,與「漏掉的東西高度相關」相符)。
16. **判官抓不到「漏掉的」**(Fox 等 arXiv 2608.31016,2026-08-31;Chen 等 arXiv 2608.01000,2026-08-02)
    - 運作:醫療病歷上判官抓增改的成對鑑別力 0.79–0.94、抓遺漏只有 0.50–0.63(0.5 等於亂猜),「先列所有事實再逐條檢查」救回一部分。2608.01000 第 4 節:植入的多餘項被抓到是遺漏項的 6–7 倍,但這是 WordNet 詞表、Qwen2.5 7B/14B;72B 只剩 2.3 倍;GPT-5.1 扣掉誤報後遺漏偵測與亂猜分不開;原文明說這組結果「不宣稱適用於測試套件」。
    - 證據:2608.31016 為 A−;2608.01000 第 4 節為 B。深度:二手摘要(數字已核)、讀全文。
    - 關係:缺口(代碼審的漏處理分支、漏遷移、漏合約條款可能被系統性漏抓);與圖譜引用衝突(見〈筆記與程式或來源對不上〉)。
17. **嚴重度是最不穩的標籤**(Wunder 等,IEEE S&P 2024 CVSS 研究;Calboreanu arXiv 2605.12280 v2,2026-06-19)
    - 運作:CVSS 使用者隔段時間再評同一漏洞,68% 給出不同嚴重度。2605.12280 的 LLM 稽核案例:嚴重度 κ=0.458(95% 信賴區間 0.008–0.811,只 18 個樣本,第二編碼者是四家 LLM 的眾數);缺陷數逐輪 15、8、12、2、8、1、4、1、0 不單調;§3.5 正文推薦「連兩次全範圍乾淨」,但作者自己只用一次乾淨、沒驗證。
    - 證據:CVSS 為 A;2605.12280 為 C。深度:二手摘要、讀全文。

排序依據:①世界證據強度與一致性;②打在 Lumos 已量到的痛點(修補誘發新問題、折入對錯不明、同家盲點、逃逸);③沿用既有零件、改動小、能先「只觀測」上線;④是不是別條的前置。跟研究筆記的排序不同處:把引句錨定的修補提到第 1(它是第 2、4 名的前置),新增第 7 名「單家族提醒斷線」(核對時才發現)。

- 要做什麼:每週從審查帳抽 20 條已折入的程式類發現,交給沒參與那輪的席(優先外家)用「真、相關、非瑣碎」三準則判,記成「折入抽查精確率」,按鏡頭分組;可加 Uber 法:折入後用同一席對修後版本重跑,仍重現的標「折入未生效」。

**6. 外家額度用在刀口上,再加零成本的打散**
- 要做什麼:①外家只派給「低共識、存活 major 以上」的辯方;②high 的找錯席各自打亂凍結材料的檔案順序(種子記帳);③其中一席改吃「diff+不超過 2k token 的結構化摘要」。

**7. 接回「單家族」提醒**
- 要做什麼:外家沒派時,處置閘照手冊說的印一句「這次只有同一家模型在審,結論要寫成『單家族視角下未發現』」。

- 以前怎麼判過:編制資料化計劃原本的設計是設計審外家否決「沒派要註記」、代碼審 high 外家「必派」;2026-09-30 改條件席時這條提醒順帶斷掉,查無有人決定要拿掉它。

**8. 專找「漏做」:先列條款、再逐條判**
- 要做什麼:diff 碰到合約不變式或計劃驗收條款時,合約鏡頭的必交產出是「條款清單→每條:有實作(附行)/缺/不適用」;遺漏型發現被降級時,反證必須指出實作那一行。

**9. standard 加第二位審查者**

**10. 分級加入「大小」,並用逃逸帳畫捕獲曲線**

- 要做什麼:只在換席位模型或改派工詞之前跑;從逃逸帳挑真漏網,把當時的原始 diff 不加標記混進一輪正常材料,分記「走到」(引句碰到那段)與「抓到」,並掃輸出裡的察覺字(test、canary、植入、考)。

## 世界證據對 Lumos 做法的挑戰

世界證據**支持**大架構:多席取聯集不投票、禁互辯、找與驗分開、處置完才算過、停在人工放行、外層重算不信自報、只增不改的帳、到頂交人。挑戰集中在架構裡由模型自己說了算的幾格,和幾個資源配置。每條附「怎麼驗證挑戰成不成立」。

1. **折入率 98.8% 沒人獨立量。** 已處置的 4669 條裡 98.8% 是折入、全帳 1941 條只有 21 條附理由放行;野外 AI 留言被拒 56.3%、企業採用率 27–65%;Beko 導入後「已解決」73.8% 但 PR 關閉時間變長。兩種解釋分不開:辯方之後真的很準,或處置閘讓折入最省力(代碼審有 major 時連 minor 都不能放行)。另帳面 8449 條扣掉已處置還有約 3780 條不在漏斗,成因沒查。驗證:候選 5 的抽查;低於 80% 就成立。
2. **判官只看審查材料時,放行輪多數可能是退步。** 迴圈內最強判官放行的輪 44% 是真退步(第 1 條);設計審席位全在迴圈內,看不到「該不該是這個解」。驗證:拿自主迴圈歷史提案與 exec-anchor-gate 案,讓一個不讀設計、只讀 repo 與帳本的代理先回答「既有層能不能解」,看能否在派審前標出更便宜的層。
3. **1 席最差、2 與 4 席一樣,Lumos 配置形狀相反。** Porter 1997 隨機分派:1 人較差、2 人與 4 人一樣、多開一場沒用;Lumos standard 1 席、high 每輪 7 席以上。自家 2→3 席少 13.4 個百分點、3→4 只少 2.5,形狀一致。驗證:候選 9 的補跑與置換曲線。
4. **預設同家,與錯誤相關證據相反。** 兩模型都錯時約 60% 錯成同一答案;多模型合成召回 +13.6%;OpenAI 量到審查員對模型寫的程式召回較弱。「單席漏 64.6%」的分母本身是同家席的聯集,對全部真缺陷只會更高。驗證:評測集上算各席種組合的共同漏掉率,比同家辯方與外家辯方在逃逸題上的錯誤降級率。
5. **修補誘發可能不小。** 編排者手填的帳上,583 條發現有 185 條(約 32%)被標成「上一輪修補造成」(手填、沒人驗,只能當上限參考)。世界做法相反:Qwen 修完只派一席稽核修補,Porter 說修後再審不多找到缺陷。驗證:候選 4 的機械比對與手填對照;若機械比例也在三成上下,「修完整份重審」的成本與「修補本身是主要缺陷來源」都要重估。
6. **嚴重度最不穩,卻是兩個開關。** 同一人隔段時間 68% 給不同嚴重度;LLM 嚴重度 κ 0.46(樣本 18);Greptile 用 LLM 判嚴重度濾 nit 失敗。Lumos「major 必折」「辯方只管 major 以上」都掛在它上面,被標低的真缺陷沒人看第二眼。驗證:帳上多席都報到的同一條發現,算各席嚴重度一致率;κ 低於 0.4 就成立。
7. **修補只看修後綠,考卷多半是修的人出的。** 只跑改到的測試檔漏掉 7.8% 錯誤修補;Claude 系作弊 79% 以上是改測試。另:本 repo 推送前的閘對 light 只跑關鍵字子集,結構上同一弱點。驗證:候選 3 的回放。
8. **canary 停對了一半。** 世界沒人做線上注意力探針,這點停得對;但世界繼續做離線植入評測並改用真缺陷。引句錨定只能證明席「讀過」,不能證明「抓得到」。驗證:候選 11 第一次回植的抓到率。
9. **每輪的量。** 業界每 PR 0.5–7.5 條且只報重大;Lumos 帳面平均每輪約 16 條(含多席與設計審,口徑不同)且全要處置。驗證:按輪次與鏡頭拆每輪條數,看第 2、3 輪 minor 的比例。
10. **推送式脈絡可能傷召回。** SWE-PRBench 的 8 個模型給更多脈絡時全部變差(二手摘要);派工鏡頭一次附多篇筆記,沒量過。驗證:候選 6③ 的摘要席順便量。
11. **硬擋推送沒有外部背書,辯方也沒消融過。** 產品界的 check 都中性不擋;RovoDev 消融顯示 LLM 事實判官幾乎沒效。驗證:統計 skip 與跳過檢查次數;對辯方做開/關兩組回放。

## 延伸方向

**缺口(兩份核對有一份判「查無」的)**
- 辯方反證的機械查核(答案檔查無;複查部分有、只靠守則)→ 候選 2。
- 折入真偽的獨立抽查(答案檔只在計劃;複查查無)→ 候選 5。
- 第二輪起依等級分流處置(兩份都查無)→ 候選 14;注意它和「嚴重度不穩」相衝。
- 改到判定程式時當場回放(答案檔查無;複查部分有、只有週跑)→ 候選 12。

**部分有,照實寫**:修前會紅(工具在、沒接上)、修補誘發比對(只有手填)、席位差異化(只在鏡頭)、找漏做(設計端機械、代碼端條件席)、真缺陷回放(題庫在、無執行器)、自主迴圈版本與減法出口(提示詞層)、分級訊號(6 條規則加窄的小改動閘)。

**延伸(世界也沒做好)**
- 多輪收斂評測:世界沒有任何基準量「審→修→再審」;Lumos 帳本每筆綁凍結材料,是罕見的縱向資料,可以先做成自己的評測(以前查無先例)。
- 迴圈外前置評估者:設計審與自主迴圈前,由不讀提案、只讀 repo 與帳本的代理回答「既有層能不能解」(調研提過、沒裁)。
- 飽和觀測換估計量:用 Jackknife 或 Good-Turing 並列取代鑑別力約 0 的 Chao1,仍不進閘。
- 依信心攤人:多數決 3:0 自動採用、2:1 交人(自主迴圈已有跨家複核的類似形狀,手動迴圈查無)。
- 跟其他類的接點:植入評測與判官校準見 [[Projects/世界解重新註解2026-10_評測_調研]];推送硬閘與守衛見 [[Projects/世界解重新註解2026-10_守衛閘門_調研]];總覽見 [[Projects/世界解重新註解2026-10_總覽_調研]]。

## 筆記與程式或來源對不上的地方

**圖譜與技能檔**
1. 收斂閘漏項敏感度 v2 計劃摘要寫「2608.01000(程式):植入多的被抓到是少的 6–7 倍」,正文也標「程式領域」。實際:6–7 倍出自 WordNet 詞表、Qwen2.5 7B/14B,72B 只剩 2.3 倍,原文明說這組「不宣稱適用於測試套件」。同一錯誤也在 v1 計劃、2026-09-03 席間覆蓋率量測、派工時自動補清單計劃,共四篇。同一行把「多席投票無效」接在後面,但這篇論文明說沒跑多模型、多代理審查。建議:立一篇 Issue,四篇一起改成「詞表、小模型 6–7 倍;前沿模型扣誤報後無淨效果;程式碼組沒做這個實驗」。
2. 同一行 2608.31016 的 0.50–0.63:數字對,但那是成對鑑別力(0.5 等於亂猜),不是偵測率。建議補一句。
3. 代碼審技能主說明檔說「沒派外家時問閘會自動轉述」;程式實際已不印任何單家族提醒(見候選 7)。參考檔有同樣的句子,研究筆記也照抄了這個說法。建議:修程式接回提醒,或改手冊。
4. 代碼審技能主說明檔同一步裡,一句寫辯方「預設 Codex」,下一點寫「辯方也用同門」;參考檔寫「2026-09-30 起預設同門」。建議以 2026-09-30 的決定為準,改掉「預設 Codex」那句。
5. 設計審派工範本第 7 節仍寫「至少一席跨家族、預設 Codex」,跟條件席規則矛盾。以編制表為準,改範本。(2026-10-13 已修,連同多數決的跨家族那一次一起改成條件派,見 [[Systems/design-loop]] d13)
6. canary-audit 摘要與設計審參考檔引 2606.19749「最強單席 71.6%、六模型並集 83.3%」:數字對,但領域是研究論文審查,不是代碼審查。建議補標。
7. 設計審參考檔席位紀律 B3 的「α 最好僅 0.563」:出自 MT-Bench 成對偏好、三個開源判官中的最高值,不是普遍上限;B1 的出處應是 Findings of EMNLP 2025。建議補脈絡。
8. convergence-evidence-gate 引 2605.12280 的 κ 0.46:沒寫樣本只 18 個、第二編碼者是四家 LLM 的眾數。建議補一句。
9. 到期沒有後續的回頭條件:收斂閘漏項 v2 的量測(2026-10-03)、全報 vs 抑噪試點(2026-10-05)、自主迴圈「給真產出路徑或正式退場」(2026-10-05)。建議各自補決定。

**研究筆記本身(本篇已改正)**
10. 研究筆記說推送分級在新增行命中「金流、對外送出、正式環境不可逆、自我治理」四類型樣就升 high。查證:那四類關鍵字是給設計文字判門與自主迴圈用的;推送閘的分級只看 6 條程式形狀規則加「有沒有程式檔」,自動路徑都帶 `--no-lint`。
11. 研究筆記的自主迴圈候選寫「外層一律用主線版本重算,防提案分支改閘」。查證:這個流程沒有提案分支(提 PR 模式已拒跑),實際風險是編排者在同一份工作目錄有寫檔權限、外層之後用被改過的版本重算。候選 13 已改寫。
12. 研究筆記的修前紅最小版是「在修正前提交只疊測試檔」。查證:代碼審修正關卡計劃第 3 輪評估過並換掉,理由是會漏輔助檔。候選 3 不再提這個做法。

## 誠實界線

- 研究筆記 104 條世界解,13 條主研究員深讀、91 條由五個同模型子研究員寫成;主研究員回原文抽查 7 處承重事實。本篇沒有重新上網複驗,標「未複驗」的照標。
- Lumos 現況以 2026-10-11 兩份乾淨核對為準(repo 提交 b453b94f);兩份判定不同處(辯方查核、折入抽查、當場回放)都已並列,事實其實一致,差在分類用詞。答案檔自述派交叉核對代理時被子代理上限擋下,「查無」是單人判讀,複查補了一部分。
- 本篇作者自己只到 repo 查了三件事:推送分級用哪些規則、技能檔對辯方預設家族的寫法、編制表有沒有「沒派要註記」的席。
- 帳本數字(528 輪、8449 條、98.8% 折入、23 筆逃逸)取自 2026-09-21 的計劃筆記,沒有重算;「約 32% 是修補造成」來自編排者手填,沒人驗過。
- 產品類數字多半是廠商自報(B)或宣稱(D);「被處理率」多由 LLM 推論。進度幻象是作者自稱的初步稿,ReviewBench 發表才 6 天。
- 所有候選都沒過 Lumos 自己的設計審,排序是證據與成本的判斷,不是已驗證的效益;第 5、6、9、14 名會增加成本或改動 2026-09-30 的裁定,需要人裁。
