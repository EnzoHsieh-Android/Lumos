# 公開精簡版（離職交接用）

`PRIOR-ART:` ① **最小解在既有層**——不造新機制；CLI 從既有單檔生成子集，skill／hooks 直接複製既有檔案。② **世界解過**：「單一源產出 minimal 發行版」有成熟先例（busybox applet 白名單、vim tiny/huge build）。③ **裁定＝borrow-design**：借「白名單驅動的建置變體」形態，**不採**打包工具（零依賴家規，且本案是一次性產出，引入 build pipeline 不划算）。自建只有一支 ast 剖析腳本。

## 目標（一句話）

> **新人 clone 專案 → 裝上精簡版 → 能讀懂專案既有的知識圖譜。**

不是發布一個產品，是**交接一份可讀的資產**。

★**優先序（2026-07-31 使用者更正）**★：**「可讀」是目標，「可維護」是加分**。
**不設任何強制**——不擋 commit、不擋 push、不催更新圖譜。交接後他們維不維護得下去，是他們的選擇，本案不用機制去逼。

## 情境與相容性（已實查，2026-07-31）

| 事實 | 影響 |
|---|---|
| Landmark 已 vendored 完整版 `scripts/lumos`（checked in） | 新人 clone 就有；但他**機器上**沒有全域指令、沒有 skill、沒有 Claude hooks |
| **Landmark 的** `CLAUDE.md` 引用 `lumos-project-notes` **9 次**（本 repo 自己的 CLAUDE.md 是 4 次，勿混），而該 skill 是 user-scope symlink 到維護者個人 clone | ★**這是真正的缺口**★——維護者離開，skill 消失，紀律區塊會叫 agent 去用一個不存在的東西 |
| git hooks 呼叫 `$REPO_ROOT/scripts/lumos`（vendored），非全域指令 | **精簡版與既有工作流並存不衝突**，不需要動 Landmark |
| 新人只在「改 code 且 tier=high」時會撞到 code-loop 閘 | 那是寫程式活動、不在本案目標內；退路 `python3 scripts/lumos ...` 仍在 |

## 條款

### [S1] 白名單
**保留**（分界原則：維護圖譜本身 → 給；產出審計／評測結果 → 砍）
- 讀取／導航：`search` `context` `show` `contracts` `links` `backlinks` `map` `export` `decisions` `stale` `recent` `stats`
- 寫入：`set` `append` `new` `archive` `decision-add` `decision-supersede` `decision-reindex`
- 健檢：`lint` `doctor`（含 Check T/R/J）
- 合約鏈：`guard`（list/scaffold/bind/audit/trace/kill/kill-add）
- 圖譜維護紀律：`impact` `cochange` `self-audit` `sync-verified-by` `rel-cascade` `spec-trace` `signoff` `anchor`
- 機器層安裝：見 [S3]（**不含** `init`／`update`／`deinit` 等專案層指令）

**移除**：`pitfalls` `code-loop` `canary` `loop` `fold-check` `refcheck`（對抗審計 loop）、`testmap` `test-layers` `lint-check` `lint-watch` `sqlfluff-sarif` `stylelint-sarif` `compose-metrics`（測試／linter 工具鏈）、`gov`（治理帳，主要彙整 loop 產物）。

### [S2] 生成方式（ast，非 regex）
- 用 python 內建 `ast` 移除白名單外的 `cmd_*` 函式定義、其 subparser 註冊（**含迴圈註冊形式**——`links`/`backlinks` 正是迴圈註冊）、其 dispatch 分支。
- **共用 helper 一律保留**（保守：寧可多留，也不要生成出跑不動的檔）。
- 產物須 `compileall` 通過、SyntaxWarning 為零。
- **為何用 ast 不用 regex**：2026-07-30 實證 regex 剖 Python 兩次出錯（漏抓迴圈註冊指令→53 誤算 51；漏抓三元式賦值→verdict 值域少一個）。

### [S3] ★安裝器只做機器層★（本案最容易毀掉東西的一條）
新寫一支安裝器，**只做三件事**：
1. 全域 `lumos` 指令（指向精簡版）
2. `~/.claude/skills/lumos-project-notes/`（**實體複製**，不是 symlink——來源會消失）
3. （原規劃的 Claude hooks 已取消，見 [S4]）

**明確不做**：不 scaffold 圖譜、**不注入／不更新任何 CLAUDE.md**、不 vendor 工具進專案、**不設 `core.hooksPath`**、不裝任何會擋人或催人的 hook。

> **已查證的有利事實（2026-07-31）**：`core.hooksPath` 存在於 `.git/config`，而該檔**不隨 clone 傳遞**。故新人 clone 後 git hooks **天然就不生效**——只要安裝器不去設它，「不擋新人」這件事不需要額外工程。
理由：專案層動作會用精簡範本覆蓋既有專案的紀律區塊，毀掉維護者仍在使用的工作流。
**不得沿用** `install.sh`／`scripts/install-graph-toolchain.sh`（腳本）或 `lumos bootstrap`／`lumos init`／`lumos update`（指令）——它們都會碰專案層。

### [S4] 交付內容
| 項目 | 來源 | 備註 |
|---|---|---|
| `lumos`（精簡） | [S2] 生成 | |
| `skills/lumos-project-notes/`（含 `reference.md`） | 直接複製 | **最關鍵**——沒有它，圖譜寫下去會壞 |
| ~~Claude hooks~~ | **不給** | `check-graph-sync.py` 的作用正是催人「改 code 要更新圖譜」＝強制維護，與「不設強制」的裁定衝突；`verification-rot-check.py`／`impact-hook.py` 同理不給。新人要的是讀得懂，不是被提醒 |
| 機器層安裝器 | [S3] 新寫 | |

**不給**：`lumos-design-loop`／`lumos-code-loop`／`lumos-core-knowledge` 三支 skill（**Landmark 圖譜**全庫實際只有 1 篇有 `core_refs:` 欄位，價值低）。

### [S5] README（自足性——本案的第二個重點）
交接後無人可問，README 必須讓沒看過這套東西的人自己上手：
- 怎麼裝、怎麼確認裝好了
- 進場三步（search → context → contracts）
- **frontmatter 四條鐵則**（違反會長 ghost 節點、整篇 property 失效）——這是最容易踩壞的
- 合約鏈是什麼、`doctor` 為什麼會擋、怎麼解
- **明講範圍**：這是功能子集，不含對抗審計 loop；且 Python 是原始碼語言，**移除的是入口不是全部程式碼**

### [S6] 交付前三道機械驗證（一次性，但不可跳）
1. **負向**：`--help` 的 choices 不得出現任何被移除的指令。
2. **正向**：白名單內每支指令可被呼叫；`doctor` 要**實跑**（不只 `--help`）。
3. **等價**：拿 `governance/eval/retrieval-goldset.json`（30 條查詢）對完整版與精簡版各跑一次，搜尋結果須一致。
4. **真機預演**：在一台**乾淨 HOME** 上跑完整流程（clone 專案 → 裝精簡版 → 查圖譜 → 寫一個節點 → `lint` → `doctor`），確認新人路徑真的走得通。

## 實務隱患

- ★**安裝器誤碰專案層**★：只要不小心呼叫到 re-inject，既有專案的 CLAUDE.md 紀律區塊會被精簡範本覆蓋。→ [S6] 真機預演必須斷言「專案的 CLAUDE.md 前後 byte-equal」。
- **skill 必須是實體複製非 symlink**：來源（維護者的個人 clone）會消失。
- **`doctor` 的檢查項與白名單耦合**：若某個 Check 依賴被砍的指令，精簡版 doctor 會壞 → [S6] 正向驗證要實跑 doctor。
- **`guard kill` 需 config 宣告 run_cmd**：沒宣告就跑不動，錯誤訊息要說得清楚，不能只丟 traceback。
- **共用 helper 保留造成誤解**：公開版仍看得到治理相關小函式，可能被誤讀為「功能其實還在」→ README 必須明講。
- ~~新人撞到 code-loop 閘~~：**已消除**——新人 clone 後 `core.hooksPath` 未設，git hooks 不生效。惟若日後有人手動跑既有的 `install-hooks.sh`，閘會被啟用；README 應說明「不需要跑那支」。
- **交接後無人維護**：出 bug 沒人修。緩解＝Python 是源碼，他們改得動；README 要說明這點。

## 測試策略

| 條款 | 測試 | 型態 |
|---|---|---|
| [S2] | 生成後 `compileall` 通過＋SyntaxWarning 零；**迴圈註冊的指令在該砍時真的被砍掉** | 單元＋反事實 |
| [S3] | 安裝器**不得**觸及專案層：斷言跑完後專案 `CLAUDE.md`／`scripts/` 前後 byte-equal | **反事實（最重要）** |
| [S6] | 三道驗證各有測試；**等價驗證要能抓到差異**（故意改精簡版排序參數 → 必翻紅） | 反事實 |
| [S5] | README 提及的每個指令都存在於白名單（防教到已砍功能） | 機械守衛 |

**反事實優先**：[S3] 與 [S6] 的價值全在「壞掉時會不會擋」，必須有「弄壞→必翻紅」的測試。

## 誠實天花板

- **這不是藏程式碼**：Python 是原始碼語言。移除的是**功能入口**，共用 helper 仍在。
- **等價驗證只涵蓋搜尋**：goldset 是檢索用的，不保證其他指令兩版行為一致。
- **生成腳本沒有第二來源可對照**：它若剖錯，三道驗證能抓到「指令還在／不能跑」，抓不到「語意被改壞」。
- **一次性交付**：沒有回歸測試會持續跑，交出去之後品質不再有機械保證。
