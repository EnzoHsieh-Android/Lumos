## 這篇的歸納(★是我的歸納,不是查到的;推翻條件寫在最後★)

兩份調研的存活缺口攤開後分成**兩族**,混在一起談會誤判:

**家族甲:宣稱與現實脫鉤,而且沒有東西會發現。**
- 勾選框沒人勾、`status/doing` 停滯、翻案待辦零判定、提醒喊 185 次沒人理、settle 35 條全部規格雜湊過期。
- 共同點:**狀態是手寫的,沒有可重算的來源,寫下去就開始漂**。
- ★這一族已有被證明有效的自家解法★:`loop verify-progress` 的 help 自述「不看散文,只從帳本結構欄位看審到哪」——狀態從證據算,不給人維護。

**家族乙:機械檢查了「形式」,沒檢查「內容」。**
- `[src:路徑:行號]` 驗路徑在不在,不驗那行支不支持主張。
- 「測試存在且綠」驗測試綠,不驗那個任務做完了(見 [[Projects/執行DAG_調研]] 外家 f2)。
- 引句檢查驗那句話在不在快照裡(字串包含比對),不驗那句話有沒有被正確使用。
- `--accept-reason` 驗非空,不驗理由成不成立。
- `seat-check` 驗引句錨得進派工材料,不驗引句支不支持那條發現。

★家族甲是紀律病,人也會犯;家族乙是 **AI 特有**的★——AI 極擅長生產「形式完全正確、內容不成立」的東西:一個真實的行號、一句真的存在的引文、一個非空的理由、一個綠色的測試。**每一項都通過機械檢查,而整體是錯的。**

## 世界的見解(逐條附數字與出處)

### 1. 引用存在 ≠ 引用支持:世界已經把它拆成三層來量

arXiv 2605.06635《Cited but Not Verified》,14 個 LLM × 130 個研究題:

| 層 | 問什麼 | 前沿模型表現 |
|---|---|---|
| Link Works | 連結打得開嗎 | **94–100%** |
| Relevant Content | 來源跟主張同一個主題嗎 | **>80%**(即 ≤20% topically 無關) |
| **Fact Check** | **來源真的支持那個具體主張嗎** | ★**24–77%**★(三層裡變異最大) |

★對照本 repo★:`[src:]` 驗的是「路徑在、行號沒越界」——**大約落在第一層**。第二層(那段程式碼跟這條主張同一個主題嗎)與第三層(它真的支持嗎)**現在完全沒有驗**。
★誠實界線:那是「深研究 agent 引網頁」的數字,不是「agent 引自己剛讀過的程式碼行」的數字,不能直接外推——只能當先驗,不能當預測(本日已因外推類比被外家打過一次)。★

### 2. 記憶下毒:內容篩檢原理上攔不住,必須靠外部接地

arXiv 2608.21230,對 Aegis 記憶系統打假事實(LongMemEval 語料,注入量僅占 1.2%):

- 乾淨準確率 0.850 → 被下毒後 **0.300**(只剩三成五價值);被下毒的記憶**排第一名的比例 100%**。
- ★四階段內容篩檢管線,對 prompt injection 有 0.832 recall,**對 360 筆假事實一筆都沒攔下**★。
- 作者的理論主張:**「要分辨一個假斷言和真斷言,通常需要被篩文本之外的外部接地」**——毒訊沒有任何結構標記(不含指令、不含角色操縱、不含編碼技巧),語意上與正常內容無法區分。
- **provenance 當「加權排序」失敗**:出貨權重下與不設防在統計上無法區分(p=0.80);調高權重才部分改善。作者主張 provenance 應該當成**佔位配額式的硬約束**而不是加分項——★但明說「我們沒有實作也沒有評估這個機制」★。

★對本 repo 的意義(兩個方向相反的訊號)★:
- **好消息**:`[src:]` 本來就是**外部接地**(指向程式碼),站在那篇論文說「唯一有效」的那一邊;不是靠讀文本內容判真假。
- **好消息 2**:Lumos 的不對稱接線(推測行不得掛合約標記)是**硬約束**,不是加權排序——正好避開論文量到失敗的那種做法。
- **壞消息**:接地存在不等於接地被檢查。**現在沒有任何一步去看「那一行真的支持這條主張嗎」。**

### 3. 機械強制 vs 散文治理:世界把本 repo 的家規量出來了

arXiv 2605.14744《Mechanical Enforcement for LLM Governance》,2400 案 / 8 條件 / 每格 N=300:

- ★**純文字治理下,27.3% 的「延後決定」是化妝式合規**★——文字上完全符合要求,實質不含任何可行動的資訊(論文舉例:「因案情複雜,需進一步審查」)。機械強制降到 **7.4%**(減 73%)。
- ★**治理品質與任務準確度會脫鉤**★:資訊缺失情境下,機械強制組**治理品質最好**(化妝率 0.088)而**任務準確度崩到 0.285**;純文字組則兩者一起爛。→ **兩者必須分開量,用任務成功率當治理品質的代理指標會蓋掉治理失敗。**
- 核心理論:**「當同一個模型既解釋政策又滿足政策時,那條政策就只是建議而不是約束」**(regressional Goodhart)。機械原語一律**跑在 LLM 的解釋迴圈之外**;約 32.7% 的案子由機械直接決定。
- 其中一個原語 **I6Q** 值得直接搬:**要求理由的最低品質**(≥10 tokens、詞彙多樣度 ≥0.4)——這是「化妝式合規」的機械對治。
- 作者自陳限制:單一模型家族(Llama 3.1 70B)、合成領域、40/60 切分是任意的、兩組都仍受框架效應影響、需要跨模型驗證。

### 4. 驗證天花板:這不是可以修好的 bug

arXiv 2606.26300《The Verification Horizon》:**「沒有任何固定的獎勵函數能在能力持續成長時保持有效;驗證必須與生成者共同演化。獎勵駭客不是可以修補的 bug,而是持續朝不完美目標最佳化的必然結果。」** arXiv 2605.21384(SpecBench)給了量法:**同一批任務準備兩套測試——agent 看得到的驗收套與藏起來的測試套,兩者通過率的差就是「獎勵駭客缺口」**。
