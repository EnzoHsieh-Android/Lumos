# 中心性重驗排程計劃

> 緣起：2026-07-28 閉環盤點——重驗優先序現況是**字母序**（非時間序，r1 修正假基線）；圖中心性×陳舊度是風險加權的自然解。

PRIOR-ART: ① 最小解層級——`cmd_stale`/Check S 既有輸出加排序鍵，無新機制；PageRank power iteration 零依賴 ~30 行。② 世界解——PageRank 標準演算法；GraphRAG 生態以 PPR 傳播為共識。**在地反證必答（r1-std 誠實化：A3 是 search+edit 雙面被殺，非只 search）**：A3（in-degree 權威加分）goldset 雙面負增益（search 0.875→0.847、edit P@8 0.70→0.65）——edit 面（改碼推薦）語意上比 search 更近「波及面」，in-degree 在那也輸。本計劃的差異論證因此**降格為假設**：(a) 重驗排「壞掉傷害面」與檢索排「相關性」是不同 oracle；(b) MOC 整類排除切樞紐主源；(c) **Landmark 人判實驗＝轉正閘（make-or-break）——人判無感即殺整個計劃，沿 A3 消融紀律，不硬轉正**。③ 裁定=borrow-design。

## 規格（[S] 條款）

- [S1] **中心性 helper**：`_graph_pagerank(env, personalization=None)`——節點集＝vault 全節點**排除 type=moc**；邊＝wikilink 出入連結（env 既有索引，ghost 已在建邊時丟棄）；阻尼 0.85、收斂閾 1e-6 或 50 迭代；**dangling 節點質量均攤回全圖**（標準處理；MOC 移除引致的新 dangling 同規則處理）；收斂判定用 L1 norm。`personalization` 參數位預留給 [[Projects/檢索PPR邊權_計劃]]（兩計劃共用核心），v1 恆 None。純函式、小圖手算可測。
- [S2] **排序鍵（r1-std 拆軌重定義）**：兩側候選母體性質不同，**兩軌各自定義、不強融**：
  - **stale 軌（Verification 候選）**：`risk = PR百分位 × (1 + log1p(陳舊天數))`——乘數帶 +1 底板（r1-std 修正：log1p(0)=0 會殲滅 PR 訊號，0 天時 risk=PR 而非 0）。中心性＝**typed 反向索引（etype=verified_by）**取被 verified Systems 的 PR max（不用無型別 in_e，防 related/正文連入誤收；反向來源不限 type=system，Project 掛 verified_by 同收）；查無對象＝百分位 0.5 中性。陳舊天數＝`date` 欄，**缺欄 fallback＝檔名日期前綴→created**（16/63 自家 Verification 無 date，實測）。
  - **Check S 軌（System 候選）**：**純 PR 排序，不乘天數**——Check S 現行語意是二值過期判定、無天數概念（sa_missing 清單連日期都沒有），硬造天數＝另創口徑；兩張清單（sa_missing/sa_stale）**各自內部**按 PR 降冪重排，清單不合併。
  - **PR 百分位定義**：對「非 moc 全節點集的 PR 值」取 percentile rank（同分 average-rank）；Verification 的對象 max 值放同一母體取分位。三段欄＝等頻 33/67 切。tie-break＝天數降冪→檔名。
- [S3] **顯示整合**：`lumos stale` **僅 bare 模式**預設融合排序＋分位欄（`--match`/`--candidate` 維持現行輸出不動），`--legacy` 保字母序；doctor Check S 兩張清單各自按 PR 重排——**明示效果＝換掉各自前 8 筆櫥窗**（2×8 雙窗，非單一前 8）；**實作約束**：重排做在餵入 `_soft_list` 之前（該 closure 為多 Check 共用，不可改動本體）；掃描迴圈與 gov_events 寫入順序不動；Check S 無逃生 flag——sink 防範改依 gov 帳可查全清單＋誠實邊界（r1-std 修正：原引用的 --legacy 對 doctor 不存在）。

## 邊界（明確不做）

- 不新增輪詢/排程器；不動 Check S 觸發條件與軟硬度；不寫入任何帳。
- 不做 betweenness（PageRank 的 in-link 語意已對齊「傷害面」理據）；個人化 PPR 歸 [[Projects/檢索PPR邊權_計劃]]（該計劃 spec 未寫，參數位為本計劃單方預留）。
- 不做自動重驗（排序器非 scheduler）。

## 實務隱患

- **self-governance（r1 升格為真命中）**：Check S 只露前 8 筆——排序偏置會**系統性決定誰永遠不被看見**（r1 F10：樞紐霸榜＋截斷疊加）。防範：(a) MOC 整類排除（樞紐主源切除）；(b) 金流/守衛類 System 若 PR 低仍可能沉底——誠實邊界明記「中心性≠業務重要度」，人挑恆壓過排序；(c) `--legacy` 一鍵回字母序。
- **payment/prod-irreversible（不適用）**：純讀、git 可逆。

## 測試策略（[S] 對應）

- [S1]：`t_graph_pagerank`——4 節點手算小圖：A→B→C（C **無出邊＝dangling**，驗質量均攤）＋ 孤兒 D（得基礎分不為 0）；MOC 節點不進節點集；ghost 連結不炸。
- [S2]：`t_stale_central`（落 test_lumos.py，沿 t_* 慣例）——(a) 高中心對象的 stale Verification 排前於低中心更舊者；(b) **0 天高中心不沉底**（+1 底板：risk=PR 非 0）；(c) 查無對象＝中性 0.5；(d) 無 `date` 欄走檔名前綴 fallback；(e) `--legacy`＝字母序；(f) typed 反向（verified_by）取對象、related 連入不誤收。
- [S3]：Check S 兩清單各自 PR 降冪（斷言各自前 8 選集符合）；gov_events 寫入序不變；`--match`/`--candidate` 輸出不受影響。
- **實驗場（Landmark，r1-std 重定義——三個母體實況修正：status:stale=0 篇/MOC 僅 1 個無 in-link/55% Verification 無對象鏈）**：(a) 排序對照**不走 cmd_stale 預設模式**（母體空集），改 helper 直接對 Landmark **有對象鏈的 active Verification 子集**（38 篇）出「風險排序 vs 檔名序」前 15 對照表，**交人判＝本計劃轉正閘**（無感即殺）；中性席占比（46/84）如實附註。(b) 檔名序＝日期前綴＝實質時間序，對照解讀基準如實標明。(c) MOC 偏置實驗**移至 toolchain vault**（MOC 數量足）做排除前後 top-10 差異；Landmark 不適用（MOC=1）。(d) 產物落點＝本計劃節點 body 對照表（不另生 csv 檔）。

## 誠實邊界

- 中心性＝連結拓撲的傷害面代理，**不是業務重要度真值**——金流節點連結少照樣重要；人挑恆壓過排序建議（sink 風險已列實務隱患）。
- 陳舊天數 log1p＝粗刻度；精算衰減等逃逸帳有樣本再調（同 [[Systems/design-loop]] d5 經濟學：先累後校準）。
- PageRank 對本圖（幾百節點）近似平滑 in-degree——選它是取「傷害面」語意與 [[Projects/檢索PPR邊權_計劃]] 共用核心，非宣稱拓撲深度優勢。
