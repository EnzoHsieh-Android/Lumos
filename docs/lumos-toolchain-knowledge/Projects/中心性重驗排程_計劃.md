# 中心性重驗排程計劃

> 緣起：2026-07-28 閉環盤點——重驗優先序現況是**字母序**（非時間序，r1 修正假基線）；圖中心性×陳舊度是風險加權的自然解。

PRIOR-ART: ① 最小解層級——`cmd_stale`/Check S 既有輸出加排序鍵，無新機制；PageRank power iteration 零依賴 ~30 行。② 世界解——PageRank 標準演算法；GraphRAG 生態以 PPR 傳播為共識。**在地反證必答**：本 repo A3 消融（in-degree 權威加分）已在 search 場景被殺（「高連結節點＝導覽樞紐非答案，勿憑直覺復活」）——本計劃的差異論證＝(a) 場景不同：search 排「答案相關性」，本計劃排「壞掉傷害面」（愈多節點依賴其正確性，重驗優先級愈高——這正是 in-link 的語意）；(b) 樞紐偏置主源（MOC/導覽節點）**整類排除**於節點集；(c) 驗收不用 auto-sanity（防循環論證），用 Landmark 人判對照。③ 裁定=borrow-design。

## 規格（[S] 條款）

- [S1] **中心性 helper**：`_graph_pagerank(env, personalization=None)`——節點集＝vault 全節點**排除 type=moc**；邊＝wikilink 出入連結（env 既有索引，ghost 已在建邊時丟棄）；阻尼 0.85、收斂閾 1e-6 或 50 迭代；**dangling 節點質量均攤回全圖**（標準處理，防葉節點質量流失）。`personalization` 參數位預留給 [[Projects/檢索PPR邊權_計劃]]（兩計劃共用核心），v1 恆 None。純函式、小圖手算可測。
- [S2] **排序鍵（r1 重設計）**：`risk = PR分位(0..1) × log1p(陳舊天數)`。
  - **母體適配**：`stale` 候選＝Verification 節點 → 其中心性取 **frontmatter 反向對象（被 verified 的 Systems）的 PR max**（Verification 自身是葉，取對象傷害面）；查無對象＝PR 分位 0.5（中性，不懲罰）。Check S 候選＝System 節點 → 用自身 PR。
  - **陳舊天數口徑**：`stale` 用該 Verification 的 `date`；Check S 用**其自身過期判定的天數**（沿 Check S 現行語意，不另創口徑——避免「剛 self_audit 卻被推隊首」的自打架）。
  - log1p 壓天數（防百倍天數輾壓個位倍 PR 差）；同分 tie-break＝天數降冪→檔名。
- [S3] **顯示整合**：`lumos stale` 預設融合排序＋中心性分位欄（高/中/低＝PR 分位三段），`--legacy` 保**字母序**（舊序的真身）；doctor Check S 的顯示清單按同 helper 重排——**明示效果＝換掉前 8 筆櫥窗讓給高風險**（`_soft_list` 截斷語意如實宣稱）；掃描迴圈與 gov_events 寫入順序**不動**（實作約束）。

## 邊界（明確不做）

- 不新增輪詢/排程器；不動 Check S 觸發條件與軟硬度；不寫入任何帳。
- 不做 betweenness（PageRank 的 in-link 語意已對齊「傷害面」理據）；個人化 PPR 歸 [[Projects/檢索PPR邊權_計劃]]（本計劃只留參數位）。
- 不做自動重驗（排序器非 scheduler）。

## 實務隱患

- **self-governance（r1 升格為真命中）**：Check S 只露前 8 筆——排序偏置會**系統性決定誰永遠不被看見**（r1 F10：樞紐霸榜＋截斷疊加）。防範：(a) MOC 整類排除（樞紐主源切除）；(b) 金流/守衛類 System 若 PR 低仍可能沉底——誠實邊界明記「中心性≠業務重要度」，人挑恆壓過排序；(c) `--legacy` 一鍵回字母序。
- **payment/prod-irreversible（不適用）**：純讀、git 可逆。

## 測試策略（[S] 對應）

- [S1]：`t_graph_pagerank`——4 節點手算小圖：A→B→C（C **無出邊＝dangling**，驗質量均攤）＋ 孤兒 D（得基礎分不為 0）；MOC 節點不進節點集；ghost 連結不炸。
- [S2]：`t_stale_central`——(a) 高中心對象的 stale Verification 排前於低中心更舊者（融合非純天數）；(b) 今天剛過的節點不因 log1p(0)=0 併列亂序（tie-break 生效）；(c) 查無 verified 對象＝中性分位；(d) `--legacy`＝字母序。
- [S3]：Check S 顯示序走同 helper（斷言前 8 筆選集變化符合排序）；gov_events 順序與重排無關（斷言寫入序不變）。
- **實驗場（Landmark，2026-07-28 使用者指示）**：對 LandmarkMember vault（275 節點實圖）跑 [S1]/[S2]——輸出「融合排序 vs 字母序」前 15 名對照表**交人判**（非 auto-sanity）：人裁「新序是否更接近『該先重驗誰』的直覺」；MOC 排除前後 top-10 差異一併附上（驗樞紐偏置切除有效）。

## 審計修正紀錄

- r0 pre-flight（2026-07-28，haiku）：7 命中全屬「spec 提議之新物尚未存在」＝設計文件常態，非缺陷；現況假設與 code 相符。
- r1 light 單席（2026-07-28，canary type a「A9 靜態先驗乘數」caught；probe 重植×2 頂格如實註記）：**blocker×1**＝排序欄位（self_audit）在 stale 實際候選母體（Verification 專屬清單）不存在→S2 母體適配重設計（Verification 取 verified 對象 PR）。**major×4**＝①假基線（現況＝字母序非時間序）→敘述/對照/`--legacy` 語意全修真；②A3 消融反證未面對→PRIOR-ART 補差異論證＋MOC 整類排除；③乘法退化（0 天歸零併列/天數輾壓）→log1p＋tie-break＋Check S 口徑對齊；④「只改列印順序」不實（top-8 截斷＝換可見集合）→如實宣稱＋gov_events 不動約束。**minor 批**＝穿過措辭（betweenness 語言）改權威度理據、dangling 均攤規格化、計劃②寫全稱＋參數位、測試圖 dangling 修正、實驗改人判、d5 引用寫全稱（[[Systems/design-loop]] d5 經濟學）、體積口徑統一。**light ratchet：升 standard（-std panel）**。

## 誠實邊界

- 中心性＝連結拓撲的傷害面代理，**不是業務重要度真值**——金流節點連結少照樣重要；人挑恆壓過排序建議（sink 風險已列實務隱患）。
- 陳舊天數 log1p＝粗刻度；精算衰減等逃逸帳有樣本再調（同 [[Systems/design-loop]] d5 經濟學：先累後校準）。
- PageRank 對本圖（幾百節點）近似平滑 in-degree——選它是取「傷害面」語意與 [[Projects/檢索PPR邊權_計劃]] 共用核心，非宣稱拓撲深度優勢。
