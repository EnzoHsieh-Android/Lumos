# 中心性重驗排程計劃

> 緣起：2026-07-28 閉環盤點——重驗優先序現況：stale 軌＝檔名日期前綴的**實質時間序**（r2 修真：兩 vault 的 Verification 檔名全帶日期），Check S 軌＝真字母序；價值主張＝「純時間/字母」→「傷害面加權」。

PRIOR-ART: ① 最小解層級——`cmd_stale`/Check S 既有輸出加排序鍵，無新機制；PageRank power iteration 零依賴 ~30 行。② 世界解——PageRank 標準演算法；GraphRAG 生態以 PPR 傳播為共識。**在地反證必答（r1-std 誠實化：A3 是 search+edit 雙面被殺，非只 search）**：A3（in-degree 權威加分）goldset 雙面負增益（各條件最差值：search 0.875→0.847@w0.2、edit P@8 0.700→0.653@w0.1，詳 [[Projects/節點靜態先驗_調研]] 消融紀錄）——edit 面（改碼推薦）語意上比 search 更近「波及面」，in-degree 在那也輸。本計劃的差異論證因此**降格為假設**：(a) 重驗排「壞掉傷害面」與檢索排「相關性」是不同 oracle；(b) MOC 整類排除切樞紐主源；(c) **Landmark 人判實驗＝轉正閘（make-or-break）——人判無感即殺整個計劃，沿 A3 消融紀律，不硬轉正**。③ 裁定=borrow-design。

## 規格（[S] 條款）

- [S1] **中心性 helper**：`_graph_pagerank(env, personalization=None)`——節點集＝vault 全節點**排除 type=moc**；邊＝wikilink 出入連結（env 既有索引，ghost 已在建邊時丟棄）；阻尼 0.85、收斂閾 1e-6 或 50 迭代；**dangling 節點質量均攤回全圖**（標準處理；MOC 移除引致的新 dangling 同規則處理）；收斂判定用 L1 norm。`personalization` 參數位預留給 [[Projects/檢索PPR邊權_計劃]]（兩計劃共用核心），v1 恆 None。純函式、小圖手算可測。
- [S2] **排序鍵（r1-std 拆軌重定義）**：兩側候選母體性質不同，**兩軌各自定義、不強融**：
  - **stale 軌（Verification 候選）**：`risk = PR百分位 × (1 + log1p(陳舊天數))`——乘數帶 +1 底板（r1-std 修正：log1p(0)=0 會殲滅 PR 訊號，0 天時 risk=PR 而非 0）。中心性＝**typed 反向索引（etype=verified_by）**取被 verified Systems 的 PR max（不用無型別 in_e，防 related/正文連入誤收；反向來源不限 type=system，Project 掛 verified_by 同收——此為本計劃自立裁定（typed 索引本就不濾來源型別）；對象若為 moc（不在 PR 節點集）＝跳過取其餘 max，全 moc＝無鏈組）；查無對象＝**獨立「無鏈」分組列於有鏈組之後、組內按天數**降冪**排序、tie-break＝檔名**（r3 補方向；「＝現況行為」的前提＝date 欄與檔名前綴一致，分歧時以 date 欄為準；r2 修正：右偏分布下 0.5「中性」實為結構性墊底的偽分數——無從評傷害面就不偽裝分數；無鏈組＝純時間序即現況行為，不需實驗檢定）。陳舊天數＝`date` 欄，**缺欄 fallback＝檔名日期前綴（regex `^\\d{4}-\\d{2}-\\d{2}`）→ created → 三層全缺＝剔除該候選並印警示（fail-visible，規格級行為；無鏈組成員同規則）**（16/63 自家 Verification 無 date，實測）。
  - **Check S 軌（System 候選）**：**純 PR 排序，不乘天數**——Check S 現行語意是二值過期判定、無天數概念（sa_missing 清單連日期都沒有），硬造天數＝另創口徑；兩張清單（sa_missing/sa_stale）**各自內部**按 PR 降冪重排，清單不合併。
  - **PR 百分位定義**：對「非 moc 全節點集的 PR 值」取 Hazen 百分位 **(rank−0.5)/N**（同分平均秩;N=0 空母體直接跳過排序）（值域開區間、永不為 0 或 1——防最低分席 risk 歸零沉底，同 0 天修正對稱；同分 average-rank）；Verification 的對象 max 值放同一母體取分位。三段欄＝等頻 33/67 切。tie-break：stale 軌＝天數降冪→檔名；Check S 軌＝檔名（該軌無天數概念，r2 補漏）。
- [S3] **顯示整合**：`lumos stale` **僅 bare 模式**預設融合排序＋分位欄（＝[S2] 三段 band 標籤，同物同名）（`--match`/`--candidate` 維持現行輸出不動），`--legacy` 保字母序；doctor Check S 兩張清單各自按 PR 重排——**明示效果＝換掉各自前 8 筆櫥窗**（2×8 雙窗，非單一前 8）；**實作約束**：重排做在餵入 `_soft_list` 之前（該 closure 為多 Check 共用，不可改動本體；sa_stale 席現為預格式化字串，需先改建 (rel,msg) 元組再排——r2 補）；掃描迴圈與 gov_events 寫入順序不動；Check S 無逃生 flag——sink 防範改依 gov 帳可查全清單（前提註記：Check S 進 gov 帳僅 `doctor --ci`，日常裸跑無帳）＋誠實邊界。

## 邊界（明確不做）

- 不新增輪詢/排程器；不動 Check S 觸發條件與軟硬度；不寫入任何帳。
- 不做 betweenness（PageRank 的 in-link 語意已對齊「傷害面」理據）；個人化 PPR 歸 [[Projects/檢索PPR邊權_計劃]]（該計劃 spec 未寫，參數位為本計劃單方預留）。
- 不做自動重驗（排序器非 scheduler）。

## 實務隱患

- **self-governance（r1 升格為真命中）**：Check S 只露前 8 筆——排序偏置會**系統性決定誰永遠不被看見**（r1 F10：樞紐霸榜＋截斷疊加）。防範：(a) MOC 整類排除（樞紐主源切除）；(b) 金流/守衛類 System 若 PR 低仍可能沉底——誠實邊界明記「中心性≠業務重要度」，人挑恆壓過排序；(c) `--legacy` 一鍵回字母序。
- **payment/prod-irreversible（不適用）**：純讀、git 可逆。

## 測試策略（[S] 對應）

- [S1]：`t_graph_pagerank`——4 節點手算小圖：A→B→C（C **無出邊＝dangling**，驗質量均攤）＋ 孤兒 D（得基礎分不為 0）；MOC 節點不進節點集；ghost 連結不炸。
- [S2]：`t_stale_central`（落 scripts/test_lumos.py，沿 t_* 慣例）——(a) 高中心對象的 stale Verification 排前於低中心更舊者；(b) **0 天高中心不沉底**（+1 底板：risk=PR 非 0）；(c) 查無對象＝入無鏈分組列於有鏈組後（斷言不派分數）；(d) 無 `date` 欄走檔名前綴（regex `^\\d{4}-\\d{2}-\\d{2}`）→ `created` → 三層全缺＝剔除該候選並印警示（fail-visible）；(e) `--legacy`＝字母序；(f) typed 反向（verified_by）取對象、related 連入不誤收。
- [S3]：Check S 兩清單各自 PR 降冪（斷言各自前 8 選集符合）；gov_events 寫入序不變；`--match`/`--candidate` 輸出不受影響。
- **實驗場（Landmark，r1-std 重定義——三個母體實況修正：status:stale=0 篇/MOC 僅 1 個無 in-link/55% Verification 無對象鏈）**：(a) 排序對照**不走 cmd_stale 預設模式**（母體空集），（Landmark active status:stale＝0、bare 模式不濾 Archive 會列 1 筆 archived——兩帳如實並記，r3 同步）改 helper 直接對 Landmark **有對象鏈的 active Verification 子集**出「風險排序 vs 檔名序（＝實質時間序）」前 min(15,子集數) 對照表，**交人判＝本計劃轉正閘**（無感即殺）；子集數字**以實作時 typed 索引實跑為準**（r2 修正：粗數法 38/46 與 stem 完整解析 ≈48/36 不一致，spec 不釘死易漂的數）；對象鏈口徑＝**typed 索引實跑為準**（正文 stem 連結粗數法不採——38 vs ≈48 之差即兩法之差；typed 反向來源結構上不會落在 Archive，Archive 口徑句免立）；無鏈組占比如實附註。(b) 檔名序＝日期前綴＝實質時間序，對照解讀基準如實標明。(c) MOC 排除邏輯改**合成圖單元測試**驗證（併入 `t_graph_pagerank`：程式內建假 env（沿 t_* 內建 fixture 慣例，不生外部檔）造 MOC 樞紐重圖，「排除前」對照＝同圖把 moc 節點改標 system 型別重建 env 再跑）——r2 修正：兩個實 vault 的 MOC 都只有 1 個（toolchain 亦然，r1-std 折入時「數量足」未查證即寫，r2 抓回），實圖偏置源現況本弱；排除規則仍保留（防未來 MOC 增生），但不宣稱經實圖實驗驗證。(d) 產物落點＝本計劃節點 body 對照表（不另生 csv 檔）。

## 誠實邊界

- 中心性＝連結拓撲的傷害面代理，**不是業務重要度真值**——金流節點連結少照樣重要；人挑恆壓過排序建議（sink 風險已列實務隱患）。
- 陳舊天數 log1p＝粗刻度；精算衰減等逃逸帳有樣本再調（同 [[Systems/design-loop]] d5 經濟學：先累後校準）。
- PageRank 對本圖（幾百節點）近似平滑 in-degree——選它是取「傷害面」語意與 [[Projects/檢索PPR邊權_計劃]] 共用核心，非宣稱拓撲深度優勢。
