# 歷史弱測試手冊評估_計劃

## 目的與最小試行

PRIOR-ART: 借用 SWE-bench 的修復前／後測試轉態思想（https://www.swebench.com/SWE-bench/guides/evaluation/），先驗歷史考卷本身；不是採用其資料集或總分。
RETIRE-IF: 歷史弱測試不能在錯版重現通過，或強測試不能只因目標問題翻紅並在修復版回綠，該案例退出效果分母。

本階段只建立一個歷史案例的重播入口，零新依賴，所有歷史程式於隔離暫存目錄執行；不修改真實 HOME、checkout 或全域技能。低風險本機 eval，先跑症狀診斷再固定重播，不派實作前設計席。固定 2026-09-16 鎖退路修復造成可重入回歸，錯版 2b4cb7ce22a49a07f215f2e1762b352c9e54415d、修復版 810beb93dbe4329a8ac0c340c5985d38bdff011a。

[S1] 重播應在錯版及修復版各執行原弱測試與修正強測試；有效結果至少有非零斷言、現場前置斷言真，且只有目標巢狀斷言由紅轉綠。匯入错误、程序逾時、零斷言列無效。 [manual:執行固定入口並核對四組明細]
[S2] 證據應保存完整歷史來源提交、檔案與測試片段 SHA、執行器 SHA、原始輸出和逾時調整。 [manual:核對輸出 report.json 的來源與 instrument 欄]

## 效果比較下一階段

先通過 S1/S2 才納入模型考卷：無手冊控制對正式手冊，固定模型、題目及起始程式，每臂重複，首次生成在任何故障回饋前凍結；同一測試在歷史錯版、修復版都執行，以目標斷言失敗而非程序超時算檢出。模型不看修復 patch、強測試、審查報告或故障答案，給相同正常行為規格，避免提示解法。兩臂平手如實報。這個案例驗的是明示鎖合約的內部機制，不冒充公開 CLI 端到端測試；它不是套算式同義測試，涵蓋更廣的「測試情境沒成立」。

## 模型對照預先凍結（2026-10-07）

四場固定 claude-opus-5-5、effort low，每臂兩次，順序 control/handbook、handbook/control。control 無規範，handbook 強制提供正式共用手冊〈實作測試品質〉全文；不是技能路由評估。兩臂同一 API、同一正常行為規格與歷史錯版取鎖函式片段，同一 Read-only 會談工具。來源只供 implementation.txt，不供 git 歷史、修復版、舊弱測試、強測試及故障報告。首次交付為唯一 Python fence；不提供執行器或故障回饋，不量測回饋後修訂。

採零依賴受限 unittest 語法（固定 fixture、s.lock/fallback_ready/held/external_written、有限斷言與 with），拒絕其他 import/賦值/呼叫。測試 API 同時明講可重入和搬移快取，降低選情境難度；結果只適用這種明示合約與 fixture 的受限首次生成，不外推自由開發或完整CLI。

取鎖等待兩秒時由fixture捕捉 TimeoutError，轉成具體 AssertionError: lock-enter-incomplete；同時記 entry 深度及 fallback 狀態。檢出需修復版有非零測試、非零明示斷言、全綠，錯版無 errors、有該斷言失敗且觀測到 depth>0 的 fallback 取鎖卡住。整體15秒程序逾時、語法超出支援範圍、匯入錯誤、零測試列 invalid，不当 survived，也不計改善。

先凍結控制：前後取鎖弱例 survived、真巢狀強例 detected、空測試／錯誤基準／不允許import invalid，全部一致才開始模型會談。保存每場原始事件、最終測試code及SHA、來源／手冊／執行器快照manifest和各版細項。不得因效果不佳改題目或挑重複；instrument錯誤保留舊結果並全臂一致處理。兩臂皆全抓到記平手，不立改善結論。
