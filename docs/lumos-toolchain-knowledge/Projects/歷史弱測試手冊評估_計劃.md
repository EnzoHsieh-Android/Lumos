[S1] 重播應在錯版及修復版各執行原弱測試與修正強測試；有效結果至少有非零斷言、現場前置斷言（證明被測情境真的成立的那條斷言）為真，且只有目標巢狀斷言由紅轉綠。匯入错误、程序逾時、零斷言列無效。 [manual:在完整歷史、UTF-8 語系下跑 `python3.14 governance/eval/historical_test_quality.py --out <新目錄>`，核對 report.json 四組 rows 只有 faulty/strong 的巢狀斷言紅、前置斷言皆真]
[S2] 證據應保存完整歷史來源提交、檔案與測試片段 SHA、執行器 SHA、原始輸出和逾時調整。 [manual:同一份 report.json 的 versions、historical_file_sha256、original_test_sha256、runner_sha256 與 instrument 欄；runner_sha256 只對應產生當下的入口版本，舊卷證與現行入口的差異看該卷證目錄的處置紀錄]

## 模型對照預先凍結（2026-10-07）

四場固定 claude-opus-5-5、effort low，每臂兩次，順序 control/handbook、handbook/control。control 無規範，handbook 提供正式共用手冊〈實作測試品質〉全文——入口在執行當下從技能文件切出該段（不是凍結副本），前兩批實際使用的全文存在各自 manifest；不是技能路由評估。兩臂同一 API、同一正常行為規格與歷史錯版取鎖函式片段，同一 Read-only 會談工具。來源只供 implementation.txt，不供 git 歷史、修復版、舊弱測試、強測試及故障報告。首次交付為唯一 Python fence；不提供執行器或故障回饋，不量測回饋後修訂。

採零依賴受限 unittest 語法（固定 fixture、s.lock/fallback_ready/held/external_written、有限斷言與 with），拒絕其他 import/賦值/呼叫。測試 API 同時明講可重入和搬移快取，降低選情境難度；結果只適用這種明示合約與 fixture 的受限首次生成，不外推自由開發或完整CLI。

取鎖等待兩秒時由fixture捕捉 TimeoutError，轉成具體 AssertionError: lock-enter-incomplete；同時記 entry 深度及 fallback 狀態。檢出需修復版有非零測試、非零明示斷言、全綠，錯版無 errors、有該斷言失敗且觀測到 depth>0 的 fallback 取鎖卡住。程式另要求錯版也有非零明示斷言，錯版一進巢狀就卡住，所以巢狀前沒有前置斷言的寫法會被判 invalid；這條與上句不一致，見下一批前置條件。整體15秒程序逾時、語法超出支援範圍、匯入錯誤、零測試列 invalid，不当 survived，也不計改善。

先凍結控制：前後取鎖弱例 survived、真巢狀強例 detected、空測試／錯誤基準／不允許import invalid，全部一致才開始模型會談。保存每場原始事件、最終測試code及SHA、來源／手冊／執行器快照manifest和各版細項。不得因效果不佳改題目或挑重複；instrument錯誤保留舊結果並全臂一致處理。兩臂皆全抓到記平手，不立改善結論。

## 下一批模型實驗開跑前必須完成（設計審 r1）

已完成的兩批平手結論不受下列問題推翻；但在逐項完成前，不得用這套入口跑新的模型效果實驗：

1. 手冊改讀凍結副本並在 manifest 記 handbook_sha256 與評分依賴（historical_test_quality.py、test_quality_handbook.run_model）的指紋；不再於執行期從技能文件切字串（切法遇 `###` 子標題會截斷、錨點句一改就失敗，手冊新增的連結也可能讓手冊臂讀不存在的路徑而整場 invalid）。
2. 檢出規則與上方文字一致：錯版不要求巢狀前先有斷言；補一組「巢狀前沒有前置斷言」的控制，並在兩臂重算前先固定。
3. 逾時預算隨方法數調整或改成累計卡住時間上限：現在每個卡住的巢狀方法吃 2 秒、整支 15 秒，實測 8 個方法即 invalid，會懲罰測試寫得多的一臂。
4. 手冊與案例的獨立性：三案中鎖與 Java 兩案的來源事故記在手冊所依據的筆記裡，手冊臂勝出時要能分辨學到通則還是記住線索；開跑前選定獨立於手冊來源的案例，或把這兩案只列為對照。
5. invalid 分臂報告、分母口徑事先固定；沒呼叫 Read、python fence 不只一個、讀了不可讀路徑等儀器失效分臂計數。
6. 入口的環境錯誤寫成 invalid 卷證而不是丟例外：子程序輸出用 UTF-8 解碼並以換行切行、解析失敗列 invalid；mkdir 前先檢查歷史提交與直譯器版本；逾時格保存 stdout/stderr；案例集逐案輸出 qualified 並據此列 effect_candidates，原測試 SHA、instrument、直譯器與 git 版本直接寫進 manifest。
7. 擴充點寫明：新增案例要同步 `CASES`、`load_materials()` 的 provenance、alarm 縮短與前置標籤豁免的案例判斷、`retired_effect_control`。

已知未處理的風險：錯版取鎖迴圈有 `except OSError`，SIGALRM 丟的 TimeoutError 是 OSError 子類，若剛好落在該區段會被吞掉而逾時成 invalid；60 場未遇到，機率未量化。

上方「模型對照預先凍結」那條 REVISIT 以對照完成關閉，但評分器在看過模型輸出後才補 normal fixture 與標準尾段支持（兩臂一致重算、平手結論不變）；「預先凍結」一詞只適用於修訂後的版本。
