# 檢索訊號三件（排隊中，2026-09-14 立案）

> 白話：問的是「加什麼標籤對搜尋和評測有幫助」，量完之後答案有點反直覺——**最值錢的兩件都不是新標籤**。一件是把早就有、權重很高、卻只填了一成的欄位補起來；一件是開始記「大家實際搜了什麼」。第三件才是真的新標籤。

**本篇只是材料與數字，設計還沒做。** 動手前要各自寫成條款、過設計審查迴圈。上游是 [[Projects/標籤系統盤點_調研]]。

★2026-09-14 更新：[A] 已移交 [[Projects/檢索核心重建_計劃]]；[B]、[C] 仍在排隊★。原本排在 [[Projects/標籤系統精簡_計劃]] 之後——那一輪在收掉沒人讀的東西，這三件是新增會被讀的東西，混在一起審會很難審。

## [A] 別名欄回填 ★已移交 [[Projects/檢索核心重建_計劃]] 執行（2026-09-14 Enzo 選入該輪）★

- **現況（2026-09-14 實測）**：511 篇裡有別名欄的 106 篇，其中 47 篇明寫空的，真正有值的 **59 篇（11.5%）**。
- **為什麼值得**：別名在排序裡的權重是 3.5，只輸標題的 4.0。而評測題庫裡有 41% 的題型（縮寫、同義詞、單字）正是它在解的。
- **待決定**：要不要回填舊帳（目前只有跨過某個日期的新節點會被硬擋）、回填靠人還是靠 agent 提候選、怎麼驗回填的品質不是湊數（湊數的別名比空的更糟，這句話目前只在提示訊息裡，沒有機械判準）。

## [B] 查詢紀錄與點擊回饋

- **現況**：使用帳只在兩個指令寫入，只記時間、節點、指令三個欄位。搜尋的查詢字串完全沒留。
- **要做什麼**：搜尋時把查詢字串記下來；再把「同一段時間內接著開了哪一篇」接起來，就是點擊回饋。
- **為什麼值得**：評測現在的天花板是「題目是人編的」。有了真實查詢分布，金標集才知道自己有沒有蓋到真的會被問的題。
- **待決定**：隱私與帳本體積（查詢字串會帶專案內容）、怎麼定義「接著開了」（時間窗多長）、要不要區分「開了第一名」與「開了第五名」（後者是負回饋）。

## [C] 導覽樞紐 vs 答案 的標註

- **背景**：2026-07-11 試過拿被連入數當權威度訊號，評測雙面負增益，已殺除。當時的結論是「高連結節點是導覽樞紐、不是答案」。
- **這次的主張**：**被殺的是量法，不是那個訊號**。總索引那類已經靠型別先驗降權處理掉了；漏掉的是「不是總索引、但實質是目錄」的大計劃節點。
- **待決定**：標在哪一層（新標籤家族？還是既有欄位加一個值）、誰來標、降權多少（要走消融實驗，不能憑感覺定）、以及最重要的——**先量出這類節點到底有幾篇、佔多少噪音，數字撐不起來就不做**。

## 風險與回頭條件

- **這三件都還沒設計，上面的「值得」是從數字推的，不是驗過的。** [A] 與 [C] 的效益都要走金標消融才算數；[B] 要先有資料才知道分布長什麼樣。
- REVISIT:2026-11-14 若這三件仍停在排隊狀態，回頭判是不是根本不該做；[A] 的覆蓋率數字要重量一次（節點會一直增加）。
