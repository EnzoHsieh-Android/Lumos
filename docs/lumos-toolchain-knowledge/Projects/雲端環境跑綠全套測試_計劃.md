# 雲端環境跑綠全套測試_計劃

白話:雲端工作階段裡跑推送前的全套測試,固定有 5 支紅,原因全在環境、跟改動無關,於是每次推送都只能 `--no-verify`——那會連筆記形狀、漂移、錨點這些閘一起略過。這份把環境補齊,讓推送閘照常走。

5 支的原因:
- 2 支建虛擬環境的(直譯器路徑相關):uv 放在家目錄的 python3.14 是跨目錄捷徑,從捷徑建的虛擬環境載不到標準庫。改用直譯器真實路徑就過。
- 2 支「帳寫不進去要明講」:測試用唯讀權限造寫入失敗,root 身分不受唯讀限制,現場造不出來。改成把帳檔換成同名資料夾,root 也寫不進去。
- 1 支沙箱推送:容器沒裝 rsync。

PRIOR-ART: Claude Code 雲端工作階段的 SessionStart hook 正是給「開場裝依賴」用的(官方 session-start-hook 做法),不自建;測試現場造法借檔案系統本身的限制(資料夾不能當檔案寫),不靠權限。
RETIRE-IF: 雲端容器的預設映像已內建 rsync 與非捷徑的 Python 3.14(開場腳本連續 4 週什麼都沒裝),就把開場腳本對應那段拿掉。

## 做法

1. `.claude/settings.json` 註冊 SessionStart hook,同步執行(推送前的全套測試依賴它,非同步會有先後競態)。
2. hook 只在雲端跑:缺 rsync 就用 apt 裝;用 uv 裝 Python 3.14,在家目錄另放一支只叫 python3.14 的轉呼叫小殼並加到 PATH 前面,不動系統的 python3。
3. 兩支寫入失敗測試改用共用小工具,把帳檔換成同名資料夾。

## 驗證

- 開場腳本在這台容器上實跑成功,python3.14 指到小殼、sys.executable 是真實路徑。
- 原本紅的 5 支全部改綠(建 venv 兩支、寫入失敗兩支、沙箱推送一支)。
