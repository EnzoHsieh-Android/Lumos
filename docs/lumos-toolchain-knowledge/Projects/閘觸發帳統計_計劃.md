## 新機制準入三問(Growth test)

3. **既有小修蓋得住?** 蓋得住,本案即是小修:`lumos gov` 本來就在讀這本帳,加一段統計輸出;零新子命令、零新帳檔、零新紀律。

## 設計草案(待 design-loop)

### S1 `lumos gov --stats`

**母體 = `lumos gov` 既有讀入的帳**(bypass/rot-queue/governance/canary/kill/signoff/ci)。★「七本」不是固定常數★:第 7 源 ci 帳是條件載入(`scripts/lumos:2941-2947`,專案未宣告 ci 區塊就完全不 load),故輸出首行印**本次實際載入哪幾源**,不寫死數字。

#### ★三層數字,不可互相冒充★(r1 三席一致抓到)

`cmd_gov` 的管線有三層,每層數字都不同:

| 層 | 是什麼 | 實測(全史) |
|---|---|---|
| 原始行 | 帳檔實際寫入的行數 | 20,139 |
| **去重列** | 以 (commit, 節點集, gate, kind, token) 去重後(`scripts/lumos:2950-2957`) | 8,156(governance 一本)/ 8,825(七源合流,`--full` 印出行數) |
| 呈現行 | 預設模式再過一層**呈現去噪**(同日同 gate/kind/node 折 ×N、>6 節點群收單行,`scripts/lumos:2961-3000`) | **1,026** |

**本統計一律以「去重列」計數,並併印原始行數。**
★硬規格:輸出必須明寫「本統計不等於 `gov` 預設畫面的行數——預設畫面另有一層呈現折疊」★。原草案寫「去重後的列即『人會看到幾筆』」是**錯的**(去重 8,825 vs 預設畫面 1,026,差 8.6 倍),已刪。

#### 讀到的欄位(本文用到的帳本欄位,先定義)

`cmd_gov` 把各帳檔映射成統一列,本案只用其中五個欄位:
- `gate`:哪道閘(如 `check-s`)。`kind`:該次結果,值域**由各來源自定、非封閉枚舉**;本帳實見 `warned`/`blocked`/`approved`/`passed`/`skipped`。
- `hard`:布林,`true`=硬擋、`false`=軟提醒(advisory)。`nodes`:涉及節點名清單,**可為空陣列**。
- `token`:去重鑑別子,只有 canary 來源會填(`scripts/lumos:2933`),其餘為空字串;本案除了參與去重之外不使用它。

#### 逐 gate 輸出

**八欄**:去重後筆數、原始行數、不同節點數、不同 commit 數、首見日、末見日、收斂指標、分類桶。

- **不同 commit 數**:來源 mapper 硬寫 `commit: ""` 者(canary,`scripts/lumos:2931`)→ 此欄印 `n/a(該來源不記 commit)`,★不得印成 1★。
- **收斂指標**:分母=該 gate 在窗口內出現過的不同節點數;分子=其中「末次出現日 < 窗口內最後一天」者。
  - ★**只對 advisory 類算**(`hard=false` 且 `kind=warned`)★:人為動作留痕(`approved`/`passed`/`skipped`)印 `n/a`。理由:`anchor-approve` 照字面算會拿到 0.8 的假收斂——那只是低頻人為動作,不是「問題被修好了」(r1 s2 席,實算驗證)。
  - **分母為 0 → 全欄 `n/a`、不入任何桶**。★逐 gate 逐窗口實算,不得預設「哪些 gate 結構上沒有節點」★:多個 mapper 硬寫 `nodes: []`(code-loop `scripts/lumos:13956`、canary `2931-2932`、ci `2944-2945`、bypass `2911-2912`),且 `anchor-approve` 實際有 5 列節點為空——這是**每列**的性質,不是每 gate 的性質(r1 s1+s3 席)。

#### 分類桶

- **零觸發**:該 gate 在窗口內零筆。
  ★**前置要件:必須有 gate 全集,否則這個桶產不出來**★——「逐 gate 掃出現過的值」永遠看不到零筆的 gate,而 repo 內**目前沒有任何 gate 註冊表**(實查:無 `_GATES`/`GATE_NAMES` 之類常數)。故本案**必須新增 `_KNOWN_GATES` 常數**明列所有會寫帳的 gate 名,並配一條測試釘死「`scripts/lumos` 內所有 `gov_events.append({"gate": ...})` 的字面值都在表內」——漂了機械翻紅。★這是本案唯一新增的資料結構,且它是頭號證據(五道零觸發檢查)的產生前提,不是選配★(r1 s1 席 blocker)。
  措辭必須自曝限制:「窗口內零筆——可能從未觸發,也可能是有效嚇阻或守的情境還沒發生;零觸發不等於無價值」。
- **不收斂**:**每節點平均出現次數** = ★該 gate 所有列的節點出現次數總和★ / 不同節點數,超過門檻(草案 20)即入桶。
  ★分子不是「筆數」★:一列可帶多個節點(實測 `anchor-approve` 有 2 節點列 13 筆、3 節點列 1 筆、5 節點列 1 筆),用筆數當分子算出來的不是「每節點平均」(r1 s2 席)。
  措辭同樣要自曝限制:「入此桶不等於該閘無用——低頻人為留痕也可能因基數小而落入,判讀前先看 kind」。
- **正常**:其餘。

#### 與既有旗標的互動(全部明講,不留未定義)

- **位置參數 `node` + `--stats`**:`cmd_gov` 在去重後、任何下游計算前就把列縮到單一節點(`scripts/lumos:2958-2960`)。本案**照做但強制標示**——輸出首行印「⚠ 已縮限至節點 <name>,以下統計僅為該節點視角」。★不得靜默縮限★(r1 s3 席)。
- **`--full` + `--stats`**:統計取自去重層,**不受 `--full` 影響**,兩者併用時統計輸出逐字元相同。
- **`--since`**:沿用,預設 90 天;輸出首行印實際窗口。「窗口內最後一天」指窗口內實際出現的最大日期,不是今天。要全史用 `--since 9999`。
- **輸出不變性**:不帶 `--stats` 時 `gov` 輸出**逐字元不變**(既有消費者零擾動),此為硬要求。

### 範圍刀(明確不做)

- **不刪任何閘、不降級任何警告**——本案只產資料,退場動作是人另外裁。
- **不改 doctor 判定、不改 rc、不改 `--ci` 落帳邏輯**。
- **不做自動退場**、不做門檻可設定(v1 寫死,漂了再說)。
- **不重算呈現層行數**(第三層數字只在說明中點名,不進統計欄位)。
- **不新增帳檔、不改任何帳檔格式;不帶 `--stats` 時不改 `gov` 既有輸出**(★原寫「不改 gov 既有輸出」漏了限定詞,與 S1『加一段輸出』字面矛盾,r1 s3 席★)。★原草案寫「不碰其他帳檔」是自違——`lumos gov` 本來就合流七帳,加在它讀側不可能只看一本;pre-flight 掃出,已改為上述真正做得到的界線。★

## 實務隱患

**通用三問**:
- **併發**——純唯讀(開檔逐行讀 JSONL),無寫入無鎖。與正在 append 的 `doctor --ci` 同時跑,最壞是讀到半行→該行 parse 失敗→照既有規格跳過不計,不炸。
- **效能**——冷路徑(人工回顧時才跑)。現況 20,139 行、線性掃一次,無 N² 比對;計數用字典。若帳長到百萬級再談增量,v1 不做。
- **資源**——全走 with-open 即開即關,無連線無鎖持有。

**風險類逐類答**:
- **self-governance(pitfalls 命中)**:本案★不擋任何東西★,故無「誤擋」可言,也不需要逃生口——恆 rc0、不改 doctor 判定。★但反向風險存在且更該講:本統計的輸出會被拿去主張「某道閘可以退場」,而它量的是「響過幾次」不是「有沒有用」——一道從沒響過的閘可能正是因為它有效嚇阻,或它守的情境還沒發生。★故措辭必須把「零觸發」與「無價值」切開,且本案範圍刀明訂不刪不降級。★同一風險在「不收斂」桶也成立且已有已知偽陽性★:`anchor-approve` 是人為動作留痕,平均次數會使它落入不收斂桶,但它根本不是「該收斂而沒收斂」的東西——故該桶措辭亦須自曝限制(見 S1),不可只保護零觸發桶(r1 s3 席)。
- **已排除:金流**——不碰任何金額/交易。
- **已排除:對外送出**——純本地讀檔,無網路。
- **已排除:不可逆**——唯讀,不寫任何檔。
- **已排除:認證/PII**——帳本只有 gate 名、節點名、commit sha,無個資無憑證。
- **已排除:遷移/schema 變更**——不改帳本格式,只讀既有欄位。
- **快取/狀態同步**——不做快取,每次重算;故無 staleness。
