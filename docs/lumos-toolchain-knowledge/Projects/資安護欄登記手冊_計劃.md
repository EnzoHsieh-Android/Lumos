# 資安護欄登記手冊_計劃

白話：資安這條線的推送閘只判「登記了的護欄」，但守則和 skill 首頁一個「資安」字都沒有，登記格式與證據格式只寫在工具鏈自己的計劃筆記裡、消費專案讀不到——AI 不會主動登記，就算想登記也不知道怎麼寫，整條線等於沒開。這份計劃補三個入口（注入 CLAUDE.md／AGENTS.md 的守則範本、skill 首頁、指令索引的子檔表）與一份手冊，範例取自 order-demo 實際判過合格的護欄。

PRIOR-ART: 最小解在文件層（入口一行加一份手冊），不改閘門判定；借用既有的 skill 子檔與守則查詢表格式，不自建新的提示機制。
RETIRE-IF: 工具能從程式碼自動產生護欄登記與證據圍欄（不再需要人照手冊手寫），或連續兩季消費專案照手冊登記仍判 registration_error 的比例高過三成（手冊沒用，要換做法）。

## 背景

- 2026-10-21 使用者問「資安這條會不會自動調用、手冊有沒有指引」，查證結果：推送閘、高風險代碼審的資安席、規格閘的資安提醒會自動跑，但全部以「專案已登記護欄」為前提；登記本身沒有任何入口叫 AI 去做。
- 使用者 2026-10-21 選「要，照正常流程做」，再裁「做完整」：補觸發條件、寫手冊、拿 order-demo 實跑。

- [S2] 當手冊的範例圍欄原樣貼進功能筆記時,`security list` 應零登記錯誤並把護欄列為候選 [test:t_secguide_example_registers]
- [S3] skill 首頁的「動手前」應有一行講觸發情境並指到手冊 [test:t_secguide_skill_home]
- [S4] 指令索引的子檔表應列出手冊,並講到觸發情境與人審簽章 [test:t_secguide_index]
- [S5] README 資安段應講明先登記才會判,提問那句應寫成要 AI 照守則叫 [manual:讀 README.md 與 README.en.md 資安段前兩條,對照 Systems/安全證據閘 的預檢規則]

## 回退

- 整份回退：刪掉手冊檔、守則範本與兩份產出的那一列、skill 首頁那一行、索引兩列、README 兩條，還原「九個子檔」字樣；兩支測試一起刪。不動任何閘門判定，回退不影響已登記的專案。
