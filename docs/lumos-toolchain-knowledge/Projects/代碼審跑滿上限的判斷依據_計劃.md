# 代碼審跑滿上限的判斷依據_計劃

PRIOR-ART: 不自建停止理論,借三處:VRR-Stop(Wu 等,arXiv 2607.17641v1)的「停不停看再修一輪的預期邊際收益、修正會改壞對的東西」;Cloudflare AI 代碼審的「增量重審帶上次處理狀態」;Google eng-practices 的「大改動拆小、談不攏往上找人裁」。機制層面沿用既有的 `loop next`(已有 cap-reached 狀態)、既有帳本欄位與凍結審材、既有 quote-check 的引句定位,不加新依賴。
RETIRE-IF: ①上線後連續 8 週,跑滿時印出的建議被人推翻的次數多過採納(建議沒在幫人判斷);或 ②三個月內零次跑滿(問題自己消失了,這段輸出只是負擔)。

## 一句話

跑滿上限時,工具不只說「停下交給人」,而是先把三個數字算好、依數字給一個建議(再一輪/換做法/附理由放行),讓人裁的時候有依據。**只提醒,不擋。**

## 為什麼不是把上限拉高

研究和我們自己的帳都指向同一件事:卡住的時候再多跑幾輪通常換不到東西,還可能把對的改壞。上面摘要的三個例子,多跑的輪次裡折入數沒有往下走。問題不在上限太低,在人裁的時候看不到「還有沒有進展」。

## 做法

### 三個訊號(都從既有的帳和凍結審材算,不問模型)

1. **折入走勢**:每一輪折入幾條(帳本的折入清單,整輪各席加總)。判成「下降」(最後一輪少於前一輪,且少於第一輪的一半)/「持平或上升」。
2. **修正引起的比例**:最後一輪的每條發現,拿它的第一句引句去最後一輪的凍結審材定位(沿用 quote-check 的比對);定位到的那行是新增行,而且這行不在上一輪凍結審材的任何地方 → 算「上一輪修正引起的」。印成「幾條裡有幾條」。
3. **同類重複**:記帳新增選填旗標 `--finding-class <id>=<短名>`(編排者填,例如「靜默回空」「守衛假綠」);同一個短名連續兩輪出現就算重複。沒填就印「沒填類別,判不了」,不猜。

### 建議怎麼給(固定規則,不問模型)

依序套,第一個成立的就是建議:

- 修正引起的超過最後一輪的一半,或同類重複 → **換做法**:拆小改動、回頭改設計、或整類拿掉(對應「再修換不到東西」)。
- 走勢持平或上升 → **換做法**:改動可能太大或設計有洞,建議拆。
- 走勢下降,且最後一輪只剩 minor → **附理由放行**。
- 走勢下降 → **再一輪有意義**。

門檻(一半、第一輪的一半)是起點,回測後再調;調了要改測試。

### 印在哪裡

- `loop next` 回 cap-reached 時,在「停下來交給人」底下印三個數字與建議。
- `loop status --disposal`(每一輪都會跑)在輪數已達上限時也印同一段——因為帳顯示編排者跑滿後常直接記下一輪,沒再問 `loop next`。
- 只印不擋,也不改任何閘的判定。

## 條款

- [S1] 當代碼審迴圈的輪數達到該分級上限且閘未過,`loop next` 的輸出應在交給人的那句底下列出每輪折入數、修正引起的條數與同類重複狀態,並給出一個建議 [test:t_loop_cap_report_lists_signals]
- [S2] 若最後一輪有超過一半的發現落在上一輪凍結審材沒有的新增行,則建議應是換做法而不是再一輪 [test:t_loop_cap_report_fold_induced_suggests_reshape]
- [S3] 若每輪折入數持平或上升,則建議應是換做法 [test:t_loop_cap_report_flat_trend_suggests_reshape]
- [S4] 當走勢下降且最後一輪只剩 minor,建議應是附理由放行;走勢下降但仍有 major,建議應是再一輪 [test:t_loop_cap_report_declining_trend]
- [S5] 若沒有任何一輪填了問題類別,則同類重複一項應印「判不了」而不是「沒有重複」 [test:t_loop_cap_report_no_class_is_unknown]
- [S6] 當輪數已達上限,`loop status --disposal` 應印出與 S1 相同的一段,且不改變原本的過關判定與退出碼 [test:t_disposal_prints_cap_report_without_changing_verdict]
- [S7] 若某條發現的引句在凍結審材裡定位不到,則它應被算成「判不了」並另列條數,不得算進修正引起或非修正引起 [test:t_loop_cap_report_unanchored_quote_counted_separately]

## 回退

全部是新增的輸出段落與一個選填記帳旗標,不動任何閘的判定。回退=拔掉 `loop next` 與 `loop status --disposal` 裡呼叫報告函式的那兩處;選填旗標留著無害(舊帳沒有這欄,讀的地方都當沒填)。

## 誠實界線

- 「修正引起」靠引句定位加「上一輪審材沒有這行」判斷;新寫的行剛好跟上一輪審材某行一字不差會漏算,引句錨不到的另列不猜。
- 同類重複靠編排者自己填短名,沒填就沒有這個訊號;這一項不自動化,因為問題類別要判斷,硬用關鍵字分群會製造假重複。
- 建議規則的門檻是從外部研究與三個歷史例子推的起點,沒有經過回測;回測排在 REVISIT。
- 帳裡看得到「跑滿後常直接記下一輪」,這份計劃只讓資訊出現在那時一定會看的地方,**不擋第四輪**;要不要擋是另一個決定。
