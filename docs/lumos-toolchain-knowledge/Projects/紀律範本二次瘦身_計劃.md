# 紀律範本二次瘦身_計劃

> 白話:每個專案的 CLAUDE.md / AGENTS.md 裡都有一段工具鏈紀律,每一回合都會被帶進對話。它 7 月瘦過一次,之後二十天又長回五成六。這次照同一個做法再整理一次:規則一條不刪,只把寫在規則旁邊的日期、實測數字、誰裁的這些來歷,搬到本來就在講那件事的筆記裡。

PRIOR-ART: ①最小解層級=改範本文字,不動注入機制 ②做法照 [[Projects/上下文瘦身_計劃]](07-29,依 Anthropic 官方 context engineering 指南)與 [[Projects/skills提示工程優化_調研]](09-11:外部研究說規則檔讓成本多兩成以上、大小對遵守率量不到影響;範本裡歷史敘事約占兩成)③自建=0,沒有新依賴

## 做了什麼

- 拿掉:4 處日期戳(「2026-08-11 在一個導入專案上實測出來的三條」「2026-08-22 Enzo 裁」「2026-08-31 全圖盤點 52 件實證」「2026-09-10 人裁」)、實測數字(「某導入專案實測 8 句有 3 句 0 筆」「一天內六次判斷失準…其中四次…」「一天 31 次太多…」)、第四條那段的長篇起因。
- 規則保留、理由縮成一句:第四條併進「查得到才算先行」成為第④條,留「丟結論它會順著你講」「判斷錯本來就要重查一次,這一步只是提前付」「只有這個場合要派,其他查詢照常」;鐵則三留「全套跑在對話裡會超時」;鐵則四留「純散文的回頭條件沒人會回頭」。
- 改寫一列:中文查詢那列改成跟工具自己的提示同一個說法(黏成一串沒有「各詞」可退),09-11 實測黏成一串仍是 0 筆,規則本身還對。
- 拆一個標題:原本「給人看的回報用白話」底下混了設計先問世界與診斷先行兩條,拆成「設計與排查」,文字不變。
- 代碼審提交那條縮成一句並指路 lumos-code-loop(細節本來就在 skill 步驟 8)。
- 搬家去處:「六次判斷失準」那段 → [[Verification/2026-08-22_缺席推論探針題組]];「8 句有 3 句」與 09-11 重驗 → [[Projects/中文無空白查詢回退_計劃]];三條查詢體悟的來歷原本就在 [[Systems/lumos-cli-read]] 決策 d5;52 件在 [[Projects/回訪掃描_計劃]];提交規範的人裁在 [[Projects/提交推送規範_計劃]]。
- 兩個乾淨 agent 各自獨立比對新舊兩版(卷證 `governance/review-reports/紀律範本二次瘦身/`):逐條那席拆出約 63 條規則,49 條逐字保留、6 條同義改寫、2 條搬走、6 條有問題(2 條重大);情境推演那席推了 12 個情境,1 條重大、3 條小(其中 1 條它自己判行為不變)。兩席重疊 3 條——都指到接手那列掉了「逐字稿尾端」與「不判進度、逐字稿缺就明說」。6 條全部補回原文(另 1 條行為不變、不用改),補完 7381 bytes。
- 本 repo 的 CLAUDE.md、AGENTS.md 用 `lumos update`(來源 repo 只刷新紀律區塊)重新注入,區塊外的內容逐字不變(已比對)。
