# 行內忽略註解要留紀錄_計劃

> 白話:新加一行讓檢查工具略過的註解(例如 `// ast-grep-ignore`、`# noqa`、`@Suppress("MagicNumber")`),目前可以不留紀錄地繞過新增告警閘。要讓它跟新增告警一樣,得寫理由放行、留下紀錄。從 [[Projects/簡報審查抓到的機制缺口_計劃]] 移出:那份計劃的設計審連兩輪在這一件上被打穿,這裡重新設計。

PRIOR-ART: 社群 linter 自己就有「忽略註解本身也是告警」的規則:ESLint 社群規則 require-description、no-use;detekt 的 ForbiddenSuppress;ruff 的 PGH004(blanket noqa)與 RUF100(沒用到的 noqa);SonarQube 追蹤 NOSONAR(https://docs.sonarsource.com/sonarqube-server/quality-standards-administration/managing-quality-gates/tracking-inline-comments)。首選方向:在 [[Systems/linter精選目錄]] 的標準設定裡開這些規則,讓新增告警閘照既有流程擋,跟 [[Systems/pitfalls-lint-adapter]] 的「lumos 不內建棧規則、規則庫讓給社群 linter」一致;Lumos 自己的 ast-grep 規則包另寫一條抓 `ast-grep-ignore` 的規則。對照方向:lumos 自建各工具的忽略寫法對照表(r1、r2 的設計,被指出跟既有決策相反)。
RETIRE-IF: 放行紀錄裡忽略註解那類的筆數,人工抽查後誤報多過真的忽略 → 收回那幾條規則,改回只在審查時看。

## 依據來源

| 機制 | 依據 | 出處 |
|---|---|---|
| 用 linter 自己的規則抓籠統的忽略註解 | ruff PGH004 檢查不指定規則、整行全略過的 noqa | https://docs.astral.sh/ruff/rules/blanket-noqa/ |
| Kotlin 端抓不准略過的 @Suppress | detekt style 規則組的 ForbiddenSuppress:回報被禁止略過的規則被 suppress | https://detekt.dev/docs/rules/style/ |
| 忽略註解要被追蹤、留紀錄 | SonarQube 追蹤行內 NOSONAR 註解 | https://docs.sonarsource.com/sonarqube-server/quality-standards-administration/managing-quality-gates/tracking-inline-comments |
| 不自建各工具的忽略寫法對照表 | lumos 不內建棧規則、規則庫讓給社群 linter 的既有決策 | [[Systems/pitfalls-lint-adapter]] |

## 審查帶過來的問題

設計輸入,原文在 `governance/review-reports/簡報審查抓到的機制缺口/` 的 r1、r2 席報告;括號裡的 c、b、i、a 編號是 `r1-intake.md`、`r2-intake.md` 收貨時編的流水號(c 正確性、b 邊界、i 整合、a 架構對齊),對照與原文出處在那兩份收貨紀錄的判讀表:

- 跟既有決策相反:lumos 不內建棧規則(r2 i5)。
- 認工具:整串正規式是第二套做法,版本釘選、包裝詞、套件執行器都會認不到(r1 a1、b9;r2 c3、b7、i9、a2)。
- 寫法涵蓋:noqa 不分大小寫、ruff: disable 等、mypy/bandit/biome/ktlint/sqlfluff/PMD/Checkstyle(r1 b7、i10、c6;r2 c6、b8)。
- Kotlin @Suppress:多行寫法的指紋會撞、編譯器警告名與小寫名的判法(r1 i11;r2 b6、c5)。
- 掛點:要只在推送範圍模式、不漏進回合結束鉤子的工作樹模式(r1 i5;r2 a5)。
- 放行口徑:同檔一模一樣的一行只要放行一次,另見 [[Issues/放行綁指紋同檔複製貼上的同一行不再擋]](r1 i4)。
- 訊息與統計:放行指令要帶 --rule,否則按規則統計會少算(r2 c11、i10)。
