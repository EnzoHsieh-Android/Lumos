# 原生代碼審當通才席_計劃

> 白話:高風險代碼審裡「鏡頭5」那一席原本是自家派的同門通才。這篇讓它改照 Claude Code 官方 `/code-review` 的審法看——八個角度依序找(逐行、被刪掉的行為、跨檔追蹤、重用、簡化、效率、修的深度、慣例)——但仍用 Lumos 自己的子代理跑,引句、嚴重度、翻紅重現、唯讀隔離、收貨記帳全照既有規則。

PRIOR-ART: 世界解總覽〈委派與照留地圖〉建議把代碼審「找問題」那段委派一部分給原生 `/code-review` 當額外一席([[Projects/世界解重新註解2026-10_總覽_調研]])。審法取自 Claude Code 2.1.299 本機版 `/code-review` 在 high 強度派給子代理的派工詞(2026-10-14 實驗讀到),改寫成中文放進 `skills/lumos-design-loop/templates.md` §7.9;派工、引句、嚴重度與隔離沿用同檔 §0、§3 既有規則,不另立。

RETIRE-IF: 上線後累計 10 個高風險代碼審迴圈,鏡頭5 通才席「存活且折入的 major」少於同輪其他四個找問題席平均的一半,就把鏡頭5 改回原本的無鏡頭通才。

## 決策紀錄(為什麼不直接接官方工具)

- 第一版設計是在獨立複本無頭跑官方 `/code-review`,再用轉換指令把結果變成席報告。設計審 r1 四席獨立指出三類根因:無頭會談不受審查席唯讀外掛管、全部放行只封三個指令前綴、複本會載入被審材料裡的設定與掛鉤;轉換器自己挑引句、另一個模型補等級,等於第二套引句與等級規則;原文照抄可注入假的等級行。另外 `/code-review` 不帶強度時沿用使用者上次打的強度,可能誤觸另外計費的 ultra。
- 每一條都修得掉,但補的東西多半是在重做子代理本來就有的保護。使用者 2026-10-14 裁定改成「審法寫進通才席」:失去的是官方更新時自動跟上,用回頭條件定期比對補。

## 範圍

- 這篇:高風險代碼審鏡頭5 的派工鏡頭改成八角度審法(範本 §7.9)、編制備註指過去、代碼審手冊第 2 步寫明。
- 不做:設計審(八角度審的是程式改動)、standard 單席與 light(單席照舊無鏡頭通才)、把官方工具接進來跑(見上)。

## 做法

- 範本新增 §7.9〈通才鏡頭〉:一段取代 §3「審查鏡頭」第 4 點「本案特定鏡頭」的文字(圖譜鏡頭照留,五問與角色卡照 §7 只留給正確性席),八個角度依序找、每個角度最多 6 個候選、收齊再去重、最多報 10 條,會出錯的排在清理類前面,講得出具體失敗情境的就列、給不出的不列(§3 抑噪),純風格與一致性歸架構對齊席,改動裡的 CLAUDE.md 當被審資料;嚴重度與翻紅重現照 §3,不另寫一套。§7.7 立場表加通才一列。
- 編制 `_TIER_ROSTER` 的 `("code", "high")` 鏡頭5 備註加上「通才照 Claude Code /code-review 八角度審法(templates.md §7.9)」,席名照舊 `通才-<模型>`。
- 代碼審手冊第 2 步寫明鏡頭5 用 §7.9。

## 驗收條款

- [S1] 當讀高風險代碼審編制時,鏡頭5 應 仍是算人數的同門席,備註 應 指到八角度審法與範本 §7.9;範本 §7.9 貼進派工詞的那段 應 剛好八個角度、寫明嚴重度與翻紅重現照 §3、給不出失敗情境不列、最多 10 條、取代第 4 點而保留圖譜鏡頭,目錄與 §7.7 立場表 應 有通才鏡頭 [test:t_templates_generalist_lens_section]
- [S2] 當派高風險代碼審時,鏡頭5 的派工詞 應 用 §3 整份、只把「審查鏡頭」第 4 點換成 §7.9 那段,圖譜鏡頭照留、五問與角色卡留給正確性席 [manual:讀下一個高風險代碼審迴圈的派工單與鏡頭5 席報告,確認第 4 點是 §7.9、`LUMOS-IMPACT` 行還在、報告格式照 §3]

## 回退

- 刪掉範本 §7.9、把鏡頭5 備註與手冊那一行還原;S1 的測試綁定一併拿掉。
