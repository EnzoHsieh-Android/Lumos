# 端到端驗收對照表涵蓋報告_計劃

白話:Android 端到端驗收的功能對照表(`.lumos/macrobench.json` 的 `e2e.features`)寫得夠不夠,現在只有推送那一刻才知道:改到一支沒歸屬的檔,推送前檢查就要求整套跑。這份計劃加一個只讀的報告 `lumos android-e2e coverage`,事先列出對照表的三種缺口:沒歸屬的程式檔、沒有會判情境的功能、沒人用的驗收素材。只報告、不擋。2026-10-27 Enzo 照「只報告、預設按目錄分組」的方向開工。

PRIOR-ART: 最小解在既有的 `lumos android-e2e` 子指令底下多一個只讀報告;世界解過:測試涵蓋率工具(coverage.py、JaCoCo)報「哪些程式沒被測試碰到」,Nx 的 `project.json` 沒歸屬到專案的檔會在 `nx graph` 裡顯示成孤兒;借用「按目錄彙總、加旗標才逐檔」的報法(coverage.py 的 `--skip-covered`、JaCoCo 按套件彙總)。範圍判斷與逐檔歸屬沿用推送前判定的 `_e2e_scope_hit` 與 `_e2e_file_owner`(推送前判定的 `_e2e_gate_owners` 也呼叫它)([[Projects/Android端到端驗收_計劃]]〈推送前怎麼按功能判〉),不另寫一套;整棵樹逐檔查歸屬時先用 `_e2e_owner_ctx` 建一次索引(跟推送前判定同一支),不每支檔重新正規化對照表;讀不到設定的擋下訊息走共用的 `_say_block`(推送前判定那邊定的單一出口,有靜態守衛測試)。自建只有報告本身。
RETIRE-IF: 上線三個月後,兩個真實專案的治理帳裡推送前判定因「對不到任何功能」要求整套跑的次數是 0、而且使用者沒提過這個報告,就把這個子指令與 doctor 那一行撤掉。

## 報告列什麼

1. 沒歸屬的程式檔:工作目錄已追蹤的檔裡(`git ls-files`;設定也讀工作目錄,補完對照表不用先提交),指紋範圍內(`_e2e_scope_hit` 判在範圍)、不在任何功能的 `paths` 底下、也不在 `shared_paths` 底下的檔。驗收素材(`.maestro/`、門檻檔、`flows` 列的檔)不算程式檔,不列在這一項。預設按資料夾彙總:每個有沒歸屬檔的資料夾一行「資料夾、幾支沒歸屬、這個資料夾共幾支」,資料夾是檔案所在的那一層(取 `app_dirs` 底下第一層的話,通常整個 `app/src` 只剩一列,看不出缺在哪);加 `--files` 才逐檔列。落在 `shared_paths` 底下的另印一行「共用程式幾支」:推送前判定對它們一樣要求整套跑,所以程式檔裡「沒歸屬」加「共用程式」正好是推送前會要求整套跑的那批;驗收素材不列,但改到沒被任何情境列到的素材(例如重錄的基準圖、門檻檔),推送前判定照樣要求整套跑。
2. 沒有會判情境的功能:功能底下每個情境都只列了效能(推送前按功能判時這種情境不用驗,等於這個功能沒驗)。
3. 沒人用的驗收素材:`e2e.flows` 裡沒有任何情境列到的流程檔、`e2e.visual` 裡沒有任何情境列到的截圖畫面。整套跑照樣跑它們,但按功能跑永遠不會跑到。

- `--changed`:第 1 項只看這次改到的檔(改到的檔清單照 `--changed` 挑功能那一套,`_e2e_changed_files`),開發中就知道改到的程式檔推送時會不會因為「對不到任何功能」被要求整套跑(驗收素材不在這一項,見第 1 項);第 2、3 項照常列。
- `--json`:印成 JSON(三項各一個清單),給 AI 讀。
- 回傳碼:報告印得出來就回 0,不論有沒有缺口;設定讀不懂、`e2e` 段不合格、沒有 `features` 回 2 並說原因。

## 還有哪裡看得到

- `lumos doctor` 的 AE 段(還沒人看過的 AI 放行那一段)多一行「功能對照表有 N 支程式檔沒歸屬、M 個功能沒有會判的情境、K 份驗收素材沒人用;看:lumos android-e2e coverage」,三個數字都是 0 就不印;看的是工作目錄(跟報告本身同一份),算不出來就不印。
- skill lumos-android-evidence〈新增功能或使用情境時一起補〉那段加一句:補完對照表跑一次 `lumos android-e2e coverage --changed`。

## 不做

- 不擋推送、不擋提交:缺歸屬的後果推送前檢查已經會擋(要求整套跑)。
- 不推功能歸屬(不從程式的 import 或目錄名猜哪支檔屬於哪個功能):猜錯比列出來更糟,歸屬由人寫進對照表。
- 不看程式內容判斷「這支檔重不重要」:只看路徑。

## 條款

- [S1] 當功能對照表有程式檔不在任何功能的 `paths`、也不在 `shared_paths` 底下時,`lumos android-e2e coverage` 應按目錄彙總列出(目錄、沒歸屬幾支、共幾支),加 `--files` 時逐檔列;單元測試檔(預設排除)、驗收素材、指紋範圍外的檔不列;回 0 [test:t_android_e2e_coverage_unowned]
- [S2] 當一個功能每個情境都只列了效能時,報告應把它列成沒有會判情境的功能;`e2e.flows` 或 `e2e.visual` 有沒被任何情境列到的項目時,應列成沒人用的驗收素材 [test:t_android_e2e_coverage_cases_and_materials]
- [S3] 當帶 `--changed` 時,第 1 項應只看這次改到的檔(跟 `--changed` 挑功能同一份改動清單),第 2、3 項照常;帶 `--json` 時三項各印成一個清單 [test:t_android_e2e_coverage_changed_json]
- [S4] 當設定讀不懂、`e2e` 段不合格或沒有 `features` 時,報告應回 2 並說原因 [test:t_android_e2e_coverage_bad_config]
- [S5] 當工作目錄的功能對照表有缺口時,`lumos doctor` 的 AE 段應多印一行三個數字與看的指令;三個數字都是 0、或算超過 10 秒時不印 [test:t_android_e2e_coverage_doctor_line]
- [S6] 當在 macrobench-lab 上新增一支不在任何功能的程式檔時,`lumos android-e2e coverage --changed` 應列出它,補進對照表後再跑應不再列 [manual:實驗室副本上加一支檔跑一次、補對照表再跑一次,兩次輸出貼進驗證紀錄]
