# Flutter 補棧_計劃

> 白話：讓這套工具鏈多認得一種語言。Dart 原本只有「掃得到測試」那一格，其他三格是空的——改 Dart 的檔不會被問任何效能問題，審查員也拿不到 Dart 的寫碼慣例。這篇記這次補了哪三格、題目為什麼是這六題、以及哪些話現在還沒有證據。

## 八格盤點（2026-09-13，用程式逐格確認，不是憑印象）

| 格子 | 補之前 | 補之後 |
|---|---|---|
| 程式碼副檔名清單 | ✅ 本來就有 | 不動 |
| 符號形狀 | ❌ 沒有任何 profile 認領 `.dart` | ✅ 新開一個 |
| 測試綁定 | ✅ 本來就有（`test('名')`／`testWidgets('名')`） | 不動 |
| 骨架測試指令 | ✅ 本來就有 | 不動 |
| 效能追問題組 | ❌ 完全沒有 | ✅ 六題 |
| 副檔名→慣例 skill | ❌ 沒有 | ✅ 指到新寫的那份 |
| 慣例 skill 本體 | ❌ 沒有 | ✅ 新寫 |
| 兩份目錄 | linter 目錄有、效能目錄沒有 | ✅ 效能目錄補上 |

**符號形狀那格不能借隔壁**：型別 PascalCase、方法 camelCase，看起來跟 Kotlin 一樣，但 **Flutter 的 State 類幾乎都是底線開頭的私有類別**（`_HomePageState`）。借 Kotlin 那條 `^[A-Z]` 會讓筆記裡最常被點名的那種類別一律判成「查無」。所以只多開一個可選的前置底線，其餘照舊。這正是那份 SOP 說「方法正則不要照抄隔壁語言」的同一類陷阱，只是換到符號那一格。

## 題目怎麼選

### d1：題組偏哪個方向

- **決定**：兩邊都顧，用觸發字分流。
- **誰裁的**：Enzo，2026-09-13。
- **為什麼**：Flutter 專案裡畫面碼與純 Dart 碼混在同一個 repo 很常見，只顧一邊會讓另一半完全問不到。
- **替代方案為什麼沒選**：偏畫面會讓純 Dart 的套件與後端拿不到任何題；偏非同步會漏掉這個棧最貴的那類問題（組建成本與長清單）。
- **為什麼不需要新機制**：觸發本來就是條件式的——題目只在改動行出現對應詞彙時才適用。跟 Java 那次同一個裁決、同一個理由。

### 六題與它們的分工

| id | 常駐還是畫面特有 | 治什麼 |
|---|---|---|
| `dart-build` | 畫面特有 | 組建函式裡做重活、重建範圍太寬 |
| `dart-list` | 畫面特有 | 長清單一次全建、key 不穩、圖片沒降解析度 |
| `dart-dispose` | 常駐 | 訂閱與各種 controller 沒釋放、await 回來對著拆掉的畫面操作 |
| `dart-async` | 常駐 | 外呼沒逾時、Future 錯誤無聲蒸發、迴圈裡逐筆等 |
| `dart-isolate` | 常駐 | 重活留在主 isolate（**這個棧特有**：Dart 單執行緒，主 isolate 被佔住畫面完全不更新） |
| `dart-platform` | 常駐 | 平台通道沒逾時、本機資源同步讀寫 |

**反面詞**：`dart-async` 特別收了 `.then(`／`.whenComplete(`／`Future.delayed`——不用 async/await、改寫成 then 鏈做同一件事的舊碼要亮同一題，而維護舊碼正是最需要被問的時候。

## 這次跟前三次補棧不一樣的地方

**慣例 skill 的機檢欄是真的驗過的**。前兩次（Python 是逐條跑過、Java 整份標「未實跑」）之間差很多；這次本機裝了 Dart SDK，把要引用的 18 個 lint 規則代號寫進設定檔跑一次，**另外混進一個故意不存在的名字當對照組**——只有那一個被分析器判為不認得，其餘 18 個全部被承認。這證明的是「規則名存在」，**不是**「這條規則抓得到我描述的壞例」。

## 誠實邊界
