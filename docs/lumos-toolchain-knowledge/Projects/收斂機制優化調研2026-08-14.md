# 收斂機制優化調研2026-08-14

Enzo 指派:搜「多席不同鏡頭、多輪 K=2 收斂機制」還有什麼可優化。方法=網搜業界/學界現況,對照同日立案的內部實跑痛點帳。

## 外部證據來源

- 相關性瓶頸:arXiv 2605.29800(Nine Judges, Two Effective Votes,Apple)——9 席 7 家族 panel ≈ 2 票有效資訊;最強單席打平或勝全 panel;聚合演算法最多追回 11% 缺口。
- 停損寫法:多判準停損(穩定窗 w=2+信心門檻+實質/表面語意區分,三取二)、業界慣例「綠燈或邊際遞減(nitpick-only 即停)、cap 2-3 防無限迴圈」。
- 收斂模式整理:Code as Agent Harness(arXiv 2605.18747)六型收斂,test-gated 最有原則——可執行 substrate 錨行為訊號非對話共識。
- capture-recapture 天花板:軟體審查文獻(Wohlin 1995 起 10+ 年線)——前提違反→系統性低估殘餘;缺陷捕獲率異質需大量審查者才穩。
- 穩健聚合:RoPoLL(arXiv 2606.30931)——看過,不推(見 summary)。

### 新證據一:總體獨立性指標會蓋掉條件效應(直接修正候選①的算法)

arXiv 2608.06940「Blind to the Pivotal Vote」——**打的正是本調研引為核心依據的
effective-votes 那套度量**(2605.29800)。論點:總體平均遮蔽條件效應,
**「總體相依」與「條件決策效用」是兩個問題**。

實測(HumanEval+/MBPP+,k=7):換一席帶來的準確率增益 **+11.2 個百分點全部集中在
「一票之差」的題(佔 16.2%)**,其餘題目的增益是 **0.0000**。

**★對候選①的直接修正★**:原設計是算「某鏡頭從未獨自抓到過東西 = 白付的席」。
但一面倒的輪次本來就不需要多一席,**把那些輪次算進去會系統性低估好席**——
砍錯席比不砍更糟。正確做法:**只在「勢均力敵」的輪次上算獨佔貢獻**
(我們的對應物 = 席間 severity 分歧輪 / 單席獨有輪,`capture_counts` 與辯方路由帳都記得到)。

**挑席指標也要換**:該篇實證判準確率會被基率騙(該資料集 80.4% 基率),
建議改用 MCC(對基率穩健):與拒絕率 r=−0.85、跨測試集與 panel 準確率 r=0.86。
席間差距實例:準確率 58.5%~87.2%、MCC 0.253~0.541。

### 新證據二:結構化異議(對照後我們多數已有,只有一項可抄)

arXiv 2608.18167「Adversarial Review」——三 agent(主/審查員/批評者)、雙層迴圈、
上限五輪。對照本專案:

| 它的做法 | 我們 |
|---|---|
| 審查期間 artifact 凍結,評審穩定才准改 | ★已有且更嚴★ quote-check 明訂比對派工凍結快照,理由寫在 skill:「用現檔的話折入後引句會自我成真」 |
| 要求證據為基礎的異議 | ★已有且更嚴★ 每條 finding 附逐字引句 ≥10 字 + `refcheck` 機驗 file:line 存在 |
| 批評者判決分三類(AGREE / DISAGREE_EVIDENCE / DISAGREE_CONCERN) | **只有二元(真/假)** ← 唯一可抄點 |
| 三 agent 全跑 | ★我們更省★ 路由制:機械證實免辯方,只有低共識才派 |
| — | ★我們多一層★ 辯方預設外家(不同家族),打同門盲點 |

它報告的最大失敗模式=**false consensus(為了同意而同意)**:批評者被弱反駁說服就讓步。
三分類是它的修法,F1 0.457 → 0.533。

**★裁定:三分類先不做★**——它是從 naive 起點修上來的,我們起點有引句錨定 + 行號機驗 +
外家反證三層,**同樣的增益吃不吃得到估不出來**,而它要改的是派工範本(散文層,
[[Systems/design-loop]] 對散文層收斂差)。**重啟條件:出現一次「辯方被弱反駁說服、
事後證明該 finding 是真的」的實例。**

> **★2026-08-27 補:重啟條件的偵測儀器已建,裁定本身不動★**——當日治理日報又把同篇論文(0.457→0.533)當新發現端上、未對決策帳;Enzo 裁走中間路。〈誠實界線〉自承「帳裡只有 caught/severity/處置、沒有逐席對錯標註」→ 上面那條重啟條件原本**根本偵測不到**。已補 `canary record --refute-verdict <id>=agree|evidence|concern`(辯方三態進帳,**純記帳、不改降級規則**,見 [[Systems/finding-refute]] d4 與 [[Verification/2026-08-27_辯方表態記帳]]):evidence(降級)那批就是重啟條件的候選池,累積 ≥10 筆或每季巡檢時回頭抽驗「降錯、後來證明是真的」。**三分類判閘仍不做**;抽出一例才走正式翻案。

> **★2026-09-01 三度重現+新外證(裁定不動)★**——世界治理掃描(governance/reports/world-governance-scan-2026-09-01.md)又把同一篇論文當新發現推薦開案,被 Enzo 一句「辯方不是改過了嗎」擋下才查帳:這是 08-14 原案、08-27 日報之後**第三次**;三次全走「查世界→推薦」路徑、全沒過決策帳,破口同型(進場紀律破口①變體),季檢(REVISIT 11-30)時把「重複端案次數」一併看。順手補兩筆當時沒有的外證,**都支持既有裁定、不觸發重啟條件**:①arXiv 2604.19049「Refute-or-Promote」實測單發反駁 vs 互辯省 30-40% 成本、vs 多席投票 precision 高 40-50%——背書我們路由制+禁互辯的經濟性;②現實假陽性災情:curl 關 bug bounty、HackerOne 暫停 IBB(2026-03),LLM 假陽性報告被維護者稱為 DoS——背書辯方殺假陽性層的必要性。

### 誠實界線

- 兩篇新證據**只讀到論文正文層,未做同構實測**。「+11.2pp 集中在 16.2% pivotal」是它的
