# 受波及合約測試真跑閘_計劃

> 白話:改到相依功能時,工具現在只會「點名」那些功能綁的測試,跑不跑靠編排者自律。Enzo 2026-08-22 裁:被點名的要當場跑完才能往下——把它做成閘:`lumos code-loop pass` 留痕前,先把波及節點上綁的合約測試真跑一遍,一條紅就拒絕留痕(pre-push 與 CI 認留痕,所以等於推不上去)。

## 需求(r1 折入後)
1. **掛在擋的路徑上,不是記錄的路徑**:`lumos code-loop check`(pre-push 每次推送都呼叫,不分 tier)在判定 tier/留痕之前,先算 `impact --diff <range> --sync-check` 的固定席,收集這些節點 ★INVARIANT★ 行上的 `[test:…]`,用 `resolve_test_refs` 解平台前綴,逐 `(platform, method)` 真跑;任一紅/超時/方法名不合法/測試名不存在於該平台真測試集合 → check 回 BLOCKED(rc1),pre-push 擋,訊息列合約、測試、尾段輸出。全綠 → 放行並在訊息附「受波及合約測試 N 條綠,M 秒」。
2. **假綠三防**(s2 F1/F2、s1 F3):①測試名必須存在於 Check T 同一套平台真測試索引(`classify_invariants` 的 dangling/fake 判定),懸空/偽證據一律紅,不靠 rc;②去重鍵=解析後完整指令(同 kill),跨平台同名各跑各的;③方法名重驗失敗(同 `_KILL_METHOD_OK_RE`)= 紅,不是「沒綁」。
3. **fail-open 邊界**(明列,其餘都擋):沒 run_cmd / diff 算不出(無 merge-base、淺 clone,同 `_codeloop_guard_verdict` 慣例)/ 沒固定席 / 固定席沒綁測試 → 不擋,印一行提醒,**並寫治理帳 gate=bound-tests kind=no-config|no-pins|no-bound**——零觸發要看得見。
4. 逃生門:`--skip-bound-tests --note <理由>` 只對 check 生效(環境變數 `LUMOS_SKIP_BOUND_TESTS=1` 給 CI);寫治理帳 kind=skipped;被 gov --stats 統計。
5. CI:CI 已跑全套測試當後盾,CI 的 check 步驟設 `LUMOS_SKIP_BOUND_TESTS=1`,不重跑(ci.yml 同步)。

## 設計(r1 折入後)
- 重用(不複製):`_kill_run(cmd, cwd, timeout)`;`load_platforms`(每平台 `run_cmd`/`root`,無 method_regex 頂層鍵);`resolve_test_refs(inv_text, platforms, default)` 解平台前綴(legacy 不切、未定義前綴 raise→視為紅);`classify_invariants(env)` 的 real/dangling/fake 判定當存在性檢查;`_KILL_METHOD_OK_RE` + `shlex.quote` 重驗方法名;`cmd_impact_diff(..., as_json=True)` 取 pinned 且 `contract` 非空的節點(注意 contract 非空含 ★IRREVERSIBLE★/risk 軸,這些節點抽不到 [test:] 會自然落入「沒綁」分支)。
- 新函式:`_bound_tests_for_diff(repo_root, diff_range) -> items[(node, platform, method, status)]`、`_run_bound_tests(repo_root, items) -> results`;在 `_codeloop_guard_verdict` 起頭接上,結果併進 verdict dict(`bound_tests: {ran, red, skipped_reason}`)。
- 治理帳:**獨立 gate=bound-tests**,kind ∈ red/green/skipped/no-config/no-pins/no-bound,nodes=相關合約節點;進 `_KNOWN_GATES`、`_STATS_NODE_SEMANTICS`;gov --stats 可見採用率。寫帳用自己的小 writer(`_append_governance_log` 直接呼叫),不改 `_codeloop_gov_log` 簽名。
- 超時:**沿用 runner 同名環境變數 `LUMOS_TEST_TIMEOUT`**(peer 今天加的,預設 180s,0=不限)當單支上限;whole-suite(run_cmd 無 {method})用 kill 同款 `max(600, floor)`。不另立第三個變數。任一支超時 → 當次輸出直接給 `--skip-bound-tests --note` 範本(即時止血),不等三次。
- 本 repo 實測(s3):固定席 35、綁測試節點 5、去重 38 支、序列 28.7s——保護面窄(35 選 5)是覆蓋率問題,靠 doctor 裸合約提醒逼綁;不是效能問題。

## 非目標
- 不跑相依功能的「整套」測試,只跑合約綁定的;不接 testmap affected(檔案級)。
- 不動 pass/skip 的語意;不動 pre-push 腳本(它本來就呼叫 check)。

PRIOR-ART: 既有 kill 執行面 + impact 固定席 + code-loop check 判定式三者接線,零新依賴;業界「affected tests」(Bazel/Nx)是檔案級依賴圖,我們用圖譜合約級,借概念不借實作。

## 風險與回頭看條件
- hermetic:run_cmd 有副作用的測試每次 push 都會跑。★放行理由★:run_cmd 是專案自己宣告的測試指令,跟 CI 跑全套同等副作用、同一信任邊界(同 kill);不另建「安全跑」旗標——那會變成又一個零觸發開關。回頭看:若 gov --stats 出現 bound-tests red 且原因是外部資源(DB/配額),再加單支白名單跳過。
- 零觸發:消費端多數沒 run_cmd → 帳上 no-config 會累積。回頭看:**30 天後 gov --stats 若 bound-tests 只有 no-config/no-pins、零 green/red → 在入口 hook 加「本專案沒設 run_cmd,合約測試閘沒開」提醒**;再 30 天仍零 → 列入只退場不痛的機制檢討。
- 本 repo 單體大檔固定席 35:實測 28.7s 可接受;若三次 check 超過 3 分鐘 → 加 `--bound-direct-only`(只跑 direct 相依)。
