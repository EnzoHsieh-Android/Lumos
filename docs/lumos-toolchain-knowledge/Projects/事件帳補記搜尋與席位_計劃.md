# 事件帳補記搜尋與席位_計劃

白話:事件帳外掛([[Systems/lumos事件帳]])已經逐筆記下每個子代理的工具呼叫,但少了三樣東西,所以「核對審查員引用的檔有沒有真的讀過」做不起來([[Projects/Claude-mod第二批_計劃]] 第二輪拿掉的那一項):搜尋用了什麼條件、子代理在哪個目錄做事、這個子代理是哪一席審查員。這篇只補記錄,核對留到下一篇。

PRIOR-ART: 沿用事件帳外掛既有的 `toolExtra` 與 `spawnFields` 兩支純函式加欄位,不另開觀察點;Bash 指令已經照「前 500 字」的寫法記,搜尋條件照同一種「截斷、只記輸入不記結果」的寫法。席位標記的格式不另訂:直接用審查席隔離外掛([[Systems/lumos-guard]])認的那一條 `SEAT_RE`,兩邊由一支 Python 測試釘成同一條。

RETIRE-IF: ①「核對審查員讀檔」那篇兩個月內沒開工,或開工後決定不用這幾個欄位——欄位撤掉;②事件帳整個撤掉時一起撤。

## 範圍

- **做**:
  1. `Grep`、`Glob` 的工具事件多記 `pattern`(前 200 字)、`glob`(前 200 字)、`output_mode`(前 40 字);只收字串,其他型別不記。2026-10-07 用 `claude -p --plugin-dir` 載入新版外掛真跑一次 Grep 驗過欄位名:事件記到 `pattern`、`glob`、`output_mode` 與 `paths`。
  2. `Bash` 的工具事件多記 `cmd_len`(整條指令的長度),讓讀的人知道 `cmd` 有沒有被截斷。
  3. `spawn` 事件多記 `cwd`(派工輸入帶的工作目錄;沒帶就是 null)與 `seat`(審查席隔離外掛會把這份派工認成審查席時,記「迴圈/輪次/席名」,前 200 字;不是標記或標記寫壞都是 null)。
- **不做**:
  - 核對審查員讀檔(另開一篇;要等這幾個欄位上線、有真實資料再設計)。
  - 讀取端 `lumos events` 的文字輸出不加這些欄位(JSON 輸出本來就帶全部欄位)。
  - 子代理每一筆工具事件都帶 cwd:子代理的工作目錄在派工那筆就有,每筆都記只是重複。

落點:[[Systems/lumos事件帳]]。

## 做法要點

- 「不記提示全文」([[Projects/Lumos事件帳_計劃]] 事件表那節)照舊:`seat` 只記第一個非空行、而且只在它整行符合標記格式時記值,派工詞其他內容一律不碰。這是那條規則唯一的例外,記成決策。
- 標記判法:事件帳外掛的 `seatOf` 照審查席隔離外掛 `parseMarker` 的同一套寫(以換行與 U+2028、U+2029 分行,剝格式字元後判空行,嚴格比對 `SEAT_RE`,驗三段)。兩支外掛各放一份一模一樣的案例檔 `seat-fixture.ts`,各自的測試跑同一批案例;`t_ledger_seat_re_matches_guard` 釘住兩邊 `SEAT_RE` 一字不差、兩份案例檔一字不差(代碼審 r1:原本只抄正規式,第一行判法與三段驗證跟守衛分岔)。外掛測試不能引用別的外掛資料夾裡的檔,所以案例檔放兩份而不是共用一份。
- 截斷一律用字串的前 N 個字;不是字串就不記那個欄位。

## 條款

外掛行為的條款綁在 `mods/claude/lumos-ledger/hooks/ledger.test.ts`,測試標題以「補記」加條款編號開頭,用 `claude plugin test mods/claude/lumos-ledger` 在本機跑。

- [S1] 當 `Grep` 或 `Glob` 的工具事件被記,應多記 `pattern`、`glob`(各前 200 字)與 `output_mode`;欄位不是字串時不記 [manual:claude plugin test mods/claude/lumos-ledger 標題以「補記 S1」開頭的測試全綠]
- [S2] 當 `Bash` 的工具事件被記,應多記 `cmd_len`,值是整條指令的長度 [manual:claude plugin test mods/claude/lumos-ledger 標題以「補記 S2」開頭的測試全綠]
- [S3] 當 `spawn` 事件被記,應多記 `cwd`(派工輸入的工作目錄或 null)與 `seat`(審查席隔離外掛會認成審查席時的「迴圈/輪次/席名」,前 200 字,否則 null),不記派工詞其他內容;共用案例檔的每一筆兩支外掛判得一樣 [manual:claude plugin test mods/claude/lumos-ledger 標題以「補記 S3」開頭的測試全綠]
- [S4] 當 Python 端檢查兩支外掛的原始碼,事件帳外掛的 `SEAT_RE` 與 `seat-fixture.ts` 應跟審查席隔離外掛的一字不差 [test:t_ledger_seat_re_matches_guard]

## 回退

- 外掛改動只在 `toolExtra` 與 `spawnFields` 多加欄位,`git revert` 那個提交即可;已經寫進事件帳的舊事件多幾個欄位,讀取端不認得的欄位本來就略過。
