# 指令索引與情境測試_計劃

> 白話:Claude 常常跳過 lumos 直接 grep,結果不準。原因不是態度,是「我現在想幹嘛 → 該敲哪個指令」這張對照表不存在:80 個子指令散在五份 skill 共 21 萬字元裡,十幾個指令在任何給 Claude 的規則裡零提及。本案建一套分塊的指令索引、改寫注入 CLAUDE.md 的規則、並用「模擬情境看 Claude 會不會自己敲」來驗收,不是直接呼叫指令。

## 起因(2026-08-22,Enzo 三連訊息)
1. 排查工具整體調用是否都有明確指示,Claude 知道什麼時機用;分門別類、可自動索引、不漏。
2. 字元太多就分塊建索引,別讓 Claude 吃太多 context 注意力低下。
3. 其他寫給 Claude 的規則一起優化;每個指令做一次測試——模擬場景看 Claude 會不會自動調用,才算規則吃進去;直接呼叫指令沒意義。

## 現況量測(2026-08-22)
- 子指令 80 個(argparse 計);`lumos --help` 有手寫一句話說明,但子指令 argparse 的 help 多為空。
- 覆蓋矩陣(`lumos <cmd>` 字面在 CLAUDE.md 區塊 / 五份 SKILL.md / reference.md 出現次數):零提及者 ci-status、cochange、compose-metrics、decision-reindex、deinit、delguard、drift-history、export、install、link-candidates、rel-cascade、remove、teardown、uninstall、update、anchor、sqlfluff/stylelint-sarif、stats。
- skill 既有「常用指令速查」按工具分類(讀/寫),不是按 Claude 當下衝動分類;操作卡草案(`[[Projects/lumos操作卡_草案]]`)只列十幾個。

PRIOR-ART: 最小解在 skill 層(加一個 commands/ 資料夾與一頁總目錄)+ CLAUDE.md 範本改一段;世界解=progressive disclosure(Anthropic skills 官方建議:SKILL.md 短、細節放子檔按需讀)→ borrow-design。不建新機制,新增只有一條測試釘「索引不漏指令」和一支情境探針腳本。

## 設計
1. `skills/lumos-project-notes/commands/INDEX.md`(≤3.5k 字元):「grep 衝動 → 先敲哪個 lumos」對照表 + 八類各一行,指向子檔。
2. 八個子檔 `commands/<類>.md`:每列=情境(人話觸發句)| 指令 | 結果怎麼讀 | 不用它會怎樣。80 個子指令全歸位;hook 自動跑的標明「不用手動」。
3. `t_command_index_complete`:從 argparse 取子指令全集,斷言每個都出現在 commands/*.md。
4. CLAUDE.md 範本(graph-discipline.md):「圖譜先行」段改成「grep 衝動對照表」精簡版 + 指向 INDEX;總長不增。
5. 五份 SKILL.md 頭版:常用指令段改為指向 INDEX,只留最常用六條。
6. 情境探針 `scripts/scenario_probe.py` + `governance/scenarios/*.jsonl`:headless `claude -p` 在臨時專案副本跑情境,stream-json 抓工具呼叫;判準=在任何 grep/Grep 之前出現 `lumos <期望指令>`。每類至少三個情境,全部跑一輪,結果進 Verification。

## 非目標
- 不改任何指令的行為;不新增指令。
- 不追求情境測試 100%——這是量「規則有沒有被吃進去」的儀器,紅的拿來改索引措辭,不是拿來硬撐。
