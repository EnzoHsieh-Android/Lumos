# PR基準重播_計劃

> 白話:要證明一支新測試「真的在驗這次的改動」,最直接的辦法是把它放到還沒改的舊程式上跑:必須紅;放到改好的程式上跑:必須綠。世界上叫 fail-to-pass。這份計劃在 PR 檢查時,對「這個 PR 新增或改過的每一支測試函式」做這件事。第一階段只記結果不擋,量過誤報率再決定擋不擋。這裡記方向、世界做法與前一份計劃踩過的坑,設計審開始時再補做法與驗收條款(見最後的回頭條件)。

## 由來

從 [[Projects/高風險測試證據加嚴_計劃]] 拆出(那份的 d8)。那份計劃的設計審 r1 到 r5 每輪都在基準重播換形狀(翻帳找紅、沿用風險低推送前檢查、推送前重播、PR 檢查重播),r5 三席一致抓到:以測試檔為單位挑要重播的測試,在本 repo(測試幾乎全在 `scripts/test_lumos.py` 一支檔)必誤擋;綁需求計劃的條款去挑,新計劃綁沒改過的舊測試時又會整個漏查。卷證在 `governance/review-reports/高風險測試證據加嚴/`。

## 世界做法(2026-11-04 查證)

- **以測試函式為單位**:ScottHysom #681/#684(兩版各收集一次測試清單,差集就是新測試;每一支都不能在舊程式上綠)、robot_sf #9989(比函式語法樹,新增或改過都算;逐支回報、只提醒)、open-cam #475/#536(比語法樹;否決以檔為單位,理由是「真訊號淹沒在幾百支本來就該綠的無關測試裡」)。
- **以檔為單位的坑**:devops-cli #3124:重播環境壞掉讓整支檔全紅,「至少一支紅就放行」照樣放行,「The check proves nothing」;#1722:把整個測試目錄換成新版撞出 INTERNALERROR。
- **改過的既有測試在舊程式上就綠,誤報多**:robot_sf 在 20 個 PR 上量到準確率 8%,排除純測試 PR 後 33%(加固測試、守住舊行為的改動本來就該綠),建議只提醒。沒有人把「新增」與「改過」分開量。
- **被跳過、沒收集到的算沒證明**:open-cam #536「a partly skipped test is not an all-clear」;devops-cli 收集錯誤不算證明。
- **選到 0 支會假紅**:#684 先在新版逐支跑一次,確認選中的測試真的存在、真的跑了。
- **加對照組防環境全紅**:沒改的測試在舊程式上必須綠。
- **結果另存成檔**:三家多寫在 CI 的 job summary,但它讀不到 API(community #27649,未驗);devops-cli #844 的起因就是「CI keeps no artifact」。要統計就寫成 JSON 上傳成 artifact。
- **改名或搬家的測試會被當成新的**(#681),參數化改了參數 id 也會變:要有附理由的豁免。
- **沒有一家拿需求計劃當挑測試的來源**,都是直接看這個 PR 改了哪些測試。

## 方向(待設計審)

1. 挑測試:新增的 = 新版測試清單減舊版測試清單(`_platform_test_index` 各算一次);改過的 = Python 比函式語法樹,Kotlin/Java 見待決問題 Q1。跟需求計劃、風險高低都脫鉤。
2. 重播:分岔點(PR 目標分支的 merge-base)那一棵只換上新版的測試檔,正式程式碼留舊版;兩棵各跑一次挑出的測試。
3. 判定:新增的在舊程式上紅、新版綠 = 證實;新增的在舊程式上綠 = 反證;改過的在舊程式上綠 = 提醒;被跳過、沒收集到、只在準備步驟出錯、逾時 = 沒證明;對照組(沒改的測試)在舊程式上不綠 = 環境壞了,整次判不了。
4. 第一階段只記不擋:結果寫成 JSON 檔上傳成 artifact,`lumos ci-wait` 讀回來記進治理帳;量一段時間的反證裡有幾成是真問題,再決定反證要不要擋。
5. 豁免:改名、搬家、參數化改 id 的測試,要能附理由標記「在舊程式上本來就綠」,理由印給審查人看。

## 前一份計劃五輪審查留下、這份要先避開的坑

- CI 裡寫進治理帳的事件,工作結束就沒了(r5):結果要另存成檔、由本機讀回。
- 工具自己出錯時,本 repo CI 的慣例是讓 CI 紅,不是放行(r5 架構對齊)。
- 新閘名要登記進 `_KNOWN_GATES`,沒登記會靜默不寫(r5);新增頂層命令會讓釘命令數的測試與文件紅。
- 消費專案 CI 淺層 checkout 算不出分岔點,會靜默跳過;本 repo 主線有沒有分支保護、PR 檢查紅了擋不擋得住合併,沒查過(r5)。
- `lumos ci-wait` 只看整個 run 的結論,跳過會被報成綠;推功能分支不觸發這個 workflow,推完馬上等會得到沒有 run(r5)。
- 測試跑紅會留下暫存現場(r3 最小實驗量到 18 個),重播子程序的暫存目錄要指到工作樹底下一起收;每支每棵約 2.7 秒。
- 編譯型語言:新測試與對照組在同一模組,新測試在舊程式上編不過會連帶對照組紅,這時整次判不了(r3、r4)。
- 路徑要用 `_nodehome_name_status(…, norm=False)` 拿去 git 查,不然分解字形的檔名查不到(r5)。
- 外部給的版本範圍要走 `_lens_range_ok` 這類既有檢查(r5 架構對齊)。
- 改測試檔前先 `lumos anchor approve`(`scripts/test_lumos.py` 在錨點裡)。
