# 圖譜進迴圈入口栓_計劃

PRIOR-ART: **借用既有原語,不建新機制、不加依賴**——A 借用檢索引擎兩個內部原語:OR 候選收集(現內嵌於 `cmd_search` 回退段 scripts/lumos:2151-2185,實作時抽成共用 helper,兩處共用禁分岔)+ `_rank_score_candidates`(BM25F)。★r2 訂正:**不走 `cmd_search` 頂層**——片語階段單命中即 break 會抑制 OR(scripts/lumos:2173-2175),事故本尊實測 1 篇帶空白命中就把 0.90 近名整篇藏掉;r1 版寫「多詞回退正好接住切詞查詢」不實★(檢索健康:週考全綠 hook P 0.73-0.80、lift 54-82%,2026-08-24 帳)+ `loop next` 既有輸出慣例;B 用同一比對原語 + `cmd_new` 既有入口。兩條皆 advisory 不擋,對齊「前置加重一律拒」(不加席不加輪,只把既有資訊端到眼前)。**已排除**:機械相似度硬擋(誤殺合法近名)、把搜尋接進處置閘(閘語意變更須另案)。

## 問題(兩次真實燒錢事故,非假想)

**這條線=「節點搜尋得到 → 迴圈真的用上」。檢索本身健康**(見 PRIOR-ART 考卷數字),漏在兩個入口:

- **開迴圈不看圖譜**:`loop next` 給輪次/席位/記帳模板,不給「這主題圖譜已有什麼」。★事故:impact 鏡頭案(2026-08-29)開案時 `送審前impact鏡頭機械化_計劃`(已裁 A 案、拒加閘)已存在,搜尋可中,但無任何機械點代打——兩輪設計審(十席次)燒完才由外家席發現,案停★(詳 [[Projects/impact鏡頭機械化_計劃]]「我方犯的錯」節)。
- **建節點不查近名**:`cmd_new` **完全同名會擋**(既有五道檢查之一),但**近名零檢查**。掛點在 `cmd_new` 內、同名檢查之後(★r2 訂正時序:比對集建檔前收集、訊息建檔後印,見提案 B★)。★同案:建 `impact鏡頭機械化_計劃` 時近名節點連檔名都撞一半,零警告★。

## 提案(兩條,全 advisory 不擋;r1 三席+r2 兩席折入後 v3)

**A. `loop next` 首輪加「主題既有節點」advisory 段**
- 觸發:**只在首輪**(`n_next == 1`,帳齡零必走 plant-canary;比照同函式 `cluster_hint` 的 N=1 抑噪先例 scripts/lumos:5889——逐輪重印=噴無效噪音)。只掛正常 emit 出口;rc2 硬擋出口(如忘帶 --tier)不印。
- 查詢源:有 `--spec` → **計劃節點檔名優先**;編號僅 fallback(`auto-2026-08-30` 型編號實測命中 68 篇零相關——印似是而非的 5 筆比 0 筆更毒)。
- 切詞與清洗(機械規則,無黑名單;NFC+lower 後**重用 `_rank_tokenize`** scripts/lumos:1871,禁第二份實作):
  1. 取切詞結果後**丟棄可拆分的母 token**(含連字號/底線的 ASCII 複合 token,只留拆片)——★r2 訂正:`_rank_tokenize("auto-2026-08-23")` 實測回 `['auto-2026-08-23','auto','2026','08','23']`,母 token 非純數字、字面舊濾網濾不掉,會令誠實分支永不觸發★;
  2. 濾純數字 token(「2026」實測命中 381/385=全庫召回)與長度 1 的 ASCII token;
  3. 去重。
- 測試例三枚(精確集合):`intake-guard`→`{intake, guard}`;`圖譜進迴圈入口栓`→bigram 串(實測 top-5 與人工斷詞完全相同);`auto-2026-08-23`→`{auto}`→ 走「無主題訊號」分支。
- 召回:直接 OR 候選+`_rank_score_candidates` 排序(共用 helper,見 PRIOR-ART);**superseded/翻案節點必須納入**(「已裁不做」正是最值錢的命中),輸出標 status。直取原語不經 cmd_ 層、無列印,無 redirect 需求;若實作最終仍呼叫會印的 cmd_ 層才需 redirect_stdout(前例 scripts/lumos:5927)。
- 輸出合約(文字模式,專屬多行段比照 roster 迴圈 scripts/lumos:5905,不塞五鍵白名單 scripts/lumos:5911),三分支唯一化:
  1. 清洗後 token ≤1 且無 CJK 段 →「編號無主題訊號,未查圖譜」;
  2. 查了、OR 候選為 0 →「查過 <query>,圖譜這主題無既有節點」;
  3. 有候選 → 段首「圖譜既有節點(查:<query>):」+ 每筆一行「- <節點名> [<status>] 決策 <N> 條」,近名者行尾加「★近名」(判準沿用 B:剝前綴後 difflib ≥0.6)。
  ★r2 訂正:原「top1 分數低於門檻」子句**刪除**——BM25F 的 N/df/avgdl 以候選集為語料(scripts/lumos:2129-2131),跨查詢不可比,絕對門檻無法定義,設錯方向=系統性假陰性;誠實零行只掛「零候選」這個機械事件★。
- `--json`:`related_nodes = {"query": str|null, "queried": bool, "nodes": [{"name": str, "status": str|null, "decisions": int, "near_name": bool}]}`,放進 `out` dict;未查(分支1)= queried=false、nodes=[];查了零候選(分支2)= queried=true、nodes=[]。既有消費端(test_lumos.py 內 `loop next` 呼叫 40 處、其中 JSON 消費 4 處,機械數)全逐鍵取值,加鍵不破壞。
- 一行指路:「先讀再開;近名者尤其要讀它的 decisions」。

**B. `lumos new` 近名 advisory(比對建檔前、告知建檔後)**
- 時序唯一化(★r1 外家「建檔前防撞自相矛盾」+r2 兩席「殘影」訂正★):**比對集(同型別資料夾的既有檔名)在寫檔前收集;訊息在建檔完成後印**——★r2 D-3:建檔後才重掃會把新檔自己算進候選,自比 1.0 必 ≥0.6,每次建檔 100% 誤鳴★。事故裡貴的不是建檔,是之後燒掉的審查輪;告知落在開案那一刻,仍攔在昂貴段之前。
- 範圍:**限 project/system/issue 三型**(`ntype != "verification"`;Verification 實測 156 檔 81% 有 ≥0.6 鄰居=天天誤鳴)。**只在同型別資料夾內比**(跨型比會系統性誤鳴 Systems/X↔Issues/X 合法同主題對,實測 `範本system`↔`範本issue` 0.67)。
- 判準:剝掉開頭 `YYYY-MM-DD_` 前綴後,**檔名 difflib ≥0.6 單判準**(「同詞幹」已刪:repo 無 stemmer 不可實作)。剝前綴誠實標註:納入的三型現況 228 檔僅 1 檔有日期前綴,此規則是防未來的一行保險,非現在主力。
- 命中 → 建檔完成後印「★近名節點已存在:○○(status/決策 N 條)——若同主題,先讀它再繼續;重複開案的成本在後頭★」;低相似/零命中靜默。印 stdout(既有測試對 `cmd_new` stdout 的斷言全為包含式子字串,加行不破;★r2 訂正:原寫「只斷 rc」不實★)。
- Projects 的 top pair 幾乎全是合法 `X_計劃`↔`X_實作計畫` 變體(0.85-0.92,與事故對 0.903 同分段、檔名層不可分離)——advisory 不試圖分離,提醒「先讀計劃」對合法變體反而是 feature。

**兩條共同鐵則:fail-open**——advisory 全體包 try/except,任何內部例外靜默跳過,**絕不改變宿主指令的 rc 與既有輸出**:A 的例外不得改變 emit 輸出與 rc(`loop next` 的 rc 是載重語意 scripts/lumos:5745-5750);B 的例外不得改變 rc、不得影響已完成的建檔結果(訊息印不出來=少一個提醒,不是建檔失敗)。★r2 訂正:原「B 掛在 mkdir 前」句刪除(與建檔後即告矛盾的殘影)★。

## 誠實天花板與重驗條件(r1 訂正)

- **定位=紀律輔助,非根治**。外家 r1 反證成立:同案紀錄明載編排者**跑了提示入口仍忽略**([[Projects/impact鏡頭機械化_計劃]]:53)——根因是紀律沒守,不純是「不知道存在」。A/B 只把資訊送到眼前、降低偶發遺漏,擋不住不讀;機械強制已在 impact 案裁「不做」,本案是那次裁定下最便宜的殘餘手段。
- **自主迴圈消費的坑(r1 邊界席)**:現行 orchestrator-prompt **不跑 `loop next`**,且其 lumos 呼叫全走 `--vault __SCRATCH__/kg`(scratch 近空)——未來若把 related_nodes 接進去而不解 vault 錨定,誠實零行會**恆為假陰性**,精準複製本案要防的病。本案不改 orchestrator-prompt;接上前必須先解 vault 指向。
- **重驗**:上線後下一次「重造輪子」事故若再發生,查當時 A/B 有沒有印、印了為何沒用——印了沒用=升級議題(546 計數器再議),沒印=切詞/召回 bug。B 的 0.6 門檻與型別範圍為單次量測,若 Projects 端出現週級誤鳴照樣回這裡調。
