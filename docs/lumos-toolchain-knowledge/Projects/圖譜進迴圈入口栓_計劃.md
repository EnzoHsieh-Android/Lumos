# 圖譜進迴圈入口栓_計劃

PRIOR-ART: **借用既有原語,不建新機制、不加依賴**——A 借用檢索引擎兩個內部原語:OR 候選收集(現內嵌於 `cmd_search` 回退段 scripts/lumos:2151-2185,實作時抽成共用 helper,兩處共用禁分岔)+ `_rank_score_candidates`(BM25F)。★r2 訂正:**不走 `cmd_search` 頂層**——片語階段單命中即 break 會抑制 OR(scripts/lumos:2173-2175),事故本尊實測 1 篇帶空白命中就把 0.90 近名整篇藏掉;r1 版寫「多詞回退正好接住切詞查詢」不實★(檢索健康:週考全綠 hook P 0.73-0.80、lift 54-82%,2026-08-24 帳)+ `loop next` 既有輸出慣例;B 用同一比對原語 + `cmd_new` 既有入口。兩條皆 advisory 不擋,對齊「前置加重一律拒」(不加席不加輪,只把既有資訊端到眼前)。**已排除**:機械相似度硬擋(誤殺合法近名)、把搜尋接進處置閘(閘語意變更須另案)。

## 問題(兩次真實燒錢事故,非假想)

**這條線=「節點搜尋得到 → 迴圈真的用上」。檢索本身健康**(見 PRIOR-ART 考卷數字),漏在兩個入口:

- **開迴圈不看圖譜**:`loop next` 給輪次/席位/記帳模板,不給「這主題圖譜已有什麼」。★事故:impact 鏡頭案(2026-08-29)開案時 `送審前impact鏡頭機械化_計劃`(已裁 A 案、拒加閘)已存在,搜尋可中,但無任何機械點代打——兩輪設計審(十席次)燒完才由外家席發現,案停★(詳 [[Projects/impact鏡頭機械化_計劃]]「我方犯的錯」節)。
- **建節點不查近名**:`cmd_new` **完全同名會擋**(既有五道檢查之一),但**近名零檢查**。掛點在 `cmd_new` 內、同名檢查之後(★r2 訂正時序:比對集建檔前收集、訊息建檔後印,見提案 B★)。★同案:建 `impact鏡頭機械化_計劃` 時近名節點連檔名都撞一半,零警告★。

## 提案(兩條,全 advisory 不擋;r1 三席+r2 兩席折入後 v3)

- Projects 的 top pair 幾乎全是合法 `X_計劃`↔`X_實作計畫` 變體(0.85-0.92,與事故對 0.903 同分段、檔名層不可分離)——advisory 不試圖分離,提醒「先讀計劃」對合法變體反而是 feature。

## 誠實天花板與重驗條件(r1 訂正)

- **定位=紀律輔助,非根治**。外家 r1 反證成立:同案紀錄明載編排者**跑了提示入口仍忽略**([[Projects/impact鏡頭機械化_計劃]]:53)——根因是紀律沒守,不純是「不知道存在」。A/B 只把資訊送到眼前、降低偶發遺漏,擋不住不讀;機械強制已在 impact 案裁「不做」,本案是那次裁定下最便宜的殘餘手段。
- **自主迴圈消費的坑(r1 邊界席)**:現行 orchestrator-prompt **不跑 `loop next`**,且其 lumos 呼叫全走 `--vault __SCRATCH__/kg`(scratch 近空)——未來若把 related_nodes 接進去而不解 vault 錨定,誠實零行會**恆為假陰性**,精準複製本案要防的病。本案不改 orchestrator-prompt;接上前必須先解 vault 指向。
- **重驗**:上線後下一次「重造輪子」事故若再發生,查當時 A/B 有沒有印、印了為何沒用——印了沒用=升級議題(546 計數器再議),沒印=切詞/召回 bug。B 的 0.6 門檻與型別範圍為單次量測,若 Projects 端出現週級誤鳴照樣回這裡調。
