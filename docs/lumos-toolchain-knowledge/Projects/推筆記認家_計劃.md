# 推筆記認家_計劃

> 白話:每支程式檔現在都有一篇「管它的」節點(家)。改那支檔時,家應該是最該被推給 agent 看的那一篇——可是推筆記的機制到現在還沒在用它。這案讓推筆記認家;因為家從此一定會被推,上線前先抽查家填得對不對,寫入當下也多一句可疑提醒。另外讓接手舊專案、還原節點時,每篇還原出來的節點都一定寫明它管哪幾支檔。

## 名詞

- **家**:照 [[Projects/每支檔有家_計劃]] 的定義——狀態 doing/done/stale 的 Systems 節點,about_code 列了這支檔;比對用同一支字面比對鍵,不看預標指紋。
- **家對照表**:「檔 → 管它的那幾篇」。只有一支算法([S1]),每支檔有家與推筆記共用。
- **確認過的家**:這支檔在那篇裡真的被寫出來——兩種命中算一種:①那篇的摘要或正文任何位置出現這支檔的完整路徑(repo 相對路徑,字面比對);②既有那支三處共用的抽取(refcheck、改檔前推筆記、每支檔有家用的同一支)在那篇抽到這支檔(反引號範圍內的完整路徑,或在受版控檔裡唯一的裸檔名)。不另寫一套 token 規則:沿用同一支抽取的正規化與路徑判定,只多一個「掃全文找完整路徑」的模式,兩個模式的關係用測試釘住(反引號那組必為全文那組的子集)。★裸檔名只在反引號裡算★——沒有副檔名的程式檔(本工具鏈主程式、三支 git hook)的檔名是普通詞,全庫 65 篇 Systems 節點有 62 篇正文出現裸字「lumos」,放寬會讓分兩級對家最多的那支檔整個失效。2026-09-12 實算:115 對家配對有 99 對(86%)算確認過——三個 POS 的 46 對全部算,本工具鏈 69 對裡 53 對。
- **必推名單**:推筆記的固定席——事故、帶合約的直接節點、一跳硬合約(INVARIANT/IRREVERSIBLE)間接節點,加上本案的家;不截斷,一定會推給 agent。
- **可選名單**:其餘候選照分數競爭,最多 10 篇加 3 篇保底。
- **大檔**:家對照表裡這支檔有 ≥ `LUMOS_IMPACT_ABOUT_MAX`(預設 8)個家;篇數用家對照表算,不用舊的 about 計數(舊計數不分類型與狀態)。本工具鏈主程式 2026-09-12 實算 31 個家(每支檔有家那篇天花板 KEY 行寫的 30 是 2026-09-11 的數字,上線那次提交順手更新)。★門檻 8 是舊量尺調出來的★:舊的 about 計數對主程式算 65、家對照表算 31,同一個 8 在新量尺下實質更鬆——沿用是為了不在同一次改動裡動兩個變數,重校排進回頭條件。
- **從程式重建的節點**:蓋了 `regen: from-scratch/<日期>` 章的 Systems 節點(節點還原 SOP 第 4 步蓋)。
- **組裝檔**:把別的東西接起來、自己沒什麼行為的程式檔——依賴注入模組、Application 或啟動類別、路由表。

## 核心裁定

### 甲、推筆記認家

- [S1] 家對照表只有一支算法:把每支檔有家現在的算法抽成一支純函式,輸入是「每篇的類型、狀態、about_code」,輸出「檔 → 家」。每支檔有家從提交快照餵資料,推筆記從已經載入的工作目錄圖譜餵;推筆記那邊不讀 git、不開子行程,同一個圖譜只算一次(行程內快取,同既有 about 計數的快取方式)。 [test:t_impact_home_uses_nodehome_definition]
- [S2] 改檔前推筆記(`lumos impact --file --ranked`,也就是 Edit 前那個自動推筆記的 hook)把目標檔的★確認過的家★當成一條入口,不必正文用反引號寫這支檔(Enzo 2026-09-12 裁分兩級:沒確認的家只照原本三條路,不保送也不加分——about_code 的品質沒有機械保證,分兩級讓填錯的家大多落在不保送那一級)。每篇只出現一次:已經是候選(事故、直接、間接,含被分到「參考道」的風險類間接節點)的,原項加上「家」標記、改成必推,種類與分數照舊——參考道裡的家搬進必推名單、從參考道拿掉;還不是候選的,新增一項,種類是「家」、必推、分數記 0(必推項不看分數決定去留)。沒確認的家:不新增、不升級、不加分,它本來怎樣就怎樣。自由席的直接節點被升成必推後,「直接節點保底」那段照原規則從被截掉的直接節點補回,這是加法、照舊。★這條取代舊案「about 不是第四條入口」的裁定★:現行測試 ⑨ 改成只在旋鈕關掉時檢查,說明文字同步改。 [test:t_impact_home_confirmed_is_entry_and_pinned] [test:t_impact_home_unconfirmed_not_pinned] [test:t_impact_home_no_duplicate_node] [test:t_impact_home_moves_out_of_lane] [test:t_impact_about_hit]
- [S3] 必推名單的順序:事故最前,其次家,其餘照原本;事故同時是家的算事故;家之間照分數高到低、同分照篇名。 [test:t_impact_pins_order_incident_home_rest]
- [S4] 大檔(家的篇數照家對照表算,不分確認與否)的家不當入口:不新增、不升級,跟現在一樣只靠原本三條路;已經是候選的家只加「家」標記給顯示用。不看合約種類——這樣不必定義「帶合約的家」,也不會把舊案壓下去的風險類搭便車噪音帶回來(舊案 held 那題 22 誤放全出自改主程式)。 [test:t_impact_home_cap_for_big_files]
- [S5] 只加不降:事故、帶合約的直接節點、一跳硬合約間接照原本規則進必推,不因為不是家而被降;不是家、只被反引號提到的節點照原本規則。 [test:t_impact_home_is_additive_only]
- [S6] 另外三條讀取路徑也認家:推送前的波及計算(`impact --diff`)多檔聚合時,「家」標記取或、記下它是哪幾支檔的家,必推名單照 [S3] 的順序排(事故、家、其餘照分數)——分數較高的那一筆整項取代時,家標記與「是哪幾支檔的家」也要併回,不能被沖掉;派審查員時的圖譜參考,差異模式走上一條、自然吃到;計劃模式呼叫的是不帶排序的 `impact --file --json`,那個輸出多一個頂層鍵列出家(比照既有「參考道」用獨立頂層鍵的做法,沒學過的讀者不受影響),計劃模式把家收進固定席、照 [S3] 的順序排(事故、家、其餘),再受每檔篇數上限——不然家會排在最後、被上限截成只列名。 [test:t_impact_diff_keeps_homes] [test:t_dispatch_lens_diff_includes_homes] [test:t_dispatch_lens_spec_includes_homes]

- [S8] 顯示(旋鈕開著時):Edit 前推筆記的清單上,確認過的家那一行標「★家★」(同既有 ★關於★、★COMBO★ 這種掛在必推項上的額外標記寫法);沒確認的家不標,免得看的人以為它有保證;必推名單的標頭改寫成三種理由「出過事故、帶著不能破壞的合約,或是你要改的這支檔的家」,不再說每篇都帶合約或事故。其他講到固定席的地方一起改:風險掃描送審前的提示(「帶硬合約或出過事故的一定要看」「帶合約/事故的那幾篇」)、派工鏡頭計劃模式的空結果訊息(「沒牽到任何帶合約/事故的節點」);派工鏡頭的種類表加「家」;改完程式寫回圖譜時的點名提示(「合約 / 事故 / 直接相依」)、`impact --file` 與 `impact --diff` 人讀輸出的兩張種類表也一起改。大檔時已是候選、落在可選名單的家,可選名單那一行也標「★家★」(只加標記、不升級)。 [test:t_impact_hook_shows_home_label] [test:t_pinned_wording_mentions_home]
