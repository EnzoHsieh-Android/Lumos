# 審查有沒有用記帳_計劃

> 題目一句:讓「審查到底有沒有用」變成機器數得出來的帳,不是散文。Enzo 2026-09-08 裁「開工」;起因見同事 session 的盤點(回報在 [[Projects/loop數據收集_計劃]] 那條線)。
> 這不是「建一套評測系統」,是「開始記」——三個數字、一個逃逸帳、一段讀側;不回填舊卷證、不做統計模型。

## 為什麼(2026-09-08 我自己量的)

- **審查帳有 1216 筆,但答不出「報了幾條、站得住幾條」。** 席位列的 `--findings` 在 skill 裡寫「存活條數」,實務上有人填席位報的總數、有人填存活的,語意早就混了;被編排者機械重現駁回的發現★根本沒有 id★(只寫在 intake 散文),機器數不出。
- **兩個現成欄位一次都沒人填**:`--refute-verdict`(辯方表態)1216 筆裡 0 筆——今天查明原因是七個輪次一輪辯方都沒派(路由規則下多半不觸發),所以它不是主力;`lumos loop escape` 逃逸帳 0 筆到今天才補第 1 筆(#19 那條線的隔離缺陷被推送閘抓到,審查放行後的漏網)。
- **席報告「看起來」數得出「報了幾條」,r1 五席證明不行。** 收貨 SOP 要求每條 finding 一行 `severity: <值>`,寫側早就擋「讀不到任何 severity: 獨立宣告行」(code-loop reference)。對今天下午 18 份席報告(code-clause-bindings 兩個編號)實算,行首 `severity: minor|major|blocker` 的行數有 16 份跟手填的 `--findings` 一致;不一致的 2 份是驗收輪的架構席報告——它把前輪已折平的舊發現連同舊 severity 標籤原樣留著。今天早上的 8 份(嚴重度嵌在標題破折號後,如「## F1 — BLOCKER」)機器數到 0。★所以自動數不是萬靈丹:報告格式至少三種,驗收輪的舊項要有辦法排除★——這正是 [S1] 演算法要先講清楚的。
- **兩本帳可信度不同級**(同事 session 抄走的那句):閘擋了誰是機器寫的、賴不掉;人漏了什麼、人駁回了什麼只能靠人誠實。讀側必須分開印、不可拿人工帳的數字去算機器帳的比率。

## 做什麼(r1 折入後;r1 之前的寫法見卷證 r1-snapshot.md——那版想「從席報告自動數」,五席用四種真實報告格式證明會數到 0)

### [S1] 「報了幾條」由機器從★已正規化★的席報告數;寫側拒收沒正規化的報告 [test:t_canary_reported_normalized]

- r1 想「自動數」被四種真實格式打穿,r2 想「人填+下限守衛」被證明單向、可填 1 就過。★第三版:不讓人填,也不容忍格式★——
  `canary record` 帶 `--report` 時,寫側對報告做正規化檢查,不過就 rc2 並印出哪幾行要改:
  ①檔首第一個非空行必須是檔級 `severity: <clean|minor|major|blocker>`(★不跳 HTML 註解★——專案三處明令不偵測註解;來源註記之類放它後面);
  ②之後每條 finding 恰一行獨立 `severity: <值>`(`_report_severities` 認得的那種;它是專案唯一的 severity 解析,不另寫寬鬆版);
  ③★殘留的其他寫法一律擋★:任何含 severity/嚴重度 字樣卻不是標準宣告的行(`- severity: minor`、`**severity:** major`、`Severity:`、`sev:`、`嚴重度:高`)、方括號等級 `[major]`、標題裡嵌等級(`## F1 — BLOCKER`)、破折號接大寫等級——用一支「拒收偵測」正則(放在 `_report_severities` 旁,只用來拒、不用來數;有 `_quote_rows` 的壞格式偵測當先例)掃到就 rc2,訊息列出行號。例外只有三種:引句行(引句:/> 開頭)、圍欄內、總結句(最嚴重/最高/整份/總結/不對齊共/blocking 條數——SOP 本來就要寫);r3 通才席拿 code-batch20 真報告證明「列舉殘留寫法」會漏,所以偵測是泛的、例外是列舉的。
- `reported` = 檔級之後的獨立宣告行數(含 minor、排除 clean),機器寫進帳,沒有旗標可覆蓋;驗收輪留前輪已折平的舊項時不留任何 severity 字樣(SOP)。
- ★被擋也要留痕★(r3 接手席 blocker:rc2 不落帳=永遠看不到「撞牆後沒記」有多少):寫側擋下時往治理帳寫一筆 `canary/rejected`(報告沒正規化 / 缺 refuted-set),`gov --stats` 的「閘的動作」與審查段都印次數,跟 K 對照就看得出有沒有人撞牆後不記。
- 收貨正規化(SOP)因此多一步:架構席那種每一問一行 `- severity: X` 的格式,收貨時去掉列表符號變獨立行;Codex 席的來源註記放檔級行之後。
- 寫側再一條:`--findings`(存活)≤ `reported`。`--findings` 既有語意與 `--light`/`--gate` 對它的 fail-closed 依賴一律不動。
- 代價講明:今天有三種格式在用,上線後這三種都會被擋,編排者收貨時要先正規化(SOP 本來就要求);擋下訊息要能直接照做。

### [S2] 載體列:「編排者重現不到」清單必帶、id 要對到 intake 的重現表列 [test:t_canary_refuted_set]

- 有 `--findings-set` 就★必帶 `--refuted-set`★(跟 folded/accepted 同一種硬擋慣例),值 `none` 表示 0 條;`id=理由` 逗號串,理由 ≥4 字且含實字(沿用 `_MANUAL_MIN_CHARS` 那套門檻)。
- ★對 intake 驗,整字不是子字串★:帶非 none 的 refuted-set 時必帶 `--intake`;每個 id 要在 intake 檔裡有一列同時含「整字的 id」(前後不是英數:`a1` 不因 `a10` 命中——三席拿本案自己的 intake 證過)與 `HIT`/`MISS`/`重現`/`採信` 任一字樣(機械重現表那一列;r3 通才席:既有 intake 不全用 HIT/MISS);對不上 rc2。id 用 intake 重現表的編號。
- 駁回 id 不得與 findings-set 重疊。閘仍不驗重現的對錯(人工判斷);讀側把 R 標成「編排者重現不到(人填,已對 intake)」。
- ★不加 `--self-found-set`★(外家席:它會變成把「席位報了但我不想折」改標成自找的口袋)。編排者自找的發現在讀側由算式推出:S = max(0, M+R−N),印成「存活多於席位報的 S 條(編排者自找或漏併)」,不另設欄位。

### [S3] 讀側:問閘那一輪印一行、全庫一段,缺欄位五格都印「?」 [test:t_gov_stats_review_yield]

- `lumos loop status <編號> --disposal` 尾端(觀測,不進合取;凍結/回放模式照既有慣例不印觀測尾)印★問閘的這一輪★一行:
  「席位報 N(機器數)→ 存活 M / 編排者重現不到 R(人填,已對 intake)→ 折 F / 放行 A;存活多於席位報的 S 條(編排者自找或漏併);這條迴圈累計逃逸 E」。
  N=該輪席位列 `reported` 加總,★同一席同一份報告只算一次★(同席會先留痕一筆、再當載體一筆;以 (auditor, report_sha256) 去重——Codex r3 用今天真帳證明會重複);任何欄位缺(2026-09-09 前的帳)該格印「?」、五格各自判、不拿散文猜數字;★N/M/R 任一是 ? 就不算 S,印「算不了(缺欄位)」★。
  多席同輪時 M/R 只來自唯一載體,席位漏併進載體集合的機器查不到——這是既有處置帳的邊界,intake 逐席對映表是唯一稽核線,段首講明。
- `lumos gov --stats` 新段「審查有沒有用(只算有 `reported` 的 K 輪,2026-09-09 起)」:K、Σ報、Σ存活、Σ重現不到、Σ折、Σ放行、Σ「存活多於席位報」、逃逸筆數與最重等級;
  另印兩個給回頭條件用的數字:「有 findings-set 的輪裡 refuted-set 非 none 的比例」與「存活多於席位報(S>0)的輪數」。K < 5 或近 30 天不到 3 輪時多印「樣本太少,別下結論」(門檻是暫用值,REVISIT 時看)。
- ★段首固定兩句★(disposal 那一行也印縮短版):①「人記的帳跟機器擋的帳(『閘的動作』那段)可信度不同級,不要拿這裡的數字去算那裡的比率」②「N 是機器從報告數的、R 是人填的;這段內部也不印比率、別自己算 Σ折/Σ報 當『審查有用率』」。
- 「駁回」在所有輸出、文件、旗標說明裡一律寫「編排者重現不到」。

### [S4] 逃逸的當下就記:只改 skill,不動 ci-wait [manual:對照 skill diff 人看]

## 實務隱患(r1 折入後)

- **拒收會讓別的 session 記帳被擋**:沒正規化的報告、沒帶 `--refuted-set` 的載體,一上線就 rc2。對策:擋下訊息直接印哪幾行要改成什麼、該帶什麼;兩個 skill 範本與速查表同步改;這正是「有東西逼」的那一半,選填就會重演 0/1216。
- **拒收偵測的邊界**:它只認得列出來的幾種殘留寫法;新的寫法(例如把等級寫成「嚴重度:高」)不會被擋、也不會被數——`reported` 會少算,方向是「低估報幾條」,讀側的 S 會變大而不是變小。
- REVISIT:2026-10-08 跑 `lumos gov --stats` 看「審查有沒有用」段的 K 與「存活多於席位報」輪數,再抽 10 份席報告人工對一次 reported
- **「編排者重現不到」清單靠編排者誠實**:id 對 intake 重現表驗只證明「intake 那一列有這個 id 和 HIT/MISS」,不證明重現做對了——跟逃逸帳同一個天花板,段首寫明;讀側永遠不印比率。
- **選填欄位沒人填的老病**:refute_verdicts 就是前科,所以 S1 由機器數、S2 必帶;沒有任何新的選填欄位。
- REVISIT:2026-11-08 跑 `lumos gov --stats` 看「審查有沒有用」段印的兩個數:refuted-set 非 none 的比例(0% 也是答案:代表沒人重現不到、或沒人記)與 S>0 的輪數;比例低於兩成就回頭看是沒派辯方還是沒記
- **自我治理(self-governance)這一類**:這本帳量的是治理工具自己的審查流程,記帳的人(編排者)同時是被量的人。對策:①報幾條由機器從綁了 sha 的報告數、沒正規化就拒收,編排者填不了、改了報告 sha 就對不上(r2 通才席戳破我 r2 版「雙向夾」是假的——那版守衛單向);②駁回要有 id、對 intake、理由有實字;③讀側不印比率、不進任何閘,沒有「把數字做好看就能過關」的誘因。已排除:自動調參、把這段當閘。
- **兩本帳混算**:段首固定兩句;讀側不印任何比率。
- **併發**:兩個 session 記同一輪只會多幾筆 append-only 的列,讀側加總會重複——這是既有 canary 帳的既有邊界(記帳前查 `loop next`),不在本案。
- **不涵蓋**:「白擋了什麼」(閘誤擋)這一軸——機器帳那邊 `gov --stats` 已有 fail-open/blocked 計數,誤擋要人判,不在本案。
- **效能**:讀側多掃一次 canary 帳(1216 筆、約 1 MB),`gov --stats` 已經在讀它,不另開檔。
