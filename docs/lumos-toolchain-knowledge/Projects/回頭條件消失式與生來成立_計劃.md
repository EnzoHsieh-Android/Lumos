# 回頭條件消失式與生來成立_計劃

白話:回頭條件的條件鍵(`when-file`、`when-symbol`、`when-test`、`when-status`)全是「等某樣東西出現」,沒辦法寫「等某支檔或某段程式不再出現就回頭」。這份計劃加一個條件鍵 `when-gone`。

原本這份也要做第 11 項「寫下時就已成立」(drift scan 對現在成立的條件往回查寫下那一版);設計審三輪每輪都在「往回查歷史」那塊挖出結構問題、而且每次修完又帶出新錯,2026-10-03 Enzo 裁縮案:這份只做 `when-gone`,第 11 項拆到 [[Projects/回頭條件寫下時就成立_計劃]],改用既有的單篇歷史走訪重新設計。檔名保留(卷證與帳本綁著這個編號)。

依據:
- 消費專案清漂移回傳(2026-10-02,第 6 項,去識別):「等某支檔不再直接讀系統時間就回頭」——when-file、when-symbol、when-test 只能等東西出現。建議 `[when-gone:路徑::樣式]`。
- 2026-10-03 乾淨查證員核對現況(唯讀,[[Projects/回頭條件寫法補齊_計劃]] 依據同一次):條件鍵只有四個、全是正向判定;推送時已經會擋「這次新寫(或改了條件)的回頭條件,條件已經成立」(既有測試 `t_drift_when_probes_evaluate_and_trigger` ⑨)。
- 條件文法、評估與推送判定在 [[Projects/存量漂移防線_計劃]]〈做法〉第 0、2 節;家在 [[Systems/存量漂移守衛]]。

PRIOR-ART: 最小解在工具這一層(條件評估本來就在 lumos 的推送判定與 scan 裡)。世界上最接近「等東西消失」的是 feature flag 平台的清理提醒(旗標在程式碼裡已經沒有引用就提示移除)與 Ruby todo_or_die 的條件式到期;都是「某個符號或文字不在了就觸發」,本案照這個形狀,只認明寫的路徑與字面字串,不做樣式或正則(條件要讀得懂、判得穩)。
RETIRE-IF: 上線兩個月後 `when-gone` 零使用(用一次性腳本對兩邊圖譜跑 `_probe_lines` 與 `_retire_lines`,數解析出的 `gone` 條件——含還在等的;不數文件裡的範例——設計審 r3 正確性席:原稿數 `[when-gone:` 字串,本計劃與手冊自己的範例就數不到零;代碼審 r1 正確性席:`drift scan --json` 只列已成立與判不了的,還在等的數不到),拿掉這個鍵。
REVISIT:2026-12-03 用一次性腳本對兩邊圖譜跑 `_probe_lines` 與 `_retire_lines` 數解析出的 `gone` 條件幾條,照 RETIRE-IF 判

## 範圍

- **做**:第 6 項(條件鍵 `when-gone`)。
- **拆出**:第 11 項(寫下時就已成立)——[[Projects/回頭條件寫下時就成立_計劃]]。
- **不做**:樣式、正則、萬用字元的消失條件——只認路徑與字面字串。

## 做法

1. **寫法**:`[when-gone:<路徑>]`——樹上找不到這個路徑就成立;`[when-gone:<路徑>::<字串>]`——找不到這個路徑、或那支檔裡不再出現這段字就成立。
   - 路徑:規矩同 `when-file`(不准 `/` 開頭、不准 `..` 段);反斜線轉斜線與 NFC 正規化**只做在路徑那段**。路徑裡不能有 `::`(從第一個切,天花板 4)。
   - `::` 從**第一個**切(字串裡可以有 `::`);沒有 `::` 就是只有路徑。
   - 字串:照字面、分大小寫,**去頭尾空白**後比對、不能是空的(帶了 `::` 就要有字串);不能含 `]`(標記在第一個 `]` 結束)、換行、反引號(反引號會被可見文字的規矩剝掉,實際比對的不是作者寫的那串)。
   - 沒有不帶路徑的寫法。
   例:`REVISIT:[when-gone:src/instrumented.py::time.time()][by:2027-01-31] 不再直接讀系統時間了,把註解裡的警告拿掉`。
2. **拆值與讀鍵的地方逐一列出**(以 2026-10-03 的程式為準,函式名):
   - `_drift_cond_split(v, k)` 加鍵參數:`gone` 切第一個 `::`、沒有 `::` 回 (路徑, 空字串);其他鍵照舊切最後一個。下面所有拆值都呼叫它,不另寫切法(設計審 r3 架構對齊席)。
   - **值的正規化與驗證收成一支 `_probe_check_value(k, val)`** → (正規化後的值, 錯誤或 None):先用 `_drift_cond_split` 切、只對路徑那段做反斜線轉斜線(既有 `_probe_parse` 對 file/symbol/test 是整串轉,`gone` 的字串不能轉)、驗、再驗一次正規化後的(既有「先驗、正規化、再驗」的順序,擋 `a\..\x.py` 與 `..\x` 這種繞過);`_probe_parse` 與 `_slot_retire_err` 都改呼叫它——RULE 撤除條件現在不轉反斜線、`[retire:when-gone:..\x]` 會被放過,兩條路的要求要一致(設計審 r3 正確性席、邊界席、通才席、架構對齊席);`_probe_value_err`、`_probe_norm_value` 變成它的內部步驟,`gone` 的分支在 `_probe_gone_err` 與 `_probe_norm_value` 的 `gone` 分支,兩者都經 `_drift_cond_split(v, "gone")`。
   - `_probe_named_err`:只給 symbol/test,不動。
   - `_DriftProbeTree.prefetch`、`unread_for`、`one`:帶字串的 `gone` 跟帶路徑的 symbol 一樣預讀、點名、判。
   - `_drift_probe_cond_candidate`:見第 4 點。
   - `_drift_row_unread`:帶字串的 `gone` 點名那支檔。
   - `_drift_probe_path_warn`:`gone` 不提示(找不到是它的正常成立狀態)。
   - `_slot_retire_err`:`gone` 不必另外要求 `::`(它本來就帶路徑),值驗證走 `_probe_check_value`。
   - 反引號:共用解析器拿到的是剝過反引號的文字,所以另寫一支 `_probe_gone_backtick_err(raw)` 看**原文**(原文裡 `[when-gone:` 或 `[retire:when-gone:` 開始、找得到同一個標記的 `]` 才算標記、之間有反引號就報「條件寫錯」;說明文字裡提到 `when-gone:` 不算——代碼審 r1 正確性席;不放進值驗證 `_probe_check_value`,因為那裡拿到的值已經剝過反引號,代碼審 r1 架構對齊席問過)。字串裡也不能有 `[`(標記在第一個 `]` 結束,後面會被默默截掉;代碼審 r1 正確性席),筆記形狀擋的回頭條件檢查(`_ns_revisit_violations`)與格子撤除條件檢查(`_slot_retire_err` 的呼叫端)都呼叫它(設計審 r3 架構對齊席:原稿兩個呼叫端各寫一份)。
3. **評估**(`_DriftProbeTree.one` 多一個分支):
   - **「在」怎麼算**:那一版的樹上這個路徑是一般檔、連結檔或子模組,或它是資料夾(樹上有以 `路徑/` 開頭的條目),都算在;全都沒有才算消失。`_DriftProbeTree` 建樹時多存一份「全部條目」(既有的 `files` 只放一般檔,不動它的意思)。
   - **帶字串**:路徑在、但不是一般檔 → 判不了;是一般檔就另讀原始位元組(既有的 `_read` 讀完會用替代字元解碼成文字,誤讀的內容也會「找不到字串」),`_DriftProbeTree` 加一份位元組快取、走同一次批次讀,單檔上限照既有讀檔上限(超過判不了)。內容含 NUL、是 Git LFS 指標檔(開頭 `version https://git-lfs.github.com/spec/`)、或不能用嚴格 UTF-8(`utf-8-sig`)解碼(Big5 這類沒有 NUL 的舊編碼)→ 判不了;能解碼就在文字裡找字串,找不到 → 成立。
   - **判不了要講對原因**:`_DriftProbeTree` 記下每個 `gone` 條件判不了的原因(不是一般檔、含 NUL、LFS、不是 UTF-8、超過上限、讀不出),scan 與推送判定的「判不了」訊息照這個原因寫,不沿用「git 讀不出程式檔或筆記」那句固定字(設計審 r3 邊界席、通才席)。
   - **工作目錄模式**(`drift scan` 不帶 `--at`):清單照既有的工作目錄讀法,sparse-checkout 沒拉下來的檔、還沒暫存的刪除、被 gitignore 的檔都算消失;NFD 檔名照既有列檔的正規化(天花板 5)。
   - `_drift_probe_one`、`_drift_probe_line` 不動(新鍵走同一支)。
4. **推送判定**:`_drift_probe_cond_candidate` 對 `when-gone` 看路徑在不在這次推送改到的檔裡,或是以它為前綴的資料夾裡有檔被改到;其餘轉變判定照舊。寫下時就已成立的(字串拼錯、檔名寫錯、全形冒號、被 gitignore 的檔——永遠不會在樹上),推送時照既有規矩被點名「這次新寫(或改了條件)的回頭條件,條件已經成立」。**只有這一種**(新寫或改了條件、起點沒有同一條)而且路徑在終點版本就找不到時,點名訊息後面多一句「路徑在這一版就找不到——打錯字、全形符號,或是被 gitignore 的檔?」;這次推送刪掉檔讓條件成立的(起點有同一條)不加這句——刪檔是 `when-gone` 最主要的合法觸發(設計審 r3 正確性席、通才席)。這句加在 `_drift_probe_check` 拿到判定結果之後(判定函式 `_drift_probe_judge` 不認得任何條件鍵,不讓它認得 `gone`;設計審 r3 架構對齊席)。檔被改名或搬家時,舊路徑消失、條件成立,推送會點名(天花板 3)。
5. **列舉鍵的地方由同一張表產生或逐一同步**:`_PROBE_KEYS` 加 `gone`;程式裡的兩句訊息(`_probe_value_err` 的「只有 file、symbol、test、status」、`_slot_retire_err` 的「只收 when-file/…」)從 `_PROBE_KEYS` 組字;筆記形狀擋否定現況句提醒裡「條件怎麼選」那段補一句 `when-gone`。文件裡列鍵的地方逐一改:`skills/lumos-project-notes/commands/03-寫回圖譜.md`(「四種鍵」改寫成不寫死數目的說法)、`skills/lumos-project-notes/reference.md`(撤除條件事件那句)、注入消費專案紀律區塊的範本 `scripts/templates/graph-discipline.md`(RULE 撤除條件機器式那句;範本沒有版本戳,版本由注入當下插值)。範本改了之後在本 repo 跑 `lumos update` 重新注入 `CLAUDE.md` 與 `AGENTS.md` 的紀律區塊(doctor Check D 會守兩邊一致;設計審 r3 通才席、邊界席)。`skills/lumos-project-notes/SKILL.md` 沒有列鍵,不動(r2 稿誤列)。漂移守衛測試掃這兩句程式訊息、提醒那段、上面三份文件,都要提到 `_PROBE_KEYS` 的每個鍵。

## 實務隱患

- **繞過**:`when-gone` 寫一個本來就不存在的字串,推送時被點名「已經成立」——作者可以表態照留繞過;這是明寫的動作、留在表態檔,不另擋。
- **效能**:`when-gone` 帶字串時多讀一支檔的位元組(同帶路徑的 symbol,有預讀,同一次批次讀);推送判定只在那支檔這次被改到時才評估。
- **併發**:只讀 git 物件;不寫帳。
- **回滾**:還原本案的提交:`when-gone` 變成「不認得的條件鍵」——新寫的提交時被擋、已寫的 scan 列成寫錯的條件、推送判定不評估(既有對寫錯條件的處理)。範本與注入區塊照還原後的範本再跑一次 `lumos update`。沒有資料要收。
- **相容**:新鍵只是多認一種寫法,既有四種鍵的判定不變。消費專案要 `lumos update` 之後才認得 `when-gone`,更新前寫了會被舊版擋成「不認得的條件鍵」。
- **跨環境**:評估只看被推送那一版的樹與檔內容;本機與 CI 同一支判定。
- 已排除:金流:只讀筆記與 git 物件
- 已排除:對外送出:不呼叫網路
- 已排除:不可逆:只決定擋不擋、列不列,還原提交就回去
- **守衛面**:推送判定(會擋的閘)多認一種條件鍵——判錯會讓該擋的不擋或不該擋的擋;讀不準的一律判不了(推送時判不了算要處理,既有規矩),用既有的轉變判定與測試守,不新增擋的種類。

## 天花板

1. 提交時不評估條件:新寫的已成立條件要到推送才被點名。
2. 判不了的都靠推送「判不了算要處理」兜底:Big5 這類舊編碼的程式檔,帶字串的 `when-gone` 永遠判不了、每次碰到那支檔的推送都會被點名。
3. `when-gone` 只認字面字串與原路徑:改寫成同義寫法、或檔改名搬家,都算「不再出現」,條件會提早成立——推送時會被點名,作者挑字串時要挑會真的消失的那段。
4. 字串不能含 `[`、`]`、換行、反引號;路徑不能含 `::` 與方括號——Next.js 的 `app/[id]/page.tsx` 這種路徑寫不進任何條件鍵(標記在第一個 `]` 結束;代碼審 r2 正確性席,when-file/symbol/test 原本也會被截斷、對還在的檔誤判,這次一起擋)。
5. 工作目錄模式的 scan 照工作目錄看「在不在」:sparse-checkout 沒拉下來的檔、還沒暫存的刪除、被 gitignore 的檔都算消失;要看提交的狀態用 `--at`。
6. 寫法與讀取的邊角(代碼審 r3 附理由放行):雙反引號包住含反引號的範例(``[when-gone:a::`b`]``)會被誤擋成條件寫錯(偏嚴,改成文字說明就過);git 模式讀不出的檔補問大小沿用剩下的預算、大小會被問兩次(只對讀不出的那幾支)。
