# 結案連帶掃描_計劃

白話:一篇計劃做完、一張 Issue 結案、一條決策被翻案之後,圖譜別處常常還寫著「等它」「待裁定」「排隊中」,結案那篇自己的摘要也還寫「未裁定」、正文還留著沒處理的回頭條件。rtb 第三次全圖譜比對修了 125 筆漂移,其中 29 筆是「修了又壞」,大多是這一類。這次做三件事:①掃出「連到已收尾筆記、同一句還寫待定」的句子,給一條指令補上已裁定的括號;②用工具結 Issue 時,摘要還寫待定、或還有沒處理的回頭條件,就先擋下;③作廢的筆記也跟結案的 Issue 一樣,作廢當下列出回頭條件、到期時標明「已作廢」。

依據:[[Projects/交接2026-10-03_計劃]]〈rtb 第三輪提案〉第 2 優先的 A1、A5、B4。

PRIOR-ART: todocheck(TODO 必須綁 issue 單號,單號關了 TODO 還在 CI 就報錯;它的提案 #57 進一步在關單那一刻、還有綁著的 TODO 就把單重開——等於在結案那一刻擋)對應 A1 的偵測與 A5 的「結案那一刻擋」;adr-tools 的 `adr new -s`(新決策取代舊決策時,工具自動把舊那篇改成「已被取代」並連回新的)對應「翻案後工具主動處理連帶,不靠人記」;Karpathy 的 LLM wiki lint(定期找被新資訊推翻、卻沒跟著改的舊說法)對應 c6 走既有的 drift scan 定期掃。同專案:c2 到 c5 的偵測、表態、修法與修復帳([[Projects/存量漂移改法_計劃]]),計劃收尾時的連帶待辦列出(`_drift_plan_followups`)、Issue 結案時的回頭條件列出(`_issue_close_revisits`)。todocheck 靠的是明確的單號寫法;我們的筆記是散文,所以偵測只認少數明確的待定詞、而且要跟連結在同一個子句裡,換來的是會漏(見〈天花板〉1)。
RETIRE-IF: 連續 8 週 c6 在工具鏈與 rtb 兩邊的 drift scan 都是 0 筆、而且期間沒有人回報同類漂移,就把 c6 偵測與修法撤掉,只留結案那一刻的列出;或 c6 被表態成「不是漂移」的筆數多過被修掉的筆數(誤報多過真的),就改判準或撤掉。

## 範圍

- 做:漂移種類 c6 的偵測(drift scan、doctor 的漂移段、推送前 drift check 的只列出)、表態(drift ack)、修法(drift fix --kind c6)。
- 做:結案、作廢、加決策、翻決策之後,當場列出連到那篇還寫待定的句子(只列出、不擋)。
- 做:drift fix --kind c2 --close 擋「摘要決策行還寫待定」與「還有沒處理的回頭條件」,新增 --decision 與 --keep-revisits 兩個參數。
- 做:作廢(status superseded,任何類型)納入既有的「結案時列出回頭條件」與 doctor E5 的結案標記。
- 做:上線時用新指令修掉工具鏈圖譜現有的 2 筆 c6 與 3 篇已結案 Issue 的待定決策行(〈做法〉7)。
- 不做:`lumos set <Issue> status <結案值>` 擋下——set 是通用的欄位寫入指令,維持只列出(現況),本案把待定決策行也加進它的列出;要擋就用 drift fix --close。
- 不做:已收尾、已結案筆記裡的回頭條件全庫常駐清單(試算 102 行、大多合理,理由見摘要第三行)。
- 不做:rtb 提案的 A3(別篇指向已刪除的回頭條件)、B1、B2 等其他項,另開計劃。

## 做法

1. **c6 偵測**(`_drift_state_findings` 加一段,scan、doctor、check 共用):
   - 「已收尾」:被連的那篇 status 是 done、resolved、wontfix、superseded 之一(任何類型;集中成一個常數)。
   - 「待定詞」:集中成一個常數,只收明確表示還沒定的詞——待裁定、尚未裁定、未裁定、未裁、待決定、尚未決定、還沒決定、還沒做、尚未實作、還沒實作、還沒修、未處置、排隊中、還在排隊、`[todo]`。不收「待辦」「TODO」(試算時「連鎖待辦單」「TODO 註解」這類名詞造成大量誤報)。
   - 「同一子句」:把一行在句號、半形與全形分號、—— 處切開,待定詞跟連結落在同一段才算(全形分號是代碼審 r1 正確性席抓到漏寫的)。
   - 只看來源筆記的正文與 summary 欄位(含寫成單行值的 summary,值只有註解的不算),跳過程式碼圍欄;行內程式碼不剝(首頁索引的 `[todo]` 就寫在行內程式碼裡)。全形引號(「」『』“”)裡的字不算——專案慣例只是在提某個詞就用全形引號包起來。來源筆記本身已收尾的不看(那是歷史紀錄);連回自己的不算。
   - 已裁定括號(「(已裁定:」或全形開頭,配對到收尾的括號為止、算巢狀)整塊當成一個字看:括號裡的分號、——、待定詞與連結都不參與判斷;子句裡有這塊括號就不算待定,同一行別的待定子句照判(補一個不會把整行都算處理掉)。
   - 一行一筆:related 列出這一行裡所有命中的已收尾目標(排序、圖譜內相對路徑)。c6 加進「表態要綁當時清單」的種類(同 c2、c3):表態後又有別的目標收尾,重新列出。
2. **推送前 drift check**:c6 跟 c2 到 c5 一樣只列出不擋;列出的條件沿用現成的——來源那篇這次有改,或 related 裡有一篇這次被改或收尾。
3. **c6 修法** `lumos drift fix <節點> <行號> --kind c6 --settled "<結論>" [--by <節點>] [--date YYYY-MM-DD] [--dry-run]`:
   - 自己判(不要求被連的那篇已收尾,因為加決策、翻決策之後被連的那篇狀態沒變;同 count 種類的先例):那一行要有待定子句而且裡面有連結,沒有就回 2。
   - 待定子句裡連結不只一個時要給 --by 指定是哪一篇,沒給回 2 並列出候選;只有一個就用它。
   - 在待定子句的結尾(下一個切點之前;子句在行尾就是行尾)補 `(已裁定:<日期> <結論>,見 [[<目標>]])`,日期預設今天;連結用解出來的完整相對路徑(去 .md)。長行裡補在行尾會離那句太遠,上線時實際修工具鏈那筆才看出來。
   - 表格行(行首是 |)、開頭欄位裡 summary 以外的行、寫成單行的 summary(值可能帶引號,補進去會弄壞開頭欄位)、同一行有兩個以上待定子句連到同一個目標(一次補不完)、要補的位置落在行內程式碼裡(補進去連結失效)回 2,請人手改;--settled 的括號要成對;那一行已經沒有沒補括號的待定子句回 2。處理到的判準看這個目標還在不在那一行的待定連結裡(同一行連到別篇的待定子句照樣是 c6)。
   - 沿用 fix 的乾淨檢查、寫入鎖、修復帳(記 kind=c6、目標、結論)。處理到的判準:那一行不再是 c6 發現、磁碟內容等於算出的改後內容。
4. **當場列出**(新函式,只印、不擋、不改回傳碼):列出圖譜裡連到這篇、同一子句有待定詞的行(偵測同第 1 點,但不要求這篇已收尾),每行附 c6 修法指令範本。呼叫的地方:
   - `lumos set <任何類型> status <已收尾的值>` 成功之後(main 分派處,跟計劃收尾的連帶待辦、Issue 結案的回頭條件列出同一個位置);
   - `drift fix --kind c2 --close` 成功之後;
   - `lumos decision-add`、`lumos decision-supersede` 成功之後(被加或被翻的那篇)。
5. **drift fix --kind c2 --close 的兩道擋**(都在寫入前判,擋下時一個檔都不寫):
   - 待定決策行:那篇 summary 裡開頭是 DECISION: 而且含待定詞(同第 1 點的常數)的行。有這種行又沒給 --decision → 回 2,列出那幾行與寫法。給了 --decision:新句本身還含待定詞回 2(換了等於沒換);剛好一行就把 DECISION: 後面整段換成「[<今天>] <新句>」(縮排與 DECISION: 不動);好幾行回 2,請人先手改到剩一行;沒有待定行卻給了 --decision 回 2。
   - 回頭條件:那篇還有沒結案的回頭條件(`_revisit_lines`,已寫合格 [closed:] 的不算)又沒給 --keep-revisits → 回 2,列出每一行,說明兩條路:逐行加 [closed:日期 理由],或確定結案後還要回頭量的,用 --keep-revisits "<理由>" 留著。給了 --keep-revisits:照常結案,修復帳記下理由與留下的行號;沒有活的回頭條件卻給了 --keep-revisits 回 2。
   - 結案後原本那段「列出還留著的回頭條件」(`_closing_revisits`,原名 `_issue_close_revisits`)照舊會印(帶了 --keep-revisits 時就是留下的那幾行)。
6. **作廢也算**:
   - `_issue_close_revisits` 改名 `_closing_revisits`,也接「任何類型的筆記改成 superseded」:列出這篇全部沒結案的回頭條件,提示「作廢了,這幾行要搬到取代它的那篇、改成結案說明,或在那一行加 [closed:日期 理由]」。計劃改成 done 照舊不列(已收尾的計劃常刻意留撤除用的回頭條件)。
   - 同一支在 Issue 結案時多列「摘要裡還寫待定的決策行」(只列出)。
   - doctor E5 的到期清單:來源筆記 status 是 superseded 的,行尾加「(這篇已作廢)」,同 Issue 已結案的標法;照樣列、照樣計數。
7. **上線時**:修掉工具鏈現有的 2 筆。Projects/標籤系統精簡_計劃 第 31 行「等檢索核心重建落地後才執行」用 c6 修法補括號;MOC/index 第 44 行是人工維護的索引,錯的是 `[todo]` 標籤本身(檢索核心重建 2026-09-16 收案不落地),直接手改成 `[done]` 與一句結果,比補括號正確。3 篇已結案 Issue 的待定決策行(只退場不痛的機制、外家席長期缺席仍照跑loop、寫下風險當成處理風險)照當時正文的結案內容手改。rtb 那邊由 rtb 會談自己跑 drift scan 處理。
8. **同步文件**:CLI help(drift fix 的 --kind 加 c6、--settled、--by、--decision、--keep-revisits);`skills/lumos-project-notes/commands/` 裡講存量漂移的那頁與 reference.md 指令表;`docs/command-reference.md` 與 `docs/指令參考.md` 的 drift 列;[[Systems/存量漂移守衛]] 的種類清單與這次的 WHY;[[Systems/lumos-cli-write]] 記 decision-add、decision-supersede 之後的列出。

## 實務隱患

- **誤報**:散文判讀一定有。收窄詞表加同一子句是試算過的取捨(工具鏈圖譜 2 筆,兩筆都是真的);c6 只列出不擋推送,誤報可以 drift ack 表態;RETIRE-IF 寫了誤報多過真的就改或撤。
- **擋下結案讓人改走 lumos set 繞過**:set 本來就是通用寫入、維持只列出,列出內容補上待定決策行;drift fix --close 才是建議的結案路徑。這是刻意的天花板,不是漏洞(〈天花板〉3)。
- **修法寫壞筆記**:只在待定子句結尾插一段括號,表格行與摘要以外的開頭欄位直接拒絕;沿用 fix 既有的乾淨檢查與修復帳。
- 已排除:金流:只讀寫筆記與治理帳
- 已排除:對外送出:不連網、不寄送任何東西給外部
- 已排除:不可逆:修法只改筆記文字,修復帳記改了哪幾行,用 git 退
- 已排除:守衛面:推送前 drift check 對 c6 只列出不擋;唯一新增的擋在 drift fix --close 這條手動指令裡,不碰推送閘

## 天花板

1. c6 只認詞表裡的待定詞、而且要跟連結在同一子句;換個說法(例:「之後再看 `[[X]]`」)、或待定詞與連結分在兩行,都抓不到。
2. 一個子句裡只要已經有一塊已裁定括號,整個子句就不算待定;同一子句再連到第二篇已收尾筆記的話,那一篇漏抓(括號補在子句結尾,同一子句連兩篇時補第一篇就要用 --by 指定,寫法上少見)。
3. `lumos set` 結 Issue 不擋,只列出;要擋請用 drift fix --kind c2 --close。
