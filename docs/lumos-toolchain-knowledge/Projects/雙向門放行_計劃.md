# 雙向門放行_計劃

★這篇是**待命草案**:由 [[Projects/規格落成可驗收條件_計劃]] 四輪設計審後拆出(Enzo 2026-09-17 裁「拆兩份、先上半套」),**沒有過審、不落地、不派審**。它保存「雙向門不派審、只跑條款」整套設計與四輪 95 條折入的結果,等半套(句式+綁定+跑紅)跑過 30 份計劃、且 [[Projects/逃逸自動記_計劃]] 的對回率過關,才開迴圈重審。開審時本篇要先重新凍結、重派六席,r1–r4 的卷證只當背景。★

白話:做錯能退回的計劃(雙向門)不派人審、只讓機器跑條款;做了回不去的(單向門)才派人。誰是雙向門由機器判、作者只能往嚴格調;放行留痕;逃逸帳按門分開量;三條絕對門檻決定整套要不要退回。

RETIRE-IF: ①任何一份雙向門計劃出現 blocker 級逃逸 → 立刻退回 ②前 30 份雙向門計劃裡 major 以上逃逸 ≥3 份 → 退回 ③`push-gate-unreviewed` ≥2 份 → 門判定規則重審(三個數字是拍的,正當性只來自它們自己會收斂)
開工條件:半套上線 90 天且過 30 份計劃;逃逸自動記 RETIRE-IF ① 的對回率 ≥ 五成;本篇重新過設計審。

**硬單向門(機械、不可申辯,任一命中即是)**:
1. 關鍵字表命中四類任一——**掃描範圍=計劃全文,只跳過「實務隱患」節內、且形如 `已排除:<四類中文名>:<理由>` 的合格行**(r1 正確性席:四行已排除本身就含類別名,不跳過會把雙向門全部打回單向,機制自我否決)。**r2 正確性/邊界席抓到 r1 的補丁堵了觸發沒堵範圍**:只認「已排除:」字首、不限節、不限類,任何人在任何段落寫一行「已排除:這段其實在講 DELETE FROM」就能把那行洗出掃描——本篇自己實務隱患節的「已排除:效能」「已排除:多人並行」就是不在四類卻會被跳過的實例。**判定(跳不跳)與證明(算不算四行之一)共用同一支解析 `_excluded_line(line)`**:去前綴借既有條款行解析器同一個前綴正則(`_CLAUSE_LEAD_RE` 那組字元集:空白、`-`/`*`/`+`/`•`/數字與 `)`/`.`/`、`、引用符 `>` 含多層——r3 架構對齊席:自己再列一套窄的是第二種做法);冒號半形全形都收;類名不在四類、或不在實務隱患節 → 不是合格行,照掃(r2 邊界席:縮排/引用塊/全形冒號的變體否則會讓自我否決復發)。**「實務隱患節」的邊界定死(r3 正確性/邊界席 blocker:兩輪都在修「這一行算不算」,沒人定義「這一段算不算」;vault 裡標題有 8 種變體如「## 實務隱患(逐類答)」「## 五、實務隱患」)**:只認二級標題 `##`,標題去掉序號前綴(「五、」「5.」)與括號後綴後以「實務隱患」開頭;節的範圍到下一個 `##` 或 `#` 標題(三級標題屬於節內);同名節有多個就全部算;fence 內的行照 `_visible_lines` 規則不算(共用函式 `_section_lines(text, 標題)`,S29 綁測試)。光是討論這些詞仍會命中,誤判代價只是多一次審查,接受。
2. 計劃連到的節點(`related`、`lands_in`、正文 `[[連結]]`)帶 `★IRREVERSIBLE★` 或 `★CHECKPOINT★` 合約行,或掛任何 `risk/` 標籤。**這條走的是合約行掃描那一支**(`cmd_contracts`/`IRREVERSIBLE_RE`/`CHECKPOINT_RE`),不是關鍵字表——r1 接手席抓到「要動什麼」表漏列這個依賴。
3. 作者在開頭欄位寫 `door: one-way`(`door` 要登記進已知欄位清單,否則 lint 只軟提醒)。

**雙向門的條件(全部滿足才算)**:硬單向門三條都沒命中,**且**「實務隱患」節裡對四類各有一行 `已排除:<中文類名>:<理由>`(半形或全形冒號都收;理由 ≥4 字含實字;類名必須是上表的中文名,不收英文鍵)。缺任何一類 → 當單向門,閘印出缺哪一類。

**★這四行通常是 AI 自己寫的——這是自我認證,沒有獨立性(Enzo 2026-09-17 裁:不補人簽門、不派模型看,靠逃逸帳事後量)★**。代價寫明:門判定變成「AI 說它退得回,就當它退得回」,唯一的糾錯是第五節的逃逸帳與第六節的退場條件。為了讓逃逸能追責,規格閘留痕時**要把那四行排除理由一起記進帳**。

作者寫 `door: two-way` 沒有意義(不會比機械判定更鬆);寫 `door: one-way` 有意義(直接硬單向)。

### 三、綁定規則

- **雙向門**:每條條款只准 `[test:<測試名>]`,測試要真的存在——存在性走 `_clause_bindings_for`(處置閘第五步實際呼叫的那支;初版寫 `_classify_one` 是錯的,那支判的是 ★INVARIANT★ 合約行)。**每條條款的測試名必須互不相同**(r1 邊界席:十條全綁同一支也能過「全部存在」)。出現 `[manual:]` 就擋,訊息直接說「要嘛綁測試,要嘛把門升成單向」。
- **維持既有行為型的條款**加 `[keeps]` 標記,表示「這條綁的是既有的綠測試、防回歸用」;沒有標記的條款一律視為新行為,其測試在規格閘時必須是紅的(見第四節)。**標記的形狀定死(r2 邊界席)**:半形小寫 `[keeps]`,在同一定義行任意位置,收進 `[test:]`/`[manual:]` 同一個標記家族(`INV_TAG_RE`)解析——**那支正則現在沒有 `keeps` 分支(r3 邊界席 blocker:「同一家族」在程式現況是假的),落地要加一個裸標籤分支,列在「要動什麼」**;`[Keeps]`、全形括號等變體一律當沒標(=新行為要紅),閘印一句「看到疑似 keeps 變體」。**★全標 keeps 的後門(r2 正確性/邊界席 blocker)★**:S6 只驗「沒標 keeps 的每一條要紅」,十條全標 keeps 就是空集合恆真、零支紅直接放行。堵法兩條都要:①雙向門計劃**至少一條未標 keeps**(零條新行為的計劃不該走規格閘——那是純重構,走代碼審);②標 keeps 的測試**必須在計劃建立當天之前的提交樹裡就存在於同一支測試檔**:取測試檔在 `created` 日期之前的最後一次提交(`git log -1 --before=<created> --format=%H -- <測試檔>`),`git show <那個 sha>:<測試檔>` 裡要有 `def <測試名>`;找不到提交、或那版沒有這個名字 → 不合格擋下並印原因。**r2 寫的 `git log -S` 首次出現日期是錯的(r3 正確性席 blocker)**:pickaxe 搜整個歷史、不限路徑、不驗至今存活——把樁測試取一個古早被刪掉的測試名就繞過;看「那一天的樹裡有沒有」不看「歷史上出現過沒有」才擋得住,squash 也不影響(看樹不看首次出現;r3 邊界席)。改過名的測試視為新測試(擋下,訊息說「改名要先把新名字提交進歷史再標 keeps」);未提交的測試找不到 → 擋下。**三層(每條紅/至少一條未標 keeps/既存性)各防不同攻擊面,不合併**(r3 簡化席核可:拿掉任一層都重開一個已知洞)。
- **單向門**:`[test:]` 或 `[manual:≥4 字含實字]` 照舊;**計劃必須有「## 回退」節,內容 ≥20 字含實字**(r1 邊界席:「非空」會被一個標點放行)。
- **關鍵取捨**:雙向門不准 manual 是整套的核心張力。綁不上測試=這條寫得不夠清楚,或這份計劃其實是單向門。

### 四、新閘 `lumos spec-gate <計劃.md>`(印法照處置閘)

1. **門**:單向/雙向,哪個訊號命中(或缺哪一類已排除)。
2. **句式**:幾條合格、幾條看不懂、有沒有複合觸發。
3. **綁定**:缺幾條、manual 違規幾條、測試名重複幾條、回退節有沒有且夠長(單向門)。
4. **跑**:把綁定的測試真的跑一次(沿用 `.lumos/config.json` 的 `test.run_cmd`)。**前提:run_cmd 必須帶 `{method}` 能鎖單支**,沒有就擋下並印怎麼改——整套聚合退出碼歸因不到條款,跟 guard-kill 那支把它標成弱證據(`killed_unattributed`)是同一件事,規格閘不收弱證據(r1 邊界席)。
   **「紅」的判準(r2 邊界席:斷言為假跟指令跑不起來在退出碼上長一樣)**:解析測試工具輸出裡的支數(unittest 的 `Ran N test(s)`、pytest 的 `N failed / N passed` 相加),**N==1 且失敗才算紅;N==0**(匯入錯、檔名錯、環境缺)是弱證據,擋下並印原因,不當紅也不當綠;**N≥2**(r3 正確性席:參數化、同名不同類、`-k` 子字串撞名)也擋下,印「篩選匹配到 N 支,測試名要唯一,換更長的名字」。**PRIOR-ART 訂正(r3 邊界/簡化席)**:r2 寫「借 [[Systems/bound-tests-gate]]」是錯的——那支 `_ran_evidence_check` 自己的註解就寫「證的是有東西跑過,不是跑的是你要的那一支」,只認有沒有出現 `N passed`、不解析數字;解析支數是**新寫的判準**,不是借來的。**真殘餘寫進殘餘段**:本 repo 的 `run_cmd` 是 `-k` 子字串比對,967 支測試裡有 158 組名字互為子字串(簡化席機械數),那些名字的條款在規格閘會被 N≥2 擋下——這是逼作者改名,不是閘壞掉。
   **雙向門放行的條件**:①至少一條條款(零條款一律擋——r1 邊界席:空集合走 `all()` 會放行一份什麼都沒驗的計劃)且**至少一條未標 keeps**(r2)②每條綁定的測試都存在且名字互不相同 ③沒標 `[keeps]` 的每一條,其測試現在都是紅的;標了 `[keeps]` 的可以綠但要通過第三節的既存性檢查。**「至少一支紅」改成「每條新行為各自紅」**(r1 正確性/邊界/簡化三席:一支樁測試就能讓一批不相干的條款集體過關)。**成本誠實寫(r2 簡化席)**:這是把寫測試的工搬到設計審之前——一份八條條款的計劃要先寫八支會紅的測試;S13 健檢要順便印「每份雙向門計劃的條款數與紅測試數」,RETIRE-IF ② 的訊號出現時才分得清是規則太嚴還是沒空。
- **殘餘(寫明,不假裝解掉)**:「綁一支永遠失敗的樁測試」機械上仍擋不住;本 repo 既有的處置是代碼審與 guard-kill 殺傷力驗證,規格閘不重做。「先另開一個不相干的提交預埋樁測試、之後再標 keeps」(r3 簡化席)機械上也擋不住,靠第六節逃逸帳事後量。「鎖單支」靠 `-k` 子字串是做不到的(見上),靠 N≥2 擋下逼改名。
- 雙向門四步全過 → 印 `PASS(雙向門):直接實作,不派審`,**留痕走既有審查帳寫入口 `cmd_canary`,把 `kind` 的封閉列舉擴充一個 `spec-gate`**(r1 架構席:不准繞過寫入口另開路徑;讀側 `_round_valid_m2` 也要認得這個 kind),記錄帶 `door`、四行排除理由、**全部 `[test:]` 名稱清單**、**條款區塊的指紋**(全部 `[S]` 定義行正規化後串起來的 sha256,不是整檔——r3 邊界席:整檔會被 `updated:` 欄位挪動這種跟條款無關的維護弄成過期;r2 接手席:留痕後計劃被改、條款改名,推送閘會對舊測試名下手)與**門判定規則版本 `door_rule`**(整數常數 `_DOOR_RULE_VERSION`,初值 1;改到 `PITFALL_CLASSES`、合約行掃描、已排除規則任一支就 bump,代碼審看;S32 綁測試——r3 接手/簡化席:沒條款、沒初值、沒改版判準就是指引不是機制)。留痕帶 `loop`、不帶 `round`。**讀側(r2 簡化席 blocker)**:`_round_valid_m2` 是處置閘「兩席有效」的安全謂詞,`spec-gate` 記錄**不計入分子、也不讓那一輪判無效**——直接塞進白名單元組會把「兩份真 canary」稀釋掉;接手席數到 `scripts/lumos` 裡 10 處硬寫 kind 白名單的讀側(r3 接手席重數),**S28 涵蓋全部讀側**(r2 寫 S23 是抄錯編號):計數型讀側不計入、判定型讀側不因它判無效,測試對每處各餵一筆。取門時看**最新一筆** spec-gate 留痕(程式現況 `_door_for_loop` 就是覆寫到最後一筆,r2 邊界席:文件要寫明)。

### 六、退場條件(先寫死,結果出來前不改)
