# 雙向門放行_計劃

★2026-09-17 落地(Enzo 裁「另外一半,雙門準備開工」「做出來在模擬測試就好」,見 d1):不等草稿寫的 30 份計劃,直接實作、每條條款綁 fixture 測試(23 支,scripts/test_lumos.py 的 t_spec_gate_door_* / t_spec_gate_twoway_* / t_prepush_spec_gate_* / t_doctor_escape_by_door 等)。下面「設計」一節是四輪設計審後的草稿原文,**以「落地紀錄」一節與 [[Systems/規格閘]] 的 KEY 行為準**;草稿與落地不同之處逐條列在落地紀錄。★

白話:做錯能退回的計劃(風險低)不派人審、只讓機器跑條款;做了回不去的(風險高)才派人。誰是風險低由機器判、作者只能往嚴格調;放行留痕;逃逸帳按門分開量;三條絕對門檻決定整套要不要退回。

RETIRE-IF(小改動閘,2026-09-17 加):全靠人驗的風險低計劃前 20 份裡,被小改動閘擋下的比例 >50%(規則太緊、大家乾脆升單向)或逃逸帳出現 ≥2 筆歸到它們(規則太鬆)→ 重審四維度的數字。
RETIRE-IF: ①任何一份風險低計劃出現 blocker 級逃逸 → 立刻退回 ②前 30 份風險低計劃裡 major 以上逃逸 ≥3 份 → 退回 ③`push-gate-unreviewed` ≥2 份 → 門判定規則重審(三個數字是拍的,正當性只來自它們自己會收斂)
開工條件(原草稿):半套上線 90 天且過 30 份計劃;逃逸自動記對回率 ≥ 五成;本篇重新過設計審——★2026-09-17 Enzo 裁提前開工(d1),三條都沒等;代價是零真實風險低計劃實證,糾錯全靠上面的 RETIRE-IF 與 doctor S14★。

## 小改動閘(2026-09-17,Enzo 裁「小改動不至於要綁測試」「行數太 low,看 AWS/Meta/學術怎麼判」)

風險低改成收 `[manual:]`。一份計劃一支測試都沒有(全靠人驗)時,放行照舊、留痕標 `manual_only`,推送前不跑測試改跑**小改動閘**:四個維度全部成立才放行,任一不成立就擋並說是哪一維、怎麼辦(補測試、縮小改動、或升成風險高走設計審)。

PRIOR-ART:Amazon 單風險低判的是可逆與後果,不給大小數字;Meta RADAR/DRS 自動放行低風險 diff 走「資格閘(SOX、開源、code freeze、CI 綠、作者資歷、檔名前後綴黑名單、黑名單字串)→ 靜態啟發式 → ML 風險分數(按百分位)→ LLM 審(信心 ≥8/10)→ 確定性驗證」,公開文件沒有行數上限,放行 diff 的事故率是人審的 1/50;Google 每個改動都審、100 行合理/1000 行太大;學術(Mockus & Weiss 2000、Kamei 2013 十四指標、2022 重評估)最能預測出事的是擴散度(檔數/目錄/子系統/熵)、相對變動量、歷史(近期改動者數、是否修 bug、檔齡)與經驗,簡單的檔數與人數就很強。

| 維度 | 判準(常數 _SMALL_CHANGE,規則版本 _SMALL_CHANGE_RULE_VERSION=1) | 借自 |
|---|---|---|
| 擴散 | 碰的程式檔 ≤5、目錄 ≤2,而且每支都在計劃落點(lands_in/related 節點的 about_code)內;帳本/卷證/筆記不算 | Kamei NF/ND;落點內是本工具鏈獨有的資訊 |
| 相對量 | 每檔 (新增+刪除) ≤ 原本行數 20%,或絕對 ≤300 行(二擇一成立即可) | Kamei 相對 churn;300=Google 100 行的三倍寬鬆 |
| 歷史 | 落點沒 risk/ 標籤(門判定已擋)、碰的檔不是裁判檔(錨點清單、scripts/hooks/)、近 90 天逃逸帳沒有歸到同落點的列 | Meta 檔名黑名單與「出過事的來源封鎖」;Kamei 歷史維度 |
| 目的 | 計劃不連 Issues(修 bug 的缺陷率高於新功能) | Kamei FIX |

候選對回:只有這次改動碰到該計劃的檔或它落點的檔,那份計劃才是候選;只碰落點外的檔的提交對不回任何計劃,不會被這道閘看到(誠實界線:落點外要跟落點內的檔在同一次改動裡才抓得到)。數字全是拍的,RETIRE-IF 在上面。

- **維持既有行為型的條款**加 `[keeps]` 標記,表示「這條綁的是既有的綠測試、防回歸用」;沒有標記的條款一律視為新行為,其測試在規格閘時必須是紅的(見第四節)。**標記的形狀定死(r2 邊界席)**:半形小寫 `[keeps]`,在同一定義行任意位置,收進 `[test:]`/`[manual:]` 同一個標記家族(`INV_TAG_RE`)解析——**那支正則現在沒有 `keeps` 分支(r3 邊界席 blocker:「同一家族」在程式現況是假的),落地要加一個裸標籤分支,列在「要動什麼」**;`[Keeps]`、全形括號等變體一律當沒標(=新行為要紅),閘印一句「看到疑似 keeps 變體」。**★全標 keeps 的後門(r2 正確性/邊界席 blocker)★**:S6 只驗「沒標 keeps 的每一條要紅」,十條全標 keeps 就是空集合恆真、零支紅直接放行。堵法兩條都要:①風險低計劃**至少一條未標 keeps**(零條新行為的計劃不該走規格閘——那是純重構,走代碼審);②標 keeps 的測試**必須在計劃建立當天之前的提交樹裡就存在於同一支測試檔**:取測試檔在 `created` 日期之前的最後一次提交(`git log -1 --before=<created> --format=%H -- <測試檔>`),`git show <那個 sha>:<測試檔>` 裡要有 `def <測試名>`;找不到提交、或那版沒有這個名字 → 不合格擋下並印原因。**r2 寫的 `git log -S` 首次出現日期是錯的(r3 正確性席 blocker)**:pickaxe 搜整個歷史、不限路徑、不驗至今存活——把樁測試取一個古早被刪掉的測試名就繞過;看「那一天的樹裡有沒有」不看「歷史上出現過沒有」才擋得住,squash 也不影響(看樹不看首次出現;r3 邊界席)。改過名的測試視為新測試(擋下,訊息說「改名要先把新名字提交進歷史再標 keeps」);未提交的測試找不到 → 擋下。**三層(每條紅/至少一條未標 keeps/既存性)各防不同攻擊面,不合併**(r3 簡化席核可:拿掉任一層都重開一個已知洞)。
- **風險高**:`[test:]` 或 `[manual:≥4 字含實字]` 照舊;**計劃必須有「## 回退」節,內容 ≥20 字含實字**(r1 邊界席:「非空」會被一個標點放行)。

### 四、新閘 `lumos spec-gate <計劃.md>`(印法照處置閘)

1. **門**:單向/雙向,哪個訊號命中(或缺哪一類已排除)。
2. **句式**:幾條合格、幾條看不懂、有沒有複合觸發。
3. **綁定**:缺幾條、manual 違規幾條、測試名重複幾條、回退節有沒有且夠長(風險高)。
4. **跑**:把綁定的測試真的跑一次(沿用 `.lumos/config.json` 的 `test.run_cmd`)。**前提:run_cmd 必須帶 `{method}` 能鎖單支**,沒有就擋下並印怎麼改——整套聚合退出碼歸因不到條款,跟 guard-kill 那支把它標成弱證據(`killed_unattributed`)是同一件事,規格閘不收弱證據(r1 邊界席)。
   **「紅」的判準(r2 邊界席:斷言為假跟指令跑不起來在退出碼上長一樣)**:解析測試工具輸出裡的支數(unittest 的 `Ran N test(s)`、pytest 的 `N failed / N passed` 相加),**N==1 且失敗才算紅;N==0**(匯入錯、檔名錯、環境缺)是弱證據,擋下並印原因,不當紅也不當綠;**N≥2**(r3 正確性席:參數化、同名不同類、`-k` 子字串撞名)也擋下,印「篩選匹配到 N 支,測試名要唯一,換更長的名字」。**PRIOR-ART 訂正(r3 邊界/簡化席)**:r2 寫「借 [[Systems/bound-tests-gate]]」是錯的——那支 `_ran_evidence_check` 自己的註解就寫「證的是有東西跑過,不是跑的是你要的那一支」,只認有沒有出現 `N passed`、不解析數字;解析支數是**新寫的判準**,不是借來的。**真殘餘寫進殘餘段**:本 repo 的 `run_cmd` 是 `-k` 子字串比對,967 支測試裡有 158 組名字互為子字串(簡化席機械數),那些名字的條款在規格閘會被 N≥2 擋下——這是逼作者改名,不是閘壞掉。
