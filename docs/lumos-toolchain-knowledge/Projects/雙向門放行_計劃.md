# 雙向門放行_計劃

★2026-09-17 落地(Enzo 裁「另外一半,雙門準備開工」「做出來在模擬測試就好」,見 d1):不等草稿寫的 30 份計劃,直接實作、每條條款綁 fixture 測試(23 支,scripts/test_lumos.py 的 t_spec_gate_door_* / t_spec_gate_twoway_* / t_prepush_spec_gate_* / t_doctor_escape_by_door 等)。下面「設計」一節是四輪設計審後的草稿原文,**以「落地紀錄」一節與 [[Systems/規格閘]] 的 KEY 行為準**;草稿與落地不同之處逐條列在落地紀錄。★

白話:做錯能退回的計劃(雙向門)不派人審、只讓機器跑條款;做了回不去的(單向門)才派人。誰是雙向門由機器判、作者只能往嚴格調;放行留痕;逃逸帳按門分開量;三條絕對門檻決定整套要不要退回。

RETIRE-IF: ①任何一份雙向門計劃出現 blocker 級逃逸 → 立刻退回 ②前 30 份雙向門計劃裡 major 以上逃逸 ≥3 份 → 退回 ③`push-gate-unreviewed` ≥2 份 → 門判定規則重審(三個數字是拍的,正當性只來自它們自己會收斂)
開工條件(原草稿):半套上線 90 天且過 30 份計劃;逃逸自動記對回率 ≥ 五成;本篇重新過設計審——★2026-09-17 Enzo 裁提前開工(d1),三條都沒等;代價是零真實雙向門計劃實證,糾錯全靠上面的 RETIRE-IF 與 doctor S14★。

### 四、新閘 `lumos spec-gate <計劃.md>`(印法照處置閘)

1. **門**:單向/雙向,哪個訊號命中(或缺哪一類已排除)。
2. **句式**:幾條合格、幾條看不懂、有沒有複合觸發。
3. **綁定**:缺幾條、manual 違規幾條、測試名重複幾條、回退節有沒有且夠長(單向門)。
4. **跑**:把綁定的測試真的跑一次(沿用 `.lumos/config.json` 的 `test.run_cmd`)。**前提:run_cmd 必須帶 `{method}` 能鎖單支**,沒有就擋下並印怎麼改——整套聚合退出碼歸因不到條款,跟 guard-kill 那支把它標成弱證據(`killed_unattributed`)是同一件事,規格閘不收弱證據(r1 邊界席)。
