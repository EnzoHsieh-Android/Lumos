# 標註刷新_計劃

> 白話:我們有一份考自己搜尋功能的考卷,答案是人批過的金標。但筆記庫一直長大,新筆記沒批過答案,照「沒批=算錯」的規則,筆記庫一更新分數就崩——上次崩過一次只好把考卷凍在舊庫上。本案的解法:庫更新時**只補批新出現的題**(不整本重批)、補批走現成的雙評審流程(Claude+Gemini,吵架人裁)、沒補完機器擋住不准換庫、再加一顆「該補批了」的警示燈。

## 緣起(事故帳)

2026-08-08 補鏈四筆後依 r1 協定重釘快照至 ab910519:P@8 0.713→0.447、hook 固定席噪音 77 條——新快照拉進 7/20 後全部未標節點,依「未標=噪音」規則淹沒指標。裁定回退 285d429,corpus_revision_note 明言「語料前進須配套標註刷新(另立 labeling 計劃)」。本案補此前置;紅燈(hook P@8 0.6944 差 0.0056)的後續改善全被此鎖死。

## PRIOR-ART

`PRIOR-ART: borrow-design(TREC pooling/incremental qrels + 自家 rater 協定)`——檢索評測界標準解:語料/系統前進浮出未判文件→delta 補判;「未判=不相關」為已知偏差,bpref/condensed-list 等改尺方案因會使既有門檻數字全失效而拒。補標協定的**判準與輸出格式**沿用 `governance/eval/raters/rater-instructions.md`(0/1/2 判準+純 JSON 輸出+仲裁 by/why);執行與放行機制經 r1 審計擴充(B 席換 Gemini、一致=同值、degraded 退化、批次級放行介面、labeled_at 欄位——見 S2),非僅換執行器。

## 規格

### S0 共同定義(r1 折入:母體與三態,全案唯一口徑)
- **評測母體=計分觸及集(2026-08-18 落地後發現修正)**:search 題=兩臂(legacy/ranked)**各前 10**;edit 題=free **前 k(=8)**+**全部固定席**(pinned 不受名額限制,事故指標 pin_noise 全涵蓋;★與 `impact --top 50` 的關係:50 是候選撈取窗(供排序與固定席浮出),計分與未標判定只摸 free 前 8+pins,撈取窗≠母體★)。★不是 build_goldset 的出卷小池,也不是全召回母體——r1 折入的「legacy 不截斷∪top50」口徑實測連原快照都 54% 未標(399/738;金標只批過出卷小池)→ repin 永不可過;收斂到「未標了會實際影響分數」的位置後,原快照殘餘 13.7%(53 筆=出卷池與觸及集的邊界欠帳,成為第一批 delta)★。S1 的 delta、S3 的斷言、S4 的 rate,一律以此為準(單一實作=collect_unjudged)。
- **標註三態**:`已判`(labels 有鍵且 final∈{0,1,2})/`未標`(labels 無此鍵,或有鍵而 final 為 null)/`從未入池`不另立——以評測母體為準,母體內非已判即未標。★禁止沿用 `_labels_of`/`unl` 的收斂讀法(它們把未標與已判0 混成同一值)★。
- **題目凍結**:delta 模式只讀 goldset 既有 `search`/`edit` 題目陣列,★禁重呼 `edit_cases()`★(它按當前 HEAD 的 git log 選題,語料前進題目就漂)。edit 題的 file 已刪除/改名→該題標 `skip:file-gone` 列清單,不炸不猜。
- **歷史快照重放**:對非工作樹語料算池/算母體,一律借 `retrieval_eval.py` 既有 worktree 釘定機制(`git worktree add --detach <tmp> <sha>` 後把 vault 指過去);S1/驗收的「重放 ab910519」即走此路(r1:原「目標語料=當前工作樹」與重放驗收互斥,以此修正)。

### S1 delta 出卷
- 新腳本 `governance/eval/refresh_labels.py`(獨立於 build_goldset,rc 語意乾淨;r1:CLI 介面明名)——`python3 refresh_labels.py delta [--snapshot <sha>] [--json]`:對目標語料(預設當前工作樹;--snapshot 走 worktree)算**評測母體**,與 labels diff → 未標清單 → 產 delta 標註表(沿 sheet 格式,僅未標列,卷頭註明「本卷為 delta 片段,案例不連號屬正常」)+ 機器可讀 JSON。
- 已判候選不重出(金標不重批)。同時列**孤兒已標鍵**(labels 有、目標語料查無此節點——rename/刪除產物)供人工遷移;rename 的機械同步=v2 不做(範圍刀),孤兒偵測進 v1。
- **裸跑防護(r1)**:`build_goldset.py` 全量重建改為需 `--force-full` 旗標;無旗標=印 usage rc2。現況裸跑會把 429 筆金標整本清空(main() 無條件 `{"final": None}` 重建+覆寫),此雷必須先拆。

### S2 補標(雙評審+人閘)
- A 席=乾淨 Claude agent、B 席=Gemini(`gemini -m <flash 現行版> -p`,headless;★刻意不鎖版跟隨現行 flash——rater 漂移風險已列實務隱患,鎖版反而累積落後★),同一份 rater-instructions(判準一句話:2=必看/1=有用/0=噪音;權威全文在該檔);各產 `rater-{claude,gemini}-delta.json`。
- **一致=同值**(0/1/2 完全相等;1 vs 2 =不一致)。一致 → 列入「建議 final」(final=一致值,免逐筆人裁);不一致 → 逐筆人裁(deep-read;裁決寫進 goldset labels 的 `by`/`why` 欄位——★此為 goldset labels 既有慣例(82 筆實證),與 adj-verdict-*.json 的 `v`/`why` 是兩個工件各自沿用,不混★)。B 席票寫 `gemini` 鍵(沿 claude/codex 慣例);每筆併入時寫 `labeled_at`(ISO 日期,新欄位;舊標無此欄=mtime 比對豁免)。
- ★整批 merge 進 goldset `labels` 前必經人放行(批次級人閘)——一致案免的是逐筆裁決,不免整批放行★。**放行介面(r1)**:diff 預覽(逐筆 node/建議 final/兩席原值)+不一致筆全列;放行動作=人跑 merge 指令並留 signoff 一句,防盲簽。
- **B 席斷供退化(r1,機制明文)**:B 席輸出檔缺/JSON 壞 → 該輪標 `degraded:single-rater`,A 席全部結果進「人裁」桶(無一致快速路),流程不 crash;協定其餘不變。
- **寫入紀律(r1)**:goldset 一律 tmp+atomic rename;單寫者約定——寫 goldset 只有「人放行的 merge 流程」一個入口,自動排程(S4)只讀 goldset、只寫 delta 表。
- 免費額度界線:Flash 日 250 req;批量以實測為準(2026-08-18 首測:現行全量欠帳 53 筆/held 21 筆;歷史重放 ab910519 為 401 筆——大批次分日跑或 batch 化)。

### S3 重釘機械閘
- `refresh_labels.py repin`:斷言目標語料**評測母體** `unjudged == 0` 才寫入 `snapshot_commit`;否則 **rc1 硬擋**並吐 delta 清單。★rc 語意為本腳本權威(0=已重釘/1=有未標硬擋/2=輸入壞),不沿用 retrieval_eval 的「rc1=調參軟訊號」慣例——消費端「不看 rc」的既有豁免(autonomous-loop.sh 明文)只適用 retrieval_eval,不適用本腳本(r1:同 rc 碼兩語意必須分腳本承載)★。
- 過渡:重釘當週新舊快照各跑一輪考卷。**可區分機制(r1)**:history 每筆新增 `goldset_snapshot` 欄位(=該輪使用的 snapshot_commit);`retrieval_eval.py` 加 `--snapshot <sha>` 覆寫旗標供跑舊快照;過渡的舊快照輪以 `mode: goldset-transition` 寫入(`mode` 為 history 既有欄位,現值如 `goldset`;transition 為新增值)——autonomous-loop「取最後一筆 goldset 列」的判定不受干擾。`corpus_revision_note` 記轉場一句話(goldset 檔層級的敘述,不當 history 逐行標記用)。

### S4 未標率常設訊號
- `retrieval_eval.py` 每輪對**評測母體**算 unjudged rate(分母=held split 全題評測母體候選數彙總,search/edit 合計;分子=其中未標數;train 不計)並印出+寫入 history(`unjudged_rate`/`unjudged_count` 兩欄)。
- 週閘 wrapper=`governance/autonomous-loop.sh` 週期考卷段(現呼叫 `retrieval_eval.py --goldset … --split held` 處):**unjudged_count > 0 即在日誌報數值**;超通知線(★暫定 10%,尚未正式校準——2026-08-18 首測 12.6% 亮燈屬預期真欠帳;首輪補標清零後以常態值重定★)→ 自動產 delta 表(呼叫 refresh_labels.py delta)+ LINE 通知(line_notify 既有範式:token 讀 ~/.config/ai-daily/line_token、訊息=表路徑+補標流程指針)→ 等人放行補標。★死區澄清(r1):10% 是「通知升級線」不是「唯一亮燈線」——任何 >0 在每輪考卷日誌都可見,且真要重釘時 S3 出口必吐 delta 清單,1–9% 區間不存在「無預警被擋」(擋的當下就拿到待辦清單)★。

## 刻意不做(記帳防回鍋)
- 改指標語意(bpref/只算已判):既有門檻與歷史分數全失效,拒;未標靠 delta 補標消滅,不靠改尺。
- 變更節點重標:節點內容改動後舊標註可能過期——v1 僅列「mtime > labeled_at」清單軟提醒,不阻塞重釘。★殘留風險明文(r1):S3 綠=無未標,不保證舊標仍新鮮;此風險 v1 承受,靠軟提醒+人裁抽查兜底★。
- rename 機械同步:v1 只做孤兒已標鍵偵測+人工遷移(遷移=直接編輯 goldset json 把舊路徑鍵改新路徑,git diff 可審;無輔助腳本 v2 再議),goldset 鍵隨 rename 自動改寫=v2。
- 無人放行即入金標:人閘不可拆——兩席一致只買「免逐筆裁決」,整批 merge 仍必經人放行(pbt-oracle 教訓:自動生成+自動採納=maker bias 閉環)。
- Pro 付費仲裁:量小人裁更獨立;量大再開 billing($2/$12,一輪數元台幣)。
- LLM 在計分迴圈:評審只產標註,計分恆決定論可重算——LLM 永不出現在分數計算路徑上。

## 實務隱患
- **B 席可用性**:Gemini 免費層規則今年已變兩次;斷供走 `degraded:single-rater` 退化機制(S2 明文),不阻塞。
- **評審漂移**:rater 模型版本換代→標註口味漂——delta 只批新題、舊金標不動,漂移影響侷限於增量;仲裁人裁兜底。
- **併發(r1 補)**:goldset 是共享可變檔——人放行 merge 與排程讀取可能交錯;處置=atomic rename+單寫者約定(S2 明文);排程恆只讀。
- **[self-governance]**:S3 是擋人閘(rc1)——假紅風險=delta 清單誤報;斷言邏輯與 S1 同源(同一份評測母體計算),不另寫一套。
- **[prod-irreversible]**:goldset 是 repo 檔案 git 可回退;唯裸跑清空屬「檔案可回、重標成本不可回」——已以 --force-full 旗標拆雷(S1)。
