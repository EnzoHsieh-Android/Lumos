# 收斂閘漏項敏感度_計劃

> **★作廢:r1 審完判整份重寫(Enzo 2026-09-03 裁,見 d2)。本篇是「為什麼重寫」的紀錄,不是待辦。★**
> 接手的是 [[Projects/收斂閘漏項敏感度v2_計劃]]。**想動這題之前先讀完本節與 d2**——
> 本篇的問題陳述、外部實證、「這個數字誰消費」三節仍然成立且被 v2 承接;
> ★死掉的只有實驗設計那一段(劣化算子、選材規則、判定工具)★。

## ★r1 撞死在哪(給下一個想開這題的人)★

五席合計 33 條、4 個獨立 blocker,卷證在 `governance/review-reports/收斂閘漏項敏感度/`。

1. **核心算子的資料前提不存在**。本篇宣稱「被刪的條款不是我自己想的,是從該迴圈帳上 `folded_set` 反推」
   ——但帳上存的是編排者當下自取的助憶 id(`R1`、`refcheck重造`),★抽查 40 筆只有 17 筆能在自家席報告
   找到任何一個 id★。從 id 到「一段可機械刪除的文字」中間至少缺三層,而那條鏈唯一的持有者是當時
   編排者的判斷,沒有留痕。
2. **選材規則選出來的樣本不獨立**。字典序前 8 個裡 6 個帳上只有 r1(沒有前一輪可比);另有三個迴圈
   共用同一份快照(sha256 逐字元相同)。設計審 53 個迴圈,跑過兩輪以上的只有 25 個。
3. **判定工具方向相反**。`quote-check` 是防「捏造引用」——你說某句在,它去材料裡找,找不到判你造假。
   而本案要驗的是相反的事:這句原本在、現在被刪了,審查員有沒有指出「缺」。★正確抓到刪除的人
   根本引不出那句話★(它已不在材料裡),而不附引句的報告會被判「零引句=驗不了=失敗」——
   等於把抓對的記成沒抓到。
4. **重跑會污染真迴圈的帳**。`--loop` 是自由文字,四個讀取端全用字串相等過濾;卷證目錄直接以迴圈名
   命名,重跑沒改名有覆寫原始不可變快照的風險,而那些快照是回放與引句錨定依賴的基準。

其餘 major:n=8 只有 9 個離散值、35%/70% 兩門檻都落在兩值中間永遠踩不到;漏了拓樸上最近的親兄弟
`lumos loop replay`;隔離環境沒選邊(本專案 2026-08-23 出過探針副本推上真遠端的事故);
M3 是定義了沒人消費的孤兒尺;引用的「紀律層被量過 0 條」在動筆前一天已被來源節點更新為 1。

## 我方犯的錯(誠實記)

1. **把「我猜資料裡有」寫成「機械反推」**。難度錨那一段的整個賣點建立在一個我從未打開帳檔驗證過的
   對應關係上。★家規第四條要求「說沒有之前先派人對」,我做了;但沒有一條規矩要求「說有之前也要對」★
   ——這次的教訓是肯定斷言同樣要對,而且它更危險,因為它不會觸發任何警覺。
2. **數字沒機械數就寫進計劃**。「76 個可用迴圈」重算得 67/72/75/80,沒有一種讀法對得上 76。
   同一個錯誤形態在 `Issues/審計紀錄數字必機械數`(memory)已記過五次。
3. **借用既有工具沒讀它的判準方向**。引用了 `quote-check` 的行號、也確認它存在,但沒問「它是為了防什麼
   而設計的」——存在性驗過了,語意沒驗。


> 白話:我們的審查迴圈判「可以收工了」的條件是——這一輪提出來的每個問題都處理完了。它從來沒問過另一半:**該提出來的有沒有被提出來**。外部這個月有兩篇不同領域的論文各自量到同一個不對稱:AI 判官抓「多出來的東西」很準,抓「漏掉的東西」接近擲硬幣。本案不直接補那個洞,而是**先做一把尺**——拿真的收斂過的迴圈材料,機械刪掉一條當初被審查員抓出來的實質條款,重跑同一輪,看有沒有人再抓到一次。抓不到,就證實自家也有這個盲區;抓得到,外部數字在自家不成立,這題關掉。

PRIOR-ART: ① 最小解層級——不新增閘、不改判準,只是把既有的「隔離 worktree 裡故意弄壞、看守衛會不會叫」(guard kill)那一招,指向審查閘本身;實驗骨架直接沿用 [[Projects/修法A_lumos先行ablation_計劃]] 的預註冊格式。② 世界解過沒——解過:注入已知缺陷、重跑同一條管線、比對偵測率,是評估「評估器」的標準做法(擾動式後設評估);但**沒有任何一篇是把它用在多席設計審查流程上**,所以借方法、自己搭,不是抄現成。③ 裁定=borrow-design,零依賴原生實作。

## 一句話

收斂閘只驗「你列的都處理完了」(自洽),不驗「該列的都列了」(覆蓋)。本案不修它,先量它——**弄壞材料,看它會不會叫**。

## 為什麼是這一條

### 外部:兩篇獨立實證,而且把便宜的解法全否決了

- [arXiv 2608.31016](https://arxiv.org/abs/2608.31016)(醫療紀錄,500 組單一錯誤對照,八種判官設計):抓加料/改錯判別力 0.79–0.94,抓漏掉 0.50–0.63。★關鍵是它試過的補救全部無效★——換措辭、多席投票、自動提示詞優化,只移動操作點,生不出可用的偵測力。這一句預先否決了「多找幾席、把提示寫好一點」。
- [arXiv 2608.01000](https://arxiv.org/abs/2608.01000)(程式領域,離我們近得多):判斷某物該不該在集合裡 F1 0.74–0.90;叫它**自己列出那個集合**,產出的測試只接受 19–42% 的正確解。植入的「多的」被抓到是「少的」的 **6–7 倍**,生產失誤比 10:1 偏向漏。
- ★第二篇給了本案的設計依據★:同一個模型,叫它寫出**判準**(規則本身)F1 ≈0.99,叫它把判準涵蓋的東西**一條條攤出來**就垮。作者原話是問題不在它不懂、也不在說不出規格,而在無法把規格涵蓋的範圍具體攤出來。**所以分工是「攤清單」歸程式、「逐條判」歸 AI**——不是靠運氣,有理由。

### 自家:閘的形狀正好符合那個盲區

現行處置閘**四類條件**全過才 PASS——PASS 訊息逐字列出這四個標籤:G3 ∧ 處置全清 ∧ 留痕可重算 ∧ 引句全錨定(`scripts/lumos:11771-11776`);★每一類內部還有子條件★,失敗字串可多於四個(如「無處置帳」「留痕缺席」)。管發現處置的那一條(`scripts/lumos:11588-11607`)驗的是 `folded_set ∪ accepted_set == findings_set`,外加折∩放行不得非空、放行理由不得缺、輪內有 blocker 則放行必空——**全部都是集合自洽**。而 `findings_set` 是編排者自己打進 CLI 的字串。★這裡要講精確,否則會被誤讀★:寫入端(`cmd_canary`,`scripts/lumos:4004`)**有**機械檢查,而且違反就 rc2 當場擋——但它檢查的全是**三個集合彼此自洽**(折∪放行==全部、折∩放行==空、放行理由齊、輪內有 blocker 則放行必空)。★沒有任何一項把 `findings_set` 的內容拿去跟一個外部來源比對★——這份清單沒有參照物,自洽再嚴也證明不了覆蓋。

同一件事圖譜早就記過天花板(`Systems/convergence-evidence-gate` 摘要:「findings 數源頭仍是 LLM 裁決」「枯竭≠挖乾」),只是一直沒有數字。

### 落差:對程式碼真打一拳,對自己寫的規矩一次都沒量過

`Issues/嚴謹度分配偏向機械層` 的對照表:程式碼層有「沙盒真弄壞、綁定測試必翻紅」(`lumos guard kill`),自己寫的紀律層**被前後量過效果的 0 條**。2026-09-02 的 [[Projects/修法A_lumos先行ablation_計劃]] 是第一條(也是唯一一條)跨過去的,但它打的是規則散文、跑的是情境探針,**沒有人把這一招指向審查閘**。

## ★這不是重推上個月被停的案子★(下一個接手的人先讀這節)

[[Projects/impact鏡頭機械化_計劃]] 2026-08-29 Enzo 裁停案,死因是結構性的:**派工那一刻沒有機械強制點**——派審查員發生在編排者呼叫 AI 的瞬間,沒有 hook 攔得到,所以任何方案都只是「另一支你可能不跑的指令」。兩輪十席次沒有一席找得出強制點。重開條件寫死=先答出強制點在哪。

**本案不落在派工那一刻,落在收斂那一刻。** 收斂閘是機械跑的、pre-push 真的會擋(`scripts/hooks/pre-push:126` → `_codeloop_guard_verdict`,`scripts/lumos:16728`)。那一刀砍不到這裡。

★自我檢驗條款★:**本案任何一步若要求「派工前多跑一道指令」,就是踩回同一顆地雷,該當場退掉**。本案只做唯讀重跑與量測,不新增任何人要記得跑的東西。

另外兩個必須避開的坑,都是自家實測出來的:

- **不可落在字串比對層**。上次實測「派工單列一個不存在的檔 + 報告寫一句我讀了它」→ 全綠(rc0=指令回傳碼 0,代表通過;rc1=判定失敗、rc2=輸入或環境錯誤)。世界那邊 [CASCADE](https://arxiv.org/abs/2604.19400) 的解法同義:不要問 AI「這兩者一致嗎」,要找一個能執行的東西來分辨。本案的「能執行的東西」=被刪的那條條款是否被逐字錨回(沿用既有 quote-check 機制,`scripts/lumos:11670-11691`)。
- **不可與 canary 混為一談**。`Systems/canary-audit` decision d2 明文只收純加性瑕疵、禁非局部型,理由是植入物必須能乾淨移除、不污染真 findings。本案是**減法且非局部**,看似違反——但那條規則管的是「植進正在計分的真迴圈」;本案在隔離副本裡重跑歷史迴圈、記在獨立帳上,不碰任何真迴圈的計分。★這個區別要在實作時用目錄與帳檔隔離兌現,不是嘴上說說★。

## 實驗設計(★預註冊,跑完不得改★)

### 材料

帳上 868 筆、80 個迴圈跑過處置閘(代碼審 27 / 設計審 53),其中 **76 個留有凍結快照且末輪 findings > 0**,可直接用。★選法預註冊,避免挑好看的★:限設計審(散文題,才是漏項盲區的戰場)、末輪 findings ≥ 3、按迴圈名字典序取前 8 個符合條件者。

### 兩組

| 組 | 材料 | 跑法 |
|---|---|---|
| **control**(對照) | 原快照,一字不動 | 同一份派工詞(派審查員時給它的那段指示)、同席數重跑 |
| **treatment**(劣化) | 機械刪掉**一條當初被折入的實質條款** | 其餘完全相同 |

★算子怎麼選才不會又校不準難度★:被刪的條款**不是我自己想的,是從該迴圈帳上 `folded_set` 反推**——也就是「當初真的有審查員抓到、並要求補進去的那一條」。這保證★它至少被偵測過一次★——判準:該條款是同一份文件的前一輪(r(N-1))由某一席寫進報告、並被編排者折入的,帳上 `folded_set` 有它的 id、席報告裡有它的逐字引句。這是天然的難度錨,不是我對難度的估計。這一條直接對應 `Systems/canary-audit` 裡「審查規模實驗三次都因難度沒校準而停止投資」(實驗二天花板 3/3 全中、實驗三地板 0/6 全滅)的教訓。

### 四把尺與讀法(★結果出來前寫死★)

| 尺 | 定義 |
|---|---|
| **M1 復原率** | treatment 組裡,被刪的那條有沒有任何一席點出來(判定=報告引句能逐字錨回快照,沿用既有 quote-check) |
| **M2 帳面動不動** | treatment vs control 的 findings 數與 severity 有沒有差 |
| **M3 閘判決** | 處置閘 PASS/FAIL 有沒有因為劣化而改變 |
| **M4 對照組偽陽** | control 組(沒刪任何東西)有沒有無中生有報出「缺了這條」 |

讀法:

1. **M1 ≤ 35%** → 確認自家也有漏項盲區,外部數字站得住 → **觸發「清單先行」為修法候選,另開計劃**,落點必須是收斂閘(見上節)。
2. **M1 ≥ 70%** → 席位對減法其實敏感,外部數字在自家不成立 → **本題關案**,結論寫回 `Systems/canary-audit` 與 `Systems/convergence-evidence-gate`,免得下次日報又端一次。
3. **35–70%** → 不下結論。看 M2:若帳面數字完全不動(嚴重度與 findings 數兩組相同),仍算「閘吃的是形式不是內容」的證據,寫進 Issue 但不觸發修法。
4. **M4 > 10%** → 儀器噪音過大(席位會自己編出缺漏),M1 的讀數降級為「初步」,要加場次重跑才准當依據。
5. ★難度校準閘★:**M1 = 0% 或 100%(地板/天花板)→ 判「難度沒校準」,本次不下結論**,調整算子(換一條被折入的條款)重跑一次;★只補一次,不無限重試★——這是 2026-08-02/03 停止投資審查規模那條線的直接教訓。

### 成本(誠實講,我沒把握)

真實約束是帳號用量配額,不是錢:情境探針實測**每 5 小時窗口約 50–55 場**。但一場多席審查比一場探針貴多少,**我沒有量過**,不能直接換算。所以先跑 8 個迴圈 × 2 組 = 16 輪當第一批,跑完才知道真實單價;若第一批就撞窗口,照 [[Projects/修法A_lumos先行ablation_計劃]] 既有的 `--wait-on-limit` / 逐題補缺機制處理。

## 誠實界線

- **只量一種瑕疵**:整段刪除(減法、非局部)。缺回退、缺冪等這類「本來就沒寫」的漏,跟「寫了被刪掉」不完全同型——本案量的是後者,推論到前者要打折。
