# 審材來源能從遠端完整還原

白話：只有版本號像只有地址；要實際走得到、拿得到完整來源，才能重驗。

WHY:修復指引若只留下patch與SHA，squash/rebase或臨時clone清理後，兩版來源可能不可得。沿Git既有bundle／ref與讀取器，不自建封存引擎，也不要求每輪產巨大完整歷史。出處本案R3 integration-F1與高風險整合設計審。

PRIOR-ART:Git官方bundle將verify定義為格式及目前物件庫的前置閉包檢查；它不等於已fetch所需來源。https://git-scm.com/docs/git-bundle ，2026-10-07實讀。

VERIFY:自空目錄network bare clone https://github.com/EnzoHsieh-Android/Lumos.git 的main，實得e80705c4b3c1d8acf677100b5495ca54cedac0bc及c4f2b0cf479ccdff5823524c0b6954113819496b前置閉包；verify增量封存後fetch封存ref，還原95735eff7f3e17c930d43eecde5dd9d7c4fe9eff，tree 8b79d92d1f997aee73a34e653929505640d0e33b，必要CLI與測試blob指紋相符。未使用本機objects或alternates。實際命令、退出碼及原輸出在r3-validation/remote-prerequisite-cold.json，增量原件reviewed-957-incremental.bundle。

VERIFY:另有空物件庫未供前置時verify rc1、供完整前置後verify/fetch rc0的負正控制；收據reviewed-957-incremental-cold.json。完整bundle約107MB、完整來源archive約112MB的實驗保留收據而不提交巨大原件；archive只還原tracked blob/mode/tree，不代答commit血緣。第一次clone未指定封存ref造成HEAD無法解讀的原失敗也保留，不能只挑成功結果。

VERIFY:恢復原研究歷史保留各功能独立提交，本地original-history-home-check實際rc0；最终新main整合後仍另驗，不把历史clone通過移作最後放行。

REVISIT:2026-10-20 由來源留存交付入口重查遠端前置閉包；整理提交或遠端改寫當次依revalidate_when先重驗。這是一個實際還原樣本，不代表已量到真實代碼審輪數改善。

RETIRE-IF:版本庫已有可核對的耐久固定來源服務並替代臨時版本封存時，撤掉重複封存步驟；同案例兩版及實際載入核對要求保留。
