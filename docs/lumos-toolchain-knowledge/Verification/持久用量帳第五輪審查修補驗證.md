# 持久用量帳第五輪審查修補驗證

## 結論

第五輪七席（正確性、併發資源、邊界、合約圖譜、平台終端、架構對齊、資安）審同一份凍結差異，修前 05e87b54、修後 4d765d5c。唯一的重大問題是終端修補的防回歸測試沒有現場：在有控制終端的開發機上，拿掉 `O_NOCTTY` 照樣全綠。其餘小問題同根因收成五組，一次修掉，每組先寫會紅的測試再修。

- 終端：新增 `t_confirm_tty_no_ctty_session_survives`，子程序以新 session 啟動並先斷言自己是 session leader、開不了 `/dev/tty`。
- 輸出寫入：新建檔照 umask、只有自己擁有的既有檔才沿用權限、唯讀檔照舊拒絕、裝置與 FIFO 直接寫、暫存檔名固定短名；`--out` 與 `--history` 在呼叫模型前就檢查；歷史檔以不跟隨連結的方式追加。原子寫入收斂成探針一份，消融腳本改匯入。
- 等待：補 `--wait-on-limit 301` 的案例，證明先等 300 秒、再只等剩下 1 秒。
- 報表：字面反斜線先加倍，超過四位的碼點用八位寫法，一般空白照空白，另轉義 `:`、`@`、`~` 與 `www.`，擋掉自動連結與刪除線。

## 驗證

- 修補前新測試的紅燈：權限、唯讀、長檔名、報表三條各自翻紅（原始輸出 `governance/review-reports/code-probe-postreview-dispatch-ledger/r5-red-before-fix.log`）。
- 修補後：探針相關子集 396 passed / 0 failed、終端確認 8 passed、消融單元測試 32 OK、消融子集 4 passed。
- 還原翻紅：拿掉 `O_NOCTTY`、等待改成一次睡滿、拿掉開跑前檢查、不設權限、報表不擋自動連結、不沿用自己檔權限、別人的檔也沿用，七種改壞版本各自讓對應測試翻紅（輸出 `r5-mutation-checks.log`）。拿掉 `O_NOCTTY` 那次，現場斷言照綠、子程序收到掛斷，證明測試真的走到被修的那條路。
