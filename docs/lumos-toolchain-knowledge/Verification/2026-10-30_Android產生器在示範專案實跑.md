# 2026-10-30_Android產生器在示範專案實跑

> 白話:計劃驗收條款 S10 的手動驗證。產生器的產出在工具鏈 repo 裡只能比對文字、編譯不到,所以拿 macrobench-lab 示範專案(購物車範例,單一 app 模組)真的用 Gradle 跑一次架構測試。條款原本寫「結果寫進那個專案的驗證紀錄」;示範專案那條分支(arch-rules-draft)還沒決定要不要推,證據放在那邊只存在本機,所以記在這裡。

## 怎麼跑

在 macrobench-lab 從 arch-rules-draft 開一個實驗用工作樹,用產生器 `--root com.example.mblab.cart --scope app/src/main/java/com/example/mblab/cart` 產出架構測試與舊檔清單,蓋掉原本的 `ArchitectureRulesTest.kt`,跑 `./gradlew :app:testDebugUnitTest --tests '*ArchitectureRulesTest*'`,從 `app/build/test-results` 的 XML 讀每支測試的紅綠與失敗訊息裡點名的檔。

## 結果

1. 第一次跑(預設組、new-only、還沒埋違規):9 支裡分層那支紅,訊息是 Konsist 的 `Layer Domain doesn't contain any files`——`assertArchitecture` 只要有一層在範圍內一支檔都沒有就直接失敗,new-only 剛採用時範圍內全是舊檔。Konsist 0.17.3 的 `assertArchitecture` 沒有放過空層的參數(查過 jar 的方法簽名)。**修法**:分層那支改用 import 判斷(同一套禁止方向),資料檔與技能文件一起改。改完重跑 9 支全綠。
2. 舊檔 `domain/CartModel.kt`(在清單上)與新檔 `domain/Promo.kt` 各加一行 `import android.util.Log`,另加新檔 `presentation/PromoBanner.kt` 直接 import 資料層:紅的是 `domainHasNoAndroidImports`(只點名 Promo.kt)與 `layersDependOnlyInward`(只點名 PromoBanner.kt),CartModel.kt 被跳過。
3. 從舊檔清單刪掉 CartModel.kt 那一行再跑:`domainHasNoAndroidImports` 同時點名 Promo.kt 與 CartModel.kt。
4. 整份舊檔清單拿走:9 支全紅,訊息是「找不到舊檔清單 …」,沒有靜默全綠。
5. 六個開關全反那組(multi、all、optional、lite、always、single)產出同樣編譯得過、跑得起來;單一 uiState 那支因範例的 ViewModel 公開的是 `state` 而紅,改名成 `uiState` 後轉綠(不是永遠紅)。

Gradle 單元測試的工作目錄是 app 模組,不是 repo 根;往上找 `.lumos/config.json` 找得到根,範圍比對也對(第 2、3 步的紅綠就是靠它)。多模組專案沒驗,見 [[Projects/Android目標架構開關與舊檔畢業_計劃]] 的回頭條件。

代碼審 r1 之後(舊檔清單讀法改成逗號嚴格、用例必有那版的 ViewModel 測試加嚴)重新產出預設組跑一次:編譯得過、清單讀得到,紅綠跟上面第 3 步一致;在清單最後一個字串後面多加一個逗號,9 支全紅,訊息講「逗號也不能多(刪掉最後一行時,前一行的逗號要一起拿掉)」。

代碼審 r2 之後(舊檔清單的讀法改成兩條正規式)再產出預設組跑一次:編譯得過;正常清單與空陣列 `{"files": []}` 都讀得進去(紅綠只來自埋的違規);最後一行後面多一個逗號時 9 支全紅,訊息講清單形狀不認。這也是兩條正規式在 Java 那頭的實際判法,跟工具鏈測試用 Python 跑的判法一致。

代碼審 r3 之後(正規式改佔有式量詞、`\A` `\z`、BOM 放進正規式)再產出預設組跑一次:編譯得過;正常清單、帶 BOM 的清單、多加 5000 條的清單都讀得進去(紅綠只來自埋的違規;改之前的正規式在本機 JDK 17 上 3000 條就堆疊溢位);檔尾多一個 U+2028 時整份不認、9 支全紅並說明。
