## 過程中被機械守衛咬住兩次（正面案例）

1. **命令數漂移守衛**：新增兩個頂層命令後，`t_docs_command_count` 立刻在三份文件上翻紅——這正是它昨天被加進來的目的，且 spec [S5] 已預先寫進連動。
2. **假 gh fixture 的跳脫壞掉**：測試自身的 stub 產生了語法錯的 Python，導致所有 `ci-wait` 案例都走 fail-open；靠「verdict 應為 green 卻是 unavailable」的斷言抓出來——若當初只斷言 rc0，這個壞 fixture 會靜默通過（rc0 正是 fail-open 的回值）。**測試要斷言語意不是只斷言 rc**。

## 順手硬化

`ci-wait` 的 git 呼叫改 fail-open（PATH 缺 git 時原本會 traceback）——由「gh 缺席」測試逼出來。

## 誠實天花板

- **晚註冊 run 的 grace 期是緩解非保證**：無法證明沒有更晚註冊的 workflow。
- **修復重試上限／flaky 判別／Issue 產出屬 skill 紀律層**，工具端只出 rc1 訊號與失敗證據，不機械強制。
- **v1 不含 PR 流程**：紅燈仍會短暫存在於 main（靠當輪修補回），要「紅燈進不了 main」需 v2。
