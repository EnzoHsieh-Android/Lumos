## 值得記的結論

- **分不出對錯的候選拿掉**:detekt 的 `TooGenericExceptionCaught`、`SwallowedException` 對 CO-2 實跑連「先重拋 CancellationException」的好寫法也報,真正的壞寫法 `runCatching` 反而不報;Slack 的 `RawDispatchersUse` 連預設參數注入的好寫法也報。
- **代號不存在**:detekt 沒有 `MissingUseCall`、`ArrayInDataClass`;Android Lint 沒有 `NetworkOnMainThread`;androidx 沒有 `ComposableModifierFactory`;dagger-lint 2.53.1 只有四條,型錄原列的另外八個代號不存在。
- **UI-61 的前提跟官方相反**:Android 官方 custom-modifiers 頁明寫可以用 `@Composable` 寫 Modifier 工廠(只列三個限制),Slack 2024 年以此為由刪掉 `ComposeComposableModifier`(compose-lints #378)。型錄把它整列當錯誤寫法,名稱改標(出處不全);規則包沒有規則引用這列。
- **UI-67 的壞寫法編不過**:`awaitPointerEventScope { return@pointerInput }` 在 nowinandroid 編譯就失敗(「'return' is prohibited here」),由編譯器擋;`ReturnFromAwaitPointerEventScope` 管的是把 scope 的結果接出來再重進。
- **UI-16 的代號隨版本變**:新版 Compose 對 `Animatable(0f)` 由 `RememberInComposition` 報,不是 `UnrememberedAnimatable`;`LazyListState()` 沒有任何規則報。
- **TEST-12 拿掉出處不全**:kotlinx-coroutines-test 原始碼三個舊 API 都標 `@Deprecated`、訊息叫人改用 `runTest`,註解寫 1.6.0 起棄用、1.9.0 起 ERROR,直接支持這列。
