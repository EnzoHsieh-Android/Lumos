# 2026-08-03 Windows 真機三輪驗證通過

## 一句話

**三支 `.ps1` 開頭掛了兩個月的「沒有在真機 Windows 上跑過」，兌現了。**

## 三輪

| 輪 | 版本 | 結果 |
|---|---|---|
| 1 | v1.3 | 5 條缺陷（2 BLOCKER）——README 的一行安裝**在 CJK 語系 100% 失敗** |
| 2 | v1.4 | 3 條——**其中 1 條是我修 v1.3 時造成的**（BOM 把問題搬到 `irm \| iex`） |
| 3 | **v1.5** | **一次通過** |

## ★這三輪真正的價值★

**8 條缺陷裡，沒有一條是讀 code 讀得出來的：**

| 缺陷 | 為什麼讀不出來 |
|---|---|
| DBCS 前導位元組吞掉引號 | 要知道 Windows `MultiByteToWideChar` 對非法尾碼的行為 |
| BOM 讓 `irm \| iex` 炸第 1 行 | 要知道 `irm` 回字串、`iex` 不剝 BOM |
| `$Args` 是保留自動變數 | **要跑最小重現才看得出來**（回報者原話） |
| git pack 檔的唯讀屬性 | POSIX 上 `chmod 444` 根本擋不住刪除 |
| `~/.claude/skills/` 會掃描 `.bak` 目錄 | 要真的開一次 session 才看得到 skill 清單 |

★**「修好一半」在真機上是可被觀測的，在開發機上不是。**★
v1.4 那條最貴——我用 BOM 修好磁碟執行，同時弄壞了 README 唯一教的入口，
而本機所有測試都是綠的。

## 為什麼要寫這個節點

`Verification/2026-08-01_slim-python移植` 與 `2026-08-01_slim-終審三缺陷修復`
的 `revalidate_when` 裡，過去的自己寫了：

> 「或未來真的拿到 Windows 機器做真機驗證後（屆時要把『未驗證』標記一併更新，
> **不能讓已驗證的部分繼續掛著誠實標記**）」

**那個觸發條件現在成立了。** 本節點就是執行它。

★**誠實標記兌現之後必須更新，否則它會退化成永久免責條款**★——
掛著「未驗證」很安全，但掛久了就分不出「真的沒驗」與「忘了更新」。

## 逐項對照（有證據 vs 仍無證據）

**現在有真機證據**：一行安裝、`lumos.cmd` shim 真的被找到並執行（`lumos stats` 讀到 275 篇）、
`.ps1` 不再關掉呼叫端視窗、`$LASTEXITCODE` 型別與值正確（成功 `[0]`／失敗 `[2]`，皆 `Int32`）、
`-ErrorAction Continue` 確實蓋過 `Stop`（錯誤路徑印得出訊息且流程繼續）、
CLAUDE.md 位元組級還原、不誤動使用者自有 skill。
