# 2026-11-06_Android儀器測試範本與架構測試實跑

> 白話:照範本檔〈Android 實驗專案骨架〉把 T6–T13 與 T4 的 Ktor 小節每一格(測試小節 × 被測程式小節)組成一個 Android app 模組,真的在 Robolectric、純 JVM 與模擬器 `kds_bench`(API 34)跑,讀 JUnit XML 看每支測試是不是矩陣寫的結果,每個紅用收證工具的 `assertion_failure` 判是不是斷言失敗。驗 [[Projects/Android儀器測試範本與架構測試_計劃]] 的 S4、S5 與實驗 E1–E12;S1–S3、S6、S7 是 repo 裡的資料測試,見 [[Systems/kotlin規則包]]。

## 做法

- 實驗專案從 lab(macrobench-lab)`git clone` 到會談暫存區,只拿它的 Gradle wrapper 與 `local.properties`;每格一個 app 模組,`build.gradle.kts` 照骨架的 `app/build.gradle.kts`(只換 namespace),`dependencies` 貼那組〈依賴〉(〈依賴:X〉配〈測試:X〉;寫「在〈依賴〉之外再加」的兩份合併),標「plugins { } 加」「android { } 加」「檔尾」的圍欄照標的位置貼;〈測試〉〈假依賴〉照節開頭的「跑在哪」放 `src/test` 或 `src/androidTest`;被測程式組法同前半(〈好寫法〉每段一檔,再用那一格點名的小節換掉同名的)。跑的就是範本檔裡的字,沒有另抄。
- 例外:T6 的舊結構檔(`schemas/AppDb/1.json`、`2.json`)由小程式先用第 1、2 版 Entity 建置產生(代表專案歷史);Room 3 那幾格照範本寫的兩處機械改法(import 換 `androidx.room3.`、`migrate` 加 `suspend`)套到〈好寫法〉〈壞寫法〉;T12 每格先用〈好寫法〉帶 `-ParchunitFreezeInit` 建凍結清單再換回那格程式跑;T13 每格自成一個 Gradle 專案(Konsist 掃整個專案)。
- 判定:矩陣寫「斷言紅」的,XML 失敗節點經 `assertion_failure` 判成真、訊息含矩陣寫的片段;沒點名的要綠;小節裡每支 `@Test` 都要出現在矩陣。模擬器的 XML 在 `build/outputs/androidTest-results/connected/debug/`。
- 重跑:JVM 與 Robolectric 每格連跑 20 次(`--rerun`),模擬器每格 5 次(每次重裝 APK);例外是 T12 由 E13 新加的 4 格,每格跑一次(理由見 E13 末條)。
