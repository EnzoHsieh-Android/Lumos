## 行級過濾那條的完整重現

在一個乾淨的臨時 repo 裡放這支檔並提交：

```python
def risky():
    try:
        do_work()
    except ValueError:
        pass
```

然後**只把第 4 行**改成 `except:`，再提交。這次改動碰到的是第 4 行，但檢查工具把問題報在**第 2 行**——因為它比對的是整個 try/except 結構，報告位置用結構的開頭。行級過濾判斷「第 2 行不在新增行集合裡」，把這條真問題丟掉，而且不說一聲。

這不是特例：任何跨多行的規則都有這個性質。

## 取基準版的方式

整批打包（`git archive <版本> -- 檔1 檔2`）**只要有一個檔在那個版本不存在，整條指令就 fatal 失敗、零輸出**——不是「跳過那個檔、其他照跑」。實測用一次同時新增一支檔、修改另一支檔的普通改動就會踩到。

改成逐檔取出（`git show "<版本>:<路徑>"`）之後，「取不到」正好等於「這支在基準版不存在」，語意剛好就是我們要的「新檔的告警全算新增」。中文與帶空白的路徑都試過，沒問題。

**一個 shell 陷阱**：本機的 shell 會把 `$VAR:a.py` 裡的冒號加單字母當成路徑修飾符吃掉，雙引號擋不住，要寫成 `${VAR}:a.py`。

## 這篇不能證明什麼

- **不能證明任何設計是對的。** 只證機制跑得動、代價多少。
- **不能代表消費專案。** 所有數字量的是工具鏈自己這個 repo，而且這個 repo 目前一個檢查工具都沒宣告。
