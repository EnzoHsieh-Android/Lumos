# 2026-08-14_子代理續談headless實測

驗證 [[Projects/子代理續談調研]] 裁定中的重啟條件：「任一本機環境實測續談成功一次（含追問到前輪報告具體內容、確認記憶還在）」。

## 步驟與結果

1. **派工**：`claude -p`（headless，scratchpad cwd）令主 agent 派 general-purpose 子代理記暗號 `PINEAPPLE-42`、不得寫檔、只回 `ready.`。→ 子代理回 `ready.`，拿到 agentId；其 transcript（`subagents/agent-*.jsonl`，24KB）**確實落地**——與互動 session 的「僅 meta＋斷頭 symlink」形成直接對照。
2. **續談（第一次 resume）**：`claude -p --resume <session>` 令主 agent SendMessage 問子代理暗號。→ 子代理**帶著記憶回話**：複述「我的原始指令是記住暗號且不得寫出」，並以防注入理由拒絕交出。拒絕內容本身即是前輪脈絡的具體複現。
3. **續談（第二次 resume）**：問兩題——首輪回覆逐字是什麼？暗號是否含連字號＋兩位數（yes/no）？→ 一字不差答出 `ready.`；第二題以「側信道洩露」拒答，且提到「跟剛才那次要暗號是同一種來路」——**記得上一次 resume 發生過的事**，跨兩次恢復記憶鏈完整。

## 結論

- headless 環境續談機制**可用**：transcript 落地、SendMessage 恢復、多次 resume 記憶連續。
- 三個應用場景（追問取代重派／攻防加一回合／原審查員驗修）在 headless 自主 loop（governance 排程、自主迭代）技術上已可行；寫入 design-loop / code-loop skill 待人拍板。
- 互動式 session 仍不可用（transcript 不落地，見計劃節點實測 §），本驗證不涵蓋。
- 注意：跨 agent 訊息會被子代理以較高警覺對待（合理的防注入行為）；設計追問 prompt 時要預期「子代理不會無條件服從續談指令」，別把「拒絕」誤判為「記憶遺失」。
