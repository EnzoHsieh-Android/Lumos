# 2026-09-16_別名欄對檢索的實際貢獻


## 一句話

**別名欄現在對檢索的貢獻幾乎是零**，但原因不是權重太低，是**欄位絕大多數時候是空的**——而且已經填的那些，有一半以上填的是「文件別稱」而不是「有人會拿來找它的詞」。

## 現況盤點（533 篇，自己機械數的）

| 狀態 | 篇數 | 佔比 |
|---|---|---|
| 連 `aliases` 欄都沒有 | 412 | **77%** |
| 有欄位但留空 | 52 | 10% |
| 真的填了 | 69 | **12.9%**（平均 2.4 個） |

★第一次數的時候我算成 22.7%，是腳本的 bug★：抓 `aliases:` 那行之後沒有在下一個頂層欄位停住，把下一個欄位的項目也算進來了。改成正確解析 frontmatter 才得到 12.9%，跟圖譜既有的紀錄（11.5%，兩天前）對得上。

## 消融：把別名權重從 0 掃到 12

排序欄位權重是 標題 4.0 / **別名 3.5** / 摘要 2.5 / 標籤 1.5 / 正文 1.0。

| 別名權重 | 排序品質 nDCG@5 |
|---|---|
| 0.0（等於關掉） | 0.6786 |
| 1.75 | 0.6786 |
| **3.5（現況）** | **0.6802** |
| 7.0 | 0.6802 |
| 12.0 | 0.6802 |

**整條曲線是平的，全距 0.0016。** 其餘三個指標（第一個對的答案多靠前、前五名命中率、第一名品質）在所有權重下**一字不差**。

## 為什麼平：欄位根本沒被命中

拿題庫的查詢詞去比對「標成相關」的節點的別名欄：

- 206 個相關節點裡，**只有 4 個（1.9%）**的別名被查詢詞命中。
- 縮小到「必看」等級的 85 個節點：**沒填的 75 個（88%）**、填了但沒命中 7 個、填了且命中 3 個。

**主因是沒填，不是填錯。** 這跟權重曲線平掉完全一致——欄位空的，權重再高也沒東西可加分。

## ★但「填了卻沒命中」那 7 筆透露了填法問題★

- 查「guard kill 排程 每日」→ 那篇機制節點的別名只有「殺傷力驗證」。那是這個機制的中文說法，**但人查的是指令名**。
- 查「CI 分支 main 兜底」→ 別名是「工作流全貌／workflow overview／流程圖」。那是**這篇文件的別稱**，不是**有人會拿來找它的詞**。

**現行的填法是「這篇文件還可以叫什麼」，有用的填法是「有人會用什麼詞來找它」。** 建檔提示寫的是後者（「大家實際上怎麼描述這個問題」），但實際填出來的多半是前者。

## 對「回填別名能改善檢索」這個前提的影響

- **沒有推翻它**：主因是沒填，補起來才知道有沒有效。
- **但修正了做法**：補得不對等於白補；而且**光靠調權重救不了**，這條已經用消融排除。

REVISIT:2026-11-16 回填之後重跑這組消融，看曲線有沒有從平的變成有斜率——那才是「別名真的在工作」的證據。

## 第二段（同日）：回填 54 篇之後量了，而且順便把尺的雜訊量出來了

### 做法與它的邊界

挑「題庫裡標成必看、而且沒填別名」的 57 個節點，派兩個代理逐篇寫別名。**寫的人看不到題庫**，只看那篇筆記本身回答「有人會用什麼詞來找這篇」。57 篇裡 3 篇被判定不該填（標題已經夠好找），實際寫了 54 篇、平均 3.9 個。

**★這是上限實驗，不是無偏估計★**：節點是**照題庫挑的**——只補那些跟題庫相關的。寫的人雖然盲，挑的人不盲。所以它回答的是「最好情況下能有多少效果」。

寫出來的東西品質不錯，像「lumos ci-wait」「CI紅了本機不知道」「killed/survived/drifted」這種——確實是人會打進搜尋框的詞，不是文件別稱。

### 結果：+0.004

| | 排序品質 | 其餘三個指標 |
|---|---|---|
| 回填前 | 0.6802 | — |
| 回填 54 篇後 | 0.6842 | **一字不動** |

### ★這把尺的雜訊有多大（條款早就要求、一直欠著的那件事）★

把 15% 的標註各翻一級（呼應抽驗量到的評審不一致率），跑 40 次：

| | 值 |
|---|---|
| 分數落在 | **0.6360 ～ 0.7075** |
| 標準差 | 0.0193 |
| **全距** | **0.0715** |

**別名回填的 +0.004 是雜訊全距的 5.6%。** 只要有兩三筆標註判得不一樣，就能製造出比它大十倍的差異。

**結論：這把尺看不出別名回填有沒有效。** 不是「沒效」，是**解析度不夠**——二十題、雜訊 0.07，撐不起 0.01 等級的判斷。

### ★連帶打臉一個我自己訂的門檻★

[[Projects/檢索核心重建_計劃]] 的收工條款寫「排序品質 +0.05 以上才算過」。**雜訊全距 0.0715 比那個門檻還大**——也就是說那個門檻從一開始就是假的。而同一條款裡我自己寫過「門檻小於雜訊的話那個門檻就是假的」，卻沒去量。

那個案子已經收案不落地，結論不受影響（它的實測是 +0.001，兩個版本都遠低於雜訊）；但**任何之後想用這把尺訂門檻的人，要先看這裡的 0.0715**。

### 處置（2026-09-16 Enzo 裁）

**別名照樣寫進語料，但明記「檢索效果在雜訊以內、未經證實」。** 理由是別名對「人找東西」本來就有價值，那是它原本的用途；但不得讓下一個人以為「回填別名能改善檢索」已經被證明。

**全庫回填暫緩**——不是因為別名沒用，是因為現在沒有能判斷它有沒有用的工具。往下走的順序應該是：先把尺的解析度做出來（加題到幾十題起跳，或換一個對標註雜訊不敏感的指標），再談回填。

REVISIT:2026-11-16 尺的解析度若提上來，回頭用同一組別名重量一次——那 54 篇的前後對照是現成的實驗材料。
