## 實作時撈到、設計期沒預見的兩件事

★這兩件都算逃逸(設計期該看出來卻沒有),已記進逃逸帳★:

1. **安全檢查把目錄名寫死**:判斷快取目錄可不可信的那個函式,拿「解析後的路徑」跟寫死的舊目錄名比對——所以同一層底下新增任何目錄都永遠不過這關,新機制被**靜默停用**(症狀:功能沒作用但什麼也不報,跟本案要修的病同一種形狀)。改成比對目錄自己的名字,防連結繞路的原意不變。
2. **弄紅一支既有測試,而原因是那支測試的現場不真實**:它造完檔就提交、工作樹是乾淨的,只在對話紀錄裡「宣稱」改過某支檔。舊算法信它,新算法問版本控制看到乾淨就閉嘴。**行為改變是真的**(改完又改回去、改完就提交都會這樣,已列入計劃的已知限制);但那支測試要測「改了碼沒寫回」,就該真的改檔——所以改的是現場,不是斷言。

## 代碼審第一輪抓到什麼(六席)

★這一節是後補的:上面那些是實作當下的狀態,代碼審之後又修了四條行為問題與五處文件。★

| 席 | 最嚴重 | 關鍵發現 |
|---|---|---|
| 資安 | blocker | **被打開的資料夾自帶的設定,能讓我們查工作樹狀態時執行任意指令**(編排者實測重現:證據檔被建出來) |
| 邊界 | blocker | 中文檔名變八進位亂碼;排除規則對「被刪掉的檔」失效 |
| 外家備援 | blocker | 中文檔名(★第一個講出來的是它★——它看不到專案脈絡,只拿到一份 diff) |
| 合約一致 | blocker | 送給模型那條路仍用被換掉的那套壞清單 |
| 正確性 | major×2 | 同上兩條,獨立撞上 |
| 架構對齊 | minor | ⚠ **被審材料的範圍是錯的**(見下) |

### 三條打到要害的

1. **中文檔名**(三席獨立報):版本控制預設把非 ASCII 檔名轉義成八進位,解析出來的路徑指向不存在的檔。★這個專案的檔名大量是中文,等於天天踩★;而且**凍結被審材料時本來就照流程帶了正確旗標,實作那支查詢時卻忘了**——同一天、隔幾個指令。
2. **模型那條路**(兩席獨立報):為了不把別人的改動塞給模型而取交集,★而交集的來源正是這次要換掉的壞清單★——於是用 shell 改的檔在那條路完全不列名,少報換個位置活著。正解不是修交集,是承認「這一輪」算不準:列完整清單,風險用措辭講明。
3. **任意指令執行**(資安席):★觸發面是本批改動擴大的★——改動前這條路完全不呼叫版本控制,現在幾乎每輪都呼叫,而它會吃被打開那個資料夾自己的設定。修法是呼叫時把那一項關掉;★誠實邊界:只關掉已知會執行指令的那一項,不宣稱所有設定都擋得住★。

### 編排者自己的失誤,一併記著

**被審材料的範圍打錯了。** 產 patch 時用了分支名當起點,而本地主線在開工期間被推進過——於是算出來的不是「我改了什麼」,而是「我跟現在的主線差在哪」,**含別人改動的反向差異,看起來像我刪掉了他們的功能**。六席裡有五席看的是這份錯材料。

諷刺的是:前一步才剛查出正確的雜湊值,下一步順手打了分支名。而「工作區裡用分支名當範圍會算成別人的」正是這個專案記過的教訓。

影響評估:五席的發現都針對我真正改的那兩支檔,所以**發現本身仍然有效**,錯材料只是多了雜訊。已用正確範圍重產並重新凍結。
