# 2026-07-31_公開精簡版一行安裝卸載與代碼審修復

驗證對象:[[Projects/公開精簡版_實作計畫]] 的補充 Task 6——這是分支 `feat/public-slim-handoff` 的最後一個 Task,給精簡版加一行安裝（`slim/get.sh`）／一行卸載（`slim/uninstall.sh`），並修掉分支終審代碼審抓到的兩條 minor（`scripts/slim-scan.py` 候選視窗置中、`slim/skills/lumos-project-notes/{SKILL.md,reference.md}` 缺掃描斷言覆蓋）。

## ① `slim/get.sh` —— 一行安裝入口

`curl -fsSL https://raw.githubusercontent.com/citrus-android-developer/Citrus_Lumos/main/get.sh | bash`。固定落點 `~/.lumos-slim`：已是合法 git repo → `git pull --ff-only`（冪等）；已存在但非 git repo → 拒絕 rc2；不存在 → `git clone`。`git` 指令缺失時給清楚錯誤訊息而非 traceback（`command -v git` 前置檢查）。首次跑完後執行 `~/.lumos-slim/install.sh "$@"`，額外參數（如 `--force`）原樣轉發。

## ② `slim/uninstall.sh` —— 一行卸載

`curl -fsSL https://raw.githubusercontent.com/citrus-android-developer/Citrus_Lumos/main/uninstall.sh | bash`（或裝好後 `~/.lumos-slim/uninstall.sh`）。安全紀律逐條實現：

- **`~/.local/bin/lumos`**：與 `~/.lumos-slim/scripts/lumos` sha256 比對，符合才 `rm -f`；不符 → 印訊息、rc2；`--force` 才允許跳過比對強制移除。
- **`~/.claude/skills/lumos-project-notes/`**：先 `mv` 成 `.bak.<timestamp>` 備份，不直接 `rm -rf`。
- **`~/.lumos-slim`**：確認內含 `scripts/lumos` 與 `install.sh`（長得像本包）才 `rm -rf`。
- **絕不碰**：任何專案目錄、`~/.claude/settings.json`、`~/.claude/hooks/`、其他任何 skill——三個判斷式全部只讀寫 `BIN`/`SKILL`/`PKG` 三個路徑常數，沒有一行觸及這四類路徑。
- 判定 ① 失敗即 `exit 2` 中止全流程，不會片面繼續備份/移除後續步驟。

### 獨立審計(maker≠checker)

兩條 ★INVARIANT★（sha256 比對才移除全域指令 / skill 目錄先備份才移除）派了一個沒看過實作理由的乾淨 agent 審計：讀 `slim/uninstall.sh` 與兩支綁定測試，在暫存副本各自打斷合約（移除改無條件執行、備份改直接 `rm -rf`）重跑對應測試，兩次都確認翻紅（非稻草人綁定），才用 `lumos guard audit` 留痕。真實 `slim/uninstall.sh` 全程未被該次實驗動到（md5 核對一致，`git status` 乾淨）。

## ③ 代碼審 2 條 minor

**minor-1**：`scripts/slim-scan.py` 的 `scan_python_file()` 原本 `text = " ".join(node.value.strip().split())[:120]`——從常數字串**開頭**截前 120 字，不是「以命中點為中心」。修法：新增 `_windowed_text(s, token, width=120)`，找 token 位置後取周圍窗口（超界加 `…`），`scan_python_file()` 與 `main()` 的 markdown 逐行掃描路徑都改用此函式。

回歸測試 `t_slim_scan_window_centered`：造一段填充文字 > 120 字、命中詞（`lumos gov`）排在填充文字之後的合成 docstring：

**minor-2**：`slim/skills/lumos-project-notes/reference.md`（與 `SKILL.md`）從未被任何測試餵進 `slim-scan.py`——`t_slim_readme_assertions` 只掃 `README.md`。新增 `t_slim_skill_reference_scan_assertions`：掃 `SKILL.md`+`reference.md`，用**(檔名, 行號, token, form)四元組**精確白名單（比 README 用的 (token, form) 兩元組更精確——不會因為同一 token/form 出現在新的一行就被靜默放行），並額外斷言候選總數與白名單條數一一對應（防白名單有死條目而候選變少卻沒人發現）。

實測掃描 `SKILL.md`+`reference.md` 得 22 條候選（全在 `reference.md`，`SKILL.md` 乾淨）：21 條是已人工審過的自我揭露句（明講「這條指令本精簡版沒交付」，如 `install`/`uninstall`/`update`/`bootstrap`/`init`/`deinit`/`teardown`/`gov`/`spec-trace`/`self-audit`/`signoff` 等）、1 條（`reference.md:342` `install` prose）是已審查的假陽性——講的是 `npx playwright install` 裝瀏覽器,跟 `lumos install` 無關,裸 token 無法分辨語境的已知代價。

## ④ README 補「怎麼移除」

`slim/README.md`〈怎麼裝〉補一行安裝（curl 版）與兩行版（先 `git clone` 再跑 `install.sh`）並列；新增〈怎麼移除〉（一行卸載 + 逐條列會做什麼/不會碰什麼)、〈`~/.lumos-slim` 是什麼〉（固定落點解釋、可不可以自己刪）兩段。改完後重跑 `slim-scan.py` 對 README.md 掃描，候選集合仍等於既有已審查白名單（6 條，4 類 token：init/update/self-audit/signoff，皆 prefixed 形態，數字不變），無新增非預期懸空引用。

## 意外

- lint 一開始擋下兩條 ★INVARIANT★（缺 `[audit:]`，pre-push 會擋）——這暴露出一個過程瑕疵：一開始手寫 KEY 行時把 `[audit:sonnet/...]` 也一起手打上去，等於自己審自己（maker=checker），被 `lumos lint` 的措辭（"綁了測試但未獨立審計"）點出來後才補派了真正獨立的 agent 去審計、實測驗證綁定測試會真的翻紅，再讓那個 agent 自己跑 `lumos guard audit` 留痕。教訓：`[audit:]` 不是格式欄位,是「已發生獨立審計」的宣稱,不能手寫佔位。
