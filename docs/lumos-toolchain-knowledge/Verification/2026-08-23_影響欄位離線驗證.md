# 2026-08-23_影響欄位離線驗證

> 白話:「關於」欄位驗過了,但它接不住「不是在講你、你改了卻會出事」那類筆記。
> Enzo 問能不能用標籤分「提到」和「關於」——答案是關係不只兩種,至少四種,
> 這篇驗第三種「影響」。**結論:訊號成立,但單靠模型會推太寬;共改歷史是它的尺。**

## 為什麼「關於」不夠:四種關係

| 關係 | 意思 | 系統現況 |
|---|---|---|
| 提到 | 正文順帶列了路徑 | ★唯一有的★,用它推另外三種 → 雜訊 |
| 關於 | 這篇在講這支的行為(實作在哪) | about_code,已驗(2026-08-23) |
| **影響** | 這篇講的規則管到哪些檔(改了會違反) | **本篇驗** |
| 教訓 | 改這類東西該記得這件事 | 未驗 |

r1 那個案例把「關於」與「影響」的差別講透:`anchor-integrity`(守衛檔要簽名)——
模型標它**關於** pre-push(實作在那);考卷說改 pre-commit、impact-hook 也**必看**(它守所有 hook)。
★模型答的是「實作在哪」,考卷要的是「影響誰」。兩者都對,是兩種關係。★

原本給 about_code 的判準「改這支檔的人不看這篇會不會做錯事」——**其實是在問「影響」**,
模型回答時偏向「關於」是因為那比較好判。★拆開問,兩欄各自會乾淨。★

## 實驗一:工具鏈(已知答案=考卷「必看但 about 不含」的 8 對)

Codex 讀全文、判準明寫「要跨篇推:這篇提到的機制實際守哪些檔,可能要 grep」。

| | 結果 |
|---|---|
| 接住已知答案 | **4 / 8(50%)** |
| 每篇「影響」比「關於」多 | 1~8 支,最多 `autonomous-iteration-loop`(3→11) |

漏的 4 個同型:`anchor-integrity` 接住 pre-commit 漏 impact-hook——**兩支都是被它守的 hook,
模型跨篇推到一半停了**。工具鏈的「影響」是機制性的,邊界要讀程式碼才知道。

改用事故筆記:正文提到的檔就是「改這些會再出同一種事」的直接證據。挑 4 篇(各提 3~5 支)。

## 實驗三:共改歷史當尺(模型多列的 56 支,歷史上跟核心檔一起改過嗎)

Landmark git 1809 commits、358 個動 Server .cs;`lumos cochange rules --all` 5241 條規則。

| | 支數 | 佔多列 |
|---|---|---|
| 歷史上跟事故檔一起改過 | **27**(其中 conf≥0.5 的 17) | 48% |
| 從沒一起改過 | **29** | 52% |

無共改的那 29 支看檔名:發票補登、對帳自癒、管理端 QA——**都碰點數,但跟那幾件事故從沒同時動過**。

★結論:共改歷史是「影響」欄位的尺★——模型語意判斷偏寬,共改行為證據偏窄,兩者對照才收斂。
用「有共改才留」篩,多列噪音砍一半以上,留下的 45 支(18 正文 + 27 共改)全有證據。

## 設計含意(進 [[Projects/固定席扇出降權_計劃]] 當下一步)

1. **「影響」與「關於」分兩欄**,判準分開問。`about_code` 問「這篇講哪支」,
   新欄 `impacts_code` 問「改哪支會違反這篇講的規則」。
2. **`impacts_code` 的寫入流程多一道共改篩**:模型標完,無共改的標 `推測:` 前綴或降級。
   這跟既有 regen 節點的 `推測:`/`佚失:` 標記同款慣例。
3. **事故類節點優先標 `impacts_code`**——那正是 r2 s3f1 打穿降級規則的那類
   (「改 A 出過事」的筆記不列 B,但改 B 的人看到不虧),影響欄正好補這個洞。

## 誠實缺口

- **共改只證「曾經一起改」,不證「該一起改」**(同 commit 順手改不相干的東西);
  反過來從沒一起改過也不代表沒影響(還沒出過那種事)。它是證據層不是真理層。
- **工具鏈 50% 是 8 對的結果,Landmark 94% 是 18 對的結果**——都小。
- **Landmark 事故正文提到的檔是「至少這些」不是「只有這些」**——模型多列的 27 支有共改的,
  可能真的該列,已知答案本身不完整。
- 三個實驗標的人都是 Codex、判準都是我寫的——同源循環,與 about_code 那篇同款。
- **`impacts_code` 平均一篇十幾支**,塞進固定席等於什麼都推——★它的用法要另想★,
  不是照 about_code 那套「命中就排前排」。可能是 hook 顯示「這篇管到你改的檔」的提示層,
  而不是排序層。未定。
