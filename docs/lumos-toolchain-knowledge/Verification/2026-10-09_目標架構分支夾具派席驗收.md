# 2026-10-09_目標架構分支夾具派席驗收

驗的是計劃驗收條款 [S9]:派工單附了目標架構段時,架構對齊席是否依目標規則判段內的檔、段外照鄰居,並以「目標規則:」引句標出違反哪條。

## 怎麼驗

- 夾具:一個臨時 repo,main 上有兩支舊 Billing 控制器(直接打 db)、一支 Domain 聚合 Order(有 pay 方法守「空訂單不可付款」)、一篇目標架構節點(三條 RULE:Domain 不依賴資料庫、不變規則只在聚合根、範圍外只能經應用服務進入),宣告 app/Domain/** 用這篇。feat 分支同時新增範圍內的 OrderRepository(import db)與範圍外的 CheckoutController(直接 new Order、直接改 _status)。
- 用這個分支的 lumos 跑 pitfalls --diff:鄰居組只列 CheckoutController,目標組列 OrderRepository,不印規則。
- 用 dispatch-lens --arch-target 產生目標段(三條規則原文 + 命中檔),照掛鉤附上的位置貼進新版 §7.6 範本,派一席 sonnet 架構對齊。
- 卷證:review-reports 的「架構對齊可宣告目標架構」資料夾裡 s9-fixture.patch、s9-arch-segment.txt、s9-manual-架構對齊-sonnet.md。

## 結果:通過

- 兩組分開答:範圍內照規則判、範圍外照鄰居判。
- 範圍內:OrderRepository 直接 import db → major,附「目標規則:」引句。
- 範圍外反方向依賴兩條都抓到:直接 new 領域物件、繞過 pay 直接改內部欄位 → 各一條 major,附引句。
- 範圍外跟鄰居比,控制器直接打 db 判為本層原本做法、不算跨層——沒有把目標規則誤套到別組。
- 判不準的三處標 ⚠ 交回(requests 是否算第二種 HTTP client、改資料庫列算不算改聚合內部、應用服務層不存在),沒有硬判。
