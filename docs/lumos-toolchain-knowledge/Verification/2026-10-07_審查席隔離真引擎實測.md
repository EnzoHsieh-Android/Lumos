# 2026-10-07_審查席隔離真引擎實測

白話:審查席隔離外掛([[Systems/lumos-guard]])上線後,第一次在真的 Claude Code(2.1.292)上把它宣稱的保護一項項跑過。每項都用「被擋那邊沒有檔、放行那邊有檔」核對,不只看子代理自己的回報。

## 怎麼測

- 暫存 repo 開在家目錄底下(外掛把 `/tmp` 一帶當暫存根,repo 不能在裡面),放一份假的席報告暫存檔。載入主線的審查席隔離與事件帳兩支外掛(`--plugin-dir`)。
- 審查席一律是派工詞第一行帶 `LUMOS-SEAT: probe/r1/s` 的子代理;互動會談用 `expect` 操作(要拿掉 `CLAUDE_CODE_CHILD_SESSION`)。

## 結果

| 項目 | 怎麼做 | 結果 |
|---|---|---|
| 基本隔離 | `claude -p` 派審查席:寫 repo、讀別席報告、寫自己的工作資料夾、跑 `gh` | 寫 repo、讀報告、`gh` 都被擋;工作資料夾寫得進去;repo 沒多出檔 |
| `/clear` 之後 | 互動會談在背景派審查席(先等 40 秒再寫 repo、再寫工作資料夾),派完馬上 `/clear` | 工作資料夾那個檔出現(那一席在 `/clear` 後還活著、跑完了),repo 的檔沒出現(被擋) |
| 熱重載之後 | 同上,但把 `/clear` 換成改外掛檔觸發熱重載,新版把擋下訊息加上 RELOADED 字樣;審查席在重載後跑 `gh`,把擋下訊息寫進工作資料夾 | 寫回來的訊息帶 RELOADED(新版確實載入),新版記憶體是空的卻照樣認得這一席——對照表從 `$.state` 讀回;repo 沒被寫。連帶證實第一次存回 `$.state` 成功 |
| workflow 派出的審查席 | `claude -p` 用 Workflow 工具跑一個 `agent()` | 寫 repo 被擋、寫工作資料夾成功;事件帳在有圖譜的工作目錄裡記到 `agent_type: workflow-subagent`、`seat: probe/r1/s` |

## 沒驗的

- 審查席用 Grep 帶 `file_path`:本機建置的子代理沒有 Grep 工具,測不了。
- 熱重載剛好落在「已啟動、還沒登記完」的那幾毫秒:窗口太窄,實測抓不到,留在計劃的誠實界線。
- 同一行程內 `/resume` 切會談:沒測,回頭條件在計劃裡。
- 一場會談累積多少席要設上限:要一個月的真實資料,回頭條件在計劃裡。
