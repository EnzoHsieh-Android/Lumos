# 2026-09-09 接入靜默失效七項：落地

> 白話：把「閘看起來過了、其實沒作用」的五道靜默補起來。六件是加提醒與產骨架，一件是真的改判定——因為那道閘現在會**主動報告假的好消息**。

## 七項各驗到什麼

| 項目 | 結果 | 怎麼確認的 |
|---|---|---|
| 設定骨架 | ✅ | 單語言猜對、多語言走多平台格式、認不出留空寫說明；產出的是**合法 JSON**（我第一版寫了註解，那會讓整份設定解析失敗） |
| 技術棧不符提醒 | ✅ | 判準是「跟 repo 實際副檔名不符」，設定檔寫死錯的值也照樣出聲；本 repo 實測抓到一條真的 |
| `about_code` 沒接上提醒 | ✅ | 收緊成「有合約且綁測試」後本 repo 2 篇，符合計劃門檻；抓到的其中一篇正是合約測試閘自己的節點 |
| 忽略設定跟設計一致 | ✅ | 治理帳不再被忽略（CI 唯一路徑）、本機留痕目錄改成忽略；既有設定不覆寫 |
| 零覆蓋出聲 | ✅ | 四種來源各一句人話，訊息帶推送前腳本認得的關鍵字 |
| **假綠改成擋** | ✅（代碼審後重做） | 端到端兩個方向：證不出跑過 → 拒絕報綠**而且真的擋下推送**；輸出說得出跑了幾支 → 照樣報綠 |
| 表態訊息兩條路徑 | ✅ | 失敗與成功都不再說「治理帳是 CI 唯一讀得到的地方」那個錯誤主張 |

## 實作時才發現的三件

- **「找不到知識庫」那條原本走不到**：我照計劃把它從另一種狀態裡分出來，但沒有知識庫時，更早的波及計算會**先**失敗成一句沒人看得懂的話。把檢查移到最前面才真的講得出「是不是跑錯資料夾，或這個專案還沒初始化」。
- **既有測試的假執行器本身就是反面教材**：它不管傳什麼測試名都回成功——正是新閘要抓的形態。改成會拒絕不存在的測試名（更像真的測試工具），而不是放寬閘去遷就它。
- **兩支既有測試在斷言被刻意翻掉的舊行為**：治理帳必須被忽略。已改成斷言新行為，並在測試裡寫明為什麼翻。

## 我自己製造的三個錯（兩個被既有守衛接住）

- 在 JSON 設定檔裡寫註解——**那正好會製造出本案要解的那種靜默**（整份設定解析失敗、退回預設）。自己在驗證骨架能不能被讀回來時抓到。
- 新健檢在「知識庫不在 git 專案底下」時直接炸——既有的健檢測試翻紅抓到。
- 把測試檔寫壞而且**先寫檔才驗語法**，整個測試檔一度無法解析。改成先驗語法再寫檔。

## 代碼審 r1 打掉重做了最重的那一項

兩席（一席通才、一席只看架構對齊）共 14 條，全折、零放行。三條 blocker：

- **「假綠改成擋」那句話當時是假的**。我把狀態從「綠」換成「無法確認測試真的跑過」，也印了訊息——但真正決定推送擋不擋的那支只認「紅」，這個新狀態它根本沒在看。結果是：訊息換了一行字，推送照過。
- **判準本身建立在一個沒驗過的前提上**。原本假設「測試工具找不到指定測試時會回非零」。實際去跑：C# 的 `dotnet test --filter` 對不到測試會印「No test matches」然後**回 0**；jest 的 `-t` 對不到會印「1 skipped」然後**回 0**；xcodebuild 就算三段都寫對、方法名打錯一個字，也是跑 0 支**回 0**。八種技術棧裡只有 Python 的 pytest 分得出來（回 5）。**所以原設計會把最常見的幾種棧全部判成「不可信」**——那不是擋錯人就是等於沒擋。
- **猜技術棧時另開了第三份手寫的副檔名對照表**，而且已經漂出錯值：`.vue` 寫成一個根本不存在的符號設定值。真的照那份骨架設定下去，使用者每次讀設定都會看到一行警告，而且不會知道為什麼。

## 新的判準：不看退出碼，看它自己說跑了幾支

- 測試工具跑完都會在輸出裡講「執行了幾支」：xcodebuild 印「Executed 1 test」、C# 印「Passed: 1」、jest 印「Tests: 1 passed」、pytest 印「1 passed」。**跑 0 支的時候這行會變成 0 或整個不見**。
- 所以現在的做法是：指令回成功之後，再去它自己的輸出裡找這行。找得到＝真的跑過，綠算數；找不到＝它說成功但什麼都沒跑，不能算綠。
- 這比原本的做法強在**逐支判**：合約上綁的測試名打錯一個字，只有那一支會被抓出來，不是整批一起判。
- 只填了在這台機器上真的跑過、而且**對照過「跑 1 支」與「跑 0 支」兩種輸出**的四種。其餘四種沒有可跑的實例，留空、退回舊的冒煙測試——不憑想像寫樣式。

## 一個意外收穫：`-quiet` 本身就是個坑

計算機專案原本的測試指令帶了 `-quiet`。把「跑 1 支」和「跑 0 支」兩次輸出存下來逐行比對，**兩份完全一樣**（只差時間戳）——`-quiet` 把唯一能證明跑過東西的那行藏掉了。所以：

- 產出的 Swift 骨架指令刻意不帶 `-quiet`，註解寫明理由。
- 擋下來的訊息直接點名這件事，不是丟一句「證不出跑過」讓人自己猜。
- C# 的骨架則反過來加了一個旗標（`RunConfiguration.TreatNoTestsAsError=true`），實測加了之後對不到測試就直接回非零——那條指令因此連退出碼都變可信。

## 沒驗到的

- **冒煙測試只在兩種執行器上驗過**（xcodebuild、shell 假執行器）。若有測試框架在「找不到指定測試」與「測試失敗」兩種情況都回非零，會被判成可信——那是保守方向，不會誤擋，但也就抓不到那種假綠。回頭條件在計劃節點。
- **CI 端完全沒跑過**：忽略設定的改動要等真的有專案接 CI 才驗得到。
- **既有專案不受影響**：只改初始化行為，已經產生的忽略設定不動——所以計算機專案目前仍是錯誤狀態（本機留痕被版控、治理帳被忽略），那是刻意留著當「既有專案遷移」的第一個樣本。
- 本 repo 健檢剩 1 個既有問題（合約測試閘的驗證節點被標失效），而它的重驗條件正是本次改到的那幾支函式——這篇就是那次重驗。
