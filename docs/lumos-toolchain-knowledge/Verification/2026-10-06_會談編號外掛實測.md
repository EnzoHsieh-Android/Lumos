# 2026-10-06_會談編號外掛實測

白話:想讓外掛每回合把「當下的會談編號」交給 lumos,並記下自己看到的官方編號做配對。實作前先實測三種情況,結論是外掛看到的官方編號跟 Bash 看到的不是同一份,配對的前提不存在,這項停下。

## 怎麼測

在一場 Claude Code 會談的 Bash 裡,用 `claude -p --plugin-dir <lumos-context 資料夾>` 開子會談,叫它在 Bash 印出 `LUMOS_SESSION_ID`、`LUMOS_SESSION_BASE`、`CLAUDE_CODE_SESSION_ID` 三個值,同時記下 `claude -p` 回報的會談編號。當時外掛的回合開始掛鉤:讀 `CLAUDE_CODE_SESSION_ID` 當 BASE、讀 `$.session.id()` 當 ID,兩個都設進環境。

## 結果

| 情況 | Bash 看到的官方編號 | 外掛記下的 BASE | 外掛設的 ID |
|---|---|---|---|
| 會談裡再開 `claude -p` | 子會談自己的(對) | 外層會談的舊編號 | 子會談自己的(對) |
| 同上再 `--resume` 接續 | 跟接續前同一個(`-p` 接續不換編號) | 外層會談的舊編號 | 同左 |
| 把環境裡的官方編號拿掉再開(模擬從終端機直接開) | 子會談自己的(對) | 空 | 空(BASE 空就兩個都不設) |

- 外掛的 `$.env.get` 讀的是 `claude` 這支程式啟動時繼承來的環境;Bash 的官方編號是 `claude` 另外塞給子程式的,外掛看不到。
- 所以從終端機直接開的會談,外掛讀到空值,整項等於沒做;會談裡再開的子會談,BASE 是外層的編號。
- `claude -p --resume` 接續不換編號,重現不了「接續後停在舊值」;本會談自己就是例子(對話壓縮後接續,環境裡的官方編號仍是接續前的),要另外找方法重現。

依計劃寫好的規則(任一步不過就整項停下,不走別的備案),這項不做。要做得重新設計,例如改比對程式編號,另開題。

## 2026-10-07 補測:改用程式編號配對

- 外掛的 JavaScript 環境拿不到 `process.pid`(印出來是空的),型別檔的 `$.session` 也沒有程式編號。
- 外掛用 `$.process.run(['sh','-c','echo $PPID'])` 開一個小程式問父程式是誰,拿到的編號跟 Bash 看到的 `CLAUDE_PID` 一樣(`claude -p --plugin-dir` 實測,兩邊都是 92719)。所以配對可以改成:Bash 的 `CLAUDE_PID` 等於外掛記下的編號,才採用外掛給的會談編號;會談裡另開的 `claude -p` 是另一支程式,編號不同,不會讀錯。

## 2026-10-07 互動會談實測(Claude Code 2.1.292)

用 `expect` 開互動的 `claude`(載入實驗外掛,拿掉 `CLAUDE_CODE_CHILD_SESSION` 才存得了逐字稿、接續得了),叫它把外掛設的編號、外掛記的程式編號、`CLAUDE_PID`、`CLAUDE_CODE_SESSION_ID` 寫進暫存檔:

| 情況 | 官方 `CLAUDE_CODE_SESSION_ID` | 外掛設的編號 | 程式編號配對 |
|---|---|---|---|
| `/clear` 之後 | 換成新編號 | 換成新編號 | 對得上 |
| `/compact` 之後 | 不變 | 不變 | 對得上 |
| 互動模式 `--resume` 接續 | 不變 | 不變 | 對得上(新程式、新編號) |

- 結論:這三種常見情況下,官方編號本來就是對的,外掛給的跟它一樣。「接續或 `/clear` 後官方編號停在舊值」在這三種情況重現不出來。
- 2026-10-06 看到的舊值,出在一場從 claude.ai 遠端橋接、又因內容太長而接續的會談;要不要追那條路徑,由 [[Issues/會談編號環境變數接續後停在舊值]] 的回頭條件決定。
- 所以「會談編號交給 lumos」這項不必做;程式編號配對的做法留著,真有需要再用(到時再量每回合多開一次小程式的時間)。
