# 持久用量帳第七輪審查修補驗證

## 結論

第七輪七席審「第六輪修補差異加上合併主線時手解的衝突」（修前 483df9fe、修後 3e149721、合併 67b1dea2）。一條重大：報表自創的 `⟦U+XXXX⟧` 是 lumos 主程式既有「控制字元寫成 `\uXXXX`」之外的第二套做法，改成跟主程式 `_kill_esc` 同一套類別與寫法。其餘小問題收成五組：

- 字元裝置：開跑前檢查、取代寫入、歷史追加三處共用同一個開檔函式，不阻塞、不跟隨連結、不收控制終端、確認仍是字元裝置、改回阻塞；開跑前實際試開一次。
- 暫存檔權限：要沿用的權限在暫存檔建立時就套上，寫入前補回原值。
- 歷史追加：開檔後只收只有一個名字的普通檔與字元裝置；開跑前也擋多名字。
- 測試：借鬧鐘抓卡住後把測試執行器的逾時還回去；「不碰 umask」改成行為檢查（寫入期間任何人呼叫 umask 就失敗）。
- 其他：暫存檔重試迴圈加 100 次上限；為測試留的使用者判斷函式寫明來由；合併後主程式家筆記裡兩條互相矛盾的終端測試說明另行更正。
