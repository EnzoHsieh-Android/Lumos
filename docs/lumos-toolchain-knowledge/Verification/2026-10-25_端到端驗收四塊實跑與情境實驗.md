# 2026-10-25_端到端驗收四塊實跑與情境實驗

白話:第一批合進主線後做兩件事。一是把實驗室的四塊(UI 流程、截圖、記憶體與穩定性、效能)全開,在平板上各跑一次該過與該擋;二是用情境探針問 Claude 口語的開發任務(不提端到端驗收),看它會不會自己走到這套驗收,手冊更新前後各跑一次。這不是計劃〈實驗室驗收〉那一整套(S19),每塊只各跑一組。

## 四塊實跑

實驗室 `macrobench-lab-e2e`(分支 e2e-lab):裝上 maestro-visual-toolkit、錄主畫面基準圖 `main_visual`(Claude 錄、看過畫面正常;實驗室筆記寫了這個例外);`e2e` 段開 visual、stability、macrobench(`sh scripts/run-bench.sh scrollList`);app_dirs 加上 macrobenchmark 模組。

| run-id | 情況 | 回傳 | 結果 |
|---|---|---|---|
| lab-full-1 | 沒有 trace_processor | 1 | UI、截圖過;記憶體六項都記「沒判完」(收集腳本回 2、缺工具),沒有誤記成沒過 |
| lab-full-2 | 有 trace_processor、沒有 java_heap_dump | 1 | 同上,原因換成缺 java_heap_dump(宣告了測試資料就要錄快照) |
| lab-full-3 | 兩支都用環境變數指定 | 0 | 四塊通過,約 3 分鐘(建置有快取、效能 5 輪,印「輪數不足 20」提醒) |
| lab-leak-1 | 另開分支拿掉原生 SDK 的 release 並提交 | 1 | 只有 native_unreachable 紅,其他五項與 UI、截圖照過 |

- 穩定性那塊在實驗室用 instrumentation 驅動,要另外裝測試用 APK;範本只裝主 App,所以實驗室把測試 APK 的安裝接在 build 指令後面。計劃的設計是 Maestro 驅動,換過去就不用這段(S19 那一項)。
- 缺工具要跑完前面幾塊才發現;當天就讓範本腳本的開跑前檢查先查這兩支(測試 t_android_e2e_preflight_stability_tools),之後缺工具在動 App 之前就回 2。

## 情境探針(三題,每題一次)

題目:a 主畫面清單字放大、驗收後提交;b Compose 清單每列前加符號、照專案流程驗過再提交;c 只問改了畫面推之前要做哪些驗收。三題都寫明不准推送。判準是 Bash 有沒有出現 `android-e2e`(c 另看回答)。

| | 手冊更新前(全域 lumos 停在 7d17bd73、手冊沒有 android-e2e;實驗室只開 UI 一塊) | 更新後(全域 45c2bf25;實驗室四塊全開) |
|---|---|---|
| a | 過;讀工具原始碼 3 次才找到;跑了驗收(只有 UI 一塊) | 過;從指令手冊自檢表那一列找到、0 次讀原始碼;提交 → 驗收 → 提交紀錄,四塊通過 |
| b | 過;讀原始碼 2 次;跑了驗收 | 第一場逾時 2700 秒不算分(先自己跑的 Compose 滑動基準偶發紅,大半時間在查它);放寬到 3600 秒重跑一場:過,43 個工具呼叫,從 --help 與手冊找到,提交 → --preflight → 整套驗收(四塊通過)→ 提交紀錄;回答裡照實說這套驗收只涵蓋主畫面、Compose 頁靠它另跑的滑動基準守著 |
| c | 過;15 個工具呼叫、127 秒 | 過;10 個工具呼叫、97 秒,四塊都講對;仍讀了 4 次原始碼確認細節 |

- 兩組不只差手冊:更新後那組實驗室設定也開齊了四塊,所以 a 跑完四塊有一部分是設定的功勞;「從手冊找到、不讀原始碼」才是手冊的效果。
- 更新後 a 遇到截圖比對 94.4% 沒過時,自己並排看新舊圖、重錄基準圖再跑,依據是實驗室筆記寫的例外;正式專案換基準圖要人看過,README 寫明了。
