# 2026-08-01_公開精簡版代碼審第四輪修復

## 為什麼要做

[[Verification/2026-08-01_slim-install注入目標守衛]](Task 11)交付後,分支終審第四輪代碼審對三層守衛實作又抓到兩條殘留 finding:

- **① MAJOR**:`t_slim_install_guard_here_bypasses` docstring 宣稱驗「`--here` 繞過第二層」,但 fixture 是**一個空目錄**。空目錄永遠不會滿足第二層(`skills/lumos-project-notes/`+`scripts/lumos`+`scripts/templates/graph-discipline.md` 三件套齊備)的判定條件,所以這條測試從頭到尾只驗到第一層——把第二層整段刪掉它照樣綠,半個逃生閥零回歸覆蓋。★這是這個專案第八次撞到「測試存在但沒在驗它宣稱要驗的」★(前有:等價閘比 `''==''`、doctor 閘收下 NameError、守衛測試撞到別的預檢先失敗、上一輪 `t_slim_install_guard_repro_real_incident` 的稻草人)。
- **② MINOR**:`slim/install.sh:76` 的守衛判斷與印目標邏輯用 `$(pwd -P)`(解 symlink),但(改前)`:207` 算 CLAUDE.md 寫入路徑用的是素樸 `$(pwd)`。兩者指向同一個檔案不會寫錯地方,但 cwd 經 symlink 進來時,稽核印出的路徑字串可能與實際寫入路徑不同——弱化第三層「把目標印出來讓人眼抓錯」的價值。

## 修法

### ① 換 fixture,分兩段跑

`t_slim_install_guard_here_bypasses` 的 fixture 改成與 `t_slim_install_guard_rejects_source_repo` 同款——真的滿足第二層三件套齊備、且也帶 `.git`/`docs/*-knowledge/`/`CLAUDE.md`(模擬真實事故現場)。測試分兩段:①不帶 `--here` 先斷言確實被第二層擋下(rc=2、CLAUDE.md byte-equal 未動)——沒有這段就沒資格談「繞過」;②帶 `--here` 斷言放行(rc=0、CLAUDE.md 被更新、第三層印出仍在)。

**竄改驗證**(把第二層 `if` 換成 `if false; then`):3/5 checks 翻紅(含核心的「不帶 --here 應被擋下」那條),證明新 fixture 真的走進第二層判斷式。竄改後立即用備份還原,`git diff` 確認無殘留。

**額外檢查其他守衛測試**(逐一過六支 `t_slim_install_guard_*` + `t_slim_uninstall_refuses_foreign_bin`):只有 `here_bypasses` 有這個毛病,其餘 fixture 皆確認能真的觸發它宣稱要測的分支(`rejects_source_repo`/`repro_real_incident` 兩條上一輪審計已留有竄改證據,本輪複核既有記錄未重複竄改)。

### ② `CLAUDE_MD` 改用已解過 symlink 的 `TARGET_CLAUDE_MD`

`slim/install.sh:207` 改成 `CLAUDE_MD="$TARGET_CLAUDE_MD"`(重用第 77 行已用 `pwd -P` 算好的值),不再重新呼叫一次 `pwd`,兩處保證同源、不會分岔。

新增回歸測試 `t_slim_install_symlink_cwd_audit_path_matches_write_path`。**怎麼逼出分歧(關鍵坑)**:單純 `subprocess.run(cwd=<symlink 路徑>)` 逼不出分歧——OS `chdir(2)` 一律解到實體路徑,bash 起手若沒有匹配的 `$PWD` 環境變數可承接,素樸 `pwd` 也會回退成實體路徑。真實情境是使用者的互動 shell 先 `cd` 進 symlink(那個 shell 會把 `$PWD` 設成 symlink 形式的邏輯路徑並 export),再從那裡呼叫 `bash install.sh`——子行程 bash 沿用繼承到的 `$PWD`(經 stat 驗證與 `getcwd()` 同一個目的地就採信)。已手動驗證此 bash 行為(`PWD=<symlink> bash -c 'cd <symlink>; echo $(pwd); echo $(pwd -P)'` 兩者確實分岔)。測試用 `env=dict(..., PWD=<symlink 路徑>)` + `cwd=<symlink 路徑>` 重現,比對 install.sh 開頭印的「將修改: X」與收尾印的「✓ CLAUDE.md …已安裝/更新: Y」是否為同一字串。

**竄改驗證**(改回素樸 `$(pwd)/CLAUDE.md`):2/6 checks 翻紅(稽核路徑=實體路徑 real-proj,實際寫入路徑=symlink 邏輯路徑 link-proj,確實分岔)。竄改後立即還原、複測轉綠。
