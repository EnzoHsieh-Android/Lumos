# 2026-09-11_全報vs抑噪試點

> 白話:官方 Sonnet 5 文件說,審查派工詞叫審查員「保守、只報重要的」,它會照做而少報;建議叫它全報、交給後段過濾。我們的代碼審派工詞裡正好有兩句「抑噪紀律」。這次拿同一份已知答案的材料、同一個模型,只換這一段,各派三席比。照事先寫死的判準,結論是「維持現狀」;但全報那組多找到的十條經盲評全部是真問題、沒有假警報,這個訊號判準沒涵蓋,留給人決定要不要擴大重做。

## 怎麼做

- 材料:`code-資安席與多平台指令` 第一輪凍結 patch(1421 行);查證用的程式樹從 b4926d9c 套上那份 patch 還原,兩支主檔指紋與當時一致(不是現在已修好的 repo)。
- 六席都用 Agent 的 sonnet,派工詞除一段外逐字相同:A 組保留現行「抑噪紀律」兩句;B 組換成官方 Sonnet 5 審查建議的中文版(全報、附信心與嚴重度、由後段過濾)。兩組輸出格式相同。
- 標準答案 7 條(第一輪程式裡確實存在、後來被確認的問題,K1–K7,見計劃 [S1])。
- 報告檔名 s1–s6 隨機分派;評分交給不知道有兩組的乾淨 agent,逐條標「命中 Kx / 其他真問題 / 假問題 / 判不出」,其他真問題與假問題要附實跑或讀碼證據。
- 判準(派工前寫死):B 組三席平均命中 K 比 A 組多 1 條以上,且 B 組假問題占比不超過 A 組兩倍 → 建議改派工詞;否則維持現狀。
- 卷證:`governance/review-reports/skills-prompt-ab-2026-09-11/`(design.md 派工當下寫、scoring.md 盲評、arm-map.json 評分後才公開的分組)。

## 結果

| | A 組(抑噪,現行) | B 組(全報,官方建議) |
|---|---|---|
| 三席共報 | 6 條 | 16 條 |
| 平均命中已知問題 | 1.0 條(s3:K2;s4:無;s5:K1、K5) | 1.33 條(s1:K1、K5;s2:K1;s6:K1) |
| 已知問題以外的真問題 | 3 條 | 12 條 |
| 假問題 | 0 | 0 |

- 照判準:B 組只多 0.33 條已知問題,沒達到「多 1 條」→ **維持現狀**,不改派工詞。
- 判準沒涵蓋的訊號:B 組多報的 10 條全部經盲評實跑或讀碼確認成立、假問題 0。判準刻意只看已知問題(免得事後挑對自己有利的數字),所以這個訊號不能拿來翻判準,只能拿來決定「值不值得擴大重做」。
- 兩組都沒找到 K3(尾端空白)、K4(第二種解析做法,架構面)、K6(補救指令沒加引號)、K7(設計面天花板)——這幾條在真迴圈裡是外家席、架構席、資安席抓到的,單一通才鏡頭本來就少碰。
- 副產品:評分點名的「其他真問題」拿現在的程式重跑,有三條屬實且當時還在(不分輪零發現的高風險迴圈資安席誤判、PASS 橫幅漏列新步驟、沒設測試指令的提醒講兩遍),已折進該代碼審第三輪(O1–O3)。

## 誠實界線

- 每組三席、單一材料,是試點,不宣稱顯著。評分只有一個 agent,沒有第二評分者。
- Agent 的 `sonnet` 別名目前對到哪一版沒查;官方那段建議寫的是 Sonnet 5。
- 2026-08-04 那次只差這兩句的配對實驗量的是「抓不抓得到故意埋的錯」(p≈0.47 未定論,見 [[Projects/canary注意力檢查失效]]);這次量的是真材料上的真問題,兩次都沒達到改的門檻。
