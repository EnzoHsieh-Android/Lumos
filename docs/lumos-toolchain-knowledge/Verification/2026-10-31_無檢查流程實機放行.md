# 2026-10-31_無檢查流程實機放行

白話:驗的是「流程裡沒寫檢查時,App 壞了端到端驗收會不會照樣判 UI 通過」。結論:會。這是 [[Projects/UI流程驗收句與檢查對照_計劃]] 的動機實測;「通過」指實驗照預期重現了這個洞,不是驗收機制通過。

## 怎麼做

- 從 macrobench-lab 的 e2e-lab 分支另開一個工作樹,建 benchmark 版裝到 SM-X710。
- 兩支流程:原本的清單流程(打開 App、檢查「第 1 列.*」出現);同名但拿掉檢查的版本(只打開 App)。
- 兩版 App:正常版;改壞版(清單頁每一列的文字設成空字串)。

## 結果

| | 正常版 | 改壞版 |
|---|---|---|
| 有檢查的流程 | 回 0 | 回 1(「第 1 列.*」找不到) |
| 拿掉檢查的流程 | 回 0 | 回 0 |

- 把清單流程換成拿掉檢查的版本、App 維持改壞,照正式流程跑 `--case list.scroll --no-perf`:判定印「✓ UI 流程 .maestro/list.yaml」。整體判沒過,原因是截圖那支流程開頭自己的「第 1 列.*」檢查先紅(判定印「flow 在比對前就失敗」),不是截圖比對抓到。那次的 steps.json:build 0、install 0、ui 0、visual 1。
- 同場另跑一支探針(系統設定 App),確認 `--debug-output` 的 commands.json 會帶每條指令的 label 與狀態:完成的檢查記 COMPLETED、`optional: true` 失敗的記 WARNED、條件不成立的 runFlow 記 SKIPPED 且裡面的檢查不出現。

## 過程中出過的錯

- 第一輪記回傳碼時,`echo "… $(basename $f) rc=$?"` 的命令替換先把 `$?` 蓋成 0,兩版都記成 0;看紀錄文字發現不對,改成先存 `rc=$?` 再印,上表是改正後的結果。
- 改壞版第一輪拿掉檢查的那支遇到「Maestro Android driver did not start up in time」,沒跑起來;重跑正常。

實驗工作樹、分支、Maestro 的 ~/.maestro/tests 下這次產生的目錄都已刪除;實驗 App(com.example.mblab)已從平板移除,平板回到實驗前只裝 com.example.mblab.bench 的狀態;實驗時建置啟動的 Gradle 背景程序(確認是這次 21:15 啟動的那一個)已關。
