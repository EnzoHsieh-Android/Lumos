# 2026-11-08_detekt的CI型別檢查範本實跑

> 白話:驗 [[Projects/Android的detekt推送前真的擋_計劃]] 的手驗條款 S9——照 [[Systems/linter精選目錄]]〈②CI 型別檢查範本〉在真的 Android 專案接上 detekt 的 Gradle 外掛,產基準線後新增一處寫死 `Dispatchers.IO`,CI 那一步要擋;沒新增時要過。**結果:成立。**

## 怎麼跑

- 專案:`git clone --shared` macrobench-lab(提交 222b80a)到會談暫存區,只改複本;AGP 8.13.2、Gradle 8.13、Kotlin 2.2.21、JDK 17(jbr-17.0.14)。
- 照範本在 `app/build.gradle.kts` 加 `id("io.gitlab.arturbosch.detekt") version "1.23.8"` 與 `detekt { buildUponDefaultConfig = true; config.setFrom(…); baseline = file("config/detekt/baseline.xml") }`;共用設定 `configs/detekt/android.yml` 複製進專案(sha256 相同)。範本沒寫外掛套在哪一層,照 detekt 官方 Gradle 文件(https://detekt.dev/docs/gettingstarted/gradle/)直接套在有 Android 變體的 app 模組。

## 結果

| 步驟 | 指令 | 耗時 | 結果 |
|---|---|---|---|
| 產基準線 | `./gradlew :app:detektBaselineDebug` | 16.97 秒(含首次編譯) | 成功;寫成 `app/config/detekt/baseline-debug.xml`(15 筆:MagicNumber 12、MaxLineLength 2、UnusedPrivateProperty 1) |
| 沒新增時 | `./gradlew :app:detektDebug` | 1.69 秒 | 成功;報告 `Findings (0)`,基準線 15 筆都被濾掉 |
| 新增 `withContext(Dispatchers.IO)` 後 | `./gradlew :app:detektDebug` | 1.92 秒 | 失敗 rc=1;`LabWork.kt:26:89: Dispatcher IO is used without dependency injection. [InjectDispatcher]` |

## 範本與實測對不上的

- 基準線檔名:範本設 `baseline.xml`,變體任務實際寫 `baseline-debug.xml`(外掛自動加變體名),`detektDebug` 也讀這支。範本那句已改成實測值。
- InjectDispatcher 能報是靠 `buildUponDefaultConfig = true`:detekt 1.23.8 預設設定開著這條,共用設定沒有另外寫。
- 外掛另外產出 `detektMain`、`detektBaselineMain` 與各變體的任務,說明文字都標 EXPERIMENTAL。
- Kotlin 2.2.21 專案配 detekt 1.23.8(以 Kotlin 2.0.21 編)跑得起來,沒有版本不合的錯誤。

實驗複本與各步驟輸出在會談暫存區,要留的結果都寫在這一篇,收尾已刪。
