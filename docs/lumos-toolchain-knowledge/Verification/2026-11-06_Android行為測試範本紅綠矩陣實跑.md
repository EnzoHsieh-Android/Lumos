# 2026-11-06_Android行為測試範本紅綠矩陣實跑

> 白話:照範本檔開頭〈實驗專案骨架〉把每一組的每一格(測試小節 × 被測程式小節)組成一個純 JVM Gradle 子專案,真的跑 Gradle、讀 JUnit XML,看每支測試是不是矩陣寫的結果;每個紅用收證工具的 `assertion_failure` 判是不是斷言失敗。驗計劃的 S3、S4 與實驗 E1–E7(E8 自檢那一項在 repo 測試裡,見 [[Systems/kotlin規則包]])。

## 做法

- 用一支會談暫存區的小程式讀範本檔:每組 `## T<n>` 節的〈紅綠矩陣〉每一列組成一個子專案——`build.gradle.kts` 照〈實驗專案骨架〉、`dependencies` 貼那組〈依賴〉(T4 依測試小節挑〈依賴:OkHttp 4〉或〈依賴:OkHttp 5〉);`src/test/kotlin` 放那一列的測試小節與〈假依賴〉;`src/main/kotlin` 放〈好寫法〉每一段,再用那一格點名的小節換掉開頭宣告同名的那段(不同名的加上去)。所以跑的程式就是範本檔裡的字,沒有另抄一份。
- 57 格一起建成多專案,`gradle test --continue` 跑一次;再 `gradle test --continue --rerun` 連跑 20 次(每次 11–14 秒,XML 的 timestamp 對得上最後一次,確認真的重跑、不是讀舊報告)。
- 判定:矩陣寫「斷言紅」的,XML 失敗節點要經 `assertion_failure` 判成真,而且訊息含矩陣寫的片段;寫「逾時紅」的,型別要是 `UncompletedCoroutinesError`;沒點名的(「其他綠」)要綠;小節裡每支 `@Test` 都要出現在矩陣(「全綠:」列出全部名字)。

## 結果

- S3:57 格、209 個測試結果,第一次全對與 20 次重跑全部「不符 0 項」;每支測試 21 次的結果與失敗型別都一樣(T0 的 TEST-9 三格、T1、T2、T4 全部在內,T3、T5 也一起跑了)。
- E1:〈測試〉列的每個紅都判成斷言失敗;非斷言的紅只有 T0〈壞測試:TEST-5〉與〈壞測試:TEST-17〉兩格的 `UncompletedCoroutinesError`,矩陣本來就寫逾時紅。原本會是例外紅的八列(API-34、FLOW-29、FLOW-23、FLOW-20、API-26、API-21、DATA-72、DATA-73)都改成 `runCatching`/`backgroundScope` 加斷言,實跑是斷言紅。
- E2:每個〈壞寫法〉格只紅矩陣點名的那支;一次例外是 DATA-73 的壞寫法連帶讓 DATA-72 那支紅(JSON 沒帶 status),改測試 JSON 帶上 status 後只紅點名那支。
- E4:〈壞測試:TEST-4 沒推進就斷言〉在 `MainDispatcherRule(StandardTestDispatcher())` 下斷言紅 `expected:<Loaded(name=Ada)> but was:<Initial>`;同一支換成 nowinandroid 預設的 `MainDispatcherRule()`(Unconfined)照綠——明傳 Standard 是必要的。
- E5:`lifecycle-viewmodel-testing:2.9.4` 的 `viewModelScenario { … }.recreate()` 在純 JVM 能還原 `SavedStateHandle` 內容,T3〈測試〉改用它;舊專案沒有那個套件時用〈測試:複製 handle 版〉,兩版矩陣結果一樣。測試品質標準「畫面重建與程序被回收」那條不用補句。(**已被代碼審 r1 推翻**:viewModelScenario 版在 Android 模組的本機單元測試例外紅,T3 預設改回複製 handle 版、測試品質標準那條也改寫,見下方〈代碼審 r1 修正後重跑〉)

## 實驗推翻的寫法與改法

- **Turbine 自己的檢查不算斷言**:T0 的 `awaitComplete()`、`awaitError()` 對壞寫法紅的是 `app.cash.turbine.TurbineAssertionError`。它是 `java.lang.AssertionError` 的子類別,但 `assertion_failure` 照型別名判、不認它;計劃不改收證工具,範本改成 `awaitEvent()` 取事件後 `assertEquals(Event.Complete, …)`、`assertIs<Event.Error>(…)`,T2 的 `expectNoEvents()` 改成 `assertEquals(emptyList(), cancelAndConsumeRemainingEvents())`。依據:Turbine README 自己的範例輸出就是 `app.cash.turbine.TurbineAssertionError: Unconsumed events found`;`awaitEvent`、`cancelAndConsumeRemainingEvents` 是 1.2.1 的公開 API(javap 讀 `ReceiveTurbine`)。
- **backgroundScope 的工作 advanceUntilIdle() 不推**:它只推到前景沒有工作為止;FLOW-29、FLOW-18、FLOW-20、FLOW-24 這種工作在 `backgroundScope` 的,範本用 `runCurrent()`。寫在範本〈怎麼用〉與測試品質標準協程段的指路句。
