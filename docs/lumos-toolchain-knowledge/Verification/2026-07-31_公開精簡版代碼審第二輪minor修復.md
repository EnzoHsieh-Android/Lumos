驗證對象:[[Projects/公開精簡版_實作計畫]] Task 6 落地後,分支終審**第二輪**代碼審(canary-log `code-loop-slim-handoff` r1/r2)又抓到的兩條殘留 minor——第一輪修的是「候選 text 從開頭截斷」,這輪修的是「開窗位置回報本身不可靠」;第一輪沒測過的「uninstall 連跑兩次」也在這輪補齊。落地報告:`.superpowers/sdd/公開精簡版_實作計畫/task-7-report.md`。

## minor-1:`_windowed_text()` 用 `.find()` 猜命中位置,不是真命中位置

**問題**:`scan_line()` 回傳 `(token, form)`,呼叫端(`scan_python_file`/`main`)另外用 `_windowed_text()` 對整段字串 `.find(token.lower())` 找開窗中心——這是「找 token 第一次以子字串出現的位置」,不是「`scan_line()` 判定命中的那個位置」。真實案例:`scripts/lumos:415-417` 的 docstring 裡,`gov`(來自 `governance`)出現在第 64 字,真正被 `scan_line()` 命中的 `lumos gov` 在第 123 字,間距 ~59 字。第一輪修的視窗半徑是 58,間距恰好比半徑多 1,勉強罩不到——但這是巧合,間距再拉大(如 token 是別的詞字首、字首詞離真命中更遠)視窗會完全開錯地方。

**修法**:`scan_line()` 改回傳 `(token, form, pos)`——每種形態自己在判定的當下回報觸發位置(prefixed 用 `m.start(1)`、backtick 系用 `m.start(1) + content.find(first)`、skill-name 用 `line.find(s)`、prose 用 `m.start()`)。`_windowed_text(norm, idx, token)` 不再自己猜,直接吃呼叫端給的 `idx` 開窗。★連帶修正★:為了讓 `scan_line()` 回報的 `pos` 與 `_windowed_text()` 開窗用的字串座標系一致,呼叫端(`scan_python_file`/`main`)改成**先正規化(`" ".join(s.split())`)再餵給 `scan_line()`**,而不是先掃原始字串(含真實換行/多重空白)、事後才對 `.strip()` 過的字串開窗——後者兩份字串座標系不同,`pos` 對不上會導致開窗仍然錯位。

**紅→綠**(`t_slim_scan_window_uses_real_hit_position`,`scripts/test_lumos.py`):造一段文字,先放 `governance`(含 `gov` 子字串但不觸發任何比對形態——3 字短於 prose 形態門檻 4,且不含反引號/`lumos ` 前綴/skill 名),隔 70 字填充文字(> 58,視窗半徑),再放真正觸發 prefixed 形態的 `lumos gov`。

## minor-2:`uninstall.sh` 缺「連續跑兩次」的冪等回歸測試

**問題**:`uninstall.sh` 是刪檔案的腳本,接手者「保險起見再跑一次確認乾淨」是自然行為,但原本只測過跑一次。

**調查結果**:讀腳本(`slim/uninstall.sh`)+ 手動在暫存目錄跑兩次確認——**腳本本身不需要改**。BIN/SKILL/PKG 三步判斷式第二次跑時全部落入「東西已經不在」的 `else` 分支(純 `echo`,不觸發任何 `exit`),語意上與「這台機器本來就沒裝過」完全等價,而那個情境本就是 rc0。三步都不會二次觸發副作用:①BIN 已被 `rm -f` → `[ -e "$BIN" ] || [ -L "$BIN" ]` 為假;②SKILL 已被 `mv` 走 → `[ -d "$SKILL" ]` 為假,進不了備份分支,不會多出 `.bak.*`;③PKG 已被 `rm -rf` → `[ -d "$PKG" ]` 為假。故新增的是**純回歸測試**,鎖住這個已經正確的行為,防未來改動悄悄破壞冪等性。

**rc 判定理由**:第二次 rc 判定為 **0**——idempotent 工具(`rm -f`/`apt remove` 之類)的慣例是「不需要做事=成功」不是「報錯」;且腳本現有的「未安裝」分支本來就是 rc0(對應「這台機器從沒裝過」的情境),第二次卸載在語意上與此情境等價,理應同一個 rc。若判 rc 非 0,反而會讓接手者「保險起見多跑一次」這個自然動作被腳本自己判定為失敗,徒增困惑。

**測試**(`t_slim_uninstall_idempotent_second_run`,`scripts/test_lumos.py`):裝好 → 塞使用者自訂檔進 skill 目錄 → 跑第一次 uninstall(斷言 rc0、備份存在)→ **再跑一次** uninstall,斷言:①rc0 ②備份目錄數量不變(仍是 1,沒多產生空備份)③第一次備份出來的自訂檔內容第二次跑完後仍與跑之前一致 ④PKG/BIN 仍不存在(沒有詭異重建)。

```

  ✓ 冪等回歸測試前置:install.sh rc0
  ✓ 第一次 uninstall rc0
  ✓ 第一次跑完備份存在(前置條件)
  ✓ ★minor-2★ 第二次 uninstall 不炸,rc=0(冪等——語意等同「本來就沒裝」)
  ✓ ★minor-2★ 第二次不產生多餘的空備份目錄(數量不變,仍是 1)
  ✓ ★minor-2★ 第一次備份出來的自訂檔,第二次跑完後仍完好
  ✓ PKG 目錄第二次跑完後仍不存在(沒有詭異重建)
```
