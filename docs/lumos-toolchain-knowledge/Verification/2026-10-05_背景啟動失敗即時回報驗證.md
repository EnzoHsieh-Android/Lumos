## 混版與剩餘限制

以 F1 帳本版本 e5695c11 的舊 hook 搭配新 CLI 回應故障注入：rc0、角色卡可見，但沒有「本次背景未啟動」提示，也沒有 error 事件；因此舊 hook＋新 CLI 不在本地放行範圍。反向用新 hook 搭舊 CLI 的 lock_error 回應：舊錯誤提示、角色卡及 error 事件均保留。實際安裝前須在原案 S6 核對 hook 與 CLI 成對版本並在該環境重驗。

清鎖被權限拒絕時，本次回 spawn_error 與 lock_cleanup_error；下一次仍可能因殘鎖回 rc5。這不是已自動復原的情境；現場出現該欄位時按計劃事件入口檢查權限與真實持有者，不能按 PID 或鎖齡擅自刪鎖。Python 官方 subprocess 文件只保證可觀測的建構子 OSError 路徑；子程序建立後立即退出仍需另一種啟動確認，見計劃 PRIOR-ART 與 RETIRE-IF。
