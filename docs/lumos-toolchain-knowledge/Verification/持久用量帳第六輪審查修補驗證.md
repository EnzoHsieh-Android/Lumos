# 持久用量帳第六輪審查修補驗證

## 結論

第六輪七席審第五輪修補的差異（修前 4d765d5c、修後 483df9fe），十九條發現同根因收成八組，兩條重大都是第五輪修補自己帶出來的：把 FIFO 也當裝置直接寫，沒人讀時整批跑完後永遠卡住；為了讓新檔照 umask，把整個程序的 umask 設成 0 再設回來，正是 lumos 自己的原子寫入原語註明否決的做法。

- 取代模式只有字元裝置直接寫（不阻塞開檔，開到的不是字元裝置就不寫），FIFO、socket、連結都換成普通檔；追加模式只收普通檔與字元裝置。
- 開跑前檢查改成跟寫入規則一一對應：新建時兩種模式都查父目錄可寫，檔名過長或父路徑是普通檔轉成訊息加 rc2。
- 暫存檔跟 lumos 原語一樣用獨佔建立加 0o666 讓 umask 自己生效；沿用舊檔權限另須只有一個名字（擋硬連結）。
- 歷史追加加不阻塞旗標；跑的期間被換成連結時報錯、不跟過去。
- 報表的不可列印字元改寫成 `⟦U+XXXX⟧`，標記字元本身也照寫，字面反斜線不再加倍。
- 消融腳本的兩個原子寫入都跟判準併在同一行從探針匯入。

**第七輪更正（2026-10-09）**：上面兩點已被取代——報表不再用 `⟦U+XXXX⟧`，改成跟 lumos 主程式 `_kill_esc` 同一套 `\uXXXX`；歷史追加改成只收「只有一個名字的普通檔」與字元裝置，字元裝置開檔另加不收控制終端。現行規則與證據見 [[Verification/持久用量帳第七輪審查修補驗證]]。
