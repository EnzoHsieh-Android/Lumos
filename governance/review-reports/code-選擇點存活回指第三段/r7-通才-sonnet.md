這輪修補我驗過了,沒有找到會做出錯行為的問題。

**修到沒?** 修到了。`_choice_reader_lines` 現在整段扣掉驗收條款與預期值表那幾節的行號區間,包含節裡的圍欄行。節的起止由 `_h2_section_lines` 自己判,正文沒有另算第三套邏輯。

- **圍欄漏進正文**:原本節中間、節尾、檔尾的圍欄行會漏進正文,現在整段扣掉。
- **同名兩節**:同名新節出現時,前一節的區間先收尾,不會被後一節的起點蓋掉。
- **`_choice_plan_sections`**:標題行不論是否落在區間內,都照原來的方式切段。被扣掉的只有內容行,段名與 `#2` 編號不受影響。
- **標題與扣掉的行**:標題行本身只會被切段邏輯處理,而且扣掉的行不會變成孤立段。

**有沒有引入新問題?** 沒有。
- **既有呼叫端**:不傳 `spans` 時,`_h2_section_lines` 只多了一個 `lines = _note_lines(text)` 的區域變數和幾個 `spans is not None` 的判斷。迴圈與回傳值跟舊版一致,實務隱患節、回退節、不做清單、預期值表、依據來源、情境題驗收條款的結果不變。
- **版本連動**:`_NOGO_SKIP_LOGIC_VERSION` 升 9、`_DOOR_RULE_VERSION` 升 17,兩支釘值測試跟著更新,跑起來都綠。判法沒變,升版只讓舊留痕重算。
- **測試**:`-k choice_plan_sections` 13 項全過。

**同類位置還有沒有?** 還有,但已經登記。`##\t範圍` 這種井號後接 tab 的標題,讀取器不認為節尾,會把後面的內容吞進驗收條款。這在 `Issues/選擇點存活回指第一段末輪小問題第二段先修.md` 第 16 條已放行並約定另開題改,不算這輪新問題。

**新測試能不能抓到改壞?** 四個圍欄案例都針對區間收尾的某一處。
- 節尾少收,範圍內容會被吃掉,測試會紅。
- 同名新節處不收,第一節的圍欄會漏出,測試會紅。
- 區間少算一行,節尾那案的 `~~~` 會變成孤立段,測試會紅。
- 檔尾那案我只推理,沒有實際改壞去跑:檔尾區間若少算最後一行,可能被結尾空行掩蓋,保護力略弱。這不影響必要行為,不另列為問題。

總結:最高等級是 clean。
