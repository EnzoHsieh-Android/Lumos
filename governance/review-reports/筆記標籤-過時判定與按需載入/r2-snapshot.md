# 筆記標籤_過時判定與按需載入_計劃

> 白話:兩個宗旨——程式碼推得出來的事實,筆記不寫;其他脈絡(為什麼、規則、踩過的坑、程式看不到的現況)照前綴分類寫。脈絡寫的時候對,它依賴的程式一改就可能不成立,而且沒人會回頭看。這份計劃讓寫筆記的人(多半是 AI)在脈絡行上順手宣告它依賴哪個程式符號或哪個數量;之後有人改到那段程式、讓依賴對不上了,推送時工具就擋下來,逼人回頭看那條脈絡還成不成立。附帶的好處是同一批前綴與欄位能拿來篩:agent 查筆記時只拿跟手上這支檔有關、還沒作廢的那幾行。

依據:
- 使用者需求(2026-10-01,經 lumos-toolchain-ff 會談轉達):①制定筆記寫法規則,搭配特定標籤 ②制定檢查:用什麼規則判定某句或某個標籤已經過時 ③同一套也能拿來篩、只載入需要的片段 ④不溯及既往:舊筆記不必回頭補 ⑤網搜前例、規劃推薦做法。之後 Enzo 在本對話陸續裁定與補充,見上方摘要的 WHY 行。
- 調研(都在 `governance/audits/2026-10-01-tagdrift/`):`web.md`(網路前例)、`internal.md`(工具鏈現況盤點)、`recheck.md`(乾淨 agent 只拿原始問題重查一次)。
- rtb 試標(rtb=消費專案 rtb-production-agent-demo,2026-10-01 把自己 94 篇筆記逐行讀過兩輪、提了標籤提案並試標;見 [[Projects/漂移防治路線圖_計劃]]〈標籤試標結果〉):數量欄位標上的 21 句全判得出、當場抓到 6 句過期、誤報 0,但數量句只標得上 18%(加上值約四成);最費工的是挑對集合。
- 設計審 r1 席報告:`governance/review-reports/筆記標籤-過時判定與按需載入/`。

PRIOR-ART: ①最小解在既有層——欄位的過時判定接進既有的存量漂移檢查(它已經有「只看這次推送改到的程式」的候選篩選、「起點成立、終點不成立才擋」的轉變判定、時間預算、判不了的處理、子開關與單次跳過、推送前掛鉤與 CI 接線);名稱還在不在沿用回頭條件探針的符號判定;正規式數量沿用 doctor N 段的 HTML 註解標記;寫法提醒接進筆記形狀檢查(note-shape)的新增行與上線點;撤除條件用既有的回頭條件行;已作廢用 RULE 既有的 `[status:superseded]` ②世界解過但只解一半——Doorstop/Fiberplane drift 做錨點、cog 做存查詢、Claude Code `paths:` 做按路徑載入、Zep/Graphiti 做失效排除 ③裁定=borrow-design,原生接在既有零件上(零依賴家規)。
RETIRE-IF: 上線 8 週,新寫的脈絡行(WHY、RULE、PITFALL)帶依賴欄位的不到 5%(寫的人不用);或抽查被擋的 20 筆裡誤報多過真報;任一成立就把 `drift_check.fields` 與 `note_shape.tag_hints` 改成 off 並照〈回退〉撤。

## 現況(盤點結論,細節見 `internal.md`)

- **寫有人查、讀沒人用**:行內鍵約 25 種,硬擋推送的只有合約那一族、`[來源:]` 與回頭條件;RULE 的 since/retire/confirmed/until/status 只在手動跑 lint 時看得到(提交時 lint 沒錯就不印、doctor 丟掉提醒),`[applies:]` 解析了沒有任何消費者。
- **判過時的檢查已經不少,但都在「看名稱、看狀態」**:舊句檢查(名稱消失)、存量漂移甲乙兩種、回頭條件探針、doctor 的失效路徑與數字重算、回頭重讀(語意,只提醒)。缺的是「這一句依賴哪個東西」的宣告。
- **檢索只到「篇」**:`query` 只認 frontmatter 標籤、只列篇名;`search` 有逐行片段,但只能靠 `--regex` 篩前綴,而且 `term` 必填、每篇最多印 8 行命中。

## 設計原則

0. **兩個宗旨**(Enzo 2026-10-01 定):程式碼推得出來的事實,筆記不寫,帶了欄位也不寫成句子;其他脈絡照前綴分類寫,欄位掛在脈絡行上宣告依賴。
1. **收欄位的門檻是「有一個機械的過時檢查」**;能篩選是加分。
2. **不另起爐灶**(設計審 r1 架構席):判過時接進既有的存量漂移檢查,寫法提醒接進既有的筆記形狀檢查,撤除條件用既有的回頭條件行,已作廢用既有的 `[status:superseded]`,正規式數量用既有的 HTML 註解標記。不新增閘名、不新增上線機制、不新增第二種寫法。
3. **只在「變了」那一刻擋**:欄位起點吻合、終點不吻合才擋;起點就已經對不上的舊帳不擋(doctor 列出)。這樣一條過期的欄位不會讓之後每個無關的推送都卡住。
4. **不溯及既往=只看寫了欄位的行、只提醒新寫的行**:沒寫欄位的筆記完全不受欄位檢查影響;寫法提醒只看上線點之後新增的行。不分新舊專案(Enzo 裁)。
5. **一個事實只寫一處**:程式事實的家是程式,欄位只存依賴宣告;正文與其他欄位不複述。
6. **治理政策不跟著放寬**:RULE 要三欄齊、半年內確認才有挑戰程式碼的效力,本案不動這條;回頭條件行不能代替 `[retire:]`。

## 前綴怎麼寫、怎麼判過時(本案骨架)

用詞:**標籤=摘要行前綴**;行內 `[鍵:值]` 叫**欄位**。「判過時」欄的擋都走存量漂移檢查(`drift_check.fields`,預設擋;工具鏈也擋,Enzo 裁),提醒都走筆記形狀檢查(`note_shape.tag_hints`,預設提醒)。

| 前綴 | 寫什麼 | 必帶 | 可帶的依賴欄位 | 判過時 | 篩選(附帶) |
|---|---|---|---|---|---|
| WHY | 為什麼這樣決定、否決過什麼 | 出處(日期、決策、提交或對話) | 數量與值、錨點 | 依賴欄位從吻合變不吻合 → 擋;被新決定取代 → 帶 `[status:superseded]` 加指向新決定的連結 | `--prefix WHY`;已作廢的預設不給 |
| RULE | 程式看不到的限制 | `[since:]` `[retire:]`;要挑戰程式碼還得 `[confirmed:]` 半年內(既有政策,不動) | 同上;撤除條件想讓機器判,就在下一行緊鄰寫一行條件式 REVISIT | 依賴欄位變了 → 擋;緊鄰的回頭條件從不成立變成立 → 擋(既有);`[until:]` 過期、`[confirmed:]` 超過半年 → 提醒 | 已作廢的預設不給 |
| PITFALL | 踩過的坑、事故根因 | 出處 + 防回歸(`[test:]` 或重現指令) | 同上 | 依賴欄位變了 → 擋;`[test:]` 指的測試不存在 → 歸 [[Projects/漂移防治路線圖_計劃]] 1b 那案 | `--prefix PITFALL` |
| FACT/FLOW/DEP | 只寫程式答不了的現況(部署、資料庫、生產、外部、人工) | `[來源:]`(既有,note-shape 擋) | 不適用:程式答得了的根本不寫 | 程式驗不了;帶 `[confirmed:]` 超過半年 → 提醒 | `--prefix FACT` |
| REVISIT、RETIRE-IF | 回頭條件、撤除條件 | 日期或 `[when-*]` 條件(既有) | — | 條件成立 → 擋(既有) | — |
| KEY | 舊的未分類寫法,新寫不用 | — | — | — | — |

## 欄位 v1(三類)

| 欄位 | 寫法 | 判過時(推送時,只看這次改到 `路徑` 那支檔的欄位) | 求值 |
|---|---|---|---|
| 數量與值 | `[count:路徑::名稱=N]`、`[value:路徑::名稱=字面值]` | 起點 N(或字面值)吻合、終點不吻合 → 擋;終點那個名稱不見了 → 擋;這次新寫的欄位在終點就不吻合 → 擋(寫錯了) | 新寫的小求值器:Python 用語法樹讀模組層的指派——清單、元組、集合、字典字面值的成員數,Enum 類別的成員數,常數字面值(整數、浮點、字串、布林);其他語言或讀不出來的(例:程式組出來的集合)→ 起點終點都「判不了」就不擋,寫的當下提醒改用正規式數量 |
| 錨點 | `[lives:路徑::名稱]` | 起點有這個名稱、終點沒有 → 擋 | 沿用回頭條件探針的符號判定(同一支 `_DriftProbeTree`;Python 用語法樹、其他語言用文字) |
| 已作廢 | `[status:superseded]`,同一行要有指向取代者的 `[[連結]]` | 不擋;同一行沒有連結 → 提醒 | 既有欄位,擴到 WHY、PITFALL 行 |

- **正規式數量**:找不到具名集合時,用既有的 `<!--lumos:count=N re=… in=…-->`(HTML 註解可以裝含方括號的正規式)。本案把 doctor N 段裡內嵌的重算抽成共用函式,存量漂移檢查也呼叫它:這次推送改到符合 `in=` 的檔,才重算那個標記;起點吻合、終點不吻合 → 擋。重算受存量漂移檢查的總時間預算管,不再每個標記各自無上限地掃整個 repo。
- **列舉**併進數量:列舉的成員數用 `[count:路徑::列舉=N]`。成員互換而總數不變抓不到,記在〈天花板〉。
- **撤除條件**用既有的條件式回頭條件行(`REVISIT:[when-file:…][by:…]` 那套),緊鄰寫在 RULE 下一行,不新增欄位。
- **路徑與名稱怎麼切**:`路徑::名稱` 在「路徑」這段以第一個「帶副檔名的路徑之後的 `::`」切開,名稱可以再含 `::`(Rust、C++ 的限定名);名稱後面第一個 `=` 之後全是值,值可以含 `:` `=`,不可以含 `]`(含 `]` 的值改用正規式數量)。
- **寫在哪裡才算**:跟回頭條件同一套——只算可見的正文與摘要行;行內程式碼、表格、圍欄、frontmatter 非摘要欄位裡的欄位不評估(文件範例才不會被當真),寫在那裡的提醒「寫在不評估的地方」。
- **判不了**:照存量漂移檢查既有的處理(git 逾時、淺複製、預算用完時的嚴格判定沿用它的設定),不另訂。

不收(設計審 r1 與 rtb 原提案對照):`[enum:]`(併進 count)、`[retire-when-*]` 與 `[expect:]`(用既有回頭條件行)、`[supersedes:]` `[superseded-by:]` `[id:]`(專案已有決策的取代鏈與 `[status:superseded]` 兩套,再開一套是第三種做法)、`[snapshot:]`(「哪些小節算現況」定義不出來,[[Projects/筆記形狀擋_計劃]] 也記過這形狀不固定;留 v2)、`[retired:]` `[test-gone:]`(歸路線圖 1b/1c)、錨點的「名稱本體變了」(沒有基準可比,逐行回溯 git 成本高且淺複製判不了;同次推送改了程式又改了筆記的情況,既有的回頭重讀已涵蓋)、rtb 提的 from、same-as、deliver、recheck(留 v2)。

## 寫法提醒(筆記形狀檢查,只看上線點之後新增的行,所有專案,只提醒)

子開關 `note_shape.tag_hints`:`warn`(預設)/ `off`,照 `note_shape.negation` 的先例,壞值照 warn 並講一句。

- **W1 脈絡行提到程式符號,建議宣告依賴**:新寫的 WHY、RULE、PITFALL 行用反引號提到程式符號,又沒帶任何依賴欄位 → 提醒,並把那個名稱填進範本印出(例「這條 WHY 提到 `MODEL_VARS`,它依賴這個數量的話加 `[count:app/config.py::MODEL_VARS=4]`」)。
- **W2 程式推得出的事實別寫**:Systems 筆記新寫的摘要行含「只有/唯一/恰好 N/N 個/N 支」這類寫死數量,而且前綴不是 WHY、RULE、PITFALL、FACT → 提醒「這是程式碼推得出的事實,照宗旨不寫;如果某條脈絡依賴這個數,寫那條脈絡並加 `[count:]`」。只看摘要行;FACT 排除(它寫的是程式答不了的現況)。
- **W3 會過期的句子寫成條件式回頭條件**:沿用既有的否定現況句提醒,範例加上「RULE 的撤除條件緊鄰寫一行條件式 REVISIT」。
- **W4 RULE 生命週期提醒送到眼前**:只對新寫的 RULE 行(走新增行那條路,不是整篇 lint)印缺 since、retire、until 過期。
- **W5 改原句不追加**:寫進紀律範本與 skill;機械上交給既有的回頭重讀。
- **W6 同一行重複事實**:同一行裡 `[count:]` 或 `[value:]` 的值,在方括號外又以整個數字出現(前後不是數字或英文字母;日期 `YYYY-MM-DD` 整串跳過;中文數字不比)→ 提醒「這個數只寫在欄位裡」。只提醒(Enzo 裁降級)。
- **欄位寫壞**:鍵名不認得、少了 `=值`、值被 `]` 截斷、路徑不帶副檔名、寫在不評估的地方 → 提醒。

## 一個事實只寫一處

- **正文怎麼寫**:句子只講脈絡,依賴交給欄位。例:不寫「模型變數有四個」(程式事實);寫「WHY:[2026-10-01 討論]模型變數的數量要跟 GPU 記憶體對齊,加變數前先量記憶體 `[count:app/config.py::MODEL_VARS=4]`」——數量只在欄位裡,改成 5 個時工具擋下,逼人回頭確認記憶體還夠。不寫「分派入口在 `app/router.py`」;寫「PITFALL:[2026-09-30 事故]分派入口收到空清單會靜默成功,呼叫端要自己判斷 `[lives:app/router.py::dispatch]`」。
- **欄位不重複**:作廢只用 `[status:superseded]` 一種;撤除條件的機器式寫法只用回頭條件行一種。
- **不涵蓋**:理由、取捨、事故經過、程式看不到的限制——這些是脈絡,照常寫在正文、照前綴分類。

## 讓 AI 知道該寫什麼

1. **提交時(主要管道)**:W1 到 W6 與欄位寫壞的提醒都帶現成範本;同一次提交第一次出任何一條提醒時,多印一張六行速查表(三類欄位、前綴怎麼配、一個例子)。不管 AI 用編輯工具還是指令改筆記,提交時都會經過這裡。
2. **擋下時**:訊息印出哪篇哪行、依賴的欄位起點與終點的值、那條脈絡原句,以及「回頭讀這條脈絡還成立嗎;成立就把欄位改成新值,不成立就改寫或作廢」,加上單次跳過(`LUMOS_SKIP_DRIFT_CHECK=1`,既有)與 `drift ack`(既有)的指令。
3. **規範單源**:完整說明寫進 lumos-project-notes skill 的「寫回圖譜」子檔;紀律範本只加一行指路(範本已超過瘦身基線,不放整張表)。
4. **改檔前提示 hook 不動**:它只在改程式檔時觸發、明確排除筆記(設計審 r1 多席指出),v1 不新增筆記分支;上線後看提交時的提醒夠不夠,再決定要不要加。
5. **怎麼驗**:上線後挑三題「請在某篇筆記寫一句依賴某個數量/講某個坑出在哪個函式/講某裁定被取代」的情境,各讓 AI 實跑一次,人工看寫出來的句子帶沒帶對欄位(既有的情境探針只看工具呼叫、看不到寫進去的內容,所以先人工看)。三題答對不到兩題,就先改速查表與範本措辭。

## 按需載入(附帶)

擴 `lumos search`,不開新指令:
- `--prefix WHY,RULE,…`:只要這幾種摘要行。
- `--about <檔>`:那支檔的家筆記(about_code 列了它)的摘要行,加上錨點、數量與值欄位指到那支檔的行。
- 給了 `--prefix` 或 `--about` 時 `term` 可以不給;進入「行模式」:不套每篇 8 行的截斷,改用 `--top` 限總行數(行模式預設 80 行,`--top 0` 全給),截掉的行數印在 stderr。
- 行模式預設隱藏帶 `[status:superseded]` 的行,`--include-retired` 才給;隱藏了幾行印在 stderr。既有的 `--include-superseded`(節點層)意思不變。只看靜態標記,不在搜尋時求值任何條件。
- 輸出沿用現有的逐行片段格式,每行帶篇名;`--json` 在行模式多一個片段文字欄位。
- 給 agent 的入口:skill 的查詢表加一行「我要改這支檔,有哪些還有效的規則與坑」→ `lumos search --about <檔> --prefix RULE,PITFALL,WHY`。

## 不溯及既往怎麼做

## 天花板(v1 承認)

1. **欄位只管寫了欄位的句子**:沒寫的照樣會過時;rtb 試標數量句只標得上約四成,最常過期的「程式組出來的集合」指不到。
2. **擋得住「前提變了」,擋不住「沒回頭看就改數字」**:被擋後把 `=4` 改成 `=5` 就過了,工具驗不了人有沒有重讀那條脈絡。擋下訊息會印出脈絡原句;REVISIT 那天抽查只改數字的比例。
3. **數量與值的求值器只懂 Python 的字面值**:其他語言、程式組出來的集合讀不出來,只能改用正規式數量(要人寫正規式,挑錯集合會誤報或漏報;rtb:同詞多候選時 5 到 10 分鐘)。
4. **列舉成員互換而總數不變抓不到**(列舉併進數量的代價)。
5. **錨點只判名稱在不在**:名稱還在、行為變了抓不到;同一次推送改程式又改筆記的,交給既有的回頭重讀。
6. **閘的開關讀被推送版本裡的設定**:推的人可以在同一個提交把 `drift_check.fields` 改成 off,這道擋只防疏忽(跟 `drift_check.gate` 既有的承認一樣)。
