# 筆記標籤_過時判定與按需載入_計劃

> 白話:兩個宗旨——程式碼推得出來的事實,筆記不寫;其他脈絡(為什麼、規則、踩過的坑、程式看不到的現況)照標籤分類寫。脈絡寫的時候對,它依賴的程式一改就可能不成立,而且沒人會回頭看。這份計劃定一小套欄位和幾條寫法規則:寫筆記的人(多半是 AI)在脈絡行上順手宣告它依賴哪個程式符號、哪個數量或列舉、什麼情況下該撤掉、被誰取代了。主要目的是防過期:工具能機械地判斷「這句已經不成立了」,推送時擋下或提醒。附帶的好處是同一批欄位也能拿來篩:agent 查筆記時只拿到跟手上這支檔有關、而且還有效的那幾行,不用整篇整篇讀。只對新接入的專案預設打開,舊筆記不必補標。

依據:
- 使用者需求(2026-10-01,經 lumos-toolchain-ff 會談轉達):①制定筆記寫法規則,搭配特定欄位 ②制定檢查:用什麼規則判定某句寫法或某個欄位已經過時 ③同一套欄位也要能拿來搜尋特定訊息,讓 agent 只載入需要的片段、避免 context 加載過多 ④不溯及既往:只給新接入的專案用 ⑤網搜前例、規劃推薦做法。
- 前例調研與工具鏈盤點(都在 `governance/audits/2026-10-01-tagdrift/`):`web.md`(網路前例,A 到 E 五類)、`internal.md`(工具鏈現況:認得約 25 種行內鍵,但大多只在寫的時候查、讀的時候沒人用)、`recheck.md`(乾淨 agent 只拿原始問題重查一次,結論一致:沒有完整前例,最接近的是 rjmurillo 的 ADR frontmatter 與 Zep/Graphiti 的有效期欄位)。
- rtb 試標(rtb=消費專案 rtb-production-agent-demo,2026-10-01 把自己 94 篇筆記逐行讀過兩輪、提了標籤提案並試標;見 [[Projects/漂移防治路線圖_計劃]]〈標籤試標結果〉):數量欄位標得上的 21 句全判得出、當場抓到 6 句過期、誤報 0,但 115 句數量句只標得上 18%;最費工的是「挑對集合」。

PRIOR-ART: ①最小解在既有層——工具鏈已有回頭條件的條件文法(檔案出現、符號出現、測試出現、某篇狀態)與求值器、doctor N 段的「可重算數字」標記與重算器、舊句檢查的「名稱消失」判定、回頭重讀的判定者流程、search 的逐行片段輸出與區域標記、note-shape 的「只看新增行+上線點」機制;本案每一項都接在這些上面,不另起求值器 ②世界解過但只解一半——Doorstop/Fiberplane drift 做錨點加指紋、cog 做存查詢、Claude Code `paths:`/Kiro `fileMatch` 做按路徑載入、Zep/Graphiti 做失效排除,沒有一家用同一套句子級欄位兩邊都做 ③裁定=borrow-design:借上面各家的判準形狀,原生實作在既有零件上(零依賴家規)。
RETIRE-IF: 上線後 8 週,新接入專案裡新寫的摘要行帶 v1 欄位的不到 5%(寫的人不用,規則等於沒有);或欄位判出的「過時」裡誤報多過真報;或 search 的欄位過濾在使用帳上 8 週零次使用(載入那半沒人用)。任一成立就照〈回退〉撤掉對應那一半,三條都成立就整案撤。

## 現況(盤點結論,細節見 `internal.md`)

- **寫有人查、讀沒人用**:行內鍵約 25 種,硬擋推送的只有合約那一族、`[來源:]` 與回頭條件;RULE 的 since/retire/confirmed/until/status 只在手動跑 lint 時看得到(提交時 lint 沒錯就不印、doctor 丟掉提醒),`[applies:]` 解析了沒有任何消費者。
- **判過時的檢查已經不少,但都是「看名稱、看狀態」**:舊句檢查(名稱消失)、存量漂移甲乙兩種、回頭條件探針、doctor 的失效路徑與數字重算、回頭重讀(語意,只提醒)。缺的是「這一句綁的是哪個東西」——沒有綁定,工具只能全篇猜。
- **檢索只到「篇」**:`query` 只認 frontmatter 欄位、只列篇名;`search` 有逐行片段,但只能靠 `--regex` 篩前綴,篩不了「這支檔相關、還有效的 RULE 與 PITFALL」。推播 hook(同一支 impact-hook 的排名推播)刻意只印篇名與合約類別(防注入)。
- **文件自己有四處對不上**(盤點 4.4):reference.md 的 RULE 範例不是欄位寫法;舊精簡表的 FLOW/FACT 定義跟新規範相反;紀律範本說 RULE 要三欄齊且半年內確認才有效力、程式註解說兩欄就算;RETIRE-IF 不在摘要前綴表裡。

## 設計原則

0. **兩個宗旨**(Enzo 2026-10-01 定,其他原則都從這裡來):
   - **程式碼推得出來的事實,筆記不寫**。數量、常數值、列舉成員、某功能在哪支檔——這些讀程式就知道,寫成句子只會過期。帶了欄位也不寫成句子。
   - **其他脈絡照標籤分類寫**:用既有的前綴分類(WHY 為什麼、RULE 程式看不到的限制、PITFALL 踩過的坑、FACT 程式答不了的現況並附來源…)。本案的欄位再掛在這些脈絡行上,宣告「這條脈絡依賴哪個程式事實」。
1. **收欄位的門檻是「有一個機械的過時檢查」**(Enzo 2026-10-01 裁):標了之後工具能判它依賴的前提變了沒,才收。能拿來篩載入是加分,不是條件。沒有任何檢查的不收。
2. **先收 rtb 自己排的核心五類,其餘看用量再加**:rtb 原提案就說「標籤一多寫的人會嫌煩,其餘的看核心五個用起來的狀況再加」;rtb 試標也顯示每多一種,寫的人就多一份挑選成本。
3. **語法跟回頭條件一致、求值器沿用既有**:符號一律寫 `路徑::名稱`(跟既有的 `[when-symbol:路徑::名稱]` 同一個寫法);回頭條件的條件求值、doctor N 的數字重算、舊句檢查的名稱判定都直接拿來用,不另寫第二套。
4. **只管新行、只對新接入的專案預設開**:寫法規則只看上線點之後新增的行(note-shape 那套);設定沒寫的專案(=所有既有專案,含工具鏈與 rtb)預設關,`lumos init` 新接入時才寫進預設值。
5. **一個事實只寫一處**(Enzo 2026-10-01 補):程式事實的家是程式,欄位只存「依賴宣告」;正文與其他欄位不再複述(見〈一個事實只寫一處〉)。
6. **機械判準才准擋;語意判斷只提醒**:擋的都是「讀得到程式、算得出對錯」的判準;「綁的符號內容變了」這種可能只是重構的,交給既有的回頭重讀當候選,不擋。

## 前綴怎麼寫、怎麼判過時(本案骨架)

用詞:**標籤=摘要行前綴**;行內 `[鍵:值]` 叫**欄位**,掛在前綴行上。照宗旨,筆記只寫脈絡、照前綴分類;每種前綴規定寫什麼、必帶哪些欄位、怎麼判它過時。下面「判過時」欄標「擋」的,只對新接入專案擋(工具鏈只提醒);標「既有」的是現在已經有的檢查,本案只讓它送得到眼前或接上開關。

| 前綴 | 寫什麼 | 必帶欄位 | 可帶的依賴欄位 | 判過時 | 篩選(附帶) |
|---|---|---|---|---|---|
| WHY | 為什麼這樣決定、否決過什麼 | 出處(日期、決策、提交或對話) | ①數量與值、②列舉、⑥錨點 | 依賴欄位變了 → 擋;被新決定取代 → 帶 `[superseded-by:]`,沒成對 → 擋 | `--prefix WHY`;被取代的預設不給 |
| RULE | 程式看不到的限制(相容、法規、人工核可…) | `[since:]`、撤除條件(自由文字 `[retire:]` 或機器式 `[retire-when-*]` 擇一) | 同上 | 機器式撤除條件成立 → 擋;`[until:]` 過期 → 擋;`[confirmed:]` 超過半年 → 提醒;依賴欄位變了 → 擋 | 預設只給還有效的 |
| PITFALL | 踩過的坑、事故根因 | 出處 + 防回歸(`[test:]` 或重現指令) | 同上 | `[test:]` 指的測試不存在 → 歸路線圖 1b 那案;依賴欄位變了 → 擋 | `--prefix PITFALL` |
| FACT/FLOW/DEP | 只寫程式答不了的現況(部署、資料庫、生產、外部、人工) | `[來源:]`(既有,note-shape 擋) | 不適用:照宗旨,程式答得了的根本不寫 | 程式驗不了,只能靠時間:帶 `[confirmed:]` 的超過半年 → 提醒 | `--prefix FACT` |
| REVISIT、RETIRE-IF | 回頭條件、撤除條件 | 日期或 `[when-*]` 條件(既有) | — | 條件成立 → 擋(既有) | — |
| KEY | 舊的未分類寫法,新寫不用 | — | — | — | — |

⑤快照不掛在單行上,放在計劃小節標題下第一行,見下表。

## 欄位 v1(核心五類加錨點)

寫法沿用 rtb 原提案的標準寫法。欄位都掛在脈絡行上(照宗旨,不會有「只為了記一個數」的行);「檢查」欄擋下的意思是「這條脈絡依賴的前提變了,回頭重看這條脈絡,確認還成立再更新標籤」。「篩選」欄是附帶的好處。

| 類 | 欄位 | 防的形狀 | 檢查(主要) | 篩選(附帶) | 跟既有的關係 |
|---|---|---|---|---|---|
| ①數量與值 | `[count:路徑::名稱=N]`、`[value:路徑::常數=字面值]`;找不到具名集合時用 `[count:N re=… in=…]` | 脈絡依賴的數量或值變了,例「上限要跟上游配額對齊」依賴的那個常數被改了 | 讀那個名稱的成員數或常數值,跟 N 或字面值不同 → 擋 | 指到的檔可拿來篩「跟這支檔有關的行」 | 正則寫法跟 doctor N 段的 HTML 註解標記同一個重算器;rtb 試標 count 21 句全判得出、誤報 0,count 加 value 約可覆蓋四成數量句 |
| ②列舉 | `[enum:路徑::列舉]` | 脈絡依賴的列舉多了或少了成員,例「每種付款方式都要走風控」那條規則,付款方式多了一種 | 寫欄位時記下當時的成員清單(或句中反引號名稱),跟現在的列舉成員兩邊比,多或少 → 擋 | 同上 | 新判定;成員抽取跟①共用 |
| ③撤除條件 | `[retire-when-file:…]` `[retire-when-symbol:…]` `[retire-when-status:…]`,可加 `[expect:路徑::名稱]` | 撤除條件已成立,句子(或 RULE)還當真 | 沿用回頭條件探針求值;成立 → 擋;`[expect:]` 指的名稱不在那支檔,條件不算成立(防「檔出現了但不是那個東西」) | 條件已成立的行預設不載入 | RULE 原本的 `[retire:自由文字]` 照舊可寫,但沒有自動效力;跟 [[Projects/漂移防治路線圖_計劃]] 機制 3 重疊,本案做欄位那一半,機制 3 其餘(新條件提交時當場求值)照它自己排 |
| ④取代鏈 | `[id:短名]`、`[supersedes:節點#錨]`、`[superseded-by:節點#錨]` | 裁定被翻案、取代只標了一端 | 兩端要成對,只有一端 → 擋;錨可以是合約編號、決策編號或 `[id:]` | 帶 `[superseded-by:]` 的行預設不載入 | 取代 RULE 的 `[status:superseded]`(舊寫法照認);借 ADR superseded 鏈與 Zep「失效不刪」 |
| ⑤快照 | `[snapshot:日期@提交]`(放在小節標題下第一行) | done 計劃的現況段沒標快照、施工前的「現在」被當成現況 | 計劃轉 done 時,現況類小節沒有 snapshot → 擋;snapshot 小節外的「現在/目前」加反引號識別字 → 提醒 | snapshot 小節載入時跟著標「某天的快照」 | 呼應 [[Issues/筆記把程式現況寫進脈絡而漂移_rtb實測回饋]] d4(done 計劃現況段收成一句) |
| ⑥錨點 | `[lives:路徑::名稱]` | 脈絡講的那個東西搬走或不見了,例某條 PITFALL 講的函式被刪了 | 名稱不在那支檔 → 擋;名稱本體自這行寫下後變了 → 列進回頭重讀候選、只提醒 | 查「跟某支檔有關的行」時一定帶出 | 沿用舊句檢查的名稱判定(Python 用語法樹、其他語言用文字)與回頭重讀的候選流程;錨點語法借 Fiberplane drift 與 Sphinx「用名稱不用行號」 |

另外兩種歸別的計劃:`[retired:]` 與 `[test-gone:]`(撤除小節與懸空的測試綁定)跟 [[Projects/漂移防治路線圖_計劃]] 的 1b/1c 是同一件事,由那一案做;本案不重做。

留到 v2(核心五類用起來再看):`[from:路徑@提交]`(產物快照過期)、`[same-as:節點#錨]`(雙生句只修一半)、`[deliver:S編號]`(計劃設計句沒落地)、`[recheck:指令]`(重查指令失效)。四種都有過時檢查,符合收的門檻;延後只是控制寫的人一次要學的量。

## 寫法規則 v1(只看新增的行;W1 到 W5 只提醒,W6 見〈一個事實只寫一處〉)

- **W1 脈絡行提到程式符號,宣告依賴**:新寫的脈絡行(WHY、RULE、PITFALL)用反引號提到程式符號時,提醒加 `[lives:]`(或①②類),好讓那個符號一變就有人回頭看這條脈絡。
- **W2 程式推得出的事實別寫成句子**:Systems 筆記新寫的行含「只有/唯一/恰好 N/N 個/N 支」這類寫死數量,又不是 WHY、RULE、PITFALL 這類脈絡時,提醒「這是程式碼推得出的事實,照宗旨不寫;如果某條脈絡依賴這個數,寫那條脈絡並用 `[count:]`/`[value:]`/`[enum:]` 宣告依賴」。不擋:「是不是脈絡」靠前綴判,誤判的代價只是一句提醒。
- **W3 會過期的句子寫機器式撤除條件**:沿用既有的否定現況句提醒(「還沒有 X」改寫成回頭條件),並把 `[retire-when-*]` 的寫法加進提醒範例。
- **W4 RULE 生命週期提醒送到眼前**:提交時對新寫的 RULE 行印出缺 since/retire、until 過期這類提醒(目前 lint 有算、但提交時不印)。
- **W5 改原句不追加**:寫進紀律範本與 skill;機械上交給既有的回頭重讀,不另做檢查。

## 一個事實只寫一處

把筆記當成文字資料庫:程式事實的家是程式,脈絡的家是筆記,欄位是兩者之間的依賴宣告。同一個事實寫兩處,程式一改,只有一處會被改到。

- **正文怎麼寫**:句子只講脈絡,依賴交給欄位。例:
  - 不寫「模型變數有四個」(程式事實,照宗旨不寫)。
  - 寫「WHY:模型變數的數量要跟 GPU 記憶體對齊,加變數前先量記憶體 `[count:app/config.py::MODEL_VARS=4]`」——理由是脈絡,數量只在欄位裡,改成 5 個時工具擋下,逼人回頭確認記憶體還夠。
  - 不寫「分派入口在 `app/router.py` 的 `dispatch`」;寫「PITFALL:分派入口收到空清單會靜默成功,呼叫端要自己判斷 `[lives:app/router.py::dispatch]`」。
- **欄位不重複**:
  - 有機器式撤除條件(`[retire-when-*]`)的 RULE,不必再寫自由文字的 `[retire:]`——機器式那條就算數(RULE 要有撤除條件才有挑戰程式碼效力的規矩,由它滿足)。
  - 有 `[superseded-by:]` 就不寫 `[status:superseded]`;舊寫法照認,新寫的只留一種。
  - 小節帶 `[snapshot:]` 就不在正文再寫「這是某天的現況」。
- **W6 重複事實(會擋,新接入專案)**:同一行裡,欄位的值(數量、字面值、日期)在欄位外又出現一次——阿拉伯數字或中文數字都算——就擋,訊息印出改法(把散文那份拿掉)。只比同一行;跨行、跨篇的重複留給既有的回頭重讀判斷。工具鏈照已裁第 2 題只提醒。
- **不涵蓋**:理由、取捨、事故經過、程式看不到的限制——這些是脈絡,照常寫在正文、照前綴分類。

## 讓 AI 知道該寫什麼

寫筆記的多半是 AI;它不知道要標、或不知道怎麼標,欄位就等於沒有。分三層教,由近到遠:

1. **寫的當下(主要管道)**:AI 要改一篇筆記時,既有的改檔前提示 hook(impact-hook,現在已經會附棧別檢核題)多附一張六行的速查表——每類一行「什麼句子→標籤寫法→一個例子」。只在專案的 `note_tags.gate` 不是 `off` 時附;沒開的專案看不到,不增加負擔。
2. **寫完的提醒帶現成範本**:W1、W2 的提醒不只說「要加標籤」,而是把那一行裡的反引號名稱填進範本印出來,例「這條 WHY 提到 `MODEL_VARS`,依賴它的數量就加 `[count:app/config.py::MODEL_VARS=4]`」;W2 另外直接說「這句是程式推得出的事實,照宗旨不寫」。擋下時的訊息印出依賴變了什麼、要回頭看哪條脈絡、確認後怎麼更新欄位。
3. **規範單源**:完整說明(每類欄位什麼時候用、怎麼寫、常見寫錯、什麼時候不該標)寫進 lumos-project-notes skill 的「寫回圖譜」子檔;紀律範本只加一行指路(範本有大小上限,而且所有專案都會注入,不放整張表)。

**怎麼驗 AI 真的會寫**:情境探針(每週自動跑的口語題)加幾題「請在某篇筆記寫一句帶數量/講功能在哪支檔/講某裁定被取代的話」,看寫出來的句子有沒有帶對的欄位;答對率進每週評測紀錄。上線後第一次量到的答對率低於一半,就先改速查表的寫法,再談要不要擋。

## 天花板(v1 承認)

1. **欄位只管寫了欄位的句子**:沒標的句子照樣會過時;W1、W2 只提醒,寫的人不標,工具就不知道。rtb 試標:數量句只標得上約四成,最常過期的「程式組出來的集合」(流程圖節點數、集合相減)欄位指不到。
2. **錨點只證「符號還在、內容有沒有變」**:符號還在、內容沒變,句子照樣可能本來就寫錯;語意對不對仍靠回頭重讀與審查。
3. **數量與列舉欄位要人挑集合**:挑錯集合會誤報或漏報(rtb:有具名集合 1 到 3 分鐘,同詞多候選時 5 到 10 分鐘、最容易出錯)。v1 不做「工具列候選集合」,看寫的人實際卡多久再說。
4. **只對新接入專案預設開**:既有專案的存量漂移照舊靠存量漂移守衛與回頭重讀。
5. **多語言的符號判定只到文字層**:非 Python 用文字比對名稱,同名不同物會誤判「還在」;具名集合的成員數與常數值,其他語言只認簡單的字面清單與常數,認不出來就提示改用正則寫法。

## 不做

- 不把時間到期當主力(Guru 式到期提醒在單人維護時會變成蓋章續期;MS Learn 特地規定沒真的重審不准改日期)。
- 不做向量庫、embedding、LLM 產生檢索條件。
- 不做 `[retired:]`、`[test-gone:]`(歸漂移防治路線圖 1b/1c);v2 四種先不做(見〈欄位 v1〉末段)。
- 推播 hook 不印筆記原文(防注入的既有決定不動)。

## 實務隱患

- **併發**:不碰。全部是推送前或查詢時的唯讀計算,不新增寫入點;設定檔由人或 `lumos init` 寫。
- **效能**:數量重算沿用 doctor N 的上限(檔案數與位元組數);錨點判定只算帶欄位的行;search 的新過濾在現有逐行掃描上多一道篩,不另建索引。
- **資源**:不開長駐程序、不加連線。
- **回滾**:每一步獨立可撤,見〈回退〉。
- **相容**:舊筆記沒有新欄位,行為完全不變;`[retire:]` 寫自由文字的舊 RULE 照舊只是提醒用的文字。
- **注入**:載入是 agent 主動敲 search 拿到的唯讀片段,跟現在 search 的風險一樣;推播 hook 不印原文。
- **自我治理(誤擋的逃生口)**:這些擋都是新的推送閘(⑤快照擋在轉 done 時),誤擋時的出路照既有閘的慣例——單次跳過用環境變數(會留帳、CI 照擋,跟 note-shape 的跳過同一套)、整道關掉改設定成 `warn` 或 `off`;每次擋下與跳過都寫治理帳,`lumos gov --stats` 看得到次數,RETIRE-IF 的誤報比例就從這裡量。
- 已排除:金流:只讀筆記與程式文字,不碰任何交易或付款流程
- 已排除:對外送出:不呼叫外部服務、不寄送任何東西,全在本機與 CI 內
- 已排除:不可逆:不改資料、不刪筆記;所有擋都能用設定關掉,欄位留著無害
