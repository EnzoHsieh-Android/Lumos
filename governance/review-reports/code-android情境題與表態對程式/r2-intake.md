## 先查世界

- PRIOR-ART: 證據樣式(作者寫的正規式)第二次被打穿:r1 補了正反例自測,r2 邊界席另寫真實變體,11 條 major 全是「型錄標準寫法的合法變體被擋」或「壞寫法換行就過」。照第一要點與「守衛面字面判斷同類第二次被打穿就換形狀」,不再補正規式。業界對「誤報率未知或偏高的規則」的做法:Semgrep 規則政策分 Monitor(只記錄)、Comment(在 PR 留言提醒)、Block(擋)三種模式,官方建議新規則先在 Monitor 量真陽性率,再升 Comment,最後才升 Block(https://semgrep.dev/docs/semgrep-code/policies )。採用:證據樣式對不上一律降為提醒(Comment 級)——印出、記治理帳、列進待盲判清單,不擋;推送前照擋的只剩「缺段缺列」與「無法驗證」(那兩件不靠字面判語意)。每列之後要升 Block,要有實測依據(例如盲判或人工確認那列提醒的真陽性數與誤報數),寫成升級條件。排除:繼續逐條補正規式(兩輪打穿)。
- PRIOR-ART: 預算逾時——表態閘既有規則是逾時標 `over_budget`、已查出問題才擋、沒問題放行並記帳(scripts/lumos `_dispositions_verdict` 的既有處置);情境題逾時照同一規則,不另立擋下。
- PRIOR-ART: 宣告頭判斷——Kotlin 主建構子文法 `class Name [modifiers] constructor(...)`(https://kotlinlang.org/docs/classes.html#constructors ),`constructor` 在 class 之後屬於同一個宣告頭,不能蓋掉 `class`。
