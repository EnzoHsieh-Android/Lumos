## Findings

### f1

severity: blocker

`git show <base>:<節點路徑>` 這句話字面上驗證失敗:`impact --diff --json` 的 `node` 欄位是**vault 相對路徑**(實跑 `node: 'Systems/lumos-cli-lifecycle.md'`),不是 repo 根相對路徑;`git show c3b4f3f~1:Systems/lumos-cli-lifecycle.md` 回 `fatal: path 'Systems/lumos-cli-lifecycle.md' does not exist in 'c3b4f3f~1'`,必須補 `docs/lumos-toolchain-knowledge/` 前綴才成功(`git show c3b4f3f~1:docs/lumos-toolchain-knowledge/Systems/lumos-cli-lifecycle.md` 回 rc=0)。這是 r1 blocker③(「節點內容從 base ref 讀」)的核心實作,但 `git show` 對「路徑打錯」與「節點在 base 真的不存在」回的都是同一種 `fatal: does not exist`,無法區分——若照字面實作,每個節點都會被誤判成「本分支新增,未貼內容」,r1 blocker③其實**沒有真的修到**,只是換了一句聽起來解決了的話。更麻煩的是這支 hook 要裝到「本機所有專案」(不同 repo 的圖譜目錄名不一定叫 `lumos-toolchain-knowledge`),不能硬編前綴,spec 完全沒提怎麼取得 vault 前綴。

blocking: 是
