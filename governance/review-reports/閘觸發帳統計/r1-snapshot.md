# 閘觸發帳統計_計劃

> 白話:治理帳寫了兩萬多筆,從來沒人回頭算過「哪道閘在做事、哪道從沒響過、哪道每次都響」。本案給既有的 `lumos gov` 加一段唯讀統計,把這三類算出來。**恆觀測、不進閘、不改任何判定。** 它的用途是給「紀律要不要退場」這個至今無尺可量的問題,第一次提供資料。

## 緣起

[[Projects/graph-engineering掃描2026-08-19_調研]] 借鑑二。外界剪枝訊號=多久沒被取用、取用後有沒有促成好結果;SRE 的成熟作法更直白——**每次都響而沒人動作的告警等於沒有告警,零觸發的告警該退役**,標準動作是「匯出告警史,把「響過但沒產生任何處置」的挑出來刪或降級」。

## 實測基線(2026-08-19 量)

★兩套數字,不可混用★:`lumos gov` 讀進來後會**以 (commit, 節點集, gate, kind, token) 去重**(`scripts/lumos:2950-2957`),所以「帳裡幾行」與「人會看到幾筆」不是同一個數。下表兩欄並列。

★三個發現★:
1. **重複警告佔壓倒多數**:兩道 advisory 合計原始 19,920/20,139=**98.9%**,去重後 7,940/8,156=**97.4%**。兩個算法結論同向。
2. **但不是全然零收斂**——實算 `check-s` 的收斂指標(曾被警告、且已停止再被警告的節點比例)=**12/42=0.286**;其中六個節點在 2026-07-24 同日一起停,像是一次批次補審。★★所以草案原本用「收斂指標 0」當不收斂桶的判準是錯的,與實測直接衝突,已改(見 S1)★★。仍有 **30 個節點到帳本最後一天(2026-08-19)還在被念**。
3. **五道 doctor 檢查在 516 次 `--ci` 中零觸發**。它們確實接了帳(`gov_events.append` 在 `run_doctor` 內,如 `scripts/lumos:785,948,989,1030,1303`),所以零筆=真的沒響過,不是沒接線。

⚠ **不可混為一談**:`canary`/`signoff`/`kill` 不寫這本帳,各有自己的帳檔(canary 448 筆、signoff 8 筆、kill 帳檔不存在)。★2026-08-19 初判曾把它們與上述五道並列成「八道閘從沒寫過帳」,查證後推翻——寫別本帳 ≠ 沒觸發。★ 惟 `lumos gov` **本來就把七本帳合流成同一組 gate 值**,故本案統計天然涵蓋它們(見 S1 範圍)。

## 新機制準入三問(Growth test)

1. **真事故?** ★半過,弱點明講★。可數事實有(上表);但**查無一筆「因為警告淹沒而漏掉某事」的已記錄事故**。支持仍立案的理由:本案不是新機制,是對既有機制的**讀側量測**——而「紀律要不要退場」這題的既有處境是 [[Issues/散文紀律沒有退場機制]] 記載的「被前後量過效果的紀律=0 條」,★沒有尺,就永遠湊不出事故帳★。先造尺是解開死結的唯一入口。若裁定者認為此理由不足以豁免第一問,本案應同 [[Projects/宣稱級時間戳_計劃]] 落為 gap 佔位。
2. **風格偏好?** 否。零觸發的閘與不收斂的警告,是「宣稱有守衛但實際沒有」的正確性問題。
3. **既有小修蓋得住?** 蓋得住,本案即是小修:`lumos gov` 本來就在讀這本帳,加一段統計輸出;零新子命令、零新帳檔、零新紀律。

## PRIOR-ART

① **最小解層級**——不造新機制:讀側 `lumos gov` 加 `--stats` 段(該指令已在解析同一本帳);恆 rc0,同 seat-check「觀測不進閘」慣例。② **世界解過沒**——有,且是成熟實務不是新潮流:SRE 告警治理(actionability 判準、30 天告警史盤點、「響過但無處置」即刪或降級)、agent memory forgetting 訊號(recency/frequency/outcome salience)、data observability 的 KPI 盤點。③ **裁定 = borrow-design**(借判準與盤點動作,零依賴自寫;adopt 排除:零依賴家規)。

## 設計草案(待 design-loop)

### S1 `lumos gov --stats`

**母體 = `lumos gov` 既有讀入的七本帳**(bypass/rot-queue/governance/canary/kill/signoff/ci,`cmd_gov` docstring 明載),不另外挑一本——本案是該指令的讀側加段,母體跟著它走。**計數用去重後的列**(與 `gov` 既有呈現一致,即「人會看到幾筆」);同時併印原始行數供噪音量級對照。★兩個數字都印、都標籤清楚,不准只印一個★。

**時間窗**:沿用既有 `--since`(預設 90 天),輸出第一行印實際窗口;要全史用 `--since 9999`。

逐 gate 吐:去重後筆數、原始行數、不同節點數、不同 commit 數、首見/末見日期,以及**收斂指標**。

**收斂指標定義**:分母=該 gate 曾警告過的節點總數;分子=其中「末次被警告日 < 本帳最後一天」的節點數(即已停止再被念)。無節點欄的 gate(如 `code-loop`)→ 指標印 `n/a`,不入分類。

分類措辭(三桶):
- **零觸發**:該 gate 在窗口內零筆。★措辭必須自曝限制:「窗口內零筆——可能從未觸發,也可能是有效嚇阻或守的情境還沒發生;零觸發不等於無價值」,不下定論。★
- **不收斂**:★判準不用「收斂指標=0」(實測 `check-s` 為 0.286,該判準會漏掉最吵的那道)★,改用**每節點平均重複次數** = 去重後筆數 / 涉及節點數,超過門檻(草案 20)即入桶。
- **正常**:其餘。

**輸出不變性**:不帶 `--stats` 時 `gov` 輸出**逐字元不變**(既有消費者零擾動),此為硬要求。

### 範圍刀(明確不做)

- **不刪任何閘、不降級任何警告**——本案只產資料,退場動作是人另外裁。
- **不改 doctor 判定、不改 rc、不改 `--ci` 落帳邏輯**。
- **不做自動退場**、不做門檻可設定(v1 寫死,漂了再說)。
- **不新增帳檔、不改任何帳檔格式、不改 `gov` 既有輸出**。★原草案寫「不碰其他帳檔」是自違——`lumos gov` 本來就合流七帳,加在它讀側不可能只看一本;pre-flight 掃出,已改為上述真正做得到的界線。★

## 測試策略(TDD,先紅後綠)

1. `t_gov_stats_fields`:fixture 造帳→每 gate 六個輸出欄位(去重筆數/原始行數/節點數/commit 數/首見/末見)值正確;無節點欄的 gate 收斂指標印 `n/a`。
2. `t_gov_stats_dedup`:同一 commit 同節點同 gate 同 kind 重複 3 行 → 去重欄=1、原始欄=3(兩數分離釘)。
3. `t_gov_stats_convergence`:分母=曾被警告節點總數、分子=末次警告日早於帳本最後一天者;造「已停止」與「仍活躍」各一 → 指標值正確。
4. `t_gov_stats_buckets`:零筆 gate→零觸發桶且措辭含自曝限制句;每節點平均重複 25 次→不收斂桶;平均 3 次→正常桶。★另釘一案:收斂指標非 0 但平均重複超門檻者仍入不收斂桶(防判準退回舊版)★。
5. `t_gov_stats_window`:`--since` 縮小窗口→窗口外的列不計;輸出首行印實際窗口。
6. `t_gov_stats_rc`:`--stats` 恆 rc0;不帶 `--stats` 輸出與改動前逐字元相同。
7. `t_gov_stats_parse`:壞損 JSON 行跳過不計、不炸;缺 `nodes` 欄的列不炸。

## 實務隱患

**通用三問**:
- **併發**——純唯讀(開檔逐行讀 JSONL),無寫入無鎖。與正在 append 的 `doctor --ci` 同時跑,最壞是讀到半行→該行 parse 失敗→照既有規格跳過不計,不炸。
- **效能**——冷路徑(人工回顧時才跑)。現況 20,139 行、線性掃一次,無 N² 比對;計數用字典。若帳長到百萬級再談增量,v1 不做。
- **資源**——全走 with-open 即開即關,無連線無鎖持有。

**風險類逐類答**:
- **self-governance(pitfalls 命中)**:本案★不擋任何東西★,故無「誤擋」可言,也不需要逃生口——恆 rc0、不改 doctor 判定。★但反向風險存在且更該講:本統計的輸出會被拿去主張「某道閘可以退場」,而它量的是「響過幾次」不是「有沒有用」——一道從沒響過的閘可能正是因為它有效嚇阻,或它守的情境還沒發生。★故措辭必須把「零觸發」與「無價值」切開,且本案範圍刀明訂不刪不降級。
- **已排除:金流**——不碰任何金額/交易。
- **已排除:對外送出**——純本地讀檔,無網路。
- **已排除:不可逆**——唯讀,不寫任何檔。
- **已排除:認證/PII**——帳本只有 gate 名、節點名、commit sha,無個資無憑證。
- **已排除:遷移/schema 變更**——不改帳本格式,只讀既有欄位。
- **快取/狀態同步**——不做快取,每次重算;故無 staleness。
