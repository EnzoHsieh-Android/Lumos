## 發現

### F1　同時有兩個會談時，沒有任何方法偵測到對方，就可能各自登記成第2案
- **嚴重度：major　blocking：是**
- line 52 引句：「若另一會談也要同時試行，先由人釐清單一編排者與登記位置，再決定是否需另設協調機制；本次不先造一套鎖協議。」
- **問題**：這條只寫了「發現有人同時做」之後怎麼辦，沒寫「怎麼發現」。
  - 使用者全域規則要求每個會談用獨立的 worktree（工作目錄副本）。
  - 登記表在各自 worktree 的檔案裡，兩個會談各讀各的副本，都會看到第2格「待登記」。
- **後果**
  - 兩邊各自合格地登記成第2案，之後合併時才撞在一起。
  - 這時兩案的證據、名額與輪次都已經混在一起，事後很難拆。
- **交接段也有同樣的洞**：第 129、138 行叫下一個會談「確認沒有另一會談已接手」，但沒說用什麼來確認。
- **補充**：撤掉鎖和領號器是對的，因為前一輪診斷說它們自己會製造失敗路徑。
  - 但「完全不做偵測」跟「造鎖」是兩件事。
  - 最小做法是登記前在 main 或共用位置做一次有時間戳的唯讀檢查，或讓人在啟用時指定單一編排者。
  - 現況是啟用沒有任何機械防護，只靠人剛好想到。

### F2　「生效」記在計劃以外的筆記，但計劃要求讀的那張表沒指向它
- **嚴重度：major　blocking：否**
- line 72 引句：「再把版本與生效時間記入」（後接〔代碼審改道生效驗證〕那篇筆記）
- line 52 引句：「每案首輪與收尾時讀此表」
- **問題**
  - 生效狀態只寫在另一篇 Verification 筆記。
  - 被凍結審過的計劃本身仍寫著「尚未生效」，而且不能改，因為改了就跟 PASS 綁的版本對不上。
  - 但編排者每案「讀此表」，這張表和第2案前的核對清單，都沒要求去讀那篇生效紀錄。
- **後果有兩個方向**
  - 新會談只讀計劃，會以為永遠沒生效，因此不啟用。
  - 或是只看到 S1 的條件句，沒去核對 PASS 就自行登記。
- **補法**：在「第2案之前須核對」那一條，加上「核對生效紀錄存在且版本符合」。這是補一句話就能解決的缺口。

### F3　登記後才發現不合資格的案仍占名額，會悄悄污染五案樣本
- **嚴重度：minor　blocking：否**
- line 74 引句：「已登記案後來中止或變成不合資格仍保留名額並記偏離，不事後換掉難案」
- **問題**
  - 「是否依賴未放行探針」在登記時只能憑編排者判斷，驗收證據是否真的獨立，往往做到後面才知道。
  - 不合資格的案照樣占格，五案中可能有幾格其實不是「獨立新工作」。
  - 規格也只要求「記偏離」，沒有規定回顧時要把這類案另列、不混入比較。
- **為什麼只算 minor**
  - 這是為了防止挑案而做的取捨。
  - 回顧段已經說明「只能看個案方向」，不拿來推因果。
- **建議**：回顧時要求不合資格案分列。

### F4　誰接手由編排者決定，樣本框偏誤只有事後聲明
- **嚴重度：minor　blocking：否**
- line 74 引句：「沒接手的 repo 工作不在樣本框，最後回顧須明說」
- **問題**
  - 登記之前，編排者可以不接手難案，之後的「不換難案」規則管不到這一段。
  - 規格已經誠實限縮結論，所以不算誤導。
  - 但沒有要求記錄「看過但沒接手」的工作及理由，回顧時想講清楚樣本框也講不出來。
- **補法**：在首輪 intake 加一欄，記被跳過的候選與跳過理由。

### F5　要求前後儀器版號分開比較，卻沒定義版號，表上也沒欄位
- **嚴重度：minor　blocking：否**
- line 64 引句：「之後續試時應把前後儀器版號分開比較」
- **問題**
  - 全文沒有定義「儀器版號」是什麼，登記表五格也沒有這個欄位。
  - 第2至5案跟第1案的基準若不同，回顧時會分不出差異來自流程還是儀器。
- **補法**：在 intake 記基準提交即可，而且基準提交本來就要記。這項只是缺一句連結。
