# code-batch14 r1 — 通才席

severity: major

- [major] build_notifier() 產出的 .app 簽章保證是壞的,每次成功建置都一樣。
  引句:「plutil -replace CFBundleIdentifier -string "com.enzo.lumos.watchdog-notifier" "$NOTIFIER/Contents/Info.plist"」
  位置:`governance/install-watchdog.sh`
  blocking:是
  why: 把這段函式原封不動抽到隔離環境重跑。① osacompile 剛編完時 `codesign --verify --deep --strict` 判 valid on disk / satisfies its Designated Requirement。② 照腳本原樣跑完兩行 plutil -replace 之後再驗,變成「invalid Info.plist (plist or signature have been modified)」,spctl 給一樣的拒絕。100% 可重現——osacompile 簽的章包含 Info.plist 的內容雜湊,簽完才改 plist 等於簽完名才改合約。③ 佐證:實際 open -a 這支壞章的 app 並看系統 log,tccd 對它出現「Failed to copy signing info / unable to compute designated requirement」——權限守門在辨識這支 app 身分時已經出狀況。修法:plutil 改完之後 codesign -f -s - 重簽。

- [major] notify() 的 `&& return 0` 退路邏輯,對「通知權限被關掉」這個情境是死碼。
  引句:「open -a "$NOTIFIER" --args "$1" >/dev/null 2>&1 && return 0」
  位置:`governance/wrapper-watchdog.sh`
  blocking:是
  why: ① 對「執行檔缺失」的殘破 bundle,open -a 回 1 並印 executable is missing——這個失敗模式抓得到。② 但對「簽章壞掉但其餘完整」的 app(能正常啟動),open -a 回 0,連續兩次都驗過。③ open 的語意只代表 LaunchServices 有沒有接受啟動請求,跟 display notification 有沒有被權限擋下是兩件事。結論:對「app 存在、能啟動,但通知被權限吞掉」這個情境永遠回 0、永遠不會走到 osascript 退路——而那正是這支存在的唯一理由。它把「沒人聽得到」從一個樓層搬到另一個樓層,同一個坑。

- [minor] build_notifier() 在 osacompile 成功之後的收尾指令完全沒查回傳碼。
  引句:「cp "$tmp/lumos.icns" "$NOTIFIER/Contents/Resources/applet.icns"」
  位置:`governance/install-watchdog.sh`
  blocking:否
  why: 三行沒有任何 || 或錯誤檢查,函式最後固定 return 0。cp 或 plutil 失敗時 build_notifier() 依然回報成功。跟上面第一條同成因:整段假設「osacompile 過了後面就不會錯」,而恰恰是後面那幾行把簽章弄壞。

- [minor] `--rebuild-notifier` 不管 build_notifier 有沒有成功,都會發出「重建完成」的通知。
  引句:「build_notifier && echo "通知 app 重建好了:$NOTIFIER"」
  位置:`governance/install-watchdog.sh`
  blocking:否
  why: 把 build_notifier 換成永遠回 1 的假函式照抄這兩行:第一行的 && 正確地沒印出成功訊息,但第二行 open 是獨立敘述、不受 && 鏈保護,照樣執行。使用者機器上如果已有舊版成功建置的 app,這行就會用舊的那支發出「重建完成」——跟實際狀況不符。

- [clean] quit / 殭屍行程:實測乾淨。
  引句:「applet 一定要 quit★:不加的話它會留在事件迴圈裡不結束」
  位置:`governance/install-watchdog.sh`
  blocking:否
  why: 連續 open -a 呼叫五次,ps 每次都是 0 筆殘留;系統 log 看得到 runningboardd 在啟動後約 200ms 回報 termination。

- [clean] shell 安全性乾淨。
