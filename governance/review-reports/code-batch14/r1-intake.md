## 編排者自己重現的

規矩是「≥major 的要自己查過才准折」。這一輪有三條是我自己敲出來的,而且★推翻了外家席一半的推論★:

1. **`open` 的回傳碼到底代表什麼**(f1):外家席和通才席都說「open 回 0 不代表通知送出去」。
   我做了三組對照:
   - app 不存在 → `open` rc=**1**
   - app 存在但 applet 一跑就 error → `open` rc=**0** ← 兩席都對
   - bundle 在但執行檔被砍 → `open` rc=**1**
   所以外家席說「退路是死碼」**只對一半**:結構性失敗(bundle 壞了)退路走得到,
   走不到的是「app 跑起來了但通知被吞掉」。折入時按這個更精確的事實寫,沒有照抄它的結論。

2. **簽章被 plutil 弄壞**(f8,通才席,★這一輪最深的一條★):我自己驗:
   - 剛 `osacompile` 完 → `codesign --verify` = **valid on disk**
   - 跑完兩行 `plutil -replace` → **invalid Info.plist (plist or signature have been modified)**
   - `codesign -f -s -` 重簽 → **valid 回來了**
   而且我順手驗出通才席沒驗到的下游後果:**章壞掉時 applet 裡的 `do shell script` 會被
   系統靜默擋掉**(探針寫檔完全不發生)。這正好解釋了我在折入過程中撞到的怪現象
   ——我本來想用「applet 摸一個印子」來回報「我真的跑到了」,那個機制一直失敗,
   當時我以為是隱藏目錄或路徑問題,**其實是章壞了**。重簽之後印子機制當場就通了。

3. **applet 收不到參數**(折入過程自己撞到的,不是任何一席報的):
   `open -a APP --args "訊息"` **不會**進到 applet 的 `on run argv`。探針證明:
   handler 寫成 `on run argv` 時 applet **整支不執行**(連第一行都沒跑到),而 `open` 照樣回 0。
   改成 `on run`(不吃 argv)+ 訊息從檔案讀才會動。這條沒有席位報,是我自己量出來的。

## 誠實邊界(折完仍然存在)

**「通知權限被關掉 = 靜默不喊」這個洞,這一層真的補不起來。** 實測過三條路:
①`open` 的回傳碼——只反映有沒有啟動;②applet 自己回報——只證明它跑到了,不證明使用者看得到
(`display notification` 被權限擋時不報錯);③查通知權限——沒有官方 CLI,去翻 NotificationCenter
的 sqlite 是 SIP 保護、格式沒保證,為了一個提醒功能賭未公開內部格式不划算,不做。

所以這個洞交給兩件事:**安裝時當場發一則請人確認一次**(唯一的實質防線,而且那道防線是人不是機器,
安裝腳本的輸出裡明白這樣寫),加上**兩條不受通知權限影響的通道**——這支自己的紀錄檔、
健檢的 `[A1]` 段(後者跑在 Claude Code 的收工流程裡,不在 launchd 底下)。

通才席說「它只是把沒人聽得到從一個樓層搬到另一個樓層」——**這句話在「只靠通知」的前提下是對的**,
但前提不成立:通知從來不是唯一通道,是三條裡最不可靠、也最不需要人主動查的那一條。

## ★閘過之後又改了一次(誠實留痕)★

處置閘 PASS 之後,使用者實際看通知回報「圖示沒變,是 AppleScript 的卷軸」。
這條**不是任何一席報的**,是交付後真人驗收抓到的——而且我在此之前已經跟使用者說過
「圖示換好了」,那句話當時是錯的(我沒辦法自己看到通知,只驗到 icns 檔對、簽章有效)。

一步一步試出來,換圖示要**三件事一起做,少一件都還是預設的卷軸**:

1. **刪掉 `osacompile` 附的 `Assets.car`** —— 那是一份編譯過的圖示目錄,裡面裝著預設的
   applet 圖示,而 macOS **優先用它**、不看我們放的 `.icns`。只放 icns 完全沒有用。
   (`strings` 進去看得到 `applet` / `applet/Group` 這些條目。)
2. **重簽** —— 見上面 f8。
3. **換一個 bundle 識別碼並重新註冊** —— **通知中心會記住某個識別碼第一次註冊時的圖示**。
   前兩件做對了但沿用舊識別碼,它還是給你看快取住的舊圖示。實測:做完①②仍是卷軸,
   把識別碼加上 `.v2` 尾巴 + `lsregister -f` 之後,當場變成四角星。

代價寫在碼裡:換識別碼等於一個新 app,**通知權限要重新給**——所以裝完一定要當場發一則請人確認。
中間有一次通知整個沒出來,就是換識別碼造成的權限重置,不是 bug。

這三步已經寫進 `build_notifier()` 並加了四條結構守衛(識別碼必須帶版本尾巴、重簽必須排在
刪 Assets.car 與改 plist 之後、要有 lsregister)。**這批是 gate PASS 之後的追加改動**,
沒有再跑一輪席位審——理由:六行、機械、而且是真人在迴圈裡逐則確認出來的,
比再派一輪 sonnet 看散文可靠。記在這裡不掩蓋。
