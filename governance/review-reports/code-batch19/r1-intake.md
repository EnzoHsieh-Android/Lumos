## 編排者自己重現的(≥major 一律自己查過才折)

外家席全部標「讀碼推論,未實跑」(沙箱不可寫),所以每一條我都自己敲過:

1. **`set -e` 在 `||` 左手邊會被整個關掉**。三行腳本驗:`take_lock` 裡的寫 pid 必定失敗,
   函式照樣回 0、腳本照樣活著往下跑。**HIT。**
   ★而且孿生的 `daily-governance.sh` 更直接★——它檔頭第 12 行明寫「不用 -e」,
   所以那支從來就沒有這道保護。**兩支都要顯式檢查。**
2. **`.steal` 的殘留自癒用的是同一個 rm+mkdir 形態**:`grep` 確認兩支都有。**HIT。**
3. **旗標式 trap 的前提成不成立**:我實測 bash 收到 SIGTERM **會**跑 EXIT trap。
   所以「取鎖成功到扳旗標之間收到訊號 → 收尾什麼都不做」是真的漏。**HIT。**
4. **身分比對**:通才席的重現我照著跑得通——持鎖者走符號連結啟動,`ps` 的指令列裡
   沒有腳本名字,活著的持鎖者被判成死的,鎖被搬走。★它量到兩個行程同時印出「我拿到鎖了」
   而且同時還活著★。**HIT,而且這是最嚴重的一條。**

## ★兩席各推翻我一個判斷,兩個都推翻得對★

**① 我寫的「這一步沒有守衛,因為構造不出來」是錯的。**
外家席與通才席各自獨立指出,而且各自給了作法。作法可行:在它印出「發現殘鎖」之後
`SIGSTOP` 停住,替它把鎖換成別人的新鎖,再放行——停得住是因為現場預埋一把
「超過 60 秒的殘留接管權」,它得先跑一次 python 算年齡,那幾十毫秒就是窗口。
★「拿掉它重跑整套是 0 條紅」只證明現有測試沒咬到,不證明構造不出來。★
守衛已補,拿掉那一句會翻紅。

**② 我用「腳本自己的檔名」當身分錨,只縮小了洞、沒關掉。**
我原本折外家席 f4 時改成「用 `basename $0` 當錨」,自認解決了改名問題。
通才席的 blocker 打穿它:持鎖者與後來者的**啟動方式不同**時(一個走符號連結、一個走真名),
名字錨照樣對不上。**處置不是再調整名字比對,是把名字整個踢出判斷**——
改用 pid 加「那個行程的啟動時刻」(`ps -o lstart=`,實測穩定、跨使用者可讀、pid 不存在時回空)。
順帶把「身分問不出來 → 無條件讓行」改成「掉進鎖齡兜底」:
★無條件讓行那條路上沒有兜底,一旦誤判就是永久停擺而且完全沒有訊息。★

## ★通才席自己實測後撤掉兩條懷疑,我採信★

它懷疑 `.steal` 殘留會造成第二層雙開,建了現場跑 15 輪 × 8 行程:**0/15**。
它推理出原因——真正的互斥是下一層的 `mv`(同一個來源只有一個人搬得走)。
它也試著單獨構造收尾的讀-刪窗口,結論是「那不是獨立漏洞,要跟身分那條合起來才成立」。
**兩條我都採信**(外家席報的是同兩處,判 blocker/major)。
★但兩處我仍然折了★,理由不是它們單獨會炸,是**原子化只花三行,而留著就是同一個形態的第二份**。
`.steal` 那條我另外量到一個它沒量的角度:同一輪裡「真的走進接管區」的行程數——
rm+mkdir 版本會超過一個,mv 版本恆為一。那個數字是可觀測的,守衛就釘在那裡。

- **`lock_holder_alive "$x"; local hv=$?` 這個寫法只有在 `take_lock` 被當成 `||` 左手邊時才安全**

  不再依賴那個隱含前提。

  ——鏡像那批修法時替換區間抓太大。★既有測試當場接住★(`LOCKDIR: unbound variable`)。
