# code-batch19 — 閘過之後的誠實留痕(不動 r1-intake.md)

★這一份是新開的檔,不是改 intake。★ intake 的 sha 已經綁進帳本,
事後追加會讓整輪留痕作廢(今天已經因為這個踩過三次,見 [[Systems/loop-convergence-recording]])。

## 發生了什麼

處置閘 PASS、推送成功之後,**CI 紅了一支**:`test_steal_break_is_atomic`
在 Linux runner 上翻紅(本機 macOS 連跑都是綠的)。

```
AssertionError: 2 not less than or equal to 1 : ★同一輪有 2 個行程同時走進接管區★
```

## 根因:★那支測試量錯了東西,而且是我自己造的假訊號★

它數的是「同一輪裡有幾個行程印出『走進接管區』的訊息」。問題在於我把
**「進來後發現鎖已經換人」** 也算成「走進去了」——但那句話的意思正好相反:
它代表這個行程是在**別人已經做完接管之後**才進去的,那是**合法的接續,不是同時**。

所以那支測試量到的是時序巧合,不是互斥性。本機綠、Linux 紅,兩邊都不代表任何事。

**更難看的是**:通才席在報告裡已經明說過這件事——它跑 15 輪 × 8 行程量到 0/15,
並且講出原因(真正的互斥在下一層的 `mv "$LOCKDIR"`,同一個來源只有一個人搬得走)。
★我讀到了那段、在 intake 裡也寫了「兩條我都採信」,然後還是寫了一支「量得到」的測試。★

## 處置

1. **那支測試換掉**,改成釘真的成立而且有鑑別力的性質:
   `test_stale_steal_does_not_block_and_only_one_takes_over`
   ——殘留的接管權要破得掉(不然自主迴圈永遠跑不起來),破掉之後只准一個人接管成功。
   翻紅釘:拿掉整段破鎖邏輯 → **翻紅**;連跑三次穩定綠。
2. **`mv` 這一改本身,誠實降級成「只有結構層守衛」**。實測:把 mv 改回 rm+mkdir,
   **沒有任何一支行為測試翻紅**。結構守衛是 `t_daily_wrapper_lock_matches_source`
   (釘住兩支腳本都必須用 mv 破接管權,改回去會紅)。留著這一改的理由是
   「同一個形態不要在 repo 裡留第二份」,不是「量得到它有用」。
3. 碼裡與 [[Systems/autonomous-iteration-loop]] 都加了這段誠實記。
