## Finding

1. xargs 新分支讓「xargs 後接大量空白」變成二次方
severity: minor
   - blocking: 否
   - 歸因:有證據的修復回歸。
   - diff 位置:`_INFRA_CMD` 新加的 `xargs\s+(?:-\S+\s+)*` 分支,後面本來就接 `\s*`。
   - 問題:`\s+` 和尾端的 `\s*` 都吃空白,連續 N 個空白有 N 種切法,每種都再失敗一次。
   - 輸入:一行 `"xargs" + " "*N + "x"`,用 `_INFRA_CMD + "(?:kill|pkill)" + _INFRA_E` 在 `re.I` 下搜尋。
   - 走到哪:`_stack_norm_line` 不壓空白,`_stack_applicability` 和張力候選會把整行交給 `_STACK_TRIGGERS` 的 `pat.search`。`kill`、`wait`、`rm\s+-`、`cd`、`sed\s+-i`、`date` 等共用 `_INFRA_CMD` 前綴的 when 都會逐條中招。
   - 實測(同一行,修前正規式也就是沒有 xargs 分支的版本,與修後 f14f6808 比):

     | N | 修前 | 修後 |
     |---|---|---|
     | 5000 | 0.000 秒 | 0.23 秒 |
     | 10000 | 0.001 秒 | 0.91 秒 |
     | 20000 | 0.002 秒 | 3.7 秒 |
     | 100000 | 未測 | 92 秒 |

   - 另一個輸入:1000 組 `xargs` 加 200 個空白,全長 20 萬字,修前 0.017 秒、修後 0.39 秒。
   - 影響:要有上萬個連續空白的程式行才會卡,實際碰到的機率低。但輸出 92 秒對應 10 萬字,所以降為 minor。
   - 修法方向:把前綴改成 `xargs\s+(?:-\S+\s+)*` 後不再接 `\s*`,或用 `xargs(?:\s+-\S+)*\s+`。
   - 引句:「(?<![A-Za-z0-9_])xargs\s+(?:-\S+\s+)*)\s*」
