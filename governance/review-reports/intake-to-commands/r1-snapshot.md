# 收貨線指令化_計劃

> 白話:審查席交報告之後,把報告變成「機器讀得懂的格式」再做三道檢查、算指紋、記帳——這一整條線到今天還是**每個迴圈臨場寫一支腳本**。這篇要把它收成兩條指令。★這不是為了少打字,是因為臨場腳本已經在做危險的事★。

PRIOR-ART: 最小解在一支正規化器加一支編排指令(不新增治理層、不改任何判準);世界解=gofmt / prettier 的 canonical form、Parse-don't-validate、把外部工具輸出轉成機器可讀標準格式的轉接器——★本 repo 對 linter 做的是 SARIF,不是 reviewdog 的 rdformat,前掃抓到我張冠李戴★,這裡改引 SARIF 這條既有實作、Gerrit 的明示欄位;裁定=borrow-design(轉接器放進工具裡而不是每個人手上,但★缺值一律退件、不預設★)。

## 為什麼要做:臨場腳本已經在做危險的事

不是「不方便」而已,是三件實際發生過的:

1. **會把低報變成靜默通過**。臨場那支腳本在一行嚴重度都讀不到時,會默默把首行補成「乾淨」。而寫入端 rc2 擋的正是這件事——等於親手把「低報成乾淨」的無聲逃逸門補回去。
2. **會弄壞引句**。它剝頭尾引號、把「」換成『』,已經在入版控的卷證裡發生;那讓合法引句錨不回凍結快照,審查結論被判成不採信。★這一輪我自己就踩到,還為此改過一次審查材料★。
3. **每個迴圈各寫一份**。至少六個迴圈各記過一次不同變體,2026-09-05 才第一次寫成腳本入版控。**六份實作就是六種漂移。**

另外兩個附帶事實:
- **一輪審查的收貨與記帳沒有任何指令串起來**。每席固定三到五條參數高度重疊的指令,十一席的迴圈光收貨記帳就要打四五十條;凍結快照的指紋還要人另算,而工具內部早就在算同一個檔的指紋。
- **派工單沒有機械格式**。讀側只認一個鍵,2026-09-03 起有八個迴圈全席被判成「認不出是誰」,於是喊出假的「單一家族」「席位不足」警告——**假警告比沒警告更糟,因為它會訓練人忽略警告**。

## 要做什麼(三件,一批)

### S1 正規化收成一個子命令

- 做且**只做**三件格式轉換:把 `quote:` 標籤改成本專案的引句格式、把 `file:` 位置包成反引號、把寫在表頭裡的嚴重度抽成獨立一行。
- **保留原始檔**(`.raw`),轉換後另存,不覆蓋。
- ★找不到任何嚴重度宣告就退件(rc2=本專案 CLI 的「擋下」退出碼,不是一般錯誤),絕不代填★。這是本案的核心:臨場腳本正是在這裡出的事。
- ★嚴重度的解析必須複用既有的 `_report_severities`、引句正規化必須複用既有的 `_quote_norm`,不得自寫第二份★。自寫會出現「正規化器認得、寫入端不認」的漂移,家裡為此立過鐵則(2026-08-02 預檢與主迴圈兩份實作當場漂移)。

### S2 一條收貨編排指令

- 「凍結快照」= 派工當下把被審材料複製一份存起來、之後不再改動的那一份;引句錨定比對的對象就是它(不是現在的檔,現在的檔可能已經被折入改過)。
- 依序跑:正規化 → 引句錨定 → 檔案行號核對 → 席位對帳 → ★嚴重度對帳(`severity-check`,既有的第四道收貨)★,算出凍結快照的指紋。
  ★前掃抓到:我全篇寫「三道」,但既有其實是四道★——`severity-check` 的說明字面就寫著「第四道收貨」,而同一次全 repo 審視早就點出過「三道漏了第四道」。我延續了同一個疏漏。
- 印一條**只留嚴重度與處置給人填**的記帳命令。★這條指令本身不寫檔★;會寫檔的只有它第一步呼叫的正規化(見 S1)。
- ★不記帳、不判嚴重度、不自動寫人工判讀的結論★——人工判讀的部分仍由編排者寫。
- ★名字不要叫 intake★:那個詞已經被既有的前掃留痕檔慣例佔用,重用會混淆。

### S3 派工單格式與家族辨識

- 席位對帳先讀家族欄、讀不到才退回猜名字(現在 `_roster_dispatch_entries` 只讀 `auditor`)。
- `loop next` 直接吐派工單骨架(欄位齊、家族預填)。
- 席位檢查驗必要鍵。

## 界線與不做

- **不新增治理層、不改任何判準**。★四道★收貨檢查的判準、處置閘的合取條件、嚴重度分級,一個字都不動。
- **不自動記帳**。記帳仍是人按下去的,工具只把指令準備好。
- **不改寫重複的席位警告行**為計數形式(那牴觸該檔宣告的只追加不改寫),那件併 2026-11-26 的覆核一起裁。
- **新子命令要進指令索引與說明表**(既有守衛會擋)。

## 圖譜攔截:先讀過三天前被停的那個近似案

★圖譜攔截★站:開案前;源:[[Projects/折入去重留痕_計劃]](2026-09-03 停案)

那個案子要「把折入時的去重判斷記下來」,做法是**自己開一個獨立檔**(`rN-fold.json`)。Enzo 在第一輪攤牌後裁停,四個結構問題都指向同一件事——★映射不該是獨立檔,該掛在既有的記帳列上★:

1. **沒有寫入入口** → 驗證只在有人選擇跑的時候才發生。
2. **自報拷貝** → 等於自己驗自己。
3. **逐席快照沒有欄位指定對的是哪一份**。
4. **不在回放凍結的閉包裡** → 週跑抽查看不到它。

**本案為什麼不是同一個坑**(對著那四條死因逐條答,不是宣稱「這次不一樣」):

★先把話說精確★(前掃抓到我原本寫得太滿):本案**會寫檔**——S1 的正規化會把轉換結果另存一份、原檔留 `.raw`。所以不能說「什麼都不寫」。真正的主張是:**不新增一種獨立於強制記帳流程之外、沒有人被迫產生、也沒人被迫消費的判斷紀錄格式**。那才是折入案的死因。

| 那案的死因 | 本案 |
|---|---|
| ①沒有寫入入口 → 驗證只在有人選擇跑的時候才發生 | 席報告是記帳的**必填參數**(`--report`,不給就 rc2 擋),快照同理。不跑收貨線就記不了帳——入口是強制的,不是選擇性的 |
| ②自報拷貝 → 等於自己驗自己 | 四道機械檢查的比對對象是**凍結快照與真實程式檔**,不是本案產出的任何東西。本案不產生「供自己驗證用」的資料 |
| ③逐席快照沒有欄位指定對的是哪一份 | ★這條是前掃抓到我原本漏答的★。本案的對應關係寫在**既有帳列上**:`--report` 與 `--snapshot` 是同一筆記帳的兩個參數,工具對兩者各自算指紋存進帳,誰對誰不需要另立欄位去猜 |
| ④不在回放凍結閉包裡 | 凍結會把判定輪每筆帳列的 `report`/`snapshot` 連同內容與指紋收進閉包;本案動的就是這兩者本身,**不新增閉包外的檔案類型** |

★如果審查席認為上面哪一條對照不成立,那就是 blocker——因為那表示本案正在重蹈一個三天前才被裁停的設計。★

## 已知風險

- **多一層轉換就多一個可能出錯的地方**。緩解:轉換前後都保留、退件優先於猜測、複用既有解析器而不是自寫。
- **「印出指令給人貼」可能被當成自動化**。緩解:輸出明寫哪幾個欄位是人要自己判的。
- ★本案自己就是「工具替人做事」的一次擴張★,而這個 repo 的家規是「別治理過頭」。判準:這三件都是把**已經在做、但每次手做且做錯過**的事收進工具,不是新增儀式。
