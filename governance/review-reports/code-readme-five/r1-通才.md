1. **bash shebang 正規式漏收 `dash`/`tcsh` 等,與 Python 版 `_shebang_script` 不一致**
   `pre-commit`/`post-commit` 的 `is_shebang_code()` 要求 "sh" 前面緊接 `/` 或空白(或整字 `bash`/`zsh`)才算命中;`#!/bin/dash`、`#!/bin/tcsh` 因為 "sh" 前面是字母(`da`/`tc`),不命中。但 `check-graph-sync.py` 的 `_shebang_script()` 只是 `"sh" in line`(無鄰接要求),同一份 `#!/bin/dash` 檔案它判是程式碼。實測:在臨時 repo staged 一個 `#!/bin/dash` 的無副檔名檔,`bash scripts/hooks/pre-commit` 回 rc=0(放行,不擋),而 `check-graph-sync._shebang_script` 對同內容回 `True`。這代表 git commit 時的硬擋(pre-commit/post-commit)對這類直譯器仍有盲點,而本輪要補的正是「無副檔名主程式漏擋」這件事,判定不一致等於留了後門。此 diff 新增的 `t_code_exts_four_lists_agree` 對 shebang 只查「函式名字串有沒有出現在檔案裡」(見引句),沒有驗證四份判定的**行為**是否一致,所以這個落差不會被目前測試發現。
