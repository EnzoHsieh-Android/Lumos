# 代碼審資安席_計劃

> 白話:高風險的代碼審,一律多派一席專門從攻擊者角度看這份改動;收斂判定多一個條件——整個審查迴圈裡,至少要有一輪真的派了資安席、而且它的報告記進了帳,不然不給收斂。

## 緣起

- 2026-09-11 治理日報四篇,其中兩篇直接相關:掃 3,171 個 AI 助手設定倉庫有 16% 帶安全缺陷(這套自己就是往別人機器裝 hook 的分發者);以及「機器算得出來的判定,該擋在動手那一刻,不是推到審查員眼前指望它自己想到」。
- Enzo 問「code loop 的分席鏡頭有資安角度嗎」。查的結果:**沒有,而且是刻意的**——[[Systems/pitfalls-code-loop]] d5(2026-08-27)明文排除,理由「單人私有 repo、非對抗威脅」,回頭條件「工具鏈真的吃不可信外部輸入時重拉」。
- 現況(我查一次、另一個乾淨 agent 用原始問題獨立再查一次,2026-09-11,兩邊一致):
  - 代碼審 skill 全文沒有「安全 / security」;編制表沒有資安席;風險掃描的類軸只有併發 / 效能 / 資源。
  - 190 份派工單裡有 8–9 個迴圈臨時加過帶安全味的鏡頭(兩次查的關鍵字口徑不同,差一個),沒有任何規定要求。
  - 本機 9 個消費專案的派工單,沒有一份用過資安鏡頭。
  - 技術棧慣例 skill 只有 node-idioms 有資安條款;linter 目錄列了資安類 linter,但擋推送那條鏈恆 `--no-lint`(2026-08-26 d4)。
- d5 的前提已經對不上:repo 在 GitHub 上是 **PUBLIC**(`gh repo view` 2026-09-11 查;8/27 當時是不是公開沒查),README 教陌生人一行 `curl … | bash` 安裝;2026-09-06 [[Systems/hook信任邊界]] 實地重現「打開陌生 repo 時進場 hook 執行對方的程式」——那就是 d5 自己寫的回頭條件。而那條回頭條件是純散文、節點裡 REVISIT 行 0 筆,所以沒人被叫回來看。

## 人裁(Enzo 2026-09-11,三問三答)

1. 「消費級的專案必須要有資安鏡頭」——範圍 = 所有接了 lumos 的專案(選項:全部 / 只有對外給一般使用者用的產品;後者要人標記、標錯就漏)。
2. 觸發範圍 = **只在代碼審本來就有跑的時候加一席**(選項:另給風險掃描加「資安」類、碰到敏感程式就判高風險 / 只在 high 代碼審加一席)。代價寫在〈承認的限制〉。
3. 「工具鏈也納入吧」——所以規則不分專案:**所有專案的高風險代碼審一律必派資安席**,不需要分辨「是不是工具鏈自己」。

PRIOR-ART: ①最小解層級=既有處置閘加一步(照 `_disposal_clause_step` 的形狀)+既有編制表加一席+既有派工範本加一節;不新增指令、不動 `code-loop pass` 介面 ②世界解過:Anthropic `claude-code-security-review`(五類清單、硬排除清單、信心 <0.7 不報、每條必附 exploit_scenario;2026-09-11 讀 claudecode/prompts.py)(Anthropic 官方公開的代碼資安審查 GitHub Action)、OWASP Top 10(網頁應用最常見的十大風險清單)與 MASVS v2(OWASP 的行動 App 安全驗證標準) ③裁定=借用:資安席「看什麼 / 不報什麼 / 嚴重度錨」照 Anthropic 那份改寫、行動端補 MASVS;閘與編制照本 repo 既有架構加一小段自建;零新依賴

## 條款

- [S1] 編制表:`("code","high")` 加一席 `資安`——同門(相對於編排者,Codex 編排時就是 Codex 子代理)、不佔 W(W=這輪要派的審查人數配額;不佔=不算進人數,同「架構對齊」)、required;設計審各級、代碼審 standard 不加 [test:t_roster_code_high_has_security_seat]
- [S2] 處置閘加「資安席」一步:只對「迴圈種類是 code、帳裡任一筆 tier=high、迴圈首筆帳列時間 ≥ 生效日」的迴圈,要求帳裡至少一筆資安席帳列且留痕對得上 [test:t_disposal_security_seat_required]
  - 名字與形狀照 2026-09-08 條款綁定那一步(`_disposal_clause_step`):獨立函式 `_disposal_security_step`,回 fail / ok / skip,自己印一行 `[disposal] 資安席: …`,fail 時把 `資安席` 加進 fails。★不叫「第五條」★——處置閘的「第五步」已經是條款綁定(它對 code 迴圈恆 skip,所以功能不撞,但名字會撞);`_loop_status_disposal` 說明文字還寫「四條合取」是過期的,實作時一併改正。
  - 這個迴圈的帳裡,至少一筆審查席帳列的**席名鏡頭段 = 「資安」**。席名慣例 `<鏡頭>-<模型>`,取最後一個連字號前那段;沒有連字號就整個名字。整段相等才算(`資安審-sonnet`、`非資安-sonnet` 不算)。
  - 那筆的報告檔要在、sha 要跟帳面一致(帳列欄位是 `report_path` 與 `report_sha256`)。現況:處置閘的留痕重驗(報告 / 快照檔在且 sha 與帳面一致,原本的第③條)是寫在閘裡的迴圈,判定輪一段、intake 一段各抄一份,★沒有可呼叫的函式★。實作時先把「單一帳列的報告檔在且 sha 對」抽成一支小函式,原本的留痕重驗與資安席這一步共用,不再抄第三份。
  - 不成立 → 問閘未過(退出碼 1;退出碼 2 保留給帳面壞或參數錯),訊息三段式:缺什麼 → 為什麼在意 → 下一步指令獨立一行。成立 → 印一行「資安席:✓ 第幾輪、哪一席」。
  - **看「整個迴圈至少一輪」不是每一輪**:判定輪(閘拿來下判定的最後一輪)常是只複查修正處、只派一席的 delta 輪,這是席位對帳已知的噪音源,逐輪要求會誤擋。
  - 凍結 / 回放模式(問閘帶凍結指紋重算時):凍結只保存判定輪那一輪的報告檔,所以這一步在該模式下只看帳列(席名、tier、有沒有記 `report_sha256`),不重讀報告檔——否則早幾輪的資安席會被判成缺證據,回放恆報假漂移。
  - 讀側可重算:只讀帳本與報告檔,不信寫側。
- [S3] 生效日:常數 `_SECURITY_SEAT_SINCE = "2026-09-12T00:00:00+08:00"`,寫法與比法照 `_CLAUSE_GATE_SINCE`(用 `_loop_ts_key` 比;帳上 ts 讀不動或沒時區 → fail,壞資料不放行) [test:t_disposal_security_seat_cutoff]。迴圈首筆帳列時間早於它的,這一步印一行「生效日前開的迴圈,不要求資安席」並回 skip。理由:同一個工作目錄的其他會談當天已開的代碼審,不該在拉到新版後突然被擋。
- [S4] 派工範本:lumos-design-loop `templates.md` 加 §7.8〈資安席派工〉,§7.7 立場表加一列 [test:t_templates_security_seat_section]
  - 看什麼:①不可信輸入流到危險操作(SQL / NoSQL / 命令 / 路徑 / 模板注入、XXE〔XML 外部實體注入〕、反序列化、eval 類)②登入與權限(繞過、越權、session / token / JWT〔JSON Web Token 登入憑證〕)③密鑰與個資(寫死、進 log / repo / 錯誤訊息、PII〔能認出特定個人的資料〕)④加密與傳輸(弱演算法、關掉憑證驗證、隨機數)⑤執行邊界(hook、安裝腳本、CI 會不會執行不可信位置的檔;shell 插值;寫進使用者全域設定;授權範圍被放寬)⑥行動端(本機明文儲存、網路安全設定放寬、WebView / 深層連結、剪貼簿);另看這次新加的依賴(沒鎖版本、來源不明)。
  - 不報:DoS / 資源耗盡 / 限流(歸併發資源席)、測試檔、非關鍵欄位上沒有攻擊路徑的輸入驗證。
  - **每條發現必附攻擊路徑:誰、從哪裡、送什麼進來、拿到什麼**。寫不出來 → 標「推論」、最多 minor、blocking: 否。這條壓的是資安審最常見的毛病:一堆講不出攻擊路徑的疑慮。
  - 嚴重度錨:blocker / major = 可直接利用、導致執行任意碼 / 資料外洩 / 繞過登入權限 / 密鑰外露;minor = 縱深防禦類。
  - 附料:該技術棧慣例 skill 裡的資安條款(目前只有 node-idioms);專案若宣告了資安類 linter,把它的輸出當獨立材料附給這一席(日報 arXiv 2609.10969:換材料來源比換模型值錢)——可選,不進閘。
- [S5] skill 說明同步 [test:t_skill_code_loop_mentions_security_seat]:lumos-code-loop `SKILL.md` 步驟 2 加「high 另多派一席資安(templates.md §7.8)」;以「架構對齊」出現的每一處為清單逐一對過(commands/06、code-loop reference.md、design-loop SKILL.md 等),列席位的地方都補上。
- [S6] 決策:[[Systems/pitfalls-code-loop]] 記新決策 d6,並用 decision-supersede 把 d5 標成被取代(2026-09-11 已做) [manual:跑 lumos decisions Systems/pitfalls-code-loop 看 d5 標取代、d6 有效]

## 邊界與不做

- 不改風險掃描的觸發條件(人裁 2);不改代碼審 standard 與設計審的編制;不把 linter 接進擋推送的鏈(d4 維持);不動 `code-loop pass` 指令。
- 「安裝收據 / 重裝預演」是另一案,還在等人裁,不併進來。

## 承認的限制(每條附回頭條件)

- **只有 tier high 才審資安**:只改登入、權限、密鑰這類程式、卻被判成 standard 的改動,沒有人從資安角度看。這是人裁 2 選的取捨。

## 實務隱患

- 併發:資安席這一步只讀帳本與報告檔、不新增任何寫入;帳本被別人同時追加、讀到半行的情況,既有處置閘已經 fail-closed(壞行直接退出碼 2),這一步跑在它之後。無新增併發面。
- 效能:掃的是「這一個迴圈」的帳列(實際一個迴圈幾十筆以內)加上資安席那一筆報告算一次 sha;問閘是人手動問、推送前一次,不在熱路徑。無。
- 資源:讀檔走既有留痕重驗函式;不開連線、不拿鎖。無。
- 守衛面(這本身就是一道閘):誤擋與漏擋兩邊都要顧——誤擋:判定輪只派一席、生效日前開的迴圈、席名沒帶模型尾碼、Codex 編排;漏擋:席名亂取、`code-loop pass` 不回頭驗問閘。前者在 [S2][S3] 處理,後者寫在〈承認的限制〉附回頭條件。
- 可逆性:純程式與文件改動,revert 就退;帳本格式不變(不加欄位),舊帳不用遷移。
- 凍結判定與回放:凍結下來的判定(`verdict: {rc, fails}`,fails 是 `G3`、`留痕`、`條款綁定` 這類短標籤)會多一個可能的 `資安席`。生效日前的迴圈這一步回 skip、不進 fails,所以已凍結的舊判定回放時結果不變;這點要有測試釘住(驗收最後一條)。
- 金流(pitfalls 命中 payment):不適用——本案不碰任何金流程式;計劃裡「金流」只出現在「敏感檔案形狀」的舉例。
- 對外送出(pitfalls 命中 external-send):不適用——不對外送任何東西;資安席是本機子代理,跟其他審查席同一條路。
- 認證 / 個資 / 快取 / 遷移 / 限流 / 狀態同步:本案不碰這些程式;它們是資安席要審的對象,不是本案的改動面。

## 驗收(測試先行,每條先紅後綠)

- code 迴圈 high、生效日後、帳裡沒有資安席 → 問閘未過(退出碼 1),訊息含「資安」與下一步指令。
- 同上但有一筆 `資安-sonnet` 帳列、報告 sha 對 → 資安席這一步 ok(其餘各步照舊判)。
- 資安席帳列在,但事後報告被改(sha 不符)→ 問閘未過(退出碼 1)。
- 資安席在非判定輪(r1 有、判定輪 r2 沒有)→ 這一步 ok(迴圈層級);凍結 / 回放模式下同一份帳也 ok,且不去讀 r1 的報告檔。
- 帳上有一筆 ts 讀不動 → 這一步 fail(壞資料不放行)。
- tier standard → 不要求;設計迴圈 → 不要求;生效日前的迴圈 → 不要求且印一行說明。
- 席名 `資安`(沒帶模型尾碼)算;`資安審-sonnet`、`非資安-sonnet` 不算。
- 編制表:`loop next code-x --tier high` 印得出資安席;roster 對帳的 required 同門數多 1。
- 既有測試:roster / disposal / loop_next 相關子集全綠。
- 凍結判定回放:生效日前已凍結的代碼審迴圈,回放判定不因資安席這一步改變。
