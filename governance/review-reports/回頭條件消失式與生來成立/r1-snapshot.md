# 回頭條件消失式與生來成立_計劃

白話:回頭條件的條件鍵(`when-file`、`when-symbol`、`when-test`、`when-status`)全是「等某樣東西出現」,沒辦法寫「等某支檔或某段程式不再出現就回頭」。另一件事:一條條件式回頭條件如果寫下的當下條件就已經成立,它從來沒提醒過任何人;推送時新寫的已經會被擋,但這道檢查上線以前寫的舊行,`lumos drift scan` 只說「條件已經成立」,有人表態照留之後就再也看不出它是「生來就成立」。這份計劃補兩件事:①新的條件鍵 `when-gone`;②scan 對現在成立的條件往回查寫下那一版,標出「寫下時就已成立」,表態過的也照標。

這是消費專案 2026-10-02 清漂移回傳「回頭條件四項」裡的另兩項(第 6、11 項);第 4、7 項在 [[Projects/回頭條件寫法補齊_計劃]]。

依據:
- 消費專案清漂移回傳(2026-10-02,第 6 項,去識別):「等某支檔不再直接讀系統時間就回頭」——when-file、when-symbol、when-test 只能等東西出現。建議 `[when-gone:路徑::樣式]`。
- 同一份回傳第 11 項:drift probe 只說「現在成立」,而且表態後就靜音,看不出它生來就成立、從沒提醒過任何人(四條);建議提交當下就檢查新寫的條件。
- 2026-10-03 乾淨查證員核對現況(唯讀,[[Projects/回頭條件寫法補齊_計劃]] 依據同一次):條件鍵只有四個、全是正向判定;推送時已經會擋「這次新寫(或改了條件)的回頭條件,條件已經成立」(既有測試 `t_drift_when_probes_evaluate_and_trigger` ⑨);提交時只驗寫法、不評估;scan 只看現在成不成立、不看歷史;表態後 scan 標「已表態」、推送不再擋。
- 條件文法、評估與推送判定在 [[Projects/存量漂移防線_計劃]]〈做法〉第 0、2 節;家在 [[Systems/存量漂移守衛]]。

PRIOR-ART: 最小解在工具這一層(條件評估本來就在 lumos 的推送判定與 scan 裡)。世界上最接近「等東西消失」的是 feature flag 平台的清理提醒(旗標在程式碼裡已經沒有引用就提示移除)與 Ruby todo_or_die 的條件式到期;都是「某個符號或文字不在了就觸發」,本案照這個形狀,只認明寫的路徑與字面字串,不做樣式或正則(條件要讀得懂、判得穩)。「寫下時就已成立」借 `git log -S`(找某段文字第一次出現的提交)這種既有的考古做法,不另建索引;本 repo 的 `drift exam` 已經在歷史上重放條件,判定沿用同一支 `_drift_probe_line`。不做:提交時就評估條件(推送時已經擋新寫的已成立條件,提交時再評估要每次提交建樹,成本不划算;寫進天花板)。
RETIRE-IF: 上線兩個月後任一成立就撤掉或改規則:①`when-gone` 兩個月零使用(數圖譜裡 `[when-gone:` 出現幾次),拿掉這個鍵;②scan 的「寫下時就已成立」標記在工具鏈與消費專案各跑一次都是 0 筆,而且兩個月內沒有新的舊行被標,拿掉往回查那一段(只剩成本)。
REVISIT:2026-12-03 數兩邊圖譜 `[when-gone:` 幾處、跑 `lumos drift scan` 數「寫下時就已成立」幾筆,照 RETIRE-IF 判

## 範圍

- **做**:第 6 項(條件鍵 `when-gone`)、第 11 項(scan 標出寫下時就已成立)。
- **不做**:提交時就評估新寫的條件——推送時已經擋(既有),提交時要多建一次樹;寫進天花板。
- **不做**:樣式、正則、萬用字元的消失條件——只認路徑與字面字串。

## 做法

### 1. 條件鍵 `when-gone`(第 6 項)

1. **寫法**:`[when-gone:<路徑>]`——那支檔不在樹上就成立;`[when-gone:<路徑>::<字串>]`——那支檔不在、或檔裡不再出現這段字(照字面、分大小寫、整檔比對,含註解)就成立。路徑的規矩同 `when-file`(不准 `/` 開頭、不准 `..` 段);`::` 從**第一個**切(字串裡可以有 `::`,路徑裡不會有)——既有的 `_drift_cond_split` 與 `_probe_norm_value` 對 symbol/test 是從**最後一個**切,所以 `when-gone` 另用一支 `_drift_gone_split`(判定、預讀、點名讀不出的檔、候選篩選、正規化共用它),`_probe_norm_value` 多一個 `gone` 分支呼叫它;字串去頭尾空白後不能是空的,不能含 `]` 與換行(既有標記的切法)。沒有不帶路徑的寫法——「整個 repo 都不再出現某段字」要掃全樹,判不穩也太貴。
   例:`REVISIT:[when-gone:src/instrumented.py::time.time()][by:2027-01-31] 不再直接讀系統時間了,把註解裡的警告拿掉`。
2. **評估**:`_DriftProbeTree.one` 多一個分支:路徑不在樹上 → 成立;帶字串時讀那支檔(既有的 `_read`,讀不出回判不了),字串不在全文裡 → 成立。`_drift_probe_one`、`_drift_probe_line` 不動(新鍵走同一支)。預讀(`prefetch`)與「判不了時點名讀不出的檔」(`unread_for`、`_drift_row_unread`)把帶字串的 `when-gone` 當成帶路徑的 symbol 一樣處理,路徑用 `_drift_gone_split` 取。
3. **推送判定的候選**:`_drift_probe_cond_candidate` 對 `when-gone` 看路徑(`_drift_gone_split` 取)在不在這次推送改到的檔裡(同帶路徑的 symbol);其餘轉變判定(終點成立、起點沒有同一條或還不成立才處理)照舊。寫下時就已成立的(例如字串拼錯、檔名寫錯——永遠不會再出現),推送時照既有規矩被點名「這次新寫(或改了條件)的回頭條件,條件已經成立」;這是 `when-gone` 寫錯時的保險,跟正向條件鍵寫錯靠期限 `[by:]` 不同。
4. **文法與說明**:`_PROBE_KEYS` 加 `gone`;`_probe_value_err` 的「只有 file、symbol、test、status」改成列出五個;值驗證走一支新的 `_probe_gone_err`。RULE 的撤除條件 `[retire:when-gone:…]` 走同一支解析(`_retire_lines` 改寫成回頭條件標記再交給 `_probe_parse`),自動支援,不另寫。技能手冊 `skills/lumos-project-notes/commands/03-寫回圖譜.md` 四種鍵那句補第五種;筆記形狀擋否定現況句提醒裡「條件怎麼選」那段補一句「等東西消失用 `[when-gone:路徑::字串]`」。

### 2. 寫下時就已成立(第 11 項)

1. **scan 往回查**:`lumos drift scan` 對每一條「條件已經成立」的回頭條件(含已表態的;RULE 撤除條件不查,它們的「寫下就成立」由提交時擋寫法、推送時擋轉變),用 `git log --format=%H --reverse -S<那一行原文> -- <筆記路徑>` 找第一次出現這一行的提交(只看這一篇的歷史;筆記改過名就在改名後的第一個提交找到,天花板 2),在那個提交的樹與圖譜上用同一支 `_drift_probe_line` 判一次。成立 → 這條發現多一個標記「寫下時就已成立(提交 <短碼>),從沒提醒過」;不成立 → 不標;找不到提交、git 失敗、超過預算 → 標「判不了寫下時成不成立」。
2. **預算**:往回查吃 scan 既有的時間預算(`--budget`,預設照舊),排在本來的評估之後;同一個提交的樹只建一次(多條同一提交寫下的共用)。scan 不是閘,判不了不擋。
3. **呈現**:文字輸出那一行後面加標記;`--json` 的發現多一個欄位 `born`:`{"commit": 短碼}`、`"unknown"` 或沒有這欄。已表態的照樣標(這就是第 11 項要的:表態不該把「從沒提醒過」藏起來)。doctor Z 段不評估條件,不動。
4. **推送判定不改**:新寫的已成立條件推送時本來就擋;本案只補 scan 看存量。

## 實務隱患

- **繞過**:`when-gone` 寫一個本來就不存在的字串,推送時被點名「已經成立」——作者可以表態照留繞過;這是明寫的動作、留在表態檔,不另擋。
- **效能**:`when-gone` 帶字串時讀一支檔(同帶路徑的 symbol,有預讀);scan 往回查每條成立的條件一次 `git log -S`(在單一筆記路徑上,O(那篇的歷史))加每個不同提交建一次樹;成立的條件通常是個位數,吃 scan 既有預算,超過就標判不了。推送判定的成本不變。
- **併發**:只讀 git 物件;scan 不寫帳。
- **回滾**:還原本案的提交:`when-gone` 變成「不認得的條件鍵」——新寫的提交時被擋、已寫的 scan 列成寫錯的條件、推送判定不評估(既有對寫錯條件的處理);scan 不再標寫下時成立。沒有資料要收。
- **相容**:新鍵只是多認一種寫法,既有四種鍵的判定不變;`--json` 多一個可省略欄位,讀的人沒有靠它。消費專案要 `lumos update` 之後才認得 `when-gone`,更新前寫了會被舊版擋成「不認得的條件鍵」。
- **跨環境**:`git log -S` 在淺層 clone 看不到全部歷史——找到的「第一次出現」可能是淺層邊界,標成判不了寫下時成不成立(淺層時不往回查);本機與 CI 同一支判定。
- 已排除:金流:只讀筆記與 git 物件
- 已排除:對外送出:不呼叫網路
- 已排除:不可逆:只決定擋不擋、列不列,還原提交就回去
- **守衛面**:推送判定(會擋的閘)多認一種條件鍵——判錯會讓該擋的不擋或不該擋的擋;用既有的轉變判定與測試守,不新增擋的種類。

## 驗收條款

- [S1] 當 `[when-gone:src/a.py]` 指的檔在樹上,應 不成立;檔被刪掉 應 成立;`[when-gone:src/a.py::time.time()]` 檔裡還有這段字 應 不成立、拿掉這段字或刪掉檔 應 成立;帶字串而檔讀不出 應 判不了 [test:t_drift_when_gone_evaluates]
- [S2] 當這次推送刪掉 `[when-gone:…]` 指的那段字,推送判定 應 點名「這次推送讓條件成立了」;推送沒動那支檔 應 不列;新寫一條 `[when-gone:…]` 而字串本來就不在檔裡 應 點名「這次新寫(或改了條件)的回頭條件,條件已經成立」 [test:t_drift_when_gone_push]
- [S3] 當 `when-gone` 的路徑以 `/` 開頭、含 `..`、字串是空的,提交時 應 報「條件寫錯」;字串裡含 `::`(`[when-gone:src/a.py::Foo::bar]`) 應 從第一個切、字串是 `Foo::bar`;寫法合格 應 不擋;不認得的鍵的錯誤訊息 應 列出五個鍵 [test:t_drift_when_gone_grammar]
- [S4] 當 RULE 的撤除條件寫 `[retire:when-gone:src/a.py]`,推送刪掉那支檔 應 點名撤除條件成立 [test:t_drift_when_gone_retire]
- [S5] 當一條條件式回頭條件寫下時條件就已成立(歷史上那個提交裡它指的檔已經在),`drift scan` 應 在那條發現後面標「寫下時就已成立(提交 <短碼>)」,`--json` 應 帶 `born.commit`;寫下時還不成立、後來才成立的 應 不標;已表態的 應 照標 [test:t_drift_scan_born_true]
- [S6] 當往回查找不到提交或超過預算,scan 應 標「判不了寫下時成不成立」、`--json` 的 `born` 應 是 `"unknown"`,不改變這條發現本身 [test:t_drift_scan_born_true]

## 回退

還原本案的單一功能提交(〈實務隱患〉回滾)。設定與帳本格式沒變;scan 的 `--json` 少一個可省略欄位。

## 天花板

1. 提交時不評估條件:新寫的已成立條件要到推送才被點名。
2. 往回查只看這一篇筆記自己的歷史:筆記改過名,找到的是改名後第一次出現的提交,寫下當時的狀態可能看不到(會標成那個提交時的判定)。
3. `when-gone` 只認字面字串:改寫成同義寫法(`time.time()` 換成 `from time import time` 再 `time()`)也算「不再出現」,條件會提早成立——作者挑字串時要挑會真的消失的那段。
4. 淺層 clone 不往回查。
