- **finding 1 (blocker)**: 局部變數覆寫無法保證品質閘生效。
  - 引句：「落點=scripts/lumos impact ranked 融合塊(`query = (_payload.get("query") or "")` 之後、lex 計算之前)加 _impact_query_junk(query) 判準」
  - 具體失敗場景：Spec 僅提到對局部變數 `query` 重新賦值（`query = ""`），但未指明更新原始字典 `_payload`。若後續 `lex` 計算、`hop1` 或其他組件實作是直接從 `_payload` 取值（如 `compute_lex(_payload)`），則品質閘將被完全繞過，垃圾文本仍會進入排序路徑，導致「L 臂靜默」的目標失敗。

- **finding 2 (major)**: 「去空白」語意定義矛盾。
  - 引句：「delta 文本為垃圾(首非空字元 #! 或去空白後 <20 字)→ 視同空查詢(L 臂靜默)」
  - 引句：「S1 判準函式 _impact_query_junk(query: str) -> bool:★MINLEN=0 → 直接 return False...否則 q = query.strip(),q.startswith("#!") 或 len(q) < MINLEN(預設 20) → True」
  - 具體失敗場景：Summary 要求「去空白」（通常指移除所有 whitespace），但 S1 實作採用 `strip()`（僅移除首尾空白）。若輸入為內容極稀疏但帶有大量中間空格的垃圾文本（例如 `"A" + " "*20 + "B"`），`strip()` 後長度仍大於 20，將導致品質閘無法按預期攔截低資訊量之雜訊。

- **finding 3 (minor)**: 觀測指標對原始空查詢產生污染。
  - 引句：「JSON 輸出加 query_gated: true 觀測欄(僅觸發時)；人讀輸出加一行 stderr 註記」
  - 引句：「S1 判準函式 ... len(q) < MINLEN(預設 20) → True。空字串本就走空查詢路徑,判 True 無害(冪等)」
  - 具體失敗場景：當原始輸入 `query` 本即為空字串 `""` 時，因 `len("") < 20`，判準函式會回傳 `True` 並強制標記 `query_gated: true`。這將導致「正常空查詢」與「被攔截的垃圾查詢」在遙測統計中無法區分，違反「僅觸發時」才標記的觀測原則。
