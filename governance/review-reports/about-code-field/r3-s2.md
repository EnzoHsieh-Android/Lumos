# r3 審稿 s2——「只加分不降級」翻轉後的全文一致性

鏡頭:r2 把核心規則從「有 about 欄但不含目標檔→降自由席」翻成「只加分、不降級」。
逐段核對前提(還是不是「會降級/會剔除」)與結論(現在的機制實際做什麼)對不對得上,
並用 `scripts/lumos`(cmd_impact,約 14020-14135 行)與
`governance/eval/retrieval_eval.py` 的實際邏輯核對 spec 的推論。

---

## s2f1 — blocker:「噪音剔除改由巨檔門檻與扇出承擔」,但兩個承擔者現在都不剔除任何噪音

spec 把「精確度來源」從 r1 的「剔除」改口成「排序」後,補了一句交代噪音誰管:

引句:「噪音剔除這件事,改由巨檔門檻與扇出(A 層過渡)承擔,about_code 不碰召回」

查證兩個承擔者:

1. **扇出(A 層)沒有上線**——spec 自己在 A 層那節寫:

引句:「本節點只承載診斷與離線實驗,不動產線 code」

也就是說「扇出承擔噪音剔除」目前是空話,A 層連 design-loop 都還沒過。

2. **巨檔門檻不剔除既有噪音**——用 `cmd_impact` 的邏輯核對(scripts/lumos:14047-14049):
`pinned = bool(x.get("contract"))`(direct+合約無條件保送)與 indirect+合約+hop≤1 無條件保送,
這兩條路徑跟 about_code 完全無關。spec 自己寫的 22 個誤放正是這個機制的產物:

引句:「held 撞到失效條件——改 scripts/lumos(巨型單檔)那題 22 個誤放」

這 22 篇是三軸保送進來的,不是 about_code 放進去的;巨檔門檻「關閉 about 判定」關掉的只是
about_code 這個新訊號的加分/promote 動作,三軸該保送的照樣保送——22 個誤放不會因為門檻開關而增減一個。

**結論**:精確度來源那句話交代的兩個「承擔者」,一個未上線、一個機制上管不到既有噪音。
spec 沒有誠實寫出「現在其實沒人剔除固定席既有噪音,about_code 只是把命中的排到前面」這句話——
這正是題目問的「有沒有誠實說」,答案是沒有。

## s2f2 — major:「三條線的關係」表格是 r1 遺留,沒有跟上 r2 的翻轉

表格(全文未被 r2/r3 diff 動過,只後面一行「61→83 篇」被改):

引句:「語意層——唯一能突破字串的」
引句:「字串層,最多降一半噪音」

但「讀側怎麼用」那節自己承認 C 現在的效果:

引句:「對 P@8 無影響(P@8 不計固定席)」

查證 P@8 口徑:`governance/eval/retrieval_eval.py:305-308` 的 docstring 明寫
「P@top_k/nDCG@top_k(非固定席);固定席另計(安全機保,不算噪音)」,`gates` 字典
(main() 約 570-576 行)只有 `hook P@top_k`、`fusion`、`非固定中位/p95`、`must-see 棘輪`,
沒有任何 gate 讀 `pin_noise`。也就是說:**唯一被 gate 卡的精確度指標,C 完全碰不到**;
能移動這個指標的只有 A(扇出降權實驗量出「P@8 漲五格」)。

那麼標題「固定席扇出降權」要解的問題(固定席噪音多、拖累可信度)現在只有 A/B 在解,
C 解的是另一個問題(固定席內顯示順序)。表格仍然把 C 標成「主案」、天花板「唯一能突破字串的」,
A/B 標「過渡」——這個位階描述是 r1 demote 版的遺產,沒有隨規則翻轉重寫。

## s2f3 — major:「成績單看固定席噪音數」沒有交代 only-add 下這個數字該往哪走

引句:「about_code 是精確度工具,成績看固定席噪音數」

這句在 r2/r3 都保留,但「只加分不降級」的機制決定了它的意義已經變了:about_code 只會把
**額外**節點(依三軸判定原本不保送、about 命中後被前排/或既有 pin 被重排)推進固定席前排,
不會把任何節點移出固定席。若某個被 about 命中而促進前排的節點其實是噪音(label=0),
`pin_noise`(`retrieval_eval.py:348` `sum(1 for x in pins if lab.get(...)==0)`)只可能持平或**變大**,
不可能因為 about_code 而變小——因為它不剔除。

spec 沒有寫清楚「這個數字上線後預期不降、只求不升」,還是保留 r1「噪音數是成績單」的原始語氣
(暗示這個數字會被 about_code 拉低)。跟 s2f1 的缺口是同一個病灶:精確度來源已經不是剔除,
但敘述噪音數字時仍用「成績單」這種帶「進步/退步」意味的詞,沒有把「這個機制理論上不該讓噪音數字下降」講出來。

## s2f4 — major:巨檔門檻保留 r1 demote 語言的理由,沒有換成 only-add 下的真正理由

引句:「該檔視為巨檔,對它**關閉 about 判定、退回三軸既有路徑**」
引句:「理由:命中 ≥8 篇時 about 已無鑑別力」

「鑑別力」是 r1 demote 框架下的詞——demote 需要 about_code 能把「真的關於」跟「不關於」的節點分開,
命中太多篇時分不開,所以關掉判定。但 only-add 下 about_code 不做分辨/剔除,它唯一的動作是
「命中就推前排」。命中 ≥8 篇時它不是「沒有鑑別力」,而是「會把很多節點一次推進固定席前排」——
真正該擔心的是**固定席膨脹**(巨檔一次可能把 8+ 篇正確但邊際的 about 命中節點全部拉成前排),
不是分不清誰噪音誰不噪音。門檻本身在 only-add 下可能仍有價值(擋住巨檔造成的一次性大量前排/新增
pin),但 spec 寫的**理由**沒有跟著機制翻轉重寫,還在用「鑑別力」這個只在 demote 模型下才有意義的詞,
而且緊接著引用的「22 個誤放」案例(見 s2f1)跟 about_code 開不開關無關——這段論證整段是 r1 demote
時期的產物,r2/r3 只改了規則本身,沒有回頭改支撐這條規則的理由。

## s2f5 — minor(修正題目本身的推測,非 spec 缺口,但值得記錄):「擠掉自由席」在目前實作下不成立,真正的缺口是「固定席總數無上限且無 gate」

題目懷疑「about 命中把新節點拉進固定席,會不會擠掉自由席的東西,棘輪因此不再是後照鏡」。
查 `cmd_impact`(scripts/lumos:14071-14086):

```
pins = [r for r in results if r["pinned"]]
free = [r for r in results if not r["pinned"]]
...
_quota = int(_impact_knob("LUMOS_IMPACT_FREE_QUOTA", 10))
free = free[:min(int(top), _quota)]
final = pins + free + rescued
```

`free` 的名額(`min(top, quota)`)跟 `pins` 的數量無關——`pins` 本身「不受名額限制」(spec 自己在
扇出降權那節也這樣描述現況)。一個候選被 about 命中推進 `pins`,只是把它從「跟別人搶 free 名額」
的池子裡拿掉,**不會**吃掉 free 的配額,所以「擠掉自由席、召回真的變差」這條因果鏈在現有程式碼下
不成立——must-see 棘輪確實仍是後照鏡(它量的是 free 池的排序結果,而 pins 的膨脹不影響 free 池容量)。

但這不代表沒有缺口:**固定席總數本身會變大且沒有任何 gate 盯著**。`pin_noise` 只印不閘
(spec 自己也寫了「固定席噪音目前只印不閘」),而 pins 的筆數上限是無限的——巨檔一次推進 8 篇、
10 篇都不會被擋。「零退化」那節只承諾「無 about 欄節點的 pinned 判定不變」與「P@8 不受影響」,
沒有承諾「固定席總數不會失控膨脹」,而這件事目前確實無人守——這才是這條線真正該補的缺口,
跟題目猜的「擠掉自由席」機制不同,但同樣是「零退化」宣稱沒蓋到的角落。

## s2f6 — minor:誠實缺口節沒有收編 s2f1/s2f3/s2f4 這三個 r2 翻轉遺留的缺口

「誠實缺口」節逐條核對過(s3f4 同源循環、s3f5 distinct 樣本數、s1f1 分母口徑、s2f5 hook 顯示層
basename-match 沒收 about),這些都跟上了 r2/r3 的改動。但 s2f1(噪音剔除實際上沒人做)、

## 已核,一致

- **must-see 棘輪是後照鏡的定位**:引句「棘輪只當事後覆核」與 `must_ratchet()` 的實作(只在
  `retrieval_eval.py` main() 的離線 gate 流程裡跑,不在 `scripts/lumos` 熱路徑或 hook 裡)一致——
  它確實只在跑考卷時量,線上 hook 那一刻不會被它擋。r2 前後對棘輪角色的描述(從「安全帶」改「後照鏡」)
  跟程式碼行為對得上,不是自我矛盾。
- **「零退化」宣稱的精確範圍**(s2f4 舊引用,r2 已改寫成「只保證無 about 欄節點的 pinned 判定不變」)
  跟 s2f5 查證的 free/pins 配額分離機制一致——這句話劃的線本身沒錯,只是沒延伸覆蓋 s2f5 指出的
  「pins 總數可能膨脹」這個相鄰角落(見 s2f5,非矛盾,是覆蓋不足)。
- **stamp 格式、回滾子命令、`updated`→git 日期** 三處 r2 改動(diff 中段)彼此之間、跟後文
  「存量與增量」表格、跟「過期守衛」節的敘述前後一致,沒有發現殘留舊版措辭。
