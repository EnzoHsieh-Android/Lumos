## 依根因分組

1. 整行規則借舊債(C1、U1):只扣照片段比的規則(行號引用、釘版本),整行層級的規則一律不扣——「現況描述沒寫來源」、「SEE 只放連結」、「條件寫在不評估的地方」是同一族,收成一條規則,不逐條比規則名(`_ns_append_subtract`)。
2. 測試假綠(G1、G5):r1 改成「沒寫來源永遠不扣」之後,用沒帶來源的括號當探針的配對測試配不配都會紅,等於沒測;全部改用「舊行就有的行號引用+帶來源的括號」,每支補前置斷言(同一個專案正常補括號不擋、改一個字照報);牆上時鐘門檻改成數呼叫次數與相對倍數。
3. 上限靜默(U2、B2、K3):超過總量上限回 `"cap"`、第一次查表印一句提醒、推送記 state capped 的放寬帳;另加起點加終點的位元組總和上限 32 MiB。
4. 同名撞鍵在更早一層(B1、S1):新行抽取與開頭欄位淨差異表也用 NFC 當鍵,兩種寫法並存時另一篇整篇漏查(本案之前就有);被檢查版本裡同名並存又有新行時兩層都直接擋。折入時發現以 NFC 為鍵的檔案清單已經把兩種寫法併成一筆、數不到並存,改用不去重的路徑清單(macOS 暫存區實測,測試 ④ 是前置斷言)。
5. 同一次推送去重(Z1、U3、K1、K2):拿掉 git 目錄裡的記號檔,改讀治理帳裡同一個推送編號已經記過的行(專案既有做法);記號檔的壞內容(K1)與非原子讀改寫(K2)隨之消失;範圍不同但重疊時也不重記(U3)。
6. 申訴範圍(C2、S2):整行申訴換掉每一種範圍,只判句尾的申訴只換同一個句尾(`_note_audit_dispute_for`)。
7. 顯示用語(B3):帶句尾、但只有別的句尾判過的項目印「判過的是別的句尾」。
8. 旗標與口徑(Z2、Z3):讀被刪摘要行的那支補上 `--inter-hunk-context=0` 與 `--diff-algorithm=myers`,跟 `_ns_diff` 一致;第二層配對失敗只印不記帳,寫明理由(每個入口都會走到、會一次失敗記好幾筆;推送時由第一層的放寬帳記)。
9. 筆記與計劃(G2、G3、G4):Systems/筆記內容審 的 WHY 改成 skip 跟 check 同一個算法;否定現況句計劃兩處改成「量測程式會多算、抽樣時人工剔除」;筆記內容審計劃表格補補括號組一列、寫明第 2 版範本在推出前改過用字不算改版。
