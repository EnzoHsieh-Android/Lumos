## 背景(作者的說法,當可反駁的宣稱)
`lumos code-loop pass` 會把「這批審過了」留痕,綁當下的 commit sha。留痕之後只准再提交「帳本檔」(治理帳、審查帳、簽名檔那一類),提交別的東西會讓留痕失效、推送被擋。

2026-09-21 作者同一天漏掉兩次:每次跑 `anchor approve` 都會弄髒 `governance/anchor-baseline.json`,而他提交帳本時手打路徑清單、兩次都漏掉它,推送被「簽名檔改過了但沒提交」擋下(那道閘擋的是「本機綠但 CI 會紅」)。

這批的修法:`code-loop pass|skip` 收尾時多印一段,把「還沒提交的帳本檔」列成一行可直接貼的 `git commit ... -- <檔案>`。不是新的閘,不擋任何東西。清單沿用既有的 `_BOOKKEEPING_FILES` 白名單。

作者自述踩過一次:第一版把 `_BOOKKEEPING_DIRS`(審查卷證、回放判定那幾個目錄)也算進去,在真 repo 上列出 126 個檔,裡面全是別的 session 的卷證——照貼等於提交別人的東西。所以縮成只列 `_BOOKKEEPING_FILES`。
