severity: minor

整體判斷:修法本身在宣稱的時序性質上成立。我發現兩條 minor,沒有 major 或 blocker。

**F1(新加的時鐘檢查丟例外時,會把新建的用量帳弄壞)**
severity: minor
blocking: 否
引句:「raise ProbeAttemptLedgerError("用量帳時鐘不可判")」
- 輸入:帳檔還不存在,呼叫端沒傳 now,而 `time.time()` 回 NaN 或負數(例如時鐘壞到 1970 年以前)。
- 路徑:`sqlite3.connect` 先建出 0 位元組的檔,再 `BEGIN IMMEDIATE`,然後才讀時鐘並丟例外。`finally` 只 rollback 並關連線,留下的 0 位元組檔不會被清掉。
- 後果:時鐘修好後再呼叫,`fresh` 變成 False、`user_version` 是 0,在 `elif version != 1` 丟「用量帳版本或結構不可判」。帳永遠卡死,要手動刪檔。
- 改前這個檢查在 `connect` 之前,不會留殘檔,所以這是這次改動新增的路徑。
- 重現:我複製 `scenario_probe.py`,mock `time.time` 回 NaN。第一次呼叫丟「時鐘不可判」,檔存在且大小 0;第二次(時鐘恢復)丟「版本或結構不可判」。
- 觸發條件極少(時鐘早於 1970 年),所以只標 minor。
- 這點跟「`now` 為非數字或負數」的邊界題有關:呼叫端傳入的壞值在鎖之前就被擋了,不會碰到這條。

**F2(拿鎖後的時鐘檢查沒有測試守著)**
severity: minor
blocking: 否
引句:「if not math.isfinite(now) or now < 0:」
- 我把拿鎖後的 `isfinite` / `now<0` 檢查整段刪掉,新測試和其餘測試仍全綠,測試沒覆蓋這條新增的分支。
- 它擋的是「`time.time()` 回 NaN 或負數」,不是修補宣稱要擋的競態,所以只標 minor。
- 我另外把修法還原(改回先讀時鐘再上鎖),新測試會紅(丟 `ProbeAttemptLedgerError`)。所以新測試確實能重現原本的失敗。

### 逐項檢查結果
- **邊界**
  - 帳檔不存在、`limit=0`(提早回傳)、`now` 為非數字或負數,這段都扛得住。
  - 傳了 `now` 的路徑行為不變,仍在鎖前驗證。
  - 18000 秒邊界的算式沒動。
  - 新建帳時 `initialized_at` 用的是拿鎖後讀到的 now,與後面比較用的是同一個值,一致。
- **資源**
  - 新的例外在 `BEGIN IMMEDIATE` 之後丟出,`finally` 會 rollback 並 close,連線不會漏。
  - 殘檔問題見 F1。
- **例外與冪等**
  - 例外一律包成 `ProbeAttemptLedgerError`。
  - 沒有新的 None 回傳路徑。
  - 同一操作重跑,結果只取決於帳內容。
- **新舊互讀**
  - 帳的格式沒動,新舊版本互讀不受影響。
- **寫一半被中斷**
  - 還是單一交易,不會留下半寫的資料。
- **時鐘真的倒退**
  - 測試最後一段傳 `now=t0` 要求丟例外,證明回撥仍會停止派工。
  - 比較式 `now < max(initialized, latest)` 沒動。
- **審材範圍內無關的鏡頭**
  - `be-api-compat`:沒有對外 API 欄位變動。
  - `be-authz`:沒有新增端點。
- **鏡頭 4(時序性質)**
  - 在任何交錯下,A 先拿到鎖、B 後拿到鎖時,B 讀到的時間 ≥ A 記下的時間,理由如下。
    - A 的 `time.time()` 在 A 持鎖期間讀取,A 在 `commit` 後才放鎖。
    - B 的讀取在 B 取得鎖之後,所以真實發生順序晚於 A 的讀取。
    - 同一機器上兩個程序讀同一個牆上時鐘,所以 B 的值 ≥ A 的值。
    - 判斷式是嚴格的 `<`,相等不會誤報。
  - 鎖前沒有任何會用到時間的讀取:`lstat` 與 `mkdir` 與時間無關,`now` 只在鎖內讀。
  - 剩下的窗口只有牆上時鐘本身被 NTP 校正或手動往回調,這是真回撥,照約定該停。
  - 另有一個既有、與本次改動無關的競態:兩個程序同時新建帳時,若後到者在先到者提交前就看到 0 位元組檔,且先拿到鎖,會走到「版本或結構不可判」。我沒有重現,不列為 finding。
- **新測試**
  - 判準獨立:用 mock 讓 `connect` 時另一方先插入較晚的一筆,並把時鐘往前撥。
  - 這是在單一程序內依序模擬,沒有真的等鎖,但不影響它重現「先讀時鐘、後記帳」的失敗。
  - mock 只改 `time.time` 與 `sqlite3.connect`。`racing_connect` 內的 `real_connect` 保留了原函式,沒有擋到不該擋的呼叫。

總結:最高嚴重度 minor
