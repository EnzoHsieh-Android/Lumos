## 展開：沒修到

### 通才 F4 展開 — 「保留相對縮排」對最常見的單行片段沒有作用，對整段均勻搬動的片段也救不了

r3 [S4] 的修法：

引句:「但保留每行相對於片段第一行的縮排差」
引句:「整段重新縮排不受影響，而「同一段程式碼被移進另一個區塊」這種縮排即語意的改變仍然比得出來」

驗算兩種情況：

**情況一（單行片段，社群規則最常見的層級）**：F4 原始舉例就是「一個危險呼叫」——通常一行。單行片段裡「相對於片段第一行的縮排差」永遠是 0（自己跟自己比較），不管這一行原本縮排 8 格還是搬到縮排 4 格，正規化後的相對縮排值都是常數 0——跟直接砍掉首尾空白毫無差別。r2-新段落通才 F4 舉的「從 `if False:` 底下移進真正會執行的區塊」若只是搬一行程式碼，這條修法完全沒有改變結果，仍然會被判成同一個指紋、次數不變、放行。

**情況二（多行片段、整段均勻搬動）**：假設片段原本在深度 2（每行縮排 8 格）：
```
        x = get_value()
        run_dangerous(x)
```
兩行的「相對於片段第一行」縮排差都是 0（8-8=0）。搬進深度 1 的區塊（每行縮排 4 格，結構不變）：
```
    x = get_value()
    run_dangerous(x)
```
兩行的相對縮排差還是都是 0（4-4=0）——跟搬動前的指紋完全相同。也就是說「整段重新縮排不受影響」這句話本身沒錯，但這正是問題所在：均勻搬動一個區塊（複製貼上到別的縮排深度、內部結構不變）是「移進另一個區塊」最常見的做法，而這種搬法在這個機制下**必然**跟原地不動同一個指紋——r3 同一句話宣稱這種情況「仍然比得出來」，跟前半句「整段重新縮排不受影響」在均勻搬動的情況下是同一件事、不可能同時成立。只有片段內部各行彼此的相對縮排在搬動過程中被打亂（很少見，通常代表程式碼結構本身也變了，不是單純的區塊搬遷）才會被抓到。

severity: blocker
blocking: 是（這是 r2-新段落通才 F4 指出的同一個安全性風險——危險呼叫從死碼移進活碼——r3 沒有解決它，還多寫了一句經不起驗算的保證，會讓下一個讀者誤以為這個風險已經被機制接住）

### 通才 F7 展開 — 「保底」沒有定義數值，「沒檢查到」的結果沒有被 S9 的兩類窮盡分類收進去

r3 [S10] 新增的文字：

引句:「不要用一個必然逾時的值去跑它」
引句:「判成「沒檢查到」要留痕」

使用者要求驗算的兩點，r3 都沒有給答案：
1. **保底值怎麼定**：全文沒有任何數字、公式或「至少留 N 秒」這類下限描述，只用「保底時間」這個詞本身，實作者不知道要留多少。
2. **不夠時算擋還是算放行**：[S9] 把失敗分成清清楚楚兩類——「環境不可用」（自動放行＋自動記帳）與「真的抓到問題／檔太大」（擋＋人手動放行），並且用「兩類失敗分開處理」這種窮盡語氣宣稱只有這兩種。但「預算不夠、沒跑到的命令」既不在 S9 列出的五種環境不可用清單裡（工具沒裝、命令逾時、拉不到規則、版本代號解析不出、放行檔讀不了——這些都是「某個東西已經在跑但跑不完/拿不到」，不是「決定不跑」），也沒有被放進「擋」那一類。若按最自然的類比（跟其餘五種環境不可用一樣自動放行＋記帳）去實作，那麼原本 F7 指出的實質後果——預算被前面命令吃光時，後面完全正常的檢查在零人工介入下悄悄放行——並沒有被解決，只是不再靠「每條都真的跑到逾時」這個可觀察的現象來偽裝，變成一個更難被人發現的沉默放行路徑。

severity: blocker
blocking: 是（F7 原本的擋點是「這是設計上必然發生的塌縮」，r3 把「必然逾時」換成「保底不夠就不跑」，但沒有回答那批「不跑」的命令最後算擋還是算過——這個問題不解決，実質後果跟修之前一樣）
