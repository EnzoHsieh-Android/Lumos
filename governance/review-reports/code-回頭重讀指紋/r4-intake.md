## 根因分組與處置

同輪有 major(資1–3),accepted 必空,15 條全部折入。

- G1 推主線的核對綁在本機追蹤 ref 與遠端名字串上(資1、正1、邊1、通1):換遠端名或直接推網址就不核對(資安席實測 rc0);遠端舊值本機找不到、推到別的遠端時靜默不核對;查主線候選失敗時連功能分支也退回舊版而擋;fork 工作流(本機 main 追蹤正本)推 origin main 會誤擋且叫人 fetch 也修不好。→ 換形狀:推主線(被推的 ref 名是主線分支名,不看遠端名)時,分岔點直接用 pre-push 給的遠端舊值算(`merge-base 頂端 遠端舊值`),不用本機追蹤 ref,也就不需要祖先核對;遠端舊值全 0(新建)照舊;遠端舊值本機找不到就擋下並請先 `git fetch <遠端>`。功能分支照舊用本機主線候選,查候選失敗只影響功能分支自己的分岔點,不牽動主線核對。
- G2 git 環境讓指紋讀到假歷史或少了前後文(資2、資3):`.git/info/grafts` 在關掉 replace 後仍生效,可把分岔點偽造到藏了改動的提交;`GIT_DIFF_OPTS=-u0` 蓋掉明寫的 `-U3`,同函式內搬位置的改動指紋相同。→ 入口統一清 git 環境(四個分支逐字同一段):`GIT_NO_REPLACE_OBJECTS=1`、`GIT_GRAFT_FILE` 指向不存在的路徑(實測 grafts 不生效、也不印棄用提示)、拿掉 `GIT_DIFF_OPTS` 與 `GIT_EXTERNAL_DIFF`。攻擊測試與前置檢查自己用乾淨環境呼叫 git,在 lumos 底下跑(入口環境被繼承)也要綠。
- G3 逾時照擋之後的代價(併1、併2、併3、通2):每支改過的檔各開一次 `git diff`,約一千支檔就撞上限;只要一篇逾時,`_note_reread_own_fps` 回空集合,已算出的篇也一起判沒對照;切行一次切完、記憶體約檔案 30 倍且不看截止時間;訊息寫「重跑也一樣」但邊緣大小重跑會過。→ 一次 `git diff` 帶全部路徑、照檔切開;逾時時已算出的篇照常給認可,只有沒算出的篇照舊版判;切行改成邊切邊看截止時間、不一次建整個串列;訊息照實寫「機器忙時重推可能就會過,一直擋就是改動太大」。
- G4 文件(合1、合2、合3、資4):REVISIT 要數 CI 事件,但 CI 的帳不會留下來;入口強制設環境與推主線核對只寫在計劃與手冊,沒寫進程式的家;06 手冊說比的是追蹤 ref,程式比的是分岔點;單次跳過的帳寫在工作目錄、沒隨推送送出,可還原掉,「跳過會留帳」說得比實際強。→ REVISIT 改成到期時抽查 CI run log(寫明查法);`Systems/筆記內容審` 與 `Systems/lumos-cli-lifecycle` 各補一行 WHY;06 照 G1 新做法改寫;跳過留帳照實寫成「留在本機帳、CI 用真遠端重算時會再列出」。
- G5 純標點改動的鏈多一層(邊2):只改 `)` 時鏈取上面最近一行有字的行,比 `)` 自己那層多一層,鄰近參數行被主線改就要多重讀一次。→ 全是跳過行的改動,鏈從那一行自己的縮排往外推;測試 ⑦ 照新規則改。
