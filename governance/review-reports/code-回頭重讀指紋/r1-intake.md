## 根因分組與處置

同輪有 major(資1),accepted 必空,15 條全部折入。

- G1 位置身分被拿掉(資1、正1):新版指紋把 `@@` 行號與段落標頭都拿掉,同一段改動搬到同檔另一個前後三行相同的函式,指紋不變。→ 段落所在函式的名字(去掉參數與簽名,只留識別名)放回指紋;名字由我們自己從頂端版本的內容算,不靠 git 依屬性檔選的標頭規則(見 G3)。
- G2 準備與檢查兩邊口徑不一(正2、併3、通1):準備階段因材料截斷退回舊版、檢查階段不知道;檢查帶預算、準備不帶,慢機器上檢查會退回舊版。→ 同一篇在兩邊用同一套規則決定用哪一版,不依預算或材料長短分岔;真的算不完時檢查要講明原因,不靜默換版。
- G3 git 輸入不固定(邊1、併1、併2、架1、架2):逐檔 diff 的文字/二進位判定吃當下簽出的屬性檔;查檔案大小失敗時大小上限整個失效;取頂端檔名那次 git 沒套截止時間;截止時間夾法與 precomposeunicode 設定各多一份寫法。→ 讓 diff 不讀工作樹屬性;查大小失敗退回舊版並記原因;所有 git 呼叫都套截止時間;共用既有 helper 與常數。
- G4 文件與測試名過時(合1、合2、合3):計劃〈實作紀錄〉還寫 CHANGELOG 放 v1.3;手冊 06 沒講前後三行的例外;測試名 t_reread_fp_ff_main_uses_v1_field 與條款 S19 用舊名。
- G5 測試缺口(邊2):太大、型別變更、樹裡找不到、`[x]`/`*` 檔名、符號連結、子模組、刪檔、新增檔沒有測試,拿掉對應判斷不會紅。
- G6 紀錄偽造(資2):範圍終點在本機找不到時當成分支自己的紀錄。偽造這種紀錄跟偽造舊版紀錄效力相同,不多給權力;在計劃〈實務隱患〉寫明,並用測試釘住「偽造的紀錄最多等同舊版紀錄」。
