# code-回頭重讀指紋 r2 收貨紀錄

七席全回(正確性、併發、邊界、合約、通才、架構對齊、資安),report-normalize 都不用改、quote-check 全數錨定。共 16 條:正1、併1–2、邊1–2、合1–4、通1–3、架1–3、資1。

## 根因分組與處置

同輪有 major(正1、邊1、合1、通1、架1、資1),accepted 必空,16 條全部折入。

- G1 函式名靠關鍵字猜(正1、邊1、邊2、合1、通1、資1、通2):上一輪修補讓每段改動帶「所在函式名」,名字只認 def/class/function/func/fn 幾個關鍵字,認不到就取頂格行第一個識別字。Kotlin、Java、C、C#、TS 箭頭函式、Go 接收者、Rust impl、Python 巢狀函式與巢狀類別,兩個不同函式會拿到同一個名字,搬動改動指紋照樣不變——六席各自實測重現。頂格的賦值行也會被當成名字,主線插一行就變(通2)。同一類第二次(r1 資安席同一個洞),換形狀:不猜名字,改成放「縮排鏈的原文」——從這段改動往上,每一層縮排比它淺的最近一行(去掉頭尾空白),一路到頂格;改動本身在頂格就沒有鏈。哪個語言都一樣,`pub` 與 `adm` 的那一行原文本來就不同;頂格的賦值行不在任何改動的鏈上(除非改動縮排在它底下),主線在中間插頂格行不影響。代價:主線改了外層那一行(例如函式簽名)會多要求一次重讀,方向是多擋。
- G2 批次讀頂端繞過有上限的讀法(架1、併2):自己先比單支大小、再呼叫沒有上限的批次讀,而且沒有總量上限。→ 改用 `_nodehome_cat_blobs_capped`,帶單支與總量上限。
- G3 逾時讓 block 模式一直擋(併1、通3):準備沒有截止時間、一定算出新版;檢查有 30 秒上限,大改動下逾時退回舊版,對不上新版紀錄,每次都擋,重跑也一樣。→ 因逾時沒算出新版的那幾篇,檢查不擋、照實列出並記帳;只有真的算出指紋而對不上才擋。
- G4 同一件事寫兩份(架2、架3):段落標頭正規式多抄一份;「判定者材料會不會被截掉」的規則在兩支函式各判一次。→ 用既有的段落標頭正規式;截斷規則抽成一支兩邊共用。
- G5 文件與條款(合2、合3、合4):計劃裡講 `_patch_file_changes` 參數的現況句過時;上一輪新增的行為沒有對應條款;耗時基準是修補前量的。→ 改句、補條款並綁測試、重量基準並改回頭條件的門檻。
