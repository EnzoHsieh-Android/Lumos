**What holds:**
- **Pending marker.** It is written before the log file is opened and before `subprocess.run`. It is removed only after the result passes every check:
  引句:「pending.unlink()」
  If the parent is killed, `.pending` stays on disk.
  - The next batch's `collect_skills_health` flags it (`fatal: True`), so nothing is dispatched.
  - `load_results` skips the same-stem `.json`, so a result the orphaned child writes later can't fill in missing runs.
  - The lock doesn't pass to the orphan. Documented behaviour: fds from `os.open` are non-inheritable by default (PEP 446), and `subprocess.run` defaults to `close_fds=True`. So the next batch can take the lock, but the pending check stops it.
  - A duplicate run only happens if someone removes the marker while the child is still running. Plan line 129 forbids that.
- **Result format.** I checked live probe rows for `passed`, `n_calls`, `calls`, `answer`, `limit_hit` and `answer_content_ok`. All have the types the new check requires: `grade` returns a real bool or None, and `judge` returns a bool. So a normal run isn't rejected by mistake.
- **Exact-id selection.** `a` no longer pulls in `a-extra`. `run_job` also rejects any row whose id isn't `qid`, and any file with more than `n` rows.

finding V1: a question id starting with `-` permanently blocks the batch (S12 doesn't check for it)
severity: minor
blocking: 否
引句:「"--exact-id", qid, "--runs", str(n)」
file: `governance/eval/ablation_lumos_first.py:227`

`load_ids` only rejects empty ids, commas and control characters. For an id like `-x`, argparse sees `--exact-id -x`, treats `-x` as an option, and exits with "expected one argument" (rc 2). The argparse docs' "Arguments containing -" section says option-like strings are taken as options unless they look like negative numbers; applying that to an option's value is my inference. With rc 2 and no output file, `run_job` takes the failure path and keeps `.pending`, so the directory stays poisoned until someone clears it by hand. This fails closed, so there's no false green. Fix: pass `f"--exact-id={qid}"`, or reject a leading `-` in `load_ids`.
