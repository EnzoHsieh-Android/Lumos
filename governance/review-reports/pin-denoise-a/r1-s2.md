## 查證附錄(先把邊界釘死,後面 finding 都靠這幾條)

- **合約值域**(`_impact_contract`,`scripts/lumos:13872-13907`):實際只會回傳 5 種值之一——`None` / `"INVARIANT"` / `"IRREVERSIBLE"` / `"RISK·<X>"`(X ∈ `_RISK_ENUM = {"金流","對外送出","不可逆","守衛面"}`,`scripts/lumos:2738`,由 `risk/` 標籤 lint 鎖死)。優先序 IRREVERSIBLE > INVARIANT > RISK·* > None(`combo` 是獨立布林,不入此列舉)。
- **「RISK 類」怎麼判**:不是靠字首字串比對,是靠**列舉排除**——`_impact_contract` 只有在 `contract is None`(即沒有 INVARIANT/IRREVERSIBLE 命中)才會落到 `risk/` 標籤分支(`scripts/lumos:13901-13905`)。spec 寫的 `contract in (INVARIANT, IRREVERSIBLE)` 字面比對可以正確排除全部 4 種 `RISK·*` 值(字串不同,無誤觸風險),**但 spec 全文沒有一句話講清楚「RISK 類」在 code 裡實際長什麼樣**(見 f2)。
- **間接保送現在的字面條件**(`scripts/lumos:14458-14468`):`if contract and hop <= min(eff_depth, _pin_hop):`,`_pin_hop = LUMOS_IMPACT_PIN_HOP` 預設 **1**。也就是說現行「任何合約保送」規則實際上只吃得到 `hop==1`(hop≥2 的合約節點從未進過這條分支,直接落到 `hop>=2 需 L>0` 那道獨立閘)。

- **自由席門檻/名額**(`scripts/lumos:14484-14497`):`thresh = max(min_score, LUMOS_IMPACT_DYN_COEF(0.65) * max_free)`;`_quota = LUMOS_IMPACT_FREE_QUOTA` 預設 **10**;`free = free[:min(int(top), _quota)]`。

- **about 過期判準**(`about_code_expired`,`scripts/lumos:7736-7740`):`sh is None or nh is None or nh != sh`——**沒有 `about_code_stamp` 第三段(雜湊)一律視為過期**,不是「只有改過正文才過期」。
