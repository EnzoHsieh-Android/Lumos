# code-標註防污染 r1 收貨留痕(2026-09-15)

## 這一輪最值得記的:五席獨立撞到同一條,用五種方法

編排者在註解裡宣稱洗牌種子「綁題庫身分、不同題庫不會洗成同一種排法」。**那是假宣稱**——實際綁的是分組用的版本常數(值 `lumos-retr-v1`),兩份不同題庫會洗出同一種排法。

五席各自用不同方法證明同一件事,沒有互相看過對方的報告:

| 席 | 怎麼證的 |
|---|---|
| 外家(codex) | 讀碼看出種子來源是共用常數 |
| 架構對齊 | 比對同目錄既有前例(建題庫那支),指出這是第二種做法 |
| 邊界輸入 | 造兩份合成題庫(不同查詢、不同提交編號、同 split_salt)實測洗出★逐位元相同★的順序 |
| 正確性 | 拿真實常數值跑對照,十個共用候選逐位元相同 |
| 資安 | 在隔離 clone 上替換整個提交編號欄位,★49 個真實案例輸出不變★,證明備援欄位是死碼 |

**這種一致性比任何單席的判斷都有力**,而且證明編排者的自我宣稱不可靠——那句註解是編排者自己寫的,五席全部推翻。

## 17 條發現,全折,零放行

分三類:

**一、編排者新寫的東西自己帶的(6 條)**
- 種子綁錯欄位(五席獨立命中)→ 改成照既有前例 `Random(sha256(鍵+固定鹽))`,鍵裡帶題庫內容指紋,同時滿足「形狀對齊既有」與「跨題庫隔離」
- 題目卷會把編輯題「改動片段」裡的節點路徑原樣印出 → 輸出端加遮罩。★現況題庫零命中是運氣不是守衛★:那欄位是原封不動抄來的程式片段,而這 repo 註解到處寫節點路徑
- 題目卷遇到缺欄位整支炸 → 改成安全預設(同檔 delta 本來就是這樣做)
- 排序前沒有型別防護 → 改成印 ERROR 回 rc2(本檔慣例)
- 翻紅釘條號憑推想寫錯(實測是第 1、4 條,寫成 1、2)→ 改成實測值。★同一批工作第三次犯★

**二、編排者引入第二種做法(3 條,架構對齊席)**
- 洗牌自己拼種子字串,不走既有前例
- 測試重寫模組載入樣板,不用檔案裡既有的共用輔助(被 15+ 支測試用)
- 測試自造參數物件,不用檔案既有的慣例

**三、既有的洞,這次一併補(2 條)**
