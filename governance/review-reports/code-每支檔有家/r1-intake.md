## 判讀

- code 迴圈:輪內有 blocker 與 major,accepted 必須是空的——十五條全折,refuted 無。
- F1 觀察與判準分開驗:觀察對(會擋)。「不該擋」這個判準不採:從這次起改那支檔,工具就會推出那篇——正是這案要防的成因,不因為那篇的反引號原本只是舉例而改變。真問題是「同一個提交裡改不了、訊息沒指路」→ 折成擋下訊息指路「另開一個只改筆記的提交先改」,並用測試釘住兩步走得通、推送前一起查也過。
- F2 的判準自己重想了一遍:不只 T,凡是「同一個路徑以前不需要家、這次需要」都算新增(補 #! 同型);兩邊用同一份設定與工具自裝檔清單算,所以改設定不會讓一大批沒動的檔突然算新增。
- F5 保留「同給=用法錯誤」(第二輪外家席的裁定;鄰居 loop status 的 --light/--panel 也是同給就擋、中文訊息),改掉的是寫法:拿掉整支工具唯一的互斥群組,改成跟 loop status 同一套。cochange 的「--diff 優先」不跟——那是靜默選邊,這案刻意不要。
- F8 兩套範圍刻意不同(那套只提醒、寧可多掃;這道會擋、把整段歷史當新改動就是誤擋)→ 折成把理由寫明在掛鉤註解與節點,不合併。
- F11 行為正確,折成說明講實話,另用測試釘住「複製出來的檔一樣算新增」(使用者設了偵測複製也一樣)。
- F6 數字一律機械重數(對 d26fd9b3 比函式名集合;檢查數跑計劃列的子集加總),見驗證紀錄。
- 新測試全部先寫、修前翻紅(F11 那支釘既有行為,修前就綠——說明修正不動行為)。
