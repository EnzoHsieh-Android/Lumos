**1. 比較模式路徑限制(`_read`)**
- 符號連結繞不過。路徑先 `resolve()`(會跟隨連結)再比 `is_relative_to(root_real)`,帳上放指向 repo 外的連結會在解析後被擋。
- 大小寫與 Unicode 正規化繞不過。`root_real` 和 `fp` 用同一套解析,不一致只會讓合法路徑被誤擋,不會放行 repo 外的檔。
- 管線、裝置檔被 `is_file()` 擋掉,NUL 和孤立代理字元轉成 `OSError`,算讀不到。
- TOCTOU(`is_file` 到 `read_bytes` 之間換檔):攻擊者得先能在本機改檔案系統,PR 帶進來的帳列做不到。讀到的內容只用來比對引句、不回顯,拿不到東西。
- 硬連結:git 不存硬連結,PR 造不出來。

**2. 事件片段過濾**
- 片段只濾掉 Cc 和 Cf 兩類字元,涵蓋 ESC、C1 的 0x9b(CSI)、雙向控制字元、零寬字元和 Tags 區。Zl、Zp 已先被 `\s+` 換成空白。
- 沒濾到私用區(Co)和組合字元(Mn),最多是顯示亂碼或疊字,操控不了終端,也沒有格式欺騙價值。
- `id=` 偽造在片段移到最後之後失效:真正的 `id=` 現在在片段之前。我 grep 過,repo 裡唯一的讀取端是 `startswith("quote-rule:")` 判斷前綴,沒有人解析 `id=` 或 `quote=`,所以「取最後一個」或「dict 後者覆蓋」這類手法無處可用。
