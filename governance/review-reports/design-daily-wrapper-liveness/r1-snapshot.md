# 每日治理wrapper活著沒_計劃

> 白話:每天早上 9:30 有一支腳本自動跑五件事(治理日報、週期觀測、版本掃描、圖譜健檢、測試索引重建)。
> **9/5 那次它跑到第二步就死了,第 3 到 5 步全沒跑,而且整天沒人發現。**
> 原因不是它沒印錯誤——是**沒有任何東西在讀它印的東西**,而且它不管發生什麼都回報成功。

## 現況查證(自己開檔看的,不是轉述)

- 那支腳本的主體包在一個函式裡、結尾同一行接 `exit`(這是 9/5 那次事故之後補的,
  防的是「邊跑邊被改」),但**它沒有把五個步驟的結果加總成自己的退出碼**——
  函式回傳的是最後一步的結果,前面四步死了照樣回 0。
- **沒有整跑鎖**。機器睡過 9:30、人再手動跑一次,兩份會同時跑、互相蓋。
  ★同一個 repo 裡就有一支審過的鎖可以抄★:自主迴圈那支用「建目錄」當原子鎖,
  裡面寫 pid、鎖太舊(60 分鐘)就接管,而且處理過「剛建好目錄但還沒寫 pid」那個競態。
- **沒有完成戳記**,也**沒有任何程式在讀它的紀錄檔**(全 repo grep `governance/logs` 零命中)。
  所以「它今天有沒有跑完」這個問題,現在只能靠人自己去開檔案看。
- **治理帳 30 天長了 94%**:2026-08-08 是 2,047,015 位元組,今天是 3,966,503。
  沒有任何大小門檻或提醒。

## 設計

### [S1] 退出碼要有意義

五個步驟的結果做「有任何一個非零就非零」的加總,當作整支的退出碼。
這樣排程器記錄的 last exit code 才是真的,而不是恆為最後一步的結果。

### [S2] 完成戳記 + 死人開關要放在別的地方

- 收尾寫一個檔案(日期、各步結果),意思是「我今天跑完了」。
- ★死人開關不能放在會死的那支自己身上★——這是這一案的核心。
  放在**圖譜健檢**裡:它一天被跑數十次、每次都是獨立的行程,加一條軟提醒
  「那支每日腳本超過 36 小時沒有更新完成戳記」。
- **主通道是健檢的輸出,不是通知**。通知那條腿現在是斷的(自主迴圈暫停中),
  REVISIT:2026-10-05 跟自主迴圈的去留同一天決定要不要把通知那條接回來。

### [S3] 整跑鎖

把自主迴圈那支已經審過的鎖抄進這支的函式開頭(含 pid、60 分鐘接管、以及那個競態的處理)。
鎖目錄進忽略清單。守衛測試要釘住兩件事:鎖在函式體內(不是在函式外,否則被截斷的檔案也會搶鎖)、
收尾一定會移除。

### [S4] 帳本門檻:先出聲,不先分檔

- 只裝門檻觸發器:**超過 N MB,或近 7 日平均每日超過 500 筆**,就印一句並記一筆帳。
- ★先不分檔★:這本帳有四個整檔讀者,加上判定回放要逐行算雜湊閉包。
  分檔會動到那些,不值得現在做。分檔的做法先寫進圖譜掛回頭條件,到門檻才做。
- 順手在可逆性帳本那篇補一條:規格裡寫的「2000 筆上限」從未實作、
  而「進不進版控」那半已經裁過維持追蹤。

## 非目標

- 不改排程器設定(那是機器層的東西,不隨工具鏈分發)。
- 不做帳本分檔(見 [S4] 的理由)。
- 不重新設計通知通道(那條腿的去留跟自主迴圈綁在一起,10-05 一起裁)。

## 實務隱患

- **健檢那條軟提醒會不會變成又一則沒人看的噪音**:這個 repo 有前科。
  緩解:它只在「超過 36 小時」時才出現,正常情況完全不印。
  REVISIT:2026-10-07 查治理帳:若這條提醒出現過但那支腳本其實是好的(誤報),
  門檻要調;若它從沒出現過而那支腳本其實死過,那就是這條沒接上。
- **鎖會不會把人鎖在外面**:機器當掉留下殘鎖是真的會發生。
  60 分鐘接管那條是抄過來的既有做法,不是新發明。
  但**抄的時候要先講得出它為什麼那樣寫**——這個 repo 才因為「抄一道檢查卻漏掉關鍵一步」出過事。
- **退出碼加總會不會讓本來 fail-open 的步驟變成擋人**:不會,這支腳本不擋任何東西,
  它的退出碼只有排程器在看。但要確認排程器不會因為非零就停止排程(要查)。
- **完成戳記寫在哪**:寫在版控裡會讓每天都有一個 diff(而且是機器寫的)。
  寫在版控外的話,換一台機器就沒有。**裁定:寫在版控外的紀錄目錄**——
  它回答的是「這台機器上那支今天跑了沒」,本來就是機器局部的事實。
- **這支腳本是本 repo 專用的**:它不隨工具鏈分發到消費端(安裝器不裝這支)。
  所以這一案的所有東西都只服務本 repo,不要寫成好像消費端也會拿到。

PRIOR-ART: 最小解在收尾一行戳記加健檢一條軟檢查;
世界解=healthchecks.io / Cronitor 的心跳加寬限期、systemd 的 OnFailure、
SRE 的「對缺席告警」(alerting on absence)、flock / run-one(macOS 沒有 flock,用建目錄當原子鎖)、
logrotate 的大小條件;
裁定=borrow-design,而且其中兩件(原子鎖、對缺席告警)這個 repo 自己已經有審過的實作可以抄。
