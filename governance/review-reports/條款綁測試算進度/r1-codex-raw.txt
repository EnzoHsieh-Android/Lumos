# lumos 專案知識圖譜——一頁手冊

圖譜記「為什麼、邊界、不能改的、驗過沒」;code 只記「現在長怎樣」。圖譜跟行為事實(測試、實際執行、生產觀測)對不上時,不自動信圖譜——查清哪邊錯,立一篇事故筆記。主工具 `lumos`(python3 零依賴,自動找 `docs/*-knowledge/`)。**別用 Grep/Read/Edit/Write 直接碰圖譜的 .md 開頭欄位**——會繞過自驗和防護;正文段落用 Edit 可以。

**指令怎麼找**:`commands/INDEX.md`(本目錄,4k)——先看「grep 衝動對照表」,再按你正在做的事開九個子檔之一。下面只列每個階段最常用的。

## 1. 進場(每個子任務都重來,不是 session 開頭一次)

| 你在想… | 敲 |
|---|---|
| 這件事為什麼這樣 / 圖譜記了嗎 | `lumos search <詞>` → `lumos context <節點>`;0 命中先換同義詞;**中文概念之間加空白**(`作廢 收回 點數`,別黏成一句) |
| 動這段有什麼不能碰 | `lumos contracts <節點>` |
| 要讀全文再下結論 | `lumos show <節點>`(search 只給索引行;拿摘要判「沒記」以前真的錯過——值在筆記第 64 行,靠摘要判成沒有) |
| 篩條件(金流 / 未收案 / 連到 X) | `lumos query --tag 家族/值 [--active] [--linked <節點>]` |
| 開工掌握現況 | `lumos query --tag status/doing`;`lumos recent --days 7` |
| 圖譜空或稀疏(接手 brownfield) | 走節點還原 SOP:`commands/09-節點還原.md`(七步;需要才產節點、有就照慣例用) |

看到筆記有 `core_refs:` 或 `CORE:` → 權威在跨專案核心圖譜,改那邊(`lumos-core-knowledge` skill)。
**查得到才算先行**(Landmark 實測):0 筆看「逐詞覆蓋」標 ★ 的詞換同義詞,換三次再問人,別轉 grep;大節點先 `--brief`;單篇內部新舊打架時摘要有日期的 KEY 行 > 正文,衝突影響決策去 code 裁再回頭修。
**分清你在哪種 session**:本機 Claude Code(含手機/網頁遙控本機)有本機 git 憑證、能 push;網頁版 claude.ai/code 是雲端沙盒,對主分支沒 push 權、只能推 feature branch——「遙控」不等於「遠端版」,曾騙到 AI 一次。
被催「直接改、不用解釋」也一樣:不解釋可以,不查不行——改 code 前至少 `lumos impact --file <檔>` 一行。

## 2. 動手前

- `lumos impact --file <檔>` / `--diff <範圍>`:哪些筆記、驗證、決策會受影響(Edit 前 hook 也會塞一份,但只推你碰到的檔)。
- `lumos pitfalls --diff <範圍>`:風險分級;`tier: high` 要過代碼審(`lumos-code-loop`)。
- 要刪 / 改名東西:`lumos search <舊名> --code` 逐句判哪些筆記還在講它。
- 改了環境 / 流程 / 設定(版本、金鑰、hook、排程):`lumos stale --candidate --match <關鍵字>` 列出寫了「改到這個就該重驗」的驗證紀錄。
- 設計、spec、計劃一律寫成 `Projects/<主題>_計劃` 筆記(`type: project`),不寫到別的路徑;動筆前一行 `PRIOR-ART:`(最小解在哪層 / 世界解過沒 / 借用‧自建‧採用)。

## 3. 寫回(同一次工作內;pre-commit 擋「改 code 沒動圖譜」)

| 要做 | 敲 |
|---|---|
| 新筆記 | `lumos new <system\|issue\|verification\|project> <名>`;驗證紀錄加 `--plan <計劃> --systems <節點>` 自動雙向連 |
| 改狀態 / 日期 | `lumos set <節點> <欄位> <值>`(日期不加引號) |
| 加 / 刪清單項 | `lumos append <節點> <欄位> "[[x]]"` / `lumos remove …` |
| 記決策 / 翻案 | `lumos decision-add <節點> "<內容>" --decided <日期>` / `lumos decision-supersede` |
| 正文段落 | Edit;寫完 `lumos lint <節點>` |

**四條血換的開頭欄位鐵則**:① 多個連結一行一項,擠成一串會長假筆記 ② `summary: |` 區塊裡的 `[[連結]]` 不算連結,要關聯另放 list 欄位 ③ 值含「冒號+空格」要引號或區塊 ④ 同層不能重複鍵。用指令寫天生避開;手改才會踩。

**合約標記(動筆前掃一眼;不確定就不標,嚴禁看 code 反推)**:
```
KEY:★INVARIANT★ <業務合約,改=破壞性> [test:測試名] [audit:模型/日期] [kill:recipes]
KEY:★DEBT★ <偶然行為,可改>
KEY:★IRREVERSIBLE★ <做了回不去> [rollback:decisions]     KEY:★CHECKPOINT★ <改了難救>(建議補 [rollback:])
```
- 綁測試 / 留審計走指令:`lumos guard bind <節點> "<KEY 片段>" <測試名>`、`lumos guard audit …`;裸合約 doctor 擋,未審計 pre-push 擋。綁之前對照 [[Systems/測試假綠形態]](最隱蔽的一型:現場根本走不到被測分支;修 bug 的翻紅測試要配一條「現場成立」的前置斷言)。
- 外部不可逆(信已寄、下游已吃)用 `[guard:decisions]` 寫怎麼防重複。`[test:]` 只證程式對,「規則還符不符合業務」要人確認:`lumos signoff`。
- 從 code 重建的筆記先 `lumos set <節點> regen from-scratch/<日期>`,每條主張標 `[src:]`/`[git:]`/`推測:`/`佚失:`;佚失就寫佚失,嚴禁編。

**摘要區塊**(Systems/Issues 必有):`FLOW:`流程 `KEY:`關鍵概念 `DEP:`依賴 `TEST:`測試;Issues 用 `FLAG:`(只收 TECHNICAL/DECISION/ORIGIN) `DECISION:` `KEY:`。已結案的 Issue 正文第一段要有結案橫幅(status 在開頭欄位,`show --body-only` 看不到,讀者會把修好的當現況)。
**標籤**:`type/` `status/`(值域 lint 硬擋)、`priority/` P0–P3、`scope/`(feature/ area/ 已停用)、`risk/` 金流‧對外送出‧不可逆‧守衛面、`flag/`。

**決策與驗證**:重大決策填四欄(context / alternatives≥2 / why_chosen / trade_offs),缺資訊問人不編。驗證紀錄填 `valid_under`(前提)與 `revalidate_when`(何時重驗),用 `plan_refs` 指回計劃;漏掛 `lumos sync-verified-by --apply`。計劃結案前 `lumos spec-trace <計劃>` 看哪些條款沒人認領。

**承認風險的鐵則**(Enzo 2026-08-22 裁):筆記或訊息裡寫「沒機械守衛 / 只提醒不擋 / 單次量測 / 這數字是拍的」這類承認句,**旁邊必須有「什麼時候回頭看」**(週報、重驗條件、revalidate_when、到期日);寫不出重驗條件的,就是該處理不該承認。**回頭條件要接電**(2026-08-31 回訪案):帶日期的寫成獨立一行 `REVISIT:YYYY-MM-DD 一句要做什麼`(緊鄰原句,doctor 到期會唸、逾 14 天沒人動升級週報);綁事件的明寫事件入口——純散文=52 件盤點實證的死文。

def cmd_map(env, rel, depth):
    out_e, _ = env.edges
    seen = {rel}

    def walk(cur, d, prefix):
        if d > depth:
            return
        children = [c for c in sorted(out_e.get(cur, []))]
        for i, c in enumerate(children):
            tail = "└─" if i == len(children) - 1 else "├─"
            mark = " (↺)" if c in seen else ""
            print(f"{prefix}{tail} {c} [{status_of(env, c)}]{mark}")
            if c not in seen:
                seen.add(c)
                walk(c, d + 1, prefix + ("   " if i == len(children) - 1 else "│  "))

    print(f"{rel} [{status_of(env, rel)}]  (depth={depth}, ↺=已出現過)")
    walk(rel, 1, "")
    return 0


# 標準格式: KEY 行前綴 ★INVARIANT★ / ★DEBT★(可帶 (日期) 前綴)。
# 錨定 KEY 行起始 → 排除「散文中提到標記」的誤報(如方法論文件講解標記用法)。
INVARIANT_RE = re.compile(r"^KEY:\s*(?:\([^)]*\)\s*)?★INVARIANT★\s*(.*)")
DEBT_RE = re.compile(r"^KEY:\s*(?:\([^)]*\)\s*)?★DEBT★\s*(.*)")


def extract_contracts(note):
    """從 summary block 的 KEY 行抽標準格式 ★INVARIANT★ / ★DEBT★。回傳 (invariants, debts)。
    只認 KEY 行前綴(標準格式),散文中提及不算 — 否則方法論文件會誤報。"""
    summ = note.fields.get("summary")
    inv, debt = [], []
    if isinstance(summ, str):
        for line in summ.split("\n"):
            line = line.strip()
            mi = INVARIANT_RE.match(line)
            if mi:
                inv.append(mi.group(1).strip())
            md = DEBT_RE.match(line)
            if md:
                debt.append(md.group(1).strip())
    return inv, debt

def invariant_test_refs(inv_text):
    """從 ★INVARIANT★ 文字抽 [test:A,B] 綁定的可執行測試名(可多個,逗號分隔)。無綁定回 []。
    回**原始字串**(含任何 平台: 前綴)——供 tag 重建/顯示;平台解析走 resolve_test_refs。"""
    out = []
    for m in TEST_REF_RE.findall(inv_text):
        out.extend(t.strip() for t in m.split(",") if t.strip())
    return out


def resolve_test_refs(inv_text, platforms, default_platform):
    """把 [test:...] 解析為 [(platform, method_name)]。沿用 invariant_test_refs 的逗號切分。
    - platforms 非空(多平台):每段含 ':' → 前綴須為已定義 platform 鍵(C#/Kotlin 名不含冒號,
      故含冒號即視為 平台:名;前綴未定義 → raise ValueError,不誤當方法名);無 ':' → 歸 default_platform。
    - platforms 空(legacy,由呼叫端在 multiplatform=False 時傳 {}):**不切分**,整串(含任何冒號)
      配 default_platform → 後續走單一 method set 比對(含冒號的假想 ref 走 dangling 而非報錯)。"""
    out = []
    for seg in invariant_test_refs(inv_text):
        if platforms and ":" in seg:
            plat, name = seg.split(":", 1)
            plat, name = plat.strip(), name.strip()
            if plat not in platforms:
                raise ValueError(
                    f"[test:{seg}] 的平台前綴 '{plat}' 未定義於 platforms"
                    f"({', '.join(platforms)});不猜,免得綁錯平台")
            out.append((plat, name))
        else:
            out.append((default_platform, seg))
    return out


def invariant_audit_refs(inv_text):

SPEC_CLAUSE_RE = re.compile(r"\[S(\d+)\]")


def cmd_spec_trace(env, node, as_json=False):
    """條款級追溯(RTM 輕量版):計劃 body 的 [SN] 條款 × 回指 Verification 的認領。
    rc:全認領=0;有未認領=1;計劃無 [SN] 標記=0(opt-in 未啟用)。唯讀。"""
    import json
    rel = env.find(node)
    if rel is None:
        print(f"擋下:圖譜裡找不到叫 {node} 的筆記,先確認名稱或路徑(lumos search <關鍵字> 可以找)", file=sys.stderr)
        return 2
    plan_stem = env.notes[rel].stem
    try:
        text = (env.vault / rel).read_text(encoding="utf-8-sig")
    except OSError as ex:
        print(f"擋下:{ex}", file=sys.stderr)
        return 2
    ids = sorted({int(m) for m in SPEC_CLAUSE_RE.findall(text)})
    if not ids:
        if as_json:
            print(json.dumps({"plan": rel, "clauses": {}, "unclaimed": [],
                              "opt_in": False}, ensure_ascii=False))
        else:
            print(f"(opt-in 未啟用) {rel} 無 [SN] 條款標記——要追溯就在規格 bullet 加 [S1]/[S2]…")
        return 0
    claims = {i: [] for i in ids}
    for vrel, n in env.notes.items():
        if not vrel.startswith("Verification/"):
            continue
        prs = n.fields.get("plan_refs")
        prs = prs if isinstance(prs, list) else ([prs] if prs else [])
        if not any(plan_stem in str(x) for x in prs):
            continue   # 沒回指本計劃的提及不算認領(防偶然文字)
        # 已知設計限制:多計劃 Verification 提及 [S1] 會同時記入兩計劃的 S1
        # (條款 ID 只有數字無計劃域)——一篇 Verification 盡量只回指一個計劃
        try:
            vtext = (env.vault / vrel).read_text(encoding="utf-8-sig")
        except OSError:
            continue
        for m in SPEC_CLAUSE_RE.findall(vtext):
            i = int(m)
            if i in claims:
                claims[i].append(vrel)
    unclaimed = [i for i in ids if not claims[i]]
    if as_json:
        print(json.dumps({"plan": rel, "clauses": {f"S{i}": claims[i] for i in ids},
                          "unclaimed": [f"S{i}" for i in unclaimed]}, ensure_ascii=False))
    else:
        for i in ids:
            mark = "✓" if claims[i] else "✗"
            who = ", ".join(Path(x).stem for x in claims[i]) or "(無人認領)"
            print(f"{mark} [S{i}] ← {who}")
        print(f"\n{len(ids)} 條款 / 未認領 {len(unclaimed)}")
    return 1 if unclaimed else 0

def _ci_config(repo_root):
    """讀 .lumos/config.json 的 ci 區塊。回 (enabled, cfg)。
    總開關:未宣告 ci 區塊=功能全關(行為與未安裝逐字相同);config 壞損→退「全關」(fail-safe 到零侵入)。"""
    import json
    path = Path(repo_root) / ".lumos" / "config.json"
    try:
        data = json.loads(path.read_text(encoding="utf-8"))
    except (OSError, ValueError):
        return False, {}
    ci = data.get("ci") if isinstance(data, dict) else None
    if not isinstance(ci, dict):
        if ci is not None:
            print("⚠ .lumos/config.json 的 ci 非物件——CI 回流功能關閉(fail-safe)", file=sys.stderr)
        return False, {}
    wf = ci.get("workflow")
    if wf is not None and not isinstance(wf, (str, list)):
        print("⚠ ci.workflow 需字串或字串陣列——CI 回流功能關閉(fail-safe)", file=sys.stderr)
        return False, {}
    return True, ci


def _ci_gh(repo_root, args, timeout=60):
    """跑 gh(cwd=repo_root)。回 (rc, stdout, err_or_None);gh 缺席回 (None,"",訊息)。"""
    import subprocess
    try:
        r = subprocess.run(["gh"] + args, cwd=str(repo_root), capture_output=True,
                           text=True, timeout=timeout)
    except FileNotFoundError:
        return None, "", "gh 未安裝"
    except (OSError, subprocess.TimeoutExpired) as e:
        return None, "", f"gh 執行失敗: {e}"
    return r.returncode, r.stdout, (None if r.returncode == 0 else (r.stderr or "").strip()[:200])


def _ci_list_runs(repo_root, sha, workflows):
    """查該 sha 的 run。workflows=None→全部;字串/陣列→逐支各查一次後合併(--workflow 是單值旗標)。
    回 (runs, err)。用 gh 原生 --commit 過濾(client-side 比對會被 gh 預設 limit 20 擠掉=假綠)。"""
    import json
    fields = "databaseId,attempt,status,conclusion,displayTitle,url,workflowName"
    names = ([workflows] if isinstance(workflows, str) else list(workflows or [None]))
    out, seen = [], set()
    for name in names:
        args = ["run", "list", "--commit", sha, "--json", fields, "--limit", "100"]
        if name:
            args += ["--workflow", name]
        rc, so, err = _ci_gh(repo_root, args)
        if rc is None or rc != 0:
            return None, (err or "gh run list 失敗")
        try:
            rows = json.loads(so or "[]")
        except ValueError:
            return None, "gh 輸出非 JSON"
        for r in rows if isinstance(rows, list) else []:
            key = (r.get("databaseId"), r.get("attempt"))
            if key not in seen:
                seen.add(key)
                out.append(r)
    return out, None


def _ci_failed_step(repo_root, run_id):
    """失敗步驟名取自 jobs JSON(非 log 文字解析);多個全列以 ';' 串接。"""
    import json
    rc, so, _err = _ci_gh(repo_root, ["run", "view", str(run_id), "--json", "jobs"])
    if rc is None or rc != 0:
        return ""
    try:
        jobs = (json.loads(so or "{}") or {}).get("jobs") or []
    except ValueError:
        return ""
    hits = []
    for j in jobs if isinstance(jobs, list) else []:
        for st in (j.get("steps") or []):
            if st.get("conclusion") == "failure":
                hits.append(f"{j.get('name', '?')}/{st.get('name', '?')}")
    return ";".join(hits)


def _ci_fail_log(repo_root, run_id):
    """log 尾段:先取尾 40 行、再截 4000 字(兩上限依序)。"""
    rc, so, _err = _ci_gh(repo_root, ["run", "view", str(run_id), "--log-failed"])
    if rc is None or not so:
        return ""
    return "\n".join(so.splitlines()[-40:])[:4000]

def cmd_ci_wait(env, timeout=1800.0, repo_dir=None, sha=None, branch=None,
                grace=30.0, as_json=False):
    """[S1] push 後同輪等 CI 結論。綠 rc0/紅 rc1/未定·逾時·no-run·工具缺席 rc0/帳寫失敗·參數錯 rc2。"""
    import json
    import datetime
    import subprocess
    import time

    def emit(verdict, runs=None, note=None, rc=0):
        payload = {"sha": sha, "verdict": verdict, "runs": runs or []}
        if as_json:
            print(json.dumps(payload, ensure_ascii=False))
        else:
            if note:
                print(note)
            for r in (runs or []):
                print(f"CI {r.get('conclusion', '?'):<12} {r.get('workflow', '?')}"
                      f" {(r.get('sha') or '')[:7]} → {r.get('url', '')}")
                # 失敗證據必須進**文字**輸出:只塞 --json 等於人跑指令看不到任何可修的線索
                # (2026-07-29 外審實錘:README/skill/計劃都承諾會印,實作只進 json)
                if r.get("failed_step"):
                    print(f"  失敗步驟: {r['failed_step']}")
                if r.get("log_tail"):
                    print("  log 尾段:")
                    for ln in str(r["log_tail"]).splitlines():
                        print(f"    {ln}")
            print(f"→ 判定: {verdict}")
        return rc

    root = repo_dir or _anchor_repo_root(None)
    if root is None or not Path(root).is_dir():
        print(f"擋下:--repo-dir 指的目錄不存在: {repo_dir!r}", file=sys.stderr)
        return 2
    enabled, cfg = _ci_config(root)
    if not enabled:
        return emit("disabled", note="(未宣告 .lumos/config.json 的 ci 區塊,CI 回流功能關閉)")
    def _git_out(*a):
        try:
            r = subprocess.run(["git", "-C", str(root), *a], capture_output=True, text=True,
                               timeout=30)
        except (OSError, subprocess.TimeoutExpired):
            return ""        # git 缺席/逾時也 fail-open(絕不 traceback)
        return r.stdout.strip() if r.returncode == 0 else ""
    if not sha:
        sha = _git_out("rev-parse", "HEAD") or None
    if not branch:
        branch = _git_out("rev-parse", "--abbrev-ref", "HEAD")
    if not sha:
        print("ci-wait: 取不到 HEAD sha(空 repo?),跳過", file=sys.stderr)
        return emit("unavailable")

    deadline = time.time() + float(timeout)
    graced = 0                    # 等過幾個 grace 窗(no-run 要連等三個才下結論)
    while True:
        runs, err = _ci_list_runs(root, sha, cfg.get("workflow"))
        if runs is None:
            print(f"ci-wait: {err}(fail-open,不擋任何流程)", file=sys.stderr)
            return emit("unavailable")
        done = [r for r in runs if r.get("status") == "completed"]
        red = [r for r in done if (r.get("conclusion") or "") in _CI_RED]
        if red:                       # 任一紅即紅:立刻早退(不等其餘)
            out = []
            for r in red:
                rid = r.get("databaseId")
                out.append({"run_id": rid, "attempt": r.get("attempt", 1),
                            "workflow": r.get("workflowName", "?"), "sha": sha,
                            "conclusion": r.get("conclusion"), "url": r.get("url", ""),
                            "failed_step": _ci_failed_step(root, rid),
                            "log_tail": _ci_fail_log(root, rid)})
            rc_w = _ci_record(env, out, sha, branch)
            return rc_w if rc_w else emit("red", out, rc=1)
        if runs and len(done) == len(runs):
            if graced < 1:            # 全綠前再等一個 grace 期(晚註冊 run 緩解,非保證)
                graced += 1
                time.sleep(min(float(grace), max(0.0, deadline - time.time())))
                continue
            out = [{"run_id": r.get("databaseId"), "attempt": r.get("attempt", 1),
                    "workflow": r.get("workflowName", "?"), "sha": sha,
                    "conclusion": r.get("conclusion"), "url": r.get("url", ""),
                    "failed_step": "", "log_tail": ""} for r in done]
            rc_w = _ci_record(env, out, sha, branch)
            if rc_w:
                return rc_w
            # conclusion 三分類(計劃 [S1] 矩陣;2026-07-29 外審實錘實作只做紅/非紅二分):
            # 綠=全部落在 _CI_GREEN;非綠非紅(cancelled/action_required/stale,含未知未來值)
            # =未定,rc0 但**不得判綠**——「完成且沒紅」不等於「通過」。
            odd = [r for r in out if (r.get("conclusion") or "") not in _CI_GREEN]
            if odd:
                names = "、".join(sorted({(r.get("conclusion") or "?") for r in odd}))
                return emit("undetermined", out,
                            note=f"非成功但無失敗步驟可歸因({names}):不進修復路徑,請人判")
            return emit("green", out)
        if not runs:                  # no-run 快速路徑:等幾個 grace 窗仍零 → 收工,不白等
            # ★等一個 grace 窗不夠★(2026-09-06 實測):推送後 GitHub 註冊 run 可能要好幾分鐘,
            # 那次 14:02 推、14:15:46 才出現 run,而 ci-wait 判了 no-run。而家規明說 no-run
            # 不算過,誤報等於叫人去查一個不存在的觸發條件問題。改成連續等三個窗才下結論。
            # ★沒有完全診斷清楚★:那次 ci-wait 從 14:02 跑到 14:18 卻仍回 no-run,單靠加窗
            # 未必解釋得完(可能是 API 查詢的分支/sha 條件或回傳延遲),所以下面訊息改成講
            # 「等了多久沒看到」而不是斷言「沒有觸發」。REVISIT:2026-10-06 看帳上還有沒有 no-run。
            if graced < 3:
                graced += 1
                time.sleep(min(float(grace), max(0.0, deadline - time.time())))
                continue
            rc_w = _ci_record(env, [{"run_id": None, "attempt": 0, "workflow": "",
                                     "sha": sha, "conclusion": "no-run", "url": "",
                                     "failed_step": "", "log_tail": ""}], sha, branch)
            return rc_w if rc_w else emit(
                "no-run", note=f"等了約 {int(float(grace) * 3)} 秒仍查不到這個 sha 的 workflow run"
                                f"——可能是還沒註冊(推完馬上問常撞到)、也可能是 workflow 的 "
                                f"branch/path 條件不含這次改動。★no-run 不算過★:過幾分鐘用 "
                                f"lumos ci-status 再確認一次")
        if time.time() >= deadline:
            rc_w = _ci_record(env, [{"run_id": None, "attempt": 0, "workflow": "",
                                     "sha": sha, "conclusion": "timeout-waiting", "url": "",
                                     "failed_step": "", "log_tail": ""}], sha, branch)
            return rc_w if rc_w else emit(
                "timeout", note=f"逾時({timeout:.0f}s)未出結論,請手動查 gh run list")
        time.sleep(min(15.0, max(1.0, deadline - time.time())))


def _ci_record(env, rows, sha, branch):
    """把結果逐筆寫帳;任一筆寫失敗即回 rc2(自驗失敗優先於紅燈)。"""
    import datetime
    ts = datetime.datetime.now().astimezone().isoformat(timespec="seconds")
    for r in rows:
        rid = r.get("run_id")
        att = r.get("attempt", 0)
        concl = r.get("conclusion") or "?"
        key = (f"{rid}:{att}:{concl}" if rid else f"nosha:{sha}:{concl}")
        rec = {"ts": ts, "run_id": rid, "attempt": att, "sha": sha, "branch": branch,
               "workflow": r.get("workflow", ""), "conclusion": concl,
               "title": r.get("title", ""), "url": r.get("url", ""),
               "failed_step": r.get("failed_step", ""), "dedup_key": key}
        rc = _ci_write(env, rec)
        if rc != 0:
            return rc
    return 0

def _bound_tests_check(repo_root, diff_range, skip=False, skip_note="", payload=None, advisory=False):
    """回 dict{status, ran, red:[…], secs, calc_secs, reason, advisory}。

    status ∈ green / red / skipped / no-config / no-pins / no-bound /
             range-unavailable / whole-suite-deferred。

    advisory=True(低風險推送):紅了照樣印、照樣記帳,但呼叫端不擋(人裁 2026-09-07)。
      不選「低風險也擋」的理由:擋下去最可能的結果不是人去修測試,是人改走 --no-verify
      ——而推送關卡自己在別的地方就把那條當第三選項在教,那條零留痕。
    payload:已經算好的波及結果(推送關卡一次推送只算一次)。
    """
    import os as _os, time as _time
    if skip or _os.environ.get("LUMOS_SKIP_BOUND_TESTS") == "1":
        note = skip_note or ("env LUMOS_SKIP_BOUND_TESTS=1" if not skip else "")
        # ★旗標跳過與環境變數跳過要分開記★(設計 [S6]):前者是人當下決定並留了理由,
        # 後者多半是 CI 常態設定——混在同一個類別裡,回頭條件分不出哪一種在發生。
        kind = "skipped-env" if (not skip and _os.environ.get("LUMOS_SKIP_BOUND_TESTS") == "1") else "skipped-flag"
        _bound_tests_log(repo_root, kind, [], note)
        return {"status": "skipped", "ran": 0, "red": [], "secs": 0.0, "calc_secs": 0.0,
                "reason": note, "advisory": advisory}
    _t0 = _time.time()
    _rng, _rng_note = _bound_tests_range(repo_root, diff_range)
    if _rng is None:
        _bound_tests_log(repo_root, "range-unavailable", [], _rng_note)
        return {"status": "range-unavailable", "ran": 0, "red": [], "secs": 0.0,
                "calc_secs": round(_time.time() - _t0, 2), "reason": _rng_note, "advisory": advisory}
    # ★範圍換過了,那份算好的結果就不能用★(代碼審 r1 外家否決席判 major,查證屬實):
    # pre-push 給的 payload 是拿「空樹..HEAD」算的(整個 repo 都是 diff),
    # 而上面剛把範圍換成「跟主線的共同祖先..HEAD」。這時候若照樣吃那份 payload,
    # 固定席會是全庫合約——★正是設計明令要避免的「首推跑滿全部」那條稅★,
    # 而且範圍字串跟實際用的資料對不上,帳上會說謊。
    if payload is not None and _rng != str(diff_range or ""):
        payload = None
    items, why = _bound_tests_for_diff(repo_root, _rng, payload=payload)
    _calc = round(_time.time() - _t0, 2)
    if why:
        kind = why.split(":", 1)[0]
        # ★diff-unavailable 這個類別已經沒有來源了★:唯一會走到它的是空樹起點,
        # 而那條現在改成先換主線 tip、換不到才記 range-unavailable(設計 [S3])。
        # 留著對照組不動,免得舊帳的類別名突然消失。
        _bound_tests_log(repo_root, kind, [], why if ":" in why else _rng)
        return {"status": kind, "ran": 0, "red": [], "secs": 0.0, "calc_secs": _calc,
                "reason": why, "advisory": advisory}
    # ★不可過濾的測試指令 + 低風險 → 不跑,誠實記★(設計 [S4])。
    # 沒有 {method} 佔位符就只能整套跑,逾時上限 600 秒。低風險推送不值得付這個。
    # ★不要假裝這種情況也守住了★——所以記一個自己的類別,不混進 green。
    # ★逐平台判,不是整批判★(代碼審 r1 外家否決席判 major,查證屬實):
    # 舊寫法是「只要有一個平台可以過濾,就整批照跑」——結果那些★不可過濾★的平台
    # 照樣被 _run_bound_tests 跑整套(單套逾時 600 秒),低風險推送當場卡住。
    # 正確的隔離是:可過濾的照跑,不可過濾的那幾支個別 deferred。
    if advisory:
        _keep, _defer = _bound_tests_split_by_filterable(repo_root, items)
        if _defer:
            _bound_tests_log(repo_root, "whole-suite-deferred", sorted({i[0] for i in _defer}),
                             "測試指令不可過濾(沒有 {method}),低風險這次不跑這幾支")
        if not _keep:
            return {"status": "whole-suite-deferred", "ran": 0, "red": [], "secs": 0.0,
                    "calc_secs": _calc, "advisory": advisory,
                    "reason": "你的測試指令不能只跑一支,所以這次跳過;把指令改成可過濾的(帶 {method}),這道閘才會每次推送都保護你"}
        items = _keep
    results, err = _run_bound_tests(repo_root, items)
    if results is None:
        _bound_tests_log(repo_root, "no-config", sorted({i[0] for i in items}), err)
        return {"status": "no-config", "ran": 0, "red": [], "secs": 0.0, "calc_secs": _calc,
                "reason": err, "advisory": advisory}
    red = [(n, p, m, d) for n, p, m, v, d, _ in results if v == "red"]
    secs = round(sum(r[5] for r in results), 1)
    ran = sum(1 for r in results if r[3] == "green")
    if red:
        # ★advisory 與擋要分帳★(設計 [S6]):兩者的後果完全不同,混成一個 kind
        # 就回答不了「只提醒到底夠不夠」——而那正是人裁時掛的回頭條件要問的事。
        kind = "red-advisory" if advisory else "red-blocked"
        _bound_tests_log(repo_root, kind, sorted({r[0] for r in red}),
                         f"{len(red)} 紅/{len(results)}", secs=secs, calc_secs=_calc)
        return {"status": "red", "ran": ran, "red": red, "secs": secs, "calc_secs": _calc,
                "advisory": advisory,
                "reason": "受波及合約的測試沒過:" + ";".join(f"{n} [{m}] {d}" for n, p, m, d in red[:6])}
    # ★耗時存成獨立欄位★(設計 [S6]):以前塞在自由文字的備註裡(「46 綠 41.8s」),
    # 回頭條件量不到;而且那個秒數只算跑測試那段,不含前面算波及的時間。分開存。
    _bound_tests_log(repo_root, "green", sorted({r[0] for r in results}),
                     f"{ran} 綠", secs=secs, calc_secs=_calc)
    return {"status": "green", "ran": ran, "red": [], "secs": secs, "calc_secs": _calc,
            "advisory": advisory, "reason": f"受波及合約測試 {ran} 支全綠(跑 {secs}s、算 {_calc}s)"}


def _bound_tests_split_by_filterable(repo_root, items):
    """把這批要跑的測試按「那個平台的指令能不能只跑一支」拆成兩堆:(照跑的, 這次不跑的)。

    ★逐平台判★(2026-09-07 代碼審 r1 外家否決席):第一版是整批判——只要有一個平台
    可以過濾就整批照跑,於是不可過濾的那幾個平台照樣被跑整套(單套逾時 600 秒)。
    低風險推送不值得付那個,但也不該因為某個平台不可過濾就把可以跑的那幾支一起放掉。

    ★回不出設定就當「可過濾」★(保守:寧可跑,不要假裝守住了)——
    真的跑不動時 _run_bound_tests 自己會記 no-config。
    非 real 的項目(懸空 / 偽證據 / 名字不合法)一律留著:它們不用真跑就能判紅,
    而那正是這道閘最該講出來的東西。
    """
    try:
        plats = load_platforms(repo_root)["platforms"]
    except Exception:
        return list(items), []
    keep, defer = [], []
    for it in items:
        _n, plat, _m, st = it
        if st != "real":
            keep.append(it)
            continue
        cmd = (plats.get(plat) or {}).get("run_cmd") or ""
        (keep if ("{method}" in cmd or not cmd) else defer).append(it)
    return keep, defer

def cmd_bound_tests(diff_range, repo=None, as_json=False, advisory=False, from_json=None,
                    skip=False, skip_note=""):
    """跑「這次改動波及到的硬合約」綁的那些測試。

    ★為什麼要獨立一支指令★(2026-09-07 全 repo 審視 #17,設計 [S2],r1 外家席判 blocking):
    這件事本來藏在 code-loop check 裡,而合約測試紅了會讓那支回 rc1;推送關卡把所有 rc1
    一律解讀成「高風險改動還沒審查」,叫人去跑 code-loop pass。
    ★留下審查紀錄修不好一支紅掉的測試,下次照樣被擋。★ 訊息與處置必須分流。

    ★扁平頂層指令,不包子動詞★:這個 repo 對單一動詞的工具一律扁平,
    群組式(loop / canary / guard 那種)是留給天生有兩個以上動詞的。

    rc:0=green 或沒東西可跑 / 1=red 且不是 advisory / 2=參數或環境問題。
    --advisory:紅了照樣印、照樣記帳,但回 0(低風險推送用;人裁 2026-09-07)。
    """
    import json as _json
    root = Path(repo or ".").resolve()
    payload = _impact_payload_read(from_json) if from_json else None
    if from_json and payload is None:
        # ★失敗隔離★:讀不到那份算好的結果,不是「沒事」也不是「炸掉」——記帳放行,
        # 並且讓人看得出是這一步壞了,不要跟「真的沒東西可跑」混在一起。
        _bound_tests_log(root, "range-unavailable", [], f"讀不到已算好的波及結果:{from_json}")
        if as_json:
            print(_json.dumps({"status": "range-unavailable", "advisory": advisory,
                               "reason": f"讀不到已算好的波及結果({from_json})"}, ensure_ascii=False))
        else:
            print(f"提醒:讀不到已經算好的波及結果({from_json}),這次沒跑合約測試。", file=sys.stderr)
        return 0
    v = _bound_tests_check(root, diff_range, skip=skip, skip_note=skip_note,
                           payload=payload, advisory=advisory)

def _handoff_cmd_brief(cmd, width=80):
    """指令摘要給人看:去掉開頭的 cd <路徑>(2026-09-07 真逐字稿實看:一輪五條指令全以 cd repo 開頭,只印第一行就是五個 cd),
    取第一行非空的、截 width 字。JSON 輸出不經這裡,原文保留。"""
    lines = [l.strip() for l in cmd.splitlines() if l.strip()]
    # 整行只是 cd 或 echo 橫幅(echo "=== ④ … ===")的先跳過;同一行開頭的 cd X && / echo "…"; 也剝掉
    _noise_line = r"^(cd\s+\S+|echo\s+(\"[^\"]*\"|'[^']*'|\S+))\s*(&&|;)?$"
    _noise_head = r"^(cd\s+\S+|echo\s+(\"[^\"]*\"|'[^']*'|\S+))\s*(&&|;)\s*"
    while lines and re.match(_noise_line, lines[0]):
        lines.pop(0)
    if lines:
        for _ in range(3):
            lines[0] = re.sub(_noise_head, "", lines[0])
    first = lines[0] if lines and lines[0] else cmd.strip()
    return first[:width] + ("…" if len(first) > width else "")

 17136	def _fold_mirror_sections(text):
 17137	    """掃 text 回傳所有「鏡像段」標籤清單,供 fold-check 列舉複查用。
 17138	
 17139	    鏡像段定義(設計 §2.1):
 17140	      1. frontmatter summary block → "summary"
 17141	      2. body 內每個 ```json fence → "```json fence N"(1-indexed)
 17142	      3. ## …審計修正紀錄(含節號前綴如 ## §5 審計修正紀錄)
 17143	      4. ## …誠實天花板(含節號前綴如 ## §4 誠實天花板)
 17144	
 17145	    標題比對容節號前綴(r1-F5):regex ^##\\s+(§\\d+\\s+)?(審計修正紀錄|誠實天花板)
 17146	    """
 17147	    sections = []
 17148	
 17149	    # 1. summary block:frontmatter 有 summary: 鍵
 17150	    # Also captures body for steps 2 & 3 — single call, DRY
 17151	    fm_lines, body = split_frontmatter(text)
 17152	    if fm_lines is not None:
 17153	        for line in fm_lines:
 17154	            if re.match(r"^summary\s*:", line):
 17155	                sections.append("summary")
 17156	                break
 17157	
 17158	    # 2. ```json fences in body — body from split_frontmatter (correct offset, DRY)
 17159	    # Match ```json ... ``` fences
 17160	    json_fence_re = re.compile(r"^```json\b", re.MULTILINE)
 17161	    json_count = 0
 17162	    for m in json_fence_re.finditer(body):
 17163	        json_count += 1
 17164	        sections.append(f"```json fence {json_count}")
 17165	
 17165	
 17166	    # 3 & 4. ## …審計修正紀錄 / ## …誠實天花板 headings (with optional §N prefix)
 17167	    # Scan body only (consistent with json fence scan above)
 17168	    for m in _FOLD_MIRROR_HEADING_RE.finditer(body):
 17169	        # Use the full matched heading text (strip leading ##\s+)
 17170	        heading = m.group(0).lstrip("#").strip()
 17171	        sections.append(heading)
 17172	
 17173	    return sections

 17177	_FOLD_AUDIT_RECORD_RE = re.compile(

 17188	def _fold_value_drift(text):
 17189	    r"""偵測「同識別詞在不同處出現不同值」的漂移(全文域)。
 17190	
 17191	    掃描域排除 ## …審計修正紀錄 段(含節號前綴),該段刻意引用歷史/舊值,掃它必假陽。
 17192	    單一抽取法:掃符合值 pattern 的「識別詞+值」字串——
 17193	      - fold-check <value>  (識別詞=fold-check, value=\S+)
 17194	      - \d+\.\.\w+          (整串當 key, 如 2..depth,key 為後綴詞 e.g. depth,value 為前導數字)
 17195	
 17196	    同一識別詞出現不同值 → 一筆 {key, a, b}。
 17197	    Returns list[dict] with keys: key, a, b.
 17198	    """
 17199	    # Step 1: 排除審計修正紀錄段(從標題行到下個 ## 標題或 EOF)
 17200	    # C2 fix: only strip the audit section itself, not everything after it.
 17201	    m = _FOLD_AUDIT_RECORD_RE.search(text)
 17202	    if m:
 17203	        audit_start = m.start()
 17204	        # Find the next ## heading *after* the audit heading
 17205	        next_h2 = _FOLD_NEXT_H2_RE.search(text, m.end())
 17206	        if next_h2:
 17207	            # Keep text before audit section + text from next heading onward
 17208	            scan_text = text[:audit_start] + text[next_h2.start():]
 17209	        else:
 17210	            # Audit section is the last section — truncate to before it
 17211	            scan_text = text[:audit_start]
 17212	    else:
 17213	        scan_text = text
 17214	
 17215	    # Step 2: 單一抽取法 — 掃值 pattern,抽取「識別詞+值」對
 17216	    # fold-check \S+ : identifier="fold-check", value=next non-whitespace token
 17217	    # \d+\.\.\w+ : e.g. "2..depth", "1..depth"
 17218	    seen = defaultdict(set)
 17219	
 17220	    for m2 in _FOLD_DRIFT_FOLD_CHECK_RE.finditer(scan_text):
 17221	        val = m2.group(1)
 17222	        seen["fold-check"].add(val)
 17223	
 17224	    for m2 in _FOLD_DRIFT_DOTDOT_RE.finditer(scan_text):
 17225	        token = m2.group(0)
 17226	        # The suffix (\w+) is the concept identifier; the prefix (\d+) is the value.
 17227	        # e.g. "2..depth" → key="depth", val="2"
 17228	        parts = token.split("..")
 17229	        if len(parts) == 2:
 17230	            key = parts[1]   # e.g. "depth"
 17231	            val = parts[0]   # e.g. "2" or "1"
 17232	            seen[key].add(val)
 17233	
 17234	    # Step 3: flag any key that has more than one distinct value
 17235	    drifts = []
 17236	    for key, vals in seen.items():
 17237	        if len(vals) > 1:
 17238	            val_list = sorted(vals)
 17239	            drifts.append({"key": key, "a": val_list[0], "b": val_list[1]})
 17240	
 17241	    return drifts

 17256	
 17257	    掃描域排除 ## …審計修正紀錄 段(複用 _FOLD_AUDIT_RECORD_RE/_FOLD_NEXT_H2_RE)。
