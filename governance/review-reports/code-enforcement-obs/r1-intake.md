分級 high(1 席 + 架構對齊 + 外家否決)。被審的是「#19 enforcement 可觀測性」的實作。
★這批改的是閘本身與五支 hook★——弄壞了會讓所有「防護生效」的結論不可信。

## 收貨三道

| 席 | quote-check | seat-check |
|---|---|---|
| 通才 | ✅ 全數錨定(正規化後) | 觀測 |
| 架構對齊 | ✅ 全數錨定(正規化後) | 觀測 |

正規化:三席都有引「其他檔的既有碼」當對照組(既有落帳器、既有環境變數、既有的
`Systems/hook信任邊界` 原文、`.gitignore`…),那些本來就不在凍結 patch 裡。
照 SOP 把它們從 `引句:` 轉成「對照(引自其他檔,非被審材料)」標籤——
★`引句:` 這個標籤照規定是留給被審材料的原文★。轉完三席全錨。

## ★這一輪三席各抓到一個 blocker,三個我都自己重現過★

### 1. 安裝清單沒帶共用模組——★裝了等於沒裝★(通才 + 外家,兩席獨立命中)

五支 hook 都 `from _hookevent import guard`,但安裝的複製清單只有那五支主檔。
通才席直接跑了真正的複製函式,再跑這台機器上**真的已註冊**的 hook 指令,
證明事件檔行數**完全沒有增加**——五支全部 import 失敗、被 try/except 吞掉、靜靜退回不記帳。

我複驗:清單裡確實只有五個檔名。**HIT。**
★而且來源樹的測試照樣全綠——因為它們測的是來源樹,不是安裝副本。★

處置:加進複製清單,守衛寫成**通則**(`t_installed_hooks_bring_their_local_imports`):
凡是被複製的 hook 所 import 的本地模組,都必須也在清單裡。

### 2. 時間戳格式在 Python 3.11 以前讀不動(通才席,兩個版本實跑對照)

寫入用 `time.strftime("%Y-%m-%dT%H:%M:%S%z")`,吐的偏移量**沒有冒號**;
讀取用 `datetime.fromisoformat`,★那在 3.11 之前不吃無冒號格式★。

我複驗:同一台機器上 3.14 讀得動、**3.9 直接 ValueError**。
而 3.9 是這個 repo 的下限、3.10 是 Ubuntu 22.04 內建版本。**HIT。**
後果是「兩秒前才成功記的一筆」被判成沒跑過——★儀表板在那些機器上永久 stale,
正好打臉這批的核心賣點★。

**而我的測試原本測不到它**:消費端測試自己造事件時用帶冒號的格式,
**從沒真的呼叫過寫入器**——生產端與消費端用了不同的資料產生方式,兩邊格式從沒被放在一起驗過。
新守衛 `t_hook_event_timestamp_roundtrips_on_old_python` 把它們接起來,
而且會在這台機器上找得到的每一個 python 版本各跑一次。

### 3. 我沒查圖譜就走了一條被明文反對的路(架構對齊席)

`Systems/hook信任邊界`(2026-09-06 立,早這批兩天)明文寫:
「hook 是獨立檔,安裝時會被複製到 `~/.claude/hooks/`,**複製過去之後彼此 import 不到**」
——所以既有的決定是「複製 + 守衛」,**不是抽共用模組**。而我做的正是抽共用模組。

架構席還當場重現了第二半:`ANCHOR_FILES` 沒收這支新檔,
所以 `anchor verify` 直接失敗、**會擋住這批自己的推送**——而錨點那道是這批自己寫明
「永遠不可跳」的。我複驗:`anchor verify` 當場回「多了 1 支沒登記的檔」。**HIT。**

**處置分兩層**:
- **錨點名單補上**(無爭議),重新核可,`anchor verify` 轉綠。
- **共用模組這條路不撤,但要正面訂正那篇筆記**——因為那句話的前提是
  「複製清單只複製那五支主檔」,而把共用模組也放進清單就改掉了前提。
  ★這不是繞過,是把前提改掉,而且要付兩條守衛的代價★(複製清單 + 錨點名單,漏一個就退化成
  「裝了等於沒裝」而且測試全綠)。訂正已寫進 `Systems/hook信任邊界`,並說明兩種做法
  現在是刻意並存:**解析函式維持逐字複本**(它跟安全邊界綁在一起)、**事件寫入器走共用模組**。

## 其餘折入的六條(各自查證過)

- **hook 內部吞掉的逾時被記成 ok**(外家 blocker):派工鏡頭那支有「捕捉逾時 → 附說明 →
  正常 return 0」的路徑,而包裝器只看得到有沒有丟例外。★一支每次都逾時的 hook 會穩定顯示
  「跑過 N 次」★,而宣告的 `timeout` 類別原本沒有任何接線寫得到。處置:吞掉的那一方自己 `mark`。
- **兩個跳閘疊成完整放行**(外家 major,我實測屬實):旗標跳掉合約測試閘 + 環境變數跳掉留痕
  ——**直接推翻「合約測試閘不可跳」**。處置不是把話改小,是不准疊。
- **S7 沒蓋到 hook 事件那本帳**(外家 major):寫入錯誤吞成 False 而包裝器不看回傳值。
- **觀測用的探測會排擠本業**(外家 major):每支 hook 本業之前多跑一次 git,逾時原設 10 秒
  ——跟 hook 預算同量級。實測正常態約 13 毫秒,砍到 3 秒。
- **`stale` 這個新狀態漏改消費端**(架構 major,它當場重現):摘要的分母排除清單沒收它、
  圖示字典沒有這個鍵會印問號。★這批想解決假訊號,卻在另一個角落製造一個新的假訊號。★
- **「這個 repo 沒有這本帳」被講成「寫不進去」**(通才 major):沒跑過 init 的 repo 本來就沒有
  `docs/`,那是結構性、每次都會發生、永遠不會自己好。★那種警告久了會被忽略,恰好抵銷這批
  想建立的信任。★ 改成回「不適用」,對齊既有姐妹寫入器的靜默。
- **同一個閘名兩套欄名**(架構 major):既有寫入器用 `detail`/`branch`,新的用 `note`/`ref`,
  同一個 `gate="code-loop"` 的歷史要認兩套。處置:兩邊都寫。
  ★誠實記:時間語意的不一致沒有解掉★——既有那支的時間戳是 HEAD 的提交時間,
  新的是呼叫當下的機器時間。兩者混在同一個 gate 底下用時間窗查會語意不一致,
  這一批沒動它(改既有寫入器的時間語意會動到已經在帳上的歷史)。REVISIT:2026-12-08。

## ★折的過程中我自己造了一個 bug,既有測試接住了★

架構對齊席在講欄名不一致時順帶寫了一句:
「副作用是 `_codeloop_read_from_ledger` 永遠讀不到這批新事件——**目前不算功能性錯誤
(新事件本來就不該被當成 marker)**」。

★我把那句話當成「一個不一致」去修,順手加了分支識別欄——而它其實是在講一個保護。★
加上去之後,`blocked` 事件當場被留痕讀取器當成「審過了」的憑證讀走,
既有測試 `t_codeloop_check_diff` 翻紅。

**這是「席位順口提到的東西,我沒讀懂它在保護什麼就動手」**。
處置兩道:①落帳器不寫分支識別欄 ②讀留痕時只認 `passed`/`skipped` 兩種 kind
——★別讓「哪些 kind 算留痕」只靠欄位有沒有寫★。新守衛 `t_blocked_events_are_never_read_as_markers`,
兩個突變體都翻紅。
