# r1 收貨(code-鎖身份含內容)

standard 分級:正確性-sonnet 加架構對齊-sonnet,只審鎖身份那一個提交(119 行)。quote-check 全數錨定、report-normalize 不用改。本輪沒有 major。

## 發現

| id | 來源席 | 一句話 |
|---|---|---|
| L1 | 正確性 F1 | 寫到一半出錯的清理在關檔後才比,別人換入的空鎖或前綴內容會被當成自己的刪掉 |
| L2 | 正確性 F2、架構對齊 F1 | 啟動失敗後讀不到自己的鎖,被當成「已不是我的」回報乾淨,清鎖失敗的訊號消失 |
| L3 | 正確性 F3 | 寫入失敗那條清理路徑沒有測試守 |
| L4 | 架構對齊 F2 | 建鎖端改用內容判身份,釋放端仍比第一行 PID,兩套準則並存 |

## 重現表

| id | 怎麼試 | 結果 |
|---|---|---|
| L1 | t_excl_lock_creation_failure_cleans_own_file 加一格:寫入失敗、關檔那一刻換入空鎖 | HIT:舊程式刪掉別人的空鎖 |
| L2 | 新測試 t_lens_spawn_failure_unreadable_lock_reports_cleanup_error:Popen 失敗、讀鎖丟 PermissionError | HIT:舊程式回報乾淨 |
| L3 | 同 L1 那支加「短寫一個位元組後失敗」一格 | 成立(補測試) |
| L4 | 讀 _vault_write_lock 釋放與 _lens_release_owned_lock | 成立(兩套並存) |

## 處置

- L1 折入:寫入失敗時趁 fd 還開著比路徑與 fd 的 inode(開著時不會被重用),確定是自己的才刪、最後才關檔;拿掉「前綴也算」的寬鬆判斷。關檔本身報錯時內容已整份寫完,照內容比。
- L2 折入:_excl_lock_is_mine 只把「鎖已不在」當 False,其他讀取錯誤往外丟,啟動失敗那條路接住後回報清鎖失敗。
- L3 折入:補兩格測試(短寫後失敗清掉自己的半成品、關檔後換入的空鎖保留)。
- L4 放行:釋放端在別的程序(背景工作、另一次寫入),手上沒有建鎖時的識別碼,第一行 PID 是它們唯一拿得到的憑據;建鎖端多寫的識別碼不影響它們讀第一行。
