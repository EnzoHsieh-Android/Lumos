## 判讀(判準是編排者自己想的,不照席位給的)

- F13:判準不列舉寫法,改成看「去掉引號後的值本身」——以 [ 或 { 開頭(單一連結 [[X]] 除外)、或值裡有兩個以上 [[ 就擋。
  讀的一側的 lint(只認 `]], [[` 與 `]],[[`)刻意不動:放寬會讓既有筆記在提交檢查時新翻紅,不在這批範圍。
  加引號那種嚴格說在格式上是「一個字串」,轉換不改變讀的一側看到的東西;但寫的人十之八九是想寫清單,默默保留一筆壞值不如擋下請人改。
- F14:已存在=真的不做事(不改寫、不寫檔),訊息講「已經有了,檔案沒動」;清單寫法的重複值原本也印「多了一項」,一併修。
- F15:席位判 minor 的理由是「只影響排序加分」;編排者補一句——排序加分拿這個值比對 git 的改動路徑(大小寫敏感),寫錯就永遠對不上。
- F16/F17:about_code 的比對鍵統一成「字面正規化」(斜線統一、去 ./ 與 ..,不查檔案),append 去重與 remove 找項共用;remove 不要求檔案還在。
- F18:改用安裝端同一個常數。
- code 迴圈:輪內有 major,accepted 必須是空的——六條全折。
