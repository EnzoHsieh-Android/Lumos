## finding 1:單一「開頭欄位只有一個 `---`」的記憶檔,會讓整支清掃器當場崩潰,連累其他檔都不驗

跑法:在 `/tmp` 建一個乾淨的記憶目錄,放一篇這種檔——只有開頭一個 `---`、沒有第二個 `---` 收尾,但帶了一條會失敗的 `verify`:

```
---
title: test
verify:
  - claim: 這件事還沒發生
    file-exists: /tmp/nope-does-not-exist
metadata:
內文
```

跑 `python3 memory-sweep.py --dir <該目錄> --write`,結果不是「蓋不了章、印一句警告」,而是整支 Python 直接 Traceback、`exit=1`:

```
ValueError: substring not found
  File "memory-sweep.py", line 304, in stamp
    body_at = text.index("---", text.index("---") + 3) + 3
```

原因:`stamp()` 假設檔案一定有兩個以上的 `---`(用 `text.index("---", text.index("---")+3)` 硬找第二個),但 `shadow_copies()`/`pointer_problems()` 都有 `t.count("---") >= 2` 這層防呆、唯獨 `stamp()` 沒有。只要記憶檔是手寫、被截斷、或曾經被別的工具寫壞(開頭欄位沒收尾),而且剛好有一條驗不過的宣稱,`--write` 這條路就必炸。

引句:「body_at = text.index("---", text.index("---") + 3) + 3」

severity: blocker
blocking: 是

## finding 5:`--restore` 帶不存在的檔名,或帶 `../` 開頭路徑會逃出記憶目錄改別的檔

跑法 A(不存在的檔名):

```
python3 memory-sweep.py --dir <記憶目錄> --restore nope-does-not-exist.md
```
結果:`FileNotFoundError` 未接住,整支崩潰、`exit=1`。

跑法 B(路徑穿越,實際改到記憶目錄外面的檔):

```
echo "outside-secret-content" > /tmp/memsweep-test/outside.md
python3 memory-sweep.py --dir <記憶目錄> --restore "../outside.md"
```
結果:

```

exit=0
```

`/tmp/memsweep-test/outside.md`(在記憶目錄之外)真的被讀出來、跑過 `unstamp()`、再寫回去——`f = here / a.restore` 沒有檢查算出來的路徑是否還留在 `here` 底下。這次測試裡 `unstamp()` 對這個檔案幾乎是無害的(它沒有 `status: stale` 或 MARK 那行可拿掉,寫回內容不變),但機制上這是一個沒有邊界檢查的「用任意相對路徑讀寫檔案」的入口:一旦 `--restore` 的參數來源不是使用者直接手打(例如由 agent 依對話內容組出檔名、或未來被別的腳本包一層轉呼叫),`../../../../某處/檔案` 就能讓這支工具去動記憶目錄以外的檔案。跟這支檔案自己「不要有能被記憶內容拿到執行任意指令的入口」的設計初衷矛盾——這裡的入口不是內容而是參數,但同樣沒設防線。

跑法 A 的 `FileNotFoundError` 崩潰不需要任何特殊條件,`--restore` 打錯檔名就會發生,這部分本身足以構成阻斷理由;跑法 B 的路徑穿越則需要 `--restore` 的呼叫端傳入不受信任的路徑才會被觸發到——目前已知唯一的呼叫端(`scripts/merge-claude-settings.py`)沒有把使用者輸入接到這條路上,但程式本身完全沒有邊界檢查是事實。

引句:「f = here / a.restore」

## finding 7:`file-exists:`/`no-file:` 型別值留空,不會被判「驗不了」,而是靜靜給出錯誤答案

跑法:

```
cat > <記憶目錄>/emptyval.md <<'EOF'
---
title: t
verify:
  - claim: 忘了填路徑,理論上這個宣稱早就不成立
    file-exists:
metadata:
---
body
EOF
python3 memory-sweep.py --dir <記憶目錄> --write
```

結果:`跑了 1 條檢查(已蓋章)`,但完全沒印出任何「對不上了」或「驗不了」——因為 `pathlib.Path("").expanduser()` 在這台機器上等於 `PosixPath('.')`,而 `.` 永遠存在,所以空字串的 `file-exists:` 恆為 True,claim 被判「仍然成立」,永遠不會被蓋章。反過來,把同一個空字串接到 `no-file:` 上:

```
cat > <記憶目錄>/emptyval3.md <<'EOF'
---
title: t
verify:
  - claim: 忘了填路徑
    no-file:
metadata:
---
body
EOF
python3 memory-sweep.py --dir <記憶目錄> --write
```

結果變成恆為 False,claim 被判「對不上了」、永久蓋章,且因為值永遠是空字串,`no-file` 這條檢查以後每次跑都還是 False,**這篇記憶就再也撤不了章**(不像正常情境「條件回復成立時下次清掃自己撤掉章」)。

這兩種情況都違反這支程式自己在 `check_one()` 註解裡講的「★驗不了不判死★」設計原則——漏填值(打字漏打、YAML 縮排錯導致值被吃掉)這麼常見的手誤,結果不是被歸類成「型別不認得、參數格式不對」(回 None、印「這條驗不了」),而是被 `_chk_file_exists`/`_chk_no_file` 直接吃成一個確定的布林答案,而且兩種型別給出的是相反方向的錯——一個永遠裝沒事,一個永遠鎖死說有事。

引句:「return not pathlib.Path(arg).expanduser().exists()」

severity: major
blocking: 是

## finding 9:`pushed`/`not-pushed` 檢查一旦連到打不通的遠端,單一檢查可以吃掉遠超過整支 hook 預算(12 秒)的時間,budget 機制對它完全沒用

跑法:在乾淨的臨時 git repo 裡把 `origin` 指到一個會被連線黑洞掉的位址(`http://10.255.255.1/nonexistent.git`),設好 upstream 追蹤,寫一條 `not-pushed` 的記憶,照 hook 實際掛法帶 `--write --quiet --budget 12`(`12` 是 `scripts/merge-claude-settings.py:82` 裡登記給這支 hook 的天花板)去跑:

```
git -C /tmp/gitrepo remote add origin http://10.255.255.1/nonexistent.git
git -C /tmp/gitrepo branch --set-upstream-to=origin/main main
# 記憶檔:verify: - claim: 這個提交還沒推到遠端 / not-pushed: <該 repo 的 HEAD sha>
time python3 memory-sweep.py --dir <記憶目錄> --write --quiet --budget 12
```

結果:

```
python3 memory-sweep.py ...  0.08s user 0.05s system 0% cpu 25.142 total
exit=0
```

整支跑了 25 秒才回來,是掛在設定檔裡的 12 秒天花板的兩倍以上。原因:`check_one()` 裡的「還剩多少預算」只在**開始跑下一條檢查之前**判斷要不要提早收手(`deadline and (deadline - time.monotonic()) <= 0`),完全不管一條檢查本身要跑多久;而 `_is_pushed()` 呼叫的 `_git("fetch", ..., timeout=25)` 本身就給了 25 秒的逾時——比這支自己宣告的「單條檢查最多跑這麼久」`PER_CMD_CAP = 15.0` 還久,而 `PER_CMD_CAP` 這個常數在整支程式裡從頭到尾沒有任何地方真正拿來用(定義了但沒有任何函式讀它)。

這正是這支程式自己在檔案開頭的「內層預算」註解裡明講要避免的那種失敗模式——「內層一定要明顯小於外層⋯外層會先 SIGKILL,繞過所有 try/except⋯這支的收尾動作是印出『還有幾條沒驗到』,跑不到就等於默默假裝驗過了」——但 `pushed`/`not-pushed` 這條路徑完全沒被這套內層預算邏輯管到:一旦專案的 git 遠端連不通(離線、VPN 沒開、遠端下架、DNS 解析卡住都算),使用者這次開專案就要多等超過 12 秒,而且被真正的外層 hook timeout(harness 端的 SIGKILL)腰斬時,連「還有幾條沒驗到」這句誠實話都印不出來。

引句:「_git("fetch", "-q", up.split("/")[0], cwd=root, timeout=25)」

severity: major
blocking: 是
