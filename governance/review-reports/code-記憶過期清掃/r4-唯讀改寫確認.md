## finding 3 — `frontmatter()` 對 UTF-8 BOM 開頭的檔案整篇解析失敗,所有 verify claim 靜靜消失、連 `?missing` 都不報

`frontmatter()` 用 `text.startswith("---\n")` 判斷有沒有開頭欄位。如果檔案開頭帶 BOM(`﻿`,很多
Windows 編輯器存 UTF-8 檔案的預設行為),`text` 實際上是 `"﻿---\n..."`,`startswith("---\n")` 為
False,`frontmatter()` 直接回 `None`,`verify_blocks()` 因此回空陣列——不是 `?missing`,不是任何一種
「看不懂要出聲」,就是完全消失,跟「這篇根本沒寫 verify:」在輸出上無法區分。

這是這次改寫**引入的退化**:舊寫法用 `re.search(r"(?m)^verify:\n...", text)` 直接對全文搜尋,BOM 只
影響檔案最開頭那一個字元,不影響後面某一行是不是以 `verify:` 開頭——同一份 BOM 檔案,舊寫法能正確抓到
`verify:` 區塊,新寫法整篇失效。

實測(頭對頭比較):
```python
txt_c = "﻿---\nname: x\nverify:\n  - claim: C\n    installed: git\n---\n\n正文\n"
ms.frontmatter(txt_c)                 # None
ms.verify_blocks(txt_c)               # []  ← 這篇的 claim C 整條消失,沒有任何警告
re.search(r"(?m)^verify:\n...", txt_c)  # 舊寫法:命中,能正確抓到 claim C
```

severity: major
blocking: 是
引句:「★只解析這一段★(r1 外家席 major):原本搜整份文字,正文裡的程式碼範例也會被當成檢查。」
查證:`scripts/hooks/claude/memory-sweep.py:275`-`281`(`frontmatter()` 的 `startswith("---\n")` 判斷)。

## finding 5 — `verify:` 區塊裡一個空白行、或用 tab 縮排,會讓整段(甚至後面本來寫得完全正確的 claim)一起靜靜消失

`verify_blocks()` 先用 `re.search(r"(?m)^verify:\n((?:[ ]+.*\n)+)", fm)` 把整個 `verify:` 清單一次
撈出來,這個正則要求每一行都以「至少一個半形空格」開頭。這代表:
1. 清單項之間如果手誤留了一個空白行(常見的排版習慣),`(?:[ ]+.*\n)+` 在空白行就斷掉,只有空白行**之前**
   的內容進得了 `m.group(1)`;空白行後面的所有 claim(包括完全合法、型別鍵齊全的)整段消失,不進任何
   `verify_blocks()` 的回傳,`?missing`/`?listitem` 這些「要出聲」的分支根本沒機會跑到,因為它們是逐行
   掃 `m.group(1)`,而空白行後面的內容從一開始就不在 `m.group(1)` 裡。
2. 如果整個清單用 tab 縮排(而不是空格),`[ ]+` 完全不匹配,`m` 直接是 `None`,整個 `verify:` 區塊(哪怕
   只有一條、寫得完全正確)蒸發,回傳空陣列,跟「這篇沒寫 verify:」無法區分。

實測:
```python
# 空白行截斷,B 完全消失(不是 ?missing,是直接不在回傳裡)
t = mk("  - claim: A\n    installed: git\n\n  - claim: B\n    installed: git\n")
ms.verify_blocks(t)   # [('A', 'installed', 'git')]   ← B 整條不見

# tab 縮排,整段消失
t2 = mk("\t- claim: tab indented\n\t  installed: git\n")
ms.verify_blocks(t2)  # []
```
這條外層正則沒有被這次 delta 改動內容本身(只是把作用範圍從 `text` 換成 `fm`),但既然這次審查的題目就是
「`verify_blocks` 的五種『看不懂要出聲』還有沒有任何寫法會靜靜消失」,這兩種是目前程式碼裡真實存在、會
造成整段(不只一條)靜靜消失的寫法,值得記錄。

severity: major
blocking: 是
引句:「★任何看不懂的寫法都不准靜靜丟掉★——一律收下、型別記成 `?<原因>`,上層報成」
查證:`scripts/hooks/claude/memory-sweep.py:296`(外層 `re.search(r"(?m)^verify:\n((?:[ ]+.*\n)+)", fm)`,
只認半形空格續行、遇空白行斷開)。

### 項目 8 之一 — `git fetch` 算不算違反「唯讀,不改任何檔」

檔案裡唯一的 `subprocess` 呼叫是 `_git()`,而 `_is_pushed()` 會呼叫 `_git("fetch", "-q", ...)`——`git
fetch` 確實會寫進當前專案自己的 `.git/`(更新 remote-tracking ref、下載物件、寫 `FETCH_HEAD`),嚴格來說
不是「零檔案異動」。但這是**這次 delta 沒有碰過的既有行為**(`pushed`/`not-pushed` 這兩種宣告式檢查從
