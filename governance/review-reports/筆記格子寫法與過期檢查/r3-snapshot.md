## 格子規格(統一文法,寫進紀律範本,前綴定義的唯一來源)

**一種文法**:

```
<前綴>:<核心一句> [鍵:值] [鍵:值] …
```

- **欄位**:只有鍵名在白名單(下表加〈鍵的意思〉)裡的 `[鍵:值]` 才是欄位;其他方括號(`a[0:3]`、`[RFC:9110]`)是正文的一部分。欄位可以寫在句子前面或後面(既有 RULE 多半寫在前面)。
- **核心一句**:整行去掉前綴與所有欄位之後剩下的文字(前後空白不算);WHY 放決定、RULE 放限制、PITFALL 放症狀、FACT 放現況。核心一句空的算缺。
- **值**:可以含成對的方括號(`[[連結]]`、`[0-9]`、`app/[id]/page.tsx` 都行,解析器數括號層數);方括號不成對算這一格寫錯,印「值裡的方括號要成對」。值空的算缺。
- **重複鍵**:`[test:]` `[applies:]` `[不選:]` `[同族:]` 可以寫多次(多支測試、多個範圍);其他鍵寫兩次算寫錯(擋)。`[test:a,b]` 的逗號寫法照舊可用。
- **適用範圍**:只看摘要區塊的前綴行;圍欄、行內程式碼、表格裡的示範行不算;摘要裡縮排更深、不以前綴開頭的續行接回上一行一起判。
- **各前綴的差別只剩「哪些鍵必有」**:一張表,lint 與提交時的擋都讀它。

| 前綴 | 核心一句 | **必有鍵**(新寫的行缺了提交時擋) | 常用選填鍵 |
|---|---|---|---|
| WHY | 決定 | `[出處:]` `[因:]` | `[不選:]` `[代價:]` `[test:]` `[applies:]` |
| RULE | 限制 | `[依據:人\|外部\|審計\|法規\|相容]` `[since:日期]` `[retire:機器式之一]`;`[retire:人裁]` 另必有 `[until:日期]` | `[confirmed:日期]`(要挑戰程式碼就必須半年內)`[test:]` `[applies:]` `[until:日期]` |
| PITFALL | 症狀 | `[出處:]` `[根因:]`,再加 `[test:]`、`[repro:指令]`、`[防回歸:無 理由]` 三選一 | `[觸發:]` `[修法:]` `[影響:]` `[同族:]` |
| FACT/FLOW/DEP | 現況與數值 | `[來源:部署\|資料庫\|生產\|外部\|人工]` `[confirmed:日期]` | `[recheck:週期]` `[查:指令]` `[applies:]` |
| SEE(新) | 不寫句子 | 至少一個 `[[連結]]`,連結以外不准有字 | — |
| 任一前綴標作廢時 | — | 加上 `[status:superseded]` 就必須有 `[被取代:…]` | — |

- **鍵的意思**:`[出處:]`=這句話從哪來(日期加對話、審查、事故);`[依據:]`=誰或什麼規定了這條限制;`[來源:]`=這個現況值從哪裡觀測(既有鍵);`[confirmed:]`=最後一次確認還成立的日期(既有鍵,RULE 與 FACT 共用——FACT 原本提的觀測日期併進這裡);`[被取代:]`=這行作廢後改看哪裡,值是 `[[節點]]`、全域決策編號 `節點#dN`(跟 `decision-add` 印的同一種,單寫 `d3` 算寫錯),或 `無 <理由>`(限制自然消失、沒有接手的);不用 `by`,因為 `by` 在回頭條件裡已經是期限日期;也不用「取代」,讀起來像「我取代誰」,方向相反。
- **作廢的兩個地方**:節點開頭的決策(`decisions:`)被翻案,照舊用 `lumos decision supersede`(寫 `superseded_by`);摘要裡的前綴行作廢才用 `[status:superseded] [被取代:]`。同一件事若兩邊都有,行上的 `[被取代:]` 指到新決策的 `節點#dN`。
- **日期**一律 `YYYY-MM-DD`(只認這個寫法,不收 `20261001`、週日期);`[since:]` `[confirmed:]` 晚於今天算寫錯;`[until:]` 可以是未來。
- **撤除條件的機器式**(D):
  - 事件:`[retire:when-file:路徑]`、`[retire:when-symbol:路徑::名稱]`、`[retire:when-test:路徑::名稱]`、`[retire:when-status:節點=值]`——跟回頭條件同一套條件語法(既有 `_PROBE_KEYS` 四種)與同一個值文法檢查;一行只放一個 `[retire:]`。符號與測試必帶路徑,比回頭條件嚴:RULE 行長命、數量多,不帶路徑的候選每次推送都要讀全庫測試檔(回頭條件數量少,維持原寬度)。
  - 度量:`[retire:度量 <閘>.<種類> <比較> <整數> 近<N>週]`。閘與種類只收治理帳裡真的有的組合(白名單從 `_gate_event_or_warn` 的呼叫點整理,例 `note-shape.blocked`、`drift-check.skipped-env`);比較只收 `<` `<=` `>` `>=` `==`;N 是 1 到 26。數的是整個閘的事件數,不是這條 RULE 自己的(治理帳不認得是哪條 RULE 觸發的)。治理帳的歷史短於 N 週、或這條 RULE 的 `[since:]` 不滿 N 週,不判(暖機)。
  - 人裁:`[retire:人裁]` 加必有的 `[until:日期]`。
- **確認週期**:`[recheck:N天|N週|N月]`,N 是 1 到 999、中間不留空白,一個月算 30 天;寫不成週期的提醒一次,改用來源預設(生產 30 天、資料庫 90 天、外部 90 天、部署 90 天、人工 180 天,本篇新訂)。
- **同族掃描**(F,選填):同一形狀第二次以上出事的 PITFALL 建議寫 `[同族:查了幾處、結果]`。
- **範圍**(G):`[applies:]` 只寫具體路徑或模組。
- **SEE**(C):就是「只放連結的 DEP」換個名字,算計劃連結時跟 DEP 的連結同等對待;骨架留的空前綴(`DEP:`、`SEE:` 什麼都沒寫)照舊不算違規。
- **過程紀錄**:不開前綴、不進摘要(跟 [[Projects/筆記標籤_過時判定與按需載入_計劃]] 一致)。
- **不套格子**:合約行(`KEY:★INVARIANT★` 等)、PRIOR-ART、DECISION、TEST、VERIFY、AUTH、FLAG、CORE、REVISIT、RETIRE-IF;工具自己寫的固定樣板行,列一張豁免清單(`lumos guard plan` 寫的預告句,以及 `lumos guard settle` 轉正後帶「已轉正」尾巴的同一句,同否定現況句提醒的樣板豁免)。重建筆記(regen)寫的行不豁免:第 0 步把 skill 裡 regen 的寫法一起改成新文法。
- **代價**(承認):理由、根因原本可以寫成一句通順的話,現在要放進方括號,可讀性差一點;換到的是機器認得出、擋得住。

例子(反引號只是排版,實際寫的時候不加):

```
PITFALL:分派入口收到空清單會靜默成功 [出處:2026-09-30 事故] [根因:呼叫端沒判空] [test:t_dispatch_empty_list]
WHY:改用結構化欄位記植入型別 [出處:2026-08-05 Enzo] [因:散文帳不可重算] [不選:維持散文]
RULE:分析行程不准有送提案以外的寫入呼叫 [依據:審計] [since:2026-09-23] [retire:when-file:sandbox/policy.yaml] [test:t_analyzer_no_write]
FACT:點數商城兌換約十幾 TPS、零競爭 [來源:生產] [confirmed:2026-08-13] [recheck:30天]
WHY:改用逐行判定 [出處:2026-09-01 審查] [因:整篇判太粗] [status:superseded] [被取代:Projects/新判法_計劃#d2]
```

## 擋(提交時,只看新寫的行)

- **掛在筆記形狀檢查**:同一條路——新增行、違規清單、`LUMOS_SKIP_NOTE_SHAPE=1` 單次跳過留帳、CI 照擋(淺複製的 CI 除外,見天花板 5)。
- **開不開由掛鉤的旗標決定**:格子規則只在掛鉤呼叫 `note-shape --staged --slots` 時才跑;舊掛鉤只有 `note-shape --staged`,格子規則不跑。程式全機即時生效,但掛鉤要各專案更新,所以「程式上線」跟「開擋」分開:
  - 提交時:沒帶 `--slots` 就整段跳過格子規則。
  - 推送、CI、doctor 事後掃描:用 `note-shape --staged --slots` 這串當格子自己的上線點記號;**找不到這個記號 = 格子規則整段不跑**(明寫的例外——既有上線點找不到時是「不過濾、全查」,格子不能照抄,否則程式一上線就把整段歷史當新違規)。找得到就只查記號出現之後的提交。
  - 推送與 doctor 只抽取一趟新增行,逐提交記下那個提交的掛鉤有哪幾個記號,再把格子規則只套在有格子記號的提交上;不為格子多跑一趟 git(doctor 事後掃描既有成本約 500 個提交 9 秒,不因格子加倍)。
  - 筆記形狀檢查原本的規則照舊用原本的記號 `note-shape --staged`(新記號包含舊記號,舊規則照常認得)。
- **改到舊行不算新寫**:新增行若在「上一版」裡有同前綴、同核心一句的行(只差在欄位),算改了欄位的舊行,不套必有鍵——補 `[confirmed:]` 重新確認舊 RULE、補連結都不會被擋。細節:
  - 「上一版」:提交時是 HEAD 那一版;推送時是推送範圍的起點那一版(不是逐提交的上一個提交,所以第一個提交用單次跳過放進的違規行,第二個提交只改欄位,推送時照樣查得到);改名照既有改名偵測帶回舊路徑。
  - 跨篇搬移:同一次提交(推送時為同一範圍)裡別篇被刪掉的行若有同前綴、同核心一句,也算舊行(拆節點、併節點不被迫改寫)。
  - 核心一句是空的永遠不算舊行(空的跟空的不算同一句)。
  - **例外**:這次才加上 `[status:superseded]` 的行(上一版沒有),一律要有 `[被取代:]`——作廢幾乎都是改舊行做的,不能被舊行豁免吃掉。
- **撤除條件提交時就驗寫法**:新寫(含改了 `[retire:]` 值)的 RULE 行,`[retire:when-*]` 的值跑既有的值文法檢查(同回頭條件第一層的擋),寫錯當場擋;不留到推送時才被濾掉、變成永遠不觸發的死條件。
- **子開關(新增)**:`note_shape.slots`(`block` 預設 / `warn` / `off`)。跟總開關的關係:總開關 `note_shape.gate` 是 off 時整道不跑;總開關是 warn 時格子違規也只提醒;總開關是 block 時照 slots 的值。壞值照 block 並講一句;slots 不是 block 時 doctor 講一句(同既有開關的先例)。
- **擋下訊息**:每條印缺哪幾格、該前綴的一行範本、把這行的核心一句填進範本(核心一句超過 120 字截斷,控制字元清掉);一次最多印 20 條,其餘印總數。標題寫「筆記格子缺漏」,不沿用「程式碼推得出來的形狀」那句。
- **治理帳**:用結構欄位記(同否定現況句提醒的 `extra` 寫法),不塞說明字串——擋下事件 `extra={"check":"slots","lines":條數,"missing":{鍵:次數},"notes":[筆記路徑]}`;單次跳過時先算一次格子違規(只是新增行的字串比對),跳過事件也帶 `extra={"slots_lines":條數,"notes":[筆記路徑]}`,RETIRE-IF 才配得起來(提交前寫帳時新提交還沒有編號,改用「30 分鐘內、同一批筆記路徑」配對)。被擋下的行文字不進帳,抽查從 git 歷史重建(擋下後同路徑的下一個提交)。
- **範圍**:所有專案的新寫行(Enzo 先前裁定寫法規則不分新舊專案);一個 repo 有多個圖譜時只查第一個(既有限制,見天花板 8)。

## lint 與擋同一張表

- 既有 lint 的脈絡標記規則(WHY 要出處、PITFALL 要防回歸、FACT 要來源)與筆記形狀檢查的前綴規則,改成讀本篇的必有鍵表;RULE 六個鍵的既有解析(含值被 `]` 截斷的提醒)改成呼叫新的欄位解析器,不留兩套。
- lint 對整篇筆記只提醒。**怎麼分新舊**:冒號後第一個東西是 `[日期` 開頭的方括號(舊式出處),或 RULE 的 `[retire:]` 不是機器式,算舊寫法,照舊判準、不因新表多唸;其他都算新文法、用新表。
- 舊判準的表留著,因為舊筆記不轉換;撤掉的條件:工具鏈圖譜裡 lint 數到的舊寫法行歸零。

- 測試把「紀律範本的必有鍵表」與「程式裡的必有鍵表」釘在一起:比對的是「前綴 → 必有鍵集合」這個投影(範本那邊先拆表格、去掉反引號與 `\|` 轉義),不是比 markdown 原文。

## 格子欄位的過期檢查

| 欄位 | 什麼時候算過期 | 擋或提醒 | 掛在哪 |
|---|---|---|---|
| `[retire:when-*]` | 條件在這次推送從不成立變成立;或這次新寫(改了條件)時條件已經成立 | 擋(推送) | 存量漂移檢查:新寫一段從 RULE 行抽出 `[retire:when-*]`,交給既有的回頭條件判定(同一個轉變判定);**已標 `[status:superseded]` 的行不抽**(標作廢就是處理完了,下一次推送不再擋);預算排在回頭條件之後、用剩下的,不跟回頭條件搶;判不了的另成一張清單、帶種類標記,只列出不擋(既有的回頭條件判不了照舊擋),兩張清單的輸出都最多 20 條加總數、控制字元清掉;子開關 `drift_check.retire`(`block` 預設 / `warn` / `off`,同 `drift_check.old_sentence` 的寫法),誤報成批時只關這一段;新種類登記進 `drift ack` 與種類名稱表 |
| `[retire:when-*]` | 工作目錄裡條件現在已成立(兜底:轉變那次判不了或被跳過就再也不會被擋) | 提醒 | doctor(沿用 `drift scan` 的工作目錄判定) |
| `[被取代:]` | 指到的節點或決策不存在、或它自己也作廢了(節點 `status: superseded`,或決策 `valid: false`) | 提醒 | doctor;只看一跳,不沿鏈(叫人改指到最新的那個);`無 <理由>` 不查(不擋,維持「人寫的連結只列出」的既有決定) |
| `[retire:度量 …]` | 近 N 週的事件數符合比較 | 提醒 | doctor;一次 doctor 只讀一遍治理帳檔尾(上限照既有 24MB),所有度量共用 |
| `[confirmed:]` `[until:]`(RULE) | RULE 超過半年沒確認;`[until:]` 到期(含人裁) | 提醒 | 不新做:lint 既有的 RULE 生命週期提醒,加上 [[Projects/筆記標籤_過時判定與按需載入_計劃]] 的 doctor 段(`t_doctor_lists_stale_rules`) |
| `[confirmed:]`(FACT) | 超過 `[recheck:]` 或來源預設 | 提醒 | doctor(不計入問題數;`--ci` 也最多 20 條加總數) |
| `[test:名]` | 測試不存在 | 擋(推送) | 不在本篇:依賴路線圖 1b「所有筆記的 `[test:]` 驗存在」那案;那案上線前只驗有寫(天花板 3) |
| `SEE:` 連結 | 連到的筆記不存在 | 提醒 | doctor 既有的斷連結檢查 |
| 數量、值、錨點 | 見 [[Projects/依賴欄位_過時判定_計劃]] 的〈待解問題〉 | — | 本篇第 4 步另開設計審 |

時間到期一律只提醒;只有「條件因為這次推送剛成立」這種跟改動有關的才擋。

## 天花板

1. **擋得住「格子空著」,擋不住「格子亂填」**:有寫、內容空洞的機器分不出,靠分類判定者與 RETIRE-IF 抽查。
2. **理由、根因、代價只能驗有沒有寫,驗不了對不對**。
3. **`[test:]` 在路線圖 1b 上線前只驗有寫**:寫一個不存在的測試名也能過防回歸那格。
4. **閘的開關讀被推送版本裡的設定**:同一個提交可以把 `note_shape.slots` 改成 off,只防疏忽。
5. **淺複製的 CI 不跑**:筆記形狀檢查與存量漂移檢查在淺複製下都會跳過(既有行為),靠本機掛鉤與 doctor 的 CI 提醒補。
6. **時間類的過期只提醒**。
7. **改到舊行的判定靠「同前綴、同核心一句」**:核心一句改一個錯字就算新寫,要補齊必有鍵。
8. **一個 repo 有多個圖譜時只查第一個**:沿用筆記形狀檢查既有的範圍(既有限制,本篇不改)。
9. **度量數的是整個閘,不是單條 RULE**:治理帳不記是哪條 RULE 觸發的。

## 不做

- 不轉換、不檢查舊筆記;不改 `lumos init`。
- 不開 LOG 前綴;過程紀錄不進摘要。
- 不在推送時擋 `[被取代:]`;不沿鏈追。
- 不擋時間到期;不在推送時跑 `[repro:]` 的指令。
- 不做 `[expect:]`(漂移路線圖機制 3 提過的「條件帶預期防觸發錯位」)與「撤除條件提交時當場求值」:撤除條件在提交時只驗寫法,成立與否交給推送時的轉變判定與 doctor 兜底;錯位問題等真的出現再開案。依賴欄位那份的〈不收〉曾否決行內 `[retire-when-*]`,本篇翻案的理由:Enzo 裁「一個固定標籤加某個符號」,所有前綴的格子統一寫在行內,撤除條件不再另起一行。
- 數量、值、錨點的機械判定在第 4 步另外設計。

## 實務隱患

- **併發**:新增寫入只有治理帳(沿用既有);兩個推送各自對遠端舊值算範圍。
- **效能**:必有鍵是新增行的字串比對;撤除條件只看這次推送改到的路徑、符號與測試必帶路徑,不掃全庫,預算排在回頭條件之後;doctor 的度量一次只讀一遍治理帳檔尾;推送與 doctor 的格子檢查共用既有的一趟抽取。
- **資源**:不開長駐程序。
- **相容**:舊行不查、不轉換;舊寫法在 lint 照舊判準;範本改動會讓消費專案的紀律區塊檢查提醒到 `lumos update` 為止(既有行為),所以範本改動集中在第 0 步一次做;程式即時全機生效,但格子規則要掛鉤帶 `--slots` 才跑,找不到格子記號就整段不跑,所以程式上線不等於開擋步。
- **注入**:擋下訊息與判不了清單回填的筆記內容截斷並清掉控制字元。
- **自我治理(誤擋的逃生口)**:單次跳過 `LUMOS_SKIP_NOTE_SHAPE=1`(提交時,既有)與 `LUMOS_SKIP_DRIFT_CHECK=1`(推送時,既有);整類降級 `note_shape.slots: warn`、`drift_check.retire: warn`;撤除條件那條另可 `drift ack`;PITFALL 真的沒有防回歸可寫 `[防回歸:無 <理由>]`;限制自然消失、沒有接手的寫 `[被取代:無 <理由>]`。
- 已排除:金流:只讀筆記與程式文字,不碰任何交易或付款流程
- 已排除:對外送出:不呼叫外部服務、不寄送任何東西
- 已排除:不可逆:不改資料、不刪筆記;擋都能用子開關降級
