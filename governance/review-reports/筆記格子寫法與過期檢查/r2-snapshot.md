# 筆記格子寫法與過期檢查_計劃

> 白話:把每個前綴的內容固定成幾個「格子」,一律寫成 `[鍵:值]`。例如一條 PITFALL 寫症狀一句,再附 `[出處:]` `[根因:]` 與防回歸的測試。必有的格子缺了,提交時擋下並印出範本讓人照填;只看新寫的行,舊筆記不動。格子裡指向別處的東西(撤除條件、取代者、確認日期)再各自接過期檢查——這是「靠標籤防止過期」真正落地的地方。

- 兩次分類實驗與三輪設計審:[[Projects/筆記標籤_過時判定與按需載入_計劃]]。

PRIOR-ART: ①最小解在既有層——擋沿用筆記形狀檢查的新增行抽取、違規清單、單次跳過與擋下流程(它已經在擋「FACT 沒帶來源」「新寫行號引用」),只是多一張必有鍵表與自己的上線點;撤除條件的機器式寫法直接沿用回頭條件的 `when-*` 條件語法與轉變判定;lint 的脈絡標記規則與本篇的必有鍵讀同一張表 ②世界解過——PITFALL 的格子對照 Google SRE 事故報告範本(影響、根因、觸發、修法、發現途徑);WHY 對照 MADR(選項、決定、理由、代價、確認方式);取代鏈對照 ADR 的 Superseded by ③裁定=borrow-design;新文法的欄位解析器是新能力(既有的只認 RULE 六個鍵、遇 `]` 截斷)。

## 格子規格(統一文法,寫進紀律範本,前綴定義的唯一來源)

**一種文法**:

```
<前綴>:<核心一句> [鍵:值] [鍵:值] …
```

- **核心一句**:冒號到第一個 `[鍵:` 之間的文字;WHY 放決定、RULE 放限制、PITFALL 放症狀、FACT 放現況。核心一句空的算缺。
- **其他格子一律 `[鍵:值]`**:鍵名固定(下表);值可以含 `[[連結]]`(新的欄位解析器認得成對的雙括號),但不能有單獨的 `]`;值空的算缺;同一個鍵寫兩次算寫錯(擋)。
- **各前綴的差別只剩「哪些鍵必有」**:一張表,lint 與提交時的擋都讀它。

| 前綴 | 核心一句 | **必有鍵**(新寫的行缺了提交時擋) | 常用選填鍵 |
|---|---|---|---|
| WHY | 決定 | `[出處:]` `[因:]` | `[不選:]` `[代價:]` `[revisit:]` `[test:]` `[applies:]` |
| RULE | 限制 | `[依據:人\|外部\|審計\|法規\|相容]` `[since:日期]` `[retire:機器式之一]` | `[confirmed:日期]`(要挑戰程式碼就必須半年內)`[test:]` `[applies:]` `[until:日期]` |
| PITFALL | 症狀 | `[出處:]` `[根因:]`,再加 `[test:]`、`[repro:指令]`、`[防回歸:無 理由]` 三選一 | `[觸發:]` `[修法:]` `[影響:]` `[同族:]` |
| FACT/FLOW/DEP | 現況與數值 | `[來源:部署\|資料庫\|生產\|外部\|人工]` `[confirmed:日期]` | `[recheck:週期]` `[查:指令]` `[applies:]` |
| SEE(新) | 不寫句子 | 至少一個 `[[連結]]` | — |
| 任一前綴作廢時 | — | 有 `[status:superseded]` 就必須有 `[取代:[[節點]]或決策編號]` | — |

- **鍵的意思**:`[出處:]`=這句話從哪來(日期加對話、審查、事故);`[依據:]`=誰或什麼規定了這條限制;`[來源:]`=這個現況值從哪裡觀測(既有鍵);`[confirmed:]`=最後一次確認還成立的日期(既有鍵,RULE 與 FACT 共用——FACT 原本提的觀測日期併進這裡);`[取代:]`=作廢後由誰取代(不用 `by`,因為 `by` 在回頭條件裡已經是期限日期)。
- **日期**一律 `YYYY-MM-DD`,寫錯格式算缺。
- **撤除條件的機器式**(D):
  - 事件:`[retire:when-file:路徑]`、`[retire:when-symbol:路徑::名稱]`、`[retire:when-test:測試名]`、`[retire:when-status:節點=值]`——跟回頭條件同一套條件語法(既有 `_PROBE_KEYS` 四種),一個方括號一個條件。
  - 度量:`[retire:度量 觸發次數|跳過次數 <比較> <數字> 近<N>週]`,指標只收這兩個(白名單,其他指標算寫錯)。
  - 人裁:`[retire:人裁]` 加 `[until:日期]`。
- **確認週期**:`[recheck:N天|N週|N月]`;寫不成週期的提醒一次,改用來源預設(生產 30 天、資料庫 90 天、外部 90 天、部署 90 天、人工 180 天,本篇新訂)。
- **同族掃描**(F,選填):同一形狀第二次以上出事的 PITFALL 建議寫 `[同族:查了幾處、結果]`。
- **範圍**(G):`[applies:]` 只寫具體路徑或模組。
- **SEE**(C):取代只放連結的 DEP/FLOW;骨架留的空前綴(`DEP:`、`SEE:` 什麼都沒寫)照舊不算違規。
- **過程紀錄**:不開前綴、不進摘要(跟 [[Projects/筆記標籤_過時判定與按需載入_計劃]] 一致)。
- **不套格子**:合約行(`KEY:★INVARIANT★` 等)、PRIOR-ART、DECISION、TEST、VERIFY、AUTH、FLAG、CORE、REVISIT、RETIRE-IF;工具自己寫的固定樣板行(例:`lumos guard plan` 寫的預告句,列一張豁免清單,同否定現況句提醒的樣板豁免)。
- **代價**(承認):理由、根因原本可以寫成一句通順的話,現在要放進方括號,可讀性差一點;換到的是機器認得出、擋得住。

例子(反引號只是排版,實際寫的時候不加):

```
PITFALL:分派入口收到空清單會靜默成功 [出處:2026-09-30 事故] [根因:呼叫端沒判空] [test:t_dispatch_empty_list]
WHY:改用結構化欄位記植入型別 [出處:2026-08-05 Enzo] [因:散文帳不可重算] [不選:維持散文]
RULE:分析行程不准有送提案以外的寫入呼叫 [依據:審計] [since:2026-09-23] [retire:when-file:sandbox/policy.yaml] [test:t_analyzer_no_write]
FACT:點數商城兌換約十幾 TPS、零競爭 [來源:生產] [confirmed:2026-08-13] [recheck:30天]
WHY:改用逐行判定 [出處:2026-09-01 審查] [因:整篇判太粗] [status:superseded] [取代:[[Projects/新判法_計劃]]]
```

## 擋(提交時,只看新寫的行)

- **掛在筆記形狀檢查**:同一條路——新增行、違規清單、`LUMOS_SKIP_NOTE_SHAPE=1` 單次跳過留帳、CI 照擋。
- **自己的上線點**:提交前掛鉤多一行格子專用的記號(新字串),格子規則從「掛鉤第一次出現這個記號」那個提交起算;升級前寫好、升級後才推的提交不查。筆記形狀檢查原本的上線點(`note-shape --staged`)照舊管它原本的規則。
- **改到舊行不算新寫**:新增行若在同一篇筆記的上一版裡,有同前綴、同核心一句的行(只差在方括號欄位),算「改了欄位的舊行」,不套必有鍵;這樣補 `[confirmed:]` 重新確認舊 RULE、補連結都不會被擋。核心一句改了才算新寫。
- **子開關(新增)**:`note_shape.slots`(`block` 預設 / `warn` / `off`)。跟總開關的關係:總開關 `note_shape.gate` 是 off 時整道不跑;總開關是 warn 時格子違規也只提醒;總開關是 block 時照 slots 的值。壞值照 block 並講一句;slots 不是 block 時 doctor 講一句(同既有開關的先例)。
- **擋下訊息**:每條印缺哪幾格、該前綴的一行範本、把這行的核心一句填進範本(核心一句超過 120 字截斷,控制字元清掉);一次最多印 20 條,其餘印總數。標題寫「筆記格子缺漏」,不沿用「程式碼推得出來的形狀」那句。
- **治理帳**:擋下事件的說明欄多記格子違規條數與各鍵缺漏次數,RETIRE-IF 從這裡量。
- **範圍**:所有專案的新寫行(Enzo 先前裁定寫法規則不分新舊專案)。

## lint 與擋同一張表

- 既有 lint 的脈絡標記規則(WHY 要出處、PITFALL 要防回歸、FACT 要來源)與筆記形狀檢查的前綴規則,改成讀本篇的必有鍵表。
- lint 對整篇筆記只提醒:新文法的行用新表;舊寫法的行(行首 `[日期 出處]`、自由文字 retire)照舊判準,不因新表多唸。
- `[防回歸:無 理由]` 算有防回歸;RULE 的 `[status:superseded]` 訊息從「整行刪掉」改成「留著並寫 `[取代:]`」。
- 測試把「紀律範本的必有鍵表」與「程式裡的必有鍵表」逐字釘在一起(散落同步的守衛)。

## 格子欄位的過期檢查

| 欄位 | 什麼時候算過期 | 擋或提醒 | 掛在哪 |
|---|---|---|---|
| `[retire:when-*]` | 條件在這次推送從不成立變成立 | 擋(推送) | 存量漂移檢查:新寫一段從 RULE 行抽出 `[retire:when-*]`,交給既有的回頭條件判定(同一個轉變判定、同一個預算);`when-symbol` 必須帶路徑(不做全庫掃符號);判不了只列出、不擋(跟這次改動無關);輸出最多 20 條加總數;新種類登記進 `drift ack` 與種類名稱表 |
| `[取代:]` | 指到的節點或決策不存在、或它自己也作廢了 | 提醒 | doctor;沿鏈最多 10 層,遇到環就停並提醒(不擋,維持「人寫的連結只列出」的既有決定) |
| `[retire:度量 …]` | 近 N 週的指標符合 | 提醒 | doctor(只讀治理帳近 N 週的事件) |
| `[retire:人裁]`+`[until:]` | 日期到了 | 提醒 | doctor |
| `[confirmed:]` | RULE 超過半年;FACT 超過 `[recheck:]` 或來源預設 | 提醒 | doctor(不計入問題數) |
| `[test:名]` | 測試不存在 | 擋(推送) | 依賴路線圖 1b「所有筆記的 `[test:]` 驗存在」那案;那案上線前只驗有寫(天花板) |
| `SEE:` 連結 | 連到的筆記不存在 | 提醒 | doctor(既有斷連結檢查若已涵蓋就沿用) |
| 數量、值、錨點 | 見 [[Projects/依賴欄位_過時判定_計劃]] 的〈待解問題〉 | — | 本篇第 4 步另開設計審 |

時間到期一律只提醒;只有「條件因為這次推送剛成立」這種跟改動有關的才擋。

## 分期(每一步各自實作、各自過代碼審;回退由後往前)

## 天花板

1. **擋得住「格子空著」,擋不住「格子亂填」**:有寫、內容空洞的機器分不出,靠分類判定者與 RETIRE-IF 抽查。
2. **理由、根因、代價只能驗有沒有寫,驗不了對不對**。
3. **`[test:]` 在路線圖 1b 上線前只驗有寫**:寫一個不存在的測試名也能過防回歸那格。
4. **閘的開關讀被推送版本裡的設定**:同一個提交可以把 `note_shape.slots` 改成 off,只防疏忽。
5. **淺複製的 CI 不跑**:筆記形狀檢查與存量漂移檢查在淺複製下都會跳過(既有行為),靠本機掛鉤與 doctor 的 CI 提醒補。
6. **時間類的過期只提醒**。
7. **改到舊行的判定靠「同前綴、同核心一句」**:核心一句改一個錯字就算新寫,要補齊必有鍵。

## 不做

- 不轉換、不檢查舊筆記;不改 `lumos init`。
- 不開 LOG 前綴;過程紀錄不進摘要。
- 不在推送時擋取代鏈。
- 不擋時間到期;不在推送時跑 `[repro:]` 的指令。
- 數量、值、錨點的機械判定在第 4 步另外設計。

## 實務隱患

- **併發**:新增寫入只有治理帳(沿用既有);兩個推送各自對遠端舊值算範圍。
- **效能**:必有鍵是新增行的字串比對;撤除條件只看這次推送改到的路徑、`when-symbol` 必帶路徑,不掃全庫;doctor 的度量只讀治理帳近 N 週。
- **資源**:不開長駐程序。
