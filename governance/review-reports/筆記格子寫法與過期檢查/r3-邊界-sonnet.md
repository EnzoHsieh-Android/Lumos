固定席筆記:這次的任務說明和 spec 尾端都沒有 hook 附上的固定席筆記,所以沒有可逐條判的項目。

整體判斷:r2 的各條修補大多有補上,但補丁和既有程式銜接的地方有 6 個 blocking 問題。照 spec 字面做,會做出「每次推送都被誤擋」「已處理的規則永遠被提醒」「合法的行被誤擋」這類錯行為。

## 重點發現

**R3B1**
severity: major
blocking: 是。照字面做,每次推送都會被已成立的 RULE 撤除條件誤擋。
- 輸入:任何帶 `[retire:when-file:…]` 的舊 RULE 行,條件目前已成立。
- 壞在哪:spec 說「新寫一段從 RULE 行抽出,交給既有的回頭條件判定」,但既有判定靠「起點有沒有同一條」區分舊行與新寫。
- 這個比對只用 `_probe_lines` 解析起點筆記。`_probe_lines` 只認 `REVISIT:[when-…]` 行(`_revisit_split` 要求以 `REVISIT:` 開頭)。
- 所以起點永遠找不到 RULE 的條件。每條 RULE 都被判成「新寫或改了條件」,並被當成候選。
- `_drift_probe_judge` 的規則是「終點成立且起點沒有同一條就擋」。結果是每次推送都擋下所有已成立的 RULE 撤除條件。
- spec 的修補缺口:沒有要求起點端的抽取器與終點端共用同一支 RULE 抽取。
- 〈驗收條款〉的 S12 也沒有「新寫即已成立」和「舊行不被誤判成新寫」這兩個案例,抓不到這個錯。
- 引句:「交給既有的回頭條件判定(同一個轉變判定)」
- 佐證:`scripts/lumos:29195`(`_drift_probe_old`)、`scripts/lumos:28654`(`_probe_lines`)、`scripts/lumos:29222`(`_drift_probe_judge`)

**R3B2**
severity: major
blocking: 是。spec 規定的處理方式(標作廢)不能讓 doctor 提醒停下來,會變成永久雜訊。
- 輸入:撤除條件成立後,依 spec 標了 `[status:superseded]` 並寫了 `[被取代:]` 的 RULE。
- 壞在哪:推送那列明寫「已標作廢的行不抽」,但 doctor 兜底列和度量列沒有這個排除。S13 也沒有。
- 條件因為成立而保持成立,doctor 就永遠唸「現在已成立」。
- 既有的 RULE 生命週期提醒已經在 `st == "active"` 時才報 `[until:]` 到期和 180 天沒確認,有先例。
- 引句:「工作目錄裡條件現在已成立(兜底:轉變那次判不了或被跳過就再也不會被擋)」
- 佐證:`scripts/lumos:3388`(`rule_lifecycle_warnings` 只對 active 報到期)

**R3B3**
severity: major
blocking: 是。合法的行會被誤擋,又沒有跳脫寫法,且筆記工具鏈常寫到這類內容。
- 輸入一:正文裡用反引號舉例的欄位,例如 `` WHY:… 把 `[confirmed:]` 併進… ``。
  - 這個 repo 的摘要區塊就有(spec 自己的 WHY 行寫了 `[confirmed:]`、`[被取代:]`)。
  - 解析器若不剝行內程式碼,會把它當成值為空的欄位而擋下。
  - 解析器若沿用既有 `_strip_inline_markup`,遇到未閉合的反引號會把後面的真欄位整段丟掉,誤報「缺出處」。
- 輸入二:`[repro:]` 和 `[查:]` 的值是 shell 指令。例如 `grep -c "\[test:" f` 只有一個 `[`,「方括號要成對」會擋下,spec 沒有跳脫或例外。
- spec 只豁免了「示範行」(整行在圍欄、行內程式碼、表格裡),沒有講行內程式碼片段怎麼處理。
- 引句:「圍欄、行內程式碼、表格裡的示範行不算」
- 引句:「可以含成對的方括號(`[[連結]]`、`[0-9]`、`app/[id]/page.tsx` 都行,解析器數括號層數)」
- 佐證:`scripts/lumos:368`(`_strip_inline_markup` 的截斷語意)

**R3B4**
severity: major
blocking: 是。台北作者在本地凌晨寫的日期,推送時會被 CI 擋,而且 CI 不能單次跳過。
- 輸入:UTC+8 作者在本地 00:00 到 08:00 寫 `[confirmed:今天本地日期]`。
- 壞在哪:本地提交時過關。GitHub CI 的時區是 UTC,「今天」還差一天,同一行被判成「晚於今天」。
- 既有 `date.today()` 取的是本機日期,而且既有的未來日期只是提醒,不擋。
- 引句:「`[since:]` `[confirmed:]` 晚於今天算寫錯」
- 佐證:`scripts/lumos:3381`

**R3B5**
severity: major
blocking: 是。第 0 步的 lint 和第 1 步的擋都要用同一張必有鍵表,但 spec 把它放在兩個步驟,回退順序也會壞。
- 第 0 步寫「lint 改讀同一張表」「都在這一步」。
- 第 1 步又把「必有鍵表」列為擋的程式的一部分。
- 照字面,第 0 步的 lint 讀不到表,要不就退回「範本先換、lint 後換」的空窗,要不第 0 步自帶一張表而第 1 步重做。
- 〈回退〉先還原第 1 步,若表在第 1 步,第 0 步的 lint 會一起壞。
- 引句:「必有鍵表、`--slots` 旗標與格子上線點、舊行判定、提交時驗撤除條件寫法」
- 引句:「新的欄位解析器、lint 改讀同一張表、`[防回歸:無 理由]` 被認得、RULE superseded 訊息改寫——都在這一步」

**R3B6**
severity: major
blocking: 是。`近N週`(N 到 26)和「只讀 24MB 檔尾」不相容,會產生假提醒。
- 輸入:治理帳大於 24MB 的專案,條件寫 `< 5 近26週` 或 `== 0 近8週`。
- 現況:這份帳已 16MB,9 月一個月就約 75k 筆。依這個速度,24MB 檔尾大概只涵蓋幾週。
- 壞在哪:檔尾截斷,實際計數偏低,`<` 和 `==` 型的條件會誤報成立。
- 「暖機」只講歷史短於 N 週不判,沒說拿檔尾最早時間戳還是整檔最早時間戳。
- 引句:「一次 doctor 只讀一遍治理帳檔尾(上限照既有 24MB),所有度量共用」
- 引句:「治理帳的歷史短於 N 週、或這條 RULE 的 `[since:]` 不滿 N 週,不判(暖機)」
- 佐證:`scripts/lumos:2053`(24MB 上限)

**R3B7**
severity: minor
blocking: 否。逃生口要更安全,可在實作時補一句 fail-open,不影響其他設計。
- 現況:單次跳過在 `cmd_note_shape` 最前面印一句就 `return 0`,不碰 git 也不讀設定。
- spec 要它先算一次格子違規。
- 壞在哪:這個計算一旦丟出例外,Python 退出碼是 1,掛鉤把 rc=1 當作「擋」(`[[ "$ns_rc" -eq 1 ]] && exit 1`)。單次跳過本來是工具壞掉時的逃生口,反而變成擋。
- 否定現況句提醒就是「提醒失敗不能讓閘失敗」的先例。
- 引句:「單次跳過時先算一次格子違規(只是新增行的字串比對)」
- 佐證:`scripts/lumos:26370`、`scripts/hooks/pre-commit:230`

**R3B8**
severity: minor
blocking: 否。使用者會照著指令操作失敗,但解析規則本身清楚。
- 指令名:實際是 `lumos decision-supersede`,spec 寫成空格的 `lumos decision supersede`。
- 輸出格式:`decision-add` 只印「(編號 d2,目前有效)」,即 spec 說算寫錯的裸 `d3`。
- 回傳值:`節點#dN` 只是函式回傳值,從沒印出。而且 `rel` 帶 `.md`,和 spec 範例不同。
- 結果:使用者看 `decision-add` 的輸出會抄出被判寫錯的 `d2`。
- 引句:「全域決策編號 `節點#dN`(跟 `decision-add` 印的同一種,單寫 `d3` 算寫錯)」
- 引句:「照舊用 `lumos decision supersede`(寫 `superseded_by`)」
- 佐證:`scripts/lumos:16532`、`scripts/lumos:16390`、`scripts/lumos:40862`

**R3B9**
severity: minor

- 輸入:更新掛鉤前已寫好、未推的提交,之後 `pull --rebase`。

**R3B10**

## 實務隱患

- **併發**:無新增。只新增治理帳寫入,沿用既有做法。
- **效能**:有兩處。
  - R3B6:大帳檔尾讀取的取樣範圍與 `近N週` 不符。
  - doctor 事後掃描只看最近 200 個提交(`_NS_DOCTOR_SCAN_CAP`)。spec 的「約 500 個提交 9 秒」引的是 r1 的量測,不是實際上限,不影響行為。

- **相容**:有三處。
  - R3B9:rebase 流程破壞「不溯及既往」。
  - 掛鉤把 `note-shape --staged --slots` 的字面順序當成記號。重排參數會讓推送、CI、doctor 無聲關掉格子規則,spec 沒說要用測試把掛鉤字面釘住。
  - R3B3:行內程式碼處理未定。

- **金流、對外、不可逆**:已排除,同意 spec。它只讀筆記與程式文字,不碰交易、不外送、不刪資料。
