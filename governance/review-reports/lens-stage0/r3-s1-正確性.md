### f1

新版 `REDIRECT_RE` 的 negative lookbehind `(?<![<>&\d])` 為了不誤吃 `2>&1`,把「`>` 前面是數字或 `&`」整類都排除掉,連帶把 `1>`、`2>`、`&>` 這種合法、真的會寫檔的重導向也一起排除了,寫回被漏記。這跟 r2 f1 想修的「非結構化字串誤判」是相反方向的錯:那邊是不該算寫回的算了,這裡是真的寫回沒算。

引句:「REDIRECT_RE = re.compile(r"(?<![<>&\d])>>?\s*([^\s>&|;]+)")   # 不吃 2>&1、>/dev/null 另擋、不吃 <<」

severity: major

### f2

`_script_marks` 抓「路徑被賦給哪個變數」只認 `VAR = ...` 這種等號賦值形式,完全沒認 Python 最常見的 `with open(路徑) as f:` 語法——這種寫法不是賦值,`f` 是靠 `as` 綁定,不會被那顆正規式抓到。結果 `with open(N) as f: f.read()` 這種標準寫法整篇筆記路徑連候選 token 都被跳過讀寫判定,悄悄從量測消失。

引句:「m = re.search(r"(\w+)\s*=\s*(?:Path|pathlib\.Path|open)?\(?['\"]?[^'\"]*" + re.escape(tok.strip("'\"`,;:")), ln)」

file: `governance/eval/lens-utilization/recount.py:63`

severity: major
blocking: 是

重現(標準 `with...as` 讀檔,沒有任何 `=` 賦值):

### f4

新增的 `_safe_tokens` 為了讓 `$(cat a.md)` 這種黏住的括號能切出路徑 token,把 `$(`、`)` 直接換成空白。副作用是子殼裡的動詞(例如 `$(cat ... | head)` 的 `cat`)會被拆出來變成整個 segment 的第一個 token,被誤判成該 segment 的「動詞」;一旦動詞落在 `READ_VERBS`,後面所有 token(包含子殼外、`>` 之後真正的寫入目標)都會被無差別掃一遍 `norm_note` 加進 `read`——等於把「只被寫、沒被讀」的筆記也算成「有被讀到」,直接污染這支工具最核心的 `any`/`touched` 訊號。這個誤判在 delta 之前不會發生:舊版 `_tokens_of(seg)` 不拆括號,token 會是黏住的 `$(cat`,對不上 `READ_VERBS` 裡的 `cat`,所以不會誤觸這條分支(下面重現同時附對照組驗證)。

引句:「seg = seg.replace("$(", " ").replace("`", " ").replace(")", " ")   # 子殼/指令替換的括號先拆開,免得黏進 token(r2 s3)」

file: `governance/eval/lens-utilization/recount.py:44`

severity: major
blocking: 是

重現(out.md 只被寫入、從未被讀,新版卻把它算進 `read`;對照組印出拆括號前後的 token 差異證明是這顆改動造成的):
```
python3 -c "
import importlib.util
spec = importlib.util.spec_from_file_location('recount', 'governance/eval/lens-utilization/recount.py')
m = importlib.util.module_from_spec(spec); spec.loader.exec_module(m)
seg = '\$(cat docs/lumos-toolchain-knowledge/Systems/a.md | head) > docs/lumos-toolchain-knowledge/Systems/out.md'
print('新版 _safe_tokens:', m._safe_tokens(seg))
print('舊版 _tokens_of(未拆括號):', m._tokens_of(seg))
print('classify_bash:', m.classify_bash(seg, 'lumos-toolchain-knowledge'))
"
```
新版 token 是 `['cat', 'docs/.../a.md', '|', 'head', '>', 'docs/.../out.md']`(`cat` 被孤立出來當動詞),舊版是 `['\$(cat', 'docs/.../a.md', '|', 'head)', '>', 'docs/.../out.md']`(動詞黏著 `$(`,不會撞進 `READ_VERBS`);`classify_bash` 印出 `read={'Systems/out.md', 'Systems/a.md'}`——out.md 從沒被讀過,卻跟真正被讀的 a.md 一起被算進 `read`。
