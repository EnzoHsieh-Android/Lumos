以下是這輪 delta 新開的洞(recount.py 三條、impact-hook.py 一條、PIN_LINE 一條理論性但目前不可達)。

### f1

`_script_marks` 用「整行字串出現 read_text/write_text 就記」判讀寫,單行 `python3 -c "...; a.read_text(); b.write_text('x')"` 這種常見寫法(python -c 分號連寫,無換行)裡兩個變數的呼叫都落在同一行,函式對每個路徑都把整行當 `joined`,導致 a、b 兩個節點同時被記進 read 與 wrote——這條路徑只被讀、那條只被寫,結果卻是「兩篇都讀過也都寫過」,是誤判不是漏記,比純粹漏記更危險(會假造出「讀過」的正向訊號)。r2 自己補的 `hd3` 測試只測了多行版本(每個變數呼叫各自一行才靠 `lines[k+1:]` 往後查),沒測單行版本,所以沒接住。

引句:「joined = "\n".join(scopes)」

file: `governance/eval/lens-utilization/recount.py:69`

severity: major
blocking: 是

最小重現:
```python
classify_bash('python3 -c "from pathlib import Path; a=Path(\'docs/t-knowledge/Systems/a.md\'); '
              'b=Path(\'docs/t-knowledge/Systems/b.md\'); a.read_text(); b.write_text(\'x\')"', 't-knowledge')
```
回 `read={'Systems/a.md','Systems/b.md'}, wrote={'Systems/a.md','Systems/b.md'}`——b.md 明明只被寫卻也算進 read。

### f2

`_safe_tokens` 為了拆開 `$(`/`` ` ``/`)` 對整個 segment 做無條件字串取代,不看有沒有在引號內——真實筆記檔名若含半形括號(如「某功能(暫定).md」這種常見中文命名),這個 `)` 會在切詞前就被打成空白,把路徑攔腰打斷成兩個殘缺 token,`norm_note` 兩邊都比對不到而整段消失,跟 r2 剛修好的 f3(子殼括號黏 token)同根源、只是換了觸發條件。目前 vault 裡雖然還沒有這種檔名,但這是輸入端的通用穩健性缺陷,不是假設性 corner case。

引句:「seg = seg.replace("$(", " ").replace("`", " ").replace(")", " ")   # 子殼/指令替換的括號先拆開,免得黏進 token(r2 s3)」

file: `governance/eval/lens-utilization/recount.py:44`

severity: major
blocking: 是

### f3

`REDIRECT_RE` 的目標字元類排除 `|`,但沒把 noclobber 強制覆寫的 `>|` 運算子本身當一種合法重導向頭部處理——`>|` 後面接的路徑因為前面卡了一個不屬於目標字元類的 `|`,regex 在原位置直接吃不到目標、且該行沒有別的 `>`,所以整條 finditer 零命中,寫回被吃掉不留痕。比起 f1/f2 是窄範圍的單一運算子漏記,不會波及同指令其他偵測,影響面較小。

引句:「REDIRECT_RE = re.compile(r"(?<![<>&\d])>>?\s*([^\s>&|;]+)")   # 不吃 2>&1、>/dev/null 另擋、不吃 <<」

### f4

`_ttl_should_inject` 這輪把讀標記檔從 `float(content)` 改成 `float(content.split()[0])` 好相容新的「`<ts> <token>`」格式,但只 catch `(ValueError, OSError)`——標記檔若是空檔或純空白(disk full/程序中途被殺/併發寫入截斷,這份程式碼自己在別處已經承認有 race),`"".split()` 回 `[]`,`[0]` 丟的是 `IndexError`,不在 catch 清單裡,直接炸穿 `main()` 沒有任何外層 try/except 接住,整支 hook 非零退出、每次該 session/檔案的 Edit/Write 都會踩到同一顆壞標記檔而反覆炸,徹底違反這支 hook 全程強調的「fail-open」設計不變量。這是本輪唯一波及生產路徑(不是離線量測腳本)的洞,也是唯一會讓工具本身當掉的洞,故評為本輪最高風險項。

## 總結

r2 宣稱的六條修正(HEREDOC_RE 排 `<<<`、`_safe_tokens` 括號處理、shlex 失敗退回、引號內子指令再拆、norm_note 去空白、REDIRECT_RE 排 `2>&1`)真跑全部驗收通過,固定席合約本輪不受影響。但delta 本身新開四洞:`_script_marks` 對 python -c 單行寫法把讀寫互相誤標(f1,major)、`_safe_tokens` 的括號替換對含 `)` 的真實檔名一樣會整段打斷(f2,major,與剛修好的 f3 同根源換皮復發)、`>|` 運算子漏記(f3,minor)、TTL 標記檔壞檔會讓 `impact-hook.py` 直接炸穿違反 fail-open(f4,blocker,唯一波及生產路徑的洞);PIN_LINE 的 `.md)` 缺口理論存在但目前不可達(f5,minor)。四個 blocking 項裡最急的是 f4——不是量測腳本算錯數字,是現役 hook 會整支當掉。
