r2 針對 r2-s2 f1(`_ttl_unmark` 無條件 `unlink`、撤錯別人合法冷卻窗)的修法核對過,實際跑起來符合設計:標記內容改「`<ts> <token>`」、`_ttl_mark` 回 token、`_ttl_unmark(sid, f, token)` 讀檔比對 token 才刪,main() 的五個沒注入出口(lumos 不在 PATH、subprocess 例外、rc≠0、JSON 解析失敗、`inject_ranked_context` 回 False)全部改帶 `ttl_token` 撤,逐一核對(讀 code + 實際 mock 5 條路徑跑過)確認接線正確、無遺漏出口。派工詞裡的五個驗收情境都用倉庫的真函式重現過,結果見下面各條:情境一(A mark→A′誤判冷卻→A撤→C重跑)不是新問題、情境二(先寫者 unmark 不動、後寫者 unmark 撤)行為符合設計、舊格式標記不會永久卡住;但另外抓到兩個修法自己帶來的新缺口(f1 TOCTOU、f2 寫入失敗退回無條件刪除)。

### f2

最小重現(先讓 B 合法建立標記,再讓 A 這次的 `_ttl_mark` 寫入強制失敗、拿到 `token=None`,最後用這個 `None` 呼叫 `_ttl_unmark`):
```python
import importlib.util
from importlib.machinery import SourceFileLoader
from pathlib import Path as _Path
loader = SourceFileLoader('m', 'scripts/hooks/claude/impact-hook.py')
spec = importlib.util.spec_from_loader('m', loader)
m = importlib.util.module_from_spec(spec); loader.exec_module(m)

sid, f = 'scenD', '/tmp/scenD.py'
tokB = m._ttl_mark(sid, f)                      # B 合法建立標記
marker_path = m._ttl_marker_path(sid, f)
orig = _Path.write_text
def failing(self, *a, **k):
    if self == marker_path: raise OSError('simulated disk error')
    return orig(self, *a, **k)
_Path.write_text = failing
try:
    tokA = m._ttl_mark(sid, f)                  # A 這次寫入失敗 -> token=None
finally:
    _Path.write_text = orig
m._ttl_unmark(sid, f, tokA)                     # main() 的等價呼叫
print(not marker_path.exists())                 # True = B 的合法標記被 A 的失敗 unmark 撤掉
```
實測輸出 `True`——B 的合法標記被撤掉。

## 總結

r2 對 r2-f1 的修法本身接線正確(五出口、token 生成/比對、main() 判定與寫標記時機都核對過,`bound-tests-gate` 兩支測試 21 checks 全綠);派工詞列的五個驗收情境逐一用真函式重現,情境一、五個「對嗎」提問全部確認符合設計預期、非新問題(f3/f4/f5),`_ttl_lazy_cleanup` 成本是既有行為非本輪新增(f6);但修法自己帶進兩個新缺口:讀檔比對與 `unlink` 之間仍有一個縮小但未消除的 TOCTOU(f1,minor,窗口從 30 秒級縮到微秒級)、以及 `_ttl_mark` 寫入失敗時 `token=None` 會讓 `_ttl_unmark` 退回舊版無條件刪除、重新打開 r2-f1 原本要堵的洞(f2,major,但不需要精準時序、只要磁碟寫入失敗這個既有 fail-open 前提出現即可觸發)——兩條都因為觸發面窄且後果止於資源浪費(多跑一次全量 BFS),循 r2 同樣的標準判 blocking: 否。
