## 鏡頭 2:天數計算(fromisoformat 各種形狀 / max(_daysv) 空值)

`scripts/lumos:1027-1034`、`1037`。逐一构造实测:
- 帶 `+00:00`(header ts 一律由 `_utc_ts()` 產生,格式正是這種)→ 正常算出天數。
- 無 tz(naive)→ `tzinfo is None` 分支補上 UTC,正常。
- 非 iso 字串 / 空字串 → `fromisoformat` 拋 `ValueError`,被 `except ValueError` 接住計進 `_no_ts`,不炸。
- 未來 ts → `max(0, ...)` 夾成 0 天,符合注釋宣稱。
- 全部 ts 都非法(`_daysv` 為空)→ `max(_daysv)` 前有 `if _daysv else "建立時間不明"` 守衛,不會對空序列呼叫 `max()`。我用一份 ts="not-a-timestamp" 的帳本實跑,輸出「1 張連鎖待辦單自建立後零筆判定(建立時間不明)」,rc=0,沒有 crash。

## 鏡頭 4:supersede 白話指路兩行的位置

`scripts/lumos:16298-16308`。這裡有一個**已用實跑複現的真 bug**:T1b 新增的兩行 print 放在 `if _decision_id:` 區塊內、`CASCADE-EMPTY` 判斷之後,但**沒有被 `if _n:`(有沒有鄰居)包住**——不管 `cascade_surface` 印出幾條 `NEIGHBOR` 行,這兩行永遠印。當 `_n == 0`(零鄰居,`CASCADE-EMPTY` 觸發)時,程式先印「無 typed 連入鄰居」,緊接著又印「上面列的每個 NEIGHBOR 都要回頭判」——對著剛剛才說過「沒有列出任何東西」的空清單講「上面列的每個」。

實測復現(對一個沒有任何 typed 連入邊的決策跑 decision-supersede):
```
CASCADE c-20260825070127-abbb4a93 ROOT Projects/D.md#d1
CASCADE-EMPTY 無 typed 連入鄰居(本次翻案無已知依賴面)
已開連鎖待辦單 c-20260825070127-abbb4a93:上面列的每個 NEIGHBOR 都要回頭判——還受這條決策影響就 confirm、無關就 prune;下一步:
    lumos rel-cascade list
```
現有測試 `t_supersede_triggers_cascade`(scripts/test_lumos.py:1679)和新測試 `t_doctor_cascade_reminder` 用的都是「有一個鄰居」的 fixture,兩邊都沒測過零鄰居這條路,所以沒抓到。

finding:
severity: major / blocking: 是 / 判準:不改的話,每一次「翻案但沒有已知依賴面」(常見場景,不是稀有邊界)都會印出自相矛盾、誤導使用者/下游 agent 的指路文字,而這正是本 patch 要新增的核心功能(人話指路),做錯了會讓人去找一份不存在的清單。
