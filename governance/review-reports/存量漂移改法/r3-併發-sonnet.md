## F1 鎖外讀到的內容與鎖內要寫的內容沒有綁死,照字面實作會覆蓋別的會談剛寫的改動

blocking: 是 — 不改,實作者會用鎖外舊內容算改後全文、在鎖內原子取代,別的會談用 `lumos set` 剛加進同一篇的內容被靜默蓋掉

1. 第 1 步在鎖外用 `load_raw_for_edit` 讀一次;第 3 步鎖內只說「重建整個圖譜物件、重判」;第 4 步「算出改後內容」沒說用哪一份。第 2 步 dry-run 明寫用第 1 步的內容,字面讀第 4 步就是同一份。

## F2 「改之前沒有未提交改動」只在鎖外查一次,「git 一定退得回去」這個保證不成立
severity: major

引句:「先確認那一篇在 git 裡沒有未提交的改動(工作目錄與暫存區都乾淨;有就回 2」

## F3 「一律先確認乾淨」跟 c4 一項一項修、`--keep` 只寫表態檔互相打架
severity: major
blocking: 是 — 字面實作後,[S5] 與 [S11] 承諾的行為在同一個工作目錄裡做不到,實作者會被迫二選一放寬或加提交
引句:「同一欄有兩項以上含那三個詞時,一次修一項,每修一項那一項就不再含」
1. 第 1 步是所有種類共用的前置:那一篇有未提交改動就回 2。修第一項之後那篇已被改成未提交,同一分鐘修第二項必回 2,得先 commit(還得過 pre-commit 掛鉤)。計劃與 [S5] 都沒寫這點,文字讀起來像可以連續修。
2. 同樣的問題發生在同一篇驗證紀錄同時有 c3(status)與 c4(valid_under)時:修完 c3 才能修 c4,中間要提交;rtb 24 筆清單裡這種同篇多筆的比例沒有數,也沒排流程。
3. `--keep` 明寫「不改筆記、只寫表態檔」,卻仍要過第 1 步「那一篇要乾淨」;而直接下 `drift ack` 沒有這個限制。同一個動作兩個入口門檻不同,剛用 `--close` 改過、還沒提交的 Issue 也沒法補一筆別的表態。
4. 修法方向:把「乾淨」前置限定在會寫那一篇的種類(c1、c2 --close、c3、c4 帶參數、c5),`--keep` 與 c4 印證據不要求;並寫明同篇連續修要先提交或放寬成「未提交的改動全是本工具剛寫的、指紋對得上修復帳最後一筆」。

## F4 `guard settle` 補改 pass 節點沒有繼承 fix 的安全步驟,日期優先序在「鎖外推、鎖內變」時沒定
severity: major
blocking: 是 — 按字面實作,settle 補改這一條路沒有乾淨前置、沒有寫後驗證與還原,但修復帳與回退節照樣宣稱可退
引句:「鎖內發現需要日期、鎖外卻沒推(兩步之間被改過),回 2 要人重跑」
1. 第 3 節只說「走第 2 節同一支(前提、日期、不疊、修復帳 `via: guard settle`)」與「鎖的順序跟 fix 一樣」;沒有說第 1 節第 1 步(git 乾淨)、第 5 步(寫後重讀重判)、還原(指紋)、`LUMOS_DRIFT_FIX_FAULT` 也適用。字面實作只會得到:鎖外推日期、鎖內重判、寫、記帳。
2. 但〈修復帳〉說「要退回:……用 git 還原(第 1 節第 1 步確認過改之前沒有未提交的改動,所以一定退得回去)」,對 `via: guard settle` 的那幾筆不成立。
3. 日期優先序(`--date` > 正文已寫 > git)在鎖外算一次;鎖內若別的會談剛在正文補了一句「日期 已轉正」而且跟鎖外從 git 推的日子不同,第 3 節只處理了「鎖內需要、鎖外沒推」,沒處理「鎖內已有正文日期、鎖外用 git 推了另一個」——照優先序該用正文的,但實作者手上是鎖外那個,可能把兩個日子寫進同一篇([S2] 明寫「同一篇不出現兩個日子」)。

## F6 表態的 `ts` 沒定時區與同秒平手怎麼分
severity: minor
blocking: 否 — 最壞是多列一次或少列一次已知的表態,方向由 related 涵蓋關係把關,不會改壞筆記
引句:「取 `ts` 最新的那一筆,它的 `related` 涵蓋現在的清單(現在的是它的子集)才算已表態」
1. 「ISO 時間到秒」沒寫帶不帶時區偏移。兩個工作樹、或工具鏈與 rtb 的機器時區不同時,無偏移的本地時間字串比大小會排錯「最新」;與現有表態的 `date` 欄(`datetime.date.today()` 本地日期)同一個慣例,但這裡拿來決定新舊。
2. 同一個鍵在同一秒被兩個工作樹各寫一筆(合併後同在一檔)時,「最新」平手,而計劃已明寫「不依賴檔內順序」,所以取哪一筆沒定義。
3. 影響方向:取到 related 較小的一筆 → 重列(安全);取到較大的舊筆 → 少列一次。修法:`ts` 寫成帶偏移的 UTC,平手時取 related 較小的一筆(偏向重列)。
