# 舊句檢查_計劃

白話:程式裡某個函式、測試、旗標被刪掉或改名了,筆記裡還寫著它的句子就成了「舊句」,下一個讀筆記的人會照著去找不存在的東西。這份計劃把實驗選出來的判法做進推送前的漂移檢查:推送時把「這次消失的名稱」跟筆記比對,列出還在講它們的句子。先只提醒兩週、每次都記帳量準度,達標才改成擋。

依據:[[Projects/舊句偵測實驗_計劃]]〈實驗結果〉(2026-09-30,判法 P4r:9 題擋到 7 題、rtb 大提交要處理 16 筆、13 題非漂移誤列 0 題;沒拿來調參數的工具鏈對照組 4 筆列出 0 筆真);Enzo 2026-09-30 說「程式改了、筆記舊句還在,我要想辦法解決」,並授權編排者決策。本計劃用的判法是 P4r 再補工具鏈對照組點名的兩個誤報形狀(下稱 P4r2,〈做法〉2)。P4r2 重跑(`governance/eval/drift-exam/old-sentence/report-2026-09-30-p4r2.md`):9 題、rtb 大提交 16/65、rtb 182 個提交、13 題非漂移,跟 P4r 逐筆相同;工具鏈 300 個提交要處理 2→0,多放過的 3 句都是誤報——但那 3 句正是拿來設計這兩處改動的題,證據薄,只能說沒新增風險。實作的驗收以 P4r2 那份數字為準。

PRIOR-ART: ①判法照實驗的 P4r2,實驗程式 `governance/eval/drift-exam/old-sentence/old_sentence_exp.py` 是參考實作;抽定義擴充 `scripts/lumos` 既有的 `_drift_py_names`(同一組剖析例外、utf-8-sig 讀檔)與 `_drift_probe_is_py`(.py 或首行 shebang 含 python),不另寫第二份;筆記分區與圍欄用既有 `_notelines_regions`、`_visible_lines`;②接在既有的 `lumos drift check` 裡當一種新發現(沿用它的起點判法、表態檔、治理帳 gate 名),但判定另開一支函式、不放進 `_drift_check_core`(那支也給考試與歷史重放用,放進去會改掉既有噪音基準);③世界解:Doorstop/Swimm 的「錨點式 suspect」要先埋錨點,本專案筆記沒有錨點,所以走「比對消失的名稱」([[Projects/先問世界_存量掃描裁定]])。
RETIRE-IF: 兩週只提醒期滿(REVISIT 那天),「要處理」層每筆的真假由編排者照記帳抽判:準度低於 60%、或任一次推送超過 30 筆 → 不轉擋、留在提醒;再兩個月仍低於 60% → 整個撤掉。
REVISIT:2026-10-14 看舊句檢查兩週的提醒帳(`grep '"gate": "drift-check"' docs/.governance-log.jsonl | grep '"kind": "old-sentence'`,rtb 那份由本工具鏈的會談用跨會談訊息請 rtb 會談回報);準度與筆數照 RETIRE-IF 判轉不轉擋

## 範圍

- **做**:①`lumos drift check --diff` 多一種發現 `m1`(舊句):這次推送範圍裡,改到的 Python 檔在起點定義、終點整個 repo 都找不到的名稱,筆記裡還提到的句子;②撤除與歷史過濾(P4r2);③`m1` 的模式獨立一個開關 `drift_check.old_sentence`(warn/block/off,沒寫=warn),跟既有 c1–c5 與 probe 共用的 `drift_check.gate` 分開;④表態綁觸發的名稱;⑤每次有範圍的 drift check 都記一筆 `m1` 帳(含零筆),兩週後量準度;⑥定義快取照 blob 雜湊存,重複推送不重剖。
- **不做**:非 Python 的程式(只列一行「這次有 N 支非 Python 程式檔改動,舊句檢查不看」);`drift scan` 與健檢(doctor)跑舊句檢查(只有一棵樹,判不了消失);考試(`drift exam`,含 `--history`)跑 `m1`(考卷沒有這種題,另案);「新增程式檔喚醒否定句」(W,另案只提醒);常數改值(V)、新寫行提到找不到的名稱(P5/P6)、全歷史定義索引——實驗判定不做。
- **前置**:工具鏈自己的推送前掛鉤與 CI 要先接上 `drift check`([[Projects/存量漂移防線_計劃]]〈做法〉第 4 節,代碼審 `code-推送閘接漂移檢查` 在跑);沒接上,工具鏈這邊兩週沒有帳,REVISIT 只剩 rtb 的數。

## 做法

### 1. 抽「這次消失的名稱」

- 起點與終點:用 `drift check` 算好的那一對(`_note_audit_resolve` 回的起點,已截到上線點);起點是空樹(新分支找不到主線、或截到上線點前)時 `m1` 這次不判,印一行「舊句檢查:這次沒有起點版可比,不判」。
- 範圍裡改到的每支 Python 檔(`_drift_probe_is_py` 判定),起點版與終點版各剖一次,抽三類名稱:
  - **定義名**:所有 `def`/`class` 名(含巢狀與條件式)、模組層與類別層的指派名(擴充 `_drift_py_names`,加一個參數開類別層指派,既有呼叫端不變);
  - **旗標**:`add_argument` 登記的 `--旗標`;
  - **路徑**:這次被刪或改名的 Python 檔的舊路徑,和它的檔名。
- 形狀過濾:定義名要 4 個字以上、而且含底線或大小寫混合;旗標與路徑不受這條限制。
- 「消失」各類判準:定義名=終點**整個 repo 的所有 Python 檔**都沒有同名定義(不是逐檔比;實驗 P0→P1 從 69 降到 46);旗標=終點所有 Python 檔都沒有登記它;路徑=終點樹裡沒有這個路徑。
- 剖不動(語法錯誤、合併衝突殘留、記憶體或遞迴過深——沿用 `_drift_py_names` 的例外組):起點版剖不動的檔這次不判;終點版有剖不動的檔時,候選名稱再用文字比一次(那支檔裡有 `def 名`、`class 名`、`名 =` 或 `"--旗標"` 字樣就當它還在),不當成消失。輸出印「N 支剖不動」。
- 定義快取:每個 blob 的定義集合以 blob 雜湊為鍵,存在 `$(git rev-parse --git-common-dir)/lumos/defs-cache.json`(多工作樹共用;不進版控);最多留 20000 筆,超過時丟掉最久沒用到的;寫入走暫存檔、自驗讀得回、再原子替換;讀寫失敗或檔壞掉都當沒有快取、照常跑。終點整個 repo 的定義用快取組出來。

### 2. 找筆記裡的舊句(判法 P4r2)

- 掃圖譜筆記的正文、摘要(summary)、決策欄(`_notelines_regions` 的 body/summary/decisions);圍欄內不掃(`_visible_lines`);開頭欄位(about_code、related…)不掃。一行裡以整字出現消失的名稱就算提到(反引號內外都算)。
- **撤除節不看**:①節開頭(小標題後第一個非空行)是引用區塊或括號行,且含撤除字樣(實驗程式 `RETIRE_WORDS`:「撤除、撤掉、作廢、已失效、已過時、不是現況、被取代、已凍結、superseded、已結案、歷史紀錄」),但「尚未/還沒/未 + 撤除…」不算——整節連同子節不看;②節內任何一行獨立的引用區塊(`>` 開頭)含撤除字樣時,從那一行到節尾(含子節)不看(工具鏈對照組誤報第 4 筆——那句引用就寫在一級標題底下、宣告整篇後半是歷史紀錄,所以一級標題也適用)。
- **句內歷史字眼不列**:名稱所在那一句(在括號裡只看括號內,在括號外剝掉括號內容,再用句號、分號切)有歷史字眼就不列。字眼表照實驗程式 `HIST_WORDS` 逐字搬(`NEG_LEXICONS["zh"]` 常數,不讀專案的 neg_lexicon 設定,+「撤除、撤掉、拿掉、原寫、原本、原先、不再、舊版、舊的、刪除、刪掉、取代、搬到、搬去、改為、改叫、改成、曾、前身、撤、刪、拔掉、去掉、不帶、沒有」),再加三個詞組「當時叫、擴成、改名為」(工具鏈對照組誤報第 1、3 筆;**不收單字「叫」**,知識庫含「呼叫」的行有 748 行)。英文字整字比,中文照子字串比。字眼表放一個模組常數,測試逐項釘。
- **一筆 = 一行**:同一行提到好幾個消失的名稱只算一筆,那一筆帶**名稱集合**。
- **分層**:那一行所在的筆記是「這次任何一支改到的程式檔的家」(about_code 列了它),或那一行在摘要 → 要處理;其他 → 只列出。

### 3. 接進 drift check

- 判定另開一支(例 `_drift_old_sentence_check(root, base, tip, vault_rel, deadline)`,回要處理、只列出、剖不動支數、有沒有跑完),由 `cmd_drift_check` 在既有 c1–c5/probe 那段之後呼叫;`_drift_check_core`、考試、歷史重放都不動。
- **模式**:`_drift_config` 擴充,多回 `old_sentence` 的值(同一支讀同一個鍵,不另開第二支;讀被推送頂端提交的 `.lumos/config.json`,同既有 gate)。控制流:
  - `drift_check.gate=off` 只跳過 c1–c5/probe,`m1` 照自己的開關跑;
  - `old_sentence=off` 不跑 `m1`;warn:印、記帳、不影響回傳碼;block:要處理層有東西就讓 check 回 1;
  - `m1` 的要處理不進既有 `must` 清單,自己印、自己記帳;check 的回傳碼 = 既有那段的回傳碼與 `m1` 的回傳碼取大。
- **提示**:`_drift_fix_hint` 加一個名稱參數,對 `m1` 印「改寫或刪掉這句;確定照留就 `lumos drift ack <節點> <行號> --kind m1 --name <名稱> [--name <名稱>…] --reason "…"`」;`_drift_report_must` 那行通用 ack 句與 `_drift_print_hints` 的去重鍵都改成從同一處產生、去重鍵帶名稱集合。
- **種類登記**:`_DRIFT_KINDS` 與 `_DRIFT_KIND_NAMES` 加 `m1`(名稱「程式改了、筆記還在講舊東西」);`drift scan` 與 doctor 逐種類計數的迴圈排除 `m1`;`drift fix` 不收 `m1`(`_DRIFT_FIX_ALLOWED` 不動),提示不會指到它。
- **表態**:`drift ack --kind m1` 必須帶至少一個 `--name`(可重複;每個值走既有 `_drift_one_line` 一行檢查),其他種類帶 `--name` 回 2。`m1` 的表態記路徑、原文、種類、名稱集合;一筆發現的名稱集合**全部**被同路徑同原文的 `m1` 表態涵蓋才算已表態(仿 c2/c3 的 related 涵蓋);新名稱觸發同一行 → 照列。ack 當下不驗那一行現在真的是 `m1`(判定要範圍,ack 只有一棵樹)——〈誠實界線〉寫明。
- **治理帳**:這是新寫入點(既有 drift check 只在有要處理時記):每次 drift check 有跑 `m1` 就記一筆,gate `drift-check`,kind 依結果 `old-sentence-clean` / `old-sentence-warned` / `old-sentence-blocked` / `old-sentence-incomplete`(時間到或沒起點);note 帶「要處理 N、只列出 M、剖不動 K」與前 30 筆的 `路徑:行 名稱`,note 總長截到 2000 字;名稱與路徑先過 `_esc_clean`。
- **時間**:`m1` 用 drift check 同一個截止時間(`_DRIFT_BUDGET_SEC` 起算,前面那段用掉的就少了);每剖一支檔前、每掃一篇筆記前檢查;剖檔在行程內不可中斷,最壞多出一支檔的時間。時間到:warn 模式印「舊句檢查這次沒跑完(時間到)」、不算要處理;block 模式照既有「判不了算要處理」(放行等於一條繞過的路)。
- **終端**:筆記路徑、原文、名稱印出前過 `_esc_clean`。

## 條款

- [S1] 當推送範圍裡改到的 Python 檔有定義名、旗標或路徑在起點有、終點整個 repo 都沒有,工具應把筆記裡以整字提到它的行列成 `m1`,同一行多個名稱合成一筆帶名稱集合;終點別支檔還定義著同名的不列;終點剖不動的檔以文字比對仍找得到的不列;起點是空樹時不判並印明 [test:t_drift_m1_disappeared_names]
- [S2] 當提到消失名稱的行在撤除節(節開頭,或節內獨立引用區塊宣告之後)、或名稱所在那一句有字眼表裡的歷史字眼,工具應不列;「尚未撤除」不算撤除;含「呼叫」的句子不因此被放過 [test:t_drift_m1_history_filters]
- [S3] 當 `m1` 那一行所在的筆記是改到的程式檔的家或在摘要,應放要處理層,否則只列出;`drift_check.old_sentence` 為 warn 時要處理也不讓 check 回 1,為 block 時才回 1,為 off 時不跑;`drift_check.gate` 為 off 或 block 都不改變 `m1` 的行為與回傳碼(四種組合各驗) [test:t_drift_m1_layers_and_mode]
- [S4] 當作者用 `drift ack --kind m1 --name <名稱>…` 表態,工具應綁路徑、原文、種類、名稱集合;集合沒全部涵蓋、或新名稱觸發同一行時照列;`--kind m1` 不帶 `--name`、或別的種類帶 `--name` 回 2 [test:t_drift_m1_ack_binds_name]
- [S5] 當同一個 blob 第二次被剖,工具應用快取、不重剖;快取檔壞掉、讀寫失敗時當沒有快取照常跑;筆數超過上限時丟最久沒用到的 [test:t_drift_m1_defs_cache]
- [S6] 當 drift check 跑了 `m1`,應在治理帳記一筆(零筆也記)帶要處理、只列出、剖不動的數目與前 30 筆位置;時間到時 warn 模式印明不算要處理、block 模式算要處理 [test:t_drift_m1_events_and_budget]

## 回退

- `m1` 是 `cmd_drift_check` 裡的一次呼叫加一支獨立判定函式:拿掉那次呼叫、`_drift_config` 的 `old_sentence`、`_drift_fix_hint` 的名稱參數與 `m1` 分支、`_DRIFT_KINDS`/`_DRIFT_KIND_NAMES` 的 `m1`、表態的名稱欄與 `--name` 參數;其他種類不受影響。已記的治理帳與表態留著(`_drift_load_acks` 會濾掉不認得的種類;治理帳的 kind 是自由字串)。
- 快取檔在 git 目錄裡、不進版控,刪掉即可。
- 主要路徑是 `git revert --no-commit <功能提交>` 後把共用帳本檔留在現況(同 [[Projects/漂移修法補強_計劃]]〈回退〉的做法),revert 提交照樣過代碼審閘。

## 實務隱患

- 已排除:不可逆:只讀程式與筆記、只印與記帳,不改任何筆記內容;還原提交後外面不用收拾
- 已排除:金流:本機命令列工具,不碰付款或帳務
- 已排除:對外送出:不寄信、不打外部服務
- 守衛面(碰到):推送前多一種發現,預設只提醒;block 要專案自己設。誤報會讓人練出「看到就 ack」的習慣——兩週量準度就是為了這個。開關讀被推送頂端的設定,同一個提交把 `old_sentence` 改成 off 就放過自己——跟 `drift_check.gate` 同一條既有取捨([[Systems/存量漂移守衛]] 的 RULE,2026-09-29),CI 那步照樣讀同一份,這條不另防
- 效能(碰到):冷快取一次推送 3.6–7.4 秒(實驗量),有快取後約 0.3 秒;跟 c1–c5/probe 共用 60 秒預算,rtb 新分支首推曾量到前段就用掉 67 秒,那種推送 `m1` 會沒跑完(warn 時只印)
- 併發(碰到):快取檔兩個推送同時寫——寫入走暫存檔再原子替換,讀到壞檔當沒有快取
- 資安(碰到):剖的是自己 repo 的程式碼(`ast.parse` 不執行);筆記路徑、原文與名稱印到終端與寫進治理帳前過 `_esc_clean`;`--name` 走一行檢查

## 誠實界線

- 只看 Python。其他語言的專案這道等於沒有;實驗沒量過非 Python 的誤報,不能套這裡的數字。
- 抓不到「數量或行為變了、句子沒寫名稱」的舊句(實驗 A2),也抓不到從沒在任何一版定義過就消失的名稱(A1 的 `held_rule`)。
- 字眼表是在同一份考卷上調出來的,準度有樂觀偏差;兩週提醒期就是要量真實準度。中文字眼照子字串比,「沒有、刪、撤」這類短字會放過一些現況句(漏報)。被放過的句子不記帳,兩週帳量不到漏報;REVISIT 那天另對 rtb 抽一個大提交,把字眼過濾關掉跑一次,人工比多出來的那些。
- 起點截到 drift check 的上線點:上線點之前刪的名稱看不到;範圍愈大,「先加後刪」在範圍內發生的機會愈多,那種名稱也看不到。
- `m1` 的表態在 ack 當下不驗那一行真的是 `m1`,可以對任何一行先表態。
- 撤除節②在一級標題底下也適用:一篇筆記中段隨手寫一句含撤除字樣的引用,後面整篇都不看(P4r2 重跑報告點名、還沒踩到)。兩週帳看不到被豁免的句子;REVISIT 那天在工具鏈與 rtb 的圖譜各數一次「被②豁免的行數」,單篇超過 100 行的逐篇看是不是該豁免。
- `drift scan`、健檢與考試不跑:只有一棵樹時判不了「消失」;考試成績與噪音基準不含 `m1`。
- warn 模式時間到就放行,是刻意跟既有「判不了算要處理」相反;轉 block 時照既有規矩算要處理。
