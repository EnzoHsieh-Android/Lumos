## 實務隱患鏡頭:逐類答

- **併發(多 session 同寫一份帳)**:低風險但前提未寫明——見 f21;跨 session 歸戶另有 f6(既有 context/show 事件沒有 session_id)。
- **效能(Stop hook 解析逐字稿多大)**:可接受,但 spec 的量級說法不精確。`collect_turn_actions` 是 `read_text()` 整檔進記憶體再反向掃,所以是 O(檔案大小) 不是 O(回合大小);實測本專案最大逐字稿 55MB / 37239 行,read+splitlines 0.26s,Stop hook timeout 10s,餘裕足夠。本案的增量(多收 Read 條目、多讀一份 jsonl)可忽略。
- **回滾**:spec 說法成立。三段小改可直接刪,TTL 標記在 tmp、24h 自清;唯一殘留是帳裡已 commit 的 pushed/lens-tally 行——那正是 f7 要求先定義混合 schema 讀取規則的原因。
- **資料(使用帳被 git 追蹤,會不會污染 pre-commit 的圖譜同步判定)**:**不會,已實查**。pre-commit Gate 3 的條件是 staged 裡有 `^${GRAPH_ROOT}/.*\.md$`,`docs/.usage-log.jsonl` 既不在 GRAPH_ROOT 下也不是 .md,湊不出「動過圖譜」;`docs/*` 又整段落在 `should_exclude`,也不會被算成 code。另外 `_BOOKKEEPING_FILES` 已收錄 `docs/.usage-log.jsonl`,所以 pitfalls 自我餵食與 code-loop 留痕失效兩條也已被既有豁免蓋住。file: `scripts/hooks/pre-commit:126,151-153`、`scripts/lumos:12473-12476`
- **self-governance(pitfalls 命中)**:真的碰到,而且緩解不夠——見 f12,第一段把觀測結果印回給被觀測者,基準會被自己污染。
- **安全/注入面**:無新注入面。本案不改任何注入文字,寫進帳的是圖譜內部節點名 + 檔路徑 + session UUID,不含 diff 內容;唯一新增的外洩面是 session UUID 與被編輯檔路徑會隨帳進 git 歷史,自有 repo 可接受,但 spec 的安全段只提節點名、漏列這兩欄。
- **可逆性/破壞性**:無。全部是 append 與 stderr 列印,不刪不改任何既有檔,hook 維持 fail-open、永不 block(`Projects/主動影響幅度偵測_計劃` d 的既有裁定未被本案觸動)。
- **權限/多租戶**:無——兩支 hook 都在本機使用者自己的 repo 內跑,沒有跨使用者資料。
