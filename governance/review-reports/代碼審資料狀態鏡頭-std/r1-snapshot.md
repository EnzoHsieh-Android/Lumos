# 代碼審資料狀態鏡頭_計劃

> 白話:代碼審派審查員時,派工詞裡的「正確性」那副眼鏡多問五個 DDIA 式的問題(新舊版本讀得懂嗎、寫一半當掉會怎樣、衍生資料取哪一筆、時區對不對、會不會刪到不該刪的),並把既有的「冪等與併發」那一問寫寬一點。不擋推送、作者不用多做事。

## 現況(2026-09-29 讀檔的觀察,以檔案為準)

- 代碼審派工詞的單一來源是 design-loop skill 的派工範本第 3 節:代碼審 reference 的 refute framing 兩處寫「完整鏡頭以範本第 3 節為準」;代碼審 skill 步驟 2 只指到第 3 節的 Codex 做法與圖譜鏡頭格式,沒提正確性鏡頭內容。
- 第 3 節的審查鏡頭有四點:正確性四問(邊界、資源、例外與 None、冪等與併發)、pitfalls manifest、圖譜鏡頭、本案特定鏡頭。沒有新舊互讀、寫一半、衍生資料、時間這幾類。
- 設計審的業務類追問(對外送出、做了回不去)只在審設計稿時出現;直接審程式改動的路徑沒有。本計劃把這兩類併進同一段問句,算是交付 Enzo 那句「設計審追問接到 diff 路徑」——只在審查員鏡頭層,不在 pitfalls 的輸出層。

## 設計(r1 light 折入後的第二版;r1 十一條見〈審計修正紀錄〉)

1. **不另開一點,併進第 3 節派工詞第 1 點「正確性」**(r1 架構席 F1、通才 F5):既有的四個子題後面接五個新子題,跟既有子題同一種寫法——無條件列出、同樣要求挑具體輸入走一遍、沒有「碰到才答」這種條件句。所以 panel 多席時它跟著第 1 點走:哪一席拿到正確性鏡頭就拿到這五問,不會整段複製給每一席。
2. **重疊的兩題不另立,擴寫既有「冪等與併發」子題**(r1 通才 F2):同時讀改寫、對外送出重試併進那一條。
3. **邊界子題的填空範例拿掉「時區」**(r1 通才 F1):時間比較改由新的「時間」子題固定問,填空範例留日期窗口與 off-by-one。
4. **「不可逆」子題留在第 1 點**(r1 通才 F3):standard 單席沒有回滾席,需要這一問;panel 有回滾席時,那一席照 §7.7 立場往深處挖(退不退得掉、資料救不救得回),第 1 點只問「會不會連帶動到不該動的」。
5. **用詞對齊既有風險分類**(r1 架構席 F2):用「不可逆」「對外送出」,不另造「做了回不去」「對外副作用」。
6. **reference 裡的兩份濃縮複本一起改**(r1 通才 F4):代碼審 reference 的 refute framing 兩處各自濃縮了正確性四問,補上五個新子題標頭。
7. **代碼審 skill 步驟 2 加半句指路**,指到第 3 節正確性鏡頭含資料狀態幾問;用測試機械驗(r1 架構席 F3)。
8. 第 1 點改完的樣子(全形標點,同既有子題;r1 架構席 F5):

```
   · 邊界：空集合／只有一個元素／最大值或溢位／{本案高風險形態，如日期窗口、off-by-one}，這段扛得住嗎？
   · 資源：（不動）
   · 例外與 None：（不動）
   · 冪等與併發：同一操作重跑、或兩個請求同時進來，會壞嗎？同一次計算讀了兩次、中間被別人改了，結果會不會拼自兩個時間點？對外送出或扣款的重試會不會重複生效、收端怎麼去重？
   · 新舊互讀：新程式讀舊資料、舊程式讀新資料（新增的紀錄種類、欄位、格式），各會怎樣？
   · 寫一半：寫到一半被中斷（例外、被 kill、磁碟滿），留下什麼狀態？下次讀認得出、救得回嗎？錯誤訊息教的救法真的救得回嗎？
   · 衍生資料：它是真相來源還是算出來的（快取、索引、彙總、狀態提示）？同一件事有多筆紀錄（重跑、重試、撤回）時取哪一筆？
   · 時間：時間戳與日期比大小、判過期時，拿一個具體時刻走一遍（例如台北凌晨 1 點＝UTC 的前一天）；時鐘倒退、兩台機器時間不一致呢？
   · 不可逆：刪除、覆寫、截斷、搬移資料，會不會連帶動到不該動的？
```

9. **範本內容守衛測試**(r1 架構席 F4、通才 F6:既有的「漂移守衛」指的是檢查同一個關鍵字有沒有散落到每一份該提的檔,這支只驗範本內容齊不齊,所以不沿用那個名字,也不照 t_tension_doc_sync 那種「每檔含某個字」的形狀):測試檔裡一支小函式,輸入第 3 節派工詞圍欄的文字,回傳缺了哪幾個子題標頭;主測試對真範本跑、要回空清單,另一支對拿掉一題的副本跑、要回出那一題。消費專案沒有 skills 目錄時照既有慣例標「沒驗到」。
10. 措辭有兩處是實驗後才調的(時間題附具體時刻、衍生資料題加「多筆紀錄取哪一筆」)——實驗量的是調整前的版本,調整後的效果沒量過。

## 回退

退回=範本第 3 節第 1 點刪掉五個新子題、冪等與併發與邊界子題改回原文;reference 兩處濃縮複本與代碼審 skill 那半句改回;刪掉三支守衛測試。不碰任何帳本與閘。

## 實務隱患

- 已排除:金流:只改審查員派工詞文字,不碰任何付款流程
- 已排除:對外送出:不寄信、不打外部服務,派工詞只給審查子代理看
- 已排除:不可逆:純文字與測試,刪掉即回原狀,不動帳本
- 已排除:守衛面:不新增、不改任何推送閘或處置閘;新增的漂移守衛只驗範本文字在不在,不擋任何人的推送
- 注意力稀釋:派工詞變長,審查員可能被新題帶離原本會看的地方(實驗案 4 第一次就發生過);所以不另開一點、併進第 1 點,重疊的兩題擴寫既有子題而不新增

## 撤除條件

RETIRE-IF:三個月內代碼審席報告裡對上五個新子題、而且被折入的 finding 少於 3 條;或出現兩次以上「審查員被新子題帶離、漏掉通才本來會抓到的洞」的逃逸紀錄

## 誠實界線

- 實驗樣本小(5 個案例、兩案各 3 次),只能說「沒變差、可能稍好」,不能說有效。
- 審查員答了題不等於答對;這段只提高「有人去看」的機率。
