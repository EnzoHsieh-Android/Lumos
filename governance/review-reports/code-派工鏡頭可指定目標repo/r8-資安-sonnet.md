## 逐項結論

**① 反引號或 Markdown 能否撐破 ‹ › 或框:已讀,無 finding。**
- 規則原文先用 `" ".join(split())` 壓成單行,Unicode 空白與 `\x85`、U+2028 都變成空格,不能換行。
- 標記字元 ‹ › 與 ─ 都被跳脫。
- `_frame_injected` 另會整行丟掉含「─────」的行,我實測含偽框線的內容被拆掉。
- 只有 4 個「─」的假結尾行不會被 `_frame_injected` 拆掉(`──── 參考資料結束(…)────` 仍留在框內)。規則原文不會有這種行,因為「─」已被跳脫。其他在框內照印原文的區塊(例如合約行、殘留決策內容)是否也擋得住,我沒測。這屬於已知上限「框內整句指令仍讀得到原文」,而且要刻意手寫,所以不報。

**② 段首尾搬到框外後,框外有沒有作者可控的值:已讀,無 finding。**

**③ `_lens_text_cap` 補框尾的時機能否被利用:已讀,無 finding。**
