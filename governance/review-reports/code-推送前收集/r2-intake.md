## 根因分組與處置

同輪最高 minor。11 條折入,1 條附理由放行(併3)。

- G1 收子行程寫法(併1、併2、架1):跑測試的子殼自己寫一套 `_pids` 陣列收各片,`&` 起片與記 pid 之間有空窗,中斷落在空窗會漏收一片;掛鉤已有 `_pp_kill_jobs`(用 `jobs -p`,沒有這個空窗);主殼與子殼都沒接 SIGHUP,只對掛鉤單獨送掛斷時各片全變孤兒。→ 子殼改用 `_pp_kill_jobs`;主殼與子殼都加接 HUP(離開碼 129)。
- G2 沒人讀的 summary 欄位(通1、架2、合4 的後半):`--keep-going` 的 JSON 每筆 blocks 帶 summary、主程式多一張原因表,但沒有任何程式讀它,兩份表只為了給漂移測試比對而存在。→ 拿掉 summary 欄位與主程式那張表;漂移測試改成比對「判定函式產出的原因種類」與「掛鉤對照表的種類」兩個集合。
- G3 漂移守衛靠字面(合4 的前半):抽 reason_kind 的正則只抓字面字串,改用變數產生的種類會漏。→ 守衛另加一條:判定函式裡 reason_kind 的值一律要是字面字串,出現非字面就紅。
- G4 同檔同族重導向(架3):`pp_touched_file` 的追加寫入仍是「`>>` 之後才導走 stderr」的舊寫法。→ 改成跟 `pp_record_block` 一樣包成一組。
- G5 孤兒測試的計時窗口(邊1):等待從起掛鉤算到固定 5 秒,負載下餘裕只剩約 0.3 秒,拿掉陷阱也照綠;`took` 上限在負載下反向假紅。→ 等待改成從假全套寫下開始標記那一刻起算,`took` 上限放寬。
- G6 文件(合1、合2、合3):筆記說 git 允許 ref 名帶跳頁(實測 `git check-ref-format` 拒絕跳頁與 0x1c–0x1e,只放 U+2028、U+0085);S13 條款寫「不准有不經收尾函式的回傳」,守衛實際放行「先指派給 hit 結果的變數再 return」,而且沒驗回傳前有判非空;log 搬進暫存目錄、紅時搬出這條使用者看得到的行為沒有驗收條款。→ 改正筆記說法並拿掉測 git 推不出來的跳頁那組;S13 照實改寫,守衛加驗「return 那個變數之前要有 `if 變數:`」;補一條驗收條款並綁 `t_prepush_test_logs_inside_tmp`。
- 放行 併3:席位自己標推測、沒有實跑;內容是 `test_lumos.py` 自己用 `start_new_session` 起的子行程收不到掛鉤送的中斷,屬於測試程式的資源,不在這次掛鉤改動的範圍;那些子行程有 60 秒逾時,會自己結束。
