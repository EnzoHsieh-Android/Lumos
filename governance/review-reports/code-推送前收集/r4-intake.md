## 根因分組與處置

同輪有 major(正1),accepted 必空,12 條全部折入。

- G1 換群組的啟動器沒有退路(正1、併2、通1):`os.setpgid` 在原生 Windows 的 Python 不存在,掛鉤又明文支援 Windows 路徑;每片起跑就 AttributeError、離開碼 1,推送永遠被擋且訊息錯(「有紅」卻列不出哪支);即使繞過,Windows 的 `os.execv` 會讓外層立刻回 0,測試沒跑完就判綠。→ 啟動器 `hasattr(os, "setpgid")` 才換群組,沒有就直接照舊執行測試檔(不經 execv);setpgid 失敗也退回照舊執行。補一支測試:模擬沒有 setpgid 的 Python(例如以 `-c` 包一層刪掉 os.setpgid)時,片照常跑完、離開碼照實。
- G2 群組只送一次 TERM(併1):送訊號當下群組成員正在 fork 時,剛生出來的子行程收不到那一發,變成孤兒;併發席實測掛鉤啟動後 20–45 毫秒送 TERM 100 次中 27 次殘留,補送第二發降到 0。→ `_pp_kill_jobs` 在訊號路徑裡短等後對每個群組再送一次 TERM(群組沒有成員時的錯誤吞掉);補 20–45 毫秒視窗的實測數字。
- G3 守衛掃描器讀不懂的寫法(邊1、邊2、邊3、合3):here-doc 本文、`$'…'`、`&>`/`&>>`、`$(…)` 裡的寫檔、`2>>/dev/null` 等,掃描器會誤抓或漏抓;七個手寫例子沒釘住切段與引號規則。→ 不把掃描器補成完整的 bash 解析器:補 `$(…)` 與 `&>` 這兩種掃描器現在就看得到的寫法、切段與單引號的手寫例子各一條;here-doc 與 `$'…'` 改成守住前提——加一條斷言「掛鉤裡沒有 here-doc(`<<` 後接字)與 `$'`」,出現就紅並提示要先擴充掃描器。
- G4 條款與說明(合1、合2、合4):S10 沒有孫行程收掉、只有子殼收到 HUP 的條款句;「只有子殼收到 HUP 回 1」沒寫進文件、測試只驗非零;四句原因句定計劃為正本但沒有測試讀計劃。→ S10 補兩句並綁測試;文件寫明回 1 與「紅的是這幾支」為空的原因,⑪ 改驗 rc==1;加一支守衛逐字比對計劃那一行的四句。
- G5 PYTHONPATH 劫持(資1):環境帶含 sitecustomize 的 PYTHONPATH 能讓換群組那段與其他每個 `$PY` 閘直接回 0;修補前就有。→ 屬刻意設定環境變數的手法,在暫行範圍外;在掛鉤註解與 Systems/bound-tests-gate 照實寫成天花板(要先能控制推送行程的環境),不加機制。
