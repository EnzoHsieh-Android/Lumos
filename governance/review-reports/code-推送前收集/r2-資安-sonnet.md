資安席第二輪:四個重點都沒找到能把本該被擋的推送放行、或讓全套測試沒跑就當綠的洞。我讀了完整改動與掛鉤修補,跑了一個實驗(子殼收 TERM,/bin/bash 3.2),結果已清掉。

**版本探測讀檔找字樣**
- 探測是 `grep -q -- '"--keep-going"' "$GRAPHCTL"`,位置在 file: `scripts/hooks/pre-push:437`。真正讓舊版被當成新版的條件,是舊版 lumos 裡有帶引號的 `"--keep-going"` 字樣。
- 我查過改動前的 `scripts/lumos`,`keep-going` 出現 0 次。字樣只在 `scripts/lumos` 的 `code-loop check` 參數註冊那一處有帶引號的形式(`_clp.add_argument("--keep-going"`)。所以現有版本之間不會誤判。
- 反方向(新版被當成舊版)只會讓掛鉤少帶旗標,擋下照舊,記帳退回記一筆。這是安全方向。
- 要在舊版 lumos 裡偽造那個字樣,得先改 `scripts/lumos` 本身。能改它的人本來就能直接改判定,這不是新增的攻擊面。
- 帶了旗標的舊版會回 2,掛鉤把它當放行。這條路不是這輪新增的,而且上面已確認現有版本進不去。

**子殼的 TERM 陷阱**
- 我照 `run_group` 的寫法重現:子殼收到 TERM 後,各片都被收掉(沒有孤兒行程),子殼以 143 結束。
- 143 讓外層 `_grc` 變成非零,再讓 `_rc=1`,所以推送被擋,不會被當成綠。文件子集(`_grc`)和關鍵字組(`_krc`)兩條路都是非零即紅。
- INT 在非互動的背景子殼裡本來就被忽略,實際由掛鉤自己的 INT/TERM 陷阱轉成 TERM 送進來,一樣走這條路。

**`pp_keep_log` 的路徑能不能被換**
- 路徑由 `mktemp` 建檔,不能被預先放符號連結或換成別的檔。`cp` 只寫進自己建的那個檔。
- 檔名樣板的中段只有寫死的 `autoloop` 和 `tests`。
- `mktemp` 或 `cp` 失敗時,會刪掉剛建的檔,然後印說明句。
- 剩下的是設 `TMPDIR` 就能改位置,但那只影響完整輸出放在哪,不影響擋不擋。

**lint-waive 放行的指紋**
- 新增告警閘的指紋是「規則 + 檔名 + 命中那一行的程式碼」經 sha256 取前 16 碼(`_lint_new_key`)。兩條放行都綁 `C901` 加 `scripts/lumos` 加各自的 `def` 行,所以只能放行同規則、同檔、同一行文字的告警。
- 換成別的規則(例如行長)或別的函式,指紋都對不上,拿不去放別的新告警。
- 有一個設計上的後果,我不算洞:指紋不含複雜度數字,這兩支函式日後再變複雜,仍然不會被當成新告警。這在計劃筆記裡已有明文,放行理由也有寫。

**順手看過的小改動,都沒問題**
- 跟 `pp_record_block`、tee 同一族的寫法,錯誤訊息改丟 `/dev/null`。tee 寫不進留底檔時,`grep` 找不到「light」字樣,測試範圍維持全套,是安全方向。
- `LUMOS-BLOCKS:` 那一行只決定記幾筆。判定回 1 本來就會擋,偽造那一行最多多記或少記一筆。
- 逃逸帳改用 `elif`,只影響記帳,而且那兩呼叫本來就是失敗也放行。
