## 症狀(會翻紅的證據)

①code-prose-conv-impl 與 code-cascade-reminder 兩迴圈的 r1 carrier 皆因「引句錨在審材外現碼」觸發 disposal 閘 quote 關 FAIL,各加開一輪 delta 才過(帳:canary-log 兩迴圈 r1→r2);r2 派工詞加「引句限出自被審材料」後全數錨定——解已實測,未制度化。②cascade-reminder r1 最重三條(E2 兜底不實等)全是「機械宣稱語意錯」型,首輪前掃驗了存在性(抓到壞行號)卻放過語意;prose-lint 兩份真 spec 零命中。③現行重寫門檻(>1 條 blocking/300 字)被健康輪超標:cascade 案設計審 r1=18 審項/blocking 11/審材 59 行(帳:canary-log loop=cascade-reminder r1 scope_lines=59;blocking 數見該計劃審計修正紀錄兩行式)折完即收斂,未觸發重寫是對的——門檻誤報。

## 核心裁定

- **d1 卷證規則(治①)**:審查員報告的「引句:」格式行**限逐字出自凍結審材**;審材外佐證(讀 repo 現碼查證所得)改走「佐證通道」=file:line+敘述,不得用引句格式——存在性由 refcheck 守、真偽由編排者機械重現守,一條不漏。carrier 選席 SOP:記帳前對候選席報告跑 quote-check,選全錨席當 carrier。已排除「閘支援多材料錨定」:動閘碼,等 SOP 實測不足再議。
- **d2 前掃升級(治②)**:首輪前掃固定清單加第四類——「spec 每句機械宣稱(說某函式/機制會做 X 的),開檔讀該段碼**驗語意**,不只驗存在」;命中直接修真檔,不算 findings。prose-lint 維持措辭衛生定位,詞表不動。已排除「自動化宣稱抽取工具」:LLM 管線研究方向對,但前掃 agent 一句 prompt 就到位,不建輪子。
- **d3 重寫訊號換形(治③)**:廢「blocking 密度/300 字」,改雙訊號——(a)**折入波及幅度**:本輪折入的 diff 動了 spec 既有行的比例(git diff 可算),暫用門檻 >30% 為攤人建議訊號(Fagan 5% 是 rework-工時語意、非行數,本地換算無據,故取保守高值待校準——寧漏勿誤觸);(b)**結構命中**:blocking 命中「核心裁定」節條目 ≥2 條。兩訊號都到才建議攤人重寫;仍是人裁選項非自動。回代驗證:cascade 案(點狀 11 條、波及小)不觸發✓;prose v1(歸因錯、d1-d4 全重立)雙訊號皆中✓。[[Projects/設計審收斂重定義_計劃]] d3 原文明列「暫用門檻,[S6] 實測校準」——本改動即該校準條款的兌現,非翻案。
- **d4 落點**:全部改在 skill 文件(templates.md/SKILL.md),零碼、零新命令;design-loop 判詞語意不動(處置閘四合取原樣)。

- **卷證規則的代價**:機械席的「證據力」從引句降為敘述——但存在性/真偽兩道守衛不變,且兩個 code-loop 的 r2 已實測此紀律不影響抓漏(r2 各自照樣抓到/確認問題)。已排除:無。
