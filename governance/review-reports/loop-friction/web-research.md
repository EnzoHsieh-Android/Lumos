# 三處迴圈摩擦·問世界(2026-08-25)

背景:設計審收斂重定義落地後,cascade-reminder 實測留下三處摩擦(carrier 引句卡閘/prose-lint 零戰果/重寫門檻太低)。動手修之前查世界先例。

## ① 引句錨定紀律(carrier 引 patch 外現碼 → 閘紅)

- **法庭卷證規則(最強同構)**:上訴書狀每句事實陳述必須引卷宗冊頁(FRAP Rule 28 等);引用卷外材料可被對造聲請剔除(stricken),且傷律師在該庭的信譽——「裁判只憑卷內材料」是上訴實務基本教義。對映:凍結審材=卷宗;引句=record citation;卷外證據要嘛入卷(凍進材料)、要嘛不得用引句格式主張。
- **代碼審工具**:Gerrit/GitHub 的行內評論都錨在 diff 行/選區上;diff 外的話走一般評論通道——「錨定通道」與「自由敘述通道」天然分開,不混用。
- **LLM 引用驗證研究**:引用幻覺率實測 11–57%(各家商用模型);驗證管線標準形=宣稱抽取→檢索→段落比對→判定(CiteCheck 88.7 macro-F1;RefChecker claim-triplet;CiteAudit 多代理)。我們的 quote-check+編排者機械重現正是這條管線的手動版,方向獲證。

**折入候選**:templates 派工詞立「卷證規則」——引句(「引句:」格式)限出自凍結材料;材料外佐證用 file:line+敘述通道(存在性 refcheck 守、真偽編排者重現守);carrier 選引句全錨席寫進 SOP。**零碼改**;r2 兩案已實測此派工詞有效。

## ② 便宜層對準「事實宣稱」(prose-lint 抓不到 E2 兜底型誤判)

- **文件漂移工具業界**:Swimm Verify/Auto-sync 專利=文件宣稱用 token 錨到碼、PR/CI 時重驗;DriftGuard 做跨層(碼/SDK/docs)漂移偵測——業界共識:**宣稱要綁可重驗錨點,重驗掛在變更點**。
- **宣稱驗證研究**:FEVER 系多代理宣稱驗證、逐句抽宣稱→檢索→驗證是標準管線;spec grounding 實證(arXiv 2607.06636)=接地讓真 bug 抓更多、假警報更少。
- 對照自家:首輪前掃已驗「存在性」(函式在不在、行號對不對),漏的是「語意」(E2 讀 header 但沒用)。

**折入候選**:前掃固定清單加一條「spec 每句機械宣稱,開檔讀該段碼驗語意,不只驗存在」;prose-lint 維持措辭衛生定位不加戲。**一句 prompt 改動**。

## ③ 重寫門檻(11 blocking 單輪折完好好的,密度門檻卻已超標)

- **Fagan 再檢驗規則(關鍵找到)**:rework 幅度 >5% 被審材料 → 全隊重審;否則主持人選擇性覆核——**用「要改動多少材料」判,不用「找到幾條」判**。
- **主觀效力估計研究**:由審查員自評效力做再審決策,穩定優於「永不再審」的固定預設(Bayesian 控制模型系)。
- **編輯出版界**:developmental editing 的重寫判準=結構/地基問題(plot structure 斷裂),不是表面缺陷數;結構完好=修訂(2-3 月),結構斷=重寫(6-12 月)。

**折入候選**:門檻從「每 300 字幾條 blocking」改成雙訊號——(a)**折入波及幅度**:fold diff 動了 spec 幾 % 行數(git diff 機械可算,對齊 Fagan 5% 形狀);(b)blocking 是否命中**核心裁定**條目(結構 vs 點狀)。數字下個真案校準。本次實測佐證:cascade 案 11 條全點狀、折入波及小→不重寫正確;v1 那次歸因整錯(結構)→重寫正確——兩案回代都對。

## 證據強度但書
法庭規則與 Fagan 5% 是成文規範/經典教科書級;LLM 引用驗證是 2025-26 活躍研究(量級可信、數字別逐字搬);編輯出版界是行業慣行(方向性參考)。
