### Finding 4 — 詞表子字串誤中,無詞界判斷(確認可重現)

### Finding 5 — 非 UTF-8 輸入未被捕捉,直接 crash(確認可重現)
severity: major / blocking: 是
判準:文件明講「檔案讀不到才 rc2」,但實測非 UTF-8 檔案不是「讀不到」,是拋出未被接住的例外,整個指令當掉、rc 變成 1(既不是文件承諾的 rc0 也不是 rc2),跟自己講的 rc 語意矛盾,是會做出錯行為的缺陷,故 blocking:是。
file: scripts/lumos:13681
引句:「except OSError as e:」
`UnicodeDecodeError` 是 `ValueError` 的子類、不是 `OSError`,所以 `except OSError` 接不住它。實測餵一個帶 0xff/0xfe 非法位元組的檔案,`lumos prose-lint` 印出完整 Python traceback 後以 rc=1 結束,不是預期中乾淨的「擋下:檔案讀不到」訊息。design-loop 排乾步驟被要求「必跑」這個指令,若哪份 spec 草稿混進了非 UTF-8 貼上內容(常見:從 Word / Outlook 貼中文,帶 Big5/CP950),這一步會直接爆 traceback 而不是給出 advisory 訊息。

已讀,無 finding:輸出截斷邏輯(`hits[:40]` + 「其餘 N 處省略」)算式正確,沒有算錯或漏算其餘筆數;檔案不存在時的 rc2 分支跟文件相符,已測。
