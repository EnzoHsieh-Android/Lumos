# r1-s4 Codex 外家席審查報告

1. **[blocker] SNR 的分子、分母與統計母體均未定義，無法得到可重現結果**

   ① 引句：「公式:每題 SNR=醒席/睡席(或跨模型)分辨力÷同席重跑雜訊;SNR<1 的題=在量猜運氣,標記換題。」

   ② 問題：`分辨力`、`重跑雜訊` 沒有指定統計量；「醒席/睡席」與「跨模型」是兩種不同母體，卻用「或」混為同一公式。未定義使用命中率差、between-group variance、標準差或其他量，也未處理分母為 0、單一樣本、缺組、同席不同題等邊界。不同實作者會算出不同 SNR，且 `SNR<1` 不具固定語意。

   ③ 證據：現有校準器使用的是植入題 × 席位的 caught 矩陣，只計 caught 總數，沒有 variance/SNR 定義或重跑配對：`governance/eval/canary_calibration.py:67-78`；落帳 schema 只有 `config/plants/seats/caught_total/rows`：`governance/eval/canary_calibration.py:81-85`。spec 自己也承認最小樣本數未定：`驗證層自證三件-r1-s4.md:44`。

2. **[blocker] 指定資料源沒有「同席重跑同一題」的識別鍵，公式分母算不出來**

   ① 引句：「對象:canary 記錄帳 `docs/.canary-log.jsonl`(355 筆,含 type a-d/caught-missed/auditor,可分組)」

   ② 問題：帳中每筆 token 是一次獨立植入；沒有 `item_id`、`repeat_id`、固定題目 ID 或配置版本可把「同一題、同一席的重跑」配對。`round`、`auditor` 和自由文字 `note` 不能證明是同題重跑。照字面從這 355 筆直接估「同席重跑雜訊」會把不同 spec、不同植入、不同 prompt 與不同題混池。

   ③ 證據：最近記錄的結構欄只有 `kind/auditor/token/note/loop/round/...`，沒有題目或重跑鍵：`docs/.canary-log.jsonl:350-355`。正式離線校準器反而要求另一份有穩定 `id/file/type/token/nature` 的 `plants.json`：`governance/eval/canary_calibration.py:7-13`，證明 `.canary-log.jsonl` 本身不是該實驗資料模型。

3. **[major] S1 所需的「派工宣告」沒有被指定為輸入留痕，`unreported` 無法機械對帳**

   ① 引句：「派工宣告要查的範圍/鏡頭沒出現在報告=`unreported`」

   ② 問題：S1 宣稱腳本只吃 `review-reports` 既有留痕，但現行留痕合約只保存凍結快照與席報告，沒有 dispatch prompt、允許路徑集合、必查鏡頭集合或 manifest。沒有 prescribe 端資料，就不能判斷 report 端「有講沒做」。從報告自己寫出的「範圍／鏡頭」反推派工要求會形成自證。

   ③ 證據：現行 skill 只規定保存 `<round>-snapshot.md` 與 `<round>-<席>.md`：`skills/lumos-design-loop/SKILL.md:12`；一輪流程也只把凍結快照交給 `quote-check`，沒有 dispatch 留痕檔或 schema：`skills/lumos-design-loop/SKILL.md:11-12`。

4. **[major] 文內交叉引用指向不存在的章節**

   ① 引句：「越界另記一本、欄位格式見本文〈越界帳欄位表〉節、不進收斂帳」

   ② 問題：本文沒有〈越界帳欄位表〉節。因此 `out_of_scope` 帳的檔名、路徑、欄位、唯一鍵、寫入方式及與收斂帳的隔離均未定義，照文無法實作。

   ③ 證據：本文從 S1 直接進入 S2，沒有該節：`驗證層自證三件-r1-s4.md:23-34`；其後所有實際章節依序為「刻意不搬／射程聲明／實務隱患／審計修正紀錄／驗收線」：`驗證層自證三件-r1-s4.md:38-59`。

5. **[major] `quote-check` 的 rc1 被誤述成名為 `unverified` 的欄位**

   ① 引句：「已有 `lumos quote-check` 上線(收貨流程織入,rc1 欄位即名 `unverified`)」

   ② 問題：`quote-check` 的 rc1 是程序退出碼，不是欄位；其 JSON 結構也沒有 `unverified`，而是 `total`、`miss`、`quotes[].ok`。若實作者按 spec 讀 `unverified`，會取不到資料或把錯誤路由到另一套 settle 清單的 `status=unverified` 語意。

   ③ 證據：命令明定 rc0/rc1/rc2 語意：`scripts/lumos:8587-8591`；JSON 欄位實際為 `report/spec/total/miss/quotes`：`scripts/lumos:8610-8613`；返回值只是 `0 if not miss else 1`：`scripts/lumos:8621`。

6. **[major] S2 同時宣稱涵蓋「每週檢索考卷」，但驗收與資料模型只涵蓋 canary**

   ① 引句：「對象:canary 記錄帳 `docs/.canary-log.jsonl`(355 筆,含 type a-d/caught-missed/auditor,可分組)+每週檢索考卷」

   ② 問題：檢索考卷的題目、模型／配置重跑、分數與雜訊來源完全沒有接進公式或驗收線；驗收只要求「每 canary 型別 SNR」。因此「+每週檢索考卷」是未落地範圍，照 spec 完成驗收仍可完全漏做它。

   ③ 證據：現行週期考卷只執行 `retrieval_eval.py --goldset ... --split held`：`governance/autonomous-loop.sh:29-52`；spec 的 S2 驗收只讀 `.canary-log.jsonl` 並按 canary 型別產清單：`驗證層自證三件-r1-s4.md:58`。

7. **[major] 驗收條件強迫「該換題清單非空」，即使所有題有效也永遠不能驗收**

   ① 引句：「清單非空且人審同意其中至少一題確實該換。」

   ② 問題：這把預期結論寫成通過條件。若正確計算得到所有題 `SNR≥1`，工具反而驗收失敗，會誘使實作者調公式、混母體或挑樣本來製造至少一題。合理驗收應驗證計算正確與低 SNR 時能產清單，而非要求真實資料必須命中。

   ③ 證據：spec 同一節只定義 `SNR<1` 才標記換題：`驗證層自證三件-r1-s4.md:30`，但驗收無條件要求清單非空：`驗證層自證三件-r1-s4.md:58`，兩者在「所有題 SNR≥1」邊界直接衝突。

8. **[major] S3 落點沒有裁定，且「治理帳」究竟是哪一本未定義**

   ③ 證據：現行設計 loop 的操作權威是 `skills/lumos-design-loop/SKILL.md`，且深規另在 `reference.md`：`skills/lumos-design-loop/SKILL.md:17-29`；spec 的驗收卻只寫泛稱「skill 文本 diff」：`驗證層自證三件-r1-s4.md:59`。

9. **[major] `out_of_scope` 沒有可判定的 scope 語意，會把必要 repo 查證誤記成越界**

   ① 引句：「報告引用了派工範圍外的檔=`out_of_scope`」

   ③ 證據：現行 skill 明確要求前提層與跨系統合約也在審查職責內：`skills/lumos-design-loop/SKILL.md:8`；留痕合約卻只定義報告與快照路徑，沒有 scope manifest：`skills/lumos-design-loop/SKILL.md:12`。
