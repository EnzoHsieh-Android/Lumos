# code-ci診斷 r1 收貨留痕(2026-09-15)

## 這個迴圈為什麼存在

上一批推送後 CI 紅一支,但 CI 只印每片最後 25 行、紅的那支在中間被截掉,查不出名字;本機四片並行全綠、沒有 Linux 環境可重現。所以先補 CI 的診斷輸出,拿到名字再修。

## 一條 blocker,已折

席位指出:撈前後文那道 grep 只認 `✗ FAILED` 與 `EXCEPTION` 兩種字樣,而測試程式還有三種真實會發生、印法不同的紅——逾時、零斷言、跳過判紅。撈不到時 grep 回非零。

**觀察對,後果被講重了,兩者要分開**:

- 席位是在 `bash -eo pipefail` 下測的,那個設定確實會整步中止、後面的片全部失聲。
- 但這一步實際用的殼是 `bash -e`(真實執行記錄原文 `shell: /usr/bin/bash -e {0}`),**不含 pipefail**;管線末端是 `while`,退出碼 0,不會中止,只會少印前後文。
- 編排者兩種殼各實測一次,差別就在這個旗標;**把訂正交回席位後,席位自己去查官方文件與 runner 的 issue 交叉核對,確認預設不帶 pipefail,並明講自己原本的前提是錯的**。

**仍照席位判定折**,理由:只要有人日後把那一步改成 `shell: bash`(預設帶 pipefail),這顆地雷就會引爆,而那正是最該用到這個診斷的時候。

折法三項:兩道 grep 都接 `|| true`;樣式擴充成認得那三種紅;註解寫明「這裡的 `|| true` 不是裝飾」與兩種殼的差別,免得日後被當冗餘刪掉。
