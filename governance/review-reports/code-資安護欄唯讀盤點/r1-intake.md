# code-資安護欄唯讀盤點 r1 收貨與處置

同門七席(正確性、邊界、資源、整合、通才、架構對齊、資安)加外家一席(外家finder-codex,使用者 2026-10-19 授權資安重點功能用 Codex 交叉審)全部交回後一次存檔;存檔工具存全文,report-normalize 只做格式搬移。架構對齊席首交一條 major 標 blocking: 否,退回原席重判後改 major + blocking: 是。引句全數錨定。共 34 條(正1–3、邊1–6、資1–3、整1–4、通1–6、架1–4、安1–4、外1–4)。

多席獨立一致、可直接折入不派辯方的:型別崩潰(正1、邊1、邊2、整1、外1)、JSON 輸出不成物件(正2、邊3、外4)、空登記塊藏缺口(安1、外2)。外家 Codex 獨有、同門未報的:外3(來源無效的控制項仍讓入口算成已覆蓋)、外4(vault 選擇失敗時 JSON 模式零輸出)——已由編排者讀碼確認成立。

## 根因分組與編排者裁定(交作者照做)

- G1 壞型別讓整份盤點崩潰(正1、邊1、邊2、整1、外1):統一規則——每個 schema 檢查先驗型別再拿來當字典鍵、集合元素或做 in 查詢;驗成非法的值一律不進後續集合與查表。補一支「每個欄位依序換成容器、數字、布林、null、代理字元」的測試:每種都要 rc2、JSON 可解析、同庫其他正常控制項照列。
- G2 輸出契約(正2、邊3、邊6、安2、外4):JSON 模式改成跳脫非 ASCII 的控制類字元(代理字元、雙向控制、行段分隔),確保恆為單一合法 UTF-8 JSON;vault 選擇失敗等所有錯誤路徑在 --json 時也輸出單一 JSON 物件(含錯誤與不完整狀態)後退出 2;文字模式自由文字欄位設長度上限並以明示的資料框呈現(標明這是登記內容、不是指令)。
- G3 缺口被藏(安1、外2、外3、通3):「已登記」改成至少一條合法控制項,空登記塊或全部非法的塊不算;coverage 的映射只採計來源、決策與證據引用都通過核對的控制項,引用失效者照列錯誤但不消除入口缺口;補 unregistered_nodes、inventory_error 與「引用無效不算映射」的測試,拿掉篩選要紅。
- G4 讀取守衛沒有測試守住或可繞(通1、通2、安3、邊4、安4):補四支測試——中間目錄在列舉後被換成捷徑(拿掉 O_NOFOLLOW 要紅)、200000 層 JSON 巢狀與目錄巢狀過深(拿掉 except 要紅);vault 根目錄本身或自動找到的 docs/*-knowledge 是捷徑時拒讀;--vault 指到不像圖譜的目錄(沒有任何 Projects/Systems/Issues/Verification 子目錄)報輸入錯誤 rc2,不當零登記。
- G5 架構(架1、架2):架1 折入方式——安全讀取不再是獨立一套,改成跟一般載入同一個讀取家族的第二種模式:放在 load_vault 旁、命名成同族(例如 load_vault_safe),註解寫明兩種模式的差別(跟不跟捷徑、有無上限)與誰該用哪一種,Systems/lumos-cli-read 補一行 WHY;不改 load_vault 既有行為(那會影響全部指令,超出本案)。架2:擴充既有 _vault_in 讓它能回傳全部候選,_secinv_select_vault 改呼叫它,不再重抄候選規則。
- G6 退出碼與錯誤詞彙(架3、架4、邊5、正3):架4 放行——CLI 契約已明定 0/2(內容問題也算輸入不完整),改成 1 要先改設計並過設計審;架3 折入——在 Systems/lumos-cli-read 補一張錯誤種類對照表(security list 的 kind ↔ 既有 _READ_FAIL 與治理事件 kind),not_utf8 不重複記兩次;邊5 放行——任何捷徑都記錯誤是子計劃 d1 已決的保守做法;正3 是核對紀錄,無需修改。
- G7 效能(資1、資2、資3):coverage 先依入口 id 建一次索引;來源核對每個節點的合約只算一次;列舉時對總項目數(含非 .md 與目錄)也設上限,超過記 enumeration_failed。補大量登記的耗時測試。
- G8 測試判準與命名(通4、通5、通6):計劃「鍵的必填規則」逐項補反例(id 字元集、schema_version 型別、unclassified 並存、retired 專屬鍵、replacement_id、expires_on、assets/surfaces 指到不存在 id);S10 那條斷言改成真的檢查「不超過剩餘額度+1」並補 fstat 之後檔案長大的情境;t_seclist_integration_gaps 照母計劃六項整合控制逐項真的建模(②要有抄錯的 oracle、③要有 A 合法成功的成對對照、⑥要真的「清單完整」並斷言 coverage 與退出碼),做不到的寫明不在盤點層,不要宣稱涵蓋。
- G9 文件(整2、整3、整4):母計劃正文裡仍寫「Q3 仍阻塞、Q4 仍阻塞」的各處(接手先讀、整合分工、執行順序、首案順序、盤點指令節、交接入口)照 d8、d9 改成現況,並寫明閘門尚未上線;子計劃「本次不改 S1–S13、不改母計劃 Q3/Q4」改成標明凍結版本之後新增了哪些(綁定、d1、Q1、Q2);Verification 補「未驗:欄位值型別畸形(修好 G1 後改為已驗)」。
