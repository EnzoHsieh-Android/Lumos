# 合約測試閘什麼時候跑_計劃

> 白話:一道閘該在「可能弄壞硬合約」的時候跑,而不是在「這段程式碼看起來危險」的時候跑。
> 現在它綁在後者身上。問題是:要知道「這次改動碰到哪些合約」本身很貴(實測 3 到 200 秒),
> 而**這個 repo 2026-08-02 已經人裁過一次:不准把那個貴的計算掛進每次推送的熱路徑**。
> 所以本案的設計核心不是「把呼叫搬出去」,是**把判斷順序從貴的改成便宜的,貴的只在真的有東西要保護時才付**。

診斷與可數事實在 [[Issues/合約測試閘只在高風險推送跑]];這一篇只講怎麼修。

## 先講幾個詞(不然下面看不懂)

- **固定席**:算「改這段程式會波及哪些筆記」時,帶硬合約或出過事故的那幾篇會無條件排前面、一定要看。
- **★INVARIANT★**:筆記裡標這個記號的那一行,意思是「這條改了就會壞」。可以再綁一支真的會跑的測試當證據。
- **波及計算**:`lumos impact --diff`,吃一段改動範圍、算出受影響的筆記並排序。**它就是那個貴的東西。**
- **可過濾的測試指令**:專案宣告的測試指令裡有「跑哪一支」的佔位符(例如 `pytest -k {method}`)。
  沒有佔位符就只能整套跑。

## 第一輪審查把原設計打掉了,這裡誠實記

r1 五席合起來否掉了「把呼叫搬出風險分級」這個字面做法,理由是三條實測與一條既有裁定:

- **既有人裁擋著**(2026-08-02):「把 impact 掛進 pre-push 熱路徑…每次 push 慢 26 倍。不可接受。」
  原設計等於靜默推翻它。
- **實測**:低風險推送的波及計算,5 個 commit 要 12.5 秒、20 個 commit(86 檔)要 63.6 秒、
  全樹範圍跑到 205 秒未完成。「沒東西可跑時秒級返回」這句話**只在「這次沒碰到任何固定席」時成立**,
  而要知道有沒有碰到,得先把那個貴的計算跑完。
- **實測**:「pitfalls 少跑一次」是錯的。低風險推送會從 1 次變 2 次。
- **實測**:合約測試本身的成本兩週漲了六成(38 支 28.7 秒 → 46 支 46 秒),而且政策上還在推高綁定率。

## 設計:把順序從貴的改成便宜的

### [S1] 判斷順序(這是本案的核心)

一道獨立的判定,依序問四個問題,**任何一步答「沒有」就記一筆帳、當場返回**:

1. **這個專案有沒有宣告測試怎麼跑?**(讀一個設定檔,近乎免費)
   沒有 → `no-config`,返回。**多數消費端專案停在這裡。**
2. **這個圖譜裡有沒有任何 ★INVARIANT★ 綁了測試?**(掃一次圖譜,而圖譜為了別的檢查本來就要載入)
   沒有 → `no-bound`,返回。
3. **這次改到的檔案,跟那幾篇「有綁測試的節點」點名的檔案有沒有交集?**
   ★這一步是反過來算的★:不是「算出全部受波及節點再篩出有合約的」,
   而是「拿那一小撮有綁測試的節點,問它們點名哪些檔,跟這次改的檔取交集」。
   有綁測試的節點是個位數,交集是集合運算,**不需要跑波及計算**。
   沒有交集 → `no-pins`,返回。
4. **只有走到這裡才跑測試**,而且只跑交集到的那幾條合約綁的測試。

**這一步解掉的是 2026-08-02 那條裁定的顧慮**:貴的波及計算完全不在這條路上;
第 1、2 步幾乎免費,第 3 步是集合交集。**代價只有真的有東西要保護時才付。**

### [S2] 拆成獨立的判定入口

新增 `lumos bound-tests check --diff <範圍> [--json]`,核心直接重用既有的那支實作,不複製。
推送關卡對每個要推的 ref 各跑一次,**跟風險分級完全正交**。

**為什麼一定要拆**(r1 外家席判 blocking):現在合約測試紅了會讓 `code-loop check` 回 rc1,
而推送關卡把所有 rc1 一律解讀成「高風險改動還沒審查」,叫人去跑 `code-loop pass`——
**但留下審查紀錄修不好一支紅掉的測試,下次照樣被擋**。訊息與處置必須分流。

擋下時的訊息要講對事:哪一條合約、哪一支測試、尾段輸出、以及「這要修測試,不是補審查留痕」。

### [S3] 新分支首推不再是特例

現在對「空樹到某個 sha」的範圍有特判,直接記 `diff-unavailable` 放行——
所以「每次推送都跑」在首推時仍然是假的。
改成 [S1] 的順序之後這個特例可以拿掉:第 3 步要的是**改動的檔案清單**,
首推就是「全部檔案」,照樣算得出交集。

### [S4] 不可過濾的測試指令:誠實降級,不假裝

專案宣告的測試指令沒有佔位符時,只能整套跑,逾時上限 600 秒。
**每次推送整套跑不可接受**,所以這種情況維持只在高風險推送跑,並記 `whole-suite-deferred`,
訊息告訴專案「把指令改成可過濾的,這道閘才會每次推送都保護你」。
★不要假裝這種情況也守住了★——這正是本案要修的那種病。

### [S5] 逃生門要留得下理由

- CLI 旗標要求非空理由,記 `skipped-flag`。
- 環境變數(CI 用)不需要理由,但**改記成 `skipped-env` 這個獨立的類別**,
  跟有理由的那條分開,才數得出來誰在用哪一條。
- **整支繞過(`--no-verify`)不留任何紀錄,這件事沒有辦法在本機解決**——
  誠實寫在節點裡,不要假裝回頭條件量得到它。

### [S6] 帳要數得出來,回頭條件才接得上電

`lumos gov --stats` 現在只給 bound-tests 的合計筆數,不分類別。
本案要它按類別分帳(green / red / skipped-flag / skipped-env / no-config / no-bound / no-pins /
whole-suite-deferred),否則下面的回頭條件到期時只能靠人臨時拼查詢。

## 非目標(明寫,免得被當成本案要做的)

- **不動 CI 那半**。但要誠實記:本 repo 的 CI 另外跑一步全套測試當後盾,
  **那是本 repo 自己的東西,工具鏈沒有分發任何 CI 樣板**,所以消費端裝上工具鏈
  不會連帶拿到「CI 當後盾」。這道閘對消費端是本機唯一一道。
- 不跑相依功能的「整套」測試,只跑合約綁的。
- 不動 `code-loop pass` / `skip` 的語意。

## 要跟著改的既有文件(清單,漏一份就是以後會漂的地方)

- 上一份計劃([[Projects/受波及合約測試真跑閘_計劃]])的需求第 1 條:前提訂正。
  **還有它的非目標「不動 pre-push 腳本」——本案要動,必須明寫推翻**(r1 圖譜席指出)。
- `Systems/bound-tests-gate` 的**白話流程段**(不是合約行)。
- 三份說明書:代碼審與推送速查表、code-loop 說明書、**自動跑的那張表**(r1 圖譜席補的第三份)。
- 那份通過的驗證紀錄的重驗條件寫的是「不再呼叫」,本案是「改變呼叫條件」,字面對不上,
  落地時要手動標 stale 或補那一行。

## 實務隱患

- **會不會有人因此開始 `--no-verify`**:[S1] 的順序讓多數專案停在第 1、2 步(近乎免費),
  真正付代價的只有「有綁測試、而且這次真的改到」的推送——那正是應該付的時候。
  REVISIT:2026-10-07 查 `lumos gov --stats` 的 bound-tests 分類帳:
  `skipped-env` + `skipped-flag` 合計若超過 `green` 的一半,就是這道閘在被繞,要收窄或改成只提醒。
- **單次推送要等多久沒有門檻**:上一份計劃提過「三次超過 3 分鐘就加只跑直接相依的旗標」,
  本案把它接上電。
  REVISIT:2026-10-07 查 bound-tests 的 green 筆數裡 `secs` 欄位:近 30 天最大值若超過 90 秒,
  就加 `--bound-direct-only`(只跑直接相依那層)。
- **回頭條件查的是本機帳,打不到消費端**(r1 邊界席指出,無解但要誠實記):
  治理帳是每個專案各自本地的檔案,工具鏈沒有跨專案彙總機制。
  上面兩條 REVISIT 查的是本 repo 自己的帳,**只能回答「這道閘在本 repo 的行為」**,
  回答不了「消費端有沒有在用」。想回答後者要另外設計遙測,那是另一案,本案不做也不假裝做。
- **測試有副作用**:專案自己宣告的測試指令,跟 CI 跑全套同等副作用、同一信任邊界。
  沿用上一份計劃的放行理由,不另建「安全跑」旗標(那會變成又一個零觸發開關)。
- **[S1] 第 3 步的交集算得準不準**:節點「點名哪些檔」這件事本身有覆蓋率問題
  (筆記正文寫到的檔案路徑才算數)。**這一步比原本的波及計算保守**:
  原本會把間接相依也算進來,新做法只算直接點名。
  ★這是刻意的取捨,要寫進節點★:換來的是每次推送近乎免費,失去的是間接相依那層。
  REVISIT:2026-11-07 若治理帳出現「合約測試在 CI 紅、但本機那道閘當時回 no-pins」的案例,
  代表交集算得太窄,要把間接相依那層加回來(可以只加一 hop)。
- **成本基準要重量**:引用的舊數字(38 支 28.7 秒)已過期,現在是 46 支 46 秒,兩週漲六成。
  落地時以當下實測為準,並把數字寫成可重算的標記,不要再抄。

(先用便宜的依賴索引篩,再跑真測試,不是每次重算整張圖)、
