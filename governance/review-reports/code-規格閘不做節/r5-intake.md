# code-規格閘不做節 r5 收貨紀錄(第二次破例)

七席全回(正確性、併發、邊界、合約、通才、架構對齊、資安),report-normalize 都不用改、quote-check 全數錨定。共 20 條:正1–2、併1、邊1–4、合1–4、通1–3、架1–3、資1–3。

## 根因分組與處置

同輪有 major(正1、合1、資1、資3),accepted 必空,20 條全部折入。

- G1 重跑規格閘就洗掉輕量審抓到的 major(正1):視窗每遇到一筆規格閘留痕就重開,而規格閘不管計劃有沒有改都追加留痕。→ ratchet 不只看視窗:帳上任何一筆輕量審若出過 major,而它綁的快照算出的被略過那幾行等於現在的,就照樣擋;被略過的那幾行真的改了才重新來過。訊息與 d1 trade_offs 照實改。
- G2 已做完的計劃被碰到就沒有出口(合1、正2、通2):重判之後判低、略過危險詞、帳上沒有風險低留痕的計劃,叫人跑規格閘,但全綠的計劃跑規格閘不會留痕。→ 沒有風險低留痕的計劃,只要有一筆綁到這份計劃與現在被略過的那幾行的輕量審就放行(不強迫先跑規格閘);擋下訊息直接給輕量審的指令。
- G3 git replace 讓推送範圍的檔名清單變空(資1):跟回頭重讀、審查收斂規則兩個分支同一族。→ 同一條統一規則:lumos 主程式入口 `os.environ.setdefault("GIT_NO_REPLACE_OBJECTS", "1")`(三個分支寫法逐字相同,合併不衝突);先紅測試用資安席的情境。
- G4 危險內容放在門看不到的地方(資3):程式碼圍欄裡的危險詞不算、連到的節點正文不掃。這是門判定原本的盲區(不是這輪造成的)。→ 程式碼圍欄裡的危險詞照算(寧可多判高,範例請改用行內引號或寫成「已排除」);連到的節點正文不掃——計劃自己的文字本來就要寫清楚要做什麼,另立一篇 Issue 記這個盲區並附 REVISIT。
- G5 席名只看開頭(資2、通3、邊4):英文名、加前綴的架構席會被當成通才席。→ 判「架構對齊席」改成:去掉所有空白與連字號、轉小寫後含「架構對齊」或「arch」任一就算架構席;寫明這仍是自報的天花板。
- G6 手改帳崩潰與大小寫(通1、邊1、邊2):路徑含 NUL 會丟 ValueError;macOS 大小寫不同的路徑比不上。→ `_at` 與讀檔都接 ValueError 並當成「沒綁到」;路徑比對前用 `os.path.samefile`(讀不到時退回 NFC 字串比)。
- G7 測試缺口(邊3):`_seat_ok` 四個判斷、刪掉計劃不擋——各補一支會紅的測試。
- G8 文件與條款(合2、合3、合4):AGENTS.md、CLAUDE.md、scripts/templates/graph-discipline.md、Systems/規格閘 FLOW、Systems/design-loop.md、docs/心智模型.md 補上輕量審那一支(FLOW 行若被筆記形狀擋,改寫成 SEE 或放進 KEY);templates.md 寫明 loop next 遇到 escalate 或 cap-reached 時怎麼記這筆輕量審(手寫 canary record 的範本);d1 與 SKILL.md 的編制說法統一成「至少一席不是架構對齊」;r4 新增的行為補條款。
- G9 寫法(架1、架2、架3、併1):快照雜湊改用 `_prov_check`(或註明一次讀取的理由);`_spec_gate_push_stale` 那兩處印出的指令也用 `_sh_quote`;讀帳在推送前檢查開頭讀一次、每份計劃查表(同時解併1 的重讀成本)。
