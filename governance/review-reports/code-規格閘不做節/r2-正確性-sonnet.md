blocking: 是 — 這個判準會把「其實要做的事」判成不做而放行,門被誤判成風險低,審查席根本看不到那份計劃。
引句:「_NOGO_NEG_RE = re.compile(r"不|沒有|無|排除|暫緩|非本期|\bout of scope\b|\bnot\b", re.I)」
問題:判準只看那一行有沒有出現否定字,不看這個否定字是不是在否定那件危險的事。`不`、`無` 是單字,中文裡「不只…還要」「不需要等…這版就」「無縫」「不間斷」都含有。更糟的是,關鍵字表自己就有含「不」的詞:`prod-irreversible` 的 `不可逆`。所以只要寫出這個危險詞,這一行就會自己通過否定檢查。
失敗情境(實測 `_nogo_skip_lines` 的回傳):
- `## 不做` 底下寫 `- 不只退款,還要扣款`,第 2 行被跳過。
- 底下寫 `- 不需要等下一版,這版就扣款`,第 2 行被跳過。
- 底下寫 `- 不可逆地刪除使用者資料`,被跳過,而該行命中的正是 `不可逆` 本身。
- 底下寫 `- 直接呼叫 Stripe 扣款(不含退款)`,第 3 行被跳過。
以上寫法在有四行已排除的計劃裡,都會被判風險低,不派設計審。設計文件只承認「一開始就在不做清單寫一條其實要做的事」靠 RETIRE-IF 事後回頭查。這裡不需要刻意閃避,自然語句就會中,所以這不只是那一型。
建議:否定字至少要在行首或項目開頭附近出現,或把關鍵字命中的詞所在的子句,和否定字擺在同一個子句裡才算。含否定字的危險詞(`不可逆`)要先從行裡剝掉,再判有沒有其他否定字。
