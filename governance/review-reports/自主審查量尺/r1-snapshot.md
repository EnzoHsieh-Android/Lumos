# 自主審查量尺_計劃

PRIOR-ART: 借 Meta RADAR(arXiv 2605.30208v1)的兩個形狀:門檻用結果(退回率、事故率)校準而不是寫死;每一類自動化要有乾淨紀錄才繼續、出事可暫停。抽查借稽核抽樣的標準做法:可重算的隨機抽樣加上比例估計的信賴區間。盲審對照借 Claude Code auto 模式分類器「只看工具呼叫、不看模型自己的說明文字」的設計(出處:openedclaude/claude-reviews-claude 第 07 章,第三方對 Claude Code 2.1.88 的原始碼分析,編排者沒有對照原始碼核實)。機制層沿用既有的逃逸帳(`docs/.escape-log.jsonl`,與它的自動記帳)、代碼審通過留痕、外家審查席,不加依賴。
RETIRE-IF: ①抽查連續 30 個已放行的提交都沒有確認的缺陷,而且各類別逃逸率連續 8 週沒變 → 抽查降頻到每月一次(量尺已穩定,繼續抽只是成本);②抽查報出來的發現「重現不了」多過「重現得了」→ 停抽查,先修抽查者(它在製造噪音,不是在量漏網)。

## 一句話

做兩把量尺:一把從既有逃逸帳算「每一類改動放行之後漏了多少」,一把主動抽查已放行的改動、量出逃逸帳看不到的漏網。另做一個盲審對照實驗:量「派工單附作者的說法」有沒有讓審查席少抓東西。**這一期只量、不改任何閘**;量出來之後才談哪一類可以少審、派工要不要拿掉作者的說法。

## 為什麼先做這兩件

- 目標是人不介入審查,前提是知道「自動放行的東西有多可靠」。現在只有一本逃逸帳,而且它有三個缺口:沒分類、會重複計、只看得到浮上來的錯。
- 沒有這兩把量尺,任何「這類改動可以少審」的決定都是憑感覺——RADAR 能放手,是因為它每一類都有 60 天的退回率與事故率撐著。

## 第一件:逃逸率依類別

### 類別怎麼分

- **分級**:light / standard / high,取審查帳(`docs/.canary-log.jsonl`)裡那個迴圈記到的分級。**不是每個迴圈都有**:2026-09-26 數,代碼審 146 個迴圈裡 33 個早於分級制度、沒有分級——歸「未定錨」一類照算,不丟(設計審前掃更正,原文寫「一定有」)。
- **範圍類**:迴圈對得回計劃筆記時,取計劃的 `scope/<類>` 標籤(九類之一);對不回的標「未分類」。
- 兩者交叉就是類別。不自創新的分類——這兩個欄位都已經存在、有人維護。

### 分子與分母

- **分母**:該類別裡「放行了」的迴圈數(審查帳有收斂或通過紀錄的)。
- **分子**:逃逸帳裡歸到該類別迴圈的筆數,先去重:同一個缺陷佐證(提交編號、CI 執行編號)只算一次,歸給最早放行、改動範圍碰到它的那個迴圈;歸不到唯一一個的另列「歸因不明」,不猜。
- **分開一欄**:下一站審查接住的(例:設計審放行、代碼審抓到 blocker)不算漏到下游,另列「下一站接住」。這一欄是好事,不該跟真的漏網混在一起。

### 輸出

- 一個唯讀指令(暫定 `lumos gov --escape-rates`),每類印:放行數、逃逸數、逃逸率、95% 信賴區間(比例的 Wilson 區間)、下一站接住數、歸因不明數。
- 放行數少於 20 的類別,只印數字、標「樣本太少不下結論」。

## 第二件:隨機抽查已放行的改動

### 抽誰

- **母體**:已推上遠端、有代碼審通過留痕的提交,加上風險低計劃直接放行的提交。**後者目前沒有「放行」紀錄**:治理帳只有規格閘每次跑的紀錄(`spec-gate-run`,記的是跑的當下的提交編號,不是後來推上去的那個);實作前要先定怎麼認定這類提交,認不出來的這一期先不納入、在輸出旁寫明(設計審前掃 2026-09-26 補)。
- **抽法**:用提交編號算雜湊決定抽不抽(預設 10%)——可以重算、事後不能挑。
- **量**:每週最多 3 個(外家審查席有額度限制;也讓成本有上限)。

### 誰來查、怎麼查

- **抽查者用不同家族的模型**(外家席,Codex):只給凍結的改動與它宣稱要做的事,**不給原本的審查報告與結論**——給了它會順著原結論講。外家席不通時退用同家族模型,但帳上標「同家族,獨立性弱」,統計時分開算。
- **發現要能重現才算確認**:每條發現要附一個能讓問題現形的做法(會紅的測試或指令),由編排者機械地跑一次;跑出問題的算「確認」,跑不出來的算「未確認」。**不靠人判真假**——這是為了人不介入的目標,也跟既有「錨不到的不採信」同一個規矩。
- 確認的缺陷自動寫進逃逸帳(站名「抽查」),所以第一件的統計會吃到它。

### 輸出

- 抽查帳:抽了哪些提交、各報了幾條、確認幾條、未確認幾條、用了哪個家族。
- 估計「抽查漏網率」= 有確認缺陷的抽查提交數 / 抽查提交數,附 95% 信賴區間;同家族與不同家族分開算。

## 第三件:盲審對照實驗(先量,量到有差才改流程)

### 為什麼

- 我們的派工單都附一段「這批在做什麼(作者的說法,當可反駁的宣稱)」,審查席先讀到作者的敘事再看改動。
- Claude Code 判斷動作安不安全的分類器刻意只給它看工具呼叫、不給看模型自己寫的解釋,理由是模型寫得有說服力就會影響判斷。
- 作者的說法到底有沒有讓審查席少抓東西,我們沒量過;直接拿掉又會讓審查席不知道改動的目的,可能多報不相干的東西。所以先量。

### 怎麼做

- 接下來的代碼審,每一輪多派一席「盲審席」:鏡頭與家族跟同輪某一席相同(配對),派工材料只有凍結改動與測試,**不給作者的說法、不給計劃、不給同輪其他席的任何東西**。
- 盲審席照常記帳,帳上標明它是盲審、配對的是哪一席;它的發現照常處置(折或放行),不因為是實驗就放過。
- 累積 12 對之後比較:兩邊各抓到幾條、其中幾條被折(確認是真的)、有幾條只有其中一邊抓到。
- **判準**:盲審席被折的條數比配對席多、而且多出來的在 12 對裡出現 3 對以上 → 把「每輪至少一席盲審」寫進派工規矩;沒有差就結案、記下「作者的說法沒有量到影響」。

### 成本

- 每輪多一席,量到 12 對就停;這段期間代碼審的成本多一成到兩成。

## 條款

- [S1] 當逃逸帳裡同一個缺陷佐證被記到多個迴圈,逃逸率統計應只算一次,並歸給最早放行且改動範圍碰到它的迴圈;歸不到唯一一個時應列入歸因不明而不算進任何類別 [test:t_escape_rates_dedupe_and_attribution]
- [S2] 若逃逸帳的站名表示是下一站審查接住的,則它應列在「下一站接住」而不算進逃逸率 [test:t_escape_rates_caught_next_stage_separate]
- [S3] 當某類別放行數少於 20,輸出應標明樣本太少不下結論,且仍印出原始數字 [test:t_escape_rates_small_sample_flag]
- [S4] 當迴圈對不回計劃筆記或計劃沒有範圍類標籤,該迴圈應歸在「未分類」而不是被丟掉 [test:t_escape_rates_unclassified_kept]
- [S5] 若同一個提交被問兩次抽不抽,兩次答案應相同,且抽中比例在大量提交上接近設定值 [test:t_audit_sample_deterministic]
- [S6] 當抽查派工時,給抽查者的材料應只含凍結改動與宣稱目的,不得含原審查報告、審查帳或結論 [test:t_audit_sample_blind_material]
- [S7] 若一條抽查發現的重現做法跑不出問題,則它應記為未確認,不得寫進逃逸帳 [test:t_audit_sample_unreproduced_not_escape]
- [S8] 當抽查者是同家族模型,抽查帳應標明,且漏網率統計應與不同家族分開 [test:t_audit_sample_same_family_separate]
- [S9] 當本週已抽查 3 個提交,之後被抽中的應延到下週而不是丟掉 [test:t_audit_sample_weekly_cap_defers]
- [S10] 當派出盲審席,給它的材料應只含凍結改動與測試,不得含作者的說法、計劃筆記或同輪其他席的報告 [test:t_blind_seat_material_excludes_author_claims]
- [S11] 若一筆審查帳標了盲審,則它應帶有配對席的名字,且配對席必須在同一輪有帳 [test:t_blind_seat_record_requires_pair]
- [S12] 當盲審對照累積到 12 對,比較報告應列出兩邊各抓到幾條、各被折幾條、只有一邊抓到的有幾條,並照判準印出建議 [test:t_blind_seat_comparison_report]

## 回退

兩件都是新增的唯讀統計與一本新的抽查帳,不動任何閘的判定。回退=移除新指令與排程掛勾;逃逸帳裡站名「抽查」的列保留(它們是真的缺陷),抽查帳檔案保留作歷史。

## 實務隱患

- 對外送出(不排除):抽查與盲審席都會把凍結改動送給外家審查席(Codex,外部服務)。本 repo 是公開的;★消費專案不是★——抽查在消費專案跑時會把私有程式碼送出去。預設只在本 repo 抽查,消費專案要自己在專案設定明寫打開;盲審席照既有代碼審的外家席規矩(消費專案本來就會派外家席)。
- 併發:逃逸帳與新的抽查帳都是追加寫,多個會談可能同時寫;沿用既有記帳的寫入方式,讀的一側遇到寫一半的最後一行要略過不報錯。每週 3 個的上限要在同一週被兩個會談同時抽中時也守得住(以帳上已記的筆數判,不是以記憶體計數)。
- 效能:逃逸率統計要把逃逸帳、審查帳、治理帳與計劃筆記對起來;是手動或週報才跑的唯讀指令,不進任何提交或推送的閘。
- 已排除:金流:只讀帳本、派審查席,不碰任何付款或計費
- 已排除:不可逆:統計是唯讀;抽查確認的缺陷寫進逃逸帳是追加一列、可以人工標註撤回;盲審席的記帳跟一般席相同
- 已排除:守衛面:這一期只量、不改任何閘的判定;盲審席的發現照常處置,不因為是實驗就放行

## 誠實界線

- 盲審對照只有 12 對,只能看出很明顯的差別;抓到的條數本來就隨改動大小浮動,配對可以抵掉一部分,抵不掉全部。

- 我們的量很小(代碼審通過留痕兩個半月 224 筆),每類別的區間會很寬,要累積好幾個月才窄到能拿來調分級;這一期只保證「開始量」。
- 「歸給最早放行且改動範圍碰到它的迴圈」是啟發式,會歸錯;歸不到唯一一個的另列,不硬塞。
- 抽查只看得到「查得出來」的缺陷;抽查者跟原審查員同家族時盲點可能相同,所以分開算,也把不同家族當預設。
- 「重現得了才算確認」會漏掉難重現的真缺陷(例:只在特定環境出現),方向是低估漏網率——這一點要寫在輸出旁邊。
