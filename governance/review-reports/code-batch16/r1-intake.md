## 編排者自己重現的(≥major 一律自己查過才折)

外家席全部標「讀碼推論,未實跑」(它的沙箱沒有可寫暫存目錄),所以每一條我都自己敲過:

1. **exists 用 cwd**:`cd governance && python3 ../scripts/lumos loop next code-batch15`
   → 對一個**確實存在**的檔案印「★這個檔案現在不在了★」。**HIT**,而且是我想避免的
   「遞一條死路給人」的反面。
2. **終止狀態說「下一輪」**:`loop next graph-usage-stat`(escalate 狀態)
   → 同一次輸出裡同時印「停掉這個編號」和「下一輪要自己凍一份新的」。**HIT,兩句直接打架。**
3. **指令猜死**:補完的指令寫死 `--disposal` 與 `--repo .`。light 帳要 `--light`;
   `--repo .` 從子目錄呼叫就錯。**HIT。**
4. **fail-open 謊稱沒記**:畸形 spec_path → 例外被吞 → 印「帳上沒記」。**HIT,那是假話。**
5. **畸形值塞進指令**(通才席附註):`--spec [1, 2, 3]` 這種不能執行的指令。**HIT。**

## ★席位有一條判斷我推翻了★

通才席在最後說:我擔心的「帳上沒記這個迴圈在審什麼」字串碰撞在這份材料裡**不存在**,
理由是 gate-pending 那句寫的是「帳上**也**沒記」,多一個字所以不會被純子字串比對誤中。

**這一點錯了。** 那個「也」加在被比對子字串的**前面**——
「帳上也沒記這個迴圈在審什麼」仍然完整包含「沒記這個迴圈在審什麼」。實測驗過。
我的實測(把整段拿掉、測試照樣全綠)站得住,改成行首比對是**必要的**不是保守。

★但它同一段裡另一半是對的★:它用 3 個定點突變驗過那支測試其餘斷言確實有咬合力,
排除「整支測試都是假綠」——這個查證做得比我原本的更完整。

## 折入的九條

f1 取到舊輪卻用「上一輪」口吻 / f2 exists 用 cwd / f3 終止狀態說「下一輪」 /
f4 指令猜死閘模式 / f5 指令猜死 repo 根 / f6 fail-open 謊稱沒記 /
f7 畸形值塞進指令 / f8 `.resolve()` 沒跟既有那支對齊 / f9 測試碰到現場沒斷言咬住

修法要點:
- 取值仍取「最後一筆有值的」(那是對的),**但補完指令只在「最後一輪自己記了」時才給**
  ——拿更早輪次的材料去判最後一輪是明確錯誤的輸入,不是保守退化。
- 文案分三種:最後一輪自己記了且還會有下一輪 → 原本那句;不是最後一輪的 → 明講
  「這一份不是最後一輪審的東西」;終止狀態 → 「這個編號沒有下一輪了」。
- 路徑錨定改用既有的 `_vault_repo_root(env)`,連 `.resolve()` 都跟既有那支一致。
- 型別驗到位:非字串的 spec_path 一律當沒有,並且講「讀不動」不講「沒記」。
