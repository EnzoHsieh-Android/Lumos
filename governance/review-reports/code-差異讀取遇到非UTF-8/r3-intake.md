## 判讀

- F4 折。★「全部換字元」這個原則本身要修★:UTF-8 正常時結果一樣沒錯,但不正常時是把「中斷」變成「猜」,對要寫檔、刪檔的路徑更糟。
  - 找專案根目錄(git rev-parse --show-toplevel)的四處(移除、一鍵拆機、初始化、安裝入口)改成 errors="strict"——恢復改之前「解不了就擋」的行為。
  - 移除與一鍵拆機多接一個 UnicodeDecodeError,訊息講明是路徑編碼的問題(原本會被說成「這裡不是 git 專案」);初始化與安裝入口照原本的退路(用目前目錄/跳過專案層)。
  - 守衛多一條:凡是找專案根目錄的呼叫都必須是 strict。
  - 其他把 git 吐出的檔名拿去動檔案的地方查過:從來源更新(_pull_source_or_abort)只在檔名完全等於工具自己的帳本檔名(全是英文)時才還原,換過字元的不可能相等,只會擋下,不改。
- F5 折:命令清單第一個元素是變數時往回找同一函式裡的字串指定;sys.executable 算別的程式;其他看不出來的一律當成可能是 git。守衛自我驗證加上 Codex 的樣本。改完全檔沒有多點名任何一處。
- code 迴圈:輪內有 major,accepted 必須是空的——兩條全折。
- 數字重數(機器數):守衛管到的呼叫共 62 處,原本 3 處已有,這次補 59 處(55 處換字元、4 處嚴格解碼);Issue 筆記同步改。
