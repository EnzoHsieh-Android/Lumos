# r3 收貨紀錄更正(code-kotlin規則包)

r3 載體帳(規則-sonnet)的 `--regression-set` 填了 正1–正6、邊1、邊2、規1–規4、合1、合2 共 14 條。帳本不能改,在這裡更正它的證據等級:

- 依據只有「程式來源」:那些段落是第二輪修正(修前 73276ca7b → 修後 af64ec645)才加進來或改到的,例如 files 區塊的新讀法、缺〈來源縮寫〉節的早退、逾時測試的 4 秒門檻、`owner == rule_id` 條件、規則包裡 OkHttp/DataStore/長壽 scope/Ktor 規則的放寬,以及型錄的搬級補註。
- 沒有做派工範本 §3.1 第 6 步要求的「同一案例修前、修後各跑一次」的兩版對照,也沒有隔離區間內的其他改動。
- 所以照 §3.1 的收貨規則,這 14 條的修補因果應讀成**未判定**,不是「已支持由上一輪修補造成」。跑滿回顧(cap-retro.json)起草者也獨立判成 attribution-undetermined,兩邊一致。
- 處置去向(15 折、1 放行)與嚴重度不受影響。
- 第四輪起照 §3.1 準備修補鏡頭,由新席自己做兩版對照;沒做到的不填回歸清單。
