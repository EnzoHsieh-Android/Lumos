**Finding 1**
severity: major
blocking: 是 — 照字面實作,S7 的三級子標題與空標題案例會紅,實作者必須自己決定改 `_h2_section_lines` 的簽名,而計劃明寫不改。
引句:「沿用 `_h2_section_lines(text, _NOGO_H2_RE)` 取那一節的候選行」
問題:`_h2_section_lines` 回傳的候選行不含行首第 0 欄、以 `#` 開頭的任何行。它的迴圈對 `ln.startswith("#")` 的行一律 `continue`,既不收進結果,也只在 `## ` 或 `# ` 開頭時才結束節。所以 `### 子`、空的 `##`、`##<tab>做法` 這幾種第 0 欄標題,過濾器根本看不到。計劃說「遇到第一個像標題的行就停」,而 `_NOGO_STOP_RE` 裡的 ATX 分支(含空 `##`、tab)對第 0 欄標題是死碼。它只對縮排 1 到 3 格的標題有效,因為那種行不是以 `#` 開頭,會留在候選行裡。
具體失敗情境:計劃寫 `## 不做`、`- 不做退款`、`### 實作`、`- 本版實作扣款補償`。`### 實作` 被丟掉,`- 本版實作扣款補償` 仍在候選行裡且符合清單項目,被跳過,規格閘判風險低。這正是 r1 要擋的「做法節被吞」。我用現有函式實測:`## 不做`、`### 子`、`##`、`##<tab>做法` 之後的行全部還在結果裡,只有 `## 做法` 會停。S7 的寫法若是散文,因為散文本來就照掃,測試會假綠;S7 的清單項目版本才會紅。
修法:計劃需寫明改 `_h2_section_lines` 加選配參數(r1 原本的做法),或在過濾前自己重掃原始可見行。

**Finding 2**
severity: major
blocking: 是 — `_NOGO_ITEM_RE` 無法由計劃文字唯一寫出,不同寫法的實作會在「散文照掃」這條安全邊界上有不同結果。
引句:「以 `-`、`*`、`+` 或 `數字.`、`數字)` 開頭的行,與它底下比它縮排更深的續行」
問題:以下幾點計劃都沒定。
- 標記後要不要求空白。字面讀法「開頭」會讓 `**扣款補償**` 這種粗體散文被當成 `*` 項目,`3.14 版不做`、`2026.` 這種被當成 `數字.` 項目,`-退款` 也算。
- 行首縮排上限。4 格以上在 CommonMark 是程式碼區塊;tab 縮排怎麼算也沒寫。
- 「底下比它縮排更深的續行」以哪一行為基準:最近一個項目行,還是整個清單的第一層。
- 項目之間夾空行後,更深縮排的行還算不算續行。
- 縮排更深但前面是散文、不是項目的行,算不算。
- 懶續行(沒縮排、接在項目後面的行)計劃沒寫。保守的做法是掃,但要寫明。
具體失敗情境:在不做節寫 `**本版同時實作扣款補償**`,實作 A(不要求空白)判風險低,實作 B(要求空白)判風險高。兩個實作都「照計劃做」,只有 B 符合「散文照掃」的意圖。
修法:把 `_NOGO_ITEM_RE` 寫成具體的正規式,例如 `^ {0,3}(?:[-*+]|\d{1,9}[.)])[ \t]`,並寫明縮排基準與空行的處理。
