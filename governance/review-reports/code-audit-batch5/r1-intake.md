## 編排者自己的機械覆核(不靠席位轉述)

### f1 消費端假綠(通才 + 外家獨立指到同一條)
宣稱:把來源位置指向「這個 repo」,在消費端會拿自己跟自己比。
覆核指令與輸出:

    grep -n "_VENDORED_TOOLKIT = " -A 3 scripts/lumos
    → 11164:_VENDORED_TOOLKIT = ("scripts/lumos", "scripts/test_lumos.py", ...

**HIT**:測試檔本身確實在會被複製進消費專案的清單裡,所以在消費端 repo 根就是消費專案自己,
那條「vendored 工具是不是最新版」的檢查會拿自己比自己。通才席還另外搭了假消費端 repo 實測,
證實不管拷貝多舊都印綠。**這是我在修「別把沒驗當驗過」的過程中自己造出來的假綠。**

### f3 早退繞過收尾(外家 + 通才)
覆核方式:實跑打錯字的 -k,前後數系統暫存目錄底下的根目錄個數。
修之前會多一個;改用 finally 之後前後相等(0 → 0)。**HIT**。

### f6 常數命名
架構席說模組層常數「全部不帶底線前綴」。我查了:`_LUMOS_INPROC`(131)與 `_GH_STUB_HEAD`(17575)
都是帶底線的模組層常數,所以「全部」不成立。**但它的實質論點仍然對**——這個常數在折入 f2 之後
變成「可用環境變數覆寫的門檻」,跟 `TEST_TIMEOUT_SEC` 同類,那一類確實不帶底線。照改。
