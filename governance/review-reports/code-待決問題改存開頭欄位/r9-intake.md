## 根因分組

1. 清單外鍵名規則的邊角(甲):找不到頂格 `pending_questions:` 就整份不掃,清單頭用 `?` 複雜鍵、頂格 flow、`<<:` 合併鍵寫時題目靜默消失(C1);前綴走訪要求 `?`/`-` 後面還有字元,行尾去空白後單獨一行的 `?` 繞過複雜鍵規則(E1);status 豁免看整行縮排不看鍵欄位(E3、G3);縮排 `pending_questions:` 的檢查沒跳過 block scalar 內文,沒有這個欄位的筆記被誤擋(K1、C4);flow 跨行時續行不以 `{`/`[` 開頭,裡面的題目鍵不檢查(K2、G2)。→ 沒找到清單頭時對整份結構行查 `pending_questions` 字樣;前綴走訪接受行尾;豁免看鍵欄位;第一圈也跳過 block scalar;含待決問題時清單外的 flow 必須同一行閉合。
2. 簽核中斷(丙):Ctrl-C 落在帳寫完、fsync 之中時,帳不截回、筆記被還原,帳留一行沒戳記的簽核,guard abandon 會當成授權(N1、E2、K3、G1、C2)。→ 帳追加對任何中斷也先截回(新建的刪掉)再往外丟。
3. 小修:decision-supersede 的 `--ended` 仍用 match(C3、G4、K5);日期用 `\d` 收全形與阿拉伯數字(E6、K5);簽核備註裡的 U+2028/U+2029/U+0085 不被 json.dumps 跳脫,讀端 splitlines 會切成兩行而能偽造一行帳(S1);計劃與測試標籤過期(K6);測試沒守框線不當 emoji(K4 第一點)。
