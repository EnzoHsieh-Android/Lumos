## 根因分組

1. 清單外的題目(甲):歸屬檢查只對部分擁有者套鍵名規則——頂格那一行(E1)、決策項目(E2 流式、A7 另寫一份決策狀態機)不查;同時對合法手寫寫法太嚴(E5、E6、C5)。另寫了第四份 block scalar 判斷,語意比專案既有三份多(A6)。→ 統一:清單範圍以外每一行(含頂格、含決策底下)只套同一條鍵名規則與流式寫法規則,不再替各擁有者另寫文法;block scalar 只認專案既有的四種寫法。
2. 看不見的字元(乙):零寬字元只看兩側是不是字母、不看文字系統(E4、S2:拉丁字母間能藏位元;E3:蒙古文、馬拉雅拉姆文、波斯文詞尾被誤擋;C2:‼️ 這類 emoji 被誤擋);空白類字元混用也能藏位元(C4);相連規則沒有測試(C3);可忽略字元表的測試拿表自己當預期(K2);NFC 錯誤指錯字(E8)。→ 依文字系統放行、整份值的看不見選擇設總量上限、測試改用獨立的預期。
3. 簽核與寫入拒絕(丙):簽核在搶鎖前讀筆記、失敗時用舊內容覆寫(N1、G3)、帳讀不到時被截成 0 位元組(C1、N2)、訊息與實況矛盾(N3)、成功時少印一行(G2)、帳檔沒查符號連結(S1);讀檔函式的符號連結拒絕波及唯讀呼叫端(G1、C6);最外層印擋下訊息沒清洗(S3);殺傷力檢查遇 BOM 訊息錯(G4);決策指令的說明參數帶換行會寫壞筆記(E7);兩種接法並存與擺放(A1、A3、A4、A5)。→ 簽核在鎖內讀原狀、帳只追加不重寫、失敗只截回追加前長度;符號連結與硬連結檢查只在寫入原語、共用一支;最外層訊息清洗。
4. 文件與測試(K1、K3、K4、K5、K6、E9、A2):計劃舊段落沒跟上、測試被改弱或守不到。
