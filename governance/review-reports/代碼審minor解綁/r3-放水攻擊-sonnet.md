severity: major

## 逐項攻擊

### 擋得住(一句帶過)

- 非空且型別正確的 `finding_sources` 讓路給新步驟,跟新步驟「不適用」的條件逐項對過,沒有兩邊同時不管的縫:
  - 讓路用的是載體帶非空 dict、`code-` 開頭、輪內有 major、accepted 非空。
  - 新步驟的適用條件是同一組,只多排除 blocker。
  - blocker 在現行程式是更前面的 elif,不會被讓路。
- `{}`、型別壞掉(值是字串、清單裡混非字串)、非 `code-` 迴圈,都退回舊判或寫側 rc 2。
- 席位只低報不了:`canary record` 的現行寫側讓帳面 severity 不得低於報告最高。高報只會更嚴。
- 報告含 blocker 條時,那列帳面必為 blocker,整輪走 blocker 分支,不會進新路。
- 報告形狀的退回只會往嚴的方向(整輪全折),拿它放水沒有好處。
- 重現不到清單(refuted-set)的 major 沒人指到,第 4 點會擋。
- 回放與凍結:閉包收的是判定輪全部帳列的 report 路徑,新步驟讀得到。舊帳沒有 `finding_sources`,新步驟印「—」,結果不變。
- 回退:舊分支還原後,帶 `finding_sources` 的帳列一律走舊句判不過,寫側 rc 2 指路。
- 後記的席、重記同席,有 S8、S14 管。
- 把席放到別的 `--round` 躲開本輪核對,是舊規則就有的洞,新規則沒讓它更糟。

**finding 1:原報 major 可以全部掛在一個折入 id 下,放行的 id 可以全部掛同一條 minor,只要一處假對應就夠**
severity: major
blocking: 是
⚠ 判不準這是不是「已知天花板、交給 REVISIT」就夠。我的判斷是不夠,因為規則本身把成本壓低了。

引句:「同一條原報也可以被多個 id 指」

具體帳列與報告:

- A.md 檔級 major,依序有 #1 major(其實是守衛能被繞)、#2 major、#3 minor(錯字)。
- 載體的 findings-set 是 F1、F2、F3,其中 F3 是編排者自己列的、實質上是 major 的問題。
- 帳上 folded 是 F1,accepted 是 F2、F3。
- `finding_sources` 填 `{F1:[A#1,A#2], F2:[A#3], F3:[A#3]}`,`accept_reasons` 填 F2「錯字不修」、F3「同上不修」。

記帳與問閘各自的判定:

- 第 3 點:來源都存在。
- 第 4 點:A#1、A#2 都只被 folded 的 F1 指到,過。
- 第 5 點:F2、F3 都指到 minor、沒指到 major,過。
- 第 6 點:沒帶 `finding_obj` 自填等級就不核。
- 〈實務隱患〉自己寫「要明確造假兩處對應」,但這裡只有 F3→A#3 一處是假的。F1 一個折入 id 指兩條 major 看起來像合併,不算造假。
- S20 又明文規定「兩個 id 指同一條原報 minor 都放行」要視為合法,等於允許一條 minor 撐無限個放行額度。
- 現行 `accept_reasons` 只驗「至少 4 字含實字」,不擋「同上不修」。

補法(三選一或疊用):

1. 放行 id 的來源集合兩兩不相交(單射),放行條數就不會超過報告裡 minor 條數。這個分母是工具從報告讀的,不是編排者自填。多席報同一件事,仍可由一個 id 指多條。
2. 折入 id 與放行 id 指到的條不得重疊。
3. 放行理由必須含從所指那一條原文(該條 `severity:` 行到下一條之間)抄下的連續 ≥10 字,機械比對,比照 quote-check 的做法。

**finding 2:寫側核對讀「別席報告」的方式沒寫死,可能跟閘端分歧,把失敗全推到閘端**
severity: minor
blocking: 否

引句:「讀檔同寫側既有讀報告的方式」

- 閘端是「讀位元組、驗 sha、`errors="replace"` 解碼」。
- 寫側現行的載體 `--report` 是嚴格 UTF-8 解碼。
- 別席報告在寫側核對時,沒寫要不要驗帳上 `report_sha256`,也沒寫解碼失敗怎麼辦。
- 結果是:報告檔被動過、或含壞位元組,載體會先記進去,到閘端才失敗,而載體不能重記。
- 補法:寫側核對直接呼叫閘端同一支讀取函式(含 sha 與解碼),sha 不符或解碼失敗在記帳當下就 rc 2。

**finding 3:載體記進去之後才失敗,而且失敗發生在跑滿上限那輪,誠實的編排者沒有出路**
severity: minor
blocking: 否

引句:「一輪只能有一筆載體,不能重記,這輪就照舊全折」

- 「開下一輪時不帶 `--finding-source`」在第 3 輪(上限)不成立,只能攤給人裁。
- 最容易遇到的是載體後又有席入帳(S14)。
- 補法:`canary record` 寫側加一條,本輪已有載體帶 `finding_sources` 時,拒收該輪新增的席帳,rc 2 並指路「載體最後記」。這樣閘端才失敗的路徑只剩手改帳或檔案被竄改。

**finding 4:閘端對格式不合法的來源字串沒有條款**
severity: minor
blocking: 否

引句:「型別不對(不是 dict、值不是字串清單)判不過,不噴例外」

- S10 只在寫側驗序號是正整數。
- S22 只列路徑不在本輪、序號超出宣告數。
- 手改帳裡的 `"F1":["a.md"]`(沒有 `#`)、`"a.md#0"`、`"a.md#x"`、`"a#1#2"`,閘端會怎麼判沒寫。
- 照字面做,拆 `#` 與轉整數很可能直接丟例外,違反 S16「不噴例外」的精神。
- 補法:S22 或 S16 補一條,來源字串格式不合法一律判不過並點名,不是例外。
