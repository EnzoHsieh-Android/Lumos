我找到幾個會讓新判準判錯的輸入,其中兩個讓造假的引句直接消失、不被檢查。沒有實際執行,以下輸入都是對照 `_quote_rows`(`scripts/lumos` 第 25773 行起)和 spec 規則推演出來的。

## 1. 反引號或圍欄遮蔽讓造假引句靜默消失(比舊判準更寬鬆)
severity: major
blocking: 是
引句:「包在反引號行內程式碼或 ``` 圍欄程式碼區塊裡的不算(說明文字示範格式時常這樣寫,舊抽取器會誤抓,見 Issue 第四點)。標籤後面不是開引號的照舊不理。」
file: `scripts/lumos:25773` 現行抽取沒有任何遮蔽,`n_markers` 會數到每個「引句:「」標記。反引號包住的造假引句舊判準會抓到並判錨不到。
1. 輸入 A。報告有一條真引句,另一條造假的用反引號包起來:
   ```
   引句:「合法前綴文字至少十個字,後面接的是別的東西。」
   `引句:「這句話快照裡根本沒有喔喔喔」`
   ```
   - 第二條被 S4 遮蔽,不進 `quotes`,也不進 `n_markers`。
   - 結果 rows 只剩一條 ok,全數錨定。舊判準會判這份有一條錨不到。
   - 席位只要把自己編的引句包進反引號,這條發現的證據就完全不被檢查。
2. 輸入 B。落單反引號配對跨行,不需要完整的包裹:
   ```
   注意 ` 單獨一個
   引句:「編造的內容編造的內容編造」
   結尾 `
   ```
   - 如果遮蔽用 `` `[^`]*` `` 這類跨行配對,中間整行被吃掉,造假引句同樣消失。
   - spec 沒定義未閉合反引號怎麼處理。
3. 輸入 C。未閉合圍欄:一行單獨的 ``` 後面沒有收尾,又沒規定未閉合的圍欄遮蔽到哪裡。
   - 若遮蔽到報告結尾,之後所有引句消失。
   - 只要前面已有一條真引句,`if not quotes and not n_markers: return None` 不會觸發,不會 fail loud。
4. 這是舊判準的標記計數(`n_markers` 防逃逸機制,r3 s2 席修過)在新規則下被重新打開。
   - 修法方向:只有「完整閉合的」反引號或圍欄才遮蔽。
   - 遮蔽的標記不能直接消失,至少要列成一個非致命的 row,或要求圍欄內的引句仍計入標記數。

## 2. 落單收尾引號判定只看同一行,換行就繞過
severity: major
blocking: 是
引句:「引句結束後,同一行剩下的文字裡若有落單的同型收尾引號(前面沒有對應的開引號):這條判格式不合——前綴照抄、後半編造的形狀就是這個。」
1. 輸入:
   ```
   引句:「合法前綴文字至少十個字」
   編造後半根本不在審材裡」
   ```
2. 第一條 span 在第一個 `」` 結束,第二行是「別的行」。規則 4 不處理,整段判錨定。
3. 讀報告的人會把兩行當成同一句引句的折行。spec 自己說跨行引句是合法寫法(約 90 條),折行在報告裡很常見。
4. 同型限定還有第二個繞法。輸入 `引句:「真前綴文字至少十個字」後半編造』`:
   - 收尾是 `』`,不是 `」`,規則 4 的「同型」不算它。
   - 其他引號,如 `"` 或 `”`,也是同樣道理。
5. 兩個繞法都讓只有前綴被驗,但視覺上是完整引句。S1 的測試只覆蓋同行同型。

## 3. 反引號、圍欄與括號深度計數的交互完全沒定義
severity: major
blocking: 是
引句:「從開引號起,同型引號遇開加一、遇閉減一,回到零的那個閉引號為止是整段引句;可以巢狀,另一型引號不計深度;跨行照舊可以(舊抽取器本來就跨行,這裡保留)。」
1. 輸入:引句本身要引的是這個 repo 的原始碼或文件,裡面含反引號或圍欄。這類審查在本 repo 很常見,例如審 `_quote_rows` 本身:
   ```
   引句:「正則 `[「『]` 開頭
   ```
   - 深度計數有沒有跳過行內程式碼?spec 沒說。
   - 若跳過,`「` 不計深度,但 `_quote_norm` 比對時會剝反引號、保留 `「`,抽出的字串與比對的字串不是同一份。
   - 若不跳過,`「` 計入深度 +1,真引句判「未閉合」。
2. 輸入:多行引句中途有一行以 ``` 開頭。
   - 圍欄遮蔽先於括號配對,內容被剝掉,整段引句 norm 後比不中快照。
   - 或圍欄吃掉閉引號,判未閉合。
   - 兩者都是把真引句判成不合。
3. spec 的「實務隱患」只提到引句內有落單 `「` 字元,沒碰到遮蔽與深度的先後順序。

## 4. 兩型引號交錯時 span 結束位置不明
severity: minor
blocking: 否
引句:「從開引號起,同型引號遇開加一、遇閉減一,回到零的那個閉引號為止是整段引句;可以巢狀,另一型引號不計深度;跨行照舊可以(舊抽取器本來就跨行,這裡保留)。」
1. 輸入 `引句:「甲『乙」丙』丁」`:
   - 外層 `「` 在第一個 `」` 歸零,span 是 `「甲『乙」`。
   - 剩餘 `丙』丁」` 含落單的同型 `」`,判格式不合。
2. 外層 `『』` 裡含不成對的 `「`(例如引程式碼字面)同理,按「另一型不計深度」會被截在第一個 `』`。
3. 快照原文若本來就有交錯引號(typo 或引用片段),真引句也被判不合。
4. 頻率低,與 spec 已接受的「3 條」同量級,但 spec 沒列這種形狀。

## 5. 與 `_quote_norm` 和 10 字下限的交互
severity: minor
blocking: 否
引句:「其餘照舊:正規化後整段要是凍結快照正規化後的子字串,未滿 10 字判錨不到。」
1. `_quote_norm` 剝 `*` 與 `` ` ``,並在每行開頭剝 `>`(`scripts/lumos:25757`)。括號配對與遮蔽發生在 norm 之前。
2. 輸入:引句夾大量強調記號或反引號,例如 `引句:「**短**」`。norm 後只剩 1 字,判太短。這個是保守的。
3. 反過來,整段變長之後 10 字下限的保護變弱。
   - 整段引句 norm 後 ≥10 字就算過。
   - 配合第 1 點的遮蔽,繞過下限的成本更低。
4. spec 沒有指出順序:遮蔽 → 配對 → norm → 下限。順序不同結果不同,實作者要自己猜。
