### F1 英文長句可藏進 [test:] 值,讓內容比對看不到
severity: minor
blocking: 否。只放寬「是否算寫說明」這一道,拿到的是少一道要求,不是能執行碼或外洩;而且「可繞過的守衛」在消費專案是不是真有人在意,我只能推論。
- 誰:不受信任的貢獻者,能改消費專案的 Systems 筆記(摘要或正文)。
- 從哪裡:PR 裡對任何 type: system 的筆記加行。
- 送什麼:`- [test: This module also owns X and must not be changed without Y]`。英文字母、空白、`.`、`,`、`()` 都在白名單字元內,長度不超過 200,所以 `_nodehome_test_tag_value_ok` 判為「像測試名」。整行拿掉標記後只剩清單符號,被 `_NODEHOME_BARE_ITEM_RE` 整行丟棄;同一行前面接一般句子時,標記前的空白被吃掉,句子留下來。一行 200 字,行數不限,可以整段英文說明。
- 拿到什麼:`sig` 兩邊相同,所以 `b["sig"] != n["sig"]` 為假,不進 `content_changed`。於是 [S12]「內容有變」以及掛在它後面的要求(每支檔有家、負責範圍等)被略過,隱藏的說明內容不被當成寫回。計劃寫「中文說明、跨行句子藏不進去」,但英文句子藏得進去,這個前提不成立。
- 限度:`foreign` 規則用 `n["text"]`(沒拿掉標記)算反引號路徑,所以藏路徑引用仍被抓到;標記裡的程式行號引用等 note-shape 規則照 `slot_parse` 也還會看到整行。繞過範圍限於「內容有變」這一道。
- 建議:值再收窄成識別名形狀(不含空白,或最多一兩個空白),或把 `[test:]` 值長度上限降到測試名合理長度(例如 80)。
