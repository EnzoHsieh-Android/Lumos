## 處置

- 同輪有 major(M1–M4),依代碼審規則不放行:21 條全部折入,0 條重現不到。
- 修補因果:R1、B1 是上一輪「讀表規則收成主程式一份」帶出來的(執行器分片多了對主程式的依賴),M4 是上一輪審計紀錄寫過頭,記為修補回歸;其餘是原有漏查。
- 依根因分組:
  1. 測試偵測力(M1、M2、M3、M5、M6、M7):換表四種各一組;沒表時逐份比對輪流分的內容;頂層也濾註解行;下限兩組輸入;布林;原子換名看 inode 換了。改壞實驗 17 種全翻紅。
  2. 主程式載入(R1、B1、H1):執行器把載入主程式包起來轉成同一種擋下,訊息帶路徑、不在錯誤處理裡再載一次;兩邊都說讀不懂。
  3. 刷新(P1、R2、B2、Q3、H3、H4、H2):獨佔鎖檔、刪檔數照實際、刪不掉的列名、斷掉的連結講一聲、紅的只收比舊值大的;分派比對子指令名;說明寫明 .lumos 位置與 run 檔較寬鬆的理由。
  4. 執行器寫檔(Q1、Q2):快取與 run 檔改用每次不同的暫存名;不分片時同名舊檔先合進來、記下紅的是哪幾支。
  5. 文件(M4、M8、M9):審計紀錄改字;印日誌先撈開始時間那行;架構文件與管 CI 的筆記補上耗時表與刷新。
