沒有可利用的洞。四類攻擊面逐一看過,每類都沒有找到能同時寫出「誰、從哪、送什麼、拿到什麼」的路徑。審查只讀 patch 與固定版本 `aea70018` 的 `scripts/lumos`,沒有在臨時 repo 實跑重現,所以下面的結論都是讀碼推得的。

## 逐類結論

**1. 不可信輸入流到危險操作:已看,無。**
- 耗時表能影響的只有「哪支測試分到哪一份」,不能讓測試不跑。
  - `_shard_by_duration` 對傳入的全部名字逐支丟進桶子,所以各份聯集等於全部,和表的內容無關。
  - 表裡沒有的名字用中位數,表裡多出來的名字被忽略。
  - 秒數用 `_duration_ok` 擋掉非有限數、負數、布林、字串與超大整數。
  - 秒數就算填成 1e308,最差也是桶子總權重變 inf,結果仍是完整分割,不會漏測試。
- `_read_durations_table` 把巢狀過深的 JSON 轉成 `ValueError`,斷掉的符號連結與資料夾也被擋下,執行器每一份都 rc2。
- 有人想讓各份讀到不同的表,跑完再讀一次的雜湊比對會 rc2。
- `_load_lumos_inproc()` 在這個 runner 裡不是新增權限。
  - 該函式原本就存在,載入的是同一個 repo 裡的 `scripts/lumos`。
  - 這個 PR 的改動本來就能改 runner 與測試,CI 本來就會執行它們。
  - 載入時不會觸發 `main()`,因為有 `__main__` 守衛。

**2. CI:已看,無。**
- `concurrency.group` 只用 `github.event_name`、`pull_request.number` 與 `github.sha`。這三個值都是 GitHub 產生的數字或十六進位,攻擊者沒法塞字元,也沒有用到分支名這類可由攻擊者控制的欄位。
- `cancel-in-progress` 只在 PR 事件為真。一個 PR 只能取消自己那一組,不能影響別人的 PR 或 main 的 run。
- 分片那一行的 shell 沒有注入面。
  - `$MY_SHARDS` 來自 workflow 靜態的 matrix。
  - `$i` 是該 matrix 的數字。
  - 兩者都不是 PR 內容。
- 離開碼不會被吞掉。
  - 子殼層先 `set +e`,再 `rc=$?`,結尾 `exit $rc`。
  - 外層 `wait "$job" || rc=1` 會收到。
  - 測試 `t_ci_yml_speed_shape` 真的用 `bash -e` 跑紅、綠兩種情況,驗證外層收到同一個離開碼。

**3. 執行邊界:已看,無實際利用路徑。**
- `refresh` 的 glob 固定是 `<root>/.lumos/test-durations-run*.json`,沒有萬用字元刪檔的範圍擴張。
  - 刪檔只對 glob 列出的 run 檔做 `p.unlink()`。
  - 遇到符號連結時,`unlink` 只刪連結本身,不會刪連結指向的檔。
- 讀符號連結指向的內容時,只有 JSON 裡的 `tests` 字典、而且是合法數字的值才會被收進表。
  - 這個內容只會影響分片權重,不能洩漏檔案內容,也寫不出別的東西。
  - 不合法的內容被略過。
- `_write_lf` 用唯一暫存名、`O_EXCL` 建檔,再 `os.replace`。
  - 它不跟著暫存位置的符號連結寫出去,測試也驗了舊的固定 `.lumos-tmp` 符號連結不被跟隨。
  - 如果耗時表本身是指向有效 JSON 的符號連結,`replace` 會把連結換成一般檔。這沒有寫到 repo 外面,所以算不上逃逸。
- ⚠ 推論:`governance/` 或 `.lumos/` 若本身是指向 repo 外的符號連結,`mkdir` 與 `_write_lf` 會寫到那邊。
  - 這需要攻擊者先能在使用者的工作樹放符號連結。
  - 能放符號連結的人已經能直接改任何檔,寫出的內容也只是耗時表 JSON。
  - 這沒有新增權限,我不標成 finding。
- 耗時表列進 `_BOOKKEEPING_FILES` 後,所有消費端都是精確路徑比對 `f in _BOOKKEEPING_FILES`,沒有前綴比對,所以不會變成夾帶其他檔的通道。
  - 代碼審留痕不失效與推送判成文件改動兩處,檔案本身都是資料。
  - 這個檔內容的唯一影響是分片的分配,不會引入可執行內容。
  - 把它換成符號連結,指向會讓 JSON 讀不懂的檔,執行器會 rc2 擋下,不會悄悄放行。
- `append-only JSONL` 自動併帳那條路徑(第 24708 行附近)要求 `.endswith(".jsonl")`。耗時表是 `.json`,不會被當成可併帳的檔。

**4. 繞過面:已看,無。**
- 分片與耗時表不能讓推送前閘或 CI 的測試少跑而看不出來。
  - 聯集完整性由分割演算法保證,和表內容無關。
  - 表在跑的期間換掉由結尾比對擋。
  - 表壞掉時每一份都擋,包含純文件推送的文件子集。
- 只改耗時表的推送被判成文件改動、CI 只跑文件子集,這是設計上的決定。因為表不影響測試跑哪些,只影響分到哪一份,我不把它當繞過。
- 有人在 repo 裡強制 add `.lumos/test-durations-run*.json`(該路徑被 `.gitignore` 擋)再讓維護者執行 `refresh`,效果也只是改變權重。
  - 壞值被略過,run 檔被刪除。
  - 最壞結果是分片不平均。
