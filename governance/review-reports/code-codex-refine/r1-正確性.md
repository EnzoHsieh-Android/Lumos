## Findings

### F1
severity: major
blocking: 是
`_stop_block_dir()` 只用 `mkdir(parents=True, exist_ok=True)` 建目錄,沒有處理「該路徑已被佔用成一個一般檔案」的情況——`exist_ok=True` 只在既有路徑「已經是目錄」時才吞掉例外,是檔案時 `mkdir` 仍會丟 `FileExistsError`,而整個函式外層用 `except OSError: pass` 全部吞掉、直接回傳那個(其實是檔案的)`Path`。後果:`codex_stop_decision()` 裡 `_stop_mark_path(session_id).exists()` 對「目錄底下的子路徑」恆回 `False`(因為父路徑不是目錄),於是**每一輪** Stop 都判定「還沒擋過」而回 block;`_stop_mark_write()` 想在一個「檔案」底下開子檔會拋 `NotADirectoryError`(仍是 `OSError`),被吞掉、標記永遠寫不進去——「只擋一次」的保證對整個 session、甚至整台機器上所有 Codex session(這是一個跟 session 無關的全域路徑 `~/.cache/lumos/stop-block`)徹底失效,變成擋停無限重複。已用實際 subprocess 重現:預先把 `~/.cache/lumos/stop-block` 建成一般檔案(模擬殘留檔/別的東西占位),同一個 `sess-collision` conn續打 3 次 Stop,3 次都印出 `decision: block`(預期只有第 1 次)。
引句:「d.mkdir(parents=True, exist_ok=True); os.chmod(d, 0o700)」
file: `scripts/hooks/claude/check-graph-sync.py:487`

### F2
severity: minor
blocking: 否
`_stop_mark_write()` 用 `os.open` 拿到裸 fd 後,`os.write` 與 `os.close` 寫在同一行用 `;` 串接,沒有 `try/finally` 或 context manager——若 `os.write` 拋例外(例如磁碟滿 `ENOSPC`),`os.close(fd)` 就不會執行,fd 洩漏,只被外層 `except OSError: return False` 接住例外本身,不會補關 fd。因為這是一個执行完就結束的 hook process,洩漏的 fd 會在 process 結束時被 OS 回收,實際傷害小,但程式碼本身確實沒有資源保證。
引句:「os.write(fd, str(time.time()).encode("utf-8")); os.close(fd)」
file: `scripts/hooks/claude/check-graph-sync.py:520`

### F3
severity: minor
blocking: 否
`_stop_mark_path` 用 `re.sub(r"[^A-Za-z0-9_.-]", "_", session_id)[:120]` 消毒 session_id,但允許集合裡包含 `.` 和 `-`,所以 session_id 恰好是 `"."` 或 `".."` 時完全不會被取代,組出來的路徑會是 `stop-block-dir/.` 或 `stop-block-dir/..`——分別等價於目錄本身與其父目錄,兩者一定都「存在」。結果 `codex_stop_decision()` 對這兩個 session_id 恆回 `False`(`not True`),Codex 側的擋停功能對它們靜默失效,退回 stderr 提醒(而程式碼自己的註解說「stderr 對 Codex 模型是零訊號」),等於這個 session 完全沒有續做提示。已重現(session_id="."/".." 各打 2 次,stdout 皆無 `decision`)。實務上 session_id 通常是 UUID,兩個字面值的機率極低,但邏輯上是個真的邊界洞,且審查詞面明確要求探這一項(`/` 與 `..`)。
引句:「return _stop_block_dir() / re.sub(r"[^A-Za-z0-9_.-]", "_", session_id)[:120]」
file: `scripts/hooks/claude/check-graph-sync.py:513`
