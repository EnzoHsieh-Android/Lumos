## 問一:分層與依賴方向

新碼有兩塊會碰到「這段邏輯該放哪一層」的問題。

**(A) check-graph-sync.py 的 stop-block 快取/session 標記邏輯——⚠ 鄰居本身就不一致,交編排者裁**
新增 `_stop_block_dir()`/`_stop_mark_path()`/`_stop_mark_write()` 把「快取目錄建立、TTL 清理、原子建檔」整套邏輯直接寫在 hook 檔裡,存放位置選了 `~/.cache/lumos/...`(跟 `scripts/lumos` 的 `_lens_armed_root()`——`~/.cache/lumos/dispatch-lens/armed/`——同一個根,`file: scripts/lumos:17265`)。但這條路本身在專案裡有兩個互相衝突的既有做法:
①`dispatch-lens-hook.py` 是薄殼,快取/TTL/原子認領全部委派 `lumos dispatch-lens --claim` subprocess,hook 檔完全不碰檔案系統(`file: scripts/hooks/claude/dispatch-lens-hook.py:46-78`,docstring 明講「其餘判斷……全在 lumos 端」);
②`impact-hook.py` 卻是相反做法,`_ttl_marker_path`/`_ttl_mark`/`_ttl_lazy_cleanup` 直接把 session 標記邏輯寫在 hook 檔裡、存 `tempfile.gettempdir()/lumos-impact-<session>/`,完全不委派 `lumos`(`file: scripts/hooks/claude/impact-hook.py:171-220`)。
新碼是兩者的混血:位置像①(`~/.cache/lumos/`)、放置層級像②(邏輯留在 hook)、原子建檔手法(`O_CREAT|O_EXCL`)則正確借用了 `scripts/lumos` 既有 idiom(`scripts/lumos:9394-9405`)。因為鄰居自己就分裂成兩派,判不出「唯一正確做法」,標 ⚠。
引句:「`d.mkdir(parents=True, exist_ok=True); os.chmod(d, 0o700)`」
file: `scripts/hooks/claude/check-graph-sync.py:487`
severity: minor  (⚠ 鄰居本身不一致,交編排者)

## 問二:命名與錯誤處理

新增常數 `STOP_BLOCK_HEAD`(公開,無底線)與 `_SHEBANG_INTERPS`(底線開頭)跟既有 `CODEX_TRANSCRIPT_VERSIONS`(公開、測試直接讀 `m.CODEX_TRANSCRIPT_VERSIONS`)與 `_CODEX_EXEC_CMD_RE`(底線、純內部正則)的「會被測試直接讀=不加底線,純內部細節=加底線」慣例一致,沒有問題。`main()` 裡新包的 `try: ... except Exception: pass`(`file: scripts/hooks/claude/check-graph-sync.py:635-643`)跟同一支檔案裡本來就有的 `_impact_missing` 的 `except Exception: return []`(`file: scripts/hooks/claude/check-graph-sync.py:471`,舊碼)是同一套 fail-open 慣例,也對得上家規「hook 失敗寧可漏報不擋」,不算不一致。

唯一的落差是 argv 旗標的解析方式。`--harness codex` 這個旗標本身是既有決定(`merge-claude-settings.py` 已經在組合這行命令列、圖譜 `lumos-cli-lifecycle.md` 也記了「命令列帶 --harness codex」),不是新發明;但這是全專案第一支真的去讀 `sys.argv` 的 hook(其餘 5 支鄰居 hook 全部零 argv、只吃 stdin JSON)。專案裡唯一一個「解析命令列旗標」的既有寫法在 `merge-claude-settings.py::_parse_target`——支援 `--target=值`與`--target 值`兩種寫法、值不合法就印訊息 `sys.exit(2)` 硬擋(理由寫在註解:「值拼錯或缺值→擋下……靜默退回 claude 會改錯檔」,`file: scripts/merge-claude-settings.py:17-30`)。新碼用手刻的 `sys.argv.index(...)` 掃描,任何拼錯/缺值都靜默退回 `"claude"`,沒有錯誤路徑。方向(fail-open)本身合家規,但「同一件事在專案裡曾經被判定要硬擋、這裡選擇靜默」是命名/錯誤處理層級的落差,不是引入新架構。
引句:「`"--harness" in sys.argv and sys.argv[sys.argv.index("--harness") + 1:][:1] == ["codex"]`」
file: `scripts/hooks/claude/check-graph-sync.py:547`
