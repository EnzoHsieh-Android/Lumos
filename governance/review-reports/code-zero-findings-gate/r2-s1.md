**1) `_qsrc = carrier if carrier is not None else latest[-1]`(scripts/lumos:10037)有沒有別的路徑用到而出錯**

追蹤 `vacuous` 的賦值:`vacuous = False`(10005)只在 `if carrier is None:` 區塊內被設成 `True`(10005-10021),外部再無其他寫入點。因此 `if carrier is not None or vacuous:`(10036)這個條件只有兩種互斥狀態:carrier 非 None(此時 vacuous 恆 False)、或 carrier 是 None 且 vacuous 恆 True。換句話說,**`carrier is None` 這一支只可能在 vacuous=True 時走到**,`latest[-1]` 沒有第三條路徑可以被踩到。

另外確認 `latest[-1]` 不會 IndexError:`vacuous=True` 的前提是 `if latest and all(_fz):`(10021),`latest` 非空是進入 vacuous 的必要條件,而 `latest` 本身在更早的 `groups`/`rid, latest = next(reversed(groups.items()))`(9958-9962)那一步已保證非空(每個 group 建立時至少塞一筆,見 9948、9955)。

`_qsrc` 算出的 `rp, sp` 只用在兩處:①`if not rp or not sp:` 的留痕前置閘、②quote-check 讀檔那行。vacuous 分支會直接印「引句無可驗,略過」跳過②(10072-10073),所以 `_qsrc` 在 vacuous 情境下唯一發揮作用的地方,就是①那個前置閘——而寫側 T6 定錨規則(3545 起)保證只要該 loop 已定錨(出現過 findings_set 的 carrier),之後每筆記錄都強制帶 report/snapshot;純 vacuous-only 的 loop 則從未定錨,`--report/--snapshot` 仍是選填,若 `latest[-1]` 剛好沒帶,①閘會正確擋下印「留痕缺席」FAIL——不是漏防,是設計內的 fail-closed。

**2) `if ok and vacuous and carrier is None:` / `elif ok:` 的分支覆蓋——carrier 非 None 時跟改前逐 byte 等價嗎**

改前(diff 的 `-` context)是單一 `if ok:` 區塊,裡面先印「留痕: ✓」,接著直接進 quote-check 的 try/except。改後拆成 `if ok: print(留痕✓)` 加上 `if ok and vacuous and carrier is None: … / elif ok: <原 quote-check 區塊逐字搬過來>`。
