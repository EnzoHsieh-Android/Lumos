# 代碼審前後端角色鏡頭_計劃

> 白話:代碼審派審查員時,看這次改到的是前端還是後端,在派工詞裡自動附上對應的一張「該往哪看」清單。前端看狀態競態、畫面、無障礙、前端資安;後端補現在沒涵蓋的幾題。只影響審查員看哪裡,不擋推送、作者不用多做事。

## 現況(2026-09-29 乾淨代理讀最新 main、首輪前掃逐句核對,以程式為準)

- **已經有、而且是程式判的**:.ts/.js 家族依「離檔案最近的 package.json」判:依賴裡有前端框架(整個套件名相等)標成前端那一類、沒有標成 Node、找不到回空;其他副檔名直接用副檔名當題組鍵。拿來選棧別檢核題組和慣例 skill;全端改動各檔各判、慣例 skill 取聯集。判定一帶見 [[Systems/pitfalls-code-loop]]。
  - 沒有「前端/後端」這個角色概念,只有題組鍵;.css、.html 現在完全不判。
  - 最近那份 package.json 就是答案:monorepo 子目錄放一份沒有依賴的空殼,底下的前端檔會被判成 Node。
- **半機械、靠派工的人照做的**:推送前分級會印出該用哪份慣例 skill,派工的人要自己抄進架構對齊席的派工詞;派工範本第 3 節審查鏡頭第 4 點「本案特定鏡頭」是空白欄。
- **完全沒有的**:
  - 依前後端換審查方向或席位編制。派工範本第 3 節正確性鏡頭的例子(連線、鎖、交易、扣款重試、寫一半、時區)全是後端味。
  - 前端的正確性方向:狀態競態、元件卸載後還在寫、畫面與伺服端渲染對不上。現有前端題只有 vue 五題,全談效能。
  - 無障礙、前端資安(XSS、CSRF、token 放哪)。乾淨代理用 a11y、XSS、CSP、CORS、v-html、dangerouslySetInnerHTML、SSR、hydrat 搜範本、skill、題庫,全部零命中。
  - React、Svelte、Angular 一律被歸成 vue(另案 [[Projects/前端框架從vue分出_計劃]])。
- **派工鏡頭那條通道**:派工詞有圖譜鏡頭那行時,掛鉤叫 lumos 算一段文字接在派工詞尾端,有時間預算與 20 分鐘快取;超時只附一行超時說明,算出來是空的就什麼都不附。Codex 編排時走另一條通道(派子代理那一刻領取),設計審走第三條。掛鉤檔受指紋保護。

## 要做什麼

1. **判定每支檔的角色**:前端/後端/判不出。依序:
   - (a) 專案宣告:`.lumos/config.json` 裡一份有序清單,每條是「路徑樣式 → 角色」(形狀借 Copilot 的 applyTo),第一條命中的算數;樣式比對沿用專案既有的路徑樣式比對寫法(開頭 `**/` 的處理跟既有排除清單一致)。
   - (b) 手機與 Android 畫面:看檔案本身的匯入——.kt/.java 匯入 android 或 androidx、.swift 匯入 SwiftUI 或 UIKit、.dart 匯入 flutter 套件 → 前端。不看改動行、不受改動行數門檻影響;刪掉的檔看改動前的版本。
   - (c) 副檔名:.vue/.svelte/.tsx/.jsx/.css/.scss/.html → 前端;.cs/.java/.py/.sql → 後端(.java 已先過 b)。
   - (d) .ts/.js 家族:照既有 package.json 判定,前端框架 → 前端、Node → 後端、找不到 → 判不出。
   - 都不中就判不出,判不出就不附,不猜。
2. **兩張角色鏡頭卡**,內容單源放在 lumos 本體(跟棧別題庫同處,消費專案拿得到);派工範本第 3 節審查鏡頭加第 5 點,只寫「角色鏡頭卡由派工時自動附上,對上卡片題的發現在標題附題號」並指到單源,不複製卡片內容。
   - 前端卡(網頁與手機畫面共用,只限網頁的題標「只限網頁」),每題有題號 fe-1…:非同步回來的順序與取消、元件卸載後還在更新、載入/錯誤/空資料三種狀態、伺服端渲染與瀏覽器首次畫面對不上(只限網頁)、無障礙(鍵盤走得到、標籤、對比)、前端資安(把使用者內容當 HTML 插入、token 放在 JS 讀得到的地方、跳轉網址沒驗;只限網頁)。每題照既有慣例「挑一個具體輸入走一遍」。
   - 後端卡,題號 be-1…:不重複第 1 點正確性鏡頭已有的。只補 API 對外相容(欄位改名、刪欄位、預設值改變)、每個端點的授權檢查、大量資料要分頁、外呼逾時。
3. **機械附上**:代碼審的兩條派工通道(Claude 派工詞有圖譜鏡頭那行、Codex 派子代理那一刻領取)都附;設計審那條不附。
   - 角色卡另走一次快速計算,只看改動檔清單、檔案匯入與 package.json,不跟圖譜那段共用預算與快取;圖譜那段超時或算出空白時,角色卡照附。
   - 全端改動兩張都附;全部判不出一張都不附。
4. **推送前分級多印一行**「前端 N 支、後端 M 支、判不出 K 支」:只印在給人看的輸出、不進 JSON、不是檢核題,不改變分級。
5. **守衛測試**:同 [[Projects/代碼審資料狀態鏡頭_計劃]] 的形狀,兩張卡任一題被刪或掏空就紅,並點名是哪一題。

## 已裁(2026-09-29 Enzo,決策 d1–d3)

- 只做派工詞的角色鏡頭,不補推送前的前端檢核題、不擋推送(d1)。第 4 點那行只是給人看的統計,不算檢核題。
- 手機畫面算前端:共用前端卡的狀態競態、載入錯誤空、無障礙三題;伺服端渲染與網頁資安那幾題標成只限網頁(d2)。
- React、Svelte、Angular 從 vue 分出來另開一案,本案不做(d3)。

## 已知限制

- 空殼 package.json 會讓底下的前端 .ts 判成後端;出路是在 `.lumos/config.json` 宣告路徑對照。
- 不匯入畫面框架的手機端檔(例如純資料層)判不出、不附卡;這是刻意的,寧可不附也不附錯。

## 驗收條款

- [S1] 當專案宣告清單裡有兩條樣式都命中同一支檔,角色判定應取清單裡第一條的角色,且宣告優先於匯入與副檔名判定 [test:t_review_role_declared_first_match_wins]
- [S2] 當沒有宣告,.vue/.svelte/.tsx/.jsx/.css/.scss/.html 應判前端、.cs/.py/.sql 應判後端、依賴含前端框架的 .ts 應判前端、有 package.json 沒前端框架的 .ts 應判後端、找不到 package.json 的 .ts 與 .md 應判「判不出」 [test:t_review_role_fallback_by_ext_and_package]
- [S3] 當 .kt 或 .java 檔匯入 android 或 androidx、.swift 檔匯入 SwiftUI 或 UIKit、.dart 檔匯入 flutter 套件,角色應判前端;同副檔名但沒這些匯入的 .kt/.swift/.dart 應判「判不出」、.java 應判後端;刪除的檔應看改動前的版本 [test:t_review_role_mobile_by_imports]
- [S4] 當代碼審派工詞有圖譜鏡頭那行、且改動含前端檔,派工附段應含前端卡全文與題號;同時含前後端檔應兩張都附;全部判不出應一張都不附 [test:t_dispatch_lens_attaches_role_cards]
- [S5] 當圖譜那段超時或算出空白,派工附段應仍含角色卡 [test:t_dispatch_lens_role_cards_survive_timeout]
- [S6] 當 Codex 編排的代碼審派子代理,領取的附加內容應含同樣的角色卡;設計審通道應不含 [test:t_role_cards_codex_claim_and_not_design]
- [S7] 若角色卡單源裡前端卡或後端卡任一題被刪掉或掏空,守衛應點名缺的是哪一題 [test:t_role_cards_guard_names_missing_item]
- [S8] 當跑推送前的風險分級,給人看的輸出應多一行列出前端、後端、判不出各幾支檔,JSON 輸出與分級結果應不變 [test:t_pitfalls_diff_prints_role_counts]
- [S9] 當實作完成、接線之前,編排者應從有前端的專案挑歷史上真的出過的前端缺陷,同一份改動派兩席、一席多給前端卡,把結果寫成驗證紀錄;沒有可用樣本就在驗證紀錄明講 [manual:兩席對照實驗,結果與樣本來源寫進 Verification 筆記]

- 已排除:金流:只改審查員派工詞與提示輸出,不碰任何付款流程;計劃裡的「扣款」是在描述現有鏡頭的例子
- 已排除:對外送出:不寄信、不打外部服務;「對外相容」指被審專案的 API,本案自己不對外送東西
- 已排除:不可逆:純文字、判定函式與測試,刪掉即回原狀,不動帳本
- 守衛面:★命中★——卡片守衛測試進全套,推送前檢查與 CI 紅了就擋;刻意的(防卡片被悄悄刪改),誤擋出路是改卡片的人同步改測試對照表。另外派工掛鉤檔受指紋保護,改它要重核可
