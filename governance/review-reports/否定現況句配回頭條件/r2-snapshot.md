# 否定現況句配回頭條件_計劃

白話:筆記寫「這裡還沒有門牌」,門牌掛上那天沒人會回來改這句。事後拿新門牌去找舊句找不到(寫的時候還沒有門牌號碼可寫),所以改在**寫的那一刻**提醒:提交時看到新寫的「還沒有/尚未/目前沒有…」這種會過期的現況句,就印一段提醒,教寫的人**把那句本身改寫成一行機器判得了的回頭條件**,例如 `REVISIT:[when-file:web/src/pages/x.tsx][by:2026-12-31] 前端頁面還沒做`。之後那件事真的發生、條件成立的那次推送,既有的漂移檢查會**擋下**(2026-09-30 起預設 block),寫的人把那行改成現況說明、或 `lumos drift ack` 寫理由照留,才推得出去——這正是要的效果:過期的句子不會安靜地留著。**提醒本身只提醒、不擋**;上線要先過〈上線門檻〉,量過之後達到〈做法〉7 的門檻才談擋。

## 做法

### 1. 哪些行算「否定現況句」(`_ns_negation_hits`)

規則等於量測程式的 `classify_v3` 加 `excluded_v3`(〈與參考實作的刻意差異〉只剩取新行的範圍)。輸入是 note-shape 提交前已經算出的「這次新寫的行」(`_note_shape_eval` 裡 `_notelines_new(..., keep_other=True)` 回的 rows)。進來先濾掉區塊不是 `body` 或 `summary` 的(`_notelines_regions` 的名稱)。只看可見的字:圍欄內不看(`_visible_lines`)、行內程式碼剝掉(`_strip_inline_markup`;剝完剩下的字照判,未閉合反引號之後截掉的不看)。一行在下面全部成立時算:

1. **不是這幾種行**:REVISIT 行本身(`_revisit_split` 回 `cond`、`date` 或 `bad` 的都不看——寫錯的歸既有「回頭條件格式不合/條件寫錯」規則)、去掉列表記號後以 `RETIRE-IF:` 開頭的行、工具自己寫的三種預告樣板(行裡有 `TEST:還沒有測試在守這條`、行裡有 `]預告這條合約但還沒做:`、去掉列表記號後以 `為什麼還不做:` 開頭)。
2. **先遮掉兩種字**(換成等長的佔位字元):行內欄位 `[<鍵>:…]`,鍵是 since、retire、until、confirmed、status、applies、test、audit、kill、rollback、guard、src、git、manual、by、來源、`when-` 開頭的任何鍵(量測程式 `FIELD_RX`);固定組合 未來、有沒有、未必、無論、無法、並無、沒問題、沒有問題、無誤、無關、無妨、毫無、無效、無窮、未知、未曾、未經、no-verify、no longer(`NOT_LACK`)。
3. **窄表字眼**出現至少一處。中文(子字串,`NARROW_ZH` 19 個):還沒、尚未、仍未、尚無、暫無、待補、目前沒有、現在沒有、目前無、目前還不、現在還不、未實作、未上線、未接、未做、未支援、未完成、未定義、未補。英文:`TODO`、`TBD`、`Todo`(分大小寫,`NARROW_V3_EN_CS`)、`not yet`、`yet to`(不分,`NARROW_V3_EN_CI`),前後不能緊接英數字、底線或連字號(`TODO-list`、`TODO_x` 不中);另認「`not`/`no`/`n't` 後面 40 字內、不跨 `.;,!?` 接 `yet`」(不分大小寫)。
4. **那一處是在用、不是在提**:不在同一行成對的「」『』“”"" 裡;而且不是修飾語——從否定字眼後面往後看最多 9 個字、遇到 `,,、。;;::()()「」『』“”"` 或空白就停,途中遇到「→」或「的時候」算修飾語;「的」只對不是講「有沒有」的字眼算(講「有沒有」的是 目前沒有、現在沒有、尚無、暫無、目前無,以及後面緊接「有」的「還沒」,`EXIST_TOKENS`);「時」「前」只在緊接行尾、斷句或虛詞(就、才、會、要、先、再、也、都、便、即)時算(「前端」「時間」不算)。
5. **那一處所在的一小段不是規則句,前面沒有歷史字眼**:一小段 = 用 `。;;!?!?,,、::()()`、`——`、`—`、後面接空白或行尾的英文句點切開後,否定字眼所在的那一段;引號裡的字先遮掉。那一段裡有規則字眼(不准、不要、禁止、不得、勿、一律不、不應;`RULE_MARK_V3`,不含「別」)就不算;那一段裡、否定字眼**前面**有歷史字眼(當時、原本、原先、曾、之前、以前、那時、起初、後來、已補、已修、修掉、改成、改為、已經有、現在有了、已上線、已做完;`HIST_MARK`)就不算。
6. 每一處各自判,**有一處留下整行就算**。

**這張表獨立**:不共用 `NEG_LEXICONS`(符號檢查用、專案可用 `neg_lexicon`/`neg_extra` 換)與舊句檢查的 `_DRIFT_M1_HIST_WORDS`(含「沒有」,會把「目前沒有」整批吃掉);不讀專案設定的字眼。正式工具的常數旁照 `_DRIFT_M1_HIST_WORDS` 的寫法註明「抄自量測程式,改字先改量測程式、重跑報告」,由 [S9] 機械比對兩邊一致。

**要配的與不用配的**(量測判準的白話版,也是提醒字樣背後的判斷):
- 要配:講「某個東西現在還沒有」而它之後會出現——功能未做(「getMetrics 尚未實作,是下一個增量」)、測試還沒綁(「第二批,還沒綁測試」)、檔或節點還沒有(「派工範本目前沒有 Systems 節點管」)、流程步驟還沒做(「設計還沒做」「還沒量」)。
- 不用配:歷史句(「當時還沒有模型段」)、規則句(「不准還沒審就推」)、狀態或結果描述(「沒有問題」「本次盤點沒有推翻該結論」,大多不在窄表)、程式行為描述(「還沒提交的帳本檔會列成一行」)、在提這個字眼本身(「「目前沒有/還沒」這種句型」)。程式與資料狀態的描述(「資料庫還沒升級→結束代碼 3」)窄表仍會誤觸,留出樣本 30 行裡 14 行是這種,所以只提醒。

### 2. 什麼算「已配」

**只認那一行本身就是條件式回頭條件行**——而 REVISIT 行在〈做法〉1 第 1 點本來就不看,所以「已配」不用另外判:把否定句改寫成條件式回頭條件行,它就不再被提醒。不看鄰行:
- 設計審前的「前後 3 行內有一行條件式就算配了」拿掉:一條條件式會同時蓋掉附近好幾句、綁的不是那一句也算(邊界席、外家否決席);圍欄裡的範例也會被當成已配(架構對齊席)。
- 旁邊只有日期式回頭條件的否定句照樣提醒(已知漂移的三處就是這個形狀)。
- 同一行中間夾著 `REVISIT:`(不在行首)照樣提醒:那種寫法漂移檢查不會判。
- 改寫成回頭條件行也順帶避開筆記內容審:內容審跳過條件式回頭條件行(只限 `body`/`summary`,跟本計劃一致),否定句留在正文照送審、「there is no X」會被判成推得出(設計審回滾席)。

### 3. 掛在 note-shape 哪裡、怎麼印

- `_note_shape_eval` 加一個關鍵字參數 `hints=None`。傳進一個字典 `{"items": [], "error": None}` 時,逐篇處理新行那一段多呼叫一次 `_ns_negation_hints(p, text, rows)`,把每一筆 `(路徑, 行號, 原文, 形狀)`(形狀是 `table`/`heading`/`prose`)加進 `items`;回傳值照舊是 `(violations, errors)` 兩個,**提醒不進 violations**。這一次呼叫包在 try 裡:丟任何例外就清空 `items`、把例外類別名記進 `error`、這一次提交不再算提醒。只有 `cmd_note_shape` 在 `--staged` 時傳;`--diff` 與 `_note_shape_doctor_lines` 的事後掃描兩個呼叫端不改、不傳。(`gov_events` 也是這種「傳進來的容器當出參」的先例。)
- `cmd_note_shape`:早退改成「沒有違規、沒有錯、提醒 `items` 空、`error` 也空才回 0」。只有提醒時印完直接回 0,**不走到寫治理帳那一段**;有違規時先印違規段、再印提醒段(block 的回 1 在兩段都印完之後),治理帳那一筆的違規條數照舊是 `len(viol) + len(errs)`。讀 `note_shape.negation`、組字樣、印出這三步也包在同一個 try 裡;任何一步出錯就不印提醒、只印「提醒:否定現況句提醒這次沒跑完(<例外類別>),不影響這道檢查的判定」,rc 照既有判定——提醒失敗不能讓閘失敗(掛鉤對 rc 1 會擋提交,設計審併發席)。
- 為什麼不做成 violations 帶一個嚴重度:violations 會被 block/warn、治理帳條數、doctor 事後掃描三處消費,加嚴重度要動三處;提醒的語意是「永遠不算、不記」,另一個出口最小。
- 字樣(stderr,三段式:發生什麼→為什麼在意→怎麼改;標頭格式照 `drift_check.old_sentence` 的「提醒:…(開關=warn,不擋)」):

```

  Systems/任務流程領域模型.md:34  - 只有分析行程這一側的狀態機;執行行程那一側的操作狀態、事件與…

  條件怎麼選:跟那件東西直接綁的優先——它會在的檔 [when-file:路徑]、它的函式或類別 [when-symbol:路徑::名稱]、守它的測試 [when-test:測試名];講的是一個流程或一份計劃,用 [when-status:計劃節點=done];量測、外部、人工進度這種觀測類只能寫日期 REVISIT:YYYY-MM-DD …

程式碼查得到的現況就刪掉這句;講的是當時就寫成歷史說法;只是在提這些字眼,用引號或行內程式碼包起來。關掉這個提醒:.lumos/config.json 的 note_shape.negation 設成 off
```

  每一筆印「路徑:行號  原文」,原文是原行去頭尾空白後的前 60 個字;形狀是表格或標題時句尾加「(表格)」「(標題)」;按路徑、行號排序,最多列 10 行,其餘印「其餘 N 行沒列」。

- 觸及範圍:提交前掛鉤在 repo 裡有 `scripts/lumos` 時呼叫 note-shape(找不到 Python 3.14 時既有的 Gate PY 會先擋提交);`--no-verify`、沒裝掛鉤的提交、在別處改筆記的提交看不到提醒。在 agent 對話裡提交時,提醒在 `git commit` 的 stderr,agent 有沒有讀到看它怎麼處理輸出。

### 4. 開關與 doctor

- `.lumos/config.json` 的 `note_shape.negation`:只認小寫 `warn`(預設,印提醒)與 `off`。讀法另寫一支 `_note_shape_negation_config(text)` → `(mode, warnings)`,輸入跟 `_note_shape_config` 同一份(被檢查的版本,提交前是提交索引);不擴充 `_note_shape_config`,因為它有兩個以兩個值解包的呼叫端。沒寫或寫 `null` → warn,不印;寫了別的值(`block`、`false`、`"OFF"`…)→ warn 並印「提醒:note_shape.negation=<值> 看不懂(只認小寫 warn/off),照 warn」;設定檔讀不了或 `note_shape` 不是物件 → warn 並印「提醒:否定現況句提醒照預設 warn」(照 `_drift_old_sentence_config` 的先例另講一句——gate 那句講「照預設擋」,不另講會讓人以為提醒也擋)。這些提醒只在這次提交有要判的新筆記行時印,不是每次提交都印。擋的設計要等〈做法〉7 的門檻,所以不收 `block`。
- `note_shape.gate=off` 時整道 note-shape 不跑,提醒一起不印(照現況)。
- doctor:在 `_note_shape_doctor_lines` 裡用它已經安全讀到的同一份設定文字,放在「開關不是 block」那一行之後、`if ci: return out` 之前(推送前與 CI 路徑也看得到,照 old_sentence 那行每次都唸);`note_shape.negation` 是 off 時印「這個專案把否定現況句提醒關掉了(note_shape.negation=off)」,值看不懂時印同一句看不懂;warn 或沒寫不印。
- 沒有表態:提醒不擋,看完不改就好。

### 6. 跟其他檢查的分工

- **漂移檢查(推送前、CI)**:條件式寫下去之後的判定全是既有的 `drift check`。它對候選行「終點成立、起點沒有同一條或還不成立」判要處理,**新寫一條終點就已成立的條件式也算要處理**;2026-09-30 起沒寫設定的專案預設 block,要處理就擋推送。這一類(條件式回頭條件成立)沒有工具改法:把事做掉之後刪掉那一行或改寫成現況說明、歷史說法;還不能做就 `lumos drift ack` 寫理由照留。這是本計劃要的效果——那件事發生那次推送,過期的句子一定有人看;代價是寫條件時要確定那件事還沒發生,否則當次推送就被擋(提醒字樣第四行)。注意「還沒發生」是對**推送**而言:先寫筆記、同一次推送裡後面的提交才把東西做出來,推送時條件已成立,照樣擋。`drift scan` 列全部已成立的,不擋。
- **筆記內容審(推送前判定者)**:它判「這句是不是程式碼推得出」,「there is no X」這種會判成推得出、要刪。把否定句本身改寫成條件式回頭條件行之後,那一行被內容審跳過([[Projects/存量漂移防線_計劃]]〈做法〉第 2 節第 5 點);所以提醒教的改法不會跟內容審打架。純程式現況(讀者只看 repo 就能確認)照內容審刪掉。
- **`guard settle` 與漂移甲 c1**:工具自己寫的預告樣板由它們管,所以〈做法〉1 第 1 點排除。
- **doctor E5**:`[by:]` 到期照舊由 E5 唸。

### 7. 升級成擋的門檻(量了才談)

**口徑**:「上線提交」= 最近一次讓 `scripts/lumos` 裡的 `_ns_negation_hints` 從沒有定義變成有定義的提交(`git log -S _ns_negation_hints --format=%H -- scripts/lumos` 列出的提交裡最新、且該提交之後定義存在的那一個;回退後重上會重設起點)。「上線後的提交」= 上線提交之後、主線上改到圖譜的非合併提交。「重放」= 量測程式 `scan --renames`(用 `-M` 取新行,跟 note-shape 提交前一致)對上線後的提交跑、取 `funnel_v3` 的會提醒列。提醒不留紀錄,重放看不出寫的人有沒有真的看到提醒(`--no-verify`、沒裝掛鉤都看不出),所以第 3 條量的是「被提醒的句子後來有沒有處理」,不是「因為提醒才處理」——歸因不了,照實承認。

上線第 8 週量四條,**全部**成立、而且每一條都達到最小樣本,才把「擋」拿去給 Enzo 裁(擋要另外設計表態);任一條樣本不足就判「樣本不足、不升級」:

1. **準度 ≥ 70%**。資料來源:重放的會提醒列。抽法:隨機抽 30 行,照報告第 5 節判真假。最小樣本:會提醒列 ≥ 30 行(不到就判樣本不足)。
2. **噪音:有提醒的提交 ≤ 改到圖譜的提交的 35%,每個有提醒的提交中位數 ≤ 1 行**。資料來源:重放,全數計算(不抽樣)。分母:上線後改到圖譜的非合併提交,≥ 30 個(不到就判樣本不足)。現況:工具鏈 36%、rtb 32%,中位 1。
3. **照做率 ≥ 50%**(人工抽樣)。抽法:第 1 條那 30 行裡判成真的每一行,用原文到主線頂端的那一篇找:那句被改寫成條件式回頭條件行、被刪掉、或改寫成歷史或現況說法,算「處理了」;原文照留算沒處理;那一篇被刪或改名找不到,不計入分母。最小樣本:判成真的行 ≥ 10(不到就判樣本不足)。
4. **綁錯事件 < 10%**(人工抽樣)。抽法:上線後新寫的條件式回頭條件行(重放時新增行裡 `_revisit_split` 回 `cond` 的行),到量測那天用 `lumos drift scan --at <主線頂端>` 列出條件已成立的,逐條人工判「條件成立時,那件事是不是真的發生了」;不是的算綁錯。另外看它有沒有表態理由(`governance/drift-acks.jsonl` 用路徑加原文對),理由只當參考——表態檔沒有「綁錯」欄,也沒有「這條是不是提醒引來的」欄。最小樣本:已成立的條件 ≥ 10(不到就判樣本不足)。

### 8. 條件綁錯事件怎麼降(rtb 回報第 6 條)

- 提醒字樣明講條件怎麼選:它會在的檔(`when-file`,判的是檔在不在樹上)、它的函式名(`when-symbol`,判的是**有沒有定義**——函式、類別或模組層指定,不是名字有沒有出現)、守它的測試(`when-test`);講的是一個流程或一份計劃時,綁 symbol 常會永遠不成立或誤成立,用 `when-status`(那篇計劃收尾);量測、外部、人工進度只能寫日期。量測裡真句 2/3 可以綁東西本身。
- 寫之前確定那件事還沒發生(提醒字樣第四行,附 `lumos drift scan` 當場看);寫下去就成立的條件當次推送會被擋,等於當場提醒「已經發生了,改句子」。
- `[by:]` 必帶(既有規則),名字猜錯、條件永遠不成立時,期限到了 doctor 會唸。
- 事件綁錯是語意問題,工具判不了;〈做法〉7 第 4 條與 RETIRE-IF ③ 用人工抽樣事後判。

## 與參考實作的刻意差異

參考實作是量測程式的第三版(`classify_v3`、`excluded_v3`、`funnel_v3`),正式工具的判定照搬,常數由 [S9] 比對。只差取新行的範圍:正式工具在提交前看那一次提交的新行(`--staged` 走 `git diff --cached -M`,不截上線點);量測程式逐提交對上一版看,預設 `--no-renames`,加 `--renames` 時用 `-M`。兩種取法在工具鏈 300 與 rtb 182 上會提醒的數字相同(128、102),上線後重放一律用 `--renames`。
