# 評測尺修復（2026-09-14 立案）

> 白話：我們有一把尺在量檢索好不好，但那把尺現在**四分之一以上的刻度是空白的**（沒標過的候選一律當「不相關」算 0 分）。更糟的是，**它量不到我們接下來要修的那個問題**——題庫裡根本沒有那種題目。在修好它之前，任何檢索改動做完都證明不了做對，而且很可能被誤判成做壞。

上游是 [[Projects/檢索核心重建_計劃]] 的設計審。那個案子排隊等本案。

## 三個已量到的硬數字

| 量的東西 | 現況 | 為什麼要緊 |
|---|---|---|
| 未標候選 | **226／793（28.5%）** | 未標一律計 0 分。等於現在每次評測都有超過四分之一的候選被預設判成不相關。★這個數字每天在動★（立案當下量到 222／790，隔幾小時重跑就變 226／793，因為當天新建的筆記已進候選池但還沒標——連本篇計劃自己都在未標清單裡）。[S1] 要在動工當下用固定提交重量一次 |
| 搜尋題庫裡帶空白的題 | **3／34** | 而且實測這三題在現況下就撈得到候選。**「多詞查詢撈不到」這個要修的問題，題庫覆蓋率是零** |
| 標註快照距今 | **766 個提交**（停在 2026-08-24） | 這段期間圖譜長大、程式也改過，浮上來的新節點全都沒標過 |

## 這把尺已經誤導過一次真實決策

評測器自己的說明白紙黑字記著：**改善檢索 → 浮出新節點 → 新節點沒標過 → 全部計 0 → 改動被罰**。

2026-08-22 的實例：一個小改動讓未標節點多出來、全計 0，**足以解釋整個 -5.4% 的「退步」，而那個數字當時被讀成「改動有害」並據此撤回**。

> ★數字口徑不一致（前掃抓到，是這個 repo 自己沒調和過的舊帳）★：評測器的說明寫「未標從 4 個變 9 個、多出的 5 個」，但圖譜裡的計劃節點與驗證紀錄都寫「從 0 變 4 個、4 個強制零分」。兩種說法在同一個提交裡就已經並存。**這裡不替任何一邊裁**，只記下它不一致；要用這個事故當論據的人，先去釐清。

原句還有一句特別值得記：「該計劃當初設計的觸發情境是**語料前進**，沒想到 **code 改動**也會讓候選浮出。」——而接下來要做的檢索改動，整個目的就是讓大量以前撈不到的東西浮上來。

## 條款

- **[S1] 量現況並釘住。** 未標數與比率、題型分布、距上次重釘幾個提交，三個數字用固定提交量一次寫回本篇。**這是之後判「修好了沒」的唯一對照組。** [manual:跑未標掃描與題型統計，三個數字寫回本節點]

- **[S2] 補題：把要修的那類查詢納入題庫。** 至少三類目前零覆蓋或極少覆蓋的：**多詞（帶空白）、單字中文、以及現況會 0 候選的組合**。★題目不准憑空編★——來源要有判準（例如從真實使用情境、從既有節點標題與別名組合、從已知失效案例取），判準寫進本篇。 [manual:新題目與其來源判準寫回本節點，並說明為什麼這些題能代表要修的問題]

- **[S3] 標註走既有雙評審流程，不新造。** 用既有的合併子命令：一致的進共識、不一致的標成爭議交人裁；只有既有的寫入子命令能寫進題庫（唯一寫入口）。 [manual:雙評審輸出與人裁結果留檔，路徑寫回本節點]

- **[S4] 補標到未標歸零，然後重釘快照。** 既有的重釘子命令本來就硬擋「未標不為零不准重釘」，照它走。 [manual:重釘成功的輸出留檔，新的快照提交寫回本節點]

- **[S5] 驗這把尺本身量得準——用已知答案的改動當校準。** ★這是本案最容易被跳過、但最不能省的一步★：補完標之後，拿一個**已知效果、而且現在還切得動**的旋鈕跑一次消融，看新尺量出來的方向跟當初留的數字一致。★要點名用還活著的那幾個★（家的入口、救回筆數、查詢長度門檻這三個旋鈕現在都還在程式裡可切，當初也都留了前後數字）；**不要挑已經被消融殺除、程式碼都拿掉的那個權威度旋鈕**——那個留了數字但重跑不出來。量不出當初那個方向，就代表尺還是壞的，不能拿去驗下游。 [manual:選一個既有消融當校準題，新舊尺結果對照寫回本節點]

- **[S6] 確認「弱證據不算過」這個行為真的生效（不是新造一道閘）。** [manual:切換發生後跑一次評測，確認弱證據旗標真的會讓閘不轉綠] ★前掃更正★：原本寫成「要新接一道閘」是誤解——那個機制早就寫好、而且有單元測試（實測斷言弱證據時閘回 False），缺的只是觸發；而觸發條件就是 [S4]。本條要做的是**驗它真的生效**，因為紀錄檔裡至今沒有任何一筆帶切換標記，代表切換從沒發生過、那條路從沒在真實評測裡跑起來。

- **[S7] 本案不新增計分邏輯，但要正面承認做完會觸發既有的尺切換。** [manual:S4 跑完後確認尺切換是否發生、恆等斷言有沒有過，結果寫回本節點] ★這條原本寫成「不改尺」，是錯的★：那個裁定 2026-08-26 已被翻案（[[Projects/評測尺翻案_計劃]]），新尺早就實作好了，切換條件寫死在程式裡——**評測母體未標歸零且新舊尺恆等斷言通過，該輪起就自動切成新尺並永久記進紀錄（切了不回頭）**。本案的 [S4] 正是那個觸發條件。所以正確的說法是：本案不寫任何新的計分公式，但**它會讓已經寫好的那把尺上線**。翻案設計保證恆等切換零重錨、既有門檻數字不用動——這點要在 [S4] 跑完後實際驗過，不能只信文件。

## 邊界與不做

- **不新增計分公式。** 本案不寫任何新的評分邏輯；已經寫好的那把新尺會不會上線，由未標歸零這個條件決定，不由本案決定。見 [S7]。
- **不擴充編輯面題庫**（目前 23 題）——本案的觸發問題在搜尋面，編輯面等有需要再說。
- **不在本案做任何檢索行為改動。** 這是純粹的量測工具修復；下游的索引與召回改動在 [[Projects/檢索核心重建_計劃]]。
- **不自動化標註。** 標註品質是這把尺的天花板，[S3] 的雙評審加人裁那一關省不掉。

## 實務隱患

- **標註工作量** — 222 個未標要人看。這是本案最大的成本，也是它一直沒被做的原因。處置：[S2] 補題會再增加一些，但既有的雙評審工具能把一致的部分自動收斂、只把爭議的交給人。要先量出「需要人裁的實際有幾筆」再開工。
- **標註者偏見** — 同一個人（或同一個模型）標題目又標答案，等於自己考自己。既有的雙評審設計就是為了這個；★不一致的那些才是真正有資訊量的，不能為了省事全部從眾★。
- **補完之後又會長出新的未標** — 圖譜每天在長。這不是一次性工作，是要接進週期性檢查的。既有的週閘接線子命令就是為此存在。
- **不可逆與回滾** — 題庫是版控檔，寫入走既有唯一寫入口（原子寫入），退回就是版本還原。沒有外部系統。
- **併發** — 標註是單人單次的工作，沒有併發寫入者。
- **效能／資源／認證／限流／個資／金流／對外寄送** — 無。純本機檔案作業。

## 風險與回頭條件

- **★補完標不等於尺就準了★** — 只代表「沒有候選被預設當 0」。尺準不準要靠 [S5] 那道校準才算數；[S5] 沒過就不能宣稱修好。
- **這把尺的天花板是標註品質**，而標註是人（或模型）判斷。本案不解決這個天花板，只把「連判都沒判過」這個更低階的問題清掉。
