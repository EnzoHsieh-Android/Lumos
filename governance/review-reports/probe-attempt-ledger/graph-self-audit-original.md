## 白話還原

這個機制不是「供應商帳單」，比較像放在本機門口的打卡簿：模型每次準備啟動，先在同一本 SQLite 帳裡占一格；只要格子成功寫入，即使之後逾時、取消、解析失敗或程序死亡，也不退還。這樣歸檔結果、跨午夜或換輸出目錄，就不會把已消耗的名額洗回零。

### 為何採 SQLite

選 SQLite 有三個理由：

- Python 標準庫已有 `sqlite3`，符合零第三方依賴。
- `BEGIN IMMEDIATE` 能讓多個合作程序在同一交易內「核對剩餘額度＋寫入啟動意圖」，不用自造多檔鎖或結算協定。
- 帳獨立於結果檔，結果被歸檔、失敗或換日期目錄都不會消失。

依據：`Projects/探針持久用量帳_計劃.md:21-23,28-30`、`Systems/ablation-lumos-first.md:63,79,83-85`、`Systems/codex-harness.md:122-124`。

### 限制域

硬額度只涵蓋：

- 同一使用者、同一機器、同一 SQLite 絕對路徑。
- 明確以 `max-per-window > 0` 啟用並走該帳的探針。
- 帳裡登記的是 `launch-intent`，不是成功模型結果，也不是可核帳的付費呼叫。

不涵蓋：

- 不同帳路徑、其他使用者或其他機器。
- `--max-per-window 0` 的直跑模式。
- 舊版、未受管探針、其他模型工具。
- 供應商帳號的整體用量或跨機全域配額。

因此它只能宣稱「同一本機帳路徑內，合作程序不超額啟動」，不能宣稱帳號級五小時上限。依據：計劃 `:21,28-35`；驗證 `:5-6,18,30-35`。

### 啟用前提

首次真模型部署或遺失帳後重建，必須先由人工確認：

1. 舊版及未受管探針都已停派。
2. 沒有在途工作。
3. 新帳建立後再經五小時冷卻。

程式本身不能阻止舊版或改用另一帳路徑繼續啟動。這個前提尚未在真模型窗口完成驗證。依據：計劃 `:31`；驗證 `:6,35`。

### 出錯與恢復方式

- 壞帳、schema/version 不符、非一般檔、不可讀寫、鎖逾時或時鐘回撥：模型前 fatal，批次 `inconclusive`、`rc3`，停止後題及重試。
- 額度已滿：不插入新意圖、不啟動模型；父程序保留事故、候選與 pending 證據。
- 歸檔前須確認沒有在途探針，只處理實際存在的事故路徑，不捏造缺少的候選檔。
- 遺失帳不能從結果檔估算復原；只能按首次切換規則重建並冷卻。
- 若要整體撤回硬額度，先停真模型派工、保留帳與事故，再由使用者裁決並同步修改父計劃 S18 與 CLI 承諾；不能靜默退回結果檔推算。

依據：計劃 `:23,31,33-35,54-58`。

### 真正驗了什麼

驗證用的是 Python 3.14、暫存 SQLite 和外部邊界的假模型，沒有真模型付費呼叫：

- 壞帳能在父派工抵達模型前停止。
- 兩個獨立程序競爭最後一格，只有一方成功。
- 失敗結果歸檔及跨日後，用量仍存在。
- 缺題目前置條件不花額度。
- 零模式不建立或讀寫帳。
- 新帳冷啟動與小數 epoch 窗口。
- 已滿帳的真 CLI 合約為 `rc3/fatal/inconclusive`、零有效場、零工具呼叫。
- 供應商 limit 撞上本批最後名額時，只啟動一次且不 sleep。
- 後補了 SQLite 鎖逾時、登記意圖程序遭殺，以及兩個真正父程序競爭的控制。
- 也驗了備註檔不應被健康掃描誤認為正式結果。
- 最後留存的測試紀錄為消融 `32 tests OK`、探針邊界 `138 passed / 0 failed`；此前漏匯入造成的失敗紀錄沒有被覆蓋。

重要證據界線：最初三項控制只有壞帳父派工一項能稱為舊版翻紅；另兩項是在 helper 已加入後才跑，不能倒稱為先紅後綠。依據：驗證 `:18-28,37-47`。

### 還待完成

- 完整的「父程序死亡、子程序仍活著」組合沒有驗；現有控制只是殺掉登記意圖的程序。
- 首次真模型窗口尚未執行。
- 尚未驗證真模型下的保守誤擋、實際維護成本及吞吐影響。
- 不代表供應商配額、帳號總用量或跨機共享。
- 這不是正式第四輪代碼審通過紀錄，不能替代 code-loop cap 裁決。

依據：驗證 `:30-35,39`。

### 何時重驗或撤除

重驗：

- 修改 SQLite 交易、派工、重試或結果落地流程時。
- 首次真模型切換前，先確認舊探針已停止且無在途工作。
- 下一個真模型窗口觀察保守誤擋。
- 計劃另接了 `2026-11-08` 的檔案事件／期限回訪。

撤除：

- 下一個完整真模型窗口若顯示保守誤擋，或維護成本高於省下的呼叫成本，由使用者裁決撤回；先更新父計劃 S18 與 CLI 承諾，再移除硬額度。
