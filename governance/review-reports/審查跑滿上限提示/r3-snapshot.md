# 審查跑滿上限提示_計劃

PRIOR-ART: 停不停看「再修一輪預期換到多少」而不是輪數(Wu 等,arXiv 2607.17641v1,舊編號 r1 整合席上網核實過);卡住時拆小改動或往上找人裁(Google eng-practices);累計量過大就退回給人(Claude Code auto 模式的拒絕熔斷器,出處為第三方原始碼分析 openedclaude/claude-reviews-claude 第 07 章,沒有對照原始碼核實)。機制層沿用:每輪漏斗的共用函式 `_review_yield_round`(直接呼叫,不靠處置閘印出的那段——那段對 code 迴圈是跳過的)、處置閘判空輪的同一個欄位(各席的 `findings`)、定錨分級 `_loop_anchor_tier` 與分級上限表 `_TIER_PARAMS`、舊閘退役判定 `_panel_retired_for`、處置閘既有「唯讀時不做附帶動作」的慣例;不寫任何帳。
RETIRE-IF: ①上線後 8 週內,印了提示之後編排者照樣再開的輪,折入數仍沒下降的次數多過有下降(提示沒改變行為);②三個月內零次印出(沒人跑過上限)。

## 一句話

多席迴圈的輪數一到分級上限,`loop next` 與處置閘就在輸出末尾印每輪折了幾條、每輪最高嚴重度,加一句依固定規則給人的提示;累計折入超過 20 條不等到上限就先印。**只印,不改任何判定、階段與退出碼,也不寫任何帳。**

## 適用範圍

- 只印給「2026-08-26(含)之後開的多席迴圈」(判法直接呼叫 `_panel_retired_for`)。
- **不印**:light 分級、代碼審循序單審(沒有輪次記帳)、2026-08-26 以前的舊迴圈。
- **不動**:loop next 的判定路徑、階段名、退出碼一律照舊。帶 `--spec` 對新迴圈會被已退役舊閘擋下(退出碼 2)這個既有缺口不在本案,另記 Issue(見〈不在本案〉)。

## 做法

### 一、什麼時候印

- **到上限**:帳上已記的輪數 ≥ 分級上限(`_TIER_PARAMS[分級]` 的上限,分級取 `_loop_anchor_tier`;loop next 與處置閘都查這一張表,不另寫)。
- **熔斷**:各輪折入累計超過 20 條,不論輪數。
- loop next:只要它正常印出了結果(任何階段),就在末尾加這一段;它被擋下提早結束的路徑不印。處置閘:判定印完之後加這一段,不論過或沒過;回放與凍結(唯讀呼叫)不印——新段落自己包一層唯讀判斷,不假設外面已經包好。

### 二、印什麼

1. **閘**:這個迴圈最後一輪過了沒(處置閘自己印的時候就用它剛判的結果;loop next 印的時候只寫「要知道過了沒,帶 --spec 問處置閘」加補好的指令,不自己判)。
2. **每輪折入數**:對每一輪的帳列直接呼叫 `_review_yield_round`,取「折」欄。那一輪沒有彙總帳時:各席帳的 `findings` 全是 0 → 算折 0(處置閘判空輪也看這個欄位);否則印「這輪沒記處置」。
3. **每輪最高嚴重度**:那一輪各席帳的 severity 取最高。
4. **提示**(依序套,第一個成立的就是):
   - 有任何一輪「沒記處置」、或只有一輪 → 「判不了,自己看」。
   - 最後一輪折入數 ≥ 前一輪 → **換做法**:拆小改動、回頭改設計、或整類拿掉。
   - 最後一輪最高嚴重度 ≤ minor → **可以停**(已過閘就收;還沒過就看閘沒過的原因,代碼審照舊只准放行 minor)。
   - 其他(在降、但還有 major 以上) → **有進展,但已到上限:要不要破例再一輪,由人裁**。
5. **熔斷**:累計折入(只加記了處置的輪;有幾輪沒記處置就註明「另有 N 輪沒記處置,沒算進來」)超過 20 → 「累計折入已經 N 條,建議拆小改動」。熔斷跟第 4 點各自獨立,兩者都成立兩段都印。
- 規則只看「最後一輪對前一輪」,不用「第一輪的一半」這種門檻。

### 三、輸出格式

- 文字:一個固定標題的段落,每輪一行(輪次、折入數、最高嚴重度),然後閘一行、提示一行、熔斷一行(有才印)。loop next 的文字輸出是逐欄挑著印的,這段要明確加進去。
- `--json`(loop next 才有):多一個 `cap_hint` 物件——`rounds`(每輪 `{round, folded, max_severity, recorded}`,`recorded` 是這輪有沒有記處置,空輪算有記)、`hint`(提示代碼:`unknown`/`reshape`/`can-stop`/`human-decides`)、`breaker`(累計折入與沒算進來的輪數,沒觸發為 null)。欄位名刻意不用 `advice`,避免跟既有的 `advisory` 讀混。

## 條款

- [S1] 當 2026-08-26(含)之後開的多席迴圈帳上輪數已達分級上限,`loop next` 正常印出結果時應在末尾加上每輪折入數、每輪最高嚴重度與一條提示,且階段名與退出碼與不加時相同 [test:t_loop_next_cap_hint_appended_without_changing_phase]
- [S2] 當輪數已達上限,處置閘應在判定之後印同一段,不論過關與否,且過關判定與退出碼不變 [test:t_disposal_cap_hint_without_changing_verdict]
- [S3] 當處置閘在回放或凍結中被唯讀呼叫,處置閘應不印這一段 [test:t_disposal_cap_hint_silent_when_readonly]
- [S4] 若最後一輪折入數大於或等於前一輪,則提示應是換做法 [test:t_cap_hint_not_declining_reshape]
- [S5] 若折入數在降且最後一輪最高嚴重度不高於 minor,則提示應是可以停 [test:t_cap_hint_declining_minor_can_stop]
- [S6] 若折入數在降而最後一輪仍有 major 以上,則提示應是由人裁要不要破例再一輪,不得寫成建議再一輪 [test:t_cap_hint_declining_major_human_decides]
- [S7] 若某輪沒有彙總帳而各席帳的 findings 全是 0,則該輪應算折 0;有人報了條數卻沒有彙總帳,則應印這輪沒記處置且提示是判不了 [test:t_cap_hint_vacuous_round_counts_zero]
- [S8] 當各輪折入累計超過 20 條,loop next 與處置閘都應印建議拆小改動,不論輪數;沒記處置的輪不加進累計並註明筆數 [test:t_cap_hint_breaker_total_folded]
- [S9] 若迴圈是 light 分級、代碼審循序單審,或 2026-08-26 以前開的,則這一段應不印 [test:t_cap_hint_out_of_scope_silent]
- [S10] 當 loop next 帶 --json 且印了這一段,輸出應有 cap_hint 物件,欄位如第三節 [test:t_loop_next_cap_hint_json_fields]
- [S11] 當這一段印出,治理帳與審查帳的行數應不變 [test:t_cap_hint_writes_no_ledger]

## 回退

- 拔掉 loop next 與處置閘裡呼叫這段的兩處即回到現狀。不寫任何帳、不改任何判定,沒有東西要收拾。

## 實務隱患

- 併發:只讀帳本;處置閘讀帳的方式與壞行擋法照舊,這份不另開讀帳路徑、不寫帳。
- 效能:只對這個編號的帳列每輪呼叫一次 `_review_yield_round`;不讀凍結審材。
- 已排除:金流:只讀本機帳本、印文字,不碰任何付款或計費
- 已排除:對外送出:不呼叫任何外部服務
- 已排除:不可逆:不寫任何帳,回退就是拔掉兩處呼叫
- 已排除:守衛面:只印不擋,不改 loop next 的階段與退出碼、不改處置閘判定(S1、S2、S11 綁測試)

## 不在本案

- loop next 帶 `--spec` 對 2026-08-26 之後的迴圈會被已退役舊閘擋下(退出碼 2),「跑滿上限」這個階段對新迴圈結構上到不了——另記一篇 Issue,修法要先想清楚處置閘語意下「上限」代表什麼(舊編號 r1、本編號 r1/r2 的席報告與 intake 都有證據)。

## 誠實界線

- 提示只看折入數走勢與最高嚴重度,看不到「後幾輪是不是修正本身帶進來的」——要做得先有能逐行比對 patch 的工具。
- 門檻(20 條、只比最後兩輪)是起點,沒有回測;回看排在 REVISIT。
- 只印不擋;上限之後要不要擋下一輪,不在這份。
