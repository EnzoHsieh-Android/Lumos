## 問題(機械證據,2026-08-30 盤點)

- **審查席判不了爆炸半徑**:code 席只拿 patch+原始碼;圖譜記的「這段碼綁哪條合約、出過什麼事故、連到哪些功能」沒進派工詞。內容級盤點([[Verification/2026-08-30_席報告圖譜使用一次性盤點]]):**code 迴圈 10 份報告,嚴格 0 份真使用圖譜知識**(design 側 25-33%)。
- **派工單稽核:0/28**(機械數兩法同值:目錄法與 loop 欄法皆 28;數法=materials 欄含 -knowledge/ 路徑;前掃 agent 數 27 係其 find 誤差,已對帳):歷史 28 份 code 派工單,0 份帶爆炸半徑節點;僅 2 份帶任何圖譜材料且都是「被審 spec 自己」。
- **★關鍵時間線(前掃修正後的誠實版)★**:「每席都附圖譜鏡頭、貼內容不給路徑、固定席必答」這條規則 **2026-08-29(d8)才進 code-loop skill**(skill:19,格式指 templates §3 鏡頭 3)——歷史 0/28 是背景不是罪證;**罪證是規則上線後唯一的 code 迴圈(code-entry-latch,3 輪派工)0 執行,而編排者=規則作者本人、同一天**。紀律路線在作者身上上線當天就失守=546 形態最純標本,這是 B(機械助攻)的立案理由。
- 對照:爆炸半徑的機械強點今天全掛在編排者/推送閘(hook 推合約、落成核對、綁定測試真跑、pass 前 sync-check 四條全在跑)——唯獨「席位的眼睛」這環斷糧。

## 提案(三件)

**A(前掃後縮水:規則已存在,不重造)**:模板規則 d8 已落(skill:19「每席都附…固定席必答」+templates §3 鏡頭 3)——本案只補:①code-loop reference/SKILL 若缺 code 席範例則補一格 ②把「B 印出的爆炸半徑段」與該規則的消費關係寫明(B 產料、規則消費)。不另立新格。

**B. `loop next` code 迴圈首輪爆炸半徑 advisory(機械助攻,既有掛點)**:code-* 迴圈首輪、`--spec`=凍結 patch 在手時——從 patch 的 diff header 抽觸及檔案清單→跑既有 impact 計算→在入口栓 A 的段落旁印「爆炸半徑節點」(合約/事故 tag 優先,帶一句「逐條貼進每一席派工詞」)。不是新指令(loop next 是每輪第一步必經),advisory、fail-open,對齊入口栓 A 全部既有鐵則。

**C. 驗收=基線重跑**:下 5 個 code 迴圈後重跑內容級盤點(同 [[Verification/2026-08-30_席報告圖譜使用一次性盤點]] 口徑),code 席實質使用 0→? 是本案唯一的成效判準。

## 實務隱患(逐類答)

- **★真隱患:impact 把審計證物當程式碼來源★**(停案筆記副產物 bug#1,擋在 B 的路上):`governance/review-reports/**` 的凍結 .patch 埋著故意的 bug,pitfalls 明文排除、impact 沒排——B 若直接拿 patch 檔餵 impact,證物會把「事故」節點頂到滿分=垃圾 top。處置:B 只抽 patch **內文的 diff header 檔案路徑**(真改動檔),且排除 governance/review-reports 自身;impact 的證物排除缺陷是否順修=設計審裁。
- **★真隱患:內容量★**:波及固定席實測 20~26 篇、無一低於 8(出處 [[Projects/impact鏡頭機械化_計劃]]:52)——全貼=派工詞爆炸。處置:B 印「帶合約/事故 tag 的 top N(暫 3)+其餘印名列表」,N 為單次判斷,設計審裁。

- **併發/回滾/不可逆/對外**:advisory 輸出級,純讀,revert 即回。已排除。

- **自指**:本案材料(本計劃)將出現在自己 code 迴圈的爆炸半徑裡——自審節點慣例已有(盤點口徑排除),不另處理。
