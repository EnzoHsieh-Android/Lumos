# code-e2e-by-feature r4 記帳更正

2026-10-26,使用者在對話中選「改帳上這輪的指紋欄」。

問題:第四輪七席的審材拆成四包(程式包、文件包、修補程式包、完整快照),記帳時各席的 --spec/--reviewed 各填了自己那包的指紋。處置閘 G3 要求同輪各席填同一份凍結 patch 的指紋,判成「同輪 hash 分裂」。這是編排者記帳的錯,席位的審查內容沒有問題(r1–r3 同樣填法,只因閘只看最新一輪才沒被擋)。

改法:docs/.canary-log.jsonl 裡 loop=code-e2e-by-feature、round=r4、spec_path 不是 r4-snapshot.patch 的六筆(鏡頭1-正確性-opus、鏡頭2-資源-sonnet、鏡頭3-邊界與輸入-opus、鏡頭4-合約與圖譜一致-opus、鏡頭5-通才-sonnet、架構對齊-sonnet),把 spec_path 改成 r4-snapshot.patch、reviewed_sha256 與 result_sha256 改成 r4-snapshot.patch 的 sha256(cced3395e6058de6cf6d42efdac12c59b6305a52c11d18e3ea17a3f7c9ff4fc6)、scope_lines 改成 3032。其他欄位與其他行不動。帳本還沒推,沒有別人讀過這幾行。

依據:四包都是 r4-snapshot.patch 的子集(同一個 base 8f613342、head 7988107c 切出來的);七席的引句對 r4-snapshot.patch 全數錨定(收貨時已跑 quote-check,錨不到 0)。席報告檔、intake、各席報告指紋都沒改。
