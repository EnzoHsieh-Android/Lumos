## v2 設計(三件,全部先不擋)

### T1 · intake 檔的機械宣告行(格式層,寫進模板)

`rN-intake.md` 慣例加**兩個行首錨定的宣告行**(照 `severity:` 型,嚴格 fullmatch):

```
preflight-4: ran        ← 前掃第四類跑了(spec 對 repo 的機械宣稱逐條開檔驗過)
preflight-4-claims: 8   ← 驗了幾條;零條寫 0(退化指定字面,不得留空)
```

- **為什麼是宣告行**:正確性席 F7 證明「有 intake 檔」推不出「跑過前掃」——intake 正本是收貨重現留痕,前掃只是搭便車。專屬宣告行讓「沒跑」機械可辨(沒有那行=沒跑)。
- **為什麼不驗指令輸出**:v1 的「$ 或反引號」判準被三席獨立擊落——11/11 既有樣本全過不了、「已驗類條目」無機械判準、子字串啟發式正是既有 parse 刻意排掉的逃逸型。宣告行只證「有宣告」,真偽靠席位覆核(派工詞既有句「前掃清單在 rN-intake.md,席位可覆核推翻」)。
- 落點:`skills/lumos-design-loop/templates.md` 的 intake 慣例正本(§197 一帶)+ SKILL.md 步驟 2。**只限設計審**——code-loop 審 diff、無 intake 概念,不納入(整合席 F2/正確性席 F4 的範圍刀)。

### T2 · 處置閘 advisory 一行(讀側,不進合取)

`loop status --disposal` 對判定輪多印一行觀測(**不改 rc、不進四條合取**):

```
[disposal] intake: ⚠ 本輪目錄無 rN-intake.md(或:有檔但無 preflight-4 宣告行)——首輪前掃第四類可能沒跑
```

- **為什麼落處置閘**:外家(「落點應是輪級」)與架構席(「intake 若寫側-only 會是帳裡第一個讀側沒人驗的欄位,與『留痕欄一律讀側全席重驗』相反」)同向;處置閘本來就一輪驗一次、已在逐檔重驗 report/snapshot 的 sha。
- **為什麼 advisory**:首日硬擋會打死自主迴圈每日輪(不產 intake,三席獨立抓到)、87 個測試呼叫點全紅、7-9 處模板照字面跑不動。advisory 讓缺席**可見**而不殺人——這正是 lint 空轉誠實化同一帖藥。
- 檔案定位規則:`governance/review-reports/<loop>/rN-intake.md`,N=當輪;r2+ 無新宣稱時宣告行寫 `preflight-4-claims: 0`(退化字面,零條=過)。

### T3 · 帳面選配欄 `--intake`(寫側,選配不必附)

`canary record` 加**選配** `--intake <檔>`:給了就照 `--report` 的四行為(讀不到 rc2/空檔 rc2/路徑正規化/落 `intake_path`+`intake_sha256`;**讀檔帶 errors="replace"**,防 UnicodeDecodeError⊄OSError 炸穿——slim-uninstall 合約裡的前例,邊界席 F3);**不給不擋**。加進結局帳互斥 tuple(架構席①:不加就成唯一不受互斥管的審查欄)。同步:`loop next` 兩個指令模板加 `[--intake <rN-intake.md>]` 選配段、測試共用 helper 不動(選配不紅)。

**轉硬擋的條件(預先登記,照 [S1] 兩段式前例)**:T1-T3 上線後累積 **≥6 個新設計審迴圈**,若 intake 宣告行出現率 <5/6,且期間至少一次「缺 intake 的迴圈又出 B 桶型 blocker」→ 升級 T3 為必附(僅設計審,豁免=自主迴圈直至其 prompt 補產 intake 步驟、code-loop 恆豁免)。出現率 ≥5/6 → advisory 已夠,不升。

## 實務隱患(逐類答)

- **併發/效能/資源**:已排除——T2 多讀一個小檔;T3 與既有 --report 同迴圈同量級。
- **回滾**:T1 純模板文字;T2 一行觀測不進合取;T3 選配欄。各自 `git revert` 即回,無殘留語意。
- **不可逆/對外**:已排除——不寄送、不碰正式環境、不刪不覆蓋。
- **自主迴圈**:T2/T3 皆不擋 → 每日輪照跑,只多一行 ⚠(它的 prompt 補 intake 步驟另案,不阻塞)。
- **測試/模板**:T3 選配 → 87 個既有測試呼叫點不紅;兩個指令模板加選配段不會「照字面跑不動」。canary-audit 綁定測試與 kill 配方不受影響(不加必附)。
- **★真隱患:advisory 可能像 lint 空轉一樣被無視★**——⚠ 印了 41 天沒人理的前例就在本 repo。處置:轉硬擋條件預先登記(見 T3),且出現率數字機械可數,重驗時騙不了。
- **★真隱患:宣告行可以寫了但沒跑(唬爛)★**——T1 只證「有宣告」。處置:誠實天花板明寫;席位覆核是既有派工詞;若重驗期抓到「宣告 ran 但席位仍出同型 blocker」≥2 次,把「宣告行造假」立為事故並升級守衛。
- **與「前置加重一律拒」**:已排除——不加席不加輪;前掃是既有必做步驟,T1 只是讓它的產物有機械可辨的格式。
- **應試化**:宣告行是二值+數字,無字面可鑽;數字造假歸上一條處置。
- **零依賴**:已排除。
