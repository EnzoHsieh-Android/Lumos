# 收斂閘漏項敏感度v2_計劃

> 白話:我們的審查迴圈判「可以收工了」的條件是——這一輪提出來的每個問題都處理完了。它從來沒問過另一半:**該提出來的有沒有被提出來**。外部這個月有兩篇不同領域的論文各自量到同一個不對稱:AI 判官抓「多出來的東西」很準,抓「漏掉的東西」接近擲硬幣。本案先做一把尺去量自家有沒有這個盲區——★不製造缺陷,直接用歷史上真的有缺陷的那個版本★:每個多輪迴圈的前一輪快照,本來就真的缺了某條(當時的審查員真的抓到、報告裡留著逐字引句),拿它重跑,看今天的席位會不會再抓到一次。

PRIOR-ART: ① 最小解層級——不新增閘、不改判準、不製造材料;只是把既有的「隔離環境裡跑一份已知有缺陷的材料、看守衛會不會叫」(`guard kill`)那一招,指向審查閘本身,而已知缺陷直接取自本專案自己的歷史卷證。實驗骨架沿用 [[Projects/修法A_lumos先行ablation_計劃]] 的預註冊格式與 runner 慣例。② 世界解過沒——解過:注入已知缺陷、重跑同一條管線、比對偵測率,是評估「評估器」的標準做法(擾動式後設評估);但★沒有任何一篇是把它用在多席設計審查流程上★,所以借方法、自己搭。③ 裁定=borrow-design,零依賴原生實作。

## 一句話

收斂閘只驗「你列的都處理完了」(自洽),不驗「該列的都列了」(覆蓋)。本案不修它,先量它——**拿歷史上真的缺過東西的那個版本重跑,看它會不會叫**。

## 為什麼是這一條

### 外部:兩篇獨立實證,而且把便宜的解法全否決了

- [arXiv 2608.31016](https://arxiv.org/abs/2608.31016)(醫療紀錄,500 組單一錯誤對照,八種判官設計):抓加料/改錯判別力 0.79–0.94,抓漏掉 0.50–0.63。★關鍵是它試過的補救全部無效★——換措辭、多席投票、自動提示詞優化,只移動操作點,生不出可用的偵測力。這一句預先否決了「多找幾席、把提示寫好一點」。
- [arXiv 2608.01000](https://arxiv.org/abs/2608.01000)(程式領域):判斷某物該不該在集合裡 F1 0.74–0.90;叫它**自己列出那個集合**,產出的測試只接受 19–42% 的正確解。植入的「多的」被抓到是「少的」的 **6–7 倍**,生產失誤比 10:1 偏向漏。
- ★第二篇給了設計依據★:同一模型寫**判準**(規則本身)F1 約 0.99,叫它把判準涵蓋的東西**一條條攤出來**就垮。作者原話是問題不在它不懂、也不在說不出規格,而在無法把規格涵蓋的範圍具體攤出來。**所以分工是「攤清單」歸程式、「逐條判」歸 AI**。

### 自家:閘的形狀正好符合那個盲區

現行處置閘**四類條件**全過才 PASS。★PASS 訊息有兩種★(`scripts/lumos:11774` 與 `:11776`):一般輪逐字列「G3 ∧ 處置全清 ∧ 留痕可重算 ∧ 引句全錨定」;零發現空輪走另一句「G3 ∧ 0 發現空輪 ∧ 留痕可重算;引句無可驗不宣稱」——後者免驗處置集合與引句錨定。每一類內部還有子條件,失敗字串可多於四個。

管發現處置的那一條(`scripts/lumos:11588-11607`)驗的是 `folded_set ∪ accepted_set == findings_set`,外加折∩放行不得非空、放行理由不得缺、輪內有 blocker 則放行必空——**全部都是集合自洽**。

`findings_set` 是編排者自己打進 CLI 的字串。★這裡要講精確★:寫入端(`cmd_canary`,`scripts/lumos:4004`)**有**機械檢查、違反就 rc2 當場擋,但檢查的全是三個集合彼此自洽。★沒有任何一項把 `findings_set` 的內容拿去跟一個外部來源比對★——這份清單沒有參照物,自洽再嚴也證明不了覆蓋。同一件事圖譜早記過天花板(`Systems/convergence-evidence-gate` 摘要:「findings 數源頭仍是 LLM 裁決」「枯竭≠挖乾」),只是一直沒有數字。

### 落差:對程式碼真打一拳,對自己寫的規矩幾乎沒量過

`Issues/嚴謹度分配偏向機械層` 的對照表:程式碼層有「沙盒真弄壞、綁定測試必翻紅」(`lumos guard kill`),自己寫的紀律層★被前後量過效果的原本是 0 條,2026-09-02 修法 A 跑完後變 1 條★(該節點自己已更新,v1 引用 0 是過期值)。**沒有人把這一招指向審查閘**——本案要讓它變成第 2 條。

## ★這不是重推被停的案子,也不是第二套 replay★

### 對 impact 鏡頭機械化(2026-08-29 停案)

那案死因是結構性的:**派工那一刻沒有機械強制點**——派審查員發生在編排者呼叫 AI 的瞬間,沒有 hook 攔得到,任何方案都只是「另一支你可能不跑的指令」。兩輪十席次沒有一席找得出強制點。

**本案不落在派工那一刻,落在收斂那一刻。** 收斂閘是機械跑的、pre-push 真的會擋(`scripts/hooks/pre-push:126` → `_codeloop_guard_verdict`,`scripts/lumos:16728`)。r1 的整合席獨立查證後判此區分成立(minor,非 blocking)。

★自我檢驗條款★:**本案任何一步若要求「派工前多跑一道指令」,就是踩回同一顆地雷,當場退掉**。本案只做唯讀重跑與量測,不新增任何人要記得跑的東西。

### 對 `lumos loop replay`(v1 漏掉的親兄弟,架構席 major①)

`cmd_loop_replay`(`scripts/lumos:451`)是既有的「重跑歷史迴圈」原語,但它重算的是**判定引擎**:對凍結的輸入閉包(全列原文+逐行 sha+spec sha+檔案 blob+`engine_rev`)重跑 gate 邏輯,答的問題是「判定程式有沒有被改壞、帳有沒有被動過」。★它完全不派審查員★。

本案重跑的是**審查員**:同一份材料、今天的模型、看它抓不抓得到。兩者共用「歷史卷證是可回放的」這個前提,但答的是不同問題,不是兩套。★邊界寫死★:本案不動 `loop replay` 一行碼、不寫 `governance/replay/`;若日後要合併,合併點是共用「取某輪凍結材料」的讀取函式,不是判定邏輯。

### 對 canary 協議(2026-08-14 全面停用,d5;v1 漏掉,整合席 major)

canary 是「審一份 spec 之前偷偷植入一個假瑕疵,看審查員有沒有講出來」。★它 2026-08-14 整套停用★,理由三條:①caught/missed 翻譯不出「認真與否」②沒有下游消費者=空轉 ③僅存的煙霧偵測角色已被引句錨定用可重算的方式蓋掉。

**本案與它的三個差別,逐條對死因:**

1. ★不植入★。本案不製造任何缺陷,用的是歷史上真實存在過的版本。d2「只收純加性瑕疵、禁非局部型」的限制針對的是「植入物必須能乾淨移除」——本案沒有植入物,該限制不適用。
2. ★訊號翻譯得出動作★(對死因①②)。M1 兩個門檻各自綁死一個動作,見〈讀法〉;消費者寫在專章。
3. ★不是常設協議★。canary 死於「每輪都要做、卻沒人用結果」;本案是一次性量測,跑完歸檔,不進任何輪的例行流程。

★誠實記★:d5 的死因①(「抓到不代表認真」)對本案**部分適用**——本案量的也是「有沒有抓到」。差別在本案不拿它評價席位可靠度,只拿它回答一個是非題:「這道閘對內容漏失有沒有感覺」。若 r2 有席位認為這個差別不成立,那是本案該關的訊號。

## 實驗設計(★預註冊,跑完不得改★)

### 材料與去重

母體=**跑過兩輪以上的設計審迴圈**。★數字怎麼算的(寫死,免得下次有人拿別的母體來對)★:來源=`docs/.canary-log.jsonl`(2026-09-03 當日 868 筆);「跑過處置閘」=該筆帶 `findings_set` 欄;迴圈歸類用 `_roster_kind()`(`scripts/lumos:5750-5757`,`code-` 前綴=代碼審);「輪」取 `round` 欄。算出:80 個迴圈跑過處置閘(代碼審 27 / 設計審 53),★設計審中有 2 輪以上的 25 個、只有 1 輪的 28 個★。**不要拿 `governance/review-reports/` 的目錄數(94)來對**——那是卷證目錄,含未跑處置閘與已作廢的迴圈,母體不同。限設計審的理由:散文題才是漏項盲區的戰場。

**去重規則(★v1 就死在這★)**:選中的迴圈兩兩比對 `r(N-1)` 的 `snapshot_sha256`,**相同者只取一個**(v1 實測 `about-code-field` 三個版本共用同一份快照、`auto-loop-repair` 兩版同理)。去重後不足預定數量時**縮小樣本,不放寬條件**——樣本數寫進結果,不補人頭。

### 兩組

| 組 | 材料 | 這一組代表什麼 |
|---|---|---|
| **deficient**(有缺陷) | `r(N-1)` 的凍結快照,一字不動 | 這個版本**確實缺了某些條款**——當時的席位真的抓到並要求補進去 |
| **fixed**(對照) | `r(N)` 的凍結快照,一字不動 | 那些條款**已經補進去了**;在這一組報「缺這條」就是無中生有 |

★兩組都是歷史原件,不製造、不修改任何材料。★這一條同時解掉 v1 的三個 blocker(不需要 id→文字映射、不需要切改動塊、不會弄壞文件結構)。

### 標準答案怎麼來(★取代 v1 的 folded_set 反推★)

**答案卷=該迴圈 `r(N-1)` 各席報告本身。** 那些報告逐條寫著:當時抓到什麼、`severity` 多少、以及★逐字引句★——而引句必然錨得回 `r(N-1)` 快照(收貨三道當時就驗過)。

所以「這一條有沒有被再抓到」的判定是:新報告裡有沒有一條 finding,其引句**錨到 `r(N-1)` 快照的同一段落**。逐條比對用既有 `quote-check` 的正規化邏輯(`_quote_rows`,`scripts/lumos:11445-11475`),★方向與該工具原生用途一致★:缺陷文字存在於材料中,抓到的人引得出來。

**「同一段落」的判準寫死**:兩條引句在 `r(N-1)` 快照裡的錨定位置**區間重疊**即算同一條;完全不重疊即算不同條。★不用語意判斷、不派 AI 裁配對★——這是本案唯一可能偷渡主觀性的地方,用位置重疊把它關掉。

**只取「漏項型」的歷史 finding**(本案要量的是漏,不是全部):`r(N-1)→r(N)` 的快照 diff 中,該 finding 對應位置**只有新增、沒有刪改**的才計入答案卷。這個判定是機械的(diff hunk 的型態),不需要知道哪個 hunk 對應哪個 id。

### 四把尺與讀法(★結果出來前寫死;每把尺都必須有消費者,見下★)

| 尺 | 定義 | 誰消費 |
|---|---|---|
| **M1 復原率** | deficient 組裡,答案卷上的漏項型 finding 有幾成被重新抓到(判準=引句位置區間重疊) | ★主尺★,直接裁本案去留 |
| **M2 偽陽率** | fixed 組裡,有幾成的席位報出答案卷上那條(那條已經補好了,報出來即無中生有) | M2 高 → M1 讀數降級為「初步」 |
| **M3 帳面動不動** | deficient vs fixed 兩組的 `findings` 數與 `severity` 分布有沒有差 | M1 落在不下結論區間時,由 M3 判「閘吃的是形式還是內容」 |
| **M4 有效場次率** | 這一場有沒有真的產出可解析的報告(排除撞配額、跑掛、零引句格式錯) | <90% → 本批作廢重跑;★不是把失敗場算成沒抓到★ |

★M4 是 v1 沒有、而且非有不可的一把尺★:本案自己在派外家席時就踩過——外部席「跑掛」和「跑完」在回傳碼上分不出來;而 [[Projects/修法A_lumos先行ablation_計劃]] 第一輪 168 場中 115 場是撞配額的假失敗、當時被記成「沒敲到期望指令」。**沒有 M4,M1 會系統性偏低。**

讀法:

1. **M1 ≤ 40%** → 確認自家也有漏項盲區,外部數字站得住 → **觸發「清單先行」為修法候選,另開計劃**,落點必須是收斂閘。
2. **M1 ≥ 75%** → 席位對漏項其實敏感,外部數字在自家不成立 → **本題關案**,結論寫回〈寫回目標〉列的全部節點。
3. **40% < M1 < 75%** → 不下結論,改看 M3:兩組帳面數字完全不動(`findings` 數與 severity 分布相同)仍算「閘吃的是形式不是內容」的證據,寫進 Issue 但不觸發修法。
4. **M2 > 15%** → 席位會自己編出缺漏,M1 降級為「初步」,要加場次重跑才准當依據。
5. **M4 < 90%** → 本批作廢,補跑一次;仍不足則只報「初步」並明列缺的場次。
6. ★難度校準閘★:**M1 = 0% 或 100% → 判「難度沒校準」,本次不下結論**,擴大樣本重跑一次;★只補一次,不無限重試★——這是 2026-08-02/03 停止投資審查規模那條線的直接教訓(實驗二天花板 3/3、實驗三地板 0/6)。

**門檻為什麼是 40/75 而不是 v1 的 35/70**(邊界席 major:n=8 只有 9 個離散值,兩門檻都落在兩值中間永遠踩不到):去重後樣本量在結果出來前不確定,所以★門檻改成「不落在任何小樣本的可能值上就重設」是行不通的★——改用另一條規則:**樣本量 n 決定後、跑之前**,把 40% 與 75% 各自向最近的可達刻度取整(40% 取 ⌈0.40n⌉/n,75% 取 ⌊0.75n⌋/n),取整結果寫進本篇後才准開跑。取整後兩門檻若相鄰(中間沒有任何可達值),★判本批樣本量不足以判別,擴大樣本或改報描述性數字,不硬判★。
