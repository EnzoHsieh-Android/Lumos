# 只換測試綁定不算寫說明_計劃

白話:「每支檔有家」有一條規則是:同一個提交裡改了程式,又改了某篇系統筆記的內容,那篇就得是那些程式檔的家——不然等於把說明寫錯地方。問題是它把「換一個測試名」也當成「寫了說明」。rtb 改了一支測試的名字,另一篇筆記裡綁著舊名,換成新名就被擋;測試檔本身不需要家、也當不了家,沒有合法出口。這次讓「只換、加、刪測試綁定標記」的改動不算寫說明。

依據:[[Projects/交接2026-10-03_計劃]]〈rtb 第三輪提案〉第 4 優先的 D2;那篇有一條 2026-10-15 到期的回頭條件。

PRIOR-ART: Git 的 `diff --ignore-matching-lines`(`-I<正則>`)與 GitHub CODEOWNERS 之外常見的「只有格式或簿記的改動不需要審」做法,都是先把不算數的部分正規化掉再比;本案同一招,只拿掉綁定標記。同專案:判斷「內容有沒有變」本來就只比摘要、決策、正文三欄,`updated`、驗證連結這類開頭欄位早就不算(`_nodehome_parse_note` 的 sig,推送前逐提交那條也共用);筆記形狀擋認「舊行尾補括號不算新寫」(`_ns_is_tail_append`)是另一條規則,本案不沿用它的括號豁免,理由見摘要。
RETIRE-IF: 有人回報有人把說明藏進測試綁定標記的值裡繞過寫回落點(例如值寫成英文句子),就把可拿掉的值收窄成「這個 repo 裡找得到的測試名」;或連續一季兩個專案都沒有任何提交因為這條放行(推送前帳本看不出時人工抽查),表示需求消失,可以撤掉。

## 範圍

- 做:提交前與推送前兩條路判斷「這篇內容有沒有變」時,摘要與正文先拿掉測試綁定標記再比。
- 做:標記的值只收英數、底線、點、冒號、斜線、井號、@、逗號、連字號、空白、半形圓括號、單引號,另可整段包在一對反引號裡(測試名、類別.方法、`名稱@提交`、Kotlin 反引號測試名的英文句子都在內);值裡有中文或其他字(含方括號)的標記不拿掉,照舊算內容。
- 做:包在行內程式碼(一對反引號)裡的標記不拿掉——那是在介紹寫法(例:計劃裡寫「`[test:名稱]`」),不是真的綁定;跟行內標記解析 `slot_parse` 的既有判法一致(行內程式碼裡的方括號不算欄位)。
- 不做:更正括號、現況句改寫、回頭條件改綁的豁免(都是散文,照舊算寫說明;拆兩個提交是既有出口)。
- 不做:讓測試檔可以當家。
- 不做:`[confirmed:日期]` 這類行內日期欄位的豁免(沒有回報被擋,先不放)。

## 做法

1. 新增 `_nodehome_strip_test_tags(s)`:由左往右掃,碰到行內程式碼(反引號到下一個反引號)整段照留;碰到 `[test:…]`、`[test-gone:…]`(鍵不分大小寫、冒號半形全形都認、鍵與冒號旁可有空白,鍵的寫法同 `_SLOT_KEY_RE`)就連同標記前面的空白一起拿掉;值的字元照〈範圍〉第二條,不合就整個標記照留。不直接呼叫 `slot_parse`:它只解析一行、回欄位不回位置,而這裡要的是「拿掉後的文字」。
2. `_nodehome_parse_note` 的 sig 在摘要與正文兩欄先過這支再去尾端空白;決策欄不動。提交前(`_nodehome_evaluate` 的內容有變)與推送前(`_nodehome_mark_note_content` 的逐提交比)都讀同一個 sig,一處改兩條路都生效。
3. 寫進 [[Systems/每支檔有家]]:摘要一行 WHY 說明「內容有變」不含綁定標記與值的字元限制。
4. 上線後告訴 rtb:可以重做 2026-10-03 放棄的那次測試改名,並關掉交棒單那條回頭條件。

## 實務隱患

- **藏說明**:值限制成英數等字元,中文說明藏不進去;英文句子藏得進去(Kotlin 反引號測試名本來就是英文句子,沒辦法分),見〈天花板〉1 與 RETIRE-IF。
- **誤判沒變**:只有綁定標記被拿掉;同一行其他字有改照樣算內容有變;行內程式碼裡的舉例不拿掉。
- **提醒多唸**:只換綁定的那篇如果正好是改動檔的家,「該動哪篇」的提醒(只提醒不擋)會照樣說「它的家這次沒動」——那篇確實沒寫說明,提醒是對的。
- 已排除:金流:只改一支判定函式
- 已排除:對外送出:不連網,也不寄送任何東西給外部
- 已排除:不可逆:不寫任何檔,只改判定
- **守衛面(沒排除,本案就是放寬一道會擋提交的檢查)**:放寬的只是「內容有沒有變」這個判斷;它同時影響寫回落點與「有寫回時改動檔要有家」兩條(後者本來就該跟著放,見 [S3]),新增沒家、家被拿掉、寫進別人檔名、負責範圍那幾種判定不讀這個值,不變。

## 驗收條款

- [S1] 當同一個提交改了 A 的程式、另一篇 B 只把 `[test:舊]` 換成 `[test:新]`、多加一個綁定、刪掉一個綁定、把 `[test:x]` 改成 `[test-gone:x]`、或綁定值是包在反引號裡的英文句子時,提交前的 home check(`--staged`)應 回 0;B 同時改了一個散文字、綁定標記的值是中文、空的 `[test:]`、或改的是行內程式碼裡舉例的標記時 應 回 1 並點名 B [test:t_nodehome_test_tag_only_edit_is_not_write_back]
- [S2] 當推送範圍裡某個提交改了 A 的程式、同一個提交裡 B 只換測試綁定時,推送前的 home check(`--diff`)應 回 0;同一個提交裡 B 改了散文時 應 回 1 [test:t_nodehome_diff_test_tag_only_edit_is_not_write_back]
- [S3] 當同一個提交改了一支原本就沒家的舊檔、另一篇只換測試綁定時,應 只提醒沒家(回 0),不報「有寫回時每支改動檔都要有家」 [test:t_nodehome_test_tag_only_edit_is_not_write_back]

## 回退

還原本案的提交即可:只改一支判定函式與新增一支正規化函式,不寫任何檔、不改帳本格式。

## 天花板

1. 值是英文句子的綁定標記可以藏說明,工具分不出那是測試名還是句子;靠 RETIRE-IF 的回報觸發收窄。
2. 更正括號(行尾補一段「(更正:…)」說明舊句錯在哪)、現況句改寫仍算寫說明;跟程式改動混在同一個提交時要拆提交。
3. 現存筆記裡有些 `[test:]` 的值帶中文說明(例:「綁的是某某那半」),這種換名照樣算寫說明、照樣擋——要嘛把說明移出標記,要嘛拆提交。
