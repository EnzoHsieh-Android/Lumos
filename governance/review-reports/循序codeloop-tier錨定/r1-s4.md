作為獨立審計席，我已完成對「循序 tier 錨定」設計文件（Spec）的自洽性審查。以下是發現的邏輯漏洞與內部矛盾：

### Finding 1: 邏輯判準衝突與行為翻轉 (Major)
在 S1 的守衛判斷式中，宣稱「其餘象限一格不動」，但實則對 `code` ∧ `standard` ∧ `panel格式` 這一象限做了從「允許」到「禁止」的破壞性變更。
- **分析**：現行守衛（kind-blind）僅在「非 panel 格式」時攔截 rc2，意即現行機制是允許 `standard` 帶 `panel` 的。新設計在 `standard` 象限對 `code` 引入了「反向守衛（帶 round 即擋）」，這會導致原本合法的 `code` 檔位 panel 格式變為非法，直接違反了「不變動其餘象限」的承諾。
- **引句**：「standard | **循序 legacy 格式=設計行為, 放行**; 帳面反帶 --round(panel 格式)→ rc2 格式衝突(鏡像 light 的反向守衛)」
- **引句**：「循序是設計行為,放行;其餘象限一格不動。」

### Finding 2: 實作行為與編制表定義不一致 (Major)
S2 要求 `canary_type` 必須吐出「單值」，但 S3 定義的 `(code, standard)` 編制卻包含兩個席位（Claude + 外家否決席）。
- **分析**：若照字面實作 S2，`loop next` 的指令輸出將遺失「外家否決席」的信息，因為「單值」格式（如 `light`/`legacy`）無法承載多席位角色定義。這會導致實作出的行為漏掉 S3 合約要求的「留痕」與「否決」邏輯。
- **引句**：「canary_type 吐單值(同 light/legacy 樣式, 非 slot dict)」
- **引句**：「席=單 reviewer(claude,required,佔W)+外家否決(external,note-if-absent,note=standard 退同門+留痕)」

### Finding 3: 判準規則邏輯漏洞 (Major)
「外家否決席」的屬性定義與其「否決」功能存在邏輯悖論。
- **分析**：S3 將該席位定義為 `note-if-absent`（缺席時僅留註記）。在邏輯上，一個「否決席」若允許缺席且不阻斷流程，則該席位不具備實質否決權，僅具備「觀測」功能。這與「否決」這一強約束詞彙矛盾，且 `min_seats=1` 的設定進一步確認了該席位在實作中是可有可無的，無法達成 `standard` 檔位應有的審核強度。
- **引句**：「外家否決(external,note-if-absent,note=standard 退同門+留痕)」
- **引句**：「min_seats 同步 1。」

### Finding 4: 未定義行為與術語矛盾 (Minor)
對於 `indeterminate` 種類的處理，同時使用了兩個語意相反的術語。
- **分析**：文中稱 `indeterminate` 應「走嚴（=design 行）」，這意味著必須強制 panel 格式，否則報 rc2；但隨後又稱其與 roster 的「fail-open（失敗放行/跳過）」方向一致。在系統設計中，「走嚴/阻斷」與「放行/跳過」是互斥行為，此處描述會導致實作者在處理無前綴 loop 時無所適從。
- **引句**：「indeterminate(code 開頭無連字號)走嚴(=design 行), 與 roster 的 fail-open 跳過方向一致」

### Finding 5: 測試斷言與實作邏輯脫節 (Minor)
S2 關於 `tier_hint` 的實作落點描述與 S3 的測試收口要求存在實作路徑上的模糊。
- **分析**：S2 明確指出 `seq`（即 code ∧ standard）「不觸發」`tier_hint` 分支，但 S3 又要求對 `code` 循序 loop 的 `tier_hint` 進行措辭修真。雖然邏輯上可以解釋為「在 legacy 狀態下提示可升級至 standard」，但 S2 的「逐點接線」清單中將其標註為「不觸發」，易導致開發者忽略在 `legacy` 分支中補入對 `code` 種類的特殊判斷。
- **引句**：「④tier_hint(維持 legacy-only, seq 不觸發)」
- **引句**：「tier_hint 措辭修真: code 循序 loop 修後可補標 standard(格式相容)」
