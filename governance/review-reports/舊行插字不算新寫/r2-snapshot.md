# 舊行插字不算新寫_計劃

白話:清舊筆記時最常做的事,是在舊句後面補一個「(更正:…)」。筆記形狀擋現在把整行當成新寫的來查,於是舊句本來就有的問題(例如上線前寫的、沒帶來源的 DEP;句子裡原本就有的「還沒」)全部算到補更正的人頭上:擋提交、跳提醒。這份計劃讓它只查「這次插進去的字帶來的新問題」——前提是舊句真的被改掉了(原行不見),不是在旁邊抄一份再加字。

依據:
- 消費專案清漂移回傳(2026-10-02,第 3 項,去識別):在舊句後補更正括號,整行被當新寫——舊行原有的「還沒」觸發否定現況句提醒 24 條;一條上線前合法的舊 DEP 被當成新寫的 DEP 擋下,只好改寫成歷史 WHY。
- 本 repo 重現(2026-10-02,用測試小工具 `_ns_repo`/`_ns_note`/`_ns_stage` 建暫存專案):先提交 `DEP:付款走舊閘道 scripts/pay.py 還沒換掉`,再改成在句尾多一段「(更正:2026-10-02 已換成新閘道,見 [[Systems/Pay]])」並暫存,`note-shape --staged` 回 1(沒寫來源的 DEP),而且對原本就有的「還沒」再提醒一次。這段會寫成 [S1][S2] 的測試。
- 程式現況:`_note_shape_eval` 取「這次新增的行」(`_notelines_new`),對每行跑 `_ns_check_line`(只看正文、摘要、決策)、`_ns_revisit_violations`(也看開頭欄位其他欄),提交前另外收否定現況句提醒(`_ns_negation_collect`)與前綴提醒(`_ns_tag_hints_collect`);舊版那一行不看。後半「新程式檔喚醒舊引用」那一路另有整行相等的舊行判定。

PRIOR-ART: 「只評這次改到的部分」是 lint 接 PR 的標準做法——reviewdog 的 `-filter-mode=added`、Danger 的只看 diff 行;它們的粒度是「行」,本案的問題是「行改了、但只多了字」,所以再細到字:用標準函式庫 `difflib.SequenceMatcher` 判「只有插入」,不引新依賴。
RETIRE-IF: 上線八週後任一成立就撤掉或重想:①抽查治理帳記下的放行事件(〈做法〉6),有一半以上其實是借插字把新問題塞進舊句——那就改回整行查;②治理帳顯示八週內一次都沒放行(沒人補更正,機制是死的);③筆記形狀擋改成以「欄位」或「句子」為單位判新舊,這條被取代。

## 做法

1. **找舊版那一行(單一一支)**:新寫一支 `_ns_old_line_match(N, 起點版本的行, 終點版本的行)`,回「整行相等」「只多了字」或「沒有」與配到的 O。`_note_shape_eval` 前半(新增行)與後半(新程式檔喚醒舊引用,原本的 `ln.strip() in old` 整行相等)都改呼叫它;新增行那一路「只多了字」才放寬,喚醒那一路照舊只認整行相等(它管的是「這行根本沒改、是程式那邊變了」)。筆記格子的舊行判定(同前綴、同核心一句的文字鍵、連結只增不減,只套摘要)與 `old_by`(上線前寫的行)意思不同、不併:格子要看的是「欄位有沒有補」,`old_by` 是「上線前就在的行不查」;這三者的關係寫進 [[Systems/筆記內容閘]]。
2. **「只多了字」的條件**(全部要成立):
   - O 在**起點版本**、N 在**終點版本**;起點版本=`_note_shape_eval` 收到的 `base_where`(提交前是 HEAD,新 repo 第一次提交沒有 HEAD;推送前是推送起點、已夾到上線點;doctor 事後掃描是上線點)。沒有起點版本、那篇在起點版本不存在(含這次改名)、起點那篇讀不成 UTF-8、批次讀失敗:都不配對、照整行查(偏嚴,不 fail-open)。讀起點版本用原樣路徑,不用 NFC 過的鍵。
   - **O 被用掉**:O 這段文字在終點版本整篇出現的次數比起點版本少(原行真的被改掉了);一個 O 只能配一個 N(一對一,先到先配)。在旁邊抄一份舊行再加字,O 還在,不配。
   - O、N 兩邊都先 `strip()`(含行尾 `\r`、全形空白),以 Python 字元(碼點、不做 NFC)計;去空白後相等=「整行相等」;O 空或不到 8 個字不配;O 或 N 超過 2000 字不配。
   - `SequenceMatcher(None, O, N, autojunk=False).get_opcodes()` 只有 `equal` 與 `insert`、至少一段 `insert`。
   - O 在起點版本的區塊(`_notelines_regions`)與 N 在終點版本的區塊相同。
   - 候選篩選:同一篇、比 N 短、開頭 8 個字相同或結尾 8 個字相同;N 照終點行號由小到大處理,候選照起點行號由小到大比;配到多個取最長的 O,同長取行號最前的。
   - 上限(常數,照既有命名):每次執行最多比 2000 對(一對=一條 N 跟一個候選 O 跑一次比對),超過之後的 N 照整行查。
   - 配對表在 `_note_shape_eval` 裡每篇算一次,同時交給違規迴圈與否定現況句提醒的收集器(收集器多收一個參數),不各自重算。
3. **只報新多出來的違規**:配到「只多了字」的 N,同一個判定對 N 算一次、對 O 算一次,**照計數比、只報 N 比 O 多的**。兩邊都用 N 在終點版本的脈絡(圍欄內外 `visible`、重建標記 `regen`、檔案清單),同一把尺。鍵:
   - 程式行號引用、釘版本不合法:(規則, 片段)。注意 `_ns_check_line` 同一行同一個片段只出一條(先去重),所以「插進第二個一字不差的引用」不會多報(天花板 5)。
   - 其他整行層級的規則(沒寫來源的現況描述、SEE 只放連結、回頭條件格式不合、條件寫錯、條件寫在不評估的地方):(規則, 改法)——改法字樣帶了錯誤細節(「條件寫錯」把每種錯接在一起),新插的不同錯會讓鍵不同而照報;同一種錯不重報。
4. **否定現況句提醒**(只在提交前算):配到「只多了字」的 N,N 與 O 各取全部命中,鍵是命中的**詞表項目**(`_NS_NEG_NARROW_*` 裡的那個字眼,`not … yet` 這種浮動區間取「not…yet」這一項,不取比到的整段),照計數比;N 多出來的項目裡,取落在插入範圍內的那一個命中切片段;沒有多出來的就不提醒。命中受整段影響(規則句、歷史句的排除),插字讓舊命中消失或新命中出現都照 N 的結果。`seen`(要判的新行數)照舊算進這些行。
5. **不套用的**:筆記前綴提醒(`_ns_rule_hints`)——它的警告字串尾巴帶行文前 40 字,插字就變,而且裡面有筆記格子開擋前的預告,壓掉會讓開擋那天才第一次擋人,所以照現行整行提醒;之後加在 `_note_shape_eval` 後面的新規則(例如 1b 測試綁定)預設照整行判,要套用得自己明寫。第二層筆記內容審、存量漂移檢查不動。
6. **放行也記一筆帳**:有任何違規或提醒因為這條被減掉,記一筆治理帳(閘 `note-shape`,種類 `hinted`,`extra` 帶 `check: "insert-only"`、減掉幾條、幾行、幾篇、各規則名的條數,不帶原文)——這是對「沒違規的放行不寫帳」(2026-09-27 定的)的明確例外,給 RETIRE-IF 用;提交前與推送前各算各的。
7. **同步其他計劃的口徑**:[[Projects/否定現況句配回頭條件_計劃]] 的量測與 [[Projects/筆記形狀擋_計劃]] 的 RETIRE-IF 從本案上線那天起少算「只多了字的舊行」,各補一行說明起算日。

## 實務隱患

- **繞過**:在旁邊抄一份舊行再加字——O 還在、不配(〈做法〉2「O 被用掉」)。把舊行改寫成「只多了字」並在插入段塞新的程式現況——行號引用照片段比、會擋;沒寫來源這條整行層級規則,舊行本來就犯、不重報,新塞的現況靠第二層判定者(天花板 1)。
- **效能**:改到的筆記多一次起點版本的批次讀(`_nodehome_cat_blobs`);比對 `autojunk=False`,2000 字低變化字串最壞一對約 0.2 秒,所以單行 2000 字上限加每次 2000 對總上限;正常筆記一對不到 1 毫秒。記憶體只多起點版本的那幾篇全文。
- **併發**:已排除:只讀 git 物件;多寫的一筆治理帳走既有寫入器。
- **回滾**:還原這一個提交即回到整行查;多出來的那種帳留著無害。
- **相容**:提交與推送時擋得只會變少;doctor 事後掃描以上線點為起點配對,上線點之後才寫、又只多了字的行照整行查(跟今天一樣),不會比今天嚴。
- 已排除:金流:這道檢查只讀筆記與 git 物件,不碰任何付款流程
- 已排除:對外送出:不呼叫網路、不寄送、不寫到 repo 之外
- 已排除:不可逆:只決定擋不擋、印什麼,還原一個提交就回到原本的判法
- **守衛面**:這是擋提交與推送的閘,改的是「哪些違規算新的」——放得太寬就是一條繞過的路,所以不排除、照走設計審。

## 回退

出事時還原這一個提交即可:判定回到「新增的行整行查」,沒有改任何帳或設定的格式,多出來的那種帳留著無害。已經靠這條放行、推上去的舊行不會被追溯擋下(閘只看新寫的),要追查就跑 `lumos note-shape --diff <起點>..<終點>` 用還原後的版本重看那段範圍。

## 天花板

1. 放過的是「舊行本來就犯的違規」,不是「插進來的字一定沒問題」:插進一段新的程式現況到沒來源的舊 DEP 裡,第一層不會擋,要靠第二層判定者——送審的是整行,沒標哪一段是新插的。
2. 只認「只多了字」:補更正時順手改了一個錯字,整行照新寫查。
3. 只看起點版本:提交時以 HEAD、推送時以推送起點、doctor 以上線點為起點,三者不同;同一批工作裡先插 A、下一個提交改成 B,提交時是替換、照整行查(推送時對最初起點仍是只多了字)——要改自己剛插的字就 amend 或推前壓成一個提交。筆記在範圍內改名就配不到,照整行查(偏嚴)。
4. 只篩「開頭或結尾 8 個字相同」:句首、句尾兩頭都插字,或舊行不到 8 個字,配不到,照整行查(偏嚴,不是漏洞)。
5. 同一行同一個程式行號引用只算一條(`_ns_check_line` 先去重):插進第二個一字不差的引用不會多報。
6. 「條件寫在不評估的地方」每行只報一條:舊行已有一個、再插第二個,不會多報。
