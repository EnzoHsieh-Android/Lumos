# 筆記形狀擋_計劃

白話:筆記不留程式碼推得出來的東西(d1),這份先做機械上「一看就知道」的那一半:提交時擋下新寫的程式行號引用,以及沒寫出「程式碼答不了的來源」的現況描述。看意思才判得出來的那一半(推送前的 AI 審查員)在 [[Projects/筆記不存程式碼推得出的事_計劃]],兩份是 Enzo 2026-09-27 裁的拆分(Issue d7)——原本合在一起審了兩輪、折了 70 條還在冒,分開讓這一半先生效。

依據:[[Issues/筆記把程式現況寫進脈絡而漂移_rtb實測回饋]] 的 d1–d7;前一版規則為什麼沒擋住見 [[Projects/Lumos定位_程式碼為主脈絡為輔_計劃]]〈檢討〉;下面每一條做法都已經過那份大計劃兩輪設計審(卷證 `governance/review-reports/筆記不存程式碼推得出的事/`),這裡只收跟第一層有關的結論。

PRIOR-ART: 全部借本 repo 既有形狀——①「每支檔有家」的閘([[Systems/每支檔有家]])整套:提交前 `--staged`、推送前 `--diff <範圍>`、判定全在 lumos 裡、hook 只呼叫且只認 rc1 為擋;新分支起點「不在任何遠端分支上的最早提交」;★連同它緊鄰的三個配套一起借★——上線點截斷(`_nodehome_golive` / `_nodehome_clamp_base` 那種用提交前掛鉤裡的標記字串找上線提交)、合併提交處理(提交前遇到合併就跳過、推送前只算合併自己多改的行,`_nodehome_merge_own_changes`)、設定從被檢查的版本讀(未暫存的 off 關不掉它);②程式檔判定用它的 `_nodehome_code_kind`(副檔名清單或開頭 `#!`),內容一律從被檢查的版本讀;③圍欄判定用 `_visible_lines`;④「現況前綴要帶什麼」直接改既有的 `_CONTEXT_MARKER_RULES`(`lumos lint` 已經在跑的那套),note-shape 呼叫同一支,不另寫第二份規則;⑤行號引用抽取擴充既有共用抽取器 `_node_code_ref_tokens`(加兩個選項:認裸文字、認 `#L`),預設行為不變,refcheck、改檔前推筆記、每支檔有家三個既有使用者不受影響;⑥開關叫法照 `lint_new.gate`(block / warn / off)、跳過照 `LUMOS_SKIP_LINT_NEW`、不是 block 時 doctor 印一行照 `node_home.gate`;⑦治理帳事件走既有 `_gate_event`,照它的契約:寫帳失敗不改變擋不擋。唯一新發明的是放行寫法 `路徑@<提交>:數字`(本 repo 沒有把提交編號寫進文字的先例,所以條款把它的驗法寫死)。不採用新依賴。
RETIRE-IF: 上線兩個月後任一成立就撤掉或改規則:①被擋之後改用 skip、專案開關或 `--no-verify` 的次數超過被擋次數的三成(誤擋多到大家在繞);②對上線後新增的筆記行抽樣,行號引用或沒來源的現況前綴仍佔一成以上(擋不住);③兩條規則連續兩個月零觸發,而且抽樣也看不到這兩種形狀(問題已經不存在,閘只剩成本)。
REVISIT:2026-11-27 量上面三個數,跟大計劃的回頭日同一天。

## 做法

### 範圍與行(寫成一支共用函式,第二層之後直接用)

- **範圍**:
  - 提交前=暫存區差異;★正在合併(有 MERGE_HEAD)時整支跳過★並說一句(推送前會查合併結果),照每支檔有家。
  - 推送前:遠端已有那個版本就用「遠端版本..本機版本」;新分支或本機沒有遠端版本時,起點是「不在任何遠端分支上的提交」裡最早那個的上一個,全部已在遠端就不查,最早那個沒有上一個才從空樹比。合併提交只算它自己多改的行(不算從另一個父提交帶進來的)。
  - CI:推送前後兩個版本;前一版全零(新分支首推)時,那一步先把所有遠端分支抓下來、再用同一算法並排除這條分支自己的遠端參照。
  - ★三者最後都經上線點截斷★:起點早於 note-shape 上線的那個提交(提交前掛鉤第一次出現 `note-shape --staged` 字樣的提交)時,改從上線點算——上線前進來的是舊帳(d2)。這也涵蓋「整個 repo 第一次推送」與「CI 抓不到其他分支」:最壞退到上線點,不會退到空樹。
- **行**:圖譜筆記在範圍內新增或改動的行(改名用 git 的改名偵測認成同一篇,只算真正變動的行;偵測不到改名時新檔整篇算新增——方向是多查)。算不算在範圍內用「那一行落在被檢查版本的哪一塊」判,不靠解析欄位:落在正文、開頭欄位的 `summary` 區塊、`decisions` 區塊(含底下任意縮排的巢狀清單)算;落在其他開頭欄位不算;`decisions` 區塊裡鍵名是 id、decided、valid、superseded_by 這類結構鍵的行不算。刪掉的檔不算。
- ★程式碼圍欄裡的行照樣查★(原稿不查,r1 三席指出包進圍欄就一鍵繞過、圍欄沒關好連後面都看不到)。貼在圍欄裡的舊輸出若帶行號,一樣要釘版本或拿掉——它同樣會跟現在的程式對不上。圍欄只用來判「這一行是不是 `FACT:` 開頭的摘要行」這類結構。
- 筆記檔讀不成 UTF-8:整支擋下並講是哪支檔。

### 兩條規則(`lumos note-shape`,提交前 `--staged`、推送前與 CI `--diff <範圍>`)

1. **程式行號引用**:`路徑:數字`、`路徑#L數字`(反引號包著或裸寫都算),而且★路徑在被檢查的版本裡真的存在★、是程式檔或測試檔(副檔名清單或開頭 `#!`,內容從被檢查的版本讀;不套每支檔有家「不要求有家」的那些豁免,只排除 `.md` 等文件)。不存在的路徑(舉例、別的專案)不擋,交給第二層。**放行寫法** `路徑@<提交>:數字`:★`<提交>` 必須是至少 12 位的十六進位提交編號、在 repo 裡找得到、那個提交裡有這個路徑★;`HEAD`、分支名、標籤、`main~1` 這類會移動的名字一律不算放行。要指到測試就寫測試名。
2. **現況類前綴沒寫出程式碼答不了的來源**:新增的 `FACT:` `FLOW:` `DEP:` 行要帶 `[來源:部署]` `[來源:資料庫]` `[來源:生產]` `[來源:外部]` `[來源:人工]` 其中之一(d3;五類對應紀律範本「程式碼答不了」那一句列的部署設定、資料庫實際值、生產觀測、外部、人工核可)。★不用 `[src:]`★——那個標記已經是「從程式碼重建的筆記」指向程式位置的出處標記,帶 `regen` 的筆記會把 `[src:部署]` 當成一支叫「部署」的檔去找而判成幻覺證據(r1 三席)。只寫「以程式碼為準」加查詢不再算數。實作是改既有 `_CONTEXT_MARKER_RULES` 的 FACT 規則並加上 FLOW、DEP,所以 `lumos lint` 對整篇、note-shape 對新增行,判的是同一套。

回傳碼照鄰居:0 過、1 擋、2 參數錯;不是 git 或找不到 lumos 就放行並說一句。hook 只認 1 為擋。閘名 `note-shape` 登記進既有閘名單,擋下與放行事件走 `_gate_event`;寫帳失敗照它的契約不改變擋不擋。擋下訊息列出每一處(檔、行、哪條規則、怎麼改),並明講「內容還在工作目錄,改完再提交」;hook 不得動工作目錄。

**開關與跳過**:`note_shape.gate`:block(預設)/ warn / off,★從被檢查的版本讀★(提交前讀暫存區、推送前與 CI 讀頂端提交),工作樹裡沒暫存的 off 關不掉它;不是 block 時 `lumos doctor` 每次印一行(照 `node_home.gate`)。環境變數 `LUMOS_SKIP_NOTE_SHAPE=1` 單次跳過,寫一筆 `skipped-env` 事件。RETIRE-IF ① 的「繞過次數」= skipped-env 事件數 + doctor 看到的非 block 專案數 + doctor 事後掃到的繞過行數。

### 治理帳寫入加鎖(移出)

原稿把「替治理帳寫入加鎖」放在這裡;r1 七席有四席指出它動的是所有閘共用的寫入器、會把寫帳問題變成擋人、還漏了其他寫入者。它跟本計劃要擋的東西無關,已移到 [[Issues/治理帳多個寫入者都沒上鎖]] 另外處理;本計劃照既有寫入器現況寫帳。

### 紀律範本改寫

紀律範本〈寫筆記時〉那張表的 `FACT:` `FLOW:` `DEP:` 整列改成 d3 的收窄說法:只准寫程式碼答不了的現況,要帶 `[來源:…]`;程式碼查得到的一律不寫。同一節寫明第一層會擋哪兩種形狀、放行寫法、開關與跳過。各專案各自跑 `lumos update` 拉新版。skill 裡只指路、不放第二份定義。

### 消費專案的 CI

`lumos update` 不會動各專案的 CI 設定檔。所以 `lumos doctor` 檢查專案 CI 有沒有呼叫 `note-shape --diff`,沒有就每次印一行並給要貼的那一步(含「先抓所有遠端分支」);另外 doctor 對上線點之後、已推上遠端的提交跑一次 note-shape,有違規就列出來(抓 `--no-verify` 繞過)。工具鏈自己的 CI 手動加那一步。

## 條款

- [S1] 若新增行(含圍欄內)有指向被檢查版本裡真的存在的程式檔或測試檔的行號引用(含沒有副檔名、開頭是 `#!` 的主程式),則 note-shape 應擋下並列出每一處;指向不存在路徑或 `.md` 的、沒改動的舊行不應擋 [test:t_note_shape_line_refs_existing_code_new_only]
- [S2] 釘版本寫法只有 `<提交>` 是至少 12 位、找得到、且那個提交裡有該路徑時才放行;`HEAD`、分支名、標籤、相對寫法、找不到的編號應照樣擋 [test:t_note_shape_pinned_ref_requires_real_sha]
- [S3] 若新增的 `FACT:` `FLOW:` `DEP:` 行沒帶五種 `[來源:…]` 之一,則應擋下;只有「以程式碼為準」加查詢的也應擋下;`lumos lint` 對同一行應給同樣判定;帶 regen 的筆記寫 `[來源:部署]` 不應被重建守衛當成檔案路徑 [test:t_note_shape_current_state_prefix_requires_source]
- [S4] 推送前遇到新分支或本機沒有遠端版本時,起點應為「不在任何遠端分支上的最早提交」的上一個;CI 新分支首推應先抓遠端分支再用同一算法;三者的起點早於上線點時應改從上線點算;上線前就有的舊內容首次推送不應被擋 [test:t_note_lines_range_base_and_golive_clamp]
- [S5] 提交前正在合併時應跳過並說一句;推送前的合併提交只應算它自己多改的行,從另一個父提交帶進來的不應算 [test:t_note_lines_merge_commit_own_changes_only]
- [S6] 新增行集合應含正文(含圍欄內)、summary 區塊、decisions 區塊(含任意縮排的巢狀清單),且應排除其他開頭欄位與 decisions 的結構鍵;改名應認成同一篇;筆記檔讀不成 UTF-8 時應 rc1 並指名那支檔 [test:t_note_lines_scope_rename_and_non_utf8]
- [S7] 擋下時應印每一處的檔、行、規則與改法,且不得改動工作目錄;不是 git 或找不到 lumos 時應放行並說一句;寫帳失敗不應改變擋不擋 [test:t_note_shape_block_message_and_fail_open]
- [S8] `note_shape.gate` 應從被檢查的版本讀,工作樹未暫存的 off 不應生效;設 off 或 warn 時 doctor 應印一行;`LUMOS_SKIP_NOTE_SHAPE=1` 應放行並寫一筆 skipped-env [test:t_note_shape_config_from_snapshot_and_visible]
- [S9] 抽取器加的兩個選項預設關閉,refcheck、改檔前推筆記、每支檔有家對同一段文字的抽取結果應與改動前相同 [test:t_node_code_ref_tokens_defaults_unchanged]
- [S10] 紀律範本的 FACT/FLOW/DEP 那列應寫 d3 的收窄說法與 `[來源:…]` 五類,各專案注入的紀律區塊應與範本一致 [test:t_discipline_current_state_row_narrowed]
- [S11] doctor 應在專案 CI 沒呼叫 `note-shape --diff` 時印一行並給要貼的步驟,並列出上線點之後已推上遠端卻違反兩條規則的新增行 [test:t_doctor_note_shape_ci_and_bypass_scan]

## 回退

照這個順序,反過來會卡住別人推送:
1. 先拿掉工具鏈自己 `.github/workflows/ci.yml` 裡的 note-shape 那一步(這支檔不在 `lumos update` 同步清單裡,要手改)。
2. 消費專案不用等中心:各自把 `note_shape.gate` 設成 off(要提交才生效)就停。
3. 拿掉提交前與推送前 hook 裡的呼叫;★note-shape 指令先保留一個版本、改成只印「已撤除」並回 0★——消費專案自己貼在 CI 裡的那一步不受 `lumos update` 管,指令直接刪掉會讓它們的 CI 每次都因為找不到子指令而紅;下一個版本再刪。
4. `_CONTEXT_MARKER_RULES` 的 FACT 規則改回舊判準、拿掉 FLOW/DEP 那兩條;抽取器的兩個選項沒有使用者了可以留著(預設關閉,不影響既有行為)。
5. 紀律範本那列改回舊句時要先想好:舊句正是讓現況描述留存的出口(見〈檢討〉第 4 點)。
6. 被擋下的內容從沒進過 git,只在作者的工作目錄。

## 實務隱患

- 守衛面:新的擋人機制,誤擋會讓人習慣繞過——所以只看新行、上線前的舊帳截掉、合併不重查、不存在的路徑與文件路徑不擋、有嚴格驗過的釘版本寫法、有開關與跳過且都看得見,全部進 RETIRE-IF ①。
- 資源併發:note-shape 只讀不寫筆記;寫治理帳照既有寫入器現況(那個寫入器本身沒鎖的問題另記在 [[Issues/治理帳多個寫入者都沒上鎖]],本計劃讓每次提交都寫一筆,頻率會變高,那篇已註明)。
- 已排除:對外送出:只在本機讀 git 與檔案,不送任何內容到外部服務
- 已排除:不可逆:擋下時不產生提交、hook 不動工作目錄,內容留在作者手上;拿掉閘並照回退順序做就恢復原狀,沒有留下拿不掉的機制
- 已排除:金流:不碰任何付款或計費流程

## 誠實界線

- 這一層只擋兩種形狀;rtb 稽核裡漂移最多的「目前沒有 / 只有 N 種」句型、貼錯標籤的 WHY 行、done 計劃的現況段,形狀都不固定(句型比對抽樣準度約三分之一),要等第二層。在第二層上線前,這些照樣寫得進去。
- 行號引用的抽樣 12/12 是單人目測、樣本小;把圍欄也納入後,貼在圍欄裡的舊輸出會被擋,這部分沒有抽樣過,是 RETIRE-IF ① 要盯的誤擋來源。
- 沒有接 CI 的消費專案,`--no-verify` 推上去當下擋不住;doctor 事後會列出來,但那時已經在遠端了。
