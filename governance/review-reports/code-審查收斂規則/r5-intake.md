## 根因分組與處置

同輪有 major(資1、合1、架1),accepted 必空,14 條全部折入。

- G1 改已索引決策的內容偵測不到(資1):反例清單寫在決策內容裡,分級只看索引鍵、新增問答、守的檔,直接改決策文字追加反例三條都看不到,判 light。→ 分級對起點索引裡每筆殘留,讀它所在節點在起點與頂端兩版的決策內容,內容有變就升 high,理由句照實寫「改了已登記殘留的決策內容」;鏡頭把這種也列進新增殘留段。
- G2 讀不出時鏡頭靜默放空、理由句說錯(正1、資2、通1):治理帳或頂端索引讀不出時,分級升 high,鏡頭卻當成沒有新增,沒有附段也沒有必答題;起點沒問答、頂端讀不出時理由句寫成「刪掉問答」。→ 鏡頭在任一邊讀不出時一律回「算不出來」固定說明加必答題;分級把「讀不出」與「刪掉」分成兩種理由句。
- G3 鏡頭排序與上限可被擠掉(邊1、資3):問答照 ts 原始字串排序後取最後 12 筆,偽造 ts 可把新增列藏掉;合約照節點名排序取前 5 條,假節點問答可把真殘留擠出清單。→ 新增的列與真的殘留索引變化排最前、其餘照 `_gov_ts` 排序(讀不出的排最後);問答指到的節點不在殘留索引的,標「節點不在殘留索引」並排在真殘留之後。
- G4 鏡頭新段沒接時間預算(併1、架2):`_lens_residual_section` 沒接 deadline,單次 git 讀取最長 60 秒。→ 照外部碼表補選段同一個 deadline 寫法,逾時回「算不出來」那句加必答題。
- G5 git replace 兩種做法並存(架1、架3):這分支用逐呼叫 `_git_env_no_replace`/`no_replace=`/手帶 `env=`,另外三個分支用入口。→ 四個分支一律入口強制 `os.environ["GIT_NO_REPLACE_OBJECTS"] = "1"`(逐字同一行),這分支拿掉工廠函式、旗標與手帶 env;`_residual_blob_at` 改包 `_lens_git(binary=True)`,只留 missing/unreadable 的分辨。
- G6 文件(合1、合2、合3):templates §3 與 06 手冊仍說鏡頭內容一律從 base 讀、只有外部事實行例外,新段從頂端讀推送者寫的字;「沒答的席照漏答固定席處理」沒有對應機制;「審查席會看到」寫成無條件,新增 untestable 問答也會升 high 卻沒寫。→ 兩處手冊明寫例外與它的防護(注入框、字數上限、消毒);刪掉漏答那句,照實寫把關強度是「推送升 high、要過一輪高風險代碼審」,審查席有沒有答沒有機械核對;列出鏡頭附段的前提(LUMOS-IMPACT 標記、base 在主線、沒逾時、已提交);reference.md、06、圖譜即合約.md 補「新增 untestable 問答也升 high」。
- G7 測試缺口(合4):鏡頭新段只從命令列測;算不出來的固定句、超過上限的「另有 N 條未列」、case/checker/ts 欄位的消毒、guard audit 遇到硬連結都沒測。→ 逐條補測試並各做一次拿掉就紅的變異。
