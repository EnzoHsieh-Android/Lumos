# code-審查收斂規則 r4 收貨紀錄(跑滿後破例的第四輪)

七席全回(正確性、併發、邊界、合約、通才、架構對齊、資安),report-normalize 都不用改、quote-check 全數錨定。共 17 條:正1–2、併1、邊1–2、合1–5、通1、架1–3、資1–3。

## 根因分組與處置

同輪有 major(合1、架1、資1、資2),accepted 必空,17 條全部折入。

- G1 外層看門只看可手改的索引(正1、資1、資3):同一筆決策追加反例不改索引鍵、同句合約加第二條再手改索引、doctor 拿(節點、指紋)當字典鍵後者蓋前者,三條路都讓新的殘留不被當成新增。→ 推送範圍新增了判 untestable 的 residual-ask 列(起點帳沒有、頂端帳有),本身升 high——殘留的來源是問答,看它比看可手改的索引貼近要擋的動作;doctor 比對改成比整份清單(多重集合),鍵帶殘留指標。
- G2 審查席沒被要求看(合1):文件說把關是審查席看殘留決策與問答,但代碼審手冊與派工範本完全沒提。→ 派工鏡頭(dispatch-lens 的固定席)遇到範圍內新增的殘留或新增的 untestable 問答,附上那筆殘留決策內容與相關問答列,列成逐條必答一項「這筆殘留的問答有沒有換編號或改字重問、第二個代理是不是另一個代理」;lumos-code-loop 的 SKILL.md 與 templates 補一句;測試綁住。
- G3 本機 replace refs 偽造起點(資2):`git replace` 讓起點讀到假的索引與帳。→ 殘留相關的 git 呼叫一律設 `GIT_NO_REPLACE_OBJECTS=1`;另寫一行 REVISIT 記其他閘是否也該設。
- G4 時間戳記解析第二套(架1、正2、邊2):自寫的解析只接 ValueError,極端日期會當掉。→ 改用既有的 `_gov_ts`。
- G5 其餘(併1、邊1、合2、合3、合4、合5、通1、架2、架3):捷徑帳的警告照實寫(寫入端跟隨捷徑、讀端拒收);刪帳偵測改用計數相減(重複列各算一筆);計劃守衛面那行與 residual-ask 擋下訊息、`--help` 改成「方便不是保證」的口氣;文件檢查涵蓋所有講這件事的檔、條款與測試一一對上;改字換指紋的理由句寫成「合約句子改了(舊的拿掉、新的加入)」;讀某版檔案統一用 `git show`(或註明 cat-file 的理由);`GOV_LOG_REL` 套到所有既有字面值。
