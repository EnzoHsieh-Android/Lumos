# code-審查收斂規則 r3 收貨紀錄

七席全回(正確性、併發、邊界、合約、通才、架構對齊、資安),report-normalize 都不用改、quote-check 全數錨定。共 17 條:正1–3、併1、邊1–4、合1–2、通1–3、架1–2、資1–2。

## 判讀:「只准問一次」同類第三次,換形狀

三輪都在打同一件事——用字面身分(反例編號、合約指紋、節點名)擋「換個方式重問到想要的答案」:r1 換大小寫或標點、r2 改字換指紋或刪帳列、r3 換編號或改節點名(資2),以及把治理帳標成不比對內容讓刪帳偵測失效(資1)。反例編號是編排者自己取的標籤,字面怎麼比都擋不住換一個新名字。

改法(外層看門):推送範圍裡新增了殘留(頂端索引有、起點沒有的(節點、合約指紋、殘留指標)),推送本身升 high,走高風險代碼審——審查席看得到殘留決策與那幾筆問答,「挑到想要的答案」成為被審查的事件,不再靠字面比對擋。黑名單照留但明講是方便不是保證;刪帳偵測不再看 diff 文字,改成比起點與頂端兩版帳檔裡 residual-ask 列的集合(頂端少任何一列就升 high),屬性檔、NUL 位元組、帳尾換行都影響不了。

## 根因分組與處置

同輪有 major(正1、資1、資2),accepted 必空,17 條全部折入。

- G1 新增殘留沒人看(資2、合1、通1):外層看門(見上)。黑名單鍵改成(節點、合約指紋、編號),不再整個節點共用;手冊與計劃改寫成「只准問一次是方便,真正的把關是新增殘留的推送要過高風險代碼審」。
- G2 刪帳偵測靠 diff 文字(資1、通3、邊3、併1):改成比兩版帳檔的列集合;檔名清單失敗時也照樣比帳。
- G3 比對鍵少了合約身分(正1):拿掉殘留、縮小守備的比對鍵改成(節點、合約指紋、殘留指標)。
- G4 編號正規化把 `c-1` 與 `c1` 分開(正2):連續分隔符號合成一個之後,夾在字母與數字之間的單一分隔符號也拿掉(`c-1`、`c_1` 與 `c1` 同一個;`c1.1` 與 `c11` 仍不同,因為分隔符號夾在兩個數字之間)。
- G5 日期與指紋細節(正3、合2、邊1、邊2、邊4、架1):`[audit:]` 與問答比到秒(問答 ts 對審計戳記日期當天 23:59:59 不算晚於——改成審計戳記沒有時間時要求日期嚴格晚於問答日期,或審計戳記帶時間);日期抽取改用既有的 checker 正規式與 `_rule_date` 驗真日期,抽不到日期就擋;指紋多剝零寬與控制字元;補「取最晚日期」的測試。
- G6 寫法(架2):治理帳相對路徑寫成一個常數。
