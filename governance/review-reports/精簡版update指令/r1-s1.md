# 精簡版update指令 r1 light 單席審計報告(通才)

## Finding 1(blocker):`lumos update` 呼叫 `install.py --force` 會把「更新工具」跟「per-project 注入」兩件事焊死在一起

引句：「跑 `[sys.executable, dest/install.py, "--force"]`,回其 rc。」

install.py 的 main() 每次跑無條件做三件事:①複製 CLI ②複製 skill ③用 Path.cwd() 當 target 對當前目錄的 CLAUDE.md 做 sentinel 區塊合併/取代(注入目標守衛+CLAUDE.md 合併呼叫)。spec 讓 _slim_update() 直接呼叫、不帶任何跳過③的旗標。兩種壞行為:cwd 不像專案根→守衛 rc2 拒絕(最常見情境直接失敗);cwd 恰好像專案根→該專案 CLAUDE.md 被非預期改寫。install.py 自己的 docstring 記著同型真實事故(子代理在來源 repo 下誤跑,改掉來源 repo 的 CLAUDE.md)。spec 全文無一處提到此耦合;測試 2 用假 install.py 完全繞過真合併邏輯。

## Finding 2(blocker):`sys.argv[1]` 沒做長度檢查,裸打 `lumos` 從乾淨用法說明變成未捕捉例外崩潰

引句：「`sys.argv[1]=="update"` → `return _slim_update()`——攔在 argparse 前,免動子命令註冊手術」

現行裸跑 `lumos`(無參數)由 argparse required=True 印 usage+錯誤訊息,行為良好。spec 的攔截在 parse_args() 前直接讀 sys.argv[1],裸打時 IndexError 未被接住→使用者看到 Python traceback。全 CLI 最基本呼叫方式的全新回歸,測試策略無一條涵蓋。

## Finding 3(major):install.py 自己印出的「凍結快照」訊息未列入修真範圍,散落掃只鎖 README

引句：「散落掃關鍵詞:凍結/不會有更新/不是發布通道/update。」

install.py 安裝結束無條件印「★這是凍結快照,不是發布通道——不會有更新。…★」——與 README 凍結聲明同款字樣,但 S3 修真主詞全是 README。`lumos update` 跑完會印「不會有更新」給剛用了 update 的使用者,直接自相矛盾;測試 4 只斷言 README 內容抓不到。

max severity: blocker
