### Finding 1:沒關的圍欄,只要最後一行長得像圍欄標記,看門就認定圍欄有關好,藏在裡面的阻塞題照樣放行
severity: major
blocking: 是
歸因:有證據的原有漏查。修前修後同樣放行,所以不是回歸。但這一輪新增的「前面有圍欄沒關」防線,就是要擋這件事,卻沒擋到。

引句:「unclosed = tail < len(lines) and not re.match(r"^\s*(```|~~~)", last)」

走法:`_pq_unreachable` 不看 `_visible_lines` 內部「圍欄是否真的關上」的判定結果。它改成猜:只要檔案最後一行有字,而且長得像 ``` 或 ~~~,就當圍欄有關。實際沒關的圍欄,最後一行常常也是圍欄樣的字。例如:
- 外層用 ```` 開,內層 ``` 自己關好,外層忘了關,最後一行是 ```。
- 用 ~~~ 開,卻用 ``` 收。

這時 `_scan` 判定圍欄沒關,後面整段看不見。但看門因為最後一行像標記,把 `unclosed` 判成 False,題目行不被撈出,阻塞題消失,規格閘放行。

重現:在 `$W` 下跑 `python3.14 probe2.py before` 與 `python3.14 probe2.py after`。輸入是 `## 待決問題` 之後接 `~~~`,再接 `- [Q1] 訂單成功的定義 [類:需求][階段:需求][狀態:待人][阻塞]`,最後一行是 ```。

| 案例 | 修前 | 修後 |
|---|---|---|
| 4 個反引號外層忘了關 | `pass []` | `pass []` |
| ~~~ 開、``` 收 | `pass []` | `pass []` |
| 對照:純 ``` 沒關,最後一行是題目 | `pass` | `GATE`(正確,這是新修好的) |

修法方向:讓 `_visible_lines` 把 `_scan` 回傳的「收尾時是否還有圍欄開著」旗標露出來,不要在外層猜。現有測試「節內圍欄沒關」「標題前圍欄沒關」只用 ``` 加一般文字結尾,蓋不到這個形狀。
