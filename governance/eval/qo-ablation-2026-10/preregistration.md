## 要回答的問題

在一個剛用 Lumos 接入、還沒有程式碼的後端 repo 裡,AI 收到一句不完整的需求、拿不到人的回答(單回合、無人看守)。

> **指示檔多一段「情境出題寫法」,AI 會不會更常把該由人決定的事交到人手上,而且不會更常去問 repo 裡已經寫了的事、也不會更常直接開始寫程式?**

背景:2026-10-02 量過「在設計稿多逼作者回答四個後端失敗題」,沒過門檻、不接線([[Projects/設計審後端失敗與未知狀態_計劃]])。所以這次先量再接。

## 受測者與分組

- 兩種受測者,各自獨立做一次完整實驗:**Claude**(探針的 claude 執行器,模型 sonnet)與 **Codex**(探針的 codex 執行器,模型照本機 Codex 設定,開跑時記下版本)。
- 兩組 repo,都從同一個基底 `git clone`:基底是 `git init` + README + `lumos init`,只有一個提交,訊息 `chore: initialize evaluation fixture`。
  - 甲(現況):基底原樣。
  - 乙(多帶寫法):CLAUDE.md 與 AGENTS.md 末尾各附加 arm-b-guidance.md 全文,改動併進那唯一的提交(訊息不變)。
- 開跑前核對:兩組資料夾名稱相同、目錄樹相同、提交數與訊息相同;逐檔比對只有 CLAUDE.md 與 AGENTS.md 不同。Claude 讀 CLAUDE.md、Codex 讀 AGENTS.md,兩份都帶到乙組說明。
- 已知混淆:乙組的指示文字比較長,「多了指示」本身也可能改變行為;本實驗分不開「這段內容」與「多一段任何指示」。

## 標準答案

- gold.json:每題 6 個「該被提出的決定」,由不知道乙組說明內容、被禁止讀本 repo 的代理獨立寫成;內容自第 1 版起未改。
- gold-topics.json:從 gold.json 機械抽出的主題說明(不含正規式),給評分員用。
- gold.json 的正規式**降級為輔助指標**,不參與門檻判定(第 1 版的審查證明它連否定句也算命中)。

## 執行(qo_ablation.py run)

- 每種受測者:6 題 × 3 次 × 2 組 = 36 場,合計 72 場。
- 交錯:每個(題目, 第幾次)甲乙各跑一場,兩場的先後由種子 `qo-2026-10` 決定;題目照 P1→P6 順序。
- 探針參數:`--runs 1 --max-turns 30 --timeout 600 --answer-max 20000 --wait-on-limit 1800`,每場一個結果檔(`--out`)。結果檔存在 results/ 底下。
- 撞到用量上限的場次由探針等待重試;仍失敗的場次可以續跑(已有有效結果的跳過),續跑不改任何參數。

## 評分

- **盲評**(qo_ablation.py packets):72 場混在一起,隱去受測者、組別、場次,以種子 20261012 打亂後編成 R001… 的盲評編號,每包 8 場。對照表另存,評分完成前評分員拿不到。
- **兩位獨立評分員**:Claude(opus 子代理,乾淨脈絡)與 Codex(唯讀沙盒),各自照 rater-instructions.md 判全部 72 場;彼此看不到對方的結果。
- **一致率**(qo_ablation.py agree):以「每場 × 每個 gold 項目」為判定單位算 Cohen's kappa。
- **分歧仲裁**:兩位判不同的判定,交給第三位(另一個乾淨脈絡的 Claude opus 子代理),只看該場回答、該 gold 項目與兩個候選標籤(不告訴它哪個標籤來自誰),選一個。主指標用仲裁後的標籤。
- 亂問數:兩位評分員的平均,四捨五入到整數;分歧超過 1 時交仲裁。

## 指標

1. **交付率**(主指標):一場回答裡,被判為 `handed` 或 `assumed_confirm` 的 gold 項目數 ÷ 6。
2. **亂問數**:評分員判的「把 README 已寫的事當問題問人」的主題數(只計 P1、P2、P3、P6)。
3. **先寫程式**:由工具呼叫機械判定(qo_ablation.py 的 code_start:寫到 docs/ 以外的非 .md 檔,或 shell 寫檔、建置工具)。數場數。
4. 輔助(不進門檻):gold 正規式覆蓋率、正規式亂問數、回答長度。

## 門檻(每種受測者各自判)

**通過**要三條同時成立:

- 以 6 題為單位,每題算「乙組 3 場平均交付率 − 甲組 3 場平均交付率」,**6 題平均差 ≥ 0.15**,而且這 6 個差做單側精確符號翻轉檢定 **p ≤ 0.05**。
- 乙組亂問總數 ≤ 甲組。
- 乙組先寫程式場數 ≤ 甲組。

後兩條只能說「本樣本沒觀察到增加」,不宣稱「不會增加」。

**接線決定**:兩種受測者都通過 → A 塊接進規格閘;只有一種通過 → 攤給人裁;都沒通過 → 不接線,只留寫法說明。

## 無效條件(成立時該受測者判「無定論」)

- 任一場回答被截斷(原始長度大於保存長度)。
- 甲乙兩組都有完整 3 場有效結果的題目少於 5 題(只用完整的題目算主指標)。
- 兩位評分員的 kappa < 0.6:判準不可靠,不據以接線,攤給人裁。
- 甲乙兩組 36 場全部交付率為 0:多半是儀器或判準壞了。

## 已知限制(事先承認)

- 每組每題只跑 3 次;真正的獨立單位是 6 題。6 題全為正差時精確檢定 p 才到 1/64,樣本小,結論只當方向。
- 評分員是模型,不是人;盲評與兩人一致率只能降低、不能消除判斷偏差。
- 只量「有沒有把事交給人」,不量問題問得好不好,也不量自答對不對。
- 結論不外推到 sonnet 與本機 Codex 設定以外的模型。
