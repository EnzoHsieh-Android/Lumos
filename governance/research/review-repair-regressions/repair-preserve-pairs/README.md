# 修復與保留配對：受控實驗

人工夾具合約：cap把整數限於0..8，caller回傳相同結果，字串輸入產生TypeError。這不是正式專案合約；不能升格成圖譜INVARIANT。

| 角色／案例 | 修前 | 正確修補 | 修好負數但上限退化 |
|---|---|---|---|
| 修復：-1應為0 | 失敗 | 通過 | 通過 |
| 保留：0應為0 | 通過 | 通過 | 通過 |
| 保留：1應為1 | 通過 | 通過 | 通過 |
| 保留：8應為8 | 通過 | 通過 | 失敗 |
| 保留：caller(8)應為8 | 通過 | 通過 | 失敗 |
| 保留：字串應拋TypeError | 通過 | 通過 | 通過 |

18次執行都符合表格的預期；這不是18項產品測試全綠，第三欄的故意退化應失敗。只驗修復案例時兩種修補都綠，保留案例才指出額外退化。

重放：從experiment.json將三個sources各寫成獨立目錄的product.py，將probe_source寫成probe.py；對每個版本與cases物件執行：

```text
python3.14 -I <probe.py> <該版本/product.py> '<cases內的一個JSON物件>'
```

退出碼與原始觀測見runs及expected_rc。臨時目錄由TemporaryDirectory清理；紀錄裡當次命令的路徑為當次證據，重放時換成新目錄。原文與輸入保留，不靠舊目錄存在。

sample-pairing.json只展示根因組、角色、選例與結果指標；不是新CLI schema，沒有自動驗證器，亦非日後真實會談採用的證據。來源與適用界線見計劃筆記的PRIOR-ART。
