# 修訂輪非必要改動：歷史核對結果

結論：這份樣本不支持優先新增「後續輪不報minor」規則。先處理誤報查證、測試能否抓錯與修補後保留行為，更貼近已觀察的返工來源。

## 固定範圍與方法

固定b31337db版本的code-convergence-input-guards前兩輪原報與收貨。共10個finding ID：9個來自席、1個編排者機檢補充；九項folded、一項refuted。ID不是獨立產品缺陷數：R1 correctness-F1與rollback-F1同一測試可信度根因，R2 key-F1是測試偵測力，不是已發生產品退化。

逐項人工核對歷史處置，再以Python集合核对完整收貨ID、来源SHA-256與必留清單。機器只驗資料一致性，不判斷問題對錯。完整資料見census.json。沒有執行模型對照、外部程式或新一輪產品重現；耗時與輪數成效不由這份資料推導。

| 輪 | ID | 核對結果 |
|---|---|---|
| r1 | correctness-F1 | folded：輸出碼可能由別的拒收代答，需核對指定行為與現場前置 |
| r1 | rollback-F1 | folded：端點測試污染中間版本案例；與correctness-F1同組根因 |
| r1 | rmax-resources-F1 | folded：全樹容器存活上限不符，不是跨呼叫洩漏或RSS量測 |
| r1 | rmax-resources-F2 | folded：讀取期間工作樹變動造成誤放與誤擋 |
| r1 | operator-F1 | folded：分組失敗仍提供不確定測試證據 |
| r1 | rollback-F2 | refuted：當輪v1.0沒有報告宣稱的強制機器欄位要求；原資訊與lint反證保留 |
| r2 | state-F1 | folded：索引撤回後借用證據仍生效；原版亦有，不冒稱前輪修補引入 |
| r2 | alignment-F1 | folded：解析器OSError被誤當材料讀取錯誤；辯方minor，不洗掉原major |
| r2 | key-F1 | folded：無快取重用壞法仍綠，不能以minor或僅測試變更排除 |
| r2 | lint-F1 | folded：编排者機械補充，真複雜度增加使閘擋；不是獨立席或自選整理 |

## 候選與負控制

只延後純風格／自選重構的候選，在這10個歷史ID中延後0項；保留九個既有folded與一個有反證的refuted。不能把前份報告的合成命名例子塞進分母來宣稱省了修補。

若改成「修訂輪一律不報原minor」，key-F1會被排除；其實已有無重用壞法在舊斷言下仍綠、強化後翻紅的歷史實證。若直接排除機檢來源，lint-F1真新增複雜度義務也會被隱藏。alignment-F1原報major、辯方minor，仍是診斷錯誤，不能以後續降級當無需查證。這些是處置規則的反例，不是已觀察模型漏報率。

官方文件既建議修訂輪抑制新增nits，也將CLAUDE規則違反列為nits，並示例把不合法輸入解析成0的行為放在nit。因此跨工具等級不可直接當純風格標籤：[官方文件](https://code.claude.com/docs/en/code-review#what-you-can-tune)（查證2026-10-07，本次只借原理）。本專案架構席已排除純風格，原有辯方亦成功反證rollback-F2；本樣本支持繼續這兩個既有做法，不能宣稱全專案不再有風格返工。

## 對下一步的影響

優先沿既有修復／保留配對與測試有效性抽查，在下一個實際修訂輪核對：原案例是否真的能抓錯、修後是否保持既有行為、發現是原漏網還是修補致因。R1修補把Git reader移入判定層的退化已由原架構釘543/1攔住，修回後544/0；它是已存在的歷史修補事件，沒有增造finding或重新掛進R2。

不新增降噪分類器，不改severity、閘、輪數或既有處置。後續若實輪真出現自選整理擴張，再記錄來源、是否有必要義務與新增改動成本，按獨立採用計劃驗收。現有單功能歷史核對不能證明哪種策略改善輪數。
