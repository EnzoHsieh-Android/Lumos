# 05 設計審查迴圈(spec 要進實作前)

白話:一份設計 spec 在動手實作前,讓幾個不知道脈絡的審查員輪流挑毛病,每輪記帳;散文 spec 走處置閘——一輪裡每個發現折掉或附理由接受就算過(2026-08-25 裁;K=2 連續乾淨只剩已定錨 panel 帳的舊迴圈在用)。完整流程在 `lumos-design-loop` skill;這裡只列「什麼時候敲哪個」。

| 情境 | 指令 | 結果怎麼讀 |
|---|---|---|
| 「這輪該派誰、第幾輪、怎麼記帳?」(每輪開頭) | `lumos loop next <編號> [--tier standard\|high\|light] [--spec <計劃.md>]`;第一次一定帶 --tier | 印現在狀態、這輪要幾人、應派哪個角色、記帳的指令範本 |
| 「spec 動筆後想先掃模糊措辭」(排乾步驟) | `lumos prose-lint <計劃.md>` | 只提醒不擋,rc 恆 0;掃出的類別歸編排者排乾,派工詞明寫席位不得報 |
| 「審查員交報告了,要記這一輪」 | `lumos canary record none --loop <編號> --round rN --auditor <席> --severity <等級> --findings <數> --spec <計劃.md> --reviewed <sha256> [--scope-lines N]`;★散文設計審記帳型態(2026-08-25):各席一筆留痕**不帶三個 set**,同輪僅一筆彙總 carrier 帶 `--findings-set/--folded-set/--accepted-set/--accept-reason`;全席都要 `--report/--snapshot`★;每條發現標 `--finding-kind id=code|spec|process`(在修程式 / 被審文件 / 流程自己要求的東西) | 印憑證;超過 1800 行會提醒拆開審 |
| 「這輪/這個編號過關了沒?」 | 散文設計審新迴圈一律 `lumos loop status <編號> --disposal --spec … --repo …`(單輪全處置即收斂;同輪有 blocker 席則 accepted 必空);panel(每席各記一筆)→ `--gate --panel --min-seats 3`(K=2,僅已定錨 panel 帳的舊迴圈用);兩閘互斥,問錯會被指路;單人 `--light`;結清 `--settle <清單.json> --gate` | ✅ GATE PASS / ⛔ GATE FAIL,後面寫卡在哪一關 |
| 「審查員的引句是不是真的在 spec 裡?」 | `lumos quote-check <報告.md> --spec <凍結快照.md>` | 錨不到的引句不採信 |
| 「派工單要查的材料,報告有沒有都碰到?」 | `lumos seat-check <報告.md> --dispatch <rN-dispatch.json> [--ledger <出界帳.jsonl>]` | unreported=沒碰;out_of_scope=引到範圍外 |
| 「想找人覆核某一筆判定」 | `lumos canary second --id <憑證> --verdict agree\|overturn --auditor <另一人>` | 必須換人 |
| 「人裁判整份重寫,要收尾舊編號」 | `lumos loop rewrite <編號> --successor <新編號> --note <一句為什麼>` | 記 rewrite 事件+血緣進治理帳;連續第二次判重寫會印強制攤人警告 |
| 「不看散文,只看帳本算到哪了」 | `lumos loop verify-progress <編號>` | 結構欄位,不受報告措辭影響 |
| 「長跑的上下文太長了」 | `lumos loop compress <檔>` | 三欄壓縮 |
| 「各審查員歷史抓漏率」 | `lumos loop canary-stats` | 觀測用,不影響過不過 |
| 「多個找錯工具的結果要合併估漏網」 | `lumos loop capture-counts --finder … --finder …` | 吐 --capture-counts 參數 |

上限依分級:light 2 筆、standard/high 3 筆;第一輪沒帶 `--tier` 會退到最寬鬆的舊制(6 筆),所以第一輪一定帶。跑滿上限還沒過 → 停,攤給人裁;別無限燒。settle 結清模式不要用 `loop next`(它認不得 settle 會誤報),直接問 `loop status --settle`。
