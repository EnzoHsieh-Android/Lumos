## 寫什麼進去(上面是敲什麼,這裡是寫什麼)

**第一個問題永遠是:這句話程式碼推不推得出來。** 推得出來的別抄,抄了就會過期,而且讀的人分不出哪句是脈絡、哪句是過期的現況。

**分類規則不在這裡**:摘要行怎麼分類(`WHY:` / `RULE:` / `PITFALL:` / `FACT:`)、每類同一行還要有什麼,**唯一來源是紀律範本 `scripts/templates/graph-discipline.md` 的〈寫筆記時〉那一節**,它會被注入每個專案的 CLAUDE.md,動筆時本來就在你眼前,直接看那份。
這裡刻意不放複本——複本前面被插一段唱反調的「快速版」、複本被藏進註解、複本標點跟本尊分岔,2026-09-21 一天之內被三種手法各繞過一次;守衛改成「不准有第二份定義」,比「複本要一字不差」穩。


**寫不出來的時候**(格子的鍵、撤除條件與作廢的寫法細節在 reference.md〈格子的細節〉):
- `WHY:` 查不到 `[出處:]` 就先問人,不要憑印象寫。
- `RULE:` 寫不出機器式的 `[retire:]`,就是還沒想清楚這條該不該立;真的只能由人判斷,寫 `[retire:人裁]` 加 `[until:日期]`,到期會被提醒。
- `PITFALL:` 沒有測試就寫 `[repro:指令]`;兩個都沒有就老實寫 `[防回歸:無 <理由>]`。
- 綁的測試被刪了:`[test:名稱]` 改寫成 `[test-gone:名稱]`(可加 `@提交編號`,只當追溯線索);它只是紀錄、不算防回歸,PITFALL 另補 `[repro:]` 或 `[防回歸:無 …]`。測試還在就別寫 test-gone(推送時會被擋)。推送時碰到的筆記,整篇的 `[test:]` 都要指得到真測試、舊行也算(擋不擋看 `.lumos/config.json` 的 `note_shape.test_refs`:沒設是 warn 只提醒、設 block 才擋;細節見 06 的「推送被『碰到的筆記裡有指不到真測試的綁定』擋下」那一列)。
- `FACT:`/`FLOW:`/`DEP:` 先問要不要寫——`lumos search <詞> --code` 查得到的就刪掉這行;只放連結的改寫成 `SEE:`。

**重大決策填四欄**(context / alternatives≥2 / why_chosen / trade_offs),缺資訊問人不編——`decisions` 欄位是少數能挑戰程式碼的地方之一,所以它要經得起被引用。

**Issue 要四段齊**:① 症狀(看得到什麼) ② **根因**(為什麼會這樣) ③ 現在怎麼繞 ④ 什麼條件算修好。
- 缺根因的 Issue 之後沒人敢動,只能重查一遍。
- Issue 是「程式碼看不出的規則」最常落腳的地方:2026-09 受控實驗四題裡,唯一分得出勝負的那題(大額退費要人工核可),規則就只寫在 Issue 裡——只看程式碼那組全錯,有筆記的組過半。
- 結案的 Issue 正文第一段要有結案橫幅,並標明「以下是當時的排查紀錄,不是現況」。

**承認風險要附回頭看的條件**:寫「沒機械守衛 / 只提醒不擋 / 單次量測 / 還沒有 X」這類會過期的句子,**把會過期的那一句本身搬成獨立一行回頭條件**,原行刪掉那一句(多句長段只搬那一句;RULE/PITFALL/WHY 這類摘要行留著前綴與欄位,在摘要裡另起一行)。**一行只講一件事**(doctor 到期唸的時候會截斷,後面黏別的內容會被吃掉)。兩種寫法:
- 日期式 `REVISIT:YYYY-MM-DD 一句要做什麼`:量測、外部、人工進度這種觀測類只能寫日期,到期 doctor 會唸。
- 條件式 `REVISIT:[when-<鍵>:<值>][by:YYYY-MM-DD] 一句要做什麼`,`[by:]` 必帶(條件寫錯、永遠不成立時,期限到了至少會被唸)。條件鍵跟那件東西直接綁的優先:它會在的檔 `[when-file:路徑]`(判檔在不在樹上)、守它的測試 `[when-test:測試名]`、Python 的函式或類別 `[when-symbol:路徑::名稱]`——when-symbol 只認 Python 定義(函式、類別或模組層指定;其他語言只判名字整字有沒有出現,寫在註解或呼叫處也算,所以非 Python 的東西改用 when-file);講的是一個流程或一份計劃,用 `[when-status:Projects/名稱=done|superseded]`(節點不加 `[[ ]]`,加了會被當成條件寫錯擋下);等某支檔或某段程式不再出現,用 `[when-gone:路徑]`(樹上找不到這個路徑就成立)或 `[when-gone:路徑::字串]`(檔裡不再出現這段字就成立;照字面、不能含反引號與 `]`;檔不是 UTF-8 文字就判不了)——字串寫錯、檔名寫錯會在寫下的那次推送就被點名「已經成立」。
- 回頭條件要獨立一行、行首寫 `REVISIT:`(前面最多一層列表或引用記號);寫在句子中間、表格、核取方塊、粗體或刪除線裡的不會被讀——新寫的提交時擋(「回頭條件寫在句中」),舊的 doctor Z 段列位置。只是在提這個寫法就用行內程式碼或全形引號「」包起來。
- 不用再回頭了:在那一行加 `[closed:YYYY-MM-DD 理由]`(建議行尾;理由至少 4 個字、不放 `[[連結]]`;一行一個),寫了 doctor 不唸、條件不評估。條件已成立、但待辦還要留著提醒,用 `lumos drift ack` 表態,不是結案。
- 先確定那件事還沒發生:推送時條件已經成立,那次推送會被漂移檢查擋下(同一次推送裡後面的提交才把東西做出來也算);寫完可以跑 `lumos drift scan` 看有沒有已經成立的。scan 在某條底下印「寫下時就已成立」,表示它寫下那一版條件就已經成立、從來沒在等任何事——改成真的會發生的條件,或刪掉;表態照留也照印。
- 原句照留、旁邊另寫一行的形狀不算:條件成立時被改的只有旁邊那行,句子照樣過期。提交時新寫的「還沒有/尚未…」現況句沒搬成回頭條件行,筆記形狀擋會印提醒(只提醒、不擋)。

寫完任何節點 → `lumos lint <節點>`(見 04)。
