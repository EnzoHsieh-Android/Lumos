## 寫什麼進去(上面是敲什麼,這裡是寫什麼)

**第一個問題永遠是:這句話程式碼推不推得出來。** 推得出來的別抄,抄了就會過期,而且讀的人分不出哪句是脈絡、哪句是過期的現況。

**分類規則不在這裡**:摘要行怎麼分類(`WHY:` / `RULE:` / `PITFALL:` / `FACT:`)、每類同一行還要有什麼,**唯一來源是紀律範本 `scripts/templates/graph-discipline.md` 的〈寫筆記時〉那一節**,它會被注入每個專案的 CLAUDE.md,動筆時本來就在你眼前,直接看那份。
這裡刻意不放複本——複本前面被插一段唱反調的「快速版」、複本被藏進註解、複本標點跟本尊分岔,2026-09-21 一天之內被三種手法各繞過一次;守衛改成「不准有第二份定義」,比「複本要一字不差」穩。


**寫不出來的時候**:
- `WHY:` 查不到出處就先問人,不要憑印象寫。
- `RULE:` 寫不出退場條件,就是還沒想清楚這條該不該立。
- `PITFALL:` 沒有測試就附一條會重現的指令;兩個都沒有,這條只是感想。
- `FACT:`/`FLOW:`/`DEP:` 先問要不要寫——`lumos search <詞> --code` 查得到的就刪掉這行。

**重大決策填四欄**(context / alternatives≥2 / why_chosen / trade_offs),缺資訊問人不編——`decisions` 欄位是少數能挑戰程式碼的地方之一,所以它要經得起被引用。

**Issue 要四段齊**:① 症狀(看得到什麼) ② **根因**(為什麼會這樣) ③ 現在怎麼繞 ④ 什麼條件算修好。
- 缺根因的 Issue 之後沒人敢動,只能重查一遍。
- Issue 是「程式碼看不出的規則」最常落腳的地方:2026-09 受控實驗四題裡,唯一分得出勝負的那題(大額退費要人工核可),規則就只寫在 Issue 裡——只看程式碼那組全錯,有筆記的組過半。
- 結案的 Issue 正文第一段要有結案橫幅,並標明「以下是當時的排查紀錄,不是現況」。

**承認風險要附回頭看的條件**:寫「沒機械守衛 / 只提醒不擋 / 單次量測」這類句子,旁邊必須有什麼時候重驗。帶日期的寫成獨立一行 `REVISIT:YYYY-MM-DD 一句要做什麼`,**一行只講一件事**(doctor 到期唸的時候會截斷,後面黏別的內容會被吃掉)。

寫完任何節點 → `lumos lint <節點>`(見 04)。
