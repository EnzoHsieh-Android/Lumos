# 03 寫回圖譜(改完東西之後)

鐵則:frontmatter(開頭欄位)一律用指令改,別手改;正文段落用 Edit。多個連結必須一行一項。

| 情境 | 指令 | 結果怎麼讀 | 不用它會怎樣 |
|---|---|---|---|
| 「要新開一篇筆記」 | `lumos new <system\|issue\|verification\|project\|moc> <名稱>`;驗證紀錄加 `--plan <計劃> --systems <節點>` 自動雙向連 | 骨架建好,印出該填什麼;接著填摘要 | 手建檔漏 type/aliases,lint 擋 |
| 「改狀態/日期/類型這種單一值」 | `lumos set <節點> <欄位> <值>` | 印改成什麼;改 status 會連帶同步標籤 | 手改漏同步標籤,doctor 報漂移 |
| 「加一條驗證紀錄/關聯/標籤到清單欄位」 | `lumos append <節點> <欄位> "[[x]]"` | 自動去重 | 單字串塞多連結變 ghost 節點 |
| 「把清單裡一項拿掉(死背書、降格的指針)」 | `lumos remove <節點> <欄位> <值>` | 找不到會拒絕,不會亂刪 | — |
| 「記一條決策」 | `lumos decision-add <節點> "<內容>" --decided <日期>` | 回編號 dN | 手寫 decisions 格式壞,整條消失 |
| 「推翻一條舊決策」 | `lumos decision-supersede <節點> --match "<片段或 #dN>" --by "<新決策>"` | 舊的標 valid:false 並指向新的;會開一本連鎖帳 | 建在被推翻決策上的筆記沒人提醒 |
| 「舊筆記的決策沒編號」 | `lumos decision-reindex <節點>` 或 `--all` | 補 dN | 無法被引用 |
| 「翻案後,鄰居筆記要不要跟著改?」 | `lumos rel-cascade list`;逐篇 `confirm`/`prune` `<鄰居> --cascade-id <id> --from <節點>#dN`;中斷後 `lumos rel-cascade resume <id>` | 帳本記你判過哪些 | doctor 的 E2 會一直提醒 |
| 「做完了,要留驗證紀錄並掛回功能」 | `lumos new verification <名> --plan … --systems …`;漏掛的事後 `lumos sync-verified-by --apply` | doctor 1/4~4/4 不再報孤兒 | 驗證沒人找得到 |
| 「某篇功能筆記內容我重新確認過還站得住」 | `lumos self-audit <節點> [--date …]` | 寫 self_audit 戳記 | doctor [S] 一直提醒 |
| 「業務方點頭了,要留痕」 | `lumos signoff <節點> --note "<確認了什麼>"` | 寫簽核帳 | — |
| 「計劃條款誰認領了」 | `lumos spec-trace <計劃節點>` | 未認領的條款 rc1 | 計劃結案但沒驗證 |
| 「老驗證紀錄太多,要歸檔」 | `lumos archive [--days N] [--apply]` | 先 dry-run 再 --apply | — |
| 「改名/搬檔」 | `scripts/graph-rename.sh <舊> <新>` | 連結一起改寫 | 手搬斷連結 |

寫完任何節點 → `lumos lint <節點>`(見 04)。
