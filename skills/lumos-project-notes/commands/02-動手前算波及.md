# 02 動手前算波及(你準備改 code 的時候)

| 情境 | 指令 | 結果怎麼讀 | 不用它會怎樣 |
|---|---|---|---|
| 「我要改這個檔/這段 diff,哪些筆記、驗證、決策會受影響?」 | `lumos impact --file <檔>` 或 `lumos impact --diff <起點..終點>`;查某節點一層鄰居 `lumos impact --node <節點>` | 先列「必看」(合約/事故),再列相關 top-8;每條都是該動手前看的 | Edit/Write 時 hook 會自動注入一份,但只推你碰到的檔,邊界要自己查 |
| 「這份 spec/這段改動有什麼實務隱患?風險分級多高?」 | `lumos pitfalls <spec.md>` 或 `lumos pitfalls --diff <範圍>` | 印提問清單;`tier: high` 代表推送前要過代碼審(見 06) | 高風險改動沒審就推,pre-push 會擋 |
| 「改了這些檔,該跑哪一層測試?」 | `lumos test-layers --diff <範圍>` | 提醒用,不擋 | 漏跑整合/UI 層 |
| 「改了這些檔,具體該跑哪幾個測試?」 | `lumos testmap affected --diff <範圍>`(第一次先 `lumos testmap build`) | 建議清單,不擋 | 跑全套浪費時間,或漏跑 |
| 「改了 A 檔,歷史上常一起改的 B 檔要不要跟著改?」 | `lumos cochange check [--staged\|--diff …]`;看規則 `lumos cochange rules` | 警告清單,不擋;pre-commit 也會自動跑 | 漏改夥伴檔 |
| 「about_code 預標標錯一整批,要整批撤」 | `lumos about-code revert --batch <YYYY-MM-DD> --dry-run` 先看,再去掉 --dry-run 真撤 | 只動 stamp 第一段 = batch-<日期> 的節點;人工修正過的(claude/…)不動 | 誤撤人工修正 |
| 「我刪掉/改名了符號,筆記還在講舊的嗎?」 | `lumos search <舊名> --code` 逐句判;`lumos delguard` 是 pre-commit 自動跑的版本 | 列出還在指名舊符號的筆記 | delguard 逾時會放行,別只靠它 |
| 「這段 code 沒有任何筆記連到它,該補嗎?」 | `lumos link-candidates [--diff …]` | 候選清單,唯讀;要不要補由人裁 | 新 code 變圖譜孤兒 |
