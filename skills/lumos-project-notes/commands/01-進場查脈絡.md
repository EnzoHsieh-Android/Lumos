# 01 進場查脈絡(你想搞懂現況的時候)

規矩:**第一個工具呼叫就是這裡的指令**,grep/Read 是之後印證用。

| 情境(你心裡在想…) | 指令 | 結果怎麼讀 | 不用它會怎樣 |
|---|---|---|---|
| 「這件事圖譜有沒有記?在哪篇?」 | `lumos search <詞> [--path Systems] [--top N]` | 每行=篇名+命中行;分數越高越相關。0 命中先換同義詞,再判沒記 | 用 grep 判「圖譜沒記」,以前真的錯過 |
| 「找 code 裡有沒有提到這個符號/路徑」(配合圖譜一起看) | `lumos search <詞> --code` | 同上,但範圍含程式碼 | 分兩套工具搜,漏一邊 |
| 「這篇筆記的來龍去脈、鄰居、合約」 | `lumos context <節點> [--brief]` | 頭部先列「提醒:動這篇之前先確認前提」和合約;往下是連出/連入。大節點(Landmark 實測 40KB+)先 `--brief`,輸出超過 20KB 工具會提醒 | 只讀一篇,看不到它依賴誰、誰依賴它 |
| 「這篇完整內容」 | `lumos show <節點> [--body-only]` | 整篇原文 | search 的索引行不夠下結論 |
| 「動這個模組有什麼不能碰的?」 | `lumos contracts [<節點>]` | ★INVARIANT★=改了就是破壞性變更,後面 [test:] 是綁的測試;★DEBT★=可以改 | 碰到合約,pre-push 的 doctor 會擋 |
| 「誰連到它 / 它連到誰」 | `lumos backlinks <節點>` / `lumos links <節點>` | 一行一篇 | 改了上游不知道下游 |
| 「這一帶的關係長什麼樣」 | `lumos map <節點> [--depth 2]` | 樹狀展開 | — |
| 「篩條件:金流且未收案 / 連到 X 且還開著 / 有合約的」 | `lumos query --tag 家族/值 [--tag …(AND)] [--no-tag …] [--active] [--contract] [--linked <節點>]` | 清單;至少給一個條件 | grep 字串漏同義標籤 |
| 「當初為什麼這樣決定?翻案了嗎?」 | `lumos decisions <節點>`;全庫掃被推翻的 `lumos decisions --superseded` | 每條有編號、日期、valid;valid:false 代表已翻案 | 決策是結構化欄位,散文 grep 抓不全 |
| 「最近動了什麼 / 現在在進行什麼」 | `lumos recent --days 7`;`lumos query --tag status/doing` | 篇名+日期 | git log 看不到圖譜層進度 |
| 「圖譜多大、各夾幾篇」 | `lumos stats` | 資料夾計數 | — |
| 「畫成圖給人看」 | `lumos export [--format mermaid\|dot\|html]` | 文字圖或互動 html | — |

**中文查詢:概念之間要加空白**——`search` 先把整串當片語比對,整串找不到才退成各詞分開找;中文黏成一串沒有「各詞」可退,自然問句幾乎必定 0 筆。`作廢訂單點數怎麼收回`(0 筆)→ `作廢 收回 點數`;`會員登入流程` → `會員 登入`。0 筆時工具會提醒你。

**單篇內部可能新舊打架**(doctor 驗的是筆記之間,驗不出一篇裡前後矛盾):摘要裡有日期的 KEY 行比正文段落新;衝突又影響決策 → 去 code 裁,然後回頭修圖譜。

**搜尋的兩個提醒(工具會印,別忽略)**:
- 「多詞回退」= 整串找不到,改成各詞分開找;標 ★ 的詞是 0 命中,多半是你用的詞跟圖譜說法不同。
- 「命中≠查完」= search 只給索引,下結論前 `lumos show` 讀全文。
