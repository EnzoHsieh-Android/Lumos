# 09|節點還原(brownfield 冷啟動)

白話:接手圖譜空或稀疏的既有專案,把功能脈絡還原成節點。**完整七步與紅線在 `reference.md`〈節點還原(brownfield 冷啟動)〉**;這裡只列「什麼時候敲哪個」。進場三分岔以該節為正本,此表只放指標。

| 你正在… | 敲 |
|---|---|
| 進場判斷(有→照慣例用;殘缺→diff 補;沒有→往下) | 先 `lumos search <詞>`,命中再 `lumos context <節點>` |
| 步驟 0:裝殼+填骨架導覽頁 | `lumos init`,然後 Edit 填 init 已建好的 `MOC/index.md`(別另建) |
| 步驟 1–3:定位/追流/考古 | 讀 code 與 git(冷啟動豁免,無 lumos 指令;招式見 reference 該節) |
| 步驟 4:落節點 | `lumos new system <模組> --code <它管的檔> … --responsibility "<負責什麼、不負責什麼>"`(每支檔有家:一個模組一篇、別人的檔用連結,提交前會擋沒家的新檔。★`--code` 是必要條件:每篇還原節點都要說自己管哪些檔;真的不管檔的主題篇,負責範圍要寫明為什麼不管檔★。跟著誰住:組裝檔(依賴注入那種)住它接起來的那個功能的節點,只有一支大組裝檔才另開「組裝」節點;★別把一支組裝檔掛進每個功能節點——家太多等於沒家★;版面檔、導覽圖這類非程式檔列進用它的那篇) → Edit 摘要(DECISION 行手動加) → `lumos set <節點> regen from-scratch/<日期>` |
| 步驟 5:合約候選 | 開 `## 合約候選(收斂時複核,候選≠已標)` 章節於還原批次的計劃筆記;升格走 guard 三件(見 reference〈lumos guard〉) |
| 步驟 6:出口查核+留痕 | 變體 B 派工(逐節點雙 Sonnet)→ 建 Verification+`lumos sync-verified-by --apply` → 逐節點 `lumos self-audit <節點>` → `lumos doctor` 看這批還原動到的模組,它們的程式檔在「每支程式檔有沒有家」那段不再被列出來(真的不該有家的,把樣式寫進 `.lumos/config.json` 的 `node_home.ignore`——那裡只吃字串清單、掛不了理由,理由寫在那次提交訊息與這批還原的驗證紀錄) |
