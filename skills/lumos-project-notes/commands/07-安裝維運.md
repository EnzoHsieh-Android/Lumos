| 情境 | 指令 | 備註 |
|---|---|---|
| 新機器第一次裝 | `lumos bootstrap`(或 `~/harness/lumos-toolchain/install.sh`) | 裝全域 CLI + skills + 專案接線 |
| 新專案要用圖譜 | `lumos init` | 建資料夾、.gitignore、pre-commit/pre-push |

| 專案裡的工具組舊了 | `lumos update [--allow-stale]`;規範檔要先給人看才能改的專案先跑 `lumos update --dry-run` | 從唯一來源更新;來源拉不到最新會先停。★工具組與 CLAUDE.md、AGENTS.md 的紀律區塊要同一次提交、一起推★:只推工具不推紀律區塊,推送前健康檢查的 [D] 會把「紀律區塊跟範本不同步」算成問題擋下(rtb 2026-10-01 更新 v1.2 時遇到) |

## 筆記格子檢查的啟用與回退（Claude／Codex 共用）

看到 doctor 提示「掛鉤沒帶 --slots」時，先區分未啟用與工具故障；目前來源掛鉤不預設開這項，不因更新就宣稱已開。需要診斷時，先暫存自己的筆記，再跑 `lumos note-shape --staged --slots`，依缺鍵提示修正。

只有專案已決定正式啟用時，才在版本管理的 pre-commit 掛鉤把既有呼叫改成 `note-shape --staged --slots`，保留前面的直譯器、CLI 路徑和後面的 repo／錯誤處理參數，與設定一起提交。這個精確字串必須在真正呼叫行；不要把它寫進掛鉤註解充當上線。推送與 CI 從掛鉤歷史找該記號，找不到就不跑格子檢查，避免把全部舊帳當新違規。用 `lumos doctor` 核對接線，再用有缺格子的暫存筆記確認提交檢查確實抓到；未實測不能寫通過。

只想提醒或要退回時，在既有 `.lumos/config.json` 合併 `note_shape.slots` 為 `warn` 或 `off`；不要覆蓋其他設定。啟用後未設定此鍵預設 `block`，但仍受 `note_shape.gate` 總開關限制：總開關 `off` 不跑、`warn` 只提醒；要正式擋下需總開關也為 `block`。這個鍵只管格子，不關掉來源、行號或測試引用的其他檢查。`--slots` 保留為相容選項，不從 CLI 移除；來源或掛鉤更新後重新核對，不能只看先前那次通過。
