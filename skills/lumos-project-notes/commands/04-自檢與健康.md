# 04 自檢與健康(寫完要確認、收工要體檢)

| 情境 | 指令 | 結果怎麼讀 | 不用它會怎樣 |
|---|---|---|---|
| 「剛寫完一篇,有沒有寫壞?」 | `lumos lint <節點>` | 0 問題=過;error 不修提交會被擋,warning 建議順手補 | pre-commit 的 Gate L 會擋 |
| 「整個圖譜健不健康?」(收工必跑) | `lumos doctor [--verbose] [--ci]` | 上半是硬檢查(紅=要修),下半是提醒;`--verbose` 看全部軟提醒 | pre-push 跑 `--ci`,紅就推不上去 |
| 「我改了環境/流程,哪些驗證該重驗?」 | `lumos stale --candidate --match <關鍵字>`;已過期清單 `lumos stale` | 列出寫了「改到這個就該重驗」的驗證紀錄 | 拿失效驗證當依據 |
| 「這篇/這段時間被哪幾道閘攔過?」 | `lumos gov [<節點>] [--since N]`;純數字 `lumos gov --stats` | 時間軸;stats 表每道閘一行,「從沒出現」不代表沒用 | — |
| 「筆記點名的符號在 code 裡早就不存在了嗎?歷史上有這種漂移嗎?」 | `lumos drift-history` | 各取樣點的幽靈符號 | — |
| 「一份文件前後寫的數字/設定對不對得上?」 | `lumos fold-check <md>` | value-drift=前後不一致;reverse-omission=只寫一邊 | — |
| 「文件裡引的 檔案:行號 還對嗎?」 | `lumos refcheck <md> [--repo …]` | ok/missing/out_of_range | 引用過期沒人知道 |
| 「.lumos/lint.json 宣告的 linter 真的跑得動嗎?」 | `lumos lint-check [--smoke]` | 宣告了跑不動會紅 | — |
| 「專案依賴版本落後了嗎?」 | `lumos lint-watch` | 對比 registry 最新版 | — |
| 「Compose 可組合指標退步了嗎?」 | `lumos compose-metrics` | 對 baseline 比 | — |
| 「測試檔/hook 有沒有被動過?」 | `lumos anchor verify`;刻意改了就 `lumos anchor approve --note "<理由>"` | 不符 rc1 | pre-push 擋 |
| 「現在到底有幾層防護真的生效?」 | `lumos enforcement` | 各層 active/inactive/degraded/unknown + N/M | 唯讀,不擋 |

doctor 各段怎麼讀:段名已經是人話;`[X]` 只是段碼。紅的段落先修,提醒段有空再清。
