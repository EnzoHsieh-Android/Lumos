# 04 自檢與健康(寫完要確認、收工要體檢)

| 情境 | 指令 | 結果怎麼讀 | 不用它會怎樣 |
|---|---|---|---|
| 「剛寫完一篇,有沒有寫壞?」 | `lumos lint <節點>` | 0 問題=過;error 不修提交會被擋,warning 建議順手補 | pre-commit 的 Gate L 會擋 |
| 「整個圖譜健不健康?」(收工必跑) | `lumos doctor [--verbose] [--ci]` | 上半是硬檢查(紅=要修),下半是提醒;`--verbose` 看全部軟提醒 | pre-push 跑 `--ci`,紅就推不上去 |
| 「我改了環境/流程,哪些驗證該重驗?」 | `lumos stale --candidate --match <關鍵字>`;已過期清單 `lumos stale` | 列出寫了「改到這個就該重驗」的驗證紀錄 | 拿失效驗證當依據 |
| 「這篇/這段時間被哪幾道閘攔過?」 | `lumos gov [<節點>] [--since N]`;純數字 `lumos gov --stats` | 時間軸;stats 表每道閘一行,「從沒出現」不代表沒用 | — |
| 「筆記點名的符號在 code 裡早就不存在了嗎?歷史上有這種漂移嗎?」 | `lumos drift-history` | 各取樣點的幽靈符號 | — |
| 「已經寫進去的句子,有沒有因為別處狀態變了而過期?」 | `lumos drift scan [--at <提交>] [--json]` | 六種狀態一致檢查(c1–c6;c6=沒收尾的筆記在同一子句裡寫了待定詞——待裁定、還沒做、排隊中、`[todo]` 這類——又連到已收尾的筆記)、條件式回頭條件(probe)、RULE 撤除條件現在已成立的(retire,已作廢的不列)、數量標記 `[count:路徑::名稱=N]` 跟程式對不上的(count;只數 Python 模組最上層的字面值集合與列舉,數不準的列在問題裡講原因;程式組出來的集合或非 Python 改用 doctor N 段的 `<!--lumos:count=N re=… in=…-->` 正規式數量)全列,已表態的照列標「已表態」;現在成立的回頭條件與撤除條件底下若印「寫下時就已成立」,表示這組條件從那一版起連續出現在這篇、那一版條件就已經成立,這段期間沒在等任何事(已表態的也照印);查不出寫下時成不成立的不逐條印,最後彙總一行「另有 N 條查不出…」;`--json` 的 probe 與 retire 發現多一欄 `born`(`state` 為 true/false/unknown,另有 `commit`、`date`、`why`);每篇後面附那一種的 `lumos drift fix` 指令 | 轉正、收尾、提交之後的舊句子沒人發現 |
| 「照清單把一筆過期的句子改掉」 | `lumos drift fix <節點> <行號> --kind <c1..c6 或 count> [--dry-run]`;count 把標籤與句子裡恰好一個舊數字改成現值(句子裡找不到或不只一個就擋下、請手改),c1 可加 `--date`、c2 `--close --status <結案值> --reason "…"` 或 `--keep --reason "…"`(結案時摘要的 DECISION: 行還寫待定會擋下,加 `--decision "<結論>"` 換成「[今天] 結論」;還有沒結案的回頭條件也擋下,逐行加 `[closed:日期 理由]`,或確定結案後還要回頭量的加 `--keep-revisits "<理由>"` 照常結案)、c6 `--settled "<結論>" [--by <節點>] [--date YYYY-MM-DD]`(在待定子句結尾補「(已裁定:日期 結論,見 [[…]])」;待定子句連到好幾篇時要 `--by`;表格行請手改)、c3 `--status <值> [--by <節點>] [--reason "…"]`(`--reason` 選填,接在補的那一行最後;要新版工具,消費專案先 `lumos update`)、c4 只列證據(這篇第一次被提交的提交、卷證目錄——同一個提交加進來的與計劃名比對到的都列、標來源)、範本句與一條預填好的 `lumos set <節點> valid_under …`(把 `<整項新內容>` 換成改寫後的整句、範本句的 `<卷證>` 換成從清單挑的目錄再貼;c4 不自己寫檔、不進修復帳,set 改完先提交再對同一篇跑別的 drift fix)、c5 不帶參數 | 那篇要在版控裡而且乾淨(或只有工具自己的改動);改完寫修復帳 `governance/drift-fixes.jsonl`,跟筆記一起提交;驗證失敗照訊息 `git checkout --` 還原,工具不自動還原 | 手改容易漏句、改錯日期 |
| 「程式改了(函式、類別、旗標、程式檔被刪或改名),筆記還在講舊名稱嗎?」 | 推送時自動跑;手動 `lumos drift check --diff <起點>..<終點>`(舊句檢查 m1,跟 c1–c5 同一支指令) | 結論行一行(「這次推送消失了 N 個名稱,筆記裡還在講的——要處理 A 筆、只列出 B 筆」或「沒有名稱消失」、「沒跑完」…);要處理=這次改到的程式檔的家筆記或摘要行,其他只列出;每筆後面印改法:改成歷史說法或刪掉,照留就貼那條 `drift ack … --kind m1 --name=…`。開關 `.lumos/config.json` 的 `drift_check.old_sentence`(block/warn/off,沒寫是 warn),跟 `drift_check.gate` 各管各的:gate=off 時照樣跑,要完全關得多寫 `"old_sentence": "off"`;只看 Python 的定義名與旗標,其他語言只看被刪的路徑;`drift scan`、doctor、考試都不跑它 | 刪掉或改名的東西,筆記還叫人去找 |
| 「這一行確定照留」 | 表態前先看 `lumos drift scan` 有沒有在那條底下印「寫下時就已成立」:被標了就改成真的會發生的條件或刪掉;真的排進某篇了才照留,並用 `--tracked-in <Issue 或計劃>` 綁那篇(推送時這次新寫就已成立的只認綁了去處的照留;表態後標記照印,不會因表態消失);回頭條件與撤除條件的照留沒綁去處 30 天後失效、綁的那篇收尾也失效,drift scan 與 doctor 會重新列;`lumos drift ack <節點> <行號> --kind <種類> --reason "…"`;RULE 撤除條件(retire)的行號給擋下訊息列的那個(那一條的第一行,欄位寫在續行也一樣,給續行會被擋);舊句檢查(m1)要再帶觸發的名稱,一個名稱一個 `--name=<名稱>`(一律等號寫法,旗標名稱像 `--name=--restore` 才不會被當成選項;直接貼 check 印的那條,把 `<為什麼照留>` 換成真理由) | 表態要提交才算;回頭條件與撤除條件的照留記期限或綁的那篇;c2、c3 會記下當時連著的已收尾計劃,之後多了新的就重新列出;m1 記名稱清單,同一行分幾次表態的名稱會合起來算,之後同一行又有新名稱消失就重新列出 | 推送閘每次都唸同一筆 |
| 「一份文件前後寫的數字/設定對不對得上?」 | `lumos fold-check <md>` | value-drift=前後不一致;reverse-omission=只寫一邊 | — |
| 「文件裡引的 檔案:行號 還對嗎?」 | `lumos refcheck <md> [--repo …]` | ok/missing/out_of_range | 引用過期沒人知道 |
| 「.lumos/lint.json 宣告的 linter 真的跑得動嗎?」 | `lumos lint-check [--smoke]` | 宣告了跑不動會紅 | — |
| 「專案依賴版本落後了嗎?」 | `lumos lint-watch` | 對比 registry 最新版 | — |
| 「Compose 可組合指標退步了嗎?」 | `lumos compose-metrics` | 對 baseline 比 | — |
| 「測試檔/hook 有沒有被動過?」 | `lumos anchor verify`;刻意改了就 `lumos anchor approve --note "<理由>"` | 不符 rc1 | pre-push 擋 |
| 「現在到底有幾層防護真的生效?」 | `lumos enforcement` | 各層 active/inactive/degraded/unknown + N/M | 唯讀,不擋 |

doctor 各段怎麼讀:段名已經是人話;`[X]` 只是段碼。紅的段落先修,提醒段有空再清。筆記格子的過期提醒在 S17(作廢行的 `[被取代:]` 指不到或也作廢了)、S18(RULE 的度量式撤除條件成立,或寫法不合)、S19(FACT/FLOW/DEP 超過確認週期),三段都不計入問題數;S20 列全庫指不到真測試的 `[test:]`、作廢條目還掛活測試、佔位字、寫錯的 `[test-gone:]`,也不計入問題數(推送時只查碰到的那幾篇,擋不擋看 `note_shape.test_refs`:沒設是 warn、設 block 才擋);S20 另列一類散文撤除候選「條款仍掛 `[test:]` 而下一層寫了撤除」:真的撤除就標 `[status:superseded]`、把綁定改寫成 `[manual:已撤除,見 …]`;P2 列殺傷力配方的原文對不上程式(找不到或不只一處),以及原文對得上、最近一次真跑卻判 survived 的,只提醒不擋,怎麼修見 06 的「配方的原文在程式裡找不到或不只一處」與「P2 段說有配方最近一次真跑判 survived」兩列;S17、S18 要讀本機帳,`--ci` 不跑。
